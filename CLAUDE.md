# WebX UI — дизайн-система на Vue 3, бриф для Claude Code

Названия: npm scope `@webx-ui`, GitHub-организация `webx-ui`, репозиторий `webx-ui/webx-ui`,
префикс компонентов `Wx` (в шаблонах `<wx-button>`), CSS-классы `.wx-*`, CSS-переменные `--wx-*`.

## 1. Что это

Публичная open-source дизайн-система на Vue 3 — основа для админок (CMS) нескольких сайтов на
Laravel. Библиотека публикуется в npm, админки — отдельные приватные проекты, которые её
подключают.

Пакеты:

1. **`@webx-ui/tokens`** — цвета, отступы, типографика, радиусы, тени. JSON → CSS-переменные,
   светлая и тёмная темы.
2. **`@webx-ui/core`** — компоненты. Список компонентов брали из Element Plus как чек-лист, но
   реализуем сами. Сложная логика без стиля (Dialog, Dropdown, Popover, Tooltip, Combobox, Tabs) —
   из **Reka UI**; drag-and-drop — `vue-draggable-plus`, датапикер — `@vuepic/vue-datepicker`,
   rich-text — Tiptap.
3. **`@webx-ui/schema`** — экраны как JSON: узел `{ id, type, name, label, props, children, visible, can }`,
   патчи (add/remove/replace/move/set), реестр типов на компонентах ядра, `WxScreenRenderer`,
   JSON-схемы. Гайд — `apps/docs/guide/screens.md`, спецификация — §1 ниже.
4. **`@webx-ui/adapter-laravel`** — адаптер под Laravel (`LengthAwarePaginator`, ошибки 422,
   query-параметры сортировки и фильтров). Не начинался.

Вторая половина системы — **composer-пакеты** в `php/packages/*` (вендор `webx-ui/*`, namespace
`WebxUi`), они же ядро админки на Laravel. **Имена пакетов на обеих половинах:** всё, из чего
состоит панель, — с префиксом `module-`: каркас `module-admin` и разделы `module-auth`,
`module-media`, `module-settings`, `module-seo`; библиотеки, которые живут и без панели, — без него: `nested-set`, `localization`,
`mcp`, `routing`. Идентификатор модуля — то, чем он называется в панели, а не то, что он хранит:
администраторы — `admins`, а `users` оставлено пользователям сайта, которые станут отдельным
разделом. По тому же правилу SEO собран **одним** пакетом, а не библиотекой плюс разделом:
рендеру `<head>` без раздела рисовать нечего — ни правил, ни дефолтов, ни Organization, — то
есть библиотекой он по нашему же критерию не является. Шов между половинами держится внутри
(`WebxUi\Seo\Rendering\` и `WebxUi\Seo\Panel\`, источники через контракт). Реестр и планы — в
`docs/architecture/WEBX_UI_COMPOSER_PACKAGES.md`, конвейер публикации на Packagist — в
`docs/architecture/WEBX_UI_PHP_RELEASE.md`. **Экраны как описание** — дерево узлов в JSON,
патчи от проекта, реестр типов на обеих половинах — согласованная спецификация в
`docs/architecture/WEBX_UI_SCREENS.md`; читать до того, как трогать любой экран панели.
**Адреса сайта** — общий плоский реестр в `routing` (`routes`, форматтеры, алиасы, резолвер за
`Route::fallback()`): спецификация — `docs/architecture/WEBX_UI_ROUTING.md`, гайд —
`apps/docs/guide/routing.md`. Любой контентный модуль получает адрес там, а не у себя; `module-seo`
показывает алиасы вкладкой «Автоматические» рядом с ручными редиректами.

Ключевые принципы:

- Компоненты знают только CSS-переменные, никаких хардкод-цветов.
- Компоненты не ходят в API: данные приходят пропсами, наружу — события.
- Таблица принимает формат Laravel `->paginate()` как есть.
- **В публичное репо не попадает ничего специфичного для конкретных сайтов/клиентов.**
- `vue` — в `peerDependencies`.

## 3. Структура репозитория

```
packages/
├── tokens/src/tokens.json        # источник правды по стилю; scripts/generate.mjs → dist/tokens.css
├── core/src/
│   ├── components/<Name>/        # Name.vue + types.ts + Name.test.ts + index.ts
│   ├── composables/              # useToast, useModal, confirm, useFormField, useElementWidth, …
│   ├── internal/                 # то, что не экспортируется наружу (nodes.ts, ConfirmDialog.vue)
│   ├── styles/                   # база и подключение токенов
│   ├── plugin.ts                 # app.use(WebxUI): компоненты + директива + connectModals
│   └── index.ts                  # именованные экспорты
└── schema/src/                   # типы контрактов
apps/
├── docs/                         # VitePress: components/*.md + components/demos/*.vue + guide/*
└── playground/                   # Vite-песочница: реальные экраны админки
php/
├── composer.json                 # dev-корень: тулинг + path-репозитории пакетов
├── package.json                  # приватный @webx-ui/php: общая версия composer-пакетов
└── packages/<name>/              # composer.json + src + tests + README + LICENSE
```

## 4. Правила, которые уже стоили времени

- **Визуальное проверять в браузере, а не в jsdom.** jsdom не считает layout, поэтому ни один баг
  вёрстки он не поймает. Порядок такой: `preview_start` доков → замер (`getBoundingClientRect`,
  `getComputedStyle`, `scrollWidth` vs `clientWidth`) → правка → повторный замер. Почти каждый раз
  настоящая причина оказывалась не той, на которую было похоже.
- **Скрытая панель браузера останавливает** `requestAnimationFrame`, колбэки `ResizeObserver` и
  CSS-переходы. Измерения в ней надо запускать руками.
- **Правка пакета доезжает до `webx-cms.local` только сборкой, и с двух сторон по-разному.**
  npm-половина слинкована симлинками, но сайт грузит `dist` («The packages ship compiled»), —
  значит `pnpm --filter <пакет> build` в монорепе, иначе смотришь вчерашний бандл.
  Composer-половина на Windows не симлинк, а **копия**: `vendor/webx-ui/<пакет>` живёт своей
  жизнью, и правка `resources/screens/*.json` в чекауте до сайта не доходит вовсе. Выглядит
  одинаково — «ничего не изменилось», — а причины разные, поэтому проверять надо обе: ответ
  `/api/cms/screens/<экран>` показывает, доехала ли php-часть. И `npx vite build` в самом сайте:
  dev-сервер сайта панели браузера не годится — его `http://127.0.0.1:<порт>` рядом с
  `https://webx-cms.local` отлетает как `ERR_BLOCKED_BY_CLIENT`, и страница остаётся на старом
  собранном бандле, ничего об этом не говоря.
- **Панель, открытая кликом изнутри другой панели, закрывается тем же кликом.** Reka создаёт
  dismissable-слой посреди обработки клика, дальше видит, что тот же клик заканчивается не внутри
  неё, и считает это кликом снаружи. Открывать такие панели надо на следующем витке цикла
  (`setTimeout`), а не в обработчике. **В тестах не ловится:** синтетический `.click()` отрабатывает
  синхронно и панель остаётся открытой — нужен настоящий клик мышью в браузере.
- **Обёртка, которая объявляет пропсы ребёнка, ломает все его булевы значения по
  умолчанию.** Vue приводит необъявленный Boolean-проп к `false`, а не оставляет
  `undefined`, — и обёртка, которая эти пропсы объявила и передала дальше, отдаёт ребёнку
  `false` там, где вызывающий ничего не просил. Выглядит как «половина кнопок пропала».
  Лечится не дублированием дефолтов, а `inheritAttrs: false` + `v-bind="$attrs"`:
  необъявленное едет атрибутами и доходит как есть.
- **Сайт, слинкованный с монорепой, получает вторую копию Vue — и реактивность рвётся по шву.**
  В local-режиме `@webx-ui/*` подключены как `file:`-ссылки, и `vue` изнутри пакета резолвится в
  `packages/core/node_modules/vue` чекаута. Приложение при этом создаёт `createApp` из Vue пакета,
  а `ref()` в коде сайта — из своего: два независимых механизма реактивности, которые друг друга
  не видят. Ничего не падает, ошибок в консоли нет — просто `ref` меняется, а перерисовки нет.
  Диагноз: выставить ref в `window` и убедиться, что присвоение не меняет DOM. Лечится
  `resolve: { dedupe: ['vue'] }` в `vite.config.js` сайта. В registry-режиме не воспроизводится,
  то есть ломается ровно в том режиме, в котором ведётся разработка.
- **Стили компонента ядра снаружи одним классом не перебить.** У них scoped-правила, а scoped —
  это класс плюс атрибут; `.my-thing` проигрывает `.wx-actions[data-v-…]`. Видно только в
  браузере и выглядит как «стиль не применился»: картинка встала натуральным размером, кнопки
  уехали за рамку. Лечится не специфичностью, а собственной обёрткой вокруг компонента.
- **Диагностика нулевой ширины в CodeMirror невидима.** Парсер JSON отдаёт «ошибка в позиции 23»
  как пустой диапазон, и линтер рисует его точкой в пиксель, а не волной — линт «работает», а
  подчёркивания нет. `WxCodeEditor` растягивает такие диапазоны до конца строки; свой линтер в
  `extensions` должен делать то же сам.
- **Ключ с точкой — это один ключ, а не путь, и Laravel с этим не согласен.** Имена полей
  экранов (`general.project-name`) буквальны, а `Validator` с правилом `values.general.project-name`
  и `assertJsonPath('data.values.general.project-name')` разбирают точку как вложенность.
  Поэтому `ScreenValues` проверяет каждое значение отдельным валидатором под именем `value`,
  а тесты читают `->json('data.values')` и берут ключ из массива.
- **Картинку для canvas нельзя брать с CDN.** `WxImageEditor` рисует изображение на canvas и
  вызывает `toBlob`, поэтому у него `crossorigin="anonymous"` — и без `Access-Control-Allow-Origin`
  браузер не грузит картинку вообще. Выглядит как «редактор сломался»: интерфейс есть, а внутри
  «This picture could not be loaded». Настройкой CORS на бакете это не лечится по-настоящему —
  приватному бакету таких заголовков для панели не выдать, а подписанная ссылка всё равно ведёт на
  другой домен. Правильный ответ — отдавать байты со своего домена: у `module-media` для этого
  `files/{id}/source`, и в ресурсе он лежит отдельно от `url`. `url` остаётся тем, чем показывают.
- **Слова компонента ядра — это пропсы, а не словарь.** `WxImageEditor`, `WxFileCard` и прочие
  несут английские дефолты: они не знают ни про панель, ни про namespace. Переводит тот, кто их
  открывает, — иначе получается модуль, переведённый на десять языков, с английским диалогом
  посередине. Ищется это только глазами: тесты на паритет ключей такую дыру не видят, потому что
  ключа просто нет.
- **`overflow: hidden` обрезает не только рисунок, но и попадание указателя.** Ручка,
  которая наполовину торчит за край (углы кропа, грипы ресайза), внутри обрезающего бокса
  теряет половину мишени — промах уходит в то, что лежит под ней, и жест молча делает не
  то или не делает ничего. Обрезать надо отдельный слой с картинкой, а ручки держать
  снаружи него; заодно самому боксу нужен отступ в половину ручки.
- **Жесты пальцем эмулятор не проверяет.** Device mode десктопного браузера шлёт события указателя
  и ничего у страницы не отбирает; настоящий телефон отдаёт жест скроллеру, и события просто
  перестают приходить (`pointercancel`). Всё, что зависит от `touch-action` или `pointerType`,
  верно ровно настолько, насколько это проверено на устройстве.
- **Один vnode нельзя смонтировать в двух местах — и ломается это только в проде.** Обычный
  `<slot />` Vue клонирует сам; vnode'ы, которые едут пропом (`WxNodes` в `internal/nodes.ts`), этот
  путь минуют — поэтому `WxNodes` клонирует их на выходе, и разрезать слот надо только через него.
  В dev-сборке компилятор возвращает новый vnode на каждый рендер, и переиспользование не видно;
  в проде статический пункт кэшируется и возвращается тем же объектом, а второе место рендерится
  пустым. Проверять такое только на production-сборке.
- **`docs:preview` (sirv) строит список файлов при старте.** После `docs:build` сервер надо
  перезапустить, иначе смотришь старый бандл: свежий HTML тянет новые хеши, их нет → 404, страница
  без стилей и без гидрации. Выглядит как «правка не помогла».
- **Composer не «пропускает» `path`-репозиторий, каталога которого нет, — он падает.**
  `The url supplied for the path repository does not exist`, и это ошибка, а не предупреждение.
  Поэтому манифест, в котором прописан этот чекаут, нельзя собрать нигде больше: сайт
  `webx-cms.local` переключается между монорепой и реестром скриптом (`scripts/packages.mjs` у
  него, `scripts/link-panel.sh` здесь), а не живёт в одном состоянии. У npm то же самое с `file:`.
- **В worktree `node_modules` — симлинк на основной чекаут, и `pnpm` это не переживает.** Любой
  `pnpm <скрипт>` оттуда либо отказывается («Refusing to use task run state directory … because
  it is a symbolic link»), либо — если решит, что сменился пакетный менеджер, — идёт по симлинку
  и **сносит содержимое `node_modules` основного чекаута**: пропадают `.pnpm` и `.bin`, и
  ломается всё сразу, включая соседнюю сессию. Так же ведёт себя `preview_start` по имени из
  `.claude/launch.json`: он запускает pnpm. Из worktree запускать бинарники напрямую
  (`npx vite build`, `npx vue-tsc -p tsconfig.json --noEmit` в каждом пакете вместо рекурсивного
  `pnpm typecheck`, `node <основной чекаут>/apps/docs/node_modules/vitepress/bin/vitepress.js dev
--port 5177`), а dev-сервер поднимать фоновой командой и открывать `preview_start` с `url`.
  Лечится снос одним `pnpm install --frozen-lockfile` в основном чекауте — проверить, что
  `node_modules/.pnpm` на месте.
- **Гейт локально упирается в память, а не в ошибки.** `pnpm build` и `pnpm test` идут
  параллельно по числу ядер, dts-шаг `@webx-ui/core` и любой тест, который монтирует
  `WxCodeEditor` (CodeMirror), тяжёлые — и с седьмым пакетом в монорепе это стало срываться в
  `Fatal process out of memory: Zone` на ровном месте. Выглядит как сломанная сборка, но падает
  каждый раз в разном месте и со второго раза проходит. Перед гейтом стоит погасить dev-серверы;
  отдельный тест — `npx vitest run <файл> --pool=forks --poolOptions.forks.singleFork`.
- **Гейт перед пушем** — ровно то, что делает CI:
  ```
  pnpm build && pnpm typecheck && pnpm lint && npx prettier --check . && pnpm test && pnpm docs:build
  ```
  `pnpm typecheck` рекурсивный, по одному пакету не считается. `pnpm build` обязателен **до**
  typecheck доков: `apps/docs` резолвит `@webx-ui/core` из `dist`.
- **Смотреть — на доках.** Серверы описаны в `.claude/launch.json`: `docs` (5173),
  `playground` (5174), `docs-alt` (5175) и `docs-alt2` (5176) — последние два на случай, когда
  порт занят другой сессией.
  Демо в `apps/docs/components/demos/` — самый короткий способ увидеть компонент живым, и заодно
  ровно то, что увидит читатель документации.
- **Новый проп не появился — перезапусти dev-сервер.** `defineProps<Props>()` резолвит тип из
  соседнего `types.ts` на этапе компиляции, и правка `types.ts` не инвалидирует `.vue`: Vite
  отдаёт старую трансформацию, где пропа просто нет. Выглядит как «проп молча игнорируется»,
  диагностируется так: `curl` на модуль и поиск `<имя>: { type:` в ответе.
- **`WxActions collapse` в таблице не сворачивается, пока колонкам не задана ширина.** Ряд
  меряет себя по своей ячейке, а ячейка в `table-layout: auto` растёт под содержимое — семь
  иконок «помещаются» всегда, и вместо меню таблица уезжает вбок. Лечится `layout="fixed"` плюс
  ширина на каждой колонке, кроме одной. И меню при этом нужно наполнить словами (`#collapsed`):
  по умолчанию в выпадашку едет тот же ряд безымянных иконок. Спискам панели это больше не
  грозит: у них `collapse="always"` (через `WxRowMenu`), а он не меряет ничего.
- **Унаследованная CSS-переменная не перебивает ту, что компонент объявил на самом элементе.**
  `--wx-action-size: 44px` на обёртке меню не делает ничего: `.wx-action--sm` объявляет эту же
  переменную на себе, а значение, объявленное на элементе, всегда сильнее унаследованного —
  специфичность правила выше по дереву тут ни при чём. Выглядит как «правило не применилось»,
  причём `getComputedStyle(обёртки)` честно показывает 44px, и только замер самой кнопки
  показывает 30. Задавать такие переменные надо на том элементе, который их читает

- **Валидатор, который собирает объект заново, молча теряет новый ключ.** Путь записи агента

  протащить в содержимое чужое. Добавленный структурный ключ (`hidden`) при этом пропадал без

  добавлять во все такие сборщики, а тест писать через настоящий путь записи, а не только на
  чистой функции.
- **Картинка во флекс-ряду не сжимается, и `max-width: 100%` тут ни при чём.** У `<img>`

  только замером (`scrollWidth` обёртки против `clientWidth`) и только на достаточно широком

- **`v-on` с объектом слушателей не доезжает до `vnode.props`, а `v-bind` доезжает.**
  `v-on="{ 'row-click': open }"` работает как слушатель, но компонент, который смотрит
  `instance.vnode.props.onRowClick` (так `WxTable` решает, рисовать ли курсор-руку), не видит
  ничего: `toHandlers` кладёт ключ иначе. `v-bind="{ onRowClick: open }"` кладёт как надо. И
  главное — **`instance.vnode` не реактивен**: вывод «слушают → значит кликабельно» считается
  один раз на первом рендере и больше никогда, поэтому список, который посреди жизни перестаёт
  куда-то вести (корзина, архив), обязан сказать это пропом. Отсюда `clickable` у `WxTable`.
  В jsdom видно только по классу — ни курсора, ни подсветки там нет.

- **У выключенной кнопки нет событий указателя — и подсказки тоже.** Атрибут `disabled`

- **Комментарий в корне шаблона — это узел.** В dev-сборке Vue оставляет комментарии в дереве,

  `<script>`, а не над шаблоном.
- **`WxAction` — не один корневой узел.** Он носит свой `WxTooltip`, а тот рендерит рядом

  ничего, в тестах видно всё: `wrapper.element` — не кнопка, `wrapper.classes()` пуст,
  `wrapper.trigger('click')` уходит в пустоту. В тестах брать `wrapper.get('button')`; искать

- **У компонента с фрагментом в корне нет твоего `data-v-…`, и собственный класс на нём не
  стилизуется.** Vue ставит scope-атрибут родителя только на **однокорневого** ребёнка, а
  `WxSelect`, `WxAction` и всё, что носит рядом портал (выпадашка, тултип), — фрагмент:
  `class="wx-articles__filter"` доезжает до элемента, `.wx-articles__filter { … }` в scoped-стилях
  не совпадает ни с чем. Молча — правило просто не применяется, и элемент остаётся натуральной
  ширины; в devtools класс на месте, и выглядит это как «стиль не сработал». Проверяется одной
  строкой: `[...el.attributes].map(a => a.name)` — если `data-v-…` нет, дело в этом. Лечится
  `:deep()` от своей обёртки (`.wx-filters > :deep(.wx-select)`), а не специфичностью.
- **Контейнерные запросы вместо медиа-запросов** (`container-type: inline-size` + `@container`):
  решает ширина панели, а не окна. Где нужна не вёрстка, а поведение, — `useElementWidth`

  страницах. Такое живёт только в глобальном middleware (`Kernel::pushMiddleware`, в

  иначе закроет редактору и экран, на котором он её написал. **Тестом не ловится:** в тесте
  маршрут обычно есть, и всё «работает». Поймал `scripts/php-smoke.sh`.
- **Стек middleware, выписанный руками, не знает ничего о группе `web` этого сайта.** «Как

- **`static::observe()` внутри `boot<Trait>()` роняет модель.** `observe()` строит экземпляр
  модели, чтобы спросить у него список событий, — а модель в этот момент ещё загружается, и
  Laravel отвечает «may not be called on model … while it is being booted». Ловится только
  запуском: на вид это обычная строчка. Лечится `static::registerModelEvent()` на каждое

- **Отказ в обсервере `created`/`updated` не отменяет сохранение.** Строка уже в таблице
  (`created` бывает только после вставки), и исключение оставляет сущность с новым значением и
  без того, что от неё зависело, — форма показывает ошибку, база молча соглашается. Откатывать
  надо самому: `getRawOriginal()` в момент события ещё держит прежние значения, потому что
  `syncOriginal()` вызывается после него. Возвращать их надо сырыми (`setRawAttributes` +
  `update`), а не через `fill()`: переводимая колонка получит собственный JSON как значение
  текущего языка.
- **Границы `nested-set` в памяти устаревают молча.** Узел, загруженный до того, как под него

- **Процент высоты внутри колонки, которая сама не знает своей высоты, не разрешается ни во
  что.** `height: 100%` на экране считается от `auto` и молча становится `auto`, а экран растёт и
  тянет за собой страницу. Достать предка изнутри нечем, поэтому экран объявляет себя атрибутом

  его через `token_get_all()`, и трогает только то, что PHP считает inline HTML. Поэтому строка
  `{!! '<?xml version="1.0" encoding="UTF-8"?>' !!}` в шаблоне RSS не компилируется вовсе: PHP
  видит короткий открывающий тег, всё до `?>` читает как код, а страница падает с «syntax error,
  unexpected identifier "version"». Выглядит как ошибка в самом выражении, хотя в обычной
  php-строке `?>` внутри кавычек не ломает ничего. Писать по кускам —
  `'<'.'?xml version="1.0" encoding="UTF-8"?'.'>'`, — чтобы эти два символа нигде не стояли
  рядом.
- **Eloquent пишет `Carbon` вместе с его часовым поясом, а читает в поясе приложения.** Момент,
  разобранный из `2026-09-25T11:06:00+03:00`, уходит в колонку строкой `2026-09-25 11:06:00` и
  возвращается как 11:06 **UTC** — запись уезжает на величину смещения при каждом сохранении, в
  ту сторону, где сидит сохранивший. Перед записью приводить к поясу приложения
  (`->setTimezone(config('app.timezone'))`, у блога это `Panel\Instant`). Заодно: значение
  датапикера без смещения вообще (`2026-09-25 11:06:00`) сервер читает в своём поясе, а браузер
  в своём, и одна и та же статья показывает в поле одно время, а в списке другое — поэтому дата
  ездит по API только с `toAtomString()`, а у `wx-date-picker` для этого есть
  `valueFormat: "yyyy-MM-dd'T'HH:mm:ssXXX"`. **В тестах не видно:** и Testbench, и CI живут в
  UTC, где смещение нулевое и всё сходится.
- **Строка состояния в `WxActionBar` перекрывала кнопки, а не сжималась.** У блока состояния
  `min-width: 0`, поэтому при нехватке ширины он ужимался в ноль, а текст продолжал рисоваться
  там, где блока уже нет, — поперёк кнопок. Померено на 375 px: блок 0×105, «Сохранено · Выйдет
  25 сентября в 17:06» поверх «Сохранить черновик». Теперь бар переносится (`flex-wrap: wrap`,
  `flex: 1 1 220px` у состояния); длинную строку состояния всё равно стоит смотреть на телефоне.

## 5. Процесс

- **Пушить в remote `claude`, никогда в `origin`.** PR — через `gh`, он не в PATH:
  `"C:\Program Files\GitHub CLI\gh.exe"`.
- `main` закрыт **ruleset'ом** (не branch protection, поэтому `.../branches/main/protection`
  отвечает 404 — смотреть `gh api repos/webx-ui/webx-ui/rules/branches/main`). Апрув не нужен, но
  нужен зелёный чек `Lint, typecheck, test, build` **и** ветка должна быть свежей относительно
  `main`. Отстала — влить `main` в ветку, дождаться CI заново, потом мержить.
- **После `gh pr merge` локальный `main` остаётся старым.** `gh` синхронизирует его через
  remote по умолчанию, то есть `origin`, куда доступа нет: в конце вывода будет
  «Could not read from remote repository» и «not possible to fast-forward», хотя PR на GitHub
  уже смержен. Выглядит страшно — рабочие файлы будто откатились. Лечится
  `git fetch claude && git merge --ff-only claude/main`; проверить, что мерж прошёл, можно через
  `gh pr view <N> --json state`.
- **Changeset** на каждый PR, который меняет публикуемый пакет; docs-only — без него. Правка в
  `php/packages/*` — это changeset на приватный `@webx-ui/php`: он носит общую версию всех
  composer-пакетов.
- **У php-пакетов нет публикации, есть тег.** `release.yml` после changesets вешает `php-v<версия>`
  и вызывает `php-split.yml`, тот зеркалит каждый пакет в `webx-ui/<имя>` и ставит там `v<версия>`
  — Packagist подхватывает вебхуком. Право на запись даёт GitHub App организации
  (`PHP_SPLIT_APP_ID` + `PHP_SPLIT_APP_PRIVATE_KEY`); руками нужен только сам
  репозиторий-зеркало. Подробности и что делать на packagist.org —
  `docs/architecture/WEBX_UI_PHP_RELEASE.md`.
- **Релиз:** мерж PR с changeset'ами → бот открывает «chore: version packages» → мерж этого PR
  публикует пакеты. На npm версия появляется минут через пять после того, как воркфлоу отчитался.
  Проверять `npm view @webx-ui/core version`, а не веру: тег в git ставится сразу, регистр отстаёт.
- **Первую версию нового npm-пакета публикует человек, а не CI.** Trusted Publishing по OIDC не
  умеет создавать имя: пока пакета в реестре нет, доверенного издателя к нему и не привяжешь.
  Отвечает на это npm статусом `404 Not Found` на публикации — выглядит как «пакет не найден»,
  то есть как опечатка в имени, а не как «нет прав». Порядок такой: `pnpm --filter <пакет> publish
--access public --no-git-checks` руками (с 2FA, значит из настоящего терминала), затем на
  npmjs.com у пакета Settings → Trusted Publishing → GitHub Actions (`webx-ui` / `webx-ui` /
  `release.yml`, environment пустой), и только потом релизный PR. Настройка доходит не мгновенно:
  первый перезапуск джобы после неё может ещё раз ответить тем же 404, второй проходит.
- **Ручная публикация замораживает диапазоны на версиях «до релиза».** `workspace:^` подставляется
  в момент публикации, а первую версию нового пакета человек выпускает до релизного PR — то есть
  когда соседи в чекауте ещё старые. Так `module-settings@0.1.0` уехал с диапазоном `^0.3.1` на
  каркас, хотя нужный ему `WxScreen` появился в 0.4.0: npm ставит рядом вторую, старую копию
  каркаса, и сборка сайта падает на `[MISSING_EXPORT]`. В монорепе этого не видно — там всё
  резолвится в чекаут. Лечится не перевыпуском патчем, а местом, откуда публикуешь: **вручную
  публиковать надо не из `main`, а из ветки `changeset-release/main`** — там бот уже проставил все
  итоговые версии, и `workspace:^` подставляется теми, с которыми пакет через минуту и уедет.
  Порядок: дождаться, пока Release-воркфлоу обновит релизный PR, снять ветку в отдельный worktree,
  `pnpm install`, положить туда `dist` (исходники те же, что в `main`), `pnpm pack` — и проверить
  диапазоны в `package/package.json` тарбола до публикации, а не `npm view` после. Так
  `@webx-ui/module-seo@0.1.0` уехал сразу с `^0.19.0` на ядро.
- **Тег php-пакетов ставится до публикации в npm, и переживает её падение.** Шаг «Tag the PHP
  packages» стоит раньше changesets нарочно, поэтому упавшая npm-джоба оставляет `php-v<версия>`
  на месте, а зеркалирование пропускает (`needs: release`). Перезапуск не помогает: тег уже есть,
  шаг выходит молча, выход `php_version` пустой, `php-split` снова пропущен. Лечится ручным
  запуском: `gh workflow run php-split.yml --ref main -f tag=v<версия>`.
- **После релиза — обновить оба демо.** Локальное: `scripts/link-panel.sh` (пакеты из чекаута) и
  `composer update "webx-ui/*"` в сайте. Хомлаб: в его репозитории — режим `registry` того же
  переключателя, `composer update "webx-ui/*"`, коммит и пуш. **Ночной прогон свежий релиз не
  привозит:** он собирает по закоммиченным манифестам (`packages.mjs check` только проверяет, что
  они не смотрят в чекаут), а каретка на нулевой мажорной версии пинует минор — `^0.18.0` до
  0.19.0 не доедет никогда. То есть релиз доходит до хомлаба ровно тем коммитом, который поднял
  диапазоны, и ждать ночи бессмысленно.
- **CI на релизном PR ждёт ручного подтверждения.** Прогон на ветке `changeset-release/main`
  встаёт в `action_required`, `gh pr checks` при этом отвечает «no checks reported», а сам PR —
  `BLOCKED`. Выглядит как сломанный бот. Лечится
  `gh api -X POST repos/webx-ui/webx-ui/actions/runs/<id>/approve`; id брать из
  `gh run list --branch changeset-release/main`.
- **Начинать с `gh pr list`:** работа могла остаться в открытом PR, а не в `main`. Ветка с
  незакрытым PR — это незаконченный разговор, а не мусор.
- Детали для людей — в `CONTRIBUTING.md`.

## 6. Что дальше

Порядок не догма, но примерно такой:

1. Остаток волны 3: Carousel, Anchor, Splitter, Watermark, Marquee. Tree, TreeSelect и дерево
   внутри таблицы закрыты.
2. **Gantt** — решено делать своим, не начинали (обоснование в roadmap).
3. CMS-блоки: MediaLibrary / Gallery, Repeater, Markdown, LinkPicker, BlockPicker.
4. Экраны как описание (`docs/architecture/WEBX_UI_SCREENS.md`): рендерер, общий слой в
   `module-admin`, `module-settings`, `wx-repeater` и `module-seo` готовы — вкладка SEO теперь
   приезжает патчем от модуля, а не от сайта, и это первый патч, который кладёт не проект.
   `admins.form` и форма правила SEO на экраны пока не переводятся (решение 14.09.2026);
   `@webx-ui/adapter-laravel` — после.
5. **`module-blocks`** — конструктор блоков, **выпущен 16.09.2026** и стоит на обоих демо: тип
   блока целиком заводится в панели (схема полей, Blade, CSS, скрипт), правда в базе, вложенность —
   поле `wx-blocks`, предпросмотр по служебному адресу с токеном. Вместе с ним приехали общие
   черновики и версии сущностей (`HasDraft`, `HasVersions` в `module-admin`) и detached-узел в
   `nested-set`. Спецификация — `docs/architecture/WEBX_UI_MODULE_BLOCKS.md`; §18.1 там — точечная
   правка содержимого агентом (`blocks_edit_content`, операции по ключам, `revision` против
   затирания).
6. **`module-pages`** — **выпущен 16.09.2026** и стоит на обоих демо: дерево страниц,
   **главная — корневой узел** с пустым слагом, адрес форматтером `TreePath` (политика `Fail`),
   переводимые `title` и `slug`, мягкое удаление веткой, список табличным деревом (а на телефоне
   плоским списком с адресом в подписи), редактор вкладками с автосейвом и защитой ревизией.
   Спецификация — `docs/architecture/WEBX_UI_MODULE_PAGES.md`, гайд — `apps/docs/guide/pages.md`.
   Вместе с ним приехало SEO сущностей (`seo_meta`, `HasSeo`, `EntitySource` с приоритетом 50 и
   тип поля `wx-seo` — всё в `module-seo`, карточка на `pages.form` патчем оттуда же) и девять
   инструментов `pages_*` через те же двери, что и панель, плюс ресурс `pages://sitemap` и промпт
   `build_page`. Содержимое блоками они не правят — на это есть `blocks_edit_content`.
   Этим же закрыта проверка `routing` и SEO на живом сайте: у реестра наконец появился
   потребитель, и все адреса демо приходят из него.
7. **`module-blog`** — статьи, рубрики, теги; спроектирован 18.09.2026, не начинался.
   Спецификация и промпты по сессиям — `docs/architecture/WEBX_UI_MODULE_BLOG.md`. Первым идёт не
   сам блог, а тип поля `wx-rich-text` в `module-admin`: без него блоку «Текст» не на чем стоять.

Хвосты, про которые стоит помнить:

- Известный баг: шов в один пиксель рядом с закреплёнными колонками таблицы в Firefox; два
  варианта фикса уже отвергнуты.
- Плейграунд не показывает `SelectionArea`, `SortableList` и диалоги из кода — они живут только в
  доках. Напрашивается экран медиа-библиотеки, который свяжет все три.
