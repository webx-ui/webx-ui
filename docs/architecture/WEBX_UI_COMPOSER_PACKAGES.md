# WebX UI — реестр composer-пакетов

Что есть на стороне Laravel: назначение каждого пакета, npm-пара, правила, общие для всех. Подробности
— в спеке пакета (ссылка в карточке) и в гайде `apps/docs/guide/*`. Версии здесь не ведутся: общая
версия — в `php/package.json`, у установленного сайта — `composer show webx-ui/module-admin`.

Namespace `webx-ui/*`, код — `php/packages/*` в монорепо, публикация — split-репозиториями на
Packagist ([`WEBX_UI_PHP_RELEASE.md`](WEBX_UI_PHP_RELEASE.md)). Версия у всех php-пакетов общая, как
у `illuminate/*`: один тег — один релиз.

## Правило: MCP-инструменты у каждого модуля

Каждый модуль реализует `ProvidesMcpTools`. CRUD по его сущностям — минимум, но не цель: при
проектировании модуля отдельно разбирать, какие задачи агент реально будет с ним решать, и
предлагать специализированные tools, resources и prompts. Список инструментов — часть спецификации
модуля и ревьюится вместе с API.

Ориентиры: массовые операции («у всех товаров категории X …»); аудит и поиск проблем
(незаполненное, дубли, битые ссылки); черновики (описания, alt-тексты) с подтверждением; сводки
(что изменилось, что ждёт модерации); сквозные сценарии между модулями.

Изменяющий инструмент поддерживает `dry_run` (`Tool::mutating()` добавляет его принудительно) и
попадает в журнал вызовов. Ресурсы модуля несут правила дома и каталог того, что уже есть, — чтобы
агент переиспользовал, а не плодил.

## Правило: локализация у каждого модуля

Ни одной строки интерфейса в коде. Всё, что видит человек, живёт в `lang/` пакета и приходит
через `__('webx-<модуль>::<группа>.<ключ>')`.

- Пакет грузит переводы сам: `loadTranslationsFrom(__DIR__.'/../lang', 'webx-<модуль>')` и
  публикует их через `publishes`. **Namespace обязан начинаться с `webx-`** — `DictionaryBuilder`
  собирает словарь панели ровно по префиксам из `config('webx-localization.namespaces')`, и
  пакет с другим именем в словарь не попадёт, молча и без ошибки.
- **В поставке десять языков:** `en` (он же fallback), `ru`, `uk`, `de`, `pl`, `fr`, `es`, `it`,
  `pt`, `tr`. Fallback подкладывается **под** локаль построчно, поэтому наполовину переведённая
  группа показывает переведённое и английское, а не пустой экран. Какие из них предлагать
  администратору, решает сайт в `config('webx-localization.panel')` — пакет только везёт.
- Коды без региона. `LocaleCatalogue::normalise` приводит `pt-br` к `pt-BR`, а `ru_RU` к `ru`;
  `pt` — европейский португальский, `pt-BR` заводится, когда появится проект, которому он нужен.
- RTL (`ar`, `he`) в набор не входит намеренно: это не строки, а `dir="rtl"` и пересмотр всей
  вёрстки — своя задача, не часть перевода.
- Носителем вычитаны `en`, `ru` и `uk`. Остальные семь — машинный перевод, и README пакета
  говорит об этом прямо: репозиторий открытый, правка от носителя ценнее умолчания.
- Группы по смыслу: `module.php` (название раздела и пункты меню), `errors.php` (сообщения
  ошибок API), `validation.php` (атрибуты и переопределения), дальше — сколько нужно.
- npm-пара держит те же ключи по-английски в `messages.ts` и объявляет их
  `admin.i18n.defaults('webx-<модуль>', messages)`. Это пол: панель, собранная без сервера, всё
  равно со словами, и ключ никогда не попадает на экран вместо фразы.
- Ошибки сервера (422 в том числе) переводятся **на сервере**, по `X-Webx-Locale` из запроса.
  Фронт их только показывает.
- Множественное число — по строке на форму CLDR (`one`/`few`/`many`/`other`) и `pluralForm()` из
  `@webx-ui/module-admin`; синтаксиса плюрализации в словаре нет.
- Тест в каждом модуле: наборы ключей `en`, `ru` и `uk` совпадают — ни пропусков, ни лишнего.
- После правки `lang/` — `php artisan webx:locales:clear`: словарь кешируется, и без этого
  правка не видна.

Переводимые поля самих сущностей — другая история, это `HasTranslations` из
`webx-ui/localization`.

## Правило: имя пакета

Всё, из чего состоит панель, — пакет с префиксом `module-`: каркас `webx-ui/module-admin` и
разделы; npm-пара называется так же (`@webx-ui/module-admin`). Библиотека, которая живёт и без
панели, — без префикса: `nested-set`, `localization`, `mcp`, `routing`, `themes`, `widgets`,
`theme-default`. По имени видно, панель это или библиотека.

Идентификатор модуля (`Module::id()`, он же префикс прав `<id>.<action>`, областей MCP
`<id>:<scope>` и имён инструментов `<id>_<tool>`) называет то, что модуль показывает, а не
таблицу под ним: администраторы — `admins`. `users` зарезервировано за пользователями сайта —
отдельным модулем, когда сайту понадобятся регистрация и вход.

## Библиотеки

### `webx-ui/nested-set` — дерево

Библиотека для категорий, страниц, папок медиа и меню: трейт `HasNestedSet` (`lft`, `rgt`,
`parent_id`, `depth`), размещение и перенос поддерева, `up`/`down`, `toTree()`, `fixTree()`,
`checkTreeIntegrity`, несколько деревьев в одной таблице (`getNestedSetScopeAttributes()`),
Blueprint-макрос `nestedSet()`, мягкое удаление веткой (`softDeletesInTree()`), узел вне дерева
(для черновиков) и событие `moved`.

Решено: собственная реализация; `kalnoy/nestedset` — только ориентир по API. Отдельный
JSON-ресурс не нужен — форму для `wx-tree` даёт `toTree()`.

### `webx-ui/localization` — языки

Гайд — `apps/docs/guide/languages.md`. Разводит две задачи: фразы интерфейса (пишет разработчик,
живут в пакете) и контент (пишет редактор, живёт в БД). Таблица `locales`, сервис `Locales`,
справочник `LocaleCatalogue` (не ограничение), `HasTranslations` — переводимые атрибуты в
JSON-колонке в формате `spatie/laravel-translatable`, middleware `webx.locale` и
`webx.panel-locale`, `DictionaryBuilder` — словарь панели из `lang/` всех пакетов `webx-*`.

- **Язык панели — свойство человека, а не сайта** (`locale` в `cms_users`, `HasPanelLocale`).
  `webx-localization.panel` — языки, на которые переведён интерфейс; это другой список, чем языки
  публикации.
- **Один файл фраз на модуль, обе половины читают его же.** Второй словарь внутри npm-пакета —
  ошибка, от которой ушли.
- **Мерж построчно, а не по группам:** новый ключ не обнуляет экран, переведённый год назад.
- **JSON-колонка не даёт уникальности slug внутри языка** — уникальность адреса держит `routes`
  в `webx-ui/routing`, сразу по всем сущностям.

API словаря (`GET {api}/locales`, `GET {api}/translations/{code}` — публичные, экран входа
рисуется до сессии) — в `module-admin`; выбор языка администратором — в `module-auth`.

### `webx-ui/mcp` — MCP-сервер

Спека — [`WEBX_UI_MCP_ACCESS.md`](WEBX_UI_MCP_ACCESS.md), гайд — `apps/docs/guide/agents.md`.
Контракт `ProvidesMcpTools` (tools, resources, prompts), `Tool::read()` / `Tool::mutating()`,
`ToolRegistry` поверх реестра модулей, `webx:mcp-tools`. Транспорт — `laravel/mcp` по Streamable
HTTP на `{api_path}/mcp`. Подключение агента — OAuth через Passport с экраном согласия, `mcp_grants`;
программы — ключами (`mcp_keys`, `webx:mcp:token`); журнал каждого вызова — `mcp_calls`. Инструмент
вне областей ключа в `tools/list` не попадает.

Открыто: очередь подтверждений изменяющих операций (§12–13 спеки).

### `webx-ui/routing` — реестр адресов сайта

Спека — [`WEBX_UI_ROUTING.md`](WEBX_UI_ROUTING.md), гайд — `apps/docs/guide/routing.md`.
Адресное пространство **плоское**: страница, рубрика, категория и товар лежат в одном корне и
конфликтуют между собой, внутри одного модуля это не решить. `routes` — строка на адрес с
уникальностью `(locale, path)`; `HasUrl` + `RouteTypes::register()` — вся интеграция модуля;
форматтеры подменяются конфигом; разбор за `Route::fallback()`, найденное — в
`Resolution::of($request)`. Забронированные адреса проверяются при сохранении.

Стык с SEO: `UrlNormaliser` живёт здесь (одно написание адреса на обе половины), алиасы отдаются
панели контрактом `RouteAliases` и показываются в `module-seo` вкладкой «Автоматические».

### `webx-ui/themes`, `webx-ui/theme-default` — темы сайта

Спека — [`WEBX_UI_THEMES.md`](WEBX_UI_THEMES.md), гайд — `apps/docs/guide/themes.md`. Сайт не
копирует тему, а стоит на ней слоями: `resources/views` сайта → локальная `theme/` (только
отличия) → пакетная тема → вьюхи модулей. Обновление темы или модуля приезжает `composer update`,
потому что ничего не скопировано. `themes` — движок: цепочка, словарь токенов, `@webxTheme`,
`theme_token()`, команды `webx:theme:*`, проверка CSS на токены, `Testing\ThemeContract`.
`theme-default` — значение каждого токена, оболочка страницы, типографика прозы; нейтральная точка
старта, написанная, чтобы её перекрывали. Каждый новый сайт `webx:setup` получает свою `theme/`.

### `webx-ui/widgets` — виджеты сайта

Спека — [`WEBX_UI_WIDGETS.md`](WEBX_UI_WIDGETS.md), гайд — `apps/docs/guide/widgets.md`.
Повторяющиеся интерактивные куски — меню, шапка, диалоги, вкладки, аккордеон, согласие на cookie,
контакты, переключатель языка, слайдер, лайтбокс, видео, карта, формы — сделаны один раз: логика,
клавиатура, ARIA и поведение без JS готовы, внешний вид — скелет на токенах, который перекрашивает
тема. Страница грузит только виджеты, которые на ней стоят. В цепочке тем стоит на нижнем слое,
как модуль. Открыто — формы (W6, §17–§18 спеки).

## Каркас панели

### `webx-ui/module-admin` — каркас

Контракт `Module` + `AbstractModule`, `ModuleRegistry`, манифест `GET /api/cms/manifest`,
catch-all SPA, `ApiResponse` (пагинация Laravel как есть, 422). Общий слой для всех разделов:
экраны как описание ([`WEBX_UI_SCREENS.md`](WEBX_UI_SCREENS.md)), черновики и версии
(`HasDraft`, `HasVersions`), типы полей (`wx-rich-text`, `wx-link`, `wx-slug`, `wx-collection`,
`wx-relations`), общие категории, `LinkSource`, `CollectionSource`, связи `cms_relations`,
`RecordQuery` для хелперов шаблона, загрузка по кускам, журнал изменений
([`WEBX_UI_HISTORY.md`](WEBX_UI_HISTORY.md)), панель на сайте
([`WEBX_UI_SITE_BAR.md`](WEBX_UI_SITE_BAR.md)), ночные дампы (`apps/docs/guide/backups.md`),
`webx:setup`, `webx:doctor`, `webx:boot`, `webx:demo` ([`WEBX_UI_NEW_SITE.md`](WEBX_UI_NEW_SITE.md)).
Сайт без публичной части — `WEBX_PUBLIC=false`.

#### Пароль на сайт на время тестирования

Сайт на публичном домене до открытия закрывается HTTP Basic — весь, кроме панели, её JSON, MCP и
предпросмотра. Как включить — `apps/docs/guide/new-site.md`. Решения:

- **Место — `module-admin`, а не `module-auth`:** отвечать надо раньше маршрутизации, без сессии и
  без запроса в базу.
- **Глобальный middleware `Gate\CloseSite`** через `Kernel::pushMiddleware` в `booted()`: адрес без
  маршрута до группы `web` не доходит, а калитка, которая пропускает все 404, — не калитка. Стоит
  всегда и читает выключатель на каждом запросе; `module-admin` грузится раньше `module-seo`, так
  что калитка стоит перед редиректами и не выдаёт, какие адреса переехали.
- **Кого пускают — реестр `Gate\Openings`:** каждый пакет сам знает, где он отвечает
  (`module-admin` — панель, API, `/.well-known/*`, маски `webx-admin.gate.except`; `mcp` — свой
  путь и OAuth, агент не умеет отвечать на Basic; `module-blocks` — предпросмотр **только с
  валидным токеном**, сцена блока и бандлы). Приём заявок `module-inbox` исключением не становится.
- **Пары — только из окружения** (`WEBX_SITE_GATE`, `WEBX_SITE_GATE_USERS`), без экрана настроек:
  выключатель, которым можно запереть себя, живёт рядом с `APP_DEBUG`. Включено без пар — закрыто
  для всех. Пароль хранится как написан: хеш спасает только при утечке `.env`, где уже `APP_KEY`, а
  bcrypt на каждый запрос стоит десятки миллисекунд.
- **Ссылки-пропуска нет:** секрет в адресной строке уходит в историю, мессенджер и реферер.
- **Ответ** — 401 с `WWW-Authenticate`, `noindex`, `no-store` и `Vary: Authorization` (и у
  пропущенной страницы тоже — иначе общий кеш отдаст её следующему). Статика мимо PHP открыта.
- **`webx:doctor`:** включено без пар — ошибка; с парами — `ok` с напоминанием (не
  предупреждение: `--strict` роняет деплой закрытого тестового сайта); конфиг без блока `gate` при
  включённом окружении — ошибка. Проверка — `GateTest`, `OAuthDoorTest`, фаза `closed` в
  `scripts/php-smoke.sh`.

### `webx-ui/module-auth` — авторизация

Гайд — `apps/docs/guide/admins.md`. Своя таблица `cms_users` и guard `cms` — администратор не
пользователь сайта. Роли свои, без `spatie/laravel-permission`: права объявляют модули в
манифесте, и таблица permissions была бы второй, расходящейся копией. Sanctum в cookie-режиме.
Установка пакета сама закрывает API панели. Лог попыток входа с поиском всплесков неудач. Здесь же
экраны доступа агентов: согласие OAuth, подключённые агенты, ключи программ, журнал вызовов.

Открыто: восстановление пароля, 2FA, приглашения. MCP намеренно не выдаёт токенов и не меняет
пароли.

### `webx-ui/module-settings` — настройки сайта

Гайд — `apps/docs/guide/settings.md`, экраны — [`WEBX_UI_SCREENS.md`](WEBX_UI_SCREENS.md).
Значения, которые не принадлежат ни одной записи. Первый потребитель экранов как описания: экран
`settings.index` — JSON-дерево пакета, проект и модули кладут поверх свои вкладки патчем;
сохранение идёт по описанию — ключ, которого нет в дереве, не пишется ни формой, ни MCP. Вкладки
«Брендинг» и «Контакты» появляются, только когда их кто-то читает. Название и логотип каркас
берёт через `BrandingSource`, так что `module-admin` этот модуль не требует. Правила контента для
агентов — ресурс `settings://content-rules`. В шаблонах — `settings()`.

## Разделы: основа сайта

### `webx-ui/module-media` — файловый менеджер

Спека — [`WEBX_UI_MODULE_MEDIA.md`](WEBX_UI_MODULE_MEDIA.md), гайд — `apps/docs/guide/media.md`.
Папки деревом на `nested-set`, файлы с метаданными на любом диске Laravel, загрузка, правка
картинок, `wx-media-picker` для любой формы. MCP — папки, поиск, перенос, переименование,
удаление, загрузка по ссылке, оптимизация картинок. Открыто (§14 спеки): `mediables`, корзина,
права на папки, поиск неиспользуемых файлов.

### `webx-ui/module-blocks` — конструктор блоков

Спека — [`WEBX_UI_MODULE_BLOCKS.md`](WEBX_UI_MODULE_BLOCKS.md) (компоненты блоков — §24), зоны
лейаута — [`WEBX_UI_LAYOUT_REGIONS.md`](WEBX_UI_LAYOUT_REGIONS.md), общие блоки —
[`WEBX_UI_BLOCK_FRAGMENTS.md`](WEBX_UI_BLOCK_FRAGMENTS.md); гайды — `blocks.md`,
`layout-regions.md`. Тип блока создаётся в панели целиком (поля, Blade, CSS, скрипт); содержимое
любой сущности — массив блоков, рендер печатает его на сайте.

- **Правда в базе**, а не в сгенерированных файлах: деплой из репозитория снёс бы сделанное в
  панели. Переносимость — `webx:blocks:export` / `import`.
- Вложенность — поле `wx-blocks`, а не сущность. Blade правится из панели осознанно: раздел
  приравнен по правам к доступу на деплой.
- Предпросмотр — `/_preview/{type}/{id}` с подписанным токеном, один для фрейма, «Открыть на
  сайте» и телефона.
- Модули предлагают свои типы документом (`webx:blocks:offered --install`), а не миграцией.
- Агент правит содержимое точечно `blocks_edit_content` (операции по ключам, `revision` против
  затирания, §18.1) — второго способа не заводим.

### `webx-ui/module-pages` — страницы

Спека — [`WEBX_UI_MODULE_PAGES.md`](WEBX_UI_MODULE_PAGES.md), гайд — `apps/docs/guide/pages.md`.
Первый модуль, собранный из соседей: дерево (`nested-set`), адрес из реестра (`TreePath`, политика
`Fail`), содержимое блоками, черновик и версии, SEO. Главная — корневой узел с пустым слагом; её
ограничения отдаются возможностями узла (`can.*`), а не признаком «корень». Удаление мягкое,
веткой. Тело страницы агент правит `blocks_edit_content`.

### `webx-ui/module-menu` — меню

Спека — [`WEBX_UI_MODULE_MENU.md`](WEBX_UI_MODULE_MENU.md), гайд — `apps/docs/guide/menu.md`.
Именованные меню деревом на `nested-set`, подписи переводимые, меню одно на все языки. Цель пункта —
сущность из реестра, свой адрес или никуда. Меню объявляет конфиг, администратор может завести
своё. Наружу — данные (`menu('header')`) с кешем на меню и язык; блок «Меню» для зон лейаута.
Контракт «на что можно сослаться» (`LinkSource`, `wx-link`) живёт в `module-admin`: меню —
потребитель, а не владелец.

### `webx-ui/module-seo` — SEO: раздел панели и рендер `<head>`

Спека — [`WEBX_UI_MODULE_SEO.md`](WEBX_UI_MODULE_SEO.md), гайд — `apps/docs/guide/seo.md`.
**Один пакет, а не библиотека плюс раздел:** рендеру без раздела рисовать нечего (CLAUDE.md §1).
Шов держится внутри — `WebxUi\Seo\Rendering\` и `WebxUi\Seo\Panel\`, источники через контракт
`SeoSource`; разрез, если понадобится, механический. Правила адресов (`seo_urls`), редиректы
глобальным middleware (не группой `web`), мерж источников **по полям**, `HasSeo` / `seo_meta`,
`/robots.txt`, `/sitemap.xml` по типам реестра, hreflang, крошки, schema.org сущностей, контакты в
микроразметке. Открыто (§16): лог 404, схлопывание цепочек редиректов, форма правила как экран.

### `webx-ui/module-inbox` — формы и заявки

Спека — [`WEBX_UI_MODULE_INBOX.md`](WEBX_UI_MODULE_INBOX.md), гайд — `apps/docs/guide/inbox.md`.
Форма собирается в панели, посетитель отправляет, получатели получают письмо, у заявки статус,
ответственный и заметки. Поле формы — строка в таблице, а не узел экрана; значение хранит снимок
поля. Приём — своя дверь вне CSRF, антиспам без капчи, заявка сохраняется **до** писем. Вложения —
на приватном диске, отдача через панель. Агенту приём не отдаётся — дверь и так публичная.
Открыто: канбан; перевод публичной формы на формы `webx-ui/widgets` (W6.4).

### `webx-ui/module-audit` — аудит сайта

Спека — [`WEBX_UI_MODULE_AUDIT.md`](WEBX_UI_MODULE_AUDIT.md), гайд — `apps/docs/guide/audit.md`.
Раздел «Аудит» в группе «Система»: обход своего сайта, снимок каждой страницы и около ста проверок
без внешних сервисов — от конфига продакшена и зеркал до title, canonical, JSON-LD, битых ссылок и
сирот. Модули приносят проверки и исправления контрактами `AuditCheck` / `AuditFix`. Ставится по
умолчанию. Внешние поставщики (платные API) — спутниками, когда понадобятся; открытое — §12 спеки.

## Разделы: контент

Общее у всех: категории — общим кодом `module-admin` с данными в своей таблице; поля проекта —
патчем на экран формы и колонкой `extra`; хелпер шаблона на общем `RecordQuery`; тип блока
приезжает документом; SEO-карточка — патчем `module-seo`; права `<id>.view` / `<id>.manage`; MCP —
`<id>_*` через те же двери, что у панели, и ресурс `<id>://catalog`.

### `webx-ui/module-blog` — блог

Спека — [`WEBX_UI_MODULE_BLOG.md`](WEBX_UI_MODULE_BLOG.md), гайд — `apps/docs/guide/blog.md`.
Статьи из блоков, плоские рубрики, теги сотнями. Адреса `{prefix}/{slug}` для статьи и рубрики в
одном пространстве, `{prefix}/tag/{slug}` для тега. Дата вместо планировщика: будущая
`published_at` — 404 на сайте и «Запланирована» в панели. Теги сливаются с редиректами; тег в
индексе, только когда на его адрес написано правило SEO.

### `webx-ui/module-services` — услуги

Спека — [`WEBX_UI_MODULE_SERVICES.md`](WEBX_UI_MODULE_SERVICES.md), гайд — `apps/docs/guide/services.md`.
Услуга устроена как страница (блоки, адрес, полное SEO), категория — тоже страница. Адреса плоские

### `webx-ui/module-faq` — вопросы и ответы

лимит, разметка), а вопросы читает на рендере (`CollectionSource`, первый потребитель). Вопрос виден

### `webx-ui/module-reviews` — отзывы

`Review` нет вовсе (решение 3 спеки). Блок — один, сетка, слайдер, бегущая строка; движение стоит

### `webx-ui/module-recipes` — рецепты

Спека — [`WEBX_UI_MODULE_RECIPES.md`](WEBX_UI_MODULE_RECIPES.md), гайд — `apps/docs/guide/recipes.md`.

### `webx-ui/module-events` — события

### `webx-ui/module-banners` — баннеры
