# `webx-ui/routing` — спецификация

Реестр публичных адресов сайта: одна таблица, в которой каждая адресуемая сущность занимает свой
путь, и один резолвер, который по пути находит, кому отдать запрос. Библиотека, а не раздел
панели. Реестр пакетов — [`WEBX_UI_COMPOSER_PACKAGES.md`](WEBX_UI_COMPOSER_PACKAGES.md), SEO —
[`WEBX_UI_MODULE_SEO.md`](WEBX_UI_MODULE_SEO.md), экраны — [`WEBX_UI_SCREENS.md`](WEBX_UI_SCREENS.md).

Статус: выпущен (§16), все адреса демо приходят из реестра; отложенное — §17; язык первого
захода и плашка-предложение — выпущены, §18 (webx-ui#135). Гайд — `apps/docs/guide/routing.md`.

Реестр отдельно от модулей, потому что адресное пространство у нас **плоское** и общее: страница,
рубрика, категория и товар лежат в одном корне. Решать это внутри модуля страниц нельзя — модуль
не видит чужих адресов, а именно они и конфликтуют.

## 1. Границы

Пакет владеет **тремя вопросами**:

1. Какой путь у этой сущности (форматтеры, §4) и свободен ли он (§5).
2. Кто отвечает по этому пути (реестр типов и резолвер, §6, §8).
3. Что делать со старым путём после переименования (алиасы, §9).

Пакет **не** владеет: содержимым страниц, публикацией и черновиками (это знает сущность, §8),
мета-разметкой и ручными редиректами (`module-seo`), языком запроса (`localization`), деревом
(`nested-set`).

Пакет **не знает ни одного имени модуля**. Страницы, статьи, категории и товары приходят к нему
регистрацией типа; приставка `/article/` — это формат сегмента у модуля новостей, а не понятие
роутинга.

### Почему библиотека, а не `module-*`

По правилу именования (CLAUDE.md §1) `module-*` — то, из чего состоит панель. У реестра своего
раздела нет и не нужно: экран «все адреса сайта» логично живёт в разделе SEO, рядом с правилами и
редиректами. Публичная часть при этом использует реестр сама по себе — это ровно случай
`nested-set` и `localization`. npm-пары у пакета нет.

Важнее другое: от реестра зависит каждый контентный модуль. Если положить его в `module-seo`, то
раздел начнёт зависеть от раздела, а установить страницы без SEO станет нельзя.

## 2. Принятые решения (не переоткрывать)

1. **Адресное пространство плоское.** `/about`, `/about/mission`, `/blog`, `/parts`,
   `/alternator-belt-7100104` — один корень, одно пространство имён, уникальность общая для всех
   типов. Модульных приставок (`/pages/*`, `/catalog/*`) нет.
2. **Путь хранится целиком и строкой.** Не вычисляется на лету из дерева: вычисление не даёт ни
   индекса, ни общей уникальности, ни ответа «что живёт по этому адресу» для соседнего модуля.
3. **Адрес строит сущность, реестр получает готовое.** Формат — форматтер типа (§4), подменяемый
   проектом. Роутинг не разбирает адрес на части и не угадывает id на конце.
4. **Разрешённый суффикс возвращается в `slug` сущности** (§5). Реестр не хранит адрес, которого
   нет в форме: иначе редактор видит одно, сайт отдаёт другое, а следующее сохранение всё
   пересчитывает.
5. **Автоматические следы переезда — алиасы в реестре, ручные правила — в `module-seo`.**
   Разное происхождение и разный жизненный цикл (§9, §12). Видны редактору в одном месте — на
   экране редиректов, вкладкой только для чтения.
6. **Ручное правило-редирект старше живого содержимого.** `RedirectRequests` остаётся глобальным
   middleware и срабатывает до маршрутизации. Правило редактор пишет осознанно; панель лишь
   предупреждает, что адрес занят (§12).
7. **Точное совпадение бьёт префиксное** (§8). Поэтому `/about/mission` — своя страница, а не
   хвост `/about`.
8. **Хвост принимает тип, а не строка.** Отдельной колонки нет: `accepts_tail` берётся из
   регистрации типа по `entity_type`. Категория принимает фильтры, страница — нет.
9. **Состояния публикации в реестре нет.** Строка есть у всего, что существует; показывать или
   нет, решает сущность (§8). Две копии одного состояния разъедутся.
10. **Язык — колонкой, путь — без языковой приставки.** Маршруты объявляются внутри `{locale?}`,
    как это уже делает `SetLocale`; резолвер получает хвост без приставки. Для одноязычного сайта
    все строки в дефолтном языке, и это ничего не меняет.
11. **Алиас ссылается на строку-канон (`target_id`), а не на текст пути.** Второе переименование
    не создаёт цепочку 301 → 301.
12. **Живой канон вытесняет алиас.** Создание страницы на адресе, который занят следом от
    переезда, разрешено: алиас удаляется. Содержимое важнее следа.
13. **Кеша у резолвера нет.** Один индексный запрос на запрос страницы дешевле, чем инвалидация
    полумиллиона строк.
14. **Страница без перевода остаётся на месте — где тип так решил** (§8.7). Нет строки в языке — это по-прежнему «нет перевода»; но тип, заявивший
    `showsUntranslated`, отвечает под префиксом выбранного языка путём языка по умолчанию:
    интерфейс — на выбранном языке, содержимое — на языке по умолчанию, `noindex` и canonical на
    оригинал. Реестр при этом строк не заводит: показ без перевода — ответ резолвера, а не адрес.

## 3. Схема

### `routes`

```
id            bigint
locale        string(12)         -- код BCP-47, как в `locales`
path          string(255)        -- '' для главной, без ведущего слэша, нижний регистр
kind          string(16)         -- canonical | alias (16, а не 8: дефолт 'canonical' длиннее)
target_id     bigint nullable    -- у алиаса: строка-канон, FK на routes.id, on delete cascade
entity_type   string(32)         -- алиас morph map: page | rubric | article | category | product
entity_id     bigint
timestamps

unique (locale, path)
index  (entity_type, entity_id)
index  (target_id)
```

Почему так:

- **`path` — 255, а не 2048.** Длинную колонку нельзя проиндексировать переносимо, а весь смысл
  этой таблицы в уникальном индексе. 255 символов utf8mb4 (1020 байт) вместе с `locale` укладываются
  в 3072 байта префикса InnoDB на DYNAMIC. Адрес длиннее — ошибка валидации при сохранении, а не
  молчаливая обрезка.
- **Нижний регистр — при записи и при разборе.** Сравнение в MySQL и так регистронезависимое, но
  колонка должна быть детерминированной: иначе два импорта создают `/Parts` и `/parts` как одну
  строку в базе и как два разных адреса в карте сайта.
- **`path` без ведущего слэша.** Иначе главная — это `/` или `''`, и два места в коде выберут
  по-разному. Пусто значит главная.
- **`entity_type` — алиас morph map, не имя класса.** Имя класса в базе ломается первым же
  переездом между namespace. Карту заполняет `RouteTypes::register()` — но `morphMap()`, а не
  `enforceMorphMap()`: второе включает требование карты для **всех** полиморфных связей
  приложения, включая написанные проектом до установки пакета. Нашей колонке это ничего не
  добавляет — `getMorphClass()` отдаёт алиас, как только он в карте.
- **Алиас несёт `entity_type`/`entity_id` тоже.** «Все адреса этой сущности» — один запрос,
  каскадное удаление — тривиально.
- **Отдельного индекса под префиксный поиск нет**: запрос из §8 идёт по `unique (locale, path)`.

## 4. Как строится адрес: форматтеры

`PathFormatter::format(Model $entity, string $locale): string` — путь без ведущего слэша и без
языковой приставки; `''` — корень сайта. В пакете:

| Форматтер                          | Результат                       | Кому                                          |
| ---------------------------------- | ------------------------------- | --------------------------------------------- |
| `Slug`                             | `about`                         | рубрики, категории                            |
| `TreePath`                         | `about/mission`                 | страницы (цепочка предков через `nested-set`) |
| `SlugId`                           | `alternator-belt-7100104`       | статьи, товары                                |
| `SlugSku`                          | `hydraulic-oil-filter-46969598` | товары                                        |
| `Prefixed('article', Slug::class)` | `article/kak-vybrat-remen`      | статьи под приставкой                         |

Форматтер — **чистая функция от сущности**, и это не стилистика, а три требования:

1. Обсервер (§7) и `webx:routes:rebuild` (§11) обязаны считать одно и то же — иначе пересборка
   молча переселит половину сайта.
2. Форма показывает живой предпросмотр адреса до сохранения.
3. Смена схемы адресов у типа — одна команда: `webx:routes:rebuild --type=product` пересчитывает
   пути и оставляет старые алиасами. Ни одна внешняя ссылка не умирает.

Проект подменяет форматтер типа конфигом, не трогая модуль, — под это и заведён
`webx-routing.types.<type>.formatter`.

## 5. Уникальность и суффиксы

**Слаг — только ASCII.** Правило платформы, а не фидов: `HasLatinSlug` (пакет `localization`,
`HasUrl` подключает его сам) на `saving` приводит записываемый слаг к латинице через
`Slug::latin()` с учётом языка значения. Панель, обмен, MCP и прямой `save()` проходят через модель,
поэтому правило одно. Пустой результат — `<тип>-<id>` (`product-123`); у новой записи id ещё нет,
она вставляется с заглушкой и получает слаг сразу после вставки, до обращения к реестру.
Слаг, который не меняется в этом сохранении, не трогаем: лежащие в базе переводит
`webx:slugs:latin`. Уникальность и
суффиксы ниже работают уже после приведения.

Плоское пространство означает, что `Str::slug()` от названия — штука неуникальная: «Ремень
приводной» встретится в каталоге десять раз. Политика — на тип:

- **`fail`** — сохранение падает валидацией на поле slug. Страницы, рубрики, категории: адрес там
  делают осознанно, молча переезжать на `-2` он не должен.
- **`suffix`** — `base` занято → `base-2`, `base-3`. Импорт товаров пачкой: иначе он встанет на
  первом дубле и половина каталога не приедет.

Как считается суффикс: один запрос `where locale = ? and path like 'base%'` (префиксный LIKE идёт
по индексу), в PHP берётся максимальный существующий суффикс, плюс один. Гонку двух параллельных
импортов ловит уникальный индекс — поймали нарушение, пересчитали, повторили (ограниченный цикл).
Индекс здесь настоящая гарантия, подбор — быстрый путь.

Разрешённое значение возвращается в `slug` сущности (решение 4 из §2), и только потом форматтер
строит путь. У `SlugId` и `SlugSku` коллизия структурно невозможна, поэтому для них `fail`
безопасен.

## 6. Регистрация типа

По образцу `SeoSources` из `module-seo`: синглтон, заполняемый из провайдеров, сортировка и чтение
на месте использования.

```php
RouteTypes::register(new RouteType(
    type:        'product',              // morph alias
    model:       Product::class,
    formatter:   SlugSku::class,
    handler:     ProductPage::class,
    acceptsTail: false,
    onConflict:  OnConflict::Suffix,
));
```

`RouteHandler::handle(Request $request, object $entity, string $tail): Response` — `$tail` то, что
осталось от пути после найденной строки; `''` при точном совпадении.

`acceptsTail: true` — это весь ответ про фильтры каталога. `/filtri-mastila` лежит в реестре одной
строкой, а `category-remeni/brands-bobcat/stock-in-stock` приезжает в обработчик хвостом.
Грамматика `{facet}-{value}` — дело каталога; роутинг про неё не знает.

## 7. Запись: `HasUrl` и обсервер

Трейт на модели, по образцу `HasTranslations`: `routePath()` — канонический путь от форматтера,
`routes()` — все строки реестра сущности (канон и алиасы), `url()` — публичный адрес с языковой
приставкой, если стратегия `prefix`.

Синхронизация — обсервер, **на `created`/`updated`, внутри той же транзакции**:

- **`created`, а не `saving`.** У `SlugId` идентификатора до вставки просто нет.
- **`updated`** — пересчитать путь; изменился → старый становится алиасом, новый каноном.
- **Дерево.** Переехал узел или сменился его slug — пересчитать всех потомков (`nested-set`
  отдаёт поддерево дёшево) и каждому оставить алиас.
- **`deleted`** — строки уходят: адреса перестают отвечать и освобождают пути. Мягкое удаление
  перед этим откладывает алиасы в `routes_trashed`; окончательное уносит и их.
- **`moved`** — **своё событие в `nested-set`**, добавленное ради этого. Перемещение узла
  переписывает границы пачкой `update`, а не сохранением моделей (в том и смысл), поэтому
  `updated` при переезде не стреляет вообще: без нового события страница, перетащенная мышью,
  сохранила бы старый адрес до следующего сохранения.
- **Канон восстанавливается без своего события.** `restore()` — это `save()` модели, у которой
  `deleted_at` вернулся в null, то есть `updated` уже отработал; отказ по занятому адресу
  возвращает сущность в корзину там же. **`restored`** после него возвращает отложенные алиасы
  (§9).

**Отказ откатывает сохранение, а не только адрес.** Адрес считается после вставки, значит к
моменту отказа строка в таблице уже есть: `created` удаляет её, `updated` возвращает прежние
значения (`getRawOriginal()` ещё держит их — `syncOriginal()` идёт после события). Иначе slug в
таблице говорил бы одно, реестр — другое, и следующее сохранение закрепило бы расхождение.

Массовый импорт обсервером не идёт: `RouteSync::bulk(iterable $entities)` пишет пачками одним
upsert. Путь считает тот же форматтер — общий код, разные объёмы.

## 8. Разбор запроса

1. **Маршруты проекта выигрывают сами.** `/sign-up`, `/account/*`, `/search` — обычные маршруты.
   Реестр подключается через `Route::fallback()`, а он по определению пробуется, когда не совпало
   ничего. Никакой возни с порядком регистрации и никакого catch-all, который затеняет чужое.
   Конфиг `webx-routing.fallback` позволяет выключить регистрацию и позвать резолвер из своего
   маршрута — провайдер пакета грузится раньше провайдеров приложения, так что своим fallback
   проект наш не перебьёт.
2. **Нормализация.** Срезать слэши, в нижний регистр, query отбросить: query — это для правил SEO,
   не для тождества адреса. Если нормализованное написание отличается от пришедшего — 301 на
   нормализованное, query сохранить. Как пишется адрес, решает контракт `Contracts\Spelling`:
   по умолчанию — `RegistrySpelling` (один слэш, без слэша в конце, нижний регистр, файл
   сохраняет регистр). С `module-seo` его занимает `SeoSpelling` — те же настройки вкладки
   «Один адрес на страницу» и та же функция, что у middleware нормализации, поэтому её один 301
   уже ведёт туда, где резолвер не редиректит второй раз. Сохранённое «оставить как есть»
   выполняется; часть, которую никто не сохранял, ведёт себя как реестр.
3. **Один запрос.** Путь `a/b/c` даёт кандидатов `a/b/c`, `a/b`, `a`, `''`:

   ```sql
   select * from routes where locale = ? and path in (?, ?, ?, ?)
   ```

   В PHP: сортировка по длине убыванием, берём первую строку, которая либо точное совпадение,
   либо тип которой `acceptsTail`. Кандидатов не больше шести — глубже адресов у нас не бывает, а
   ограничение всё равно нужно, чтобы запрос на `/a/b/c/…/z` не разросся.

4. **`alias`** → 301 на текущий путь канона; если совпадение было префиксным, хвост приклеивается
   к новому пути. То есть переименованная категория уводит и свои страницы фильтров.
5. **`canonical`** → тип по `entity_type` → модель → обработчик. Он получает сущность и хвост.
6. **Публикацию проверяет обработчик**, а не реестр: у сущности это состояние уже есть. Черновик
   отвечает 404 всем, кроме предпросмотра по токену.
7. **Нет строки в языке — страница без перевода** (решение 14). Запрос пришёл с префиксом языка,
   который не язык по умолчанию, и ничего не нашёл. Тогда тот же путь ищется ещё раз — в языке
   по умолчанию, и находка принимается, только если это канон, его тип заявил
   `showsUntranslated: true` в `RouteType`, а у сущности нет своей канонической строки в
   спрошенном языке:

   - **Перевод есть, но с другим адресом** (`/ru/about`, а русская страница — `/ru/o-nas`) —
     301 на русский адрес: читатель угадал страницу, а не её написание.
   - **Перевода нет** — сущность уходит обработчику как обычно, а `Resolution` несёт метку:
     `locale` — язык, на котором спросили, и `isUntranslated()` — что строка из другого языка.
     Язык запроса ставит `webx.locale` по префиксу, поэтому шапка, подвал, слова виджетов и даты
     — на выбранном языке, а переводимые поля сущности сами падают по цепочке `Locales::chain()`
     на язык по умолчанию. Плашки «не переведено» нет: клиенты переводят сразу, случай редкий.
   - **SEO** такого ответа (§12.5): `noindex` и canonical на адрес в языке по умолчанию; в
     `hreflang` и в карту сайта он не попадает сам — у сущности нет строки в этом языке.

   Адрес такой страницы — `Untranslated::path($entity, $locale)`: префикс языка плюс путь
   канона по умолчанию; `null`, когда у сущности есть своя строка, тип не заявил, сущность скрыта,
   язык не в пути (`strategy` не `prefix` — один адрес на все языки, noindex закрыл бы оригинал)
   или путь в этом языке занят чужой строкой — она выигрывает, и ссылка туда вела бы на чужую
   страницу. Тот же класс отвечает модулю SEO и переключателю языка (WIDGETS §13), чтобы три места
   не разошлись.

   **Заявляют не все.** `module-pages` — да: страница — оформление сайта, и прочитать её на языке
   по умолчанию лучше, чем попасть на главную. Статьи блога — нет, вопрос открыт (§17): статья без
   перевода, возможно, должна прятать язык в переключателе, а не показываться на чужом языке.
   Остальные модули решают каждый за себя, по умолчанию — `false`, то есть как раньше.

8. Не нашли — спрашиваются обработчики промахов (`Misses::register(MissHandler::class)`) в
   порядке регистрации: модуль, которому адрес когда-то принадлежал, может ответить сам. Первый
   потребитель — каталог: `/{что-угодно}-{id}` живого товара — 301 на каноническое написание без
   алиаса на каждое переименование, удалённого — 301 в категорию или 410, слаг удалённой
   категории — 410. Никто не ответил — обычный 404. Ручные редиректы `module-seo` к этому моменту
   уже отработали, они глобальные и до маршрутизации.

Стоимость: один индексный запрос плюс загрузка сущности. Кеша нет (решение 13 из §2).

## 9. Алиасы

Создаются автоматически при смене пути (§7) и живут, пока жива сущность. Отдают **301** — и это
причина, по которой они должны быть правильными: постоянный редирект браузер запоминает надолго,
и ошибочный алиас стоит дороже ошибочного правила.

Чего у них нет и почему:

- **Цепочек.** `target_id` смотрит на строку-канон, а не на путь; после второго переименования
  алиас продолжает вести на актуальный адрес без обхода таблицы.
- **Бессмертия.** Удалили сущность — ушли и алиасы (`on delete cascade`). Строка в
  `seo_redirects` пережила бы удаление и вела бы в никуда; такого мусора со временем набирается
  больше, чем живых правил.
- **Потери при отмене удаления.** Корзина — это отменяемое удаление, и отмена, после которой
  старые ссылки сломаны, отменила бы его наполовину. Поэтому мягкое удаление откладывает алиасы в
  `routes_trashed`: там они ничего не отвечают и путей не держат — другая сущность вправе занять
  путь, пока эта в корзине. Восстановление возвращает каждый отложенный алиас, путь которого
  свободен и в языке которого у сущности снова есть канон; занятые остаются у новых хозяев, и
  ответ восстановления их называет (`RouteSync::revival()`, у страниц — `aliases_dropped`).
  Окончательное удаление уносит и отложенные.
- **Приоритета над живым.** Создание канона на занятом алиасом адресе вытесняет алиас (решение 12).

Ограничение роста: переезд ветки каталога — это тысячи алиасов за один клик. Храним все и смотрим
на объём; порог на сущность или по возрасту — в §17.

## 10. Забронированные адреса

Проверяются **при сохранении**, а не при разборе: молча проиграть живому маршруту хуже, чем
отказать редактору сразу.

1. **Опрос роутера.** Есть ли у проекта маршрут под этот путь (метод GET), кроме fallback. Список
   сам остаётся правдой, когда проект добавит новый экран.
2. **Список в конфиге** — для того, что маршрутом не выражено: `storage`, каталоги в `public`,
   зарезервированное на будущее.

Отдельно закрыты адреса панели: `webx-routing.reserved` наследует префикс панели из
`module-admin`, как это уже делает `RedirectRequests`.

## 11. Команды

- `webx:slugs:latin` — слаги не в ASCII: без флагов только список «было → стало», `--apply` переводит
  и пишет 301 через `AddressRedirects` (`module-seo`), потомков дерева тоже. Без `module-seo` слаги
  переводятся, отчёт говорит, что редиректы не созданы; старые адреса держат алиасы реестра. Занятый
  адрес — запись остаётся как есть, код выхода 1. `webx:doctor` предупреждает, пока такие есть.
- **`webx:routes:rebuild [--type=] [--dry-run]`** — пересчитать пути форматтерами, показать
  разницу, создать алиасы на изменившиеся. Это же штатный способ сменить схему адресов типа.
- **`webx:routes:check`** — целостность: строки без сущности, сущности без строк, алиасы без
  канона, столкновения с живыми маршрутами проекта (проект добавил `/search` там, где лежит
  страница).

## 12. Стык с `module-seo`

1. **`UrlNormaliser` живёт в `WebxUi\Routing\`.** Одно написание адреса на обе половины;
   `module-seo` зависит от `routing`. `normalise()` — путь и query, без нижнего регистра: у него
   другая задача, чем у ключа реестра; ключ — `key()`: только путь, нижний регистр, без слэшей.
2. **Вкладка «Автоматические»** на экране редиректов: список алиасов, только чтение, поиск по
   пути, переход к сущности. Данные — через узкий контракт `RouteAliases` (постранично, с
   фильтром), чтобы `module-seo` не лез в таблицу напрямую. Это третий пункт переключателя
   «Правила | Редиректы» (`/seo/aliases`), а не вкладка внутри экрана редиректов: там своя
   пагинация и свой поиск, а вкладка, которая молча сбрасывает и то и другое при возврате, хуже
   второго адреса. Переход — на живой адрес сущности (`target_url`), а не на её экран в панели:
   карты «тип → экран редактирования» нет (§17).

3. **Предупреждение о затенении.** При сохранении ручного правила панель проверяет реестр и
   говорит, что адрес занят живой страницей. Не запрещает (решение 6), а показывает.
4. **`$subject` для `SeoSource`.** Резолвер кладёт найденную сущность в запрос; `module-seo`
   забирает её оттуда — это тот самый аргумент, под который интерфейс уже написан.
5. **Страница без перевода (§8.7)** — `Seo::for()` спрашивает `Untranslated` по сущности и языку,
   а не метку запроса: тот же ответ получает и `POST /test-url`, у которого запроса страницы нет.
   Если сущность показана без перевода, `robots` — `noindex, follow`, canonical — её адрес в языке
   по умолчанию, поверх SEO-карточки и правил: карточка писалась для оригинала. `hreflang`
   закрытой страницы не печатается (как у любой `noindex`), а у оригинала такого языка нет —
   строки нет; карта сайта читает те же строки.

## 13. Кто ещё читает реестр

- Карта сайта `module-seo` — канонические строки плюс состояние сущности, через контракт.
- Выбор ссылки панели (`LinkSources` в `module-admin`) и меню — адрес сущности на языке
  рендера; языковой префикс к произвольному пути — `SiteUrl`.
- Хлебные крошки — путь и цепочка предков уже посчитаны.
- «Где используется» — обратный поиск по `entity_type`/`entity_id`.

## 14. MCP

Свои инструменты, а не хелперы для потребителей (в отличие от `nested-set`): адрес — это то, о чём
спрашивают снаружи.

- `resolve_url` — что живёт по адресу: тип, сущность, канон или алиас, хвост.
- `where_is` — адреса сущности.
- `find_conflicts` — вывод `webx:routes:check` в машинном виде.

## 15. Тесты

Форматтеры (`TreePath`, `SlugId` после вставки, `Prefixed`, свой форматтер проекта);
уникальность (`fail` роняет валидацию, `suffix` **возвращает значение в сущность**, параллельная
вставка ловится индексом); запись (алиас при переименовании, переезд ветки, удаление и
восстановление); разбор (точное бьёт префиксное, хвост, главная `''` не съедает чужие адреса,
алиас с хвостом, 301 на нормализованное с сохранением query); границы (маршрут проекта выигрывает,
забронированный адрес и адрес длиннее 255 не сохраняются); черновик — 404, предпросмотр — 200;
`rebuild --dry-run` ничего не пишет, `check` находит подброшенные поломки.

Отдельно — `scripts/php-smoke.sh`: fallback, глобальный middleware редиректов и автодискавери в
testbench не проверяются (`docs/pitfalls/laravel-and-php.md`). В smoke-приложении заводится
фиктивная сущность с трейтом, ставится страница на `/about` и проверяется, что она отвечает после
`config:cache`.

## 16. Выпуск

Выпущен вместе с вкладкой «Автоматические» в `module-seo`; первым потребителем стал
`module-pages` (тип `page`, `TreePath`, политика `Fail`). Что легло в код сверх написанного
выше и остаётся в силе:

- Событие `moved` в `nested-set` и откат отказанного сохранения (§7).
- `webx-routing.middleware` (`['web', 'webx.locale']`): `Route::fallback()` живёт вне групп и без
  этого не получает ни сессии, ни языка.
- `Resolution` — найденное кладётся в запрос объектом; из него `module-seo` берёт `$subject`.
- `Reserved` — отдельный класс: его спрашивают `UniquePath` при сохранении и `webx:routes:check`.
- `Resolver::lookup()` — «что у реестра по этому адресу» без ответа на запрос, и язык в нём
  **сайтовый**, а не язык панели. Предупреждение о затенении едет полем `route` в существующем
  `POST /test-url`.
- Страница без перевода (§8.7) и обработчики промахов (§8.8).

Открыто — §17.

## 17. Отложено

- **Порог на алиасы** (по возрасту или количеству на сущность) и команда чистки. Сначала посмотрим
  на объёмы после первого переезда крупной ветки.
- **Адреса длиннее 255.** Если понадобится — колонка-хеш рядом и уникальность по ней.
- **Мультисайт** — [`WEBX_UI_MULTISITE.md`](WEBX_UI_MULTISITE.md): уникальность `routes` становится
  `(site_id, locale, path)`. Пока сайты — разные базы, колонки нет.
- **Ручной редирект с целью-сущностью,** а не строкой: сейчас правило, ведущее на `/parts`,
  протухает, когда категорию переименуют. Реестр позволяет это починить, но это работа на стороне
  `module-seo`.
- **Карта «тип → экран редактирования»** в панели. Сейчас со строки реестра можно уйти только на
  живой адрес сущности; чтобы уйти на её форму, кто-то должен сказать, где эта форма живёт, — а
  сказать это может только контентный модуль. `module-pages` и следующие модули её не завели —
  переход на форму по-прежнему только из их собственных списков. Место для этого — `RouteType`
  или манифест модуля; решать, когда попросят.
- **Экран «все адреса сайта»** с картой пространства имён и поиском конфликтов. Пока хватает
  `webx:routes:check`.
- **Статья без перевода** (§8.7). Страницы показываются на языке по
  умолчанию под префиксом выбранного; статье это, возможно, не подходит — текст на чужом языке
  в ленте другого языка выглядит ошибкой. Вариант — переключатель прячет такой язык совсем.
  Пока у блога `showsUntranslated` нет, и переключатель на статье ведёт на главную языка, как
  раньше. Решать, когда спросит первый многоязычный сайт с блогом.
- **Страница без перевода при `strategy` не `prefix`.** Адрес один на все языки, и §8.7 там не
  включается: читатель на русском по заголовку получает 404. Показать
  оригинал без `noindex` можно, но это уже другое решение.
- **Кеш резолвера.** Появится, если профилирование на живом каталоге покажет, что один индексный
  запрос действительно чего-то стоит.

## 18. Язык первого захода

Задача webx-ui#135. Статус: выпущен. Код живёт в `localization` (настройка, кука, middleware) и
`widgets` (адрес той же страницы на другом языке, плашка-предложение у переключателя); раздел
здесь, потому что решение целиком держится на адресах реестра и §8.7. Редакция — по решениям
человека после ревью этапа 1: они сильнее первой редакции там, где расходятся.

Сценарий: основной язык сайта (`ru`) — без приставки, второй (`uk`) — под `/uk/`; по закону о
языке посетитель по умолчанию должен видеть версию на государственном языке. Человека, который
**впервые** пришёл на страницу не того языка, **один раз** переводят на **ту же страницу** нужного
языка и запоминают в куке, что это сделано; дальше его никто никуда не уводит — переключатель с
чистыми ссылками работает как раньше. Поисковые боты не перенаправляются никогда — обе версии они
видят по своим адресам, связанные `hreflang`. При повторных заходах на страницу не того языка можно
включить ненавязчивую плашку «Перейти на українську?» у переключателя (§18.6).

### 18.1. Решения

1. **Настройка — только конфиг**, `webx-localization.first_visit` (env), по умолчанию выключено;
   включает разработчик при запуске сайта (`WEBX_LOCALE_FIRST_VISIT=uk`). В панель и MCP не
   выносим: включают один раз, а ошибка там — редирект всех посетителей (§18.10).
2. **Источник целевого языка — только фиксированный код языка сайта** (`'uk'`). Варианта по
   `Accept-Language` нет. Значение не среди активных `locales` — функция молчит, `webx:doctor`
   говорит об этом.
3. **Только `strategy: prefix`.** При `header`/`none` у всех языков один адрес — вести некуда;
   middleware молчит, doctor предупреждает.
4. **Редирект — 302, `Cache-Control: private, no-store`**, никогда 301: это решение для
   конкретного человека, а не переезд адреса. Кука ставится в том же ответе.
5. **Только на ту же страницу.** Цель — ссылка `LanguageLinks` этого языка без пометки
   `fallback`: перевод (своя строка реестра) или показ без перевода §8.7
   (`Untranslated::path()`). Если у страницы в целевом языке есть только главная языка
   (`fallback`) — **редиректа нет и кука не пишется**: человек пришёл за этим товаром, а не за
   главной. Подтверждено человеком.
6. **Редирект — один раз за всё время.** Кука `webx_lang` значит «уже перенаправляли», а не «вот
   язык»: есть кука (с любым значением) — редиректа больше нет никогда, на какой бы язык человек ни
   зашёл. Значение — код целевого языка (для статистики и прокси), на поведение не влияет.
   Пишется ровно в одном ответе — редиректе. Обычный ответ куку не пишет. Язык в сессию не кладём.
7. **Параметры куки:** имя `webx_lang` (настраивается), год, `path=/`, `SameSite=Lax`, `HttpOnly`,
   `Secure` по `session.secure`, домен — `session.domain`. Без шифрования
   (`EncryptCookies::except`, как `webx_consent`): значение не секрет, а правило прокси или CDN
   должно уметь его прочитать. Категория согласия — `necessary` (WIDGETS §9.2).
8. **Переключатель не меняется.** Ни GET-параметров в ссылках, ни `rel`, ни скриптов записи
   выбора, ни проверок `Referer`: разметка при включённой настройке та же, что при выключенной.
   Раз кука уже стоит после редиректа, переход по чистой ссылке на основной язык работает сам.
9. **Где стоит — внутри `SetLocale` (`webx.locale`).** Он уже в стеке fallback-маршрута реестра
   (`webx-routing.middleware`) и маршрутов модулей (`webx-blog.middleware`, …), так что сайт не
   правит ни одного списка middleware. Порядок внутри: язык ставится как раньше → дешёвые
   исключения (§18.4) → `$next($request)` → решение по готовому ответу. Решать **после**
   обработчика приходится потому, что сущность страницы (`Resolution`) резолвер кладёт в запрос в
   контроллере, до него middleware её не знает. Цена — одна отрисованная и выброшенная страница на
   первый заход человека; с кукой и для ботов лишней работы нет.
10. **Шов между пакетами — контракт.** `localization` не знает ни `routing`, ни `widgets`; он
    объявляет `WebxUi\Localization\Contracts\PageInLanguage::url(Request $request, string $locale): ?string`
    — адрес этой же страницы в языке или `null`, «такой страницы нет». Привязка по умолчанию
    (`NoPageInLanguage`) отвечает `null` всегда. `widgets` при наличии `routing` привязывает
    `LanguagePageInLanguage` на `LanguageLinks`: ссылка языка без `fallback` → её адрес, иначе
    `null`. Один источник у переключателя, редиректа и плашки — они не разойдутся.

### 18.2. Конфиг

```php
'first_visit' => [
    'locale' => env('WEBX_LOCALE_FIRST_VISIT'),   // null — off; a language code of the site
    'cookie' => 'webx_lang',
    'lifetime' => 60 * 24 * 365,                   // minutes, the offer's cookie too
    'offer' => [
        'enabled' => (bool) env('WEBX_LOCALE_FIRST_VISIT_OFFER', false), // §18.6
        'cookie' => 'webx_lang_offer',
    ],
    'skip' => ['no_redirect', 'preview', 'signature'], // any of these in the query — nothing happens
    'except' => ['api/*', 'sitemap*.xml', 'robots.txt', 'feeds/*', '.well-known/*'],
    'bots' => [/* §18.3 */],
],
```

Путь панели (`webx-admin.path`) исключается сам, без строки в `except`. Ключи — в
`config/webx-localization.php` с комментарием, строка — в «Change it without forking» `AGENTS.md`
пакета и в гайд `guide/languages.md`.

  `Slackbot`, `TelegramBot`, `WhatsApp`, `Viber`, `Discordbot`, `Pinterest`, `redditbot`;
- **SEO, ИИ и фиды:** `AhrefsBot`, `SemrushBot`, `MJ12bot`, `DotBot`, `GPTBot`, `ClaudeBot`,
  `PerplexityBot`, `CCBot`; фиды маркетплейсов и прайс-агрегаторы ходят под своими агентами —
  сайт дописывает их сам, а сами фиды и так в `except`;
- **свои:** `WebxAudit` (`webx-audit.user_agent`) — иначе обход аудита со страницы основного языка
  уезжал бы на второй и матрица `hreflang` ломалась;
- **общие признаки:** `crawler`, `spider`, `bot/`, `bot;`, `+http` (краулеры пишут в агент адрес
  своей страницы). Голого `bot` нет — он совпадает с телефонами `Cubot`.

Пустой User-Agent — как бот. Проверка по одному `stripos` на строку, без регулярок; список
читается раз за запрос.

### 18.4. Когда редиректа нет

Проверяется по порядку, всё до `$next` — дешёвое:

1. настройка выключена, `strategy` не `prefix`, у сайта меньше двух языков, целевой язык не
   среди языков сайта (§18.1, п. 2);
2. метод не `GET`; запрос ждёт не HTML (`Accept` без `text/html`, `expectsJson()`, XHR);
   предзагрузка (`Sec-Purpose`/`Purpose: prefetch`) — иначе кука ставилась бы на страницу,
   которую человек не открывал;
3. есть кука `webx_lang`;
4. User-Agent — бот (§18.3);
5. путь — панель или в `except`; в query есть параметр из `skip`;
6. язык запроса (`Locales::current()`) уже целевой.

После `$next`:

7. ответ не `200` или не `text/html` (редирект SEO, 404, файл, JSON — как есть);
8. `PageInLanguage::url()` вернул `null` (§18.1, п. 5).

Иначе — 302 на найденный адрес плюс исходный query (без параметров из `skip`; `?page=2` и
метки рекламы сохраняются), кука, `Cache-Control: private, no-store`.

### 18.5. Кеш

- **Кеша ответов в WebX нет:** `CacheGroups` (`WEBX_UI_CACHE.md`) хранит данные, из которых
  собирается страница, а middleware отрабатывает на каждом запросе — обойти решение кешу нечем.
- **Ответ-редирект** — `private, no-store`: ни браузер, ни прокси его не сохранят и не отдадут
  тому, кто уже с кукой.
- **`Vary: Cookie` на обычные страницы не ставим.** От куки зависит, будет ли редирект, а при
  включённой плашке — есть ли она в разметке; стек `web` и так пишет куку сессии, и общий прокси
  такие ответы не кеширует. Сайт, который ставит кеш страниц на nginx/CDN, пропускает в приложение
  запросы без `webx_lang`, а при включённой плашке — и запросы с `webx_lang` без
  `webx_lang_offer`. Это строки в гайде, а не код.
- Отрисованная и выброшенная на первом заходе страница прогревает кеш данных — это польза, а не
  вред.

### 18.6. Плашка-предложение при повторных заходах

Человек, которого уже перенаправили, сам ушёл на страницу не целевого языка — и при следующих
заходах туда может увидеть небольшую плашку у переключателя: «Перейти на українську?» с кнопками
«Так», «Залишитись» и закрыть. Это предложение, а не редирект.

1. **Включается отдельным ключом** `first_visit.offer.enabled` (`WEBX_LOCALE_FIRST_VISIT_OFFER`),
   по умолчанию выключено; без включённого первого захода не работает.
2. **Кому показывать** (`FirstVisit::offer()`): есть кука `webx_lang`; нет куки отказа
   `webx_lang_offer`; не бот (§18.3); не панель, не `except`, нет параметров `skip` (превью);
   язык страницы не целевой. **Куда ведёт «Так»** — `PageInLanguage::url()`, тот же адрес, что у
   редиректа: страница, у которой на целевом языке есть только главная, плашки не получает (как не
   получила бы редиректа, §18.1, п. 5).
3. **Где.** Внутри `<x-webx-language-switcher>`, после списка языков, только у первого
   переключателя страницы (`Widgets::sequence`); `:offer="false"` снимает её с переключателя.
   Тема может напечатать ту же разметку дважды (шапка `theme-default` копирует `actions` в
   мобильное меню) — тогда скрипт показывает плашку у первого переключателя, который **виден**,
   сразу или когда откроется свёрнутое меню (`ResizeObserver`), а копии удаляет (у них один
   `id`). Без плашки разметка переключателя прежняя; с ней корень получает модификатор
   `--offer` (якорь `position: relative`).
4. **Без CLS.** Карточка `position: absolute` под переключателем, поверх страницы
   (`z-index` ниже открытого дропдауна), ширина — до `18rem` и не шире экрана минус поля; ничего
   под ней не сдвигается. Внизу свёрнутого меню места под переключателем нет — скрипт ставит
   `is-above`, и карточка встаёт над ним. Сервер печатает её `hidden`, показывает скрипт
   `language-offer.js` (свой файл dist, ≤1,5 КБ gzip вместе со стилем, грузится только на
   странице с плашкой): без скрипта отказ некуда записать, а неубираемая плашка хуже никакой.
5. **Доступность.** `role="dialog"`, `aria-modal="false"`, `aria-labelledby` на вопрос, `lang`
   целевого языка. Фокус не перехватывает (это предложение) — она следующая по Tab после
   переключателя. Esc закрывает, если не открыт дропдаун или диалог (их Esc важнее); после
   закрытия с клавиатуры фокус возвращается на переключатель. У крестика — `aria-label`.
6. **Отказ** — «Залишитись», крестик или Esc: скрипт пишет куку `webx_lang_offer=1` (год, как у
   `webx_lang`; `path=/`, `SameSite=Lax`, `Secure` на https; без `HttpOnly` — её пишет браузер).
   Не шифруется (`EncryptCookies::except`), категория — `necessary` (WIDGETS §9.2). После отказа
   плашка не показывается. «Так» — простая ссылка, ничего не пишет: на целевом языке предлагать
   нечего.
7. **Тексты** — в целевом языке (вопрос задаётся на том языке, который предлагают), ключи
   `webx-widgets::widgets.language.offer.{question,accept,stay,close}` во всех 10 языках пакета;
   каждый язык называет себя сам («Перейти на українську?», «Zu Deutsch wechseln?»). Нейтрально,
   без оценок. Тема переопределяет их ключами `theme::theme.language_offer.<key>`, сайт — через
   `lang/vendor/webx-widgets`. Язык сайта без слов пакета — английский текст `Switch to :language?`
   с самоназванием языка.

### 18.7. Что не меняется

- `hreflang`, `x-default`, canonical, карта сайта — строятся `Alternates` и реестром, не
  `LanguageLinks`. `x-default` остаётся на основном языке (адрес без приставки) — ботов туда никто
  не уводит.
- Переключатель языка — те же чистые ссылки и та же разметка, пока плашки нет.
- Аудит (`module-audit`, `hreflang.*`): обход идёт агентом `WebxAudit` без куки и не
  перенаправляется; каждая версия отвечает 200 по своему адресу, матрица взаимности — как раньше.
- 301 нормализации, `OneSpellingPerAddress`, ручные редиректы SEO стоят раньше или отвечают не
  200 — цепочки «301 → 302» на одном запросе не бывает.
- Выключенная настройка — ни одного нового заголовка, куки, скрипта и запроса.

### 18.8. Тесты

`localization` (Testbench, `PageInLanguage` подменён фейком):

- выключено — ответ как раньше, без `Set-Cookie: webx_lang`;
- первый заход человека на страницу основного языка → 302 на адрес фейка, кука `webx_lang=uk`,
  `no-store`, query сохранён, `skip`-параметры сняты; потом с кукой на `ru`-странице → 200;
- повторный заход с кукой (любое значение, в том числе `ru`) → 200 без редиректа;
- бот: каждый из групп §18.3 и пустой агент → 200, без куки; `Cubot`-телефон — человек;
- исключения §18.4: `POST`, JSON, prefetch, панель, `except`, `?no_redirect`, страница уже на
  целевом языке, ответ 404/301/не HTML, фейк вернул `null` → без редиректа и без куки;
- `locale` не код языка сайта (в том числе бывшее `header`) → молчит, doctor говорит;
- `offer()`: есть только с кукой, без отказа, не боту, не в превью, не на целевом языке, при
  включённых обоих ключах; по умолчанию выключено; обе куки не шифруются;
- `strategy: header` + включённая настройка → молчит; doctor: три предупреждения.

`widgets` (с `routing`, сущность в реестре):

- `PageInLanguage` на `LanguageLinks`: перевод → адрес строки; §8.7 → `Untranslated::path()`;
  только главная языка → `null`; маршрут модуля вне реестра → тот же путь под приставкой;
- разметка переключателя при включённой настройке совпадает с выключенной, без `webx_lang` и `rel`;
- сквозной: страница `ru` → 302 на её `uk`-версию с кукой → по чистой ссылке «Русский» →
  `ru`-страница 200 без редиректа и без новой куки;
- плашка: есть с кукой (ссылка «Так» на перевод, слова целевого языка, `hidden`, внутри
  переключателя); нет без куки, у бота, при выключенном ключе, без первого захода, после отказа,
  на целевом языке, при «только главной»; одна на страницу, `:offer="false"`;
- `language-offer.js` (vitest): показывается, «Залишитись»/крестик/Esc пишут куку и прячут,
  фокус возвращается на переключатель, Esc при открытом дропдауне не трогает, «Так» ничего не пишет;
- `DistTest`: файл в списке dist и в бюджете.

`module-audit`: обход двуязычного сайта с включённой настройкой — `hreflang.*` без находок.

Вживую — Playwright на сайте с двумя языками: плашка в светлой и тёмной темах, отсутствие сдвига
(`getBoundingClientRect` содержимого до и после показа), Esc и Tab.

### 18.10. Отложено

- **Настройка в панели** (вкладка языков `module-settings`) — когда попросит второй сайт;
  тогда же справка, право и MCP.
- **Источник языка по `Accept-Language`** — решение человека: язык первого захода всегда
  фиксированный.
- **Липкий язык** — кука как предпочтение, которое уводит и со второго захода; задача просит
  обратное, не делаем.
- **Проверка ботов по обратному DNS** (Googlebot действительно Google) — подделавший агент лишь
  не получает редирект, вреда нет.
