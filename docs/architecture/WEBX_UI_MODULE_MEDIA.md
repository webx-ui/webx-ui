# `webx-ui/module-media` — спецификация

Файловый менеджер панели: папки, файлы, загрузка, поиск, редактор изображений, медиа-поля форм.
Пара к нему — `@webx-ui/module-media`. Реестр пакетов —
[`WEBX_UI_COMPOSER_PACKAGES.md`](WEBX_UI_COMPOSER_PACKAGES.md).

Статус: выпущен (§13), отложенное — §14.

## 1. Границы

Модуль владеет **библиотекой**: файлы лежат в дереве папок, редактор выбирает их оттуда в контент
и в поля сущностей.

Модуль **не** владеет вложениями сущностей. Когда файл прикрепляют к товару или статье, сущность
хранит ссылку на него (`path` внутри своего JSON-поля), а не связь, за которую библиотека
отвечает. Смысл раздела: десятки тысяч фотографий товаров не обязаны попадать в библиотеку и
делать её медленной. Обратную сторону — удаление файла, который где-то стоит, — закрывает поиск
мест использования (§11), а не связь.

Модуль не хранит `alt` и `title`. Одна картинка в двух статьях требует двух подписей, поэтому они
живут на сущности рядом со ссылкой: `{ path, alt, title }`.

## 2. Принятые решения

1. **Удаление непустой папки** отклоняется с `409` и машиночитаемым кодом; `?force=1` удаляет
   папку со всем содержимым рекурсивно. Перед удалением панель спрашивает `contents` — счёт по
   всему поддереву и какие файлы в нём сайт ещё использует — и предлагает «удалить только
   неиспользуемые» (`delete-unused`).
2. **Переименование меняет только `name`.** `file_name` и `path` неизменны после загрузки, поэтому
   ссылки, уже записанные в контент, продолжают работать.
3. **Редактирование изображения перезаписывает тот же `path`** — все существующие ссылки остаются
   рабочими. Обновляются `hash`, `size`, `width`, `height`; `url` в ресурсе несёт `?v=<хеш>`.
   Оригинал один раз копируется в `original_path`, поэтому правка обратима. «Сохранить копией» —
   отдельное действие.
4. **Intervention Image v3** для превью и правок.
5. **Превью — один эндпоинт по требованию** с кешем варианта; пресетов размеров нет.
6. **Диск — настройка модуля** (`WEBX_MEDIA_DISK`, по умолчанию `public`), а не `FILESYSTEM_DISK`.
   Подробности в §5.
7. **Дерево — на `webx-ui/nested-set`.**
8. **Без `mediables`:** сущность хранит ключ, а не связь (§1).
9. **Все фразы модуля переводятся**; имена папок и файлов — нет (§10).

## 3. Схема

### `media_directories`

| Колонка                            | Тип                          | Примечание            |
| ---------------------------------- | ---------------------------- | --------------------- |
| `id`                               | `bigIncrements`              |                       |
| `parent_id`, `lft`, `rgt`, `depth` | `NestedSet::columns($table)` | индексы ставит хелпер |
| `title`                            | `string(255)`                | отображаемое имя      |
| `created_at`, `updated_at`         | `timestamps`                 |                       |

Корневая папка создаётся миграцией (одна, `depth = 0`), удалить её нельзя.

### `media_files`

| Колонка                    | Тип                                                  | Примечание                      |
| -------------------------- | ---------------------------------------------------- | ------------------------------- |
| `id`                       | `bigIncrements`                                      |                                 |
| `directory_id`             | `foreignId` → `media_directories`, `cascadeOnDelete` | файл всегда в папке             |
| `disk`                     | `string(32)`                                         | диск на момент загрузки         |
| `path`                     | `string(2048)`                                       | ключ на диске                   |
| `hash`                     | `char(32)`                                           | md5 содержимого                 |
| `name`                     | `string(255)`                                        | отображаемое, редактируемое     |
| `file_name`                | `string(255)`                                        | как файл назывался при загрузке |
| `extension`                | `string(16)`                                         |                                 |
| `mime`                     | `string(127)`                                        | без параметров (`; qs=…`)       |
| `size`                     | `unsignedBigInteger`                                 | байты                           |
| `width`, `height`          | `unsignedInteger` nullable                           | только для изображений          |
| `original_path`            | `string(2048)` nullable                              | копия до первой правки          |
| `optimized`                | nullable                                             | подпись настроек оптимизации    |
| `created_at`, `updated_at` | `timestamps`                                         |                                 |

Индексы: `(directory_id, hash)` — дедупликация внутри папки; `(directory_id, name)` — листинг с
сортировкой по имени; `(mime)` — фильтр по типу; `(hash)` — поиск дублей.

`media_aliases` (`path` уникален, `file_id` с каскадом) — прежние ключи файлов, сменивших формат
(§16): по ним старый адрес находит файл.

Внешний ключ с `cascadeOnDelete` держит целостность: строк файлов без папки не остаётся.

**Но удалять папку через него нельзя.** Каскад срабатывает в СУБД и не поднимает события
Eloquent, поэтому наблюдатель, стирающий байты, не вызовется: строки исчезнут, а файлы останутся
на диске навсегда. Удаление папки идёт только через сервис: собрать пути по всему поддереву,
удалить байты, потом строки, потом узлы дерева — одной транзакцией. Каскад остаётся страховкой на
случай, когда строки удаляют мимо приложения.

## 4. Хранилище

Путь: `{prefix}/{ab}/{cd}/{uuid}.{ext}`, где `prefix` из конфига (по умолчанию `media`), `ab` и
`cd` — первые символы хеша. **Путь не зависит от папки**, поэтому перемещение между папками
меняет одну колонку и не трогает байты — на S3 это разница между «мгновенно» и «copy + delete».

**Uuid в имени, а не хеш.** Один и тот же файл, загруженный в две папки, получает два ключа.
Ключ из хеша означал бы, что удаление одной из строк стирает байты для обеих.

**Дедупликация — внутри папки.** Если в целевой папке уже есть файл с таким `hash`, новый не
пишется: возвращается существующая строка, а ресурс помечается `"duplicate": true`, чтобы
интерфейс мог сказать «этот файл здесь уже есть».

Хеш считается по сохраняемым байтам (после конвейера §16) — поэтому повторная загрузка того же
снимка находит первую. Путь файловой системы допустим только у временного файла PHP.

## 5. Диски

```php
// config/webx-media.php
'disk' => env('WEBX_MEDIA_DISK', 'public'),
'prefix' => env('WEBX_MEDIA_PREFIX', 'media'),
```

`public` по умолчанию: у клиентских проектов другого хранилища обычно нет (нужен
`php artisan storage:link`). На хомлабе — `s3` (Garage, бакет `webx-cms`, path-style, публичное
чтение через `https://cdn.alexx.group/webx-cms`).

Смена диска не переписывает контент: сущность хранит `path`, а адрес вычисляется при отдаче.

**Правила, без которых S3 ломается:**

- Только фасад `Storage`. Никаких `storage_path()` и `getRealPath()` — Intervention получает
  байты (`Storage::disk($disk)->get($path)`), а не путь.
- Per-object ACL не выставляется: Garage их не любит, публичность даёт политика бакета. В
  конфиге диска `visibility` не указывается.
- Адрес файла: `Storage::disk($disk)->url($path)`, если у диска настроен `url`; иначе
  `temporaryUrl()` с временем жизни из конфига. Приватный бакет у клиента — рабочий вариант.
- Редирект на вариант обязан быть `https`: браузер молча отбрасывает переход с https-страницы на
  http-адрес.
- Перед Garage стоит CDN, поэтому `?v=<первые 8 символов хеша>` в `url` — не украшение:
  перезапись того же ключа без него продолжает отдаваться старой картинкой.
- **Байты для canvas — со своего домена:** `files/{id}/source` лежит в ресурсе отдельно от `url`;
  `WxImageEditor` с картинкой с CDN без CORS не грузит ничего.

## 6. API

Префикс — `config('webx-admin.api_path').'/media'` (по умолчанию `/api/cms/media`), middleware
`['web', 'webx.panel-locale', 'cms.auth']` плюс `cms.can:<право>` на каждом маршруте. Формат
ответов — как везде: пагинатор Laravel как есть, простые полезные нагрузки через `ApiResponse`,
ошибки валидации — `422` с `message` и `errors`.

### Папки

| Метод    | Маршрут                                 | Право          | Запрос → ответ                                                |
| -------- | --------------------------------------- | -------------- | ------------------------------------------------------------- |
| `GET`    | `directories`                           | `media.view`   | → `data`: дерево `DirectoryResource` от корня                 |
| `GET`    | `directories/{directory}/contents`      | `media.view`   | → счёт по поддереву и `in_use` — что из него сайт использует  |
| `POST`   | `directories`                           | `media.manage` | `{ parent_id, title }` → `201`, `DirectoryResource`           |
| `PATCH`  | `directories/{directory}`               | `media.manage` | `{ title }` → `DirectoryResource`                             |
| `PATCH`  | `directories/{directory}/move`          | `media.manage` | `{ parent_id, before_id?, after_id? }` → `DirectoryResource`  |
| `DELETE` | `directories/{directory}`               | `media.manage` | `?force=1` → `204`; без него на непустой — `409`              |
| `POST`   | `directories/{directory}/delete-unused` | `media.manage` | удаляет неиспользуемые файлы поддерева, говорит, что осталось |

Ответ `409` — `{ message, code: "directory_not_empty", counts: { files, directories } }`.

Корневую папку нельзя ни удалить, ни переместить — `422`. Папку нельзя переместить внутрь
собственного потомка — `422` (`HasNestedSet` бросает своё исключение, оно отображается в `422`).

### Файлы

| Метод    | Маршрут                         | Право          | Запрос → ответ                                                       |
| -------- | ------------------------------- | -------------- | -------------------------------------------------------------------- |
| `GET`    | `files`                         | `media.view`   | `?directory_id=&q=&type=&sort=&per_page=` → пагинатор `FileResource` |
| `GET`    | `files/by-path`                 | `media.view`   | `?path=` → `FileResource` по ключу (и по прежнему ключу)             |
| `GET`    | `files/{file}`                  | `media.view`   | → `FileResource`                                                     |
| `POST`   | `files/usage`                   | `media.view`   | `{ ids: [] }` → где сайт использует эти файлы                        |
| `POST`   | `files`                         | `media.upload` | multipart `directory_id`, `files[]` → `201`, список `FileResource`   |
| `POST`   | `files/chunked`                 | `media.upload` | `{ directory_id, upload }` — файл, пришедший кусками через `uploads` |
| `PATCH`  | `files/{file}`                  | `media.manage` | `{ name }` → `FileResource`                                          |
| `POST`   | `files/move`                    | `media.manage` | `{ ids: [], directory_id }` → `data: { moved: 12 }`                  |
| `POST`   | `files/delete`                  | `media.manage` | `{ ids: [], force? }` → `data: { deleted: 12 }`                      |
| `DELETE` | `files/{file}`                  | `media.manage` | `?force=1` → `204`                                                   |
| `GET`    | `files/{file}/thumb`            | `media.view`   | `?w=&h=&fit=cover\|contain` → `302` на вариант                       |
| `GET`    | `files/{file}/source`           | `media.view`   | байты для редактора со своего домена                                 |
| `POST`   | `files/{file}/edit`             | `media.manage` | операции (см. §7) → `FileResource`                                   |
| `POST`   | `files/{file}/copy`             | `media.manage` | → `201`, `FileResource`                                              |
| `POST`   | `files/{file}/restore-original` | `media.manage` | → `FileResource`                                                     |
| `POST`   | `files/optimize/pending`        | `media.manage` | §16                                                                  |
| `POST`   | `files/optimize`                | `media.manage` | §16                                                                  |

Параметры листинга:

- `directory_id` — папка; без него листинг по всей библиотеке (нужен для поиска).
- `q` — подстрока в `name`, регистронезависимо.
- `type` — `image` / `video` / `audio` / `document` / `other`, раскрывается в набор mime.
- `sort` — `name`, `-name`, `created_at`, `-created_at`, `size`, `-size`; по умолчанию `-created_at`.
- `per_page` — 24 по умолчанию, максимум 96.

Пакетное удаление — POST, а не DELETE с телом: тело у DELETE — легальный HTTP, который клиенты,
прокси и браузеры трактуют по-разному, и собственный клиент панели его не отправляет вовсе.
Один файл при этом удаляется честным DELETE. Файл, который сайт ещё использует, без `force` не
удаляется (места — §11); панель спрашивает `usage` заранее и называет места в вопросе.

Листинг **всегда** пагинирован, поиск тоже. Это единственная защита от папки на десять тысяч
файлов.

Загрузка кусками идёт через общие `uploads` из `module-admin`; `files/chunked` принимает только
загрузку, начатую тем же администратором, и дальше ведёт её тем же путём, что multipart: те же
правила по содержимому, конвейер, дедупликация и ответ.

### Ресурсы

`FileResource`: `id`, `directory_id`, `name`, `file_name`, `extension`, `mime`, `type`, `size`,
`width`, `height`, `path`, `url` (с `?v=`), `thumb`, `source`, `editable`, `has_original`,
`created_at`. `path` — то, что сущность кладёт себе в JSON рядом с `alt` и `title`. `url`
вычисляется на лету и меняется вместе с диском. `editable` — изображение, которое умеет открыть
редактор.

`DirectoryResource`: `id`, `parent_id`, `title`, `depth`, `files_count`, `children`.

## 7. Редактор изображений

`POST files/{file}/edit` принимает **операции**, а не готовый блоб:

```json
{
  "crop": { "x": 120, "y": 40, "width": 1200, "height": 800 },
  "rotate": 90,
  "flip": "horizontal",
  "resize": { "width": 1600 }
}
```

Все поля необязательны, порядок применения фиксирован: `crop` → `rotate` → `flip` → `resize`.

Блоб из браузера не принимается намеренно: канва редактора работает с превью, и её результат
уступает оригиналу в разрешении, а размер того, что прислали, проверять всё равно пришлось бы.
Сервер применяет операции к исходным байтам в полном размере.

Последовательность: при первой правке `path` копируется в `original_path`
(`{prefix}/originals/...`); результат пишется в тот же `path`; обновляются `hash`, `size`,
`width`, `height`; кеш превью этого файла удаляется; `url` получает новый `?v=`.

`copy` создаёт новую строку в той же папке с новым uuid и именем «<имя> (копия)».
`restore-original` возвращает содержимое из `original_path` обратно в `path`.

## 8. Превью

`GET files/{file}/thumb?w=320&h=320&fit=cover`. Допустимые размеры ограничены конфигом (список
разрешённых ширин), иначе один запрос со случайным `w` заставляет сервер пересчитывать что угодно.

Вариант кешируется на тот же диск: `{prefix}/thumbs/{w}x{h}-{fit}/{ab}/{cd}/{uuid}.{ext}`. Есть
в кеше — сразу `302` на его адрес (у приватного бакета — на `temporaryUrl`); нет — генерируется,
сохраняется, потом тот же `302`. Дальше файл отдаёт диск или CDN, минуя PHP. Превью файлов,
которых уже нет, убирает `webx:media:prune-thumbs` (то же делает исправление аудита
`media.orphan_thumbs`).

Не-изображения превью не имеют: `thumb` отвечает `404`, интерфейс показывает глиф расширения
(`WxFileCard`).

## 9. Права и конфиг

`media.view` — видеть библиотеку; `media.upload` — загружать; `media.manage` — переименование,
перемещение, удаление, правка изображений. Прав на отдельные папки нет (§14).

```php
// config/webx-media.php
'disk' => env('WEBX_MEDIA_DISK', 'public'),
'prefix' => env('WEBX_MEDIA_PREFIX', 'media'),
'temporary_url_ttl' => 3600,
'upload' => [
    'max_size' => env('WEBX_MEDIA_MAX_SIZE', 51200),   // килобайты, 50 МБ
    'max_files' => 20,                                  // за один запрос
    'mimes' => [...],                                   // белый список
],
'image' => [
    'driver' => env('WEBX_MEDIA_IMAGE_DRIVER', 'gd'),   // gd | imagick
    'max_pixels' => 50_000_000,                         // защита от «бомб»
    'quality' => 85,
],
'thumbs' => [
    'widths' => [160, 320, 640, 1280],
    'fits' => ['cover', 'contain'],
],
```

Белый список mime, а не чёрный: чёрный всегда неполон. По умолчанию — изображения, pdf, офисные
документы, архивы, аудио и видео.

## 10. Локализация

Действует общее [правило локализации модуля](WEBX_UI_COMPOSER_PACKAGES.md#правило-локализация-у-каждого-модуля):
ни одной строки в коде, namespace `webx-media`, десять языков в поставке, тест на совпадение
наборов ключей, `messages.ts` с теми же ключами по-английски как пол для фронта. Группы —
`module`, `manager`, `dialogs`, `errors`, `validation`.

Две вещи, специфичные именно для медиа:

- **Имена папок и файлов не переводятся.** Это не контент сайта, а рабочие подписи редактора:
  одна папка — один `title`. Переводимый `title` потребовал бы `HasTranslations` на дереве и
  превратил бы тривиальный листинг в join по переводам ради подписи, которую видит только
  администратор.
- **Ошибка загрузки приходит с сервера уже переведённой.** Размер и mime проверяет сервер, и
  сообщение о превышении лимита — единственное, что пользователь увидит в ответ на неудачную
  загрузку, поэтому язык там берётся из `X-Webx-Locale`, а не из того, на чём собрана панель.
  Загрузчик — голый `XMLHttpRequest`, поэтому этот заголовок он шлёт сам.

## 11. MCP

Инструменты — с префиксом `media_`.

| Инструмент         | Тип      | Аргументы                                  |
| ------------------ | -------- | ------------------------------------------ |
| `list_directories` | read     | —                                          |
| `list_files`       | read     | `directory_id?`, `type?`, `sort?`, `page?` |
| `search_files`     | read     | `query`, `type?`                           |
| `get_file`         | read     | `id`                                       |
| `create_directory` | mutating | `parent_id`, `title`                       |
| `delete_directory` | mutating | `id` — только пустая папка                 |
| `rename_file`      | mutating | `id`, `name`                               |
| `move_files`       | mutating | `ids`, `directory_id`                      |
| `upload_from_url`  | mutating | `url`, `directory_id`, `name?`             |
| `optimize_images`  | mutating | `ids?`, `directory_id?`, `convert?`        |
| `delete_files`     | mutating | `ids`, `force?`                            |

`Tool::mutating` сам добавляет `dry_run`. Отказ — `ToolFailure`, то есть ошибка MCP, а не
ответ `ok: false`. Рекурсивного удаления папок среди инструментов нет намеренно: по ошибочному
вызову агента его не отменить, поэтому `delete_directory` удаляет только пустую.

**Где используется.** `delete_files` (как и удаление в панели) не удаляет файл, который сайт ещё
использует, и называет места (таблица, колонка, id), пока не передан `force: true`. Места ищет
`MediaUsage` по источникам с тегом `MediaUsage::TAG`; штатный `DatabaseUsage` читает схему:
внешние ключи на `media_files` и последний сегмент ключа файла (uuid) в текстовых и JSON-колонках.
Таблицы истории, журналов и очередей пропускаются (`webx-media.usage.ignore`).

`upload_from_url` ходит только в публичный интернет: имя резолвится, каждый адрес проверяется
(loopback, частные, link-local, зарезервированные — в обеих семьях и внутри IPv6), соединение
прибивается к проверенному адресу (`CURLOPT_RESOLVE`), редиректы — вручную и с той же проверкой.
Тип берётся из байтов (без параметров заголовка), расширение — из белого списка загрузки, правила
те же, что у загрузки в панели. Исключения — `webx-media.remote.allow_hosts`.

## 12. `@webx-ui/module-media`

```ts
import { media, WxMediaField, openMediaPicker } from '@webx-ui/module-media'

createAdmin({ basePath: '/cms', modules: [media()], plugins: [auth()] }).mount()
```

| Экспорт                       | Что это                                                      |
| ----------------------------- | ------------------------------------------------------------ |
| `media()`                     | `AdminModule` с `id: 'media'` и маршрутом страницы менеджера |
| `WxMediaManager`              | страница: дерево слева, сетка справа, тулбар сверху          |
| `WxMediaPicker`               | диалог выбора; `multiple`, `type`, `directoryId`             |
| `openMediaPicker(options)`    | тот же диалог «из кода», возвращает промис с выбранным       |
| `openMediaFiles(options)`     | библиотека из кода, промис с массивом файлов (§15.3)         |
| `WxMediaField`                | поле `wx-media`, значение `{ path, alt, title }`             |
| `WxGalleryField`              | `wx-gallery`                                                 |
| `WxFileField`, `WxFilesField` | `wx-file`, `wx-files`                                        |
| `createMediaApi(context)`     | клиент; типы `MediaFile`, `MediaDirectory`                   |

Поля — единственное место, где появляются `alt` и `title`: картинку выбирают пикером, а подписи
вводят тут же, и всё это уезжает в JSON сущности.

Сборка страницы: `WxTree` для папок, `WxFileCard` в сетке, `WxSelectionArea` для выделения
рамкой, `WxUpload` для drag-and-drop, `WxImageEditor` для правки, `WxPagination` внизу. Своих
примитивов модуль не заводит. Гайд — `apps/docs/guide/media.md`.

## 15. Медиа-поля: галерея, файл, файлы

К `wx-media` добавлены ещё три типа поля, общих для описанных экранов, блоков конструктора и форм
модулей. Гайды — `apps/docs/guide/media.md`, `screens.md` (таблица типов), `blocks.md`.

### 15.1. Три новых типа, одно значение

| Тип          | Значение             | Что показывает                                           |
| ------------ | -------------------- | -------------------------------------------------------- |
| `wx-media`   | `MediaValue \| null` | одна картинка в рамке                                    |
| `wx-gallery` | `MediaValue[]`       | сетка миниатюр, перетаскивание, `alt` и `title` у каждой |
| `wx-file`    | `MediaValue \| null` | карточка файла: глиф расширения, имя, размер, подпись    |
| `wx-files`   | `MediaValue[]`       | список карточек, перетаскивание, подпись у каждого       |

Элемент везде один и тот же — `{ path, alt?, title?, url? }`, тот самый `MediaValue`, который
хранит `wx-media`. Для документа `alt` бессмысленен, и поле его не показывает; но форма значения
остаётся одна на все типы, поэтому правила, хранение и резолв пишутся один раз, а не четыре.

**Три имени, а не `wx-media` с `multiple`.** Имя типа — это то, что автор блока выбирает из списка
и что видит агент в `blocks://fields`. «Медиа с `multiple: true` и `accept: document`» никто не
выбирает, «Файлы» — выбирают. Внутри при этом один компонент и один набор правил: имена нужны
человеку, а не коду.

**Галерея — не репитер с картинкой.** Отличие не в количестве, а в том, что происходит за один
жест: десять файлов выбираются одним заходом в библиотеку, порядок меняется перетаскиванием
миниатюр, а не строк формы. Репитер остаётся для списка, у которого кроме картинки есть свои поля.

### 15.2. Значение, хранение, резолв

`store` оставляет только `path`, `alt`, `title` и порядок; `url` и всё, что приехало с клиента
сверх этого, выбрасывается — адрес не хранится никогда, иначе переезд библиотеки на другой диск
означал бы переписывание всего, что уже сохранено. По той же причине `MediaValues::resolve()`
берёт из сохранённого только `path`, `alt` и `title` — старый `url` иначе перекрыл бы
пересчитанный.

`resolve` дописывает к каждому элементу то, что известно о файле:

| Ключ                | Откуда                                      |
| ------------------- | ------------------------------------------- |
| `url`               | `FileUrls` — с `?v=` и подписью, если нужна |
| `thumb`             | адрес превью, `null` не для изображения     |
| `name`              | отображаемое имя файла                      |
| `extension`, `mime` |                                             |
| `size`              | байты                                       |
| `width`, `height`   | только у изображений                        |

**Полный набор, а не один `url`.** Шаблону нужно `width` и `height`, чтобы напечатать `<img>` без
прыжка вёрстки, и `size` с `extension`, чтобы подписать ссылку на документ. Дотянуться до
библиотеки из шаблона нечем, значит если не отдать здесь — не отдать вообще.

`source` в резолв не попадает: это байты, которые отдаёт сама панель, и нужны они одному
редактору изображений.

**Битый ключ хранится.** Файл, удалённый из библиотеки, не делает значение недействительным:
валидация существование не проверяет, `resolve` отдаёт `url: null`, поле рисует битую карточку —
и редактор видит, что именно выпало, и убирает это сам. Обратное — 422 под полем — означало бы,
что одна удалённая картинка не даёт сохранить страницу, пока её не найдут в списке из двадцати.
Ключ, сменённый переводом в WebP, находится через `media_aliases`.

**`accept` проверяется на сервере.** `props.accept` сверяется с `type` найденной строки: в галерею
нельзя положить `.zip`, подменив запрос. Проверка идёт по той же строке, которая всё равно
достаётся для резолва, — лишних запросов нет. Ненайденный файл не проверяется.

**`localized` на этих типах не поддерживается** и говорит об этом вслух. Переводятся подписи
внутри значения, как у `wx-media` (разбираются по языку **только на чтении сайта**: панель правит
карту целиком); переводимый список целиком означал бы разный набор картинок на разных языках — это
решается на уровне сущности, а не поля.

### 15.3. Пикер: множественный выбор

`MediaPicker` и `MediaManager` умеют `multiple`. В режиме выбора включается ровно то выделение,
которым менеджер пользуется для массовых операций (рамка `WxSelectionArea`, `selected: number[]`),
внизу диалога — кнопка «Выбрать (3)». Второго способа выделять файлы нет.

```ts
const files = await openMediaFiles({ accept: 'image', max: 10 })
```

Отдельная функция, а не флаг у `openMediaPicker`: тип возврата тогда честный (`MediaFile[]` против
`MediaFile | undefined`), без условных типов в сигнатуре.

`max` пикер соблюдает сам — выделение упирается в предел и говорит, сколько осталось; сервер
проверяет его же, потому что предел живёт в схеме, а не в диалоге.

### 15.4. Поля на клиенте

Под всеми тремя — один внутренний `MediaList`: `WxSortableList` для порядка, `WxFileCard` для
карточки, кнопка «Добавить» открывает пикер с `multiple`, поповер подписей — тот же, что у
`MediaField`. Раскладка (`grid` для галереи, `rows` для файлов) — проп.

**Обёртки не объявляют пропсы общего компонента**: `inheritAttrs: false` + `v-bind="$attrs"`.
Объявленный Boolean-проп, которого вызывающий не просил, приезжает вниз как `false`, а не
`undefined`, — и половина поведения молча выключается.

**Миниатюры — из `thumb`.** Галерея из сорока фотографий, нарисованная по `url`, это сорок
оригиналов.

**Правка картинки из поля не предлагается.** Файл общий, и подрезать его из формы одной страницы
значит подрезать во всех местах, где он стоит. В карточке — «открыть в библиотеке», дальше
редактор там, где видно последствия.

**Загрузка — через пикер.** Дропзоны на самом поле нет: она требует договориться, в какую папку
попадёт брошенный файл. В пикере загрузка есть, и папка там выбрана глазами.

Пропсы: `accept` (у галереи зафиксирован на `image`), `max`, `min`, `captions`, плюс `columns` у
сетки и `aspect` у миниатюры.

### 15.5. Сервер

**`MediaFiles`** — поиск строк по ключам: `whereIn` на весь список сразу, память на запрос, сброс
на `RequestHandled`; на нём же `wx-media`. Помнится строка, а не адрес: подписанная ссылка
приватного бакета живёт час и должна вычисляться заново.

**`GalleryFieldType`, `FileFieldType`, `FilesFieldType`** в `WebxUi\Media\Screens`, регистрация и
сброс — рядом с `wx-media` в провайдере. Правила: `nullable`, `array`, `max` и `min` из `props`,
форма элемента и проверка `accept` — замыканием, которое говорит номер элемента, потому что весь
список приезжает под одним именем поля и «неверный файл» без номера не говорит ничего.

### 15.6. Что ещё трогается

Типы перечислены в `BlockResources::NODES` у `module-blocks` — иначе агент про них не знает. Ядро
не менялось.

## 16. Оптимизация изображений

Конвейер — `WebxUi\Media\Images\Optimizing\ImageOptimizer`, настройки — `webx-media.optimize`.

- **Что делает.** JPEG, PNG и неанимированный WebP: поворот по EXIF, снятие метаданных, шаги из
  `steps` по порядку (по умолчанию `ScaleDown` — длинная сторона не больше `max_side`, 2560),
  кодирование с `quality` (82). Результат не меньше исходника и размер не менялся — остаются
  исходные байты. GIF, анимированный WebP, SVG и всё, что не картинка, проходят как есть.
  Картинка больше `image.max_pixels` не декодируется — ложится как пришла.
- **Загрузка** (`FileStore::store`, то есть панель, `upload_from_url`, демо): результат
  кодируется в `format` (`webp`), ключ и `file_name` получают новое расширение. Хеш — от
  сохранённых байтов, поэтому повторная загрузка того же снимка находит первую.
- **«Оптимизировать» для уже загруженного** (`LibraryOptimizing`): тот же конвейер, но формат и
  ключ не меняются — расширение входит в ключ, а ключ записан в контенте. Байты пишутся поверх,
  как у редактора: сначала строка, потом диск, в одной транзакции; превью сбрасываются, `?v=` в
  адресе меняется вместе с хешем. Копия не хранится — смысл в месте; оригинал редактора
  (`original_path`) не трогается.
- **«Перевести в WebP»** (`LibraryOptimizing::convert`, `convert: true` у MCP,
  `webx:media:webp`) — отдельный режим: JPEG, PNG (и HEIC, где читается) становятся WebP под новым
  ключом с тем же uuid. Порядок такой, чтобы сбой где угодно оставлял сайт как был: новые байты
  рядом со старыми → одной транзакцией строка получает новый ключ, старый запоминается в
  `media_aliases`, и все ссылки на старое имя переписываются (`MediaUsage::rewrite()`, история
  тоже) → только потом удаляются старые байты и превью и сбрасываются кеши рендера. WebP не меньше —
  файл не трогается. Старый публичный адрес на локальном диске отвечает 301 на новый
  (`OldAddressController`; S3 отвечает сам). Оригинал редактора остаётся в своём формате.
- **Повторный прогон.** Колонка `media_files.optimized` хранит подпись настроек
  (`max_side`, `quality`, `steps`; без `format` — он файлов в библиотеке не касается).
  Файл с текущей подписью в список не попадает, новый прогон с теми же настройками только
  терял бы качество. «Не стало меньше» тоже записывается.
- **API.** `POST files/optimize/pending` (`ids?` или `directory_id?`) → `{ ids, size }`;
  `POST files/optimize` (`ids`, не больше 10) → по файлу `{ id, status, before, after }`,
  статусы `optimized | unchanged | skipped | missing`; `convert: true` у обоих — режим WebP. Право —
  `media.manage`.
- **Панель.** Кнопка рядом с «Загрузить»: выделение, иначе открытая папка. Пачки по 10 шлёт сам
  диалог — виден счёт, есть «Остановить», очередь и воркер не нужны.
- **MCP.** `optimize_images`: без `ids` — папка или вся библиотека, за вызов одна пачка,
  `remaining` говорит, сколько осталось.
