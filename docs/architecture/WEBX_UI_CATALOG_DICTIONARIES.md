# Справочники каталога: метки, наличие, бренды

Три спутника ядра каталога за один заход: `module-catalog-labels`, `module-catalog-stock`,
`module-catalog-brands`. Архитектура семейства — [`WEBX_UI_CATALOG.md`](WEBX_UI_CATALOG.md) (§3, §11
«Анатомия спутника»), ядро и его реестры — [`WEBX_UI_MODULE_CATALOG.md`](WEBX_UI_MODULE_CATALOG.md)
§7; здесь они не повторяются. Статус: спека согласована 30.09.2026; D1 и D2 сделаны, дальше D3
(§10).

## 1. Решения (не переоткрывать)

Приняты в обсуждении 30.09.2026.

1. **Три модуля, один каркас.** У каждого свой справочник, своя часть формы товара, свой фасет,
   своя колонка списка, свои поля индекса. Отличаются кратностью и одним правилом (§2).
2. **Справочник — набор `Categories` из `module-admin`**, а не своё: `IsCategory`,
   `CategoryKind`, `CategoryRoutes`, `CategoryTools`, `CategoriesPage` в npm. Плоский список,
   ручной порядок, переводимое название, `extra`, soft delete, отказ удалить запись, за которой
   ещё стоят товары (422 с числом). Адрес, SEO и логотип бренд добавляет сам, теми же трейтами, что
   у сущностей (так и задумано в `IsCategory`).
3. **Метки — несколько на товар, наличие — одно, бренд — один.**
4. **Наличие решает «можно купить».** Флаг у статуса, правило в `Purchasability`. Количество
   (остаток) отложено.
5. **У бренда — своя страница**, адрес через `routing`. У меток и наличия страниц нет.
6. **Сайт производителя и страна бренда — не колонки.** Для проверки они приходят патчем экрана
   в `extra` (`HasExtra`) на демо и исчезают после проверки (§6).
7. **Меню:** «Каталог» → «Категории», «Товары», «Бренды», ниже подпись «Справочники» и под ней
   «Метки», «Наличие» (§5). Подпись — `WxMenuGroup` ядра; в узкой колонке она уже черта.
8. **Права — каталога.** Смотреть — `catalog.view`, править — `catalog.manage`: справочники
   правят те же люди, что и товары. Своих прав у спутников нет.
9. **Названия в интерфейсе — английские:** Labels, Stock, Brands. «Статус» остаётся за
   наличием (статус наличия), метки статусами не называем.

## 2. Три справочника

### 2.1. Метки — `module-catalog-labels`

Топ, акция, новинка. Бейдж в карточке, фильтр с мультивыбором, выборка в шаблоне
(`products()->label('sale')`).

`catalog_labels`

| Колонка                  | Тип                | Примечание                                                               |
| ------------------------ | ------------------ | ------------------------------------------------------------------------ |
| `id`                     | bigint             |                                                                          |
| `name`                   | json               | переводимое                                                              |
| `code`                   | string(32), unique | `[a-z0-9-]`; значение в адресе фильтра и в `->label('sale')`             |
| `color`                  | string(16)         | тон бейджа: `neutral`, `primary`, `success`, `warning`, `danger`, `info` |
| `is_badge`               | bool, default true | рисовать ли бейдж; служебная метка («для рассылки») — нет                |
| `is_filterable`          | bool, default true | значение в фасете                                                        |
| `position`               | int                | порядок в справочнике, в фасете, у бейджей                               |
| `extra`                  | json, null         | поля проекта                                                             |
| `deleted_at`, timestamps |                    |                                                                          |

`catalog_label_product` — `label_id`, `product_id`, первичный ключ по паре, index на
`product_id`.

- **Цвет — тон, а не hex.** Шаблон сайта кладёт тон в класс (`wx-badge--sale`-подобное решает
  сайт), панель рисует `WxTag` того же тона. Хардкод-цветов нет нигде.
- **Код, а не слаг.** Меток мало, адрес `/noutbuki/label_sale/` на всех языках один, и шаблон
  пишет `->label('sale')`, не зная id.
- **Удалить метку, на которой есть товары, нельзя** (правило набора): сначала массовое «убрать
  метку».

### 2.2. Наличие — `module-catalog-stock`

В наличии, нет в наличии, под заказ. Один статус на товар, флаг «можно купить».

`catalog_stock_statuses`

| Колонка                  | Тип                | Примечание                                            |
| ------------------------ | ------------------ | ----------------------------------------------------- |
| `id`                     | bigint             |                                                       |
| `name`                   | json               | переводимое; оно же подпись отказа в `Purchasability` |
| `code`                   | string(32), unique | `[a-z0-9-]`; значение в адресе фильтра                |
| `color`                  | string(16)         | тон, как у меток                                      |
| `is_purchasable`         | bool, default true | можно ли купить                                       |
| `is_default`             | bool               | ровно один; его получает товар без своей строки       |
| `is_filterable`          | bool, default true | значение в фасете                                     |
| `position`               | int                |                                                       |
| `extra`                  | json, null         |                                                       |
| `deleted_at`, timestamps |                    |                                                       |

`catalog_product_stock` — `product_id` (первичный ключ), `status_id` (FK, index).

- **Товар без строки — в статусе по умолчанию.** Спутник ставится на живой каталог, и 40 тысяч
  строк при установке писать не нужно. Форма нового товара предлагает статус по умолчанию;
  сохранение со статусом по умолчанию строку всё равно пишет — явное лучше неявного, а смена
  дефолта не должна молча перекладывать товары, которым статус выбрали руками.
- **Статус по умолчанию нельзя удалить,** и снять с него `is_default` можно только поставив на
  другой. Миграция создаёт три статуса: «In stock» (по умолчанию, можно купить), «Out of stock»
  (нельзя), «On order» (можно).
- **`Purchasability`:** статус с `is_purchasable = false` → `no`, код `stock`, подпись — название
  статуса. Регистрируется обычным порядком: после «снят с продажи» ядра, до «цены по запросу».
- **Смена `is_purchasable` или дефолта** помечает затронутые товары одним `touchQuery`.

### 2.3. Бренды — `module-catalog-brands`

Бренд со своей страницей, логотипом и описанием. Один на товар.

`catalog_brands`

| Колонка                  | Тип                    | Примечание                                                     |
| ------------------------ | ---------------------- | -------------------------------------------------------------- |
| `id`                     | bigint                 |                                                                |
| `name`                   | json                   | переводимое                                                    |
| `slug`                   | json                   | переводимое; адрес страницы и значение в адресе фильтра        |
| `logo_id`                | FK `media_files`, null | `nullOnDelete`; из библиотеки `module-media`                   |
| `description`            | json, null             | rich-text, текст страницы бренда                               |
| `is_published`           | bool, index            |                                                                |
| `is_featured`            | bool, index            | «популярные бренды»: `brands()->featured()`                    |
| `position`               | int                    | один порядок: справочник, фасет, featured, страница `/brands/` |
| `extra`                  | json, null             | поля проекта (§6)                                              |
| `deleted_at`, timestamps |                        |                                                                |

`catalog_product_brand` — `product_id` (первичный ключ), `brand_id` (FK, index).

SEO — `HasSeo` из `module-seo`, как у категорий.

- **Адреса.** Страница бренда — `/{prefix}/{slug}/`, тип `routing` `catalog.brand`,
  `acceptsTail: true` — хвост фильтра, как у категории (`/brands/apple/category_noutbuki/`).
  Список брендов — `/{prefix}/`, маршрут. `prefix` — конфиг, по умолчанию `brands`. Слаг
  уникален на своём языке, занятый — 422 с держателем, как у категорий.
- **Страница бренда — выдача каталога** с `scope: brand` (`CatalogQuery`, §8.1 ядра): свой фасет
  прячется, первый уровень фильтра — категории. Сверху логотип и описание. Шаблоны `brand` и
  `brands`, переопределяемые сайтом.
- **Снятый бренд:** страница 404, в фасете нет, у товаров бренд остаётся, но в карточке не
  показывается. **Удалённый** — 410, удалить с товарами нельзя (правило набора).
- **Фасет `brand` индексируемый:** «Ноутбуки Apple» — первый уровень, открыт (решение 17
  архитектуры).

## 3. Общий каркас

Что каждый спутник регистрирует в ядре. Имена точек — §7 и §10.1 ядра.

| Точка                 | Метки                            | Наличие                                      | Бренды                                               |
| --------------------- | -------------------------------- | -------------------------------------------- | ---------------------------------------------------- |
| `ProductPart`         | `labels.ids` — мультиселект      | `stock.status` — селект                      | `brand.id` — селект с поиском                        |
| `ProductColumns`      | бейджи                           | тег статуса                                  | название                                             |
| `Facets`              | `label`, Terms, не индексируемый | `stock`, Terms, не индексируемый             | `brand`, Terms, индексируемый                        |
| `DocumentContributor` | `labels` — id                    | `stock` — id, `purchasable`                  | `brand` — id                                         |
| `Purchasability`      | —                                | §2.2                                         | —                                                    |
| `BulkActions`         | `add-label`, `remove-label`      | `set-stock`                                  | `set-brand`                                          |
| `StorefrontParts`     | `catalog.card.badges`            | `catalog.card.meta`, `catalog.product.aside` | `catalog.card.meta`, `catalog.product.aside`         |
| `RecordQuery`         | `products()->label('sale')`      | `products()->inStock()`                      | `products()->brand('apple')`, `brands()->featured()` |
| `LinkSource`          | —                                | —                                            | бренды — для меню                                    |
| MCP                   | `catalog_labels_*`               | `catalog_stock_*`                            | `catalog_brands_*`                                   |

- **Поля в форме товара** — патчем `catalog.product-form` во вкладку «Основное», после категорий.
  Ключи с точкой, как требует §11.2 ядра.
- **Фасет не показывает** записи с `is_filterable = false` (метки, наличие) и снятые бренды.
- **Правка справочника** (название, код, слаг, публикация, флаги) помечает его товары
  `touchQuery` — одним запросом, не циклом.
- **Журнал:** изменения частей идут в запись сохранения товара (§11.3 ядра); справочники пишут
  свой журнал так же, как категории других модулей.
- **MCP:** инструменты справочника — `CategoryTools` набора (`list`, `create`, `update`,
  `reorder`, `delete`), поля товара — через `describe()` частей, отдельных инструментов на товар
  нет.
- **Обмен:** колонок пока не объявляем — `ExchangeColumns` появится со спекой обмена. Там будут
  `labels` (коды через запятую), `stock` (код), `brand` (слаг или название).

## 4. Панель

- **Справочник** — `CategoriesPage` набора: список с порядком перетаскиванием, форма записи —
  экран-описание (`catalog.label-form`, `catalog.stock-status-form`, `catalog.brand-form`), число
  товаров в строке.
- **Форма бренда:** «Основное» (название, слаг, логотип, публикация, featured), «Описание»,
  «SEO», «История». Логотип — выбор из библиотеки `module-media`.
- **Форма метки и статуса** — одна вкладка: название, код, тон (выбор из шести с живым тегом),
  флаги.
- **Список товаров** получает три колонки и три фильтра без правок ядра — через реестры.

## 5. Меню: подпись внутри группы

Сейчас меню — два уровня: группа и разделы в ней (`AdminNav.vue`). Правка в `module-admin`:

- **Группа объявляет свои части** в `webx-admin.groups`:
  `'catalog' => [..., 'sections' => ['dictionaries' => ['title' => '…', 'order' => 100]]]`.
- **Модуль говорит, в какой он части,** необязательным интерфейсом `HasNavSection`
  (`navSection(): string`). Интерфейс, а не новый метод `Module`: проекты реализуют `Module` и без
  `AbstractModule`, и новый метод сломал бы их.
- **`AdminNav.vue`** рисует сначала разделы без части, потом каждую часть `WxMenuGroup` с
  подписью. В узкой колонке `WxMenuGroup` — черта, это уже есть.
- **Порядок в группе «Каталог»:** «Категории» 300, «Товары» 301 (сейчас наоборот), «Бренды» 302;
  в «Справочниках» — «Метки» 310, «Наличие» 311. Будущие справочники (свойства) встают туда же.

## 6. Поля проекта у бренда: проверка `HasExtra`

`website` и `country` — патч экрана `catalog.brand-form` в плейграунде и в `webx-cms.local`: поле
ссылки и строка, без фасетов. Проверяем, что патч рисует поля, запись кладёт их в `extra`, шаблон
читает `$brand->extra('website')`, журнал видит изменения. После проверки патч удаляем — колонок не
было, удалять в базе нечего. В публичные пакеты патч не попадает.

## 7. Демо

- Метки: Top, Sale, New (с бейджами), Newsletter (без бейджа, не в фильтре).
- Наличие: три статуса миграции; у демо-товаров — примерно 80 % в наличии, 10 % нет, 10 % под
  заказ.
- Бренды: восемь вымышленных, у трёх featured, один снят; у части товаров бренда нет.

Фикстуры плейграунда — то же в памяти.

## 8. Регистрации

Каждый из трёх — как любой раздел (CLAUDE.md §4): четыре раза в `php/`, `Setup\Catalogue`,
`extra.webx.npm` и `extra.webx.panel`, `apps/playground/src/panel/main.ts`, `scripts/packages.mjs`
в `webx-cms.local`. Бренды ещё: тип `routing` `catalog.brand`, `LinkSource`, карта сайта через
реестр. Первые версии трёх npm-пакетов публикует человек (`docs/pitfalls/release-and-ci.md`).

## 9. Тесты, которые обязательны

- метки: несколько на товар; фасет с мультивыбором считает без своего фильтра; служебная метка
  не в фасете и не в бейджах; удаление метки с товарами — 422 с числом;
- наличие: товар без строки — в статусе по умолчанию; статус без `is_purchasable` → `no` с его
  названием; «снят» ядра бьёт наличие, наличие бьёт «цену по запросу»; дефолт нельзя удалить;
- бренды: адрес `/brands/{slug}/` с хвостом фильтра, свой фасет на странице бренда скрыт; снятый
  — 404 и не в фасете; удалённый — 410; занятый слаг — 422;
- форма товара: упавшая часть спутника откатывает сохранение, журнал — одна запись;
- правка справочника помечает товары одним запросом;
- меню: разделы части под подписью, разделы без части — выше, модуль без `HasNavSection` — как
  раньше.

## 12. Как легло в код (D2)

Где код разошёлся с §2–§3 и почему. Решения §1 не менялись.

- **Колонки — набора `Categories`.** `$table->category()` даёт `title`, `slug`, `position`,
  `is_visible`, `extra`, корзину и метки времени, а `CategoryForm`, `CategoryResource` и
  `CategoryTools` читают именно их. Поэтому переводимое название — `title`, а не `name`, и
  «в фильтре» (`is_filterable`) — это `is_visible` набора: запись, которую читатель не может выбрать,
  и есть запись, до которой он не дотянется. `slug` пустой всегда (как у категорий FAQ). Свои
  колонки — `code`, `color`, `is_badge` у меток, `is_purchasable`, `is_default` у наличия.
- **Общая модель в ядре** — `WebxUi\Catalog\Dictionaries\Dictionary` (абстрактная, не `final`):
  код делается из названия, если пуст (`sale`, `sale-2`), проверяется в модели — `[a-z0-9-]`,
  до 32 символов, уникален вместе с корзиной; тон — один из шести; правка полей из
  `touchingFields()` зовёт `Catalog::touchQuery(affectedProducts())` одним запросом. Бренды (D3)
  кода и тона не имеют и её не берут.
- **Поля формы товара** — карточка после `placement` во вкладке `main`: у меток `wx-categories` с
  `props.source: catalog/labels` (проверку id делает `CategorySources`), у наличия `wx-select` с
  `props.source: catalog/stock` без `options` — варианты подставит панель в D4, id проверяет
  `rules()` части. Пустое `stock.status` снимает строку: «какой бы ни был статус по умолчанию».
- **Порядок значений фасета.** Фильтр витрины сортирует термы по алфавиту; фасет меток и наличия
  реализует `OrderedFacet` ядра, и тогда фильтр берёт порядок из `labels()` — то есть `position`.
  Фасеты в ответе списка панели (`GET /products`) идут в порядке счётчиков — выстроит D4.
- **`RecordQuery`.** `ProductQuery` — `final`, поэтому шаги спутников — макросы (`Macroable`) поверх
  `narrowedBy($name, Closure)`: `products()->label('sale', 'new')` — любая из меток, включая
  служебные; `products()->inStock()` — статус с `is_purchasable`, товар без строки — по статусу по
  умолчанию.
- **Колонки списка** отдают `labels: [{ id, name, code, color }]` и `stock: { id, name, code,
color, purchasable }`; сортировки нет.
- **Документ индекса:** `labels` — id меток в фильтре, `stock` — id статуса, `purchasable`.
- **Витрина:** вьюхи `webx-catalog-labels::badges` (`ul.wx-catalog-badges` с
  `li.wx-catalog-badge--<тон>`) и `webx-catalog-stock::status` (`p.wx-catalog-stock--<тон>`, плюс
  `--card` или `--product`); стилей пакеты не несут — решает сайт.
- **Миграции** — день `2026_01_03`: таблицы связей ссылаются на `catalog_products` второго дня.
  Три статуса наличия пишутся под языком `webx-localization.fallback`, который читает любой язык
  сайта, пока их не перевели.
- **MCP:** `CategoryTools` с id модулей `catalog-labels` и `catalog-stock` —
  `catalog_labels_*` и `catalog_stock_*`; аргумент — `label` и `status`.
