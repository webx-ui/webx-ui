# `webx-ui/module-seo` — спецификация и план реализации

Раздел панели для SEO, не привязанного к сущности, и рендер `<head>` на публичной части. Пара к
нему — `@webx-ui/module-seo`. Реестр пакетов — [`WEBX_UI_COMPOSER_PACKAGES.md`](WEBX_UI_COMPOSER_PACKAGES.md),
экраны — [`WEBX_UI_SCREENS.md`](WEBX_UI_SCREENS.md).

Статус: спроектирован 14.09.2026, php-половина написана 14.09.2026 (сессия A из §13). Спецификация
описывает **v0.1**; отложенное — в §16. Места, где реализация разошлась со спецификацией, помечены
в тексте — это исправления, а не долг.

**§17 — сопровождение сущностей** (карта сайта, hreflang, крошки, schema.org, собственный
canonical): спроектировано 23.09.2026 как этап 0 перед
[`WEBX_UI_MODULE_SERVICES.md`](WEBX_UI_MODULE_SERVICES.md), не начато.

## 1. Границы

Модуль владеет **SEO, у которого нет сущности**: параметрами для произвольных URL, редиректами и
глобальными дефолтами. Он же **собирает ответ для шаблона** — резолвер и печать `<head>` живут
здесь.

Модуль **не** владеет SEO сущностей. Трейт `HasSeo` и таблица `seo_meta` появятся здесь же, но
вместе с первой сущностью (`module-pages`): сегодня их не к чему прицепить и нечем проверить.
Контракт `SeoSource` (§5) написан так, что сущность добавится ещё одним источником, без правок
резолвера.

### Почему один пакет, а не два

В реестре SEO записан двумя пакетами — библиотека `webx-ui/seo` и раздел `webx-ui/module-seo`.
**Решено делать одним.** Наше правило именования (CLAUDE.md §1): `module-*` — то, из чего состоит
панель, голое имя — библиотека, которая живёт **без** панели. `nested-set` — чистый алгоритм,
`localization` публичная часть использует сама по себе, а SEO-рендеру без SEO-раздела рисовать
нечего: ни правил, ни дефолтов, ни Organization — всё это авторится в панели. По собственному
критерию библиотекой он не является.

Шов при этом намечен внутри и его надо держать: рендер и резолвер — в `WebxUi\Seo\Rendering\`,
раздел — в `WebxUi\Seo\Panel\`, источники регистрируются через контракт, а не зашиваются. Если
когда-нибудь контентным модулям понадобится трейт без раздела, разрез по готовому шву —
механический, и на 0.x он дёшев. Раздел реестра пакетов надо переписать под это решение вместе с
кодом.

## 2. Принятые решения (не переоткрывать)

1. **Один пакет на обеих половинах**: composer `webx-ui/module-seo` (namespace `WebxUi\Seo\`),
   npm `@webx-ui/module-seo`.
2. **Префикс таблиц — `seo_*`, не `cms_*`.** `cms_users` и `cms_settings` — каркас; модуль
   называет таблицы по себе, как `module-media` называет `media_directories` и `media_files`.
3. **Приоритет мержится по полям, а не по источникам.** Правило для URL, в котором заполнен только
   `title`, не стирает `description`, пришедший ниже по цепочке. Иначе первое же правило обнуляет
   половину разметки, и это выглядит как поломка движка.
4. **Текстовые контентные поля переводимые**: `title`, `h1`, `description`, `keywords`,
   `og_title`, `og_description` — по колонке на поле. Не переводимые: `og_image`, `pattern`,
   `match_type`, `priority`, `canonical`, `robots`, `json_ld`, `is_active`. Механизм —
   существующий `HasTranslations` из `webx-ui/localization`, без новых зависимостей и без своего
   варианта хранения (§3).
5. **`robots` и `robots.txt` — разные вещи.** `SeoData::$robots` — мета-директивы страницы
   (`noindex`, `nofollow`, …), печатаются в `<meta name="robots">`. `seo.robots-txt` — глобальная
   настройка, отдаётся маршрутом `/robots.txt`. Слова похожие, сущности разные; сказать это в
   гайде прямо.
6. **Микроразметка делится на три уровня.** Про сайт (`Organization`, `WebSite`) — полями в
   настройках, JSON-LD собирается из них сам. Про сущность (`Article`, `Product`,
   `BreadcrumbList`) — кодом, позже, плагином: заполнять руками вредно, разметка разъедется с
   содержимым. Штучные исключения — поле «свой JSON-LD» у правила URL. Конструктора schema.org в
   панели **не делаем**: типов сотни, польза мала.
7. **Карточка `wx-seo` — в `@webx-ui/module-seo`**, не в ядре: ядро не знает предметных областей.
   Она же регистрируется типом в реестре экранов, чтобы её можно было вставить патчем в форму
   сущности, когда та появится.
8. **Вкладка SEO в настройках переезжает** из патча сайта `webx-cms.local` в модуль.
9. **Форма правила — шаблон, а не экран.** Как `admins.form` (решение 14.09.2026): на экраны
   переводим позже, когда механизм обкатается.
10. **Лог 404, аудит, sitemap — не в v0.1** (§16).
11. **Релиз общий**, вместе со всем, что накопилось в `main`, включая `wx-repeater` из PR #121
    (релизный PR #122 держится открытым намеренно).

## 3. Схема

### `seo_urls`

| Колонка                                                                | Тип                         | Примечание                                       |
| ---------------------------------------------------------------------- | --------------------------- | ------------------------------------------------ |
| `id`                                                                   | `bigIncrements`             |                                                  |
| `match_type`                                                           | `string(8)`                 | `exact` \| `mask` \| `regex`                     |
| `pattern`                                                              | `string(2048)`, без индекса | адрес, маска (`/catalog/*`) или регулярка        |
| `priority`                                                             | `integer` default `0`       | внутри группы совпадения, по убыванию            |
| `title`, `h1`, `description`, `keywords`, `og_title`, `og_description` | `json` null                 | переводимые, ставятся `Translatable::columns()`  |
| `og_image`                                                             | `json` null                 | значение `wx-media` — объект, **не** переводимое |
| `canonical`                                                            | `string(2048)` null         |                                                  |
| `robots`                                                               | `string(255)` null          | мета-директивы через запятую                     |
| `json_ld`                                                              | `json` null                 | свой блок разметки для этого адреса              |
| `is_active`                                                            | `boolean` default `true`    |                                                  |
| `created_at`, `updated_at`                                             | `timestamps`                |                                                  |

Модель `SeoUrl` использует **наш** `HasTranslations` из `webx-ui/localization` — `spatie/laravel-translatable`
не подключается ни здесь, ни где-либо ещё. Совпадает только форма данных в колонке
(`{"en": "…", "ru": "…"}`), и это сделано нарочно: карту, записанную по такой конвенции, прочитает
что угодно, а уход от неё — вопрос чтения колонки, а не миграции.

Механизм переводов в этой задаче **не переоткрываем** (обсуждалось 14.09.2026). Вариант
«кастом вместо трейта» рассматривался и отложен: каст закрывает разрешение значения и запись, но
не даёт скоупов запроса (`whereTranslation`, `orderByTranslation` строят путь `title->ru`), а
`__toString` вернул бы язык неявно — тогда как у нас он передаётся явно везде, от `X-Webx-Locale`
до `FieldType::resolve()`. Если каст понадобится, это отдельная правка в `webx-ui/localization`
для всех модулей сразу, а не развилка внутри SEO.

**Почему по колонке на поле, а не одна `data` со всем внутри.** `HasTranslations` работает по
атрибуту: он читает `$this->attributes[$key]` и ждёт там карту языков. Общая колонка означала бы
`{"title": {"en": …}}` — уровнем глубже, чем трейт понимает, то есть второй механизм переводов
рядом с первым. Плюс поиск и сортировка в таблице правил: `whereTranslationLike('title', …)`
собирает путь `title->ru` сам, а с общей колонкой это писалось бы руками мимо скоупов. Словарь
SEO-тегов закрыт — это стандарт, а не пользовательские поля, поэтому новая колонка здесь событие
редкое и честное. Произвольное содержимое без схемы живёт в `json_ld`.

**`og_image` не переводимое** (решение 14.09.2026): картинок на разных языках у нас нет нигде —
`localized` стоит сегодня ровно на одном узле во всей панели, на названии проекта. Отложено до
этапа, когда мультиязычные изображения понадобятся по-настоящему. Тогда это будет **не просто
флаг**: колонка уже хранит объект (`{"path": …}`), и `getTranslations()` примет его ключи за коды
языков. Значит, миграция должна переписать строки (`{…}` → `{"<язык по умолчанию>": {…}}`), а не
только добавить поле в `translatable()`. То же касается любого другого объектного значения, которое
позже решат переводить.

Уникальности по `pattern` нет намеренно: два правила на один адрес разводятся `priority`, и это
дешевле, чем объяснять редактору конфликт уникального индекса.

**Индекса по `pattern` тоже нет** (исправлено при реализации): колонку такой ширины переносимо не
проиндексировать — MySQL кончается на 191 символе utf8mb4, а `Blueprint` длину префикса не умеет.
И индексировать нечего: публичная часть сверяется со скомпилированным списком из кеша, а панель
ищет через `like '%…%'`, которому индекс не помог бы всё равно.

## 4. Подбор по адресу

Один класс `UrlMatcher` обслуживает и правила, и редиректы — иначе они разъедутся в поведении, и
«почему маска работает в правилах и не работает в редиректах» станет вопросом поддержки.

- **Что сравниваем:** путь с query-строкой, как пришло, без схемы и хоста
  (`/catalog/shoes?page=2`). Query нужен: страницы фильтров и пагинации — половина смысла правил
  для URL. Хвостовой слэш нормализуется (кроме корня).
- **Порядок:** сначала все `exact`, потом `mask`, потом `regex`; внутри группы — `priority` по
  убыванию, при равенстве `id` по возрастанию. Побеждает первое совпадение.
- **Маска:** `*` — любой отрезок без `/`, `**` — с `/`. Компилируется в регулярку один раз.
- **Регулярка:** хранится как есть, проверяется при сохранении (`preg_match` на пустой строке в
  try/catch); битая регулярка — ошибка валидации, а не 500 на публичной части.
- **Кеш:** активные правила и редиректы лежат в кеше скомпилированным списком, сброс — на
  `saved`/`deleted` модели. Публичная часть не должна делать запрос на каждый хит.

## 5. Источники и резолвер

```
interface SeoSource
{
    public function priority(): int;
    public function forUrl(string $url, ?object $subject = null, ?string $locale = null): ?SeoData;
}
```

Язык в сигнатуре — уточнение при реализации. В спецификации его не было, и тогда источнику
пришлось бы брать язык из глобального состояния; у нас он передаётся явно везде, от
`X-Webx-Locale` до `FieldType::resolve()`, и здесь тоже.

- `SeoSources` — реестр-синглтон, источники регистрируются из провайдеров. Резолвер сам ничего не
  знает ни про таблицы, ни про настройки.
- `UrlRuleSource` — приоритет `100`, читает `seo_urls`.
- `DefaultsSource` — приоритет `10`, читает `settings('seo.*')`: OG по умолчанию, шаблон title,
  Organization/WebSite в JSON-LD.
- `EntitySource` — приоритет `50`, читает `seo_meta` через `HasSeo` у переданного subject.

`SeoData` — value-object: `title`, `h1`, `description`, `keywords`, `canonical`, `robots`,
`og` (массив), `jsonLd` (список блоков). Ключевой метод — `mergeOver(SeoData $lower): SeoData`:
пустое поле уступает нижнему источнику, `jsonLd` складывается.

`Seo::for(string $url, ?object $subject = null, ?string $locale = null): SeoData` — обходит
источники по убыванию приоритета, мержит, подставляет шаблон (`{title} — {site}`), обрезает по
лимитам из конфига. Язык — запрошенный; значения разворачиваются `forLocale()`, как это делает
`FieldType::resolve` у настроек.

## 6. Рендер

- Blade-компонент `<x-webx-seo::head :for="$page" />` и директива `@webxSeo` / `@webxSeo($page)`.
- Печатает `<title>`, `meta description`, `meta keywords`, `meta robots`, `link rel=canonical`,
  `og:*`, блоки `application/ld+json`.
- Конфиг `webx-seo.php`: шаблоны по умолчанию, мягкие лимиты длин (для счётчиков в панели и
  подрезки), какие блоки печатать, приоритеты источников.
- Экранирование — обязательный тест: заголовок с кавычками и `<` не должен ломать разметку, а
  JSON-LD печатается через `json_encode` с `JSON_UNESCAPED_UNICODE | JSON_HEX_TAG`.

## 7. Редиректы

Middleware `webx.redirects` — **глобальная, не в группе `web`** (исправлено при реализации
14.09.2026). Адрес, ради которого пишут редирект, — это адрес, под который у сайта уже нет
маршрута, а запрос к такому адресу ни в какую группу не попадает: роутер бросает
`NotFoundHttpException` раньше. В группе редиректы срабатывали бы только на страницах, которые и
так работают, — то есть ровно там, где не нужны. Поймано `scripts/php-smoke.sh`: в Testbench тест
проходил, потому что маршрут в нём был.

Раз middleware глобальная, она видит и адреса панели, поэтому пропускает всё под
`webx-admin.path` и `webx-admin.api_path`: маска `/**`, написанная редактором, иначе закрыла бы
ему и экран, на котором он её написал, и тот, где её можно было бы убрать. Алиас `webx.redirects`
остаётся — на случай, если приложение захочет расставить её само.

Дальше как задумано: ищет совпадение, отдаёт `301`/`302`, увеличивает `hits` и пишет
`last_hit_at`. Инкремент — `increment()` без загрузки модели.

Защита от петли: если цель совпадает с источником после нормализации — правило игнорируется, и это
видно в панели меткой. Цепочки (A→B→C) не схлопываем: в v0.1 браузер сам пройдёт два шага.

## 8. `robots.txt`

Маршрут `/robots.txt` отдаёт значение настройки `seo.robots-txt` с `Content-Type: text/plain`.
Если значение пустое — `404`, чтобы не перебивать файл, который может лежать в `public/`. Ловушка
для гайда: физический файл веб-сервер отдаёт раньше Laravel, и это нормальное поведение, а не баг
модуля.

## 9. Патч настроек

Из провайдера модуля: `Screens::extend(Settings::SCREEN, __DIR__.'/../resources/screens/settings.json')`.
Порядок загрузки безопасен — `ScreenRegistry::extend` допускает патч к ещё не зарегистрированному
экрану, а провайдер проекта грузится последним и остаётся с последним словом.

Узлы патча (их `id` — публичный контракт, по которому проект пишет свои патчи):

| `id`             | тип           | `name`               | назначение                      |
| ---------------- | ------------- | -------------------- | ------------------------------- |
| `seo`            | `wx-tab`      | —                    | вкладка                         |
| `seo-card`       | `wx-card`     | —                    |                                 |
| `default-og`     | `wx-media`    | `seo.default-og`     | в слот `sidebar`, `aspect 16/9` |
| `title-template` | `wx-input`    | `seo.title-template` | `{title} — {site}`              |
| `robots-txt`     | `wx-textarea` | `seo.robots-txt`     | содержимое файла                |
| `org-name`       | `wx-input`    | `seo.org-name`       | Organization, переводимое       |
| `org-logo`       | `wx-media`    | `seo.org-logo`       | Organization                    |
| `org-socials`    | `wx-repeater` | `seo.org-socials`    | `sameAs`: список адресов        |

Ловушка, уже стоившая времени (CLAUDE.md §4): **точка в ключе — часть ключа, а не путь**.
`seo.default-og` — одно имя; валидатор Laravel и `assertJsonPath` читают его как вложенность.

## 10. API панели

Префикс `config('webx-admin.api_path').'/seo'`, middleware `['web', 'webx.panel-locale', 'cms.auth']`,
права `cms.can:seo.view,seo.manage` на чтение и `cms.can:seo.manage` на запись.

| Метод и адрес           | Что делает                                                                |
| ----------------------- | ------------------------------------------------------------------------- |
| `GET /urls`             | список правил, поиск по `pattern`, фильтр по `match_type`                 |
| `POST /urls`            | создать                                                                   |
| `GET                    | PUT                                                                       | DELETE /urls/{id}` | одно правило |
| `GET /redirects` и т.д. | то же для редиректов                                                      |
| `POST /test-url`        | `{ url }` → какое правило совпало, итоговый `SeoData`, цепочка источников |

`test-url` — главный инструмент поддержки: «почему на этой странице не тот title» задают чаще
всего, и отвечать на это должен один вызов, а не чтение кода.

Списки отдаются `->paginate()` как есть — таблица ядра принимает формат Laravel.

## 11. Модуль в панели

`SeoModule extends AbstractModule`: `id()` — `seo`, `group()` — `system`, `permissions()` —
`seo.view`, `seo.manage`, `order()` — рядом с настройками (у `module-settings` 800; взять 700,
чтобы SEO стоял выше), `icon()` — уточнить имя в наборе ядра.

MCP-инструменты (`ProvidesMcpTools`): `urls_list`, `urls_get`, `urls_set` (mutating, `dry_run`),
`test_url`, `redirects_list`, `redirects_set`, `import_redirects` (список «старый → новый»).
Скоупы `seo:read` / `seo:write`.

## 12. npm-половина

```
packages/module-seo/src/
├── module.ts         seo(): AdminModule — маршруты /seo и /seo/redirects, types: { 'wx-seo': … }
├── SeoUrlsPage.vue   таблица правил + диалог правила
├── SeoRedirectsPage.vue  таблица редиректов, быстрый ввод, импорт списком
├── SeoCard.vue       WxSeo — карточка полей
├── api.ts  types.ts  messages.ts  i18n.ts  index.ts
```

`WxSeo` — карточка: title, h1, description, keywords, robots (набор чекбоксов, не свободная
строка), canonical, OG (через `wx-media` + превью), счётчики длины с мягкими лимитами, превью
сниппета как в выдаче, поле «свой JSON-LD» на `WxCodeEditor` с проверкой синтаксиса. Языковые
чипы — тем же механизмом, что у названия проекта в настройках (флаг `localized` у узла).

Регистрация типа — как у медиа (`types: { 'wx-seo': { component: SeoCard, kind: 'field' } }` в

## 17. Сопровождение сущностей (этап 0 перед `module-services`)

Спроектировано 23.09.2026. Решение пользователя: SEO у новых модулей полное с первого дня, а не
«карточка сейчас, остальное потом». Всё, что здесь описано, **не про услуги**: этого сегодня не
хватает страницам и блогу, поэтому делается в `module-seo` и `routing` и сразу подключается к
ним. Услуги и все модули после них получают это готовым.

Что уже есть и остаётся как есть: карточка `wx-seo` (`HasSeo`, `seo_meta`), правила по адресу,
умолчания сайта, редиректы, `robots.txt`, JSON-LD `Organization`, алиасы при смене слага.

### 17.1. Принятые решения (не переоткрывать)

1. **Контракты, а не плагины.** `SeoExtension` из §16 не делаем: у каждой вещи ниже ровно один
   вопрос к сущности, и он пишется интерфейсом на модели. Модуль реализует то, что ему нужно, и
   ничего не регистрирует.
2. **В карту сайта попадает ровно то, чему `<head>` не печатает `noindex` и чей canonical
   указывает на себя, — и отвечает на это тот же резолвер `Seo::for()`.** Своих правил отбора у
   карты нет. Иначе тег блога с правилом SEO (решение 10 спеки блога) был бы в индексе, но не в
   карте, или наоборот, и расхождения никто не увидит.
3. **«Видно ли на сайте» — один ответ для обработчика и для карты.** Сегодня публикацию проверяет
   обработчик (`WEBX_UI_ROUTING.md` §8.6), и у каждого модуля свой способ: `isPublished()` у
   страницы, `published()` со сравнением даты у статьи, `is_visible` у рубрики. Карте нужен тот же
   ответ запросом, а не на одной модели, поэтому в `routing` появляется контракт `Visible`
   (§17.2), и обработчики переходят на него же.
4. **Источник адресов карты — реестр `routing`**, канонические строки. Сущность без строки в
   реестре в карту не попадает по определению: у неё нет адреса.
5. **Собственный canonical по умолчанию.** Страница сущности печатает `<link rel="canonical">` на
   свой канонический адрес, даже если поле в карточке SEO пустое. Из query сохраняется только
   `page` (решение 12 блога: пагинация в query), всё остальное отбрасывается. Заполненное поле
   карточки или правила по-прежнему выигрывает.
6. **Хлебные крошки — одна цепочка для разметки и для вёрстки.** Сущность отдаёт список, из него
   печатаются и `BreadcrumbList`, и видимые крошки (Blade-компонент). Две цепочки разъедутся
   первой же сменой главной рубрики.
7. **schema.org сущности модуль пишет кодом**, как и решено в §2.6. Конструктора типов в панели
   по-прежнему нет. Поле «свой JSON-LD» у правила остаётся для штучных исключений.
8. **hreflang — из реестра.** Альтернативы языков у сущности — её канонические строки в других
   языках, в которых она видна. Для адресов без сущности (лента блога, свои маршруты модулей) —
   тот же путь под приставкой каждого активного языка, и только при стратегии `prefix`: при
   `header` адрес один на все языки, и альтернатив нет.

### 17.2. Контракты

```php
namespace WebxUi\Routing\Contracts;

/** Whether the public site shows this entity. The handler and the sitemap ask the same thing. */
interface Visible
{
    public function isVisible(?string $locale = null): bool;

    /** The same answer as a query, for lists and the sitemap. */
    public function scopeVisible(Builder $query, ?string $locale = null): Builder;

    /** For <lastmod>: when what a reader sees last changed. */
    public function visibleUpdatedAt(): ?CarbonInterface;
}
```

```php
namespace WebxUi\Seo\Contracts;

/** The trail above an entity, the entity itself last, the site's home not included. */
interface HasBreadcrumbs
{
    /** @return list<Crumb> */
    public function breadcrumbs(string $locale): array;
}

final readonly class Crumb
{
    public function __construct(public string $title, public ?string $url) {}
}

/** Schema.org blocks this entity says about itself. */
interface HasStructuredData
{
    /** @return list<array<string, mixed>> */
    public function structuredData(string $locale): array;
}
```

Главную сайта в крошки первым пунктом добавляет сам `module-seo`: её название — настройка
`seo.home-crumb` (переводимая, по умолчанию слово из словаря), адрес — корень в языке. Сущность
про главную не знает.

JSON-LD, который зависит не от сущности, а от конкретной выдачи (`ItemList` на странице рубрики:
какие статьи на этой странице пагинации), кладёт обработчик: `Seo::push(array $block)`. Блок живёт
до конца запроса и складывается с остальными, как `jsonLd` в `mergeOver()`.

### 17.3. Карта сайта

- **`/sitemap.xml` — индекс**, по файлу на тип реестра: `/sitemap-{type}.xml`. Если у типа больше
  45 000 адресов — `/sitemap-{type}-{n}.xml` (лимит протокола 50 000, запас на языки).
- **Строка карты:** `<loc>` канонического адреса, `<lastmod>` из `visibleUpdatedAt()`, на
  многоязычном сайте — `xhtml:link rel="alternate" hreflang` на каждый язык сущности и
  `x-default` на язык по умолчанию. `changefreq` и `priority` не печатаем: поисковики их
  игнорируют, а редактор будет их крутить.
- **Отбор** (решение 2). Тип участвует, если его модель реализует `Visible`. Строки берутся
  пачками по 500 канонических строк реестра с `scopeVisible()`, `seo_meta` подгружается к пачке
  одним запросом, и каждая строка проходит `Seo::for()`. Правила по адресу сверяются со
  скомпилированным кешем (§4), так что отдельного запроса на строку нет.
- **Маршруты модулей без сущности** (лента блога, индекс услуг) попадают в карту через
  `SitemapRoutes::register('blog.feed')` из провайдера модуля. Это именованный маршрут: строки в
  реестре у него нет, а в карте он нужен. Отбор тот же — через резолвер.
- **Кеш.** Файлы строятся по первому запросу и кладутся в кеш приложения. Ключ несёт номер
  поколения, который поднимается на любое сохранение строки реестра, `seo_meta`, `seo_urls` и
  настроек `seo.*`. Страховка — TTL в сутки: будущая дата статьи наступает без события.
  `webx:seo:sitemap` прогревает всё сразу — для деплоя и для большого сайта.
- **`robots.txt`** дописывает строку `Sitemap: <абсолютный адрес>`, если в настройке её нет. В
  панели эту строку не видно, поэтому подсказка под полем говорит, что она добавится сама.
- **Выключатель** — `webx-seo.sitemap.enabled` (по умолчанию включено). Сайт со своей картой
  выключает его и остаётся со своей.

### 17.4. `<head>` сущности

`<x-webx-seo::head :for="$entity" />` (и `@webxSeo($entity)`) дополнительно печатает:

- `<link rel="canonical">` на себя, если canonical не задан (решение 5);
- `<link rel="alternate" hreflang>` по решению 8 и `x-default`;
- `BreadcrumbList` из `breadcrumbs()`, если сущность реализует `HasBreadcrumbs`;
- блоки `structuredData()` и всё, что положено через `Seo::push()`;
- `twitter:card`: `summary_large_image`, если есть `og:image`, иначе `summary`. Остальное Twitter
  читает из Open Graph, своих полей в карточке не заводим.

Видимые крошки — `<x-webx-seo::breadcrumbs :for="$entity" />`: `<nav aria-label>` со списком,
последний пункт без ссылки, с `aria-current="page"`. Вьюху сайт публикует и переделывает, но
цепочку берёт отсюда же (решение 6).

Всё печатаемое идёт через конфиг `webx-seo.print`, как сейчас, и каждую вещь можно выключить.

### 17.5. Первые потребители

| --------- | ---------------------------------- | --------------------------------------------- | ---------------------------------------------- |

### 17.7. Тесты

- Карта: опубликованная страница есть, черновика нет. Запланированной статьи нет, и она
  появляется после сдвига времени (по TTL, а не по событию). Сущности с `noindex` в карточке нет.
  Правило по маске с `noindex` убирает все совпавшие адреса. Адреса с чужим canonical нет.
- Тег: с флагом и без правила — нет, с правилом — есть (решение 2).
- Многоязычие: адрес в каждом языке. У сущности без слага в языке нет альтернативы в нём.
  `x-default` ведёт на язык по умолчанию. При стратегии `header` альтернатив нет вовсе.
- Разбиение на файлы по порогу: порог в тесте понижается конфигом, а не заведением 45 000 строк.
- Поколение кеша поднимается при сохранении страницы и правила. `webx:seo:sitemap` строит всё.
- canonical: пустое поле — на себя. `?page=2` сохраняется, `?utm_source=` отбрасывается.
  Заполненное поле выигрывает.
- Крошки: разметка и видимые крошки из одной цепочки. Смена главной рубрики меняет обе.
- `robots.txt` получает строку `Sitemap:` один раз, даже если её уже вписали руками.
- Обработчики страниц и блога отвечают 404 по `Visible` на том же наборе случаев, что и карта.
- Экранирование в JSON-LD крошек и `structuredData()`: кавычки и `<` в заголовке.
- `scripts/php-smoke.sh`: карта отдаётся после `route:cache` и `config:cache`.

**S1 сделана 23.09.2026.** Что вышло не так, как написано выше:

- **Canonical на себя — у любой страницы, а не только у сущности.** Он ставится в `Seo::for()`,
  то есть его видят и `<head>`, и карта, и `test-url`; `og:url` берёт его же. Выключатель —
  `webx-seo.canonical.self`, список сохраняемых параметров query — `webx-seo.canonical.query`.
- **Именованные маршруты — файлом `sitemap-routes.xml`.** Тип реестра с именем `routes` лёг бы в
  тот же файл.
- **`lastmod`:** у страницы — дата публикации (каждая публикация ставит её заново), у статьи —
  позднее из даты и последней публикации в истории (дата бывает задним числом), у рубрики и тега
  — `updated_at`.
- **Поколение поднимает один wildcard-слушатель `eloquent.*`** на строку реестра, `seo_meta`,
  `seo_urls` и любую модель `Visible`, плюс `SettingsSaved` с ключом `seo.*`. Модулю, у которого
  появляется `Visible`, делать ничего не нужно.
- **Адреса в карте — от хоста запроса**, как и всё, что печатает `url()`; команда строит от
  `APP_URL`. На одном домене это одно и то же.

**S2 сделана 23.09.2026.** Что вышло не так, как написано выше:

- **Альтернатива — только открытая для индекса.** `hreflang` в `<head>` и в карте называет язык,
  только если сущность в нём видна и `Seo::for()` этого адреса не печатает ни `noindex`, ни чужой
  canonical; страница, закрытая сама, не печатает альтернатив вовсе. Меньше двух языков — ни одной
  строки. В карте набор берётся из уже отобранных строк той же сущности, поэтому он совпадает с
  `<head>` по построению. Общий ответ «почему закрыто» — `Seo::closedBecause()`.
- **Шаг крошек без адреса или невидимый.** `Crumb::$url` может быть `null` — такой шаг печатается
  текстом, а в `BreadcrumbList` остаётся без `item`. Невидимый предок страницы и скрытая главная
  рубрика статьи выпадают из цепочки целиком — ссылка на 404 хуже, чем шаг меньше. У главной
  страницы цепочки нет вовсе.
- **`Seo::push()` живёт в атрибутах запроса**, а не в синглтоне: второй запрос того же процесса
  чужой `ItemList` не печатает.
- **Карточка «Карта сайта»** — полоса над таблицей правил в той же карточке; `test-url` отвечает
  `sitemap: {included, reason}` с причинами `disabled`, `unknown`, `alias`, `hidden`, `noindex`,
  `canonical`. `excluded` на карточке считает только `noindex` и чужой canonical: черновики — не
  вопрос «почему страницы нет в выдаче».
- **На `webx-cms.local` у статей один язык**, поэтому для проверки `hreflang` статья
  «Как выбрать приводной ремень» переведена на `uk` и `en` прямо в базе демо. Рубрика «Ремонт»
  осталась только русской и из украинской и английской цепочек выпадает — так и задумано.
