# Свойства каталога — `module-catalog-properties`

Спутник ядра каталога: свойства товаров, их значения, наборы по категориям, фасеты из свойств,
характеристики на витрине. Архитектура семейства — [`WEBX_UI_CATALOG.md`](WEBX_UI_CATALOG.md) (§6.2,
§8.3, §11), ядро и его реестры — [`WEBX_UI_MODULE_CATALOG.md`](WEBX_UI_MODULE_CATALOG.md) §7,
каркас справочников — [`WEBX_UI_CATALOG_DICTIONARIES.md`](WEBX_UI_CATALOG_DICTIONARIES.md); здесь
они не повторяются. Статус: спека согласована 30.09.2026, код не начат. Порядок работ — §14.

## 1. Решения (не переоткрывать)

Приняты в обсуждении 30.09.2026.

1. **Четыре типа:** справочник, число, текст, да/нет. Тип после сохранения не меняется — у
   значений товаров разная форма; «сменить тип» — это новое свойство и массовый перенос.
2. **У числа — единица префиксом и суффиксом**, обе переводимые и необязательные (`M` + `8`,
   `⌀` + `12` + ` мм`, `12` + ` кг` / ` kg`), и точность — сколько знаков после запятой показывать.
3. **В фильтр свойство попадает своим флагом.** Вкладка «Фильтры» категории из ядра остаётся и
   решает другое: где фасет виден и в каком порядке (§6.2 ядра).
4. **Текстовое свойство в фильтр не попадает никогда**, флага у него нет; значение переводимое.
5. **У товара — свойства набора его основной категории.** Набор наследуется: категория получает
   свойства всех предков и добавляет свои, убрать унаследованное нельзя. Порядок задаёт набор;
   унаследованные идут первыми, в порядке предка.
6. **Значения вне набора сохраняются.** Товар переехал в категорию, где свойства нет, — значение
   остаётся в базе, но нигде не показывается и не индексируется; вернули — всё на месте. Чистка —
   явным действием «удалить значения вне набора».
7. **Код свойства и слаг значения — на каждом языке.** `/noutbuki/cvet_chernyy/` и
   `/en/laptops/color_black/`. Внутренний ключ фасета (`p.12`) один и в адрес не попадает.
   Уникальность — в пределах языка; `_` запрещён везде.
8. **Смена кода или слага на любом языке — 301 со старого адреса.** Старые написания хранит ядро
   (§4.2), а не каждый спутник: переименовать умеют и бренды.
9. **Коды фасетов ядра и брендов тоже переводимы** — конфигом; по умолчанию один на все языки.
10. **Справочник значений:** комбобокс с поиском и созданием значения на лету в форме товара,
    ленивое дерево в разделе, слияние значений вместо запрета удалить используемое.
11. **Число в фильтре — слайдером или интервалами**, выбор у свойства. Интервалы задаёт админ
    (подпись, от, до, слаг на каждом языке); первый уровень по интервалу может быть открыт.
12. **Обмен:** колонка на свойство, в заголовке код; несколько значений — через `;`; дерево — путь
    через `/`; число — без единицы; незнакомое значение справочника создаётся или даёт ошибку
    строки — переключатель профиля импорта. Объявляются со спекой обмена (§11).
13. **Группы свойств для карточки** («Экран», «Процессор») — у свойства, общие на сайт.
14. **Значение справочника может нести цвет и картинку** — флагами у свойства.
15. **«В карточке»** — короткий список в плитке каталога; **«на странице»** — полная таблица
    характеристик товара.
16. **Порядок значений** — «по алфавиту» или «вручную», переключатель у свойства; числа и
    интервалы — всегда по возрастанию.
17. **Поиск по значениям** — флаг «искать по значению», по умолчанию включён у справочника и
    текста.
18. **Список товаров в панели:** фасет свойства — фильтр списка сам собой; колонка — отдельным
    флагом.
19. **Права — каталога** (`catalog.view` / `catalog.manage`), MCP — скоупы `catalog:read` /
    `catalog:write`, как у справочников (решение 8 `WEBX_UI_CATALOG_DICTIONARIES.md`). Поля товара
    — через `catalog_products_update`, своих инструментов на товар нет.
20. **Всё сразу**, одной серией: интервалы, слияние, цвет и картинка значений входят в первую
    версию.

## 2. Схема

Миграции — день `2026_01_04` (после справочников). Индексы — на всём, по чему ищут и соединяют.

### `catalog_property_groups`

Набор `Categories` из `module-admin` (`$table->category()`), как метки: `title` (переводимое),
`position`, `is_visible`, `extra`, корзина. `slug` пустой. Свойство без группы стоит в карточке
последним блоком без заголовка.

### `catalog_properties`

| Колонка                      | Тип                                | Примечание                                                                  |
| ---------------------------- | ---------------------------------- | --------------------------------------------------------------------------- |
| `id`                         | bigint                             | ключ фасета — `p.{id}`                                                      |
| `title`                      | json                               | переводимое                                                                 |
| `code`                       | json                               | переводимое; `[a-z0-9-]`, уникален среди всех фасетов на своём языке (§4.1) |
| `type`                       | string(16)                         | `select`, `number`, `text`, `bool`; не меняется (решение 1)                 |
| `group_id`                   | FK `catalog_property_groups`, null | `nullOnDelete`                                                              |
| `is_multiple`                | bool                               | несколько значений; только `select`                                         |
| `is_tree`                    | bool                               | значения деревом; только `select`                                           |
| `leaves_only`                | bool                               | товару — только лист дерева                                                 |
| `is_filterable`              | bool, index                        | фасет; у `text` всегда `false`                                              |
| `filter_mode`                | string(16), null                   | у `number`: `slider` или `intervals`                                        |
| `is_indexable`               | bool                               | может ли первый уровень быть открыт (§5.3); по умолчанию — по виду фасета   |
| `is_searchable`              | bool                               | значение идёт в полнотекстовый поиск; по умолчанию да у `select` и `text`   |
| `in_card`                    | bool                               | в плитке каталога                                                           |
| `on_page`                    | bool, default true                 | в таблице характеристик                                                     |
| `in_list`                    | bool                               | колонка списка товаров в панели                                             |
| `value_order`                | string(16), default `alpha`        | `alpha` или `manual`; у `number` не действует                               |
| `has_color`, `has_image`     | bool                               | у значений справочника есть цвет / картинка                                 |
| `unit_prefix`, `unit_suffix` | json, null                         | переводимые; только `number`                                                |
| `precision`                  | tinyint, default 0                 | 0–6; только `number`                                                        |
| `toggle_slug`                | json, null                         | у `bool`: слаг «да» в адресе на каждом языке, по умолчанию `yes`            |
| `seo_pattern`                | json, null                         | переводимый шаблон SEO первого уровня (§5.3)                                |
| `position`                   | int                                | порядок в разделе и порядок фасетов по умолчанию                            |
| `extra`                      | json, null                         | поля проекта (`HasExtra`)                                                   |
| `deleted_at`, timestamps     |                                    |                                                                             |

Флаги, которые типу не положены, модель гасит при сохранении, а не отвергает: форма присылает
всё, что видела, и переключение типа на новом свойстве не должно давать 422.

### `catalog_property_values`

Справочник значений; `nestedSet()` со scope `property_id` — плоский справочник это дерево без
вложенности, и одна таблица держит оба случая.

| Колонка       | Тип                    | Примечание                                                           |
| ------------- | ---------------------- | -------------------------------------------------------------------- |
| `id`          | bigint                 | глобально уникален — одно многозначное поле индекса (§6.2 архитект.) |
| `property_id` | FK, index              | `cascadeOnDelete` — только при окончательном удалении свойства       |
| `nestedSet()` |                        | `parent_id`, `lft`, `rgt`, `depth`; scope — `property_id`            |
| `title`       | json                   | переводимое                                                          |
| `slug`        | json                   | переводимое; `[a-z0-9-]`, уникален во всём свойстве на своём языке   |
| `color`       | string(7), null        | `#rrggbb`; данные, а не стиль — рисует его шаблон сайта              |
| `image_id`    | FK `media_files`, null | `nullOnDelete`; из библиотеки `module-media`                         |
| `extra`       | json, null             |                                                                      |
| timestamps    |                        |                                                                      |

Порядок «вручную» — это `lft` дерева: одна механика перетаскивания для плоского и древовидного.
Корзины у значения нет — есть слияние (§3.3). Пустой слаг берётся из названия.

### `catalog_property_intervals`

`id`, `property_id` (FK, index), `title` (json), `slug` (json, уникален в свойстве на языке),
`min`, `max` (decimal(20,6), null — открытый край), `position`. Интервал — `[min, max)`:
«1–2 кг» и «2–3 кг» не делят товар весом ровно 2. Пересекаться интервалы могут («до 1 кг» и
«до 2 кг») — это выбор админа, фасет считает каждый честно.

### `catalog_category_property`

`category_id`, `property_id`, `position`; первичный ключ по паре, index на `property_id`. Только
свои строки категории; наследование — чтением (§3.2).

### `catalog_product_property_values`

Одна строка на значение (§6.2 архитектуры).

| Колонка       | Тип                                | Примечание                                          |
| ------------- | ---------------------------------- | --------------------------------------------------- |
| `id`          | bigint                             |                                                     |
| `product_id`  | FK, index                          | `cascadeOnDelete` — товар удаляется только soft     |
| `property_id` | FK                                 |                                                     |
| `value_id`    | FK `catalog_property_values`, null | `select`                                            |
| `number`      | decimal(20,6), null                | `number`                                            |
| `flag`        | bool, null                         | `bool`; хранится только `true` — «нет» и есть пусто |
| `text`        | json, null                         | `text`, переводимое                                 |

Индексы: `(product_id, property_id)`, `(property_id, value_id)`, `(property_id, number)`.
Одна колонка на тип, а не одна строковая на всё: число сравнивается как число, а значение
справочника соединяется ключом.

## 3. Свойства и значения

### 3.1. Тип и форма значения

| Тип      | Значение товара                  | Фасет                                     | Индекс                        |
| -------- | -------------------------------- | ----------------------------------------- | ----------------------------- |
| `select` | id или список id (`is_multiple`) | `Terms`, у дерева — `Tree`                | `pv` — id с предками          |
| `number` | число                            | `Range` (слайдер) или `Terms` (интервалы) | `pn` — JSON по id свойства    |
| `bool`   | `true` или пусто                 | `Toggle`                                  | `pb` — id свойств с «да»      |
| `text`   | карта языков                     | нет                                       | `pt` — текст, по полю на язык |

- **Дерево и `leaves_only`:** товару можно поставить узел середины, если флага нет («подходит ко
  всем поколениям BMW 3»). В индекс узел идёт с предками (§8.3 архитектуры).
- **Число** хранится как есть, показывается с точностью и единицей: `M8`, `⌀12 мм`, `1,35 кг` —
  разделитель дроби по языку страницы.
- **Интервал** — не значение товара, а способ фильтра: товар хранит число, фасет раскладывает его
  по интервалам. Сменили интервалы — товары не трогаются, меняется только фасет.

### 3.2. Набор категории

Действующий набор категории — свойства всех предков от корня плюс свои, одним запросом по
`lft/rgt`, с кешем на категорию; сброс — сохранение любого набора и перенос в дереве.

- В форме товара, в фасетах страницы категории, в карточке и документе индекса товара участвуют
  только свойства действующего набора **основной** категории (решение 5). Дополнительные категории
  набора не добавляют.
- Свойство уже есть у предка — добавить его в набор потомка нельзя (422 с именем предка): иначе
  «убрать» из потомка превратилось бы в «переставить».
- Правка набора и перенос категории помечают товары её поддерева `touchQuery` — одним запросом.

### 3.3. Слияние, удаление, чистка

- **Слияние значений** `A → B` (одного свойства): у товаров `A` меняется на `B` (дубль у
  многозначного схлопывается), слаги `A` на всех языках становятся псевдонимами `B` (§4.2), `A`
  удаляется. У дерева `A` не может быть предком `B`; дети `A` переезжают к `B`. Одна транзакция,
  одна запись журнала, `touchQuery` по товарам `A`.
- **Удалить значение**, за которым нет товаров, — можно; с товарами — 422 с числом и подсказкой
  «слить». Слаги удалённого — псевдоним «убрать сегмент» (§4.2).
- **Удалить свойство** — в корзину: значения товаров остаются (как при переезде, решение 6),
  фасет пропадает, его коды — псевдоним «убрать сегмент». Восстановление возвращает всё.
  Окончательного удаления из панели нет, как у товаров.
- **Удалить значения вне набора** — массовое действие (§9.4) по выбору товаров; журнал пишет
  удалённое.

### 3.4. Коды и слаги

Код свойства и слаг значения на пустом языке берутся из названия транслитерацией ядра
(`Str::slug` с языком). Занятый код — 422 с держателем: другое свойство, фасет ядра или бренды.
Смена — псевдоним со старого написания (§4.2); проверка при сохранении, а не при запуске, потому
что свойства живут в базе.

## 4. Правки ядра

Всё — в `module-catalog`, первой сессией (P1), до кода свойств; каждая правка полезна и без них.

### 4.1. Код фасета на языке

- `Facet::code(string $locale): string` вместо `code()`. `Facets::byCode($code, $locale)`,
  проверка уникальности при регистрации — на каждом языке `webx-localization`.
- Коды ядра и брендов — из конфига: `webx-catalog.facet_codes` =
  `['price' => ['ru' => 'cena'], 'category' => [...], 'brand' => [...]]`; нет строки — прежний
  английский код на всех языках. `AbstractFacet` читает конфиг, фасетам ничего не делать.
- `SegmentSerializer` разбирает и строит сегменты кодом на языке контекста.

### 4.2. Псевдонимы фильтра — `catalog_filter_aliases`

`facet_key`, `locale`, `kind` (`code` | `value`), `old` (string), `target` (string, null), index по
`(locale, kind, old)`. `target` — новый код или значение фасета; `null` — «убрать сегмент».

- Разбор хвоста не нашёл код или слаг — спрашивает псевдонимы; нашёл — состояние строится из
  цели, и существующая проверка «одно написание» отвечает 301 на канон (§7.7 ядра). Сегмент с
  `null` выпадает — `/noutbuki/color_black/` удалённого свойства ведёт 301 на `/noutbuki/`.
- Цепочки не копятся: запись псевдонима `B → C` переписывает все `… → B` на `C`.
- Пишут псевдонимы фасеты сами, через `FilterAliases::record()`: свойства (код, слаг, слияние,
  удаление), бренды (слаг) — в этой же серии, отдельной строкой в P1.

### 4.3. Фасеты из базы

Статический реестр регистрирует фасеты при загрузке, а свойства живут в базе. `Facets` получает
**источник фасетов** — `Facets::source(FacetSource)`, который реестр спрашивает лениво при первом
чтении и держит до конца запроса; сам источник кеширует список в `cache` и сбрасывает его при
сохранении свойства. Фасеты источника идут после зарегистрированных, по `position`.

### 4.4. Фасет, привязанный к контексту

Двести свойств — двести фасетов, и на `SqlEngine` это двести запросов счётчиков. Поэтому фасет
может ответить, уместен ли он на странице: необязательный интерфейс `ContextualFacet::availableIn(
FilterContext $context): bool`. Свойства отвечают так: фасет есть, только если известна категория
— страница категории или выбранная в фильтре одна категория — и свойство в её действующем наборе.
На странице бренда, в поиске и в корне свойства появляются после выбора категории.

Правило ядра «фасет, зарегистрированный позже настройки, в настроенной категории скрыт» (§6.2
ядра) для свойств ослаблено: свойство, которое админ сам добавил в набор и сам пометил «в
фильтре», появляется в настроенной категории последним — это два явных действия, а не новый
модуль, молча меняющий чужие фильтры. Скрыть его можно на вкладке «Фильтры», как любой фасет.

### 4.5. Поиск по значениям на `SqlEngine`

Сейчас `SqlEngine` ищет `like` по названию, артикулу и штрихкоду. Нужен шов:
`SearchContributor::applySql(Builder $query, string $text, string $locale)`, условия которого
присоединяются через `or`. Свойства ищут по названиям значений (`select`) и тексту (`text`) у
свойств с `is_searchable`. Движок с индексом берёт поле `pt` из документа (§6).

## 5. Фасеты

### 5.1. Какие

| Свойство            | Вид      | Значение фасета | Адрес               | Индексируемый по умолчанию |
| ------------------- | -------- | --------------- | ------------------- | -------------------------- |
| `select`            | `Terms`  | id значения     | `color_black`       | да                         |
| `select`, `is_tree` | `Tree`   | id узла         | `material_steel`    | да                         |
| `number`, слайдер   | `Range`  | `min`–`max`     | `weight_1-2.5`      | нет, и включить нельзя     |
| `number`, интервалы | `Terms`  | id интервала    | `weight_up-to-1-kg` | да                         |
| `bool`              | `Toggle` | `1`             | `wifi_yes`          | нет                        |

- Фасет свойства реализует `OrderedFacet`, если `value_order = manual`; интервалы — всегда по
  `position` (от меньшего к большему — забота админа, форма предлагает отсортировать).
- Значения с цветом или картинкой фасет отдаёт в `labels()` как обычно; цвет и картинку фильтру
  даёт отдельный метод фасета свойств `swatches(array $values)` пачкой — партиал фильтра рисует
  кружки (§8.2).
- Снятая группа ничего не прячет: группа — только заголовок карточки.

### 5.2. Счёт

`sqlValues()` — пары из `catalog_product_property_values` только по товарам, у которых свойство в
действующем наборе основной категории (решение 6). На странице категории это условие одно для
всех товаров — набор известен; в `sqlValues` оно всё равно есть, потому что выбранная в фильтре
категория может быть родителем с разными наборами у детей. Дерево отдаёт узел с предками через
`lft/rgt`; интервалы — `case` по границам.

### 5.3. SEO первого уровня

Шаблон ядра «{категория} {значение}» (решение 17 архитектуры) для свойств часто звучит плохо
(«Ноутбуки Чёрный»). У свойства — необязательный переводимый шаблон `seo_pattern` (колонка json
в `catalog_properties`) с подстановками `{category}`, `{property}`, `{value}`: «{category} цвета
{value}». Пусто — шаблон ядра. Правило `module-seo` для адреса бьёт и его.

## 6. Индекс

`DocumentContributor` кладёт:

| Поле | Тип                   | Что                                                                       |
| ---- | --------------------- | ------------------------------------------------------------------------- |
| `pv` | int, multi            | id значений справочников с предками — из действующего набора              |
| `pi` | int, multi            | id интервалов, в которые попало число — фасету интервалов не надо считать |
| `pn` | JSON                  | `{ "12": 1.35 }` — числа по id свойства; новое свойство не меняет схему   |
| `pb` | int, multi            | id свойств со значением «да»                                              |
| `pt` | text, по полю на язык | названия значений и текст свойств с `is_searchable`                       |

Смена интервалов свойства помечает его товары `touchQuery` (меняется `pi`). Правка названия или
слага значения — товары значения (меняется `pt` и подписи).

## 7. Панель

### 7.1. Меню и экраны

«Каталог» → часть «Справочники» → «Свойства», order 312 (`HasNavSection`, §5
`WEBX_UI_CATALOG_DICTIONARIES.md`). Группы свойств — кнопка «Группы» в шапке раздела (как
«Категории» у товаров), `CategoriesPage` набора.

| Экран                     | Что                                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `catalog.properties`      | список: название, код, тип, группа, флаги значками, число товаров; фильтр по типу и группе; порядок перетаскиванием |
| `catalog.property-form`   | «Основное», «Значения» (`select`), «Интервалы» (`number` с интервалами), «История»                                  |
| `catalog.property-groups` | набор `Categories`                                                                                                  |

**«Основное»:** название, код (карта языков, предлагается из названия), тип (только у нового),
группа, флаги — видны только положенные типу; у числа — префикс, суффикс, точность, «слайдер /
интервалы» с живым примером `⌀12 мм`; у `bool` — слаг «да»; шаблон SEO.

**«Значения»** — узел `wx-catalog-property-values`: ленивое дерево (`useTreeNodes`) с поиском,
перетаскивание порядка и вложенности (если `is_tree`), строка — название, слаг, цвет (`WxColorPicker`),
картинка (выбор из `module-media`), число товаров; добавление строкой сверху; «Слить с…» в `···`
строки — выбор цели поиском, подтверждение с числом товаров. При `value_order = alpha` порядок не
перетаскивается — список по алфавиту языка панели.

**«Интервалы»** — таблица: подпись, от, до, слаг; добавить, удалить, перетащить; кнопка
«Отсортировать по границам».

### 7.2. Категория и товар

- **Форма категории** — вкладка «Свойства» патчем `catalog.category-form`: сверху
  унаследованные (приглушённые, с «из Электроники»), ниже свои — добавление поиском по свойствам,
  перетаскивание, удаление. Узел `wx-catalog-category-properties`.
- **Форма товара** — вкладка «Характеристики» патчем `catalog.product-form`, узел
  `wx-catalog-product-properties`: поля действующего набора основной категории по группам. Сменили
  основную категорию в форме — вкладка перечитывает набор сразу, до сохранения. Поле по типу:
  `select` — комбобокс с поиском и «Создать „…“» (при праве `catalog.manage`), у дерева — выбор в
  дереве; `number` — число с префиксом и суффиксом; `bool` — переключатель; `text` — `WxInput` с
  `localized`. Значения вне набора — свёрнутый блок «Вне набора категории» внизу, только чтение и
  кнопка «Удалить».
- **Список товаров** — колонки свойств с `in_list` через `ProductColumns` (значение строкой в
  единицах), фильтры — фасеты сами (решение 18). В фильтре списка панели привязка к контексту
  (§4.4) та же: свойства появляются, когда выбрана категория.

### 7.3. API

```
GET    /api/cms/catalog/properties                    ?q&type&group&page&per_page → paginate
POST   /api/cms/catalog/properties                    { values } → 201
GET    /api/cms/catalog/properties/{id}               → { data: { property, values } }
PUT    /api/cms/catalog/properties/{id}               { values } — часть полей, как у товара
POST   /api/cms/catalog/properties/reorder            { ids }
DELETE /api/cms/catalog/properties/{id}               soft → 204
POST   /api/cms/catalog/properties/{id}/restore
GET    /api/cms/catalog/properties/{id}/values        ?q&parent_id&page → узлы (ленивое дерево) | paginate (поиск)
POST   /api/cms/catalog/properties/{id}/values        { title, slug?, parent_id?, color?, image_id? } → 201
PUT    /api/cms/catalog/properties/{id}/values/{v}    { … }
POST   /api/cms/catalog/properties/{id}/values/{v}/move   { parent_id, before_id }
POST   /api/cms/catalog/properties/{id}/values/{v}/merge  { into } → { data: { moved } }
DELETE /api/cms/catalog/properties/{id}/values/{v}    204; с товарами — 422 с meta { products }
PUT    /api/cms/catalog/properties/{id}/intervals     { intervals: [...] } — все по порядку
GET    /api/cms/catalog/categories/{id}/properties    → { data: { inherited: [{ property, from }], own: [property] } }
PUT    /api/cms/catalog/categories/{id}/properties    { ids } — свои по порядку
GET    /api/cms/catalog/property-sets/{category}      действующий набор для формы товара, с группами
```

- **`property`**: `id, title, code` (карты), `type, group: { id, title } | null`, флаги,
  `unit_prefix, unit_suffix` (карты), `precision, filter_mode, value_order, toggle_slug,
seo_pattern, position, products_count, deleted_at`.
- **Значение**: `id, parent_id, title, slug` (карты), `color, image: { id, url, thumb } | null,
depth, has_children, products_count`.
- **Часть формы товара** — ключ `properties`, одно поле `properties.values`: объект
  `{ "<property_id>": значение }` по форме §3.1. Отсутствующий ключ не трогается, `null` — снять
  значение. Свойство не из набора — 422 по полю. `read()` отдаёт действующий набор и отдельно
  `properties.outside` — значения вне набора (только чтение).

### 7.4. Журнал

Свойство, группа и значение пишут журнал своими записями (`RecordsHistory`), как категории.
Значения товара — строки в записи сохранения товара: «Цвет: Чёрный → Серый», «Вес: 1,35 кг →
1,4 кг» — подписи и единицы на языке панели в момент записи. Слияние — одна запись у целевого
значения со строкой «Слито: Черный, товаров: 37» — счёт в конце строки.

## 8. Витрина

### 8.1. Карточка и страница

- **`catalog.card.meta`** — свойства с `in_card` в порядке набора: «Диагональ: 15,6″». Вьюха
  `webx-catalog-properties::card`.
- **`catalog.product.tabs`** — «Характеристики»: таблица по группам в порядке набора, свойства с
  `on_page`. Вьюха `webx-catalog-properties::table` (`dl.wx-catalog-specs` по группе). Значение
  справочника со страницей первого уровня — ссылка на неё (`/noutbuki/color_black/`), если адрес
  открыт; иначе текст.
- `prepare()` частей грузит значения всей страницы одним запросом, подписи — вторым.

### 8.2. Фильтр

Партиалы ядра по виду фасета плюс переопределения по свойству: `webx-catalog::filter.terms`
получает `swatches` — кружок цвета или картинка перед подписью. Слайдер — форма диапазона ядра
(§7.7 ядра), ползунок — забота сайта. Интервалы — как термы.

### 8.3. Выборка в шаблоне

`products()->property('color', 'black')` — код и слаг на языке выборки (или id);
`->property('weight', min: 1, max: 2)`; `->property('wifi')` — «да». Макросы поверх
`narrowedBy`, как у справочников. У товара в шаблоне — `$product->properties()` (загружено частью
пачкой) с `value`, `formatted`, `group`, `url`.

### 8.4. Карта сайта

Непустые открытые первые уровни свойств идут в файл `catalog-filters` ядра через его же источник —
ядро спрашивает фасеты, а не модули.

## 10. MCP

Скоупы `catalog:read` / `catalog:write`, права `catalog.view` / `catalog.manage` (решение 19).
Изменяющие — с `dry_run`.

| Инструмент                                                                | Что                                 |
| ------------------------------------------------------------------------- | ----------------------------------- |
| `catalog_properties_list` / `get`                                         | с флагами, группой, числом товаров  |
| `catalog_properties_create` / `update` / `delete` / `reorder`             | `update` принимает и интервалы      |
| `catalog_property_values_list`                                            | поиск и ветка дерева                |
| `catalog_property_values_create` / `update` / `move` / `merge` / `delete` | `merge` с `dry_run` — число товаров |
| `catalog_property_groups_*`                                               | `CategoryTools` набора              |
| `catalog_categories_properties` / `catalog_categories_properties_set`     | действующий набор / свои по порядку |

Ресурс `catalog://properties` — свойства с типами, кодами на языках, единицами и допустимыми
флагами: агент не должен предлагать фасет текстовому. Поля товара — часть `properties` в
`catalog://product-parts` (`describe()`), значение справочника — id или слаг на любом языке, как
у брендов; незнакомый слаг — ошибка с подсказкой `catalog_property_values_create`.

## 11. Отложено

Колонки обмена (со спекой обмена); несколько чисел у одного свойства; синонимы значений для
поиска; переопределение флагов свойства в отдельной категории; таблицы размеров
(`module-catalog-sizes`) — поверх этого модуля, волна B.

## 12. Демо

Сидер сайта `CatalogPropertiesSeeder` в `webx-cms.local` (как у справочников — не `webx:demo`
пакета) и те же данные в фикстурах плейграунда: группы «Основное», «Габариты»; «Цвет» — с
цветами, многозначный, вручную; «Материал» — деревом («Металл / Сталь / Нержавеющая»); «Вес» —
кг, интервалы; «Диагональ» — `″`, слайдер, точность 1; «Wi-Fi» — да/нет; «Комплектация» — текст.
Наборы — на двух ветках дерева, одно свойство у корня (наследование видно). Пара товаров со
значением вне набора. Коды на русском переведены (`cvet`, `ves`), чтобы переводимые адреса были
видны.

## 13. Тесты, которые обязательны

- ядро: код фасета на языке, занятый на одном языке — ошибка при регистрации; псевдоним кода и
  слага даёт 301 на канон, «убрать сегмент» — 301 без него, цепочка схлопывается; источник фасетов
  спрашивается один раз на запрос; `ContextualFacet` без категории не считается; `SearchContributor`
  находит по значению;
- набор: наследование от предков, порядок «предки, потом свои», добавить свойство предка — 422,
  перенос категории помечает поддерево одним запросом;
- значения вне набора: не в форме, не в фасете, не в индексе, не в карточке — и возвращаются при
  возврате категории;
- типы: флаги не своего типа гасятся; текст не становится фасетом; `bool` хранит только «да»;
  `leaves_only` отвергает узел середины;
- интервалы: `[min, max)`, открытые края, пересекающиеся считаются каждый; смена интервалов
  помечает товары;
- слияние: дубль у многозначного схлопывается, слаги — псевдонимы, дерево — нельзя в потомка;
  удаление значения с товарами — 422 с числом;
- удалённое свойство: фасет пропал, адрес с ним — 301 без сегмента, значения товаров целы и
  возвращаются восстановлением;
- форма товара: смена основной категории меняет набор; упавшая часть откатывает всё; журнал —
  строки с подписями и единицами;
- витрина: карточка и таблица по группам и порядку набора; ссылка на открытый первый уровень;
  `seo_pattern` подставляется.
