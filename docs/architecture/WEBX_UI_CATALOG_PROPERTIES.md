# Свойства каталога — `module-catalog-properties`

Спутник ядра каталога: свойства товаров, их значения, наборы по категориям, фасеты из свойств,
характеристики на витрине. Архитектура семейства — [`WEBX_UI_CATALOG.md`](WEBX_UI_CATALOG.md) (§6.2,
§8.3, §11), ядро и его реестры — [`WEBX_UI_MODULE_CATALOG.md`](WEBX_UI_MODULE_CATALOG.md) §7,
каркас справочников — [`WEBX_UI_CATALOG_DICTIONARIES.md`](WEBX_UI_CATALOG_DICTIONARIES.md); здесь
они не повторяются. Статус: спека согласована 30.09.2026; P1 (правки ядра), P2 (пакет: данные и
API), P3 (витрина) и P4 (раздел панели, npm `@webx-ui/module-catalog-properties`) сделаны, как
легло в код — §15. Порядок работ — §14.

## 1. Решения (не переоткрывать)

Приняты в обсуждении 30.09.2026.

1. **Четыре типа:** справочник, число, текст, да/нет. Тип после сохранения не меняется — у
   значений товаров разная форма; «сменить тип» — это новое свойство и массовый перенос.
2. **У числа — единица префиксом и суффиксом**, обе переводимые и необязательные (`M` + `8`,
   `⌀` + `12` + ` мм`, `12` + ` кг` / ` kg`), и точность — сколько знаков после запятой показывать.
3. **В фильтр свойство попадает своим флагом.** Вкладка «Фильтры» категории из ядра остаётся и
   решает другое: где фасет виден и в каком порядке (§6.2 ядра).
4. **Текстовое свойство в фильтр не попадает никогда**, флага у него нет; значение переводимое.
5. **У товара — свойства набора его основной категории.** Набор наследуется: категория получает
   свойства всех предков и добавляет свои, убрать унаследованное нельзя. Порядок задаёт набор;
   унаследованные идут первыми, в порядке предка.
6. **Значения вне набора сохраняются.** Товар переехал в категорию, где свойства нет, — значение
   остаётся в базе, но нигде не показывается и не индексируется; вернули — всё на месте. Чистка —
   явным действием «удалить значения вне набора».
7. **Код свойства и слаг значения — на каждом языке.** `/noutbuki/cvet_chernyy/` и
   `/en/laptops/color_black/`. Внутренний ключ фасета (`p.12`) один и в адрес не попадает.
   Уникальность — в пределах языка; `_` запрещён везде.
8. **Смена кода или слага на любом языке — 301 со старого адреса.** Старые написания хранит ядро
   (§4.2), а не каждый спутник: переименовать умеют и бренды.
9. **Коды фасетов ядра и брендов тоже переводимы** — конфигом; по умолчанию один на все языки.
10. **Справочник значений:** комбобокс с поиском и созданием значения на лету в форме товара,
    ленивое дерево в разделе, слияние значений вместо запрета удалить используемое.
11. **Число в фильтре — слайдером или интервалами**, выбор у свойства. Интервалы задаёт админ
    (подпись, от, до, слаг на каждом языке); первый уровень по интервалу может быть открыт.
12. **Обмен:** колонка на свойство, в заголовке код; несколько значений — через `;`; дерево — путь
    через `/`; число — без единицы; незнакомое значение справочника создаётся или даёт ошибку
    строки — переключатель профиля импорта. Объявляются со спекой обмена (§11).
13. **Группы свойств для карточки** («Экран», «Процессор») — у свойства, общие на сайт.
14. **Значение справочника может нести цвет и картинку** — флагами у свойства.
15. **«В карточке»** — короткий список в плитке каталога; **«на странице»** — полная таблица
    характеристик товара.
16. **Порядок значений** — «по алфавиту» или «вручную», переключатель у свойства; числа и
    интервалы — всегда по возрастанию.
17. **Поиск по значениям** — флаг «искать по значению», по умолчанию включён у справочника и
    текста.
18. **Список товаров в панели:** фасет свойства — фильтр списка сам собой; колонка — отдельным
    флагом.
19. **Права — каталога** (`catalog.view` / `catalog.manage`), MCP — скоупы `catalog:read` /
    `catalog:write`, как у справочников (решение 8 `WEBX_UI_CATALOG_DICTIONARIES.md`). Поля товара
    — через `catalog_products_update`, своих инструментов на товар нет.
20. **Всё сразу**, одной серией: интервалы, слияние, цвет и картинка значений входят в первую
    версию.
21. **Фасеты свойств есть везде, не только в категории.** На странице категории их задаёт набор;
    в поиске, на странице бренда и в корне — охват найденного (§4.4): первые 8 с охватом от 10 %
    раскрыты, остальные — в «Ещё фильтры». Выбранный фасет раскрыт всегда.
22. **Адрес со свойством на странице бренда и в корне закрыт** (`noindex, follow`): первый
    уровень бренда — категории. «Чёрные вещи Apple» — посадочная, если решит сеошник.
23. **Выдачу для фасетов не урезаем.** Счётчики и число найденного честные: фасет, который
    обещает 40 товаров и приводит к 4000, хуже медленного. Дешевизну даёт один запрос на все
    невыбранные фасеты (§5.2), а не выборка.

## 2. Схема

Миграции — день `2026_01_04` (после справочников). Индексы — на всём, по чему ищут и соединяют.

### `catalog_property_groups`

Набор `Categories` из `module-admin` (`$table->category()`), как метки: `title` (переводимое),
`position`, `is_visible`, `extra`, корзина. `slug` пустой. Свойство без группы стоит в карточке
последним блоком без заголовка.

### `catalog_properties`

| Колонка                      | Тип                                | Примечание                                                                  |
| ---------------------------- | ---------------------------------- | --------------------------------------------------------------------------- |
| `id`                         | bigint                             | ключ фасета — `p.{id}`                                                      |
| `title`                      | json                               | переводимое                                                                 |
| `code`                       | json                               | переводимое; `[a-z0-9-]`, уникален среди всех фасетов на своём языке (§4.1) |
| `type`                       | string(16)                         | `select`, `number`, `text`, `bool`; не меняется (решение 1)                 |
| `group_id`                   | FK `catalog_property_groups`, null | `nullOnDelete`                                                              |
| `is_multiple`                | bool                               | несколько значений; только `select`                                         |
| `is_tree`                    | bool                               | значения деревом; только `select`                                           |
| `leaves_only`                | bool                               | товару — только лист дерева                                                 |
| `is_filterable`              | bool, index                        | фасет; у `text` всегда `false`                                              |
| `filter_mode`                | string(16), null                   | у `number`: `slider` или `intervals`                                        |
| `is_indexable`               | bool                               | может ли первый уровень быть открыт (§5.3); по умолчанию — по виду фасета   |
| `is_searchable`              | bool                               | значение идёт в полнотекстовый поиск; по умолчанию да у `select` и `text`   |
| `in_card`                    | bool                               | в плитке каталога                                                           |
| `on_page`                    | bool, default true                 | в таблице характеристик                                                     |
| `in_list`                    | bool                               | колонка списка товаров в панели                                             |
| `value_order`                | string(16), default `alpha`        | `alpha` или `manual`; у `number` не действует                               |
| `has_color`, `has_image`     | bool                               | у значений справочника есть цвет / картинка                                 |
| `unit_prefix`, `unit_suffix` | json, null                         | переводимые; только `number`                                                |
| `precision`                  | tinyint, default 0                 | 0–6; только `number`                                                        |
| `toggle_slug`                | json, null                         | у `bool`: слаг «да» в адресе на каждом языке, по умолчанию `yes`            |
| `seo_pattern`                | json, null                         | переводимый шаблон SEO первого уровня (§5.3)                                |
| `position`                   | int                                | порядок в разделе и порядок фасетов по умолчанию                            |
| `extra`                      | json, null                         | поля проекта (`HasExtra`)                                                   |
| `deleted_at`, timestamps     |                                    |                                                                             |

Флаги, которые типу не положены, модель гасит при сохранении, а не отвергает: форма присылает
всё, что видела, и переключение типа на новом свойстве не должно давать 422.

### `catalog_property_values`

Справочник значений; `nestedSet()` со scope `property_id` — плоский справочник это дерево без
вложенности, и одна таблица держит оба случая.

| Колонка       | Тип                    | Примечание                                                           |
| ------------- | ---------------------- | -------------------------------------------------------------------- |
| `id`          | bigint                 | глобально уникален — одно многозначное поле индекса (§6.2 архитект.) |
| `property_id` | FK, index              | `cascadeOnDelete` — только при окончательном удалении свойства       |
| `nestedSet()` |                        | `parent_id`, `lft`, `rgt`, `depth`; scope — `property_id`            |
| `title`       | json                   | переводимое                                                          |
| `slug`        | json                   | переводимое; `[a-z0-9-]`, уникален во всём свойстве на своём языке   |
| `color`       | string(7), null        | `#rrggbb`; данные, а не стиль — рисует его шаблон сайта              |
| `image_id`    | FK `media_files`, null | `nullOnDelete`; из библиотеки `module-media`                         |
| `extra`       | json, null             |                                                                      |
| timestamps    |                        |                                                                      |

Порядок «вручную» — это `lft` дерева: одна механика перетаскивания для плоского и древовидного.
Корзины у значения нет — есть слияние (§3.3). Пустой слаг берётся из названия.

### `catalog_property_intervals`

`id`, `property_id` (FK, index), `title` (json), `slug` (json, уникален в свойстве на языке),
`min`, `max` (decimal(20,6), null — открытый край), `position`. Интервал — `[min, max)`:
«1–2 кг» и «2–3 кг» не делят товар весом ровно 2. Пересекаться интервалы могут («до 1 кг» и
«до 2 кг») — это выбор админа, фасет считает каждый честно.

### `catalog_category_property`

`category_id`, `property_id`, `position`; первичный ключ по паре, index на `property_id`. Только
свои строки категории; наследование — чтением (§3.2).

### `catalog_product_property_values`

Одна строка на значение (§6.2 архитектуры).

| Колонка       | Тип                                | Примечание                                          |
| ------------- | ---------------------------------- | --------------------------------------------------- |
| `id`          | bigint                             |                                                     |
| `product_id`  | FK, index                          | `cascadeOnDelete` — товар удаляется только soft     |
| `property_id` | FK                                 |                                                     |
| `value_id`    | FK `catalog_property_values`, null | `select`                                            |
| `number`      | decimal(20,6), null                | `number`                                            |
| `flag`        | bool, null                         | `bool`; хранится только `true` — «нет» и есть пусто |
| `text`        | json, null                         | `text`, переводимое                                 |

Индексы: `(product_id, property_id)`, `(property_id, value_id)`, `(property_id, number)`.
Одна колонка на тип, а не одна строковая на всё: число сравнивается как число, а значение
справочника соединяется ключом.

## 3. Свойства и значения

### 3.1. Тип и форма значения

| Тип      | Значение товара                  | Фасет                                     | Индекс                        |
| -------- | -------------------------------- | ----------------------------------------- | ----------------------------- |
| `select` | id или список id (`is_multiple`) | `Terms`, у дерева — `Tree`                | `pv` — id с предками          |
| `number` | число                            | `Range` (слайдер) или `Terms` (интервалы) | `pn` — JSON по id свойства    |
| `bool`   | `true` или пусто                 | `Toggle`                                  | `pb` — id свойств с «да»      |
| `text`   | карта языков                     | нет                                       | `pt` — текст, по полю на язык |

- **Дерево и `leaves_only`:** товару можно поставить узел середины, если флага нет («подходит ко
  всем поколениям BMW 3»). В индекс узел идёт с предками (§8.3 архитектуры).
- **Число** хранится как есть, показывается с точностью и единицей: `M8`, `⌀12 мм`, `1,35 кг` —
  разделитель дроби по языку страницы.
- **Интервал** — не значение товара, а способ фильтра: товар хранит число, фасет раскладывает его
  по интервалам. Сменили интервалы — товары не трогаются, меняется только фасет.

### 3.2. Набор категории

Действующий набор категории — свойства всех предков от корня плюс свои, одним запросом по
`lft/rgt`, с кешем на категорию; сброс — сохранение любого набора и перенос в дереве.

- В форме товара, в фасетах страницы категории, в карточке и документе индекса товара участвуют
  только свойства действующего набора **основной** категории (решение 5). Дополнительные категории
  набора не добавляют.
- Свойство уже есть у предка — добавить его в набор потомка нельзя (422 с именем предка): иначе
  «убрать» из потомка превратилось бы в «переставить».
- Правка набора и перенос категории помечают товары её поддерева `touchQuery` — одним запросом.

### 3.3. Слияние, удаление, чистка

- **Слияние значений** `A → B` (одного свойства): у товаров `A` меняется на `B` (дубль у
  многозначного схлопывается), слаги `A` на всех языках становятся псевдонимами `B` (§4.2), `A`
  удаляется. У дерева `A` не может быть предком `B`; дети `A` переезжают к `B`. Одна транзакция,
  одна запись журнала, `touchQuery` по товарам `A`.
- **Удалить значение**, за которым нет товаров, — можно; с товарами — 422 с числом и подсказкой
  «слить». Слаги удалённого — псевдоним «убрать сегмент» (§4.2).
- **Удалить свойство** — в корзину: значения товаров остаются (как при переезде, решение 6),
  фасет пропадает, его коды — псевдоним «убрать сегмент». Восстановление возвращает всё.
  Окончательного удаления из панели нет, как у товаров.
- **Удалить значения вне набора** — массовое действие (§9.4) по выбору товаров; журнал пишет
  удалённое.

### 3.4. Коды и слаги

Код свойства и слаг значения на пустом языке берутся из названия транслитерацией ядра
(`Str::slug` с языком). Занятый код — 422 с держателем: другое свойство, фасет ядра или бренды.
Смена — псевдоним со старого написания (§4.2); проверка при сохранении, а не при запуске, потому
что свойства живут в базе.

## 4. Правки ядра

Всё — в `module-catalog`, первой сессией (P1), до кода свойств; каждая правка полезна и без них.

### 4.1. Код фасета на языке

- `Facet::code(string $locale): string` вместо `code()`. `Facets::byCode($code, $locale)`,
  проверка уникальности при регистрации — на каждом языке `webx-localization`.
- Коды ядра и брендов — из конфига: `webx-catalog.facet_codes` =
  `['price' => ['ru' => 'cena'], 'category' => [...], 'brand' => [...]]`; нет строки — прежний
  английский код на всех языках. `AbstractFacet` читает конфиг, фасетам ничего не делать.
- `SegmentSerializer` разбирает и строит сегменты кодом на языке контекста.

### 4.2. Псевдонимы фильтра — `catalog_filter_aliases`

`facet_key`, `locale`, `kind` (`code` | `value`), `old` (string), `target` (string, null), index по
`(locale, kind, old)`. `target` — новый код или значение фасета; `null` — «убрать сегмент».

- Разбор хвоста не нашёл код или слаг — спрашивает псевдонимы; нашёл — состояние строится из
  цели, и существующая проверка «одно написание» отвечает 301 на канон (§7.7 ядра). Сегмент с
  `null` выпадает — `/noutbuki/color_black/` удалённого свойства ведёт 301 на `/noutbuki/`.
- Цепочки не копятся: запись псевдонима `B → C` переписывает все `… → B` на `C`.
- Пишут псевдонимы фасеты сами, через `FilterAliases::record()`: свойства (код, слаг, слияние,
  удаление), бренды (слаг) — в этой же серии, отдельной строкой в P1.

### 4.3. Фасеты из базы

Статический реестр регистрирует фасеты при загрузке, а свойства живут в базе. `Facets` получает
**источник фасетов** — `Facets::source(FacetSource)`, который реестр спрашивает лениво при первом
чтении и держит до конца запроса; сам источник кеширует список в `cache` и сбрасывает его при
сохранении свойства. Фасеты источника идут после зарегистрированных, по `position`.

### 4.4. Какие фасеты источника уместны

Двести свойств — не двести блоков фильтра. Источник фасетов (§4.3) может ответить, какие из его
фасетов уместны на странице, необязательным интерфейсом:

```php
interface RelevantFacets
{
    /**
     * @param  QueryBuilder  $products  ids of what the page found, every choice applied
     * @return list<FacetRelevance>     key, share of $products that have a value, expanded or not
     */
    public function relevant(FilterContext $context, QueryBuilder $products): array;
}
```

Ядро спрашивает его один раз на страницу, до счёта; неуместные фасеты не считаются вовсе.
Свойства отвечают так:

- **Страница категории** (или выбрана одна категория в фильтре) — свойства действующего набора с
  «в фильтре», все раскрыты; порядок — вкладка «Фильтры» категории или порядок набора.
- **Поиск, страница бренда, корень** — **охват**: одним запросом `group by property_id` по
  найденным товарам (только значения из действующего набора их основной категории, решение 6)
  считается, у какой доли найденного у свойства есть значение. Свойства с охватом не ниже
  `webx-catalog-properties.dynamic_facets.min_share` (0.1) по убыванию охвата, при равенстве — по `position`; первые
  `dynamic_facets.limit` (8) раскрыты, остальные с охватом выше нуля — в «Ещё фильтры», по
  убыванию охвата. Свойства, которого нет ни у одного найденного, нет и в фильтре.
- **Выбранный фасет раскрыт всегда**, каким бы ни был охват, — иначе выбор не снять.
- Лимит — только на свойства. Категория, цена, бренд, наличие, метки — по своим правилам.

Охват пересчитывается с каждым выбором: выбрали «Разъём: RJ-45» — наверх поднимаются свойства
сетевых кабелей. Пример и обоснование чисел — обсуждение 30.09.2026: 8 — вместе с фасетами ядра и
справочников это 11–13 блоков, два экрана колонки; 10 % отсекает свойства пары случайных товаров
смешанной выдачи и не режет главное свойство на странице бренда из многих категорий. Оба числа —
конфиг сайта.

«Ещё фильтры» — `<details>` партиала фильтра ядра: ссылки, как везде, без JS. Ответ фасета в
`CatalogResult` получает `expanded: bool`.

Правило ядра «фасет, зарегистрированный позже настройки, в настроенной категории скрыт» (§6.2
ядра) для свойств ослаблено: свойство, которое админ сам добавил в набор и сам пометил «в
фильтре», появляется в настроенной категории последним — это два явных действия, а не новый
модуль, молча меняющий чужие фильтры. Скрыть его можно на вкладке «Фильтры», как любой фасет.

### 4.5. Поиск по значениям на `SqlEngine`

Сейчас `SqlEngine` ищет `like` по названию, артикулу и штрихкоду. Нужен шов:
`SearchContributor::applySql(Builder $query, string $text, string $locale)`, условия которого
присоединяются через `or`. Свойства ищут по названиям значений (`select`) и тексту (`text`) у
свойств с `is_searchable`. Движок с индексом берёт поле `pt` из документа (§6).

## 5. Фасеты

### 5.1. Какие

| Свойство            | Вид      | Значение фасета | Адрес               | Индексируемый по умолчанию |
| ------------------- | -------- | --------------- | ------------------- | -------------------------- |
| `select`            | `Terms`  | id значения     | `color_black`       | да                         |
| `select`, `is_tree` | `Tree`   | id узла         | `material_steel`    | да                         |
| `number`, слайдер   | `Range`  | `min`–`max`     | `weight_1-2.5`      | нет, и включить нельзя     |
| `number`, интервалы | `Terms`  | id интервала    | `weight_up-to-1-kg` | да                         |
| `bool`              | `Toggle` | `1`             | `wifi_yes`          | нет                        |

- Фасет свойства реализует `OrderedFacet`, если `value_order = manual`; интервалы — всегда по
  `position` (от меньшего к большему — забота админа, форма предлагает отсортировать).
- Значения с цветом или картинкой фасет отдаёт в `labels()` как обычно; цвет и картинку фильтру
  даёт отдельный метод фасета свойств `swatches(array $values)` пачкой — партиал фильтра рисует
  кружки (§8.2).
- Снятая группа ничего не прячет: группа — только заголовок карточки.

### 5.2. Счёт

**Все невыбранные фасеты свойств — одним запросом.** У них общий набор товаров (применены все
выборы), поэтому `group by property_id, value_id` (интервалы — `case` по границам, числа
слайдера — `min/max` по `property_id`) отвечает за всех сразу. Отдельный запрос — только у
каждого **выбранного** фасета, потому что свой выбор его не сужает. Двести свойств и два выбора —
около пяти запросов, а не двести. Для этого у `SqlEngine` — групповой счёт: фасет, реализующий
`BatchCountedFacet` (`sqlValuesMany(array $keys, QueryBuilder $products)`), считается пачкой
вместе с соседями своего источника. Правка ядра — в P1.

`sqlValues()` — пары из `catalog_product_property_values` только по товарам, у которых свойство в
действующем наборе основной категории (решение 6). На странице категории это условие одно для
всех товаров — набор известен; в `sqlValues` оно всё равно есть, потому что выбранная в фильтре
категория может быть родителем с разными наборами у детей. Дерево отдаёт узел с предками через
`lft/rgt`; интервалы — `case` по границам.

### 5.3. SEO первого уровня

Открыт первый уровень свойства только на странице категории; на странице бренда, в поиске и в
корне адрес со свойством — `noindex, follow` (решение 22).

Шаблон ядра «{категория} {значение}» (решение 17 архитектуры) для свойств часто звучит плохо
(«Ноутбуки Чёрный»). У свойства — необязательный переводимый шаблон `seo_pattern` (колонка json
в `catalog_properties`) с подстановками `{category}`, `{property}`, `{value}`: «{category} цвета
{value}». Пусто — шаблон ядра. Правило `module-seo` для адреса бьёт и его.

### 7.1. Меню и экраны

`WEBX_UI_CATALOG_DICTIONARIES.md`). Группы свойств — кнопка «Группы» в шапке раздела (как

| Экран                     | Что                                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `catalog.properties`      | список: название, код, тип, группа, флаги значками, число товаров; фильтр по типу и группе; порядок перетаскиванием |

**«Основное»:** название, код (карта языков, предлагается из названия), тип (только у нового),
группа, флаги — видны только положенные типу; у числа — префикс, суффикс, точность, «слайдер /
интервалы» с живым примером `⌀12 мм`; у `bool` — слаг «да»; шаблон SEO.

**«Значения»** — узел `wx-catalog-property-values`: ленивое дерево (`useTreeNodes`) с поиском,
перетаскивание порядка и вложенности (если `is_tree`), строка — название, слаг, цвет (`WxColorPicker`),
картинка (выбор из `module-media`), число товаров; добавление строкой сверху; «Слить с…» в `···`
строки — выбор цели поиском, подтверждение с числом товаров. При `value_order = alpha` порядок не
перетаскивается — список по алфавиту языка панели.

**«Интервалы»** — таблица: подпись, от, до, слаг; добавить, удалить, перетащить; кнопка
«Отсортировать по границам».

### 7.2. Категория и товар

- **Форма категории** — вкладка «Свойства» патчем `catalog.category-form`: сверху
  унаследованные (приглушённые, с «из Электроники»), ниже свои — добавление поиском по свойствам,
  перетаскивание, удаление. Узел `wx-catalog-category-properties`.
- **Форма товара** — вкладка «Характеристики» патчем `catalog.product-form`, узел
  `wx-catalog-product-properties`: поля действующего набора основной категории по группам. Сменили
  основную категорию в форме — вкладка перечитывает набор сразу, до сохранения. Поле по типу:
  `select` — комбобокс с поиском и «Создать „…“» (при праве `catalog.manage`), у дерева — выбор в
  дереве; `number` — число с префиксом и суффиксом; `bool` — переключатель; `text` — `WxInput` с
  `localized`. Значения вне набора — свёрнутый блок «Вне набора категории» внизу, только чтение и
  кнопка «Удалить».
- **Список товаров** — колонки свойств с `in_list` через `ProductColumns` (значение строкой в
  единицах), фильтры — фасеты сами (решение 18). Фильтр списка панели выбирает фасеты
  так же, как витрина (§4.4): выбрана категория — её набор, нет — по охвату найденного.

## 13. Тесты, которые обязательны

- ядро: код фасета на языке, занятый на одном языке — ошибка при регистрации; псевдоним кода и
  слага даёт 301 на канон, «убрать сегмент» — 301 без него, цепочка схлопывается; источник фасетов
  спрашивается один раз на запрос; без категории фасеты по охвату — порог, лимит, выбранный раскрыт всегда, неуместный не считается; невыбранные фасеты свойств — один запрос; `SearchContributor`
  находит по значению;
- набор: наследование от предков, порядок «предки, потом свои», добавить свойство предка — 422,
  перенос категории помечает поддерево одним запросом;
- значения вне набора: не в форме, не в фасете, не в индексе, не в карточке — и возвращаются при
  возврате категории;
- типы: флаги не своего типа гасятся; текст не становится фасетом; `bool` хранит только «да»;
  `leaves_only` отвергает узел середины;
- интервалы: `[min, max)`, открытые края, пересекающиеся считаются каждый; смена интервалов
  помечает товары;
- слияние: дубль у многозначного схлопывается, слаги — псевдонимы, дерево — нельзя в потомка;
  удаление значения с товарами — 422 с числом;
- удалённое свойство: фасет пропал, адрес с ним — 301 без сегмента, значения товаров целы и
  возвращаются восстановлением;
- форма товара: смена основной категории меняет набор; упавшая часть откатывает всё; журнал —
  строки с подписями и единицами;
- витрина: карточка и таблица по группам и порядку набора; ссылка на открытый первый уровень;
  `seo_pattern` подставляется.

## 15. Как легло в код

Где код разошёлся с §4–§5 и почему. Решения §1 не менялись.

### P1: правки ядра

- **Код на языке — без базы при загрузке.** `Facet::code(string $locale)`; `AbstractFacet` читает
  `webx-catalog.facet_codes` (массивом, а не путём с точками: у ключа `p.12` точка своя), иначе
  `baseCode()` — ключ. Уникальность при регистрации проверяется на каждом языке, который назван в
  конфиге, и один раз за все остальные: языки `webx-localization` живут в базе, а при загрузке
  провайдера её может ещё не быть. Фасеты источника при чтении не проверяются — модуль проверяет
  код при сохранении через `Facets::taken($code, $locale, $except)`; источник с занятым ключом
  пропускается с `report()`, а не роняет каталог. Панель (`GET /facets`) и ресурс MCP отдают
  `code` на языке сайта по умолчанию.
- **Псевдонимы.** `FilterAliases::record($facetKey, $locale, $kind, $old, $target)`. Цель
  значения — само значение фасета (id), а не новый слаг: слаг переименовывается снова, id — нет,
  поэтому цепочки копятся только у кодов, и правило «`B → C` переписывает `… → B`» применяется к
  ним. Код, переименованный обратно, свой псевдоним теряет. Псевдоним кода ведёт к фасету по
  `facet_key`, `target` — только признак «жив / убрать сегмент». Слияние и удаление значения —
  `retarget($facetKey, $kind, $from, $to)`: все псевдонимы, что вели к `A`, ведут к `B` (или
  никуда). Сериализатор спрашивает таблицу только на промахе, так что живой адрес запросов не
  добавляет.
- **Бренды** пишут псевдоним слага на каждом языке, где он сменился. Прежние слаги берутся в
  `updating`, а не в `updated`: реестр адресов (`HasUrl`) успевает пересохранить модель, и в её
  собственном `updated` сырые оригиналы уже новые (ловушка — в `docs/pitfalls/laravel-and-php.md`).
- **Источник** — `Facets::source(FacetSource)`, их может быть несколько; `sourceOf($key)`,
  `flush()`. Ответ держится до конца запроса, воркер очереди сбрасывает его на каждом задании
  (`JobProcessing`).
- **Уместные фасеты спрашивает движок, а не страница.** `RelevantFacets extends FacetSource`, и
  `relevant()` получает ещё `FilterState` — без него источник не узнает, что в фильтре выбрана
  одна категория. `CatalogQuery` получил необязательный `filter` (контекст страницы); без него
  `SqlEngine` собирает контекст сам из `context`/`contextId` — так ответит и список панели.
  Выбранный фасет ядро держит раскрытым само, что бы ни ответил источник. Правило охвата (порог,
  лимит, порядок по охвату, при равенстве — по позиции) — общий помощник ядра
  `FacetRelevance::ranked($shares, $minShare, $limit)`; числа — конфиг свойств.
- **`FacetResult`** получил `expanded` и `rank` (место, которое дал источник); `toArray()` отдаёт
  `expanded`. Фильтр ставит ранжированные фасеты источника на места, которые они занимают в
  порядке страницы, — в порядке ранга; на странице категории источник возвращает их в порядке
  контекста, и настройка вкладки «Фильтры» не ломается. «Ещё фильтры» — `<details
class="webx-catalog-filter__more">` в `webx-catalog::filter`, `CatalogPage::openGroups()` /
  `moreGroups()`.
- **Ослабленное правило §6.2 ядра** — в `CategoryFacets::visible()`: фасет источника, которого
  настройки категории не упоминают, идёт последним; скрытый в настройках — скрыт.
- **Групповой счёт** — по источнику и виду: термы и деревья одним `group by facet_key, value`,
  диапазоны — `min/max`, переключатели — `count(distinct)`, то есть до трёх запросов на источник.
  `sqlValuesMany()` отдаёт строки `(facet_key, product_id, value)`. Выбранный фасет — своим
  запросом, как раньше.
- **Поиск** — реестр `SearchContributors`; условия спутников и `matching()` ядра — одна группа
  `or`.

### P2: пакет, данные, API

- **Группа свойств** — набор `Categories` (`$table->category()`, `IsCategory`), но свойство держит
  группу колонкой, а не связующей таблицей: счёт и отказ в удалении (`itemCount()`,
  `withItemCount`) переопределены на `properties()`. Группу со свойствами в корзину не отправить —
  как любую категорию панели; `nullOnDelete` из §2 срабатывает только на окончательном удалении.
- **Код на языке без своего кода** — цепочка языков перевода, как у любого переводимого поля, а
  где кода нет нигде — `p{id}`. Занятость проверяется по живым свойствам и по `Facets::taken()`;
  код свойства в корзине свободен, его старый адрес — псевдоним «убрать сегмент», а живой код
  выигрывает, потому что сериализатор спрашивает псевдонимы только на промахе.
- **Набор проверяется в `write()` части, а не в `rules()`**: то же сохранение может сменить
  основную категорию, и считается набор, который товар получит. Ошибка — под
  `properties.values.{id}`, откат — всего сохранения. `read()` отдаёт `values` в порядке набора и
  `outside`; присланный обратно `properties.outside` отбрасывается — его нет среди полей экрана.
- **Вкладка «Характеристики» формы товара патчится уже в P2** (`wx-catalog-product-properties`,
  `name: properties.values`): без узла на экране сервер поле не примет. Рисует его P4. Вкладка
  «Свойства» формы категории — только API; патч экрана — с узлом в P4.
- **Фасеты** — класс на форму: `ValueFacet` (и `OrderedValueFacet` для «вручную»),
  `TreeValueFacet`, `RangeFacet`, `IntervalFacet` (всегда `OrderedFacet`), `ToggleFacet`. Ядро
  пакует по источнику и виду, поэтому в одной пачке термов бывают и справочники, и интервалы:
  `FacetRows` строит `select` на форму и склеивает их `union all`; ключ фасета — `case` по id
  свойства (конкатенацию каждая СУБД пишет по-своему, а MySQL читает `||` как «или»).
- **Страница категории** — свойства набора «в фильтре», все раскрыты; сначала упомянутые вкладкой
  «Фильтры» в её порядке (скрытые там — не возвращаются), потом остальные в порядке набора.
- **Индекс:** у `IndexField` нет типа JSON, поэтому `pn` — строка с JSON, а `field()` фасета-слайдера
  — `pn.{id}`; `pt` — `TEXT` с `localized`, то есть `pt_{locale}`.
- **Слияние** пишет одну запись у цели (`merged`, «Черный, товаров: 37»); своё «удалено» у
  сливаемого значения погашено (`PropertyValue::$quietly`). Псевдонимы: сперва `retarget(A → B)`,
  потом удаление `A` (его хук пишет «убрать сегмент»), потом слаги `A` → `B` поверх.
- **Слаги интервалов** псевдонимов не пишут: §4.2 называет код, слаг значения, слияние и удаление.
- **API сверх §7.3:** `GET /properties?trashed=1`; ответ свойства несёт ещё `intervals`; `merge`
  принимает `dry_run` (для MCP в P5); `PUT …/intervals` отвечает списком; `GET /property-sets/{category}`
  — `{ groups: [{ group, properties }] }`, без группы — последним блоком.
- **Массовые действия:** `set-property` у товара, в наборе которого свойства нет, — ошибка у этого
  товара, остальные идут дальше; `clear-outside-set` не трогает значения свойств в корзине —
  восстановление вернёт всё.
- **Не в P2:** колонки `in_list` — реестр `ProductColumns` статический, а свойства в базе; решать
  вместе с колонками панели в P4. Пункт меню (`ModuleRegistry`) — с разделом в P4/P5.
- **Зеркало `webx-ui/module-catalog-properties` и Packagist** — руками до первого релиза
  (`WEBX_UI_PHP_RELEASE.md`): без репозитория джоба `php-split` этого пакета после мержа красная.

### P3: витрина

- **Три необязательных интерфейса фасета в ядре**, а не знание ядра о свойствах:
  `ContextualIndexing::indexableIn(FilterContext)` — спрашивают `FilterUrls::indexable()` (а с ним
  `robots`, `nofollow` ссылок фильтра) и карта сайта; свойство отвечает «да» только на странице
  категории (решение 22). `TitledFacet::filterTitle($where, $label, $locale)` — спрашивает
  `Listing`, пустой ответ — шаблон ядра; `seo_pattern` берётся **без** запасного языка: чужая
  обвязка вокруг своих слов хуже шаблона ядра. `SwatchedFacet::swatches($values)` — у
  `ValueFacet` (значит, и у дерева, и у «вручную»); пачкой на группу фильтра.
- **Кружок рисует `webx-catalog::filter.option`**, а не `filter.terms`: значение фильтра — это
  `FilterOption`, и у него теперь `swatch` (`{ color, image }`); кружок — партиал
  `webx-catalog::filter.swatch`, картинка выигрывает у цвета. Так кружок есть и у дерева, и у
  переопределившего `terms` сайта.
- **Значения страницы — один запрос**, подписи справочника в нём же (`left join` на значения), а не
  вторым; вторым — видимые группы. Держит их `ProductProperties` — `scoped`, чтобы воркер не
  отдал следующему запросу прошлую страницу. Грузит страницу часть карточки, часть таблицы своего
  запроса не делает: ядро готовит все части страницы разом.
- **Адреса первых уровней — только там, где печатаются:** таблица и `$product->properties()`, один
  контекст фильтра на товар. Карточка ссылок не несёт — карточка ведёт на товар. Ссылка — если
  фасет виден в категории, свойство `is_indexable` и адрес открыт по правилам ядра (переписанный
  посадочной — адрес посадочной).
- **Группа, снятая с показа, ничего не прячет** (§5.1): её свойства идут в последний блок без
  заголовка, вместе со свойствами без группы. Группы стоят в порядке, в котором набор встречает их
  первое свойство.
- **`$product->properties()`** — `Product::resolveRelationUsing()`, который отдаёт список, а не
  связь: Eloquent вызывает резолвер на метод, а шаблону больше ничего и не нужно;
  `$product->properties` без скобок не работает. Элемент — `ShownProperty`: `property`, `code`,
  `label`, `value` (форма типа), `formatted`, `group` (`{ id, title }` или `null`), `values`
  (значения справочника по одному: `id`, `label`, `color`, `url`) и `url` — адрес, когда значение
  одно.
- **`products()->property()`** — шаг `narrowedBy` на каждое свойство (`property:<код>`): два
  свойства сужают вместе, то же ещё раз — заменяет. Свойство — код на языке выборки или id; без
  значения — «есть любое значение» (у `bool` — «да»); у числа `min`/`max` включают оба края
  (интервалы фильтра — `[min, max)`, но в шаблоне «от 1 до 2 кг» читается включительно), одно
  число — ровно оно. Узел дерева берёт своё поддерево. Незнакомые свойство или слаг — пусто.
- **Карта сайта** — без кода в модуле: `FilterSitemap` ядра уже спрашивает фасеты категории, а
  считаются из свойств только фасеты набора (§4.4); добавилась только проверка
  `ContextualIndexing`.

### P4: раздел панели

- **Новый npm-пакет `@webx-ui/module-catalog-properties`** — `catalogProperties({ path })`: один
  модуль `catalog-properties` с тремя экранами и шестью типами узлов. Пункт меню — `PropertiesModule`
  php-половины (order 312, `HasNavSection` → «Справочники»), без MCP (P5). Первую версию публикует
  человек (P5).
- **Список** — все свойства одним запросом (`per_page` 500), без пагинации: порядок
  перетаскивается только на всём списке, поэтому при выбранном типе или группе он заперт и так и
  сказано. Сверх §7.1 — вид «Удалённые» с «Восстановить»: восстановление есть в API, а без экрана
  его не достать.
- **Тип выбирается в диалоге создания** (название + тип), в форме он — узел
  `wx-catalog-property-type`, выключенный селект у существующего свойства. Поля по типу — условия
  `visible` в `property-form.json`, без кода; живой пример числа — узел
  `wx-catalog-property-example`, на языке, который редактируется (единицы и разделитель дроби —
  его).
- **«Значения»** — `WxTree` с `lazy` (он и есть `useTreeNodes`), поиск — плоский список того же
  дерева. Слот `actions` у дерева виден только под курсором, поэтому число товаров, цвет и картинка
  стоят в самой строке, а в `actions` — только `···`. **Цвет и картинка правятся в диалоге
  значения**, а не `WxColorPicker` в каждой строке: столбец пикеров на книге в триста значений
  никто не читает, а строка показывает кружок. Значения и интервалы сохраняются сами, своими
  запросами, как галерея товара; кнопка редактора — только «Основное». Интервалы — одной кнопкой
  «Сохранить интервалы» (таблица уходит целиком, §7.3).
- **Вкладка «Свойства» категории** сохраняет набор сразу, каждым действием (`PUT …/properties`), а
  не кнопкой категории: набор — своя запись, и его правка метит товары поддерева. Патч
  `catalog.category-form` — вкладка после «Основного».
- **Вкладка «Характеристики» товара** читает основную категорию из живых значений формы — у
  `ProductEditorContext` ядра появилось `values`. Сменили категорию — ключи свойств, которых нет
  в новом наборе, **выпадают из отправляемого** (не удаляются: отсутствующий ключ не трогается,
  решение 6), а значения вернувшихся свойств берутся из того, что товар держал, в том числе из
  `outside`. «Удалить» в блоке «Вне набора категории» — массовое действие `clear-outside-set` на
  этот товар, все значения вне набора разом, с подтверждением. Ошибка по свойству —
  под своим полем: узел читает отказ через `screenErrorsKey`, который `@webx-ui/schema` теперь
  экспортирует.
- **Колонки `in_list`** — шов ядра `ColumnSource`: `ProductColumns::source()`, источник
  спрашивается при каждом чтении, после зарегистрированных колонок. Ключ колонки — ключ фасета
  `p.{id}`, значение — слова на языке панели (`Black, Grey`, `⌀12 mm`, `Yes`), только внутри
  набора основной категории; без сортировки. Одна выборка на страницу для всех колонок
  (`WeakMap` по коллекции страницы — воркер не отдаст её следующему запросу).
- **API сверх §7.3 и P2:** `ids[]` у `GET /properties` (форма товара называет свойства вне
  набора) и у `GET /properties/{id}/values` — значение по id несёт `ancestors` от корня: выбор в
  дереве показывает путь выбранного в неоткрытой ветке.
- **Патчи экранов — файлами** `resources/screens/patches/catalog.*.json`: их же кладёт на экраны
  фейковый сервер плейграунда.
- **Группы** — общие экраны категорий по `/catalog/properties/groups`; у `CategoriesOptions`
  `module-admin` появились `title` и `back` для списка, который не пункт меню. Слова панели —
  группа `panel` в `lang/*/panel.php`; npm повторяет `module`, `property`, `value`, `product`,
  `group`, `panel`, `messages.test.ts` держит ключи равными.
- **Открыто:** `products_count` значения в списке считает само значение, а отказ в удалении и
  ответ на правку — с поддеревом; у ветки дерева строка может показать 0, а удаление ответить 422
  с числом.
