# Видео в галерее товара

Дополнение к [`WEBX_UI_MODULE_CATALOG.md`](WEBX_UI_MODULE_CATALOG.md) §3 и §10.4: к картинке
галереи можно прикрепить ролик — свой файл или ссылку на YouTube. Большие файлы идут частями
через загрузку по кускам, которая живёт в `module-admin` и годится любому модулю. Пакеты:
`webx-ui/module-catalog`, `webx-ui/module-admin` и их npm-половины. Выпущено в v0.52.0; спека —
справочник того, что есть. Гайды для людей — `apps/docs/guide/uploads.md` и раздел «Video» в
`apps/docs/guide/catalog.md`.

## 1. Решения (не переоткрывать)

1. **Элемент галереи — всегда картинка; видео к ней прикрепляется.** Картинка — постер ролика.
   Карточке в списке, фидам, `og:image`, `Product.image` и `VideoObject.thumbnailUrl` нужна
   картинка, и строки без неё не бывает. Таблица остаётся `catalog_product_images`, модель —
   `ProductImage`: переименовывать то, что уже в API, журнале и обмене, ради одного поля не стоит.
2. **Площадки: только YouTube.** Сайты не привязаны к стране; добавить площадку — одна запись в
   реестре провайдеров (§3).
3. **Свои файлы — любого размера.** mp4 и webm как есть: без перекодирования, без ffmpeg на
   сервере. Тип проверяется по содержимому; кодек внутри контейнера — забота того, кто загрузил.
   Лимит — `webx-catalog.videos.max_size_mb`, а не лимиты PHP и nginx: файл идёт кусками (§4).
4. **Загрузка переживает обрыв.** Упала сеть, закрылась вкладка, уснул ноутбук — тот же файл,
   выбранный снова, узнаётся по имени, размеру и дате изменения и продолжается с того места, где
   остановился сервер. Заново тянуть 3 ГБ из-за одного обрыва — ровно то, на что ругаются.
5. **Видео может стоять первым.** Главная картинка — первая; если к ней прикреплён ролик, в
   списках всё равно её постер, а страница товара открывается на ролике.
6. **Постер своего файла снимает браузер.** Ролик, брошенный в галерею без картинки: панель
   берёт кадр (`<video>` → `<canvas>` → JPEG) из локального файла до загрузки, загружает его
   картинкой и прикрепляет к ней файл. Сервер кадры не снимает. Если браузер ролик не открыл
   (кодек), панель говорит «добавьте картинку и прикрепите к ней видео».
7. **Постер YouTube — обложка ролика.** Ссылка создаёт строку: картинка —
   `i.ytimg.com/vi/{id}/maxresdefault.jpg` (при 404 — `hqdefault.jpg`) через `Gallery::fetch`;
   пустой `alt` заполняется названием ролика из oEmbed, если он ответил.
8. **Плеер — только по клику.** До клика страница не тянет чужой JS и не ставит куки YouTube.
   Без JS кнопка — ссылка на файл или на ролик.
9. **Выключается флагом** `webx-catalog.fields.video` (по умолчанию включено), как `barcode`:
   ни кнопок в панели, ни плеера и разметки на витрине, API и инструменты прикрепления отвечают
   отказом. Уже прикреплённое хранится.
10. **Агент умеет с галереей всё, что человек, кроме выбора файла с диска** (§8): картинки и
    ролики по адресу — в том числе прямая ссылка на mp4, которую сервер скачивает в очереди.

## 2. Схема

В `catalog_product_images` три колонки, все `nullable`:

- `video_provider` — `file` или ключ провайдера (`youtube`); `null` — видео нет;
- `video` — путь файла на диске галереи или id ролика;
- `video_duration` — секунды, если известны: у файла их шлёт панель (целые секунды из
  `<video>.duration` того же локального файла, из которого снимается кадр; сервер не проверяет),
  у YouTube — неизвестно, без ключа Data API не узнать.

Файл лежит рядом с картинками товара: `catalog/{id div 1000}/{id}/{sha1}.{mp4|webm}` (sha1 —
потоком, `hash_file`, не в память).

## 3. Провайдеры

`VideoProviders` — реестр в ядре каталога, как `Facets`: провайдер отвечает на «эта ссылка моя?»
(id из адреса), «адрес для встраивания», «адрес постера», «адрес для человека». В ядре один —
`YouTubeProvider`: `youtube.com/watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`, `/live/`, `m.` и
`music.` поддомены; id — 11 символов `[A-Za-z0-9_-]`. Спутник или сайт регистрирует свой — и его
ссылки принимаются без правки ядра. Ролик провайдера, которого больше никто не регистрирует,
приходит в ресурсе как `video: null`.

## 4. Загрузка кусками (`module-admin`)

Общая часть панели, а не каталога: ею же пользуется обмен каталога (назначение
`catalog.exchange`). Свой маленький протокол, а не tus: tus-сервер на PHP — отдельная зависимость
ради четырёх запросов, которые проще написать и проверить у себя.

```
POST   /api/cms/uploads       { name, size, type, fingerprint, purpose }
                              → 201 (новая) | 200 (найдена по отпечатку) { data: { id, offset, size, chunk_size } } + Upload-Offset
HEAD   /api/cms/uploads/{id}  → Upload-Offset: n   (это GET того же адреса, тело отбрасывается)
PATCH  /api/cms/uploads/{id}  тело — байты, Upload-Offset: n → 204, Upload-Offset: n + len
DELETE /api/cms/uploads/{id}  → 204 (отмена, файл удаляется)
```

- **Сессия** — строка `admin_uploads` (`id` uuid, `admin_id`, `purpose`, `name`, `size`, `type`,
  `fingerprint` — sha1 строки клиента, `offset`, `expires_at`) и файл
  `storage/app/uploads/{id}.part`. Куски всегда на локальном диске, независимо от диска
  потребителя: в облачный дописывать нельзя.
- **Назначение** — реестр `UploadPurposes`, как `HistoryTypes`; проверяет права, тип и размер на
  создании. Замыкания читаются при каждом запросе, так что лимиты меняются конфигом:
  `UploadPurposes::register('catalog.video', permission: 'catalog.manage', types: fn () => config('webx-catalog.videos.types'), maxBytes: fn () => config('webx-catalog.videos.max_size_mb') * 1048576)`.
  `catalog.video` зарегистрировано и при выключенном флаге — отказ даёт эндпоинт прикрепления.
- **Кусок пишется дописыванием** по смещению, которое сервер знает сам; кусок не с того места —
  409 с настоящим `Upload-Offset`. Сборки в конце нет: при `offset == size` файл готов, и
  завершение — одно перемещение, а не склейка гигабайт под `max_execution_time`.
- **Размер куска** — сервер советует меньшее из `chunk_mb` и 90 % от
  `min(upload_max_filesize, post_max_size)`. Про nginx сервер знать не может, поэтому клиент на
  413 делит кусок пополам, до 256 КБ (`MIN_CHUNK`), и помнит дошедший размер до конца загрузки.
- **Возобновление.** `POST` с тем же отпечатком (имя + размер + `lastModified`), `purpose` и
  администратором, пока сессия жива, возвращает существующую сессию с её `offset`.
- **Отказы — `UploadRefused`, рендерит себя сам:** 422 с `errors.purpose|type|size|upload`, 403
  без права, 404 на чужую, истёкшую и несуществующую сессию одинаково, 409 со смещением.
  Брошенный из контроллера потребителя, отвечает так же. Место на диске проверяется на создании:
  `size` больше свободного — отказ сразу, а не на 90 %.
- **Уборка.** Сессия живёт `ttl_hours` с последнего куска; `webx:prune-uploads` ежечасно удаляет
  истёкшие с `.part`. `webx:doctor` (`UploadSpace`) предупреждает, когда свободного места меньше
  самого большого `maxBytes`.
- **Потребитель** забирает файл: `app(Uploads::class)->claim($upload, $purpose, $admin)` →
  `ClaimedUpload { id, path, name, size, type }`, сессии после этого нет. Проверка содержимого
  (`finfo` на `$claimed->path`) и хеш — до `$claimed->moveTo($disk, $path)` (потоком, `.part`
  удаляется) или `$claimed->discard()` при отказе.

npm, `@webx-ui/module-admin`: `useChunkedUpload({ admin?, storage?, retries?, retryDelay? })` —
`start(file, purpose)` резолвится id, когда файл целиком на сервере, `null` при отмене и
реджектится при ошибке (пауза промис не трогает); `pause()`, `resume()`, `cancel()`; реактивные
`progress`, `speed`, `remaining`, `state` (`idle | uploading | paused | offline | done | failed`).
Сам уходит в `offline` по событию браузера и продолжает по `online`. Отпечатки незаконченных
загрузок держит в `localStorage`; рядом `unfinishedUploads(purpose)`,
`forgetUnfinishedUpload(fingerprint, purpose)`, `uploadFingerprint(file)`. Композабл ставит
загрузку на паузу, когда умирает его scope, и не вешает `beforeunload` — это забота экрана. У
`Http` есть необязательный `send()` — запрос с CSRF и заголовками панели, без JSON и без броска на
не-2xx.

## 5. Сервер каталога

`Gallery` — дверь для всех: `add()`, `remove()`, `attachVideo()`, `detachVideo()` пишут журнал и
трогают индекс сами; контроллер, MCP и обмен ходят через них.

- `fetch()` сначала спрашивает провайдеров: ссылка на ролик — постер по §1.7 и видео в той же
  строке; прямая ссылка на `video/mp4`/`video/webm` — задача `FetchVideo` (потоком на диск, с
  лимитом §1.3), строка появляется, когда файл скачан; иначе — картинка. Возвращает
  `ProductImage|QueuedVideo` — вызывающему это надо учесть.
- `attachVideo(ProductImage, uploadId | url, ?duration)` — готовая загрузка (§4) или ссылка;
  прежний файл удаляется сразу. Отказ по содержимому удаляет `.part`: повторять ту же загрузку
  бессмысленно, только новую.
- `detachVideo(ProductImage)` — файл удаляется сразу. Удаление картинки удаляет её ролик;
  удалённый товар файлы сохраняет, как с картинками.
- **Прямой файл без картинки** — строка с общей заглушкой-постером: тёмный PNG 1280×720 с ▶ (1×1
  без GD). Сервер её не помечает, панель узнаёт по форме; если понадобится надёжнее — флаг
  `placeholder` в `video` ресурса.

### API панели

Права — `catalog.manage`, как у остальной галереи. Картинка чужого товара — 404 везде.

| Запрос                                              | Ответ                                                                                                                                                                                                                     |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST …/products/{id}/images` multipart             | картинка, как раньше                                                                                                                                                                                                      |
| `POST …/products/{id}/images { url }`               | `201 { data: image }` для картинки и YouTube; `202 { data: { queued: true, product, url, image: null } }` для прямого файла. 422 `errors.url`: `video-off`, `video-no-poster`, `image-not-a-picture`, `image-unreachable` |
| `POST …/images/{image}/video { upload, duration? }` | `200 { data: image }`; 422 `errors.upload`: `video-not-a-video`, `video-too-large`, `video-off`, плюс отказы `UploadRefused` (§4)                                                                                         |
| `POST …/images/{image}/video { url }`               | `200` для YouTube, `202 { data: { queued: true, product, url, image } }` для прямого файла (ляжет на эту картинку); 422 `errors.url`: `video-not-a-video`, `video-off`                                                    |
| `DELETE …/images/{image}/video`                     | `200 { data: image }` с `video: null`; на картинке без ролика — тот же ответ                                                                                                                                              |

Каждая картинка ресурса (`ProductForm::describe()` → `images`, ответы галереи) несёт
`video: { provider, url, embed, duration } | null`: `url` — файл на диске галереи или страница
ролика (`watch?v=`), `embed` — iframe на `youtube-nocookie.com` (у файла `null`).

Флаг и лимиты провайдер отдаёт патчем `set` узлу `gallery` экрана `catalog.product`: пропсы
`video` (bool), `videoTypes`, `videoMaxBytes` (байты). Нет пропа `video` — видео выключено.

### Журнал

Запись в поле `images`: `«{sha1}.jpg» ▶ YouTube` / `«{sha1}.jpg» ▶ clip.mp4`; прикрепление —
`null → метка`, замена — `старая → новая`, снятие — `метка → null`. У файла при прикреплении —
имя, с которым его загрузили, при снятии — хешевое имя на диске: исходное не хранится.

## 6. Витрина

- `product.blade.php`: элемент с роликом — `<figure>` с постером и
  `<button class="webx-catalog-product__play">`; встроенный скрипт без зависимостей по клику
  меняет его на `<video controls autoplay playsinline preload="none">` или iframe
  `https://www.youtube-nocookie.com/embed/{id}?autoplay=1`. Без JS — ссылка.
- `ProductMarkup`: `Product.subjectOf` — список `VideoObject`: `name` (alt картинки, иначе название
  товара), `description` (`summary`, иначе название), `thumbnailUrl` (постер), `uploadDate`
  (`created_at` строки), `contentUrl` (файл) или `embedUrl` (YouTube), `duration` (ISO 8601), если
  известна.
- Карточка в списке без изменений: постер и так главная картинка.

## 7. Панель

`GalleryField.vue`:

- **▶ — в центре превью**, а не в углу рядом с «Главная»: на картинке в 72 пикселя «Главная»
  занимает почти всю ширину. Длительность, если известна, — в том же значке. Символ — `▶︎` с
  селектором текстового вида: голый `▶` Windows рисует цветным эмодзи. Клик по превью открывает
  ролик в новой вкладке.
- Действия строки: «Прикрепить видео» → «Файл…» / «Ссылка на YouTube…»; у строки с роликом —
  «Убрать видео» с подтверждением (файл удаляется сразу).
- Зона загрузки принимает и `video/mp4,video/webm` (если `video` включён): кадр по §1.6,
  картинка, загрузка кусками, прикрепление. Строка появляется сразу с постером и полосой:
  процент, скорость, «осталось ~4 мин», пауза и отмена. Форма доступна, пока файл идёт.
- «Загрузить по адресу» принимает и ссылку на ролик, и прямую ссылку на mp4.

Как устроено:

- **Загрузки живут в редакторе, а не в поле.** `createGalleryVideo()` (`galleryVideo.ts`) создаёт
  `WxCatalogProductEditor` и отдаёт через `ProductEditorContext.video`: `WxTabs` снимает
  невидимую вкладку, и композабл внутри поля вставал бы на паузу при каждом переходе. Поле без
  редактора заводит свои. `beforeunload` вешает тот же контроллер, уход роутером спрашивает
  `ProductEditorPage`.
- **Одна загрузка за раз**, остальные ролики ждут в очереди. Отмена ролика, для которого панель
  сама сделала картинку из кадра, удаляет и картинку — её никто не выбирал.
- **Продолжение после перезагрузки.** К отпечаткам §4 панель держит в `localStorage`
  (`webx:catalog-video-targets`) товар и картинку. Предложение «Продолжить загрузку clip.mp4
  (1,2 из 3,4 ГБ)» — только на своём товаре; другой файл получает отказ словами, тот же —
  продолжает с места сервера и ложится на ту же картинку, если она ещё есть.
- **Кадр** — `probeVideo()` в `video.ts`; `<video>`, `<canvas>` и object URL приходят параметром,
  так тест проверяет кадр без DOM (в jsdom `<video>` не декодирует).
- Слова — `panel.video-*` / `panel.gallery-*` на обеих половинах.

## 8. MCP

Полный набор за `catalog:read` / `catalog:write` и права панели; параметры — `product` и `image`,
как у остальных инструментов каталога.

| Инструмент                        | Что                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------ |
| `catalog_products_gallery`        | галерея товара по порядку: картинки, подписи, размеры, ролики                        |
| `catalog_products_gallery_add`    | `{ product, url, alt?, title?, position? }` — картинка, ролик YouTube или прямой mp4 |
| `catalog_products_gallery_update` | `{ product, image, alt?, title? }` — подписи, языки картой                           |
| `catalog_products_gallery_order`  | `{ product, images: [id…] }` — весь порядок, первая — главная                        |
| `catalog_products_gallery_video`  | `{ product, image, url }` — прикрепить ролик; `url: null` — снять                    |
| `catalog_products_gallery_remove` | `{ product, image }` — удалить строку с файлами                                      |

Все пишущие принимают `dry_run`. У `…_add`, `…_video` и `…_remove` он отвечает, чем окажется
адрес, и не ходит в сеть: запись файла на диске не откатить, поэтому они не пишут-и-откатывают, а
описывают. `…_update` и `…_order` откатываются транзакцией. Прямой mp4 — ответ «поставлено в
очередь», а не ожидание гигабайт. Файлы с машины агента не загружаются: у MCP нет для этого
честного пути. `catalog://fields` говорит флаг `video` и лимит размера.

## 9. Конфиг

```php
// webx-catalog.php
'fields' => [..., 'video' => (bool) env('WEBX_CATALOG_VIDEO', true)],
'videos' => ['max_size_mb' => 2048, 'types' => ['video/mp4', 'video/webm']],

// webx-admin.php
'uploads' => ['ttl_hours' => 24, 'chunk_mb' => 8],   // WEBX_UPLOADS_TTL_HOURS, WEBX_UPLOADS_CHUNK_MB
```

Прямым ссылкам на файлы нужен воркер очереди (`FetchVideo`): без него 202 так и останется
«скачивается».

## 10. Демо

- `webx:demo` даёт одному товару ролик YouTube; своих файлов в демо нет — не тащить мегабайты в
  пакет.
- Плейграунд: эндпоинты `/uploads` — `server/panel/uploads.ts`, в памяти, кусок 256 КБ и 400 мс
  на кусок, чтобы паузу успевали нажать; статусы 200/202 роутер отдаёт через `Reply`
  (`reply.ts`). У товара 1 — ролик YouTube и ролик-файл `apps/playground/public/demo-clip.webm`
  (5 КБ, 3 с); прямая ссылка «скачивается» 4 секунды и даёт строку с заглушкой.

## 11. Отложено и открыто

- Отложено: другие площадки (одна запись в `VideoProviders`), видео-карта сайта, перекодирование и
  адаптивный стрим, длительность роликов YouTube (нужен ключ Data API), загрузка кусками для
  картинок и медиатеки (протокол §4 готов), колонка обмена для роликов (`images` уже принимает
  адреса, ссылка на ролик идёт через `Gallery::fetch`).
- Открыто: проверить на телефоне кадр из ролика с камеры (HEVC в `.mp4` Chrome на Android может
  не открыть — тогда должно прийти «добавьте картинку») и паузу при уходе в фон.
