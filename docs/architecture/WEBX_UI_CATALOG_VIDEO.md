# Видео в галерее товара

Дополнение к [`WEBX_UI_MODULE_CATALOG.md`](WEBX_UI_MODULE_CATALOG.md) §3 и §10.4: к картинке
галереи можно прикрепить ролик — свой файл или ссылку на YouTube. Большие файлы идут частями
через загрузку по кускам, которая живёт в `module-admin` и годится любому модулю. Пакеты:
`webx-ui/module-catalog`, `webx-ui/module-admin` и их npm-половины. Статус: V1 (загрузка кусками в
`module-admin`) и V2 (сервер каталога) сделаны, V3 (панель) впереди (29.09.2026).

## 1. Решения (не переоткрывать)

1. **Элемент галереи — всегда картинка; видео к ней прикрепляется.** Картинка — постер ролика.
   Карточке в списке, фидам, `og:image`, `Product.image` и `VideoObject.thumbnailUrl` нужна
   картинка, и строки без неё не бывает. Таблица остаётся `catalog_product_images`, модель —
   `ProductImage`: переименовывать то, что уже в API, журнале и обмене, ради одного поля не стоит.
2. **Площадки: только YouTube.** Сайты не привязаны к стране; добавить площадку — одна запись в
   реестре провайдеров (§3), но пока ни одна другая не нужна.
3. **Свои файлы — сразу, любого размера.** mp4 и webm как есть: без перекодирования, без ffmpeg на
   сервере. Тип проверяется по содержимому; кодек внутри контейнера — забота того, кто загрузил.
   Лимит — `webx-catalog.videos.max_size_mb` (по умолчанию 2048), а не лимиты PHP и nginx: файл
   идёт кусками (§4), и ни один кусок в них не упирается.
4. **Загрузка переживает обрыв.** Упала сеть, закрылась вкладка, уснул ноутбук — загрузка
   продолжается с того места, где остановилась: тот же файл, выбранный снова, узнаётся по имени,
   размеру и дате изменения, и панель спрашивает сервер, сколько уже дошло. Заново тянуть 3 ГБ
   из-за одного обрыва — ровно то, на что ругаются.
5. **Видео может стоять первым.** Главная картинка — первая, как и раньше; если к ней прикреплён
   ролик, в списках всё равно её постер, а страница товара открывается на ролике.
6. **Постер своего файла снимает браузер.** Ролик, брошенный в галерею без картинки: панель
   берёт кадр (`<video>` → `<canvas>` → JPEG) из локального файла — до загрузки, так что ждать
   гигабайты ради постера не надо, — загружает его картинкой и прикрепляет к ней файл. Сервер
   кадры не снимает. Если браузер ролик не открыл (кодек), панель говорит «добавьте картинку и
   прикрепите к ней видео».
7. **Постер YouTube — обложка ролика.** Ссылка на YouTube создаёт строку: картинка —
   `i.ytimg.com/vi/{id}/maxresdefault.jpg` (при 404 — `hqdefault.jpg`), скачанная через тот же
   `Gallery::fetch`; видео — этот ролик. Пустой `alt` заполняется названием ролика из oEmbed,
   если он ответил.
8. **Плеер — только по клику.** На странице товара — постер и кнопка ▶; `<video>` или iframe
   `youtube-nocookie.com` подставляются по клику. До клика страница не тянет чужой JS и не
   ставит куки YouTube. Без JS кнопка — ссылка на файл или на ролик.
9. **Выключается флагом.** `webx-catalog.fields.video` (по умолчанию включено), как `barcode`:
   выключено — ни кнопок в панели, ни плеера и разметки на витрине, API и инструменты
   прикрепления отвечают отказом. Уже прикреплённое хранится.
10. **Агент умеет с галереей всё, что человек, кроме выбора файла с диска** (§7): картинки и
    ролики по адресу — в том числе прямая ссылка на mp4, которую сервер скачивает сам в очереди.

## 2. Схема

В `catalog_product_images` — новая миграция, три колонки, все `nullable`:

- `video_provider` — `file` или `youtube`; `null` — видео нет;
- `video` — путь файла на диске галереи или id ролика YouTube;
- `video_duration` — секунды, если известны (файл — из метаданных, которые шлёт браузер;
  YouTube — неизвестно, без ключа Data API длительность не узнать).

Файл ролика лежит рядом с картинками товара: `catalog/{id div 1000}/{id}/{sha1}.{mp4|webm}`
(sha1 для больших файлов — потоком, `hash_file`, не в память).

## 3. Провайдеры

`VideoProviders` — реестр в ядре каталога, как `Facets`: провайдер отвечает на «эта ссылка моя?»
(id из адреса), «адрес для встраивания», «адрес постера», «адрес для человека». В ядре один —
`YouTubeProvider`: `youtube.com/watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`, `/live/`, `m.` и
`music.` поддомены; id — 11 символов `[A-Za-z0-9_-]`. Спутник или сайт регистрирует свой
провайдер — и его ссылки начинают приниматься без правки ядра.

## 4. Загрузка кусками (`module-admin`)

Общая часть панели, а не каталога: медиатеке и любому модулю с большими файлами нужна та же.
Свой маленький протокол, а не tus: tus-сервер на PHP — отдельная зависимость ради четырёх
запросов, которые проще написать и проверить у себя.

```
POST   /api/cms/uploads                 { name, size, type, fingerprint, purpose } → 201 { id, offset, chunk_size }
HEAD   /api/cms/uploads/{id}            → Upload-Offset: n            (сколько уже на сервере)
PATCH  /api/cms/uploads/{id}            тело — байты, Upload-Offset: n → 204, Upload-Offset: n + len
DELETE /api/cms/uploads/{id}            → 204                         (отмена, файл удаляется)
```

- **Сессия** — строка `admin_uploads` (`id` uuid, `admin_id`, `purpose`, `name`, `size`, `type`,
  `fingerprint`, `offset`, `expires_at`) и файл `storage/app/uploads/{id}.part` на локальном
  диске. `purpose` — кто заберёт файл (`catalog.video`); он проверяет права и тип на создании:
  `UploadPurposes`, реестр, как `HistoryTypes`.
- **Кусок пишется дописыванием** в `.part` по смещению, которое сервер знает сам; кусок не с того
  места — 409 с настоящим `Upload-Offset`, клиент продолжает оттуда. Сборки в конце нет: когда
  `offset == size`, файл готов, и завершение — одно перемещение, а не склейка гигабайт в запросе
  с `max_execution_time`.
- **Размер куска** — сервер советует `chunk_size`: меньшее из 8 МБ и 90 % от
  `min(upload_max_filesize, post_max_size)`. Про nginx сервер знать не может, поэтому клиент на
  413 делит кусок пополам и повторяет, до 256 КБ; дошедший размер помнит до конца загрузки.
- **Возобновление.** `fingerprint` = имя + размер + `lastModified` файла. `POST` с тем же
  отпечатком, тем же `purpose` и тем же администратором, пока сессия не истекла, возвращает
  существующую сессию с её `offset`, а не новую.
- **Уборка.** Сессии живут `webx-admin.uploads.ttl_hours` (24) с последнего куска;
  `webx:prune-uploads` в расписании удаляет истёкшие вместе с `.part`. Место на диске
  проверяется на создании: `size` больше свободного — отказ сразу, а не на 90 %.
- **Потребитель** забирает файл вызовом `Uploads::claim($id, $purpose)` → путь к готовому `.part`
  и его данные; после переноса сессия удаляется.

npm: `useChunkedUpload()` в `@webx-ui/module-admin` — `start(file, purpose)`, `pause()`,
`resume()`, `cancel()`, реактивные `progress`, `speed`, `remaining`, `state`
(`uploading | paused | offline | done | failed`). Сам уходит в `offline` по событию браузера и
продолжает по `online`; отпечатки незаконченных загрузок держит в `localStorage`, чтобы после
перезагрузки страницы предложить «Продолжить загрузку clip.mp4 (1,2 из 3,4 ГБ)» — выберите тот
же файл.

## 5. Сервер каталога

`Gallery` учится:

- `fetch()` сначала спрашивает провайдеров: ссылка на ролик — постер по §1.7 и видео в той же
  строке; прямая ссылка на `video/mp4`/`video/webm` — скачивание в очереди (`FetchVideo`,
  потоком на диск, с лимитом §1.3), строка появляется, когда файл скачан; иначе — картинка;
- `attachVideo(ProductImage, string $uploadId | string $url, ?int $duration)` — готовая загрузка
  (§4) или ссылка провайдера; прежний файл, если был, удаляется сразу;
- `detachVideo(ProductImage)` — файл удаляется сразу.

Удаление картинки удаляет и её ролик. Удалённый товар файлы сохраняет — как с картинками.

### API панели

```
POST   /api/cms/catalog/products/{id}/images                  multipart file | { url } — url может быть роликом
POST   /api/cms/catalog/products/{id}/images/{image}/video    { upload, duration? } | { url } → { data: image }
DELETE /api/cms/catalog/products/{id}/images/{image}/video    → { data: image }
```

Права — `catalog.manage`, как у остальной галереи. В `image` ресурса появляется
`video: { provider, url, embed, duration } | null`: `url` — файл или страница ролика, `embed` —
адрес для iframe (у файла `null`).

### Журнал

Прикрепление и снятие ролика — запись с полем `images`, как добавление и удаление картинки:
`«photo.jpg»: — → ▶ YouTube` / `▶ clip.mp4 → —`.

## 6. Витрина

- `product.blade.php`: элемент галереи с роликом — `<figure>` с постером и
  `<button class="webx-catalog-product__play">`; маленький встроенный скрипт без зависимостей
  меняет содержимое на `<video controls autoplay playsinline preload="none">` или iframe
  `https://www.youtube-nocookie.com/embed/{id}?autoplay=1`. Без JS — ссылка.
- Разметка (`ProductMarkup`): `Product.subjectOf` — список `VideoObject`: `name` (alt картинки,
  иначе название товара), `description` (`summary`, иначе название), `thumbnailUrl` (постер),
  `uploadDate` (`created_at` строки), `contentUrl` (файл) или `embedUrl` (YouTube), `duration`
  (ISO 8601), если известна.
- Карточка в списке — без изменений: постер и так главная картинка.

## 7. Панель

`GalleryField.vue`:

- Превью строки с роликом — значок ▶ в углу (рядом с «Главная»); клик по превью открывает ролик в
  новой вкладке, как сейчас картинку.
- Действия строки: «Прикрепить видео» → «Файл…» / «Ссылка на YouTube…»; у строки с роликом —
  «Убрать видео» (с подтверждением: файл удаляется сразу).
- Зона загрузки принимает и `video/mp4,video/webm`: картинка — как сейчас; ролик — кадр по §1.6,
  картинка, затем загрузка кусками и прикрепление. Строка появляется сразу с постером и полосой:
  процент, скорость, «осталось ~4 мин», пауза и отмена. Работать с остальной формой можно, пока
  файл идёт; уход со страницы во время загрузки спрашивает, как при несохранённом.
- Карточка «Загрузить по адресу» принимает и ссылку на ролик, и прямую ссылку на mp4; подсказка
  говорит это.
- Флаг `fields.video` приходит в описании экрана: выключен — ни меню, ни `video/*` в зоне.

## 8. MCP

Сейчас у агента галереи нет вовсе: картинки видны в `catalog_products_get`, но добавить их нечем.
В этой работе — полный набор за `catalog:read` / `catalog:write` и права панели:

| Инструмент                        | Что                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------- |
| `catalog_products_gallery`        | галерея товара по порядку: картинки, подписи, размеры, ролики                   |
| `catalog_products_gallery_add`    | `{ id, url, alt?, title?, position? }` — картинка, ролик YouTube или прямой mp4 |
| `catalog_products_gallery_update` | `{ id, image, alt?, title? }` — подписи, языки картой, как везде                |
| `catalog_products_gallery_order`  | `{ id, images: [id…] }` — весь порядок, первая — главная                        |
| `catalog_products_gallery_video`  | `{ id, image, url }` — прикрепить ролик к картинке; `url: null` — снять         |
| `catalog_products_gallery_remove` | `{ id, image }` — удалить строку с файлами                                      |

Все пишущие принимают `dry_run`. Прямой mp4 скачивается в очереди — инструмент отвечает, что
загрузка поставлена, а не ждёт гигабайт. Файлы с машины агента не загружаются: у MCP нет для
этого честного пути. `catalog://fields` говорит флаг `video` и лимит размера.

## 10. Отложено

Другие площадки (одна запись в `VideoProviders`), видео-карта сайта, перекодирование и адаптивный
стрим, длительность роликов YouTube (нужен ключ Data API), загрузка кусками для картинок и
медиатеки (протокол §4 готов, подключить — отдельная правка), колонка обмена для роликов — вместе
со спекой обмена: `images` уже принимает адреса, и ссылка на ролик в ней заработает через
`Gallery::fetch`.

## 11. Тесты, которые обязательны

- Загрузка кусками: куски дописываются; кусок не с того смещения — 409 с настоящим; повторный
  `POST` с тем же отпечатком — та же сессия и её `offset`; чужой администратор её не получает;
  размер больше свободного места — отказ на создании; истёкшая сессия убирается с файлом;
  `claim` с чужим `purpose` — отказ.
- Разбор ссылок YouTube: все формы из §3, мусор и чужие домены — не ролик.
- Ссылка на ролик в `POST …/images` — строка с постером и видео; `maxresdefault` 404 →
  `hqdefault` (`Http::fake`); прямой mp4 — задание в очереди, строка после него.
- Файл: не видео по содержимому (картинка с расширением `.mp4`) — отказ; больше лимита — отказ;
  замена ролика и снятие удаляют файл; удаление картинки удаляет её ролик.
- Флаг выключен: отказ на прикрепление в API и MCP, витрина без плеера и без `subjectOf`.
- Разметка: `VideoObject` с `contentUrl` у файла и `embedUrl` у YouTube.
- Журнал: прикрепление и снятие — запись `images`.
- MCP: каждый инструмент из §8, `dry_run`, права и скоупы.
- npm: `useChunkedUpload` — 413 делит кусок, 409 продолжает со смещения сервера, `offline` →
  пауза → `online` → продолжение (fetch подменён); панель — ▶ на превью, меню прикрепления,
  ссылка на ролик в поле адреса. Снятие кадра — функция, проверяемая отдельно от DOM (в jsdom
  `<video>` не декодирует); в браузере — на плейграунде.

## Итог V1

Загрузка кусками живёт в `module-admin` на обеих половинах; гайд для людей —
`apps/docs/guide/uploads.md`. Что V2 и V3 надо знать сверх своих промптов:

- **Ответы — под `data`, как у всей панели:** `POST /api/cms/uploads` отвечает
  `{ data: { id, offset, size, chunk_size } }` — `201` на новую сессию, `200` на найденную по
  отпечатку — и заголовком `Upload-Offset`. `HEAD` — это `GET uploads/{id}` (тот же ответ, тело
  отбрасывается). Отпечаток в базе — `sha1` строки, которую прислал клиент.
- **Отказы — `UploadRefused`, он рендерит себя сам:** 422 с `errors.purpose|type|size|upload`,
  403 без права, 404 на чужую, истёкшую и несуществующую сессию одинаково, 409 с настоящим
  `Upload-Offset`. Брошенный из контроллера каталога, он отвечает так же.
- **Регистрация назначения (V2, провайдер каталога):**
  `UploadPurposes::register('catalog.video', permission: 'catalog.manage', types: fn () => config('webx-catalog.videos.types'), maxBytes: fn () => config('webx-catalog.videos.max_size_mb') * 1048576)`
  — замыкания читаются при каждом запросе, так что тесты и сайт меняют лимиты конфигом. Флаг
  `fields.video` выключен — отказ даёт уже эндпоинт прикрепления, регистрацию можно не трогать.
- **Забрать файл:** `app(Uploads::class)->claim($upload, 'catalog.video', $request->user())` →
  `ClaimedUpload { id, path, name, size, type }`; сессии после этого нет. Проверка содержимого
  (`finfo` на `$claimed->path`), `hash_file('sha1', …)` и перенос — дело V2 **до**
  `$claimed->moveTo($disk, $path)` (потоком, `.part` удаляется) или `$claimed->discard()` при отказе.
  Незабранный `.part` подметёт `webx:prune-uploads` через TTL.
- **Куски лежат на локальном диске** `storage/app/uploads` независимо от диска галереи: в облачный
  дописывать нельзя. `webx:prune-uploads` в расписании ежечасно; `webx:doctor` (`UploadSpace`)
  предупреждает, когда свободного места меньше самого большого `maxBytes`.
- **npm:** `useChunkedUpload({ admin?, storage?, retries?, retryDelay? })`; к пяти состояниям
  спеки добавлено `idle`. `start(file, purpose)` резолвится id, когда файл целиком на сервере,
  `null` при отмене и реджектится при ошибке; пауза промис не трогает. Рядом —
  `unfinishedUploads(purpose)`, `forgetUnfinishedUpload(fingerprint, purpose)`,
  `uploadFingerprint(file)`, `MIN_CHUNK`. У `Http` появился необязательный `send()` — запрос
  с CSRF и заголовками панели, но без JSON и без броска на не-2xx.
- **Для V3:** композабл ставит загрузку на паузу, когда умирает его scope, — держать его на
  уровне формы, а не строки галереи, которая может перерисоваться. `beforeunload` композабл не
  вешает: вопрос «уйти во время загрузки?» — забота `GalleryField`. Сервер плейграунда
  (`apps/playground/server/panel`) эндпоинтов `/uploads` пока не знает — V3 добавляет их в
  фикстуры вместе с роликами.

## Итог V2

Сервер каталога готов целиком; гайд для людей — раздел «Video» в `apps/docs/guide/catalog.md`.
Что V3 надо знать сверх своего промпта:

- **Форма ролика в ресурсе.** Каждая картинка (`ProductForm::describe()` → `images`, ответы
  `PUT …/images` и обоих эндпоинтов ролика) несёт
  `video: { provider, url, embed, duration } | null`: `provider` — `file` или ключ провайдера
  (`youtube`), `url` — файл на диске галереи или страница ролика (`watch?v=`), `embed` — адрес
  iframe на `youtube-nocookie.com` (у файла `null`), `duration` — секунды или `null`. Ролик
  провайдера, которого больше никто не регистрирует, приходит как `null`.
- **Эндпоинты и ответы.**
  - `POST …/images { url }` — `201 { data: image }` для картинки и для ссылки YouTube (строка уже
    с роликом, `alt` из oEmbed); `202 { data: { queued: true, product, url, image: null } }` для
    прямой ссылки на файл — строки ещё нет, она появится после `FetchVideo`. Отказ — 422
    `errors.url`: `video-off`, `video-no-poster`, `image-not-a-picture`, `image-unreachable`.
  - `POST …/images/{image}/video { upload, duration? }` — `200 { data: image }`. Отказы: 422
    `errors.upload` (`video-not-a-video` — содержимое не mp4/webm, `video-too-large`,
    `video-off`) и всё, чем отвечает `UploadRefused` из V1: 404 на чужую, истёкшую и
    несуществующую загрузку, 422 `errors.upload` на чужой `purpose` и недокачанную. Отказ по
    содержимому удаляет `.part` — повторять ту же загрузку бессмысленно, только новую.
  - `POST …/images/{image}/video { url }` — `200` для YouTube, `202 { data: { queued: true,
product, url, image } }` для прямой ссылки (ролик ляжет на эту картинку), 422 `errors.url`
    `video-not-a-video` / `video-off`.
  - `DELETE …/images/{image}/video` — `200 { data: image }` с `video: null`; на картинке без
    ролика — тот же ответ, не ошибка. Картинка чужого товара — 404 везде.
- **`duration` шлёт панель** — целые секунды из `<video>.duration` того же локального файла, из
  которого снимается кадр. Сервер её не проверяет и не узнаёт сам.
- **Флаг и лимиты в экране.** Провайдер ставит узлу `gallery` в `catalog.product` патч `set`
  с пропсами `video` (bool), `videoTypes` (`['video/mp4', 'video/webm']`) и `videoMaxBytes`
  (байты). Читается при загрузке приложения, как `barcode`. Назначение `catalog.video`
  зарегистрировано и при выключенном флаге (V1: отказ даёт эндпоинт прикрепления), так что при
  `video: false` панель не должна начинать загрузку вовсе — иначе файл дойдёт и получит 422.
- **Прямой файл без картинки** — строка с заглушкой-постером: тёмный PNG 1280×720 с ▶, общий у
  всех таких строк. Сервер кадры не снимает, поэтому в панели такой строке нужен путь «заменить
  постер» — хотя бы подсказка «добавьте картинку и прикрепите к ней видео». Из панели этот
  случай бывает только через «Загрузить по адресу»; файл с диска приходит с кадром по §1.6.
- **Журнал.** Строка — `«{sha1}.jpg» ▶ YouTube` / `«{sha1}.jpg» ▶ clip.mp4` в поле `images`:
  прикрепление — `null → метка`, замена — `старая → новая`, снятие — `метка → null`. У файла при
  прикреплении стоит имя, с которым его загрузили, а при снятии — хешевое имя на диске: исходное
  имя не хранится.
- **Отступления от §8.** Инструменты MCP принимают `product` и `image`, а не `id`, — как
  остальные пятнадцать инструментов каталога. `dry_run` у `…_add`, `…_video` и `…_remove`
  отвечает, чем окажется адрес, и не ходит в сеть. Откатить запись файла на диске нельзя,
  поэтому эти три инструмента не пишут и потом откатывают, а только описывают. `…_update` и
  `…_order` откатываются транзакцией, как остальные.
- **`Gallery` теперь дверь для всех:** `add()`, `remove()`, `attachVideo()`, `detachVideo()`
  пишут журнал и трогают индекс сами. Контроллер и MCP ходят через них. `fetch()` возвращает
  `ProductImage|QueuedVideo` — вызывающему (обмен, импорт) это надо учесть.
- **Фикстуры плейграунда** (`apps/playground/server/panel`) должны отдавать:
  - в галерее товара одну строку с `video` YouTube и одну с `provider: 'file'` (`url` на
    маленький mp4 или на заглушку, `embed: null`, `duration`);
  - `POST/DELETE …/images/{image}/video` с ответами выше, включая 202 на ссылку `.mp4`;
  - четыре эндпоинта `/api/cms/uploads` из V1, достаточно в памяти;
  - в описании экрана `catalog.product` — пропсы `video`, `videoTypes`, `videoMaxBytes` у узла
    `gallery`.
