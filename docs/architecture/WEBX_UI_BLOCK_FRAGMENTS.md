# Общие блоки — спецификация и план реализации

Статус: спроектирована 14.10.2026; F1–F3 сделаны 14.10.2026, выходит со следующим релизом; после него — проверка на телефоне на хомлабе. Пакеты — `webx-ui/module-blocks` и
`@webx-ui/module-blocks` (главное), `webx-ui/module-admin` (доктор, панель на сайте). Первый
потребитель — стартовый сайт: секция заявки над подвалом.

Секция, которая стоит на многих страницах с одним и тем же содержимым — заявка над подвалом,
плашка акции, блок «Нам доверяют», — сейчас делается одним из двух способов, и оба плохи.
Блоком в содержимое каждой страницы — тогда текст правят на двадцати страницах. Зоной лейаута
(`WEBX_UI_LAYOUT_REGIONS.md`) — тогда она стоит на **всех** страницах, и убрать её с «Контактов»
нельзя иначе как полем на каждой записи; клиент, далёкий от этого, по вкладкам ходить не будет.

Ответ: **общий блок** — зона, которую печатает не лейаут, а тот, кто её поставил:

```blade
{{-- файловый шаблон: индекс услуг, страница статьи --}}
<x-webx-blocks::region name="request" fallback="components.request" />
```

а на странице из блоков — блок «Общий блок» с выбранной зоной, который клиент добавляет и
удаляет, как любой другой. Содержимое правится один раз, в «Регионах сайта»; где его нет —
его просто не поставили. Нужна страница со своим текстом — одна кнопка делает из общего блока
обычный на этой странице.

Это и есть «одна плашка на двадцати страницах», отложенная в §1 спеки компонентов и в §13 спеки
зон как контракт «вставить блоком».

## 1. Границы

**Внутри (`module-blocks`):** признак `fragment` в объявлении зоны; предложенный тип блока
`fragment` и узел схемы `wx-fragment`; отвязка («сделать отдельным»); защита от зацикливания;
предпросмотр общего блока — прокрутка к нему, страница, на которой он есть; прокрутка превью
страницы к блоку, внутри которого зона; API и MCP; гайд.

**Внутри (`module-admin`):** проверка доктора `Regions` не ищет общие блоки в лейауте; панель на
сайте — блок внутри общего правится как блок общего, с пометкой и отвязкой.

**Снаружи:** переопределение отдельных полей общего блока на странице («общий, но заголовок
свой», как pattern overrides WordPress 6.6) — §7; общий блок на запись через поле экрана (§13
спеки зон, «вариант зоны на сущность») — не нужен: общий блок ставят туда, где он нужен.

## 2. Принятые решения (не переоткрывать)

1. **Общий блок — это зона, а не новая сущность.** У зоны уже есть всё, что нужно содержимому,
   которое правят один раз: `HasBlocks`, черновик, публикация, история, откат, свой набор стилей,
   печатаемый тегом на месте, запасной вариант, предпросмотр, MCP `blocks_region_*`, панель на
   сайте. Второго хранилища нет; разница с шапкой — только в том, кто печатает тег.
2. **Признак в объявлении, не в базе.** `'fragment' => true` рядом с `title` в
   `webx-blocks.regions`. Объявление пишет тот же, кто печатает тег (решение 2 спеки зон), и
   знает, лейаут это или нет. Зона без признака ведёт себя, как сейчас.
3. **В «Общий блок» на странице выбираются только общие зоны.** Шапка и подвал — зоны лейаута:
   вставленные посреди страницы, они печатались бы дважды. Список в поле — зоны с `fragment`.
4. **Где общий блок есть — решает место, а не запись.** Нет поля «показывать / скрыть» на
   экранах записей: на странице из блоков общий блок — блок её содержимого (добавить, удалить,
   переставить — как любой), в файловом шаблоне — тег. Убрать с «Контактов» — удалить блок.
5. **Свой текст на одной странице — отвязкой, а не переопределением.** «Сделать отдельным для
   этой страницы» заменяет узел общего блока копией содержимого зоны: обычные блоки с теми же
   значениями, новыми ключами, в черновике страницы. Дальше они живут своей жизнью и за общим
   не следят — панель говорит об этом до нажатия. Так работают detach у компонента Figma и
   отвязка синхронизированного паттерна WordPress: одна понятная операция вместо правил, какое
   поле чьё. Переопределение полей — §7, если массово понадобится.
6. **Копируется опубликованное.** Отвязка берёт дерево, которое видит посетитель, — черновик
   общего блока может быть чужой незаконченной правкой. У зоны без публикации копировать нечего:
   кнопка недоступна, рядом — «общий блок ещё не опубликован».
7. **Цикл — отказ при публикации и пусто на сайте.** Общий блок, внутри которого (прямо или
   через другой общий) стоит «Общий блок» на него же, публикация отклоняет (422, путь цикла). На
   сайте рендер держит стек рисуемых зон: повторный вход — пустая строка и запись в лог, как у
   неизвестного типа; это страховка для дерева, опубликованного до проверки.
8. **Предпросмотр общего блока — на странице, где он есть, прокрученный к нему.** Решение 9 спеки
   зон остаётся: предпросмотр — живая страница сайта. Для общего блока добавляется только то,
   чего не нужно шапке: фрейм прокручивается к зоне и обводит её; если на выбранной странице зоны
   нет — показывается сцена (как для адреса не из реестра) с полосой «на этой странице общего
   блока нет».
9. **В интерфейсе — «Общий блок», в коде — `fragment`.** Клиент думает блоками; слово «зона»
   (region) остаётся за шапкой и подвалом. Раздел «Регионы сайта» показывает общие блоки
   отдельной группой под шапкой и подвалом.

## 3. `module-blocks`, php

### 3.1. Объявление

```php
// config/webx-blocks.php
'regions' => [
    'header' => ['title' => 'trans::webx-blocks::regions.header'],
    'footer' => ['title' => 'trans::webx-blocks::regions.footer'],
    'request' => [
        'title' => 'Request',
        'description' => 'The request form above the footer.',
        'fragment' => true,
    ],
],
```

`Regions::declared()` отдаёт `fragment: bool`; `Regions::fragments()` — имена общих блоков. В
API списка зон и в `blocks_regions` — то же поле.

### 3.2. Предложенный тип `fragment` и узел `wx-fragment`

`resources/blocks/fragment.json` (механизм `BlockOffers`, §10.3 спеки тем — ставится один раз,
`webx:blocks:offered --install`):

```json
{
  "slug": "fragment",
  "title": "Shared block",
  "group": "content",
  "schema": [{ "id": "fragment", "type": "wx-fragment", "label": "Shared block" }],
  "template": "@if ($fragment)<x-webx-blocks::region :name=\"$fragment\" />@endif\n"
}
```

Узел `wx-fragment` — значение: имя зоны (строка). Тип поля на php (`FieldTypes`) проверяет, что
имя объявлено и это общий блок; иначе — ошибка поля, как у неизвестной ссылки. Пустое — блок
ничего не печатает.

Тег `<x-webx-blocks::region>` с `:name` из значения уже работает (§4 спеки зон).

### 3.3. Рендер

- Стек рисуемых зон в `Regions` (решение 7): вход в `render()` с именем, которое уже в стеке, —
  пустая строка и `warning` в лог с путём.
- Внутри блока страницы зона печатает свой `<link rel="stylesheet">` на месте, как в лейауте
  (решение 7 спеки зон) — проверено на стартере 14.10.2026: работает, мигания нет.
- Маркеры: на странице с панелью на сайте зона внутри блока обёрнута своими
  `<!--wx-region:…-->`, блоки внутри — своими `<!--wx:…-->`; `site-bar.js` уже относит их к
  зоне, а не к странице (scan: «A record's blocks printed inside a region are the region's»).

### 3.4. Проверка цикла при публикации

`Regions::refusals()` (та же точка, где `allow` и `max`) обходит дерево черновика: каждый узел
`fragment` раскрывается в опубликованное дерево названной зоны, рекурсивно; встреча имени
публикуемой зоны — отказ `webx-blocks::regions.cycle` с путём (`request → promo → request`).
Публикация страницы цикл не создаёт (страница не зона), её не проверяем.

`refusals()` зовёт и сохранение черновика зоны (`RegionWriter::admissible()`), поэтому цикл,
который виден уже при записи, отбивается 422 сразу — черновик не сохраняется. Цикл, который
сложился позже (другая зона опубликовала ссылку на эту), ловит публикация. Узел «общего блока»
опознаётся по полю типа `wx-fragment`, а не по slug `fragment`: тип сайт может переименовать или
сделать свой (`Fragments::placed()`).

### 3.5. Отвязка

`POST /api/cms/regions/{name}/copy` → `{ data: { blocks: [...] } }` — опубликованное дерево зоны с новыми
ключами на всех уровнях (ключ уникален в пределах записи, §5 спеки блоков), значения как есть.
Право — `blocks.view` и право на запись, в которую вставляют (это проверит её сохранение).
Ничего не пишет: клиент кладёт ответ в черновик записи вместо узла `fragment` и сохраняет
обычным путём — ревизия, автосейв, история работают как всегда.

Зона без публикации — 409 `webx-blocks::regions.copy-unpublished`; зона лейаута — 404.

### 3.6. Предпросмотр

`RegionPreviewController`: после ответа обработчика страницы — если в HTML нет
`<!--wx-region:{name}-->`, а зона общая, отдаётся сцена (`stage()`) с полосой
`webx-blocks::regions.not-on-page` («На этой странице общего блока нет — он показан на пустой
странице»). Для зон лейаута — как сейчас.

### 3.7. API и MCP

- Список зон: `fragment`, а у общих — `used_on`: записи, в содержимом которых (опубликованном
  или черновике, с пометкой какое) стоит узел `fragment` с этим именем. Тот же обход, что у
  `Panel\Usage` (все записи моделей `webx-blocks.entities`, оба дерева), только по значению узла,
  а не по типу. Файловые шаблоны в `used_on` не видны — честно, с пометкой.
- MCP: `blocks_regions` отдаёт `fragment` и `used_on`; ресурс модуля объясняет агенту: общий
  блок на странице — узел `{ type: "fragment", values: { fragment: "<имя>" } }`; отвязать —
  прочитать зону `blocks_get_content(entity: "region")` и вставить её блоки с новыми ключами.
  Отдельного инструмента отвязки нет — это две существующие операции.

## 4. `@webx-ui/module-blocks`, панель

### 4.1. Узел `wx-fragment` в редакторе

Форма блока «Общий блок» вместо пустоты:

- выбор общего блока (`WxSelect` по списку зон с `fragment`);
- статус выбранного: «Опубликован» / «Есть черновик» / «Не опубликован — на сайте запасной
  вариант» / «Пуст»;
- пояснение: «Этот блок показывает общий блок сайта. Его правка изменит его на всех страницах,
  где он стоит»;
- **«Править для всех страниц»** — ссылка на `/cms/regions/{name}` (в новой вкладке — редактор
  страницы с черновиком не теряется);
- **«Сделать отдельным для этой страницы»** — подтверждение («Блок перестанет следить за общим:
  правки общего сюда больше не придут»), затем `copy` (§3.5) и замена узла в дереве на месте,
  с выделением первого из вставленных блоков.

### 4.2. Превью страницы

Выбор блока «Общий блок» в редакторе страницы должен прокручивать превью к нему, как к любому
другому. Сейчас не прокручивает (проверено на стартере: «Text» — едет, блок с зоной внутри — нет).
Причина — первая задача этапа F2: вероятнее всего, первый узел после `<!--wx:key-->` у такого
блока — `<link rel="stylesheet">` зоны с пустым прямоугольником, и `BlocksPreview` берёт его
габариты. Лечится выбором первого элемента с ненулевым прямоугольником между маркерами.

### 4.3. Редактор зоны

- Список «Регионы сайта»: две группы — «Шапка и подвал» (зоны лейаута) и «Общие блоки».
- У общего блока над деревом — «Где стоит»: `used_on` ссылками на записи; плюс строка «и в
  шаблонах сайта, которые его печатают» (их не видно).
- Превью: выбор страницы по умолчанию — первая из `used_on`, а не главная; после загрузки фрейм
  прокручивается к `<!--wx-region:{name}-->` и обводит зону (тот же стиль рамки, что у
  выделенного блока).

## 5. `module-admin`

### 5.1. Доктор

`Doctor\Checks\Regions` пропускает зоны с `fragment`: их печатает не лейаут, искать их там —
ложная тревога (на стартере сейчас: «The region [request] is declared…, but the layout does not
print it»). Вместо этого для общей зоны — `ok`, если она где-то стоит (`used_on` не пуст), и
`warn` «общий блок никуда не поставлен», если нет; про файловые шаблоны — оговорка в тексте.

### 5.2. Панель на сайте

- Клик по блоку внутри общего открывает его как блок зоны (это уже так по `scan()`), с плашкой
  «Общий блок · Request — изменится на всех страницах».
- Там же кнопка «Сделать отдельным для этой страницы» — когда общий блок стоит в содержимом
  записи этой страницы (узел `fragment` её дерева), а не напечатан шаблоном.
- Проверить на стартере, что `request` попадает в источники вкладки для страницы, где он стоит,
  а не только `header` и `footer` (`SiteBarBlocks`, «the layout's regions»). Если нет — источники
  берутся по маркерам `wx-region:` на странице.

## 6. Стартовый сайт

Сейчас (14.10.2026) на стартере собрано без правок пакетов, чтобы увидеть, что ломается:
зона `request` в `config/webx-blocks.php` (без признака), тег в
`theme/views/vendor/webx-services/index.blade.php`, запасная вьюха
`theme/views/components/request.blade.php` (блок `contact` темы тегом `<x-webx-block>`), форма
`request` модуля заявок, тип блока сайта `request` с шаблоном из одного тега — на главной.

После выпуска: `'fragment' => true` у `request`; `webx:blocks:offered --install --module=blocks`;
тип сайта `request` заменяется блоком `fragment` со значением `request` (переименованием типа
`rename_to` не обойтись — у узла появляется значение; скриптом, один раз) и удаляется.

## 7. Отвергнуто и отложено

- **Поле «показывать / скрыть зону» на экранах записей** — решение 4. Клиент не ходит по
  вкладкам; блок, который можно удалить, понятнее выключателя, который надо найти.
- **Переопределение полей на месте** («общий, но заголовок свой»). Тег зоны уже передаёт
  атрибуты блокам как `$region->data()`, но каждый тип должен уметь читать подмены, а редактор —
  показывать, какое поле общее, какое своё. Отложено до сайта, где отвязки окажется мало.
- **Общий блок как компонент (`kind = component`)** — у компонента нет содержимого, только код
  (решение 3 спеки зон).
- **Обратная привязка отвязанной копии** — «снова сделать общим». Это удалить копию и поставить
  «Общий блок»; отдельная операция не нужна.

## 8. Этапы

**F1 — php `module-blocks` и `module-admin`.** Сделан 14.10.2026 (`FragmentsTest`, `DoctorTest`).
§3.1–§3.7, §5.1. Тесты: объявление и
`fragments()`; поле `wx-fragment` отклоняет зону лейаута и необъявленную; рендер зоны внутри
блока страницы (стили на месте, маркеры в режиме панели на сайте); цикл — отказ публикации с
путём и пустота на сайте при уже опубликованном цикле; `copy` — новые ключи на всех уровнях,
опубликованное, а не черновик, 409 без публикации; предпросмотр — сцена, когда на странице зоны
нет; доктор — общий блок не ищется в лейауте; `used_on`. Changeset на `@webx-ui/php`.

Как сделано и что из этого следует дальше:

- Проверка «общий блок где-то стоит» живёт не в `Doctor\Checks\Regions` `module-admin` (тот
  без `module-blocks` не знает содержимого), а в `module-blocks`: `Doctor\FragmentsCheck`,
  регистрируется в `DoctorChecks`. Проверка лейаута только пропускает зоны с `fragment`.
- `copy` открыт по `blocks.view` / `blocks.manage` / `blocks.regions` (любое), а не только
  `blocks.regions`, как остальные `/regions/*`: его зовёт редактор страницы.
- `used_on` считается в списке зон одним обходом всех записей (`RegionForm::rows()` →
  `Usage::fragments()`); на сайте с тысячами страниц список зон станет медленнее — если
  заметно, кешировать так же, как счётчики `Usage::counts()`.
- Для F2: в предпросмотре **страницы** (не зоны) общий блок внутри блока страницы маркеров
  `<!--wx-region:…-->` не получает — `Regions::mark()` смотрит на `isMarkingForSiteBar()`, а
  превью страницы — `preview`. Прокрутке к блоку (§4.2) это не мешает (маркер блока `<!--wx:key-->`
  стоит снаружи), но рамку зоны в превью страницы так не нарисовать.
- Для F3: на стартере у `request` признака ещё нет, поэтому доктор там по-прежнему говорит
  «layout does not print it» — уйдёт с `'fragment' => true` (§6).

**F2 — npm `@webx-ui/module-blocks`.** Сделан 14.10.2026 (`FragmentField.test`, `RegionsPage.test`,
`RegionEditorPage.test`, `BlocksField.test`, `frame.test`; на стартере — Playwright). §4: узел `wx-fragment`, отвязка, группа «Общие блоки»,
«Где стоит», превью зоны с прокруткой и рамкой, прокрутка превью страницы к блоку с зоной (§4.2,
сначала причина). Тесты компонентов; проверка в браузере на плейграунде панели и на стартере —
вёрстка и прокрутка в jsdom не ловятся. Changeset на `@webx-ui/module-blocks`.

Как сделано и что из этого следует дальше:

- Причина §4.2 подтвердилась: `blockElement()` брал `<link rel="stylesheet">` зоны. Теперь он
  пропускает то, что не рисуется (`link`, `style`, `script`, `template`, `meta`, `noscript`), и
  из остального берёт первый элемент с ненулевым прямоугольником. По дороге нашлась вторая
  причина, общая для любого блока ниже первого экрана фрейма: `onLoad` мерил высоту раньше, чем
  ставил просьбу прокрутить, и повтор после роста фрейма не назначался — прокрутка упиралась в
  фрейм высотой с окно. Порядок исправлен.
- Списку зон нужно право `blocks.regions`, а редактор страницы может его не иметь. Поле берёт
  общие блоки из `GET /blocks/fragments` (право каталога, без `used_on`) — php-правка в F2.
- «Где стоит» — записи из `used_on` кнопками, которые переключают превью на эту страницу (а не
  ссылками в редакторы записей: у `used_on` нет адреса записи в панели — только модель и адрес на
  сайте); общий блок внутри другого общего ведёт в редактор того. Страница превью по умолчанию —
  первая из `used_on`, где он на сайте; она не запоминается, запоминается только выбор.
- Рамка зоны — не класс на элементе, а блок поверх страницы (`#wx-preview-region` на корневом
  элементе): зона — это несколько блоков подряд, а обёртка сломала бы селекторы сайта.
- Отвязка живёт в поле, а подменяет узел `BlocksField` (контекст `blocksFragmentKey`): форма
  блока рисуется рендерером экранов и до дерева сама не дотягивается. Вне конструктора (вкладка
  «Блоки» панели на сайте) кнопки отвязки у поля нет — это §5.2, F3.
- Индекс услуг стартера печатает зону тегом, но адреса `/services` нет в реестре — превью зоны там
  показывает сцену с полосой «не из реестра». Это поведение спеки зон, не F2.

- Источники вкладки не менялись: она и раньше брала все объявленные зоны, так что `request` в них
