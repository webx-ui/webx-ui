# Виджеты сайта — спецификация

Статус: выпущено — W1–W6 (§18, §20). Пакет — библиотека `webx-ui/widgets` (§3); правки в
`webx-ui/themes` и `theme-default` (поведения живут здесь, §2.3), в `module-settings` (вкладки
согласия и контактов, §9.5, §12.1), в `module-seo` (контакты в микроразметке, §12.1), в
`module-audit` (проверки, §15.2), в `module-inbox` (формы на движке виджетов, §17). Соседние
спеки: темы — [`WEBX_UI_THEMES.md`](WEBX_UI_THEMES.md) (цепочка слоёв, токены, проверка CSS),
блоки — [`WEBX_UI_MODULE_BLOCKS.md`](WEBX_UI_MODULE_BLOCKS.md) (рантайм `webx`, предложенные
блоки), заявки — [`WEBX_UI_MODULE_INBOX.md`](WEBX_UI_MODULE_INBOX.md). Гайды —
`apps/docs/guide/widgets.md` («Site widgets») и `apps/docs/guide/forms.md` («Forms»).

Из сайта в сайт повторяются одни и те же интерактивные куски: слайдер, увеличение картинки, видео с
YouTube, карта на странице контактов, баннер согласия на cookie, вкладки, аккордеон, мобильное меню.
Без общего пакета каждый сайт ставит их заново — свой слайдер, свой скрипт меню, своя обёртка над
YouTube — и почти никогда не ставит баннер согласия, без которого сайт с аналитикой или видео в ЕС
работать не должен.

Ответ — **один пакет виджетов**: поставил — и в шаблонах есть `<x-webx-slider>`, `<x-webx-video>`,
`<x-webx-map>`, баннер согласия на каждой странице, вкладки по атрибуту. Логика, доступность,
загрузка по требованию и согласие — готовы; вид — каркас на токенах сайта, который тема
перекрашивает и перерисовывает теми же дверями, что вид модулей.

## 1. Границы

**Внутри:**

- пакет, его место в цепочке темы, загрузка по требованию (§3, §4);
- контракт виджета: компонент, классы, CSS на токенах, скрипт, слова (§5);
- лёгкие поведения: выпадашки, диалог, вкладки, аккордеон (§6); мобильное меню (§6.1); шапка (§6.2);
  выпадающая панель (§6.3); форма в окне (§6.4);
- слайдер (§7), лайтбокс (§8), видео (§10), карта (§11);
- согласие на cookie и блокировка стороннего до согласия (§9);
- контакты как данные сайта и виджеты на них: телефоны, часы работы, мессенджеры, соцсети (§12);
- переключатель языка (§13); контентные виджеты второй волны (§14);
- формы: поля, оболочка с отправкой на месте, проверка в браузере теми же правилами, что на
  сервере, подсказки при вводе (§17);
- предложенные блоки (§15.1); проверки аудита (§15.2).

**Снаружи (и почему):**

- **Заявки.** Конструктор форм в панели, приём, хранение, антиспам, капча и письма остаются
  `module-inbox`; его формы рисуются полями этого пакета (§17).
- **Аналитика как таковая** — какие счётчики стоят и где их ключи. Здесь только то, что они не
  запускаются до согласия (§9.3).
- **Хлебные крошки** — разметка, а не поведение; отдельная задача (§19).
- **Вид.** Пакет даёт каркас, а не дизайн; красивым виджет делает тема.

## 2. Принятые решения (не переоткрывать)

1. **Один пакет, не пакет на виджет.** Каждый пакет в монорепе стоит цикла: четыре места в `php/`,
   первая публикация руками, документация, `AGENTS.md`. Виджеты маленькие, связаны общим (загрузка,
   согласие, токены) и почти всегда нужны вместе. Грузится при этом только то, что стоит на
   странице (§4) — один пакет не значит один большой файл.
2. **Логика готова, вид — каркас.** Виджет несёт поведение, доступность и базовый CSS на токенах
   `--site-*`; классы `webx-<виджет>-*` — публичный контракт (§5). Тема меняет вид токенами, CSS на
   классах или перекрытием вьюхи компонента — те же двери, что у модулей (§10.5 спеки тем).
3. **Поведения живут здесь, а не в движке тем.** Движок тем остаётся без JavaScript: цепочка,
   токены, проверки. Меню, диалог, вкладки, аккордеон — лёгкие виджеты этого пакета (§6);
   `theme-default` зависит от `widgets`, как зависит от модулей.
4. **Ничего стороннего до согласия.** Видео, карта, счётчики — до согласия на их категорию на
   странице нет ни одного запроса к третьей стороне: вместо них заглушка с понятной кнопкой (§9.4).
   Это не настройка, а поведение по умолчанию; выключить можно только явно и только для сайта вне
   ЕС, и аудит это заметит.
5. **Скрипт — только там, где виджет есть.** Компонент сам заявляет свои файлы, `@webxTheme`
   печатает только заявленные (§4). Слайдер на главной не грузит Swiper на остальные сто страниц.
6. **Без сборки на сайте.** Пакет приезжает с готовым `dist/`, как тема (§2.9 спеки тем). Сторонние
   библиотеки (Swiper, PhotoSwipe, Leaflet) вшиты в `dist/` и обновляются версией пакета, а не
   сайтом.
7. **Работает и без JavaScript.** Слайдер — прокручиваемая лента, лайтбокс — ссылка на картинку,
   вкладки — заголовки над блоками, видео — ссылка на ролик, карта — адрес и ссылка на карту, форма —
   обычный POST.
8. **Сторонние библиотеки — с лицензией MIT или равной ей**, без ключей и регистрации там, где можно
   (карта по умолчанию — OpenStreetMap без ключа, §11).

## 3. Пакет

**`webx-ui/widgets`** — библиотека без префикса `module-`: виджеты работают на любом сайте, панель
им не нужна (настройки согласия — вкладка в `module-settings`, §9.5). Namespace `WebxUi\Widgets`,
таблиц нет. Требует `webx-ui/themes` (словарь токенов, цепочка, выкладка ассетов); `routing`,
`localization`, `module-settings`, `module-media`, `module-audit` — в `suggest`.

```
widgets/
├── src/                      ← PHP: компоненты, провайдер, Consent, Forms, Audit, команды
├── resources/
│   ├── views/components/     ← <x-webx-slider>, <x-webx-video>, … (перекрываются темой)
│   ├── views/icons/          ← иконки вьюхами: стрелки, play, закрыть, сети, мессенджеры
│   ├── blocks/*.json         ← предложенные блоки (§15.1)
│   ├── screens/              ← патч экрана настроек: вкладка «Cookie» (§9.5)
│   └── js/, css/             ← исходники по виджету
├── dist/                     ← собранное: по файлу JS и CSS на виджет + общий runtime (закоммичено)
├── lang/<locale>/            ← widgets.php (подписи, ARIA, тексты баннера), panel.php, checks/audit/fixes.php — 10 языков
├── routes/web.php            ← GET csrf, двери витрины (§17.3)
└── tests/
```

В цепочке темы пакет — **нижний слой**, как модуль (§7.1 спеки тем): его вьюхи компонентов
перекрываются в `<слой>/views/vendor/webx-widgets/`, его CSS идёт первым в каскаде (шов
`Contracts\HeadPart` движка тем), его `dist/` `webx:theme:sync` выкладывает рядом со слоями темы
(шов `BottomLayers`, `public/themes/webx-ui/widgets/<hash>/`), его блоки — через `BlockOffers`.
Движок тем не знает ни одного имени виджета.

## 4. Загрузка по требованию

Компонент при рендере заявляет свой виджет: `Widgets::need('slider')` (фасад
`WebxUi\Widgets\Facades\Widgets`). Имя, которого нет ни в runtime, ни в `dist/`, — исключение:
опечатка в шаблоне иначе была бы виджетом, который молча не стартует. `@webxTheme` печатает маркер,
а когда страница отрисована целиком (шапка и подвал — после головы, и они-то первыми заявляют
виджеты), `Widgets::finish()` меняет его на `<link>` заявленных CSS в `<head>` и ставит
`<script type="module">` перед `</body>`. Только HTML с маркером: JSON предпросмотра со страницей
внутри строки не трогается. Заявки сбрасываются после каждого ответа (долгоживущий воркер).

**Общий runtime грузится на каждой странице сайта с темой** — атрибутный путь (`data-webx-tabs` в
шаблоне блока без компонента) заявить нечем, поэтому лёгкие поведения (§6), мобильное меню и шапка
лежат в нём, а тяжёлые виджеты (слайдер, лайтбокс, карта) — только через компонент. Баннер
согласия заявлен на каждой странице (§9). **Сайт без темы** `@webxTheme` не печатает ничего; его
лейаут пишет `@webxWidgets` перед `</body>` — только скрипты (runtime и заявленные), без стилей и
без баннера; `webx:setup --no-theme` вписывает строку, `webx:theme:sync` выкладывает виджеты и без
темы.

`Widgets::finish()` — ещё и единственное место, где видна вся страница: там же находятся
открывающие формы в окне (§6.4) и ссылки лайтбокса (§8), оборачиваются таблицы прозы и
заполняется оглавление (§14), пишется строчка полосы объявления в `<head>` (§14).

**Блок, нарисованный отдельно для панели** (сцена редактора типа, блок, подменённый в превью после
правки поля, `blocks_render`), уходит JSON-ом в страницу, напечатанную раньше него, — `finish()` его
не видит. `module-blocks` шлёт `WebxUi\Blocks\Events\BlockDrawn`, виджеты отвечают
`Widgets::piece()`: тот же сбор (таблицы, оглавление, лайтбокс, зум, окна форм, теги заявленного),
но по частям — `head` (стили, только с темой) и `body` (скрипты, настройки лайтбокса, окна форм), без
баннера согласия. Ответ `/render` и `blocks_render` несёт их в `assets`; панель вставляет каждый раз
только то, чего на странице нет (`addAssets()` в `frame.ts`), стили — рядом со стилями виджетов
страницы, под слоями темы.

Все скрипты монтируются через общий с рантаймом блоков `window.webx` (`webx.mount(root)`, §10
спеки блоков): каждый оборачивает `mount`, который нашёл, поэтому виджет поднимается и на живой
странице, и в блоке, который панель подменила в предпросмотре, и в куске страницы, догруженном
позже. `webx.widget(name, selector, setup)` — регистрация, `setup(el)` возвращает очистку;
монтирование идемпотентно, `webx.unmount(root)` освобождает экземпляр сторонней библиотеки.

Бюджет веса (gzip) проверяет `DistTest`: runtime с поведениями, мобильным меню и шапкой ≤ 16 КБ;
слайдер ≤ 45; лайтбокс ≤ 25; карта ≤ 50 (без тайлов); баннер согласия и контакты ≤ 6; видео (с
фоном) и подсказки ≤ 4; «до и после», оглавление, «показать ещё», зум, поле, маска, файлы ≤ 3;
таблицы, «наверх», «поделиться», счётчик, таймер, полоса объявления, переключатель языка,
пагинация ≤ 2; форма с проверкой ≤ 8. Общих чанков нет: каждый вход сборки — свой файл, и
`DistTest` держит список `dist/`.

## 5. Контракт виджета

Каждый виджет устроен одинаково, и `AGENTS.md` пакета описывает его по одной форме:

| Что              | Как                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Компонент        | `<x-webx-<имя>>` с пропсами; вьюха `webx-widgets::components.<имя>` перекрывается темой                                               |
| Классы           | `webx-<имя>`, `webx-<имя>__<элемент>`, состояния `is-*` — публичный контракт, переименование ломающее                                 |
| CSS              | каркас на `--site-*`, `@container`, без буквальных значений (проверка §8 спеки тем)                                                   |
| Локальные токены | `--webx-<имя>-*` для того, что тема чаще всего крутит (`--webx-slider-gap`, `--webx-slider-arrow-size`); по умолчанию — из `--site-*` |
| Скрипт           | через `webx.mount`, настройки из `data-*` компонента                                                                                  |
| Слова            | `webx-widgets::widgets.<имя>.*` на 10 языках; любое перекрывается пропсом                                                             |
| Иконки           | вьюхи `webx-widgets::icons.<имя>` — тема заменяет любую файлом в `views/vendor/webx-widgets/icons/`, не трогая виджет                 |
| Без JS           | описано, что видит посетитель, и это проверено тестом                                                                                 |

**CSS — один плоский класс на правило, а не `:where()`.** Проза `theme-default` написана в
`:where()`, чтобы компонент со своим классом побеждал её без усилий; каркас виджета в `:where()`
ей проигрывал. Поэтому правило виджета — `.webx-<имя>__<элемент>`, плюс не больше одного
состояния или модификатора того же элемента (`.webx-header.is-hidden`): прозу бьёт, а тема
перекрывает тем же классом — она позже в каскаде. Цепочек нет; состояние, которое меняет
вложенное, ставится на сам элемент или едет вниз локальным токеном. Свои `--webx-<имя>-*`
объявлены на `:where(:root)` из `--site-*`; ни буквальных цветов, ни запасных значений в `var()`,
ни `@media` по ширине. Правило держит `DistTest`. Без JS — правила под `html:not(.webx-js)`
(класс ставит runtime); исключение — «до и после» (§14).

Сторонние стили, которые нельзя переназначить, идут как есть и перекрашиваются их же custom
properties из локальных токенов: PhotoSwipe (`.pswp*`) и Leaflet (`.leaflet-*`) — единственные
чужие классы в `dist/`, и тест держит, что только они. Swiper своих стилей не приносит: все его
имена классов переназначены на `webx-slider*`.

## 6. Лёгкие поведения

Без зависимостей, в общем runtime, включаются атрибутом или компонентом:

| Поведение    | Атрибут / компонент                    | Что делает                                                                                     |
| ------------ | -------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `disclosure` | `data-webx-disclosure`                 | меню шапки, выпадашки; закрытие по Esc и клику мимо; ARIA `expanded`                           |
| `dialog`     | `data-webx-dialog` / `<x-webx-dialog>` | `<dialog>` с ловушкой фокуса и возвратом фокуса; мобильное меню и фильтры каталога на телефоне |
| `tabs`       | `data-webx-tabs` / `<x-webx-tabs>`     | вкладки с клавиатурой (стрелки, Home, End) и ARIA                                              |
| `accordion`  | `data-webx-accordion`                  | на `<details>`; «одна открыта» по желанию                                                      |

- **`dialog`** — `showModal()`: страница за окном инертна, это и есть ловушка фокуса. Esc, клик по
  подложке, `[data-webx-dialog-close]`; фокус возвращается открывшему; `html.webx-scroll-locked`
  с `scrollbar-gutter: stable`; адрес с `#<id>` открывает окно при загрузке. Открыто ли окно,
  читается по атрибуту `open`, а не по событию `close` — его не получает скрытая вкладка.
  `webx.openDialog` отдан наружу. Без JS окно показывается через `:target`.
- **Шторка снизу** — `<x-webx-dialog sheet>` (класс `webx-dialog--sheet`): на окне уже 40rem
  диалог встаёт снизу во всю ширину, скруглён сверху, высотой по содержимому до почти всего экрана,
  прокрутка внутри; въезжает снизу (`@starting-style`, `prefers-reduced-motion` — без анимации).
  Ширину меряет **runtime** (`matchMedia('(width < 40rem)')` → `is-sheet`, следит за поворотом):
  модальный `<dialog>` лежит в top layer поверх вьюпорта, вне любых контейнеров страницы, а `@media`
  по ширине стилям темы запрещён (THEMES §8). Фокус, Esc, подложка — как у любого диалога. Шире
  40rem, без JS и по умолчанию — карточка по центру. `description` — строка под заголовком
  (`__description`, `aria-describedby`).
- **`tabs`** — заголовки панелей становятся `role="tablist"`, стрелки по кругу, Home/End, roving
  `tabindex`; открыта панель, в которую ведёт якорь адреса, или `data-webx-tab-selected`. Без JS —
  заголовки над панелями.
- **`disclosure`** — без JS панель видна, прячет её runtime: `hidden` в разметке панели не пишут.
- Компоненты: `<x-webx-dialog id title description close sheet>`, `<x-webx-tabs label>` и `<x-webx-tabs.panel title
selected level>`.

### 6.1 Мобильное меню

Есть на каждом сайте и каждый раз пишется заново — с теми же ошибками: страница прокручивается под
открытым меню, низ меню уезжает под панель браузера на iPhone, фокус уходит за меню, длинное меню не
прокручивается. Поэтому это не поведение по атрибуту, а **компонент с готовой разметкой, слотами и
каркасом стилей**; что внутри — решает сайт.

```blade
<x-webx-mobile-menu side="right" label="{{ __('theme::menu.open') }}">
    <x-slot:top>
        <a href="/" class="site-logo">…</a>
    </x-slot:top>

    <x-webx-mobile-menu.nav :items="menu('header')" mode="drill" />

    <x-slot:bottom>
        <x-webx-phones layout="list" />
        <x-webx-consent-link />
    </x-slot:bottom>
</x-webx-mobile-menu>
```

**Устройство** — три зоны в одной панели:

| Зона | Слот         | Что                                                                                 |
| ---- | ------------ | ----------------------------------------------------------------------------------- |
| верх | `top`        | закреплён: логотип, кнопка закрытия (есть всегда, даже если слот пуст), язык, поиск |
| тело | по умолчанию | **прокручивается само**, страница под ним — нет: навигация, любые блоки сайта       |
| низ  | `bottom`     | закреплён: телефон, кнопка заявки, соцсети, «Настройки cookie»                      |

Плюс слот `trigger` — своя кнопка вместо стандартного «бургера» (полоски на CSS, `currentColor`).

**Пропсы:** `side` — `left` | `right` | `top` | `bottom` (снизу — «шторка» на всю ширину) | `full`;
`breakpoint` — до какой ширины **шапки** виден триггер (по умолчанию 960px, `@container` на корне
шапки — §2 спеки тем: решает контейнер, а не окно; число пишется в `<style>` рядом с компонентом,
потому что условие контейнерного запроса не читает custom property); `close-on-navigate` (по
умолчанию да); `history` (по умолчанию да).

**Навигация** — `<x-webx-mobile-menu.nav>` рисует дерево `menu()` в двух режимах, оба на
`<details>` (без JS ветка открывается на месте):

- `accordion` — подпункты раскрываются на месте; страница раздела — первый пункт ветки;
  `parent="split"` — ссылка раздела не повторяется: название раздела и есть ссылка, ветку открывает
  стрелка рядом (`<summary>` с `aria-label` «Подменю: …», те же слова, что у стрелки шапки).
  Выбор — атрибутом виджета (и `<x-webx-header parent>`), а не пунктом меню: то же дерево в шапке —
  выпадашка, где родитель уже ссылка, это решение раскладки, а не данных. Ветка без ссылки — как
  была; `drill` держит название ссылкой наверху уровня и `parent` не читает;
- `drill` — подпункт открывает следующий уровень поверх, с кнопкой «Назад» и названием раздела
  ссылкой наверху; для глубоких меню каталога и услуг. Список родителя под уровнем — `is-drilled`
  (`visibility: hidden`, его пункты не ловят фокус).

Текущий пункт помечен `aria-current="page"`, его ветка раскрыта (в `drill` меню открывается сразу
на ней). Пункты — `WebxUi\Widgets\Menu\Item`: читает `MenuLink` из `module-menu` (по тому, что он
несёт, а не по классу — библиотека модуль не требует) и массивы `['label', 'url' | 'attrs',
'children', 'current', 'variant']`; у массива без `current` текущим считается адрес страницы.
Сайт может не использовать этот компонент и положить в тело свою разметку — оболочка от этого не
меняется.

**Что сделано за сайт:**

- `<dialog>` поведения `dialog` (§6): ловушка фокуса, Esc, клик мимо, возврат фокуса на триггер;
- блокировка прокрутки страницы без скачка вёрстки (`scrollbar-gutter`, без `position: fixed` на
  `body`, который сбрасывает прокрутку на iOS);
- высота `100dvh`, отступы `env(safe-area-inset-*)` — низ не уходит под панель браузера и «чёлку»;
- `overscroll-behavior: contain` в теле — прокрутка меню не протекает на страницу;
- закрытие при переходе по ссылке, в том числе по якорю на той же странице;
- «Назад» в браузере закрывает меню, а не уводит со страницы (запись в истории при открытии,
  `:history="false"` выключает). Ссылку при открытой записи меню ведёт **после** того, как запись
  снята (`history.back()` → `popstate`): иначе «Назад» с новой страницы вёл бы сначала на меню;
- свайп в сторону `side` закрывает, панель идёт за пальцем;
- анимация открытия — на `--site-duration`/`--site-easing`, без неё при `prefers-reduced-motion`;
- без JavaScript — триггер — ссылка на `#webx-mobile-menu`, панель открывается через `:target`
  и закрывается ссылкой «Закрыть»; прокрутка тела работает.

**Классы и токены:** `webx-mobile-menu`, `__trigger`, `__panel`, `__panel--<side>`, `__top`,
`__body`, `__bottom`, `__close`; навигация — `webx-mobile-nav`, `__list`, `__item`, `__link`,
`__toggle`, `__level`, `__back`, `__title`, `is-current`, `is-drilled`. Локальные токены:
`--webx-mobile-menu-width` (по умолчанию `min(88vw, 400px)`), `--webx-mobile-menu-backdrop`,
`--webx-mobile-menu-padding`. Каркас — фон `--site-color-surface`, разделители
`--site-color-border`, пункты не ниже 44px по высоте.

Скрипт — в общем runtime: меню есть на каждой странице, грузить его отдельным файлом незачем.

### 6.2 Шапка

Второй кусок, который есть на каждом сайте. Виджет отвечает за **поведение и каркас**, а не за вид:
как шапка выглядит и в каком порядке стоят её части, решает тема. Иначе шапка — самая «дизайнерская»
часть сайта — превращается в компонент с пропсами на каждый случай.

```blade
<x-webx-header sticky="hide-on-scroll" collapse="auto">
    <x-slot:topbar>…телефон, часы работы, язык…</x-slot:topbar>
    <x-slot:brand><a href="/" class="site-logo">…</a></x-slot:brand>

    <x-webx-header.nav :items="menu('header')" />

    <x-slot:actions>…телефон, кнопка заявки, поиск…</x-slot:actions>
    <x-slot:mobile-bottom>…что добавить в низ мобильного меню…</x-slot:mobile-bottom>
</x-webx-header>
```

| Слот            | Что                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------ |
| `topbar`        | необязательная полоса над шапкой; при `sticky` уезжает, шапка остаётся                     |
| `brand`         | логотип; уезжает в верх мобильного меню                                                    |
| по умолчанию    | навигация; обычно `<x-webx-header.nav>`, но может быть любая разметка                      |
| `actions`       | кнопки справа: телефон, заявка, язык, поиск (позже корзина); уезжают в низ мобильного меню |
| `mobile-bottom` | добавляется в низ мобильного меню после `actions`                                          |
| `mobile`        | своё мобильное меню целиком — тогда шапка не собирает его сама                             |
| `trigger`       | своя кнопка вместо «бургера»                                                               |

**Шапка и мобильное меню — два виджета, а не один.** По умолчанию шапка сама вставляет
`<x-webx-mobile-menu>` (§6.1) и собирает его из того, что у неё уже есть: `brand` — наверх,
навигация — в тело (`<x-webx-header.nav>` отдаёт своё дерево через scoped `HeaderNavigation`, и
тело — `<x-webx-mobile-menu.nav>` по тому же дереву, а не копия десктопной разметки; своя разметка
навигации копируется как есть), `actions` и `mobile-bottom` — вниз. Меню пишется один раз, а не
дважды. Связь не жёсткая:

| Ситуация                                 | Как                                                   |
| ---------------------------------------- | ----------------------------------------------------- |
| обычный сайт                             | `<x-webx-header>` — мобильное меню соберётся само     |
| мобильное меню отличается от десктопного | слот `mobile` со своим `<x-webx-mobile-menu>`         |
| своя шапка, не виджетом                  | `<x-webx-mobile-menu>` прямо в ней (§6.1)             |
| короткое меню, «бургер» не нужен         | `collapse="never"` — мобильное меню не рисуется вовсе |

Почему раздельно: мобильное меню нужно и теме со своей шапкой; открывают его не только из шапки
(нижняя панель навигации на телефоне, кнопка в hero); и меняются они по разным причинам — шапка из-за
десктопа (выпадашки, липкость, раскладка), меню из-за телефона (жесты, высота экрана, iOS).

**Пропсы:**

- `collapse` — когда навигация прячется в мобильное меню:
  - `auto` (по умолчанию) — **когда не помещается**: шапка снимает `is-collapsed`, проверяет, что
    каждый пункт навигации лежит внутри `nav` в одну строку, а `brand` и `actions` — внутри полосы,
    и возвращает, если нет, — в одном кадре, без мерцания, при любой сетке темы.
    `ResizeObserver` на корне только назначает пересчёт на следующий кадр. Не угаданная ширина
    окна, при которой меню на 1100px либо уже не влезает, либо ещё влезло бы;
  - число (`960`) — по ширине шапки через `@container`;
  - `never` — никогда.

  Без JavaScript `auto` работает как число из пропа `breakpoint` (по умолчанию 960px): контейнерный
  запрос в `<style>` рядом, под `html:not(.webx-js)`.

- `sticky` — `none` | `sticky` | `hide-on-scroll` (прячется при прокрутке вниз, появляется при
  прокрутке вверх).
- `overlay` — шапка прозрачная поверх первого экрана (hero) и становится сплошной после прокрутки на
  свою высоту (`is-scrolled`). Цвет текста в прозрачном состоянии — локальный токен
  `--webx-header-overlay-color`: поверх тёмной картинки нужен светлый.
- `skip` — адрес ссылки «К содержимому» (`#content`) или `false`, если она есть в лейауте;
  `mode` и `side` — мобильного меню, которое шапка собирает.

**Что сделано за сайт:**

- **Высота шапки — в `--webx-header-height`** на `:root` (то, что остаётся на экране, когда шапка
  липнет: без topbar) и `--webx-header-topbar-height`, обновляются при изменении размера. Липкая
  шапка стоит с `top: calc(-1 * topbar)`. Якоря — `scroll-padding-top` на `html.webx-header-sticky`:
  переход по якорю не прячет заголовок под липкой шапкой. Этот же токен берут другие липкие вещи
  (оглавление, фильтры каталога) для `top`.
- **Ссылка «К содержимому»** первой в документе, видна при фокусе с клавиатуры; ведёт на `<main>`.
- **Выпадающие меню навигации** (`<x-webx-header.nav>` рисует дерево `menu()`; ссылка пункта ведёт
  куда ведёт, рядом кнопка-переключатель, у пункта без адреса переключатель — сам пункт):
  - мышью — открытие через 120 мс, закрытие через 300 мс после ухода; «коридор»: пока курсор в
    треугольнике к верхним углам панели, соседний пункт не перехватывает;
  - на тач-экране — по касанию, второе касание идёт по ссылке;
  - с клавиатуры — Enter и пробел открывают, ↓ ↑ внутри, ← → по верхнему уровню, Esc закрывает и
    возвращает фокус, Tab наружу закрывает;
  - выпадашка не вылезает за край окна: прижимается к правому краю (`is-flipped`);
  - текущий пункт и его ветка — `aria-current="page"` и `is-current`;
  - без JavaScript открывается на `:hover` и `:focus-within`.
- **Режим `mega`** у пункта — вместо списка подпунктов широкая панель во всю ширину шапки со своей
  вьюхой: `<x-webx-header.nav :items="…" :mega="['services' => 'components.mega.services']">`
  (ключ — адрес пункта без слэшей или его имя, вьюха получает `$item`). Режим задаёт вёрстка, а не
  пункт меню в панели: как выглядит панель — решение темы.
- `hide-on-scroll` не прячет шапку, пока внутри есть `.is-open`, открытый `<dialog>` или фокус с
  клавиатуры (`:focus-visible`, а не `:focus-within`: после щелчка мышью фокус остаётся на
  триггере, и шапка не пряталась бы никогда). Фокус, вошедший в спрятанную шапку, показывает её.
- Анимации — на `--site-duration`/`--site-easing`, без них при `prefers-reduced-motion`.

**Раскладка — дело темы.** Корень — CSS-сетка с именованными областями:

```css
.webx-header__bar {
  display: grid;
  grid-template-areas: 'brand nav actions trigger';
  grid-template-columns: auto minmax(0, 1fr) auto auto;
}
```

Логотип по центру, меню справа, две строки — тема переопределяет `grid-template-areas` одной правкой
на этих классах, не перекрывая вьюху (вторая дверь, §10.5 спеки тем). Модификаторы `--sticky`,
`--hide-on-scroll`, `--overlay`, состояния `is-scrolled`, `is-hidden`, `is-collapsed` (ставится на
корень, навигацию, действия и триггер) — для её стилей.

**Классы и токены:** `webx-header`, `__topbar`, `__bar`, `__brand`, `__nav`, `__actions`,
`__trigger`, `__skip`; навигация — `webx-header-nav`, `__item`, `__link`, `__toggle`, `__dropdown`,
`__mega`, `__sublink`, `is-open`, `is-current`, `is-flipped`. Локальные токены:
`--webx-header-height` и `--webx-header-topbar-height` (считаются), `--webx-header-bg`,
`--webx-header-overlay-color`, `--webx-header-gap`.

**Зона `header`.** Шапка сайта — зона лейаута (`WEBX_UI_LAYOUT_REGIONS.md`): пока зона пуста,
печатается Blade-компонент шапки из цепочки темы, и у `theme-default` он собран на этом виджете
(`<x-webx-header class="site-header" sticky="sticky" mode="drill" :skip="false">`: ссылка «к
содержимому» остаётся в лейауте — она нужна и тогда, когда зону заполнили в панели). Заполненная в
панели зона заменяет шапку целиком. Блок `site-header`, который дал бы шапке, собранной в панели,
то же поведение, — отложен (§19).

Подвал — не виджет: поведения у него нет, это разметка темы.

Скрипт — в общем runtime, вместе с мобильным меню.

### 6.3 Выпадающая панель

`<x-webx-dropdown>` — панель, привязанная к кнопке. Основа для выпадашки телефонов (§12.2),
расписания (§12.3), переключателя языка (§13) и кнопки быстрой связи (§12.4).

```blade
<x-webx-dropdown open-on="hover" placement="bottom-start">
    <x-slot:trigger>0800-303-332</x-slot:trigger>
    …что угодно…
</x-webx-dropdown>
```

- **Разметка** — `<details>` с `<summary class="webx-dropdown__trigger">` (атрибуты слота едут на
  него) и `.webx-dropdown__panel`. Без JavaScript это и есть выпадашка: щелчок открывает панель
  под кнопкой, место задают локальные токены модификатора `--<placement>`. Со скриптом состояние
  по-прежнему `details.open`; `aria-expanded` и `aria-controls` скрипт ставит поверх.
- **Позиционирование:** `placement` — `bottom-start` | `bottom-end` | `bottom` | `top-*`. Панель —
  `popover="manual"` там, где браузер умеет (верхний слой: `overflow: hidden` и `z-index` предков
  не мешают), место считает **скрипт во всех браузерах** — `fixed` от прямоугольника кнопки: снизу
  нет места — вверх, вылезает за край — по другому краю кнопки (`is-flipped`), шире окна —
  прижата внутрь. CSS anchor positioning не используется: запасные позиции `position-try` не
  говорят, какую сторону выбрали, а один путь проще проверить.
- **Открытие:** `click` (по умолчанию) или `hover` — открытие через 120 мс, закрытие через 300 мс,
  общий с шапкой «коридор» (`behaviours/corridor.js`); на тач-экране и пером (`pointerType`)
  `hover` всегда становится `click`.
- **Клавиатура и ARIA:** Enter/пробел открывают, Esc закрывает и возвращает фокус, Tab из панели
  и щелчок мимо — закрывают.
- Одна открытая панель на странице: открытие другой закрывает первую. Напечатанная с `open`
  открывается скриптом сразу. Опечатка в `placement` или `open-on` — исключение.

Классы: `webx-dropdown`, `__trigger`, `__panel`, `--<placement>`, `is-open`, `is-flipped`. Токены:
`--webx-dropdown-offset`, `--webx-dropdown-min-width`; поверхность — `--site-color-surface`, тень —
`--site-shadow-md`, радиус — `--site-radius-md`.

### 6.4 Форма в окне

«Заказать звонок», «Получить консультацию», «Записаться» — самое частое окно на корпоративном сайте.
Диалог (§6) с формой `module-inbox` внутри; открыть его может любая кнопка:

```blade
<a href="#webx-form-callback">{{ __('theme::contacts.callback') }}</a>
<button type="button" data-webx-form="callback">…</button>
```

- **Открывающий** — `<a>` или `<button>` с `data-webx-form="<slug>"` **или ссылка на
  `#webx-form-<slug>`**: второе вписывается в пункт меню или кнопку блока в панели, без шаблона.
  Сервер находит открывающих в отрисованной странице сам (`FormDialogs`) — забытая заявка была бы
  кнопкой, которая молча ведёт в никуда; `Widgets::form('<slug>')` — для открывающего, которого
  сервер не печатает. `<form data-webx-form>` самого inbox — тот же атрибут на другом конце,
  открывающим не считается.
- **id окна — `webx-form-<slug>`, а не `<slug>`:** голый slug (`contact`) слишком часто уже id
  раздела лендинга. Каждый slug — один `<dialog id="webx-form-<slug>" class="webx-dialog
webx-form-dialog">` перед `</body>`, сколько бы кнопок на него ни вело. Нет `module-inbox`, нет
  формы или она выключена — окна нет, ссылка остаётся ссылкой.
- Форма печатается тем же `<x-webx-inbox::form placement="modal" />`, что везде (вьюха
  `webx-widgets::form-dialog`, перекрывается): заявка помнит место `modal` (`placement`, §11 спеки
  зон). Заголовок окна — название формы, липкий: длинная форма прокручивается под ним. Описание
  формы (inbox §5, `description`) — строкой под заголовком окна (`aria-describedby`), форма внутри
  его второй раз не печатает (`:description="false"`).
- **Шторка снизу на телефоне** — `data-webx-sheet` на любом открывающем этой формы,
  `Widgets::form('<slug>', sheet: true)` или `webx-widgets.form_dialog.sheet` для всех форм в окне:
  окно печатается с `webx-dialog--sheet` (§6). Окно одно на slug, поэтому хватает одного
  открывающего; `data-webx-sheet="false"` не просит. По умолчанию — карточка, как было.
- После отправки окно показывает «спасибо» формы **вместо полей** и кнопку «Закрыть» в фокусе, и
  закрывается по кнопке, а не само: человек должен успеть прочитать. Закрытое окно — снова свежая
  форма. Так ведёт себя любая `<x-webx-form>` внутри `<x-webx-dialog>` (§17.3).
- Кнопка может передать в форму скрытое значение: `data-webx-form-value-service="{{ $service->id }}"`
  — «записаться» со страницы услуги приходит в панель уже с услугой.
- Окна вставляются в `ResponsePrepared` (первый из двух, раз за ответ), а не в `RequestHandled`: к
  нему `StartSession` уже выбросил flash, и форма, отправленная без JavaScript, вернулась бы без
  «спасибо» и ошибок. Страница, вернувшаяся с ответом этой формы, печатает окно с `open`.
- Без JavaScript ссылка `#webx-form-<slug>` открывает окно через `:target`, а вернувшееся окно с
  `open` стоит поверх страницы.

Классы: `webx-form-dialog` (+ `webx-dialog--sheet`), `__header`, `__title`, `__description`, `__close`,
`__body`; форма внутри — `webx-form
webx-inbox-form webx-inbox-form--modal`, «спасибо» и «Закрыть» — её (§17.3).

## 7. Слайдер

**Swiper** (MIT), собранный модулями: в `dist/slider.js` только навигация, пагинация, a11y,
autoplay, эффект fade и миниатюры. Своих стилей Swiper не приносит: все его имена классов
переназначены на `webx-slider__*` и `is-*`, нужное ему написано в `slider.css` по правилу одного
класса (§5).

```blade
<x-webx-slider variant="cards" :per-view="['sm' => 1.2, 'md' => 2, 'lg' => 3]">
    @foreach ($services as $service)
        <x-webx-slide>…</x-webx-slide>
    @endforeach
</x-webx-slider>
```

| Вариант   | Для чего                                                    |
| --------- | ----------------------------------------------------------- |
| `cards`   | лента карточек: услуги, товары, отзывы, команда             |
| `hero`    | первый экран: по слайду на ширину, затухание, автопрокрутка |
| `gallery` | большая картинка и миниатюры: товар, объект, портфолио      |
| `logos`   | бегущая лента логотипов без стрелок                         |

Вариант — набор настроек (`Slider::VARIANTS`) и модификатор класса `webx-slider--<вариант>`; любой
проп (`arrows pagination loop autoplay continuous effect thumbs speed label id`) — поверх,
`options` — всё прочее, что берёт Swiper. Опечатка в варианте, эффекте, брейкпоинте или числе —
исключение.

- **«На вид» — по ширине контейнера, одним источником.** `per-view` — число или карта
  брейкпоинтов `sm` (от 0), `md` (640), `lg` (960), `xl` (1280) или ширина в пикселях. Компонент
  пишет `<style>` рядом: `--webx-slider-per-view` и `@container webx-slider` на каждый
  брейкпоинт. Это свойство задаёт ширину слайда ленте без JavaScript, а скрипт читает его обратно
  (`getComputedStyle`) при старте и в `ResizeObserver` на корне — у Swiper брейкпоинты по окну.
  Слайдер в узкой колонке ведёт себя как слайдер в узкой колонке. Тема меняет число тем же
  свойством на своём классе.
- **Без JS** — лента со `scroll-snap`, которую листают пальцем или прокруткой; стрелки, точки и
  пауза напечатаны `hidden`, миниатюры делает скрипт.
- **Контролы — под лентой** у всех вариантов; где им стоять — дело темы (`__controls`, `__prev`,
  `__next`).
- **Клавиатура — своя, не модуль Swiper:** тот слушает документ и двигает все слайдеры в окне;
  здесь стрелки, Home и End двигают тот, в котором фокус. Корень — `<section
aria-roledescription="carousel" aria-label>`, слайды — `role="group"` с именем «2 / 8».
- **Автопрокрутка** останавливается при наведении и фокусе внутри; у всего, что движется само
  (`hero`, `logos`, любой `autoplay`), — кнопка паузы 44px (WCAG 2.2.2), остановленное кнопкой не
  возобновляется уходом курсора; при `prefers-reduced-motion` не стартует.
- Непрерывной ленте с малым числом слайдов скрипт дописывает копии с `aria-hidden` и `inert`.
- Картинки слайдов за пределами первого экрана получают `loading="lazy"` (`Sliders` держит стек
  открытых слайдеров: слайд берёт свой номер из верхнего кадра).
- `gallery` вместе с лайтбоксом (§8) и зумом (§14) — галерея товара в каталоге (§10.6 спеки тем).

## 8. Лайтбокс

**PhotoSwipe** (MIT): увеличение, листание группы, жесты, масштаб щипком. Только ядро — модуль
`photoswipe/lightbox` грузил бы его вторым файлом; клик ловит и группу собирает скрипт пакета.

```blade
<x-webx-lightbox :image="$picture" group="product-{{ $product->id }}" />
<a href="{{ $image->url() }}" data-webx-lightbox="product-{{ $product->id }}"
   data-width="{{ $image->width }}" data-height="{{ $image->height }}">
    <img src="{{ $image->thumbUrl() }}" alt="…">
</a>
```

- **Компонент картинки — `<x-webx-lightbox>` этого пакета:** `:image` берёт значение поля медиа
  (`url`, `thumb`, `alt`, `width`, `height` — размеры записаны при загрузке) или объект с `url()`,
  `width`, `height` (фото каталога); пропы `src width height thumb alt` — то же руками, слот —
  вместо миниатюры. Без `url` — исключение.
- **Заявка по атрибуту.** Любая `<a … data-webx-lightbox>` в готовой странице — из блока, вьюхи
  модуля, партиала темы — заявляет лайтбокс (`Lightbox::wanted()` в `Widgets::finish()`), и перед
  `</body>` один раз печатается `<script type="application/json" id="webx-lightbox">` со словами и
  иконками цепочки.
- **Группы.** Одно значение — одна группа, пустое — картинка сама по себе. Порядок — порядок
  страницы, но слайды зацикленного слайдера — по своему номеру, а копии непрерывной ленты в группу
  не входят. Перетаскивание слайдера не открывает лайтбокс; закрытие на другой картинке ставит
  слайдер на её слайд.
- **Фокус** возвращается на ссылку **последней показанной** картинки, а не на ту, что открыла:
  пролистал до пятой — Tab идёт от пятой. Корень — `role="dialog"` с `aria-modal` и именем на языке
  страницы.
- **Размеры обязательны** (PhotoSwipe без них мигает): без них картинка загружается и меряется до
  открытия — работает, но это лишняя загрузка, и аудит это говорит (§15.2).
- **Вид** — стили PhotoSwipe как есть, перекраска — его custom properties (`--pswp-bg`, …) на
  `.webx-lightbox` из локальных токенов `--webx-lightbox-*`. Подложка непрозрачная, цвета фона
  сайта: просвечивающая страница мешала читать счётчик на телефоне.
- Без JS ссылка открывает картинку.

## 9. Согласие на cookie

### 9.1 Что показывает

Баннер на каждой странице, пока нет ответа на текущую версию: короткий текст, ссылка на политику,
три кнопки — **«Принять всё»**, **«Отклонить всё»**, **«Настроить»**. «Отклонить» — того же веса и
размера, что «Принять», это один элемент с одним классом `webx-consent__button`: в ЕС согласие,
вырванное неравными кнопками, согласием не считается. «Настроить» открывает диалог `#webx-consent`
поведения `dialog` (§6) с категориями-переключателями (`role="switch"`).

| Категория     | Что в ней                                     | По умолчанию         |
| ------------- | --------------------------------------------- | -------------------- |
| `necessary`   | сессия, CSRF, сам ответ о согласии            | всегда, не выключить |
| `preferences` | язык, тема, свёрнутые блоки                   | выкл                 |
| `statistics`  | счётчики, аналитика                           | выкл                 |
| `marketing`   | рекламные пиксели, ремаркетинг                | выкл                 |
| `media`       | видео (§10), карты (§11) и прочие встраивания | выкл                 |

Категорию, которой на сайте ничего не нужно, баннер не показывает. Какие показывать — выбранные в
настройках, а если не выбраны — те, о которых что-то на сайте просит: сервер ищет
`data-webx-consent="<категория>"` в отрисованной странице и помнит найденное в кэше; скрипт
показывает ещё и уже разрешённую (разрешённое должно быть видно, чтобы его забрать).

**Баннер печатает сам пакет**, а не компонент в лейауте: его не нужно ставить и нельзя забыть —
`Widgets::finish()` кладёт вьюху `webx-widgets::consent` перед `</body>` (перекрывается в слое
темы). Напечатан с `hidden`, показывает его скрипт: ответивший не видит мигания. **Без
JavaScript баннера нет** — без скрипта и стороннее не включается, спрашивать не о чем. Баннер — у
низа окна, не выше трети экрана: текст прокручивается внутри, кнопки остаются.

Ссылка «Настройки cookie» в подвале (`<x-webx-consent-link>`) снова открывает диалог — отозвать
согласие должно быть так же просто, как дать.

### 9.2 Где хранится

Cookie `webx_consent` (первая сторона, `Path=/`, `SameSite=Lax`, `Secure` на https, срок —
`lifetime` дней): `{"v": <версия политики>, "d": "<дата>", "c": [<категории>]}`, пишет скрипт.
Версия меняется в панели, когда меняется политика или список того, что ставится, — и баннер
спрашивает заново; ответ на другую версию — не ответ. Ответ читается и на сервере
(`WebxUi\Widgets\Consent`, фасад `Facades\Consent`: `has()`, `answered()`, `answer()`, `gpc()`),
поэтому заглушку вместо видео сервер рисует сразу, без мигания. Laravel шифрует cookie —
`webx_consent` внесён в `EncryptCookies::except`, иначе сервер не прочёл бы ответ скрипта.

Журнал согласий на сервере — не сделан (§19): ответ живёт в браузере посетителя.

### 9.3 Блокировка до согласия

Всё стороннее, что ставит cookie или передаёт данные посетителя, на странице лежит **выключенным** и
включается скриптом согласия (виджет `consent-blocked`, поэтому и в куске страницы, догруженном
позже):

```html
<script type="text/plain" data-webx-consent="statistics" src="https://…/counter.js"></script>
<iframe data-webx-consent="media" data-src="https://www.youtube-nocookie.com/embed/…"></iframe>
```

- `script type="text/plain"` браузер не выполняет; после согласия скрипт пересоздаётся с настоящим
  типом (`data-webx-type`, иначе JavaScript), внешние — с `async = false`, порядок как в разметке.
  `iframe` получает `src` из `data-src`.
- Отказ после согласия — перезагрузка страницы: выполненный скрипт не выгрузить.
- Компонент `<x-webx-consent category="statistics">…</x-webx-consent>` оборачивает любой
  произвольный код (вставку из настроек сайта): без согласия печатает его в `<template
data-webx-consent>`, который скрипт распакует, с согласием — как есть. Скрипты распакованного
  шаблона пересоздаются **со своим `type`** (JSON-LD остаётся данными, модуль — модулем) и **по
  очереди**: следующий вставляется после `load`/`error` предыдущего внешнего, так что встроенный
  `Widget.init()` после `<script src>` библиотеки ждёт её. Так же печатает коды `module-snippets`.
- **Google Consent Mode v2**: при включённом баннере `consent default` печатается в `<head>` до
  слоёв всегда, а не «если есть `gtag`» — default должен стоять раньше тега Google, а узнать о нём
  заранее нельзя. Если на странице есть маркер `Widgets::EARLY` (`<!--webx-widgets:early-->`, его
  печатает место `head` модуля `module-snippets` выше `@webxTheme`), default встаёт на него, а не к
  стилям. Сервер знает ответ из cookie: разрешённое — `granted`, остальное — `denied`.
  `consent update` после ответа — через `gtag` или в тот же `dataLayer`. Соответствие:
  `statistics` → `analytics_storage`; `marketing` → `ad_storage`, `ad_user_data`,
  `ad_personalization`; `preferences` → `functionality_storage`, `personalization_storage`.
- Сигнал Global Privacy Control (`Sec-GPC: 1` или `navigator.globalPrivacyControl`) — «Принять
  всё» не включает `marketing`, в диалоге строка «ваш браузер просит не отслеживать»; включить
  руками можно.
- API для скриптов сайта: `webx.consent.has('media')`, `.categories`, `.set([...])`, `.open()`;
  событие `webx:consent` на `document` с `{ categories }`.
- Баннер выключен — разрешено всё; скрипт всё равно грузится: он и включает ждущее.

### 9.4 Заглушка

Видео и карта до согласия на `media` — заглушка на месте, нарисованная сервером по cookie: превью
(постер ролика — своя картинка, не с серверов YouTube; карта — адрес), строка «Видео загрузится с
YouTube, который может ставить cookie» и две кнопки: «Загрузить» (только это встраивание, согласия
не даёт) и «Всегда загружать видео» (согласие на `media`: баннер получает ответ, событие
`webx:consent` снимает заглушки со страницы без перезагрузки). Корень несёт
`data-webx-consent="media"` — по нему баннер предлагает «Медиа». Без JS заглушка спрятана: остаются
ссылка на ролик и адрес со ссылкой на карту. Тексты — в словаре, на 10 языках.

### 9.5 В панели

Вкладка **«Cookie»** в `settings.index` — патчем экрана `resources/screens/settings.consent.json`
от `webx-ui/widgets`, если стоит `module-settings` (патч на незарегистрированный экран не
применяется — без модуля ничего не ломается):

- баннер вкл/выкл (выкл — только для сайта, которому он не нужен; аудит это заметит, §15.2);
- тексты баннера и категорий — `localized`, плейсхолдер — слово словаря пакета;
- ссылка на страницу политики — выбор страницы сайта (`wx-link`);
- версия политики и «Спросить всех заново» — переключатель, сохраняемый с вкладкой: у экранов нет
  узла-действия, поэтому слушатель `SettingsSaved` поднимает версию на единицу и выключает его;
- какие категории показывать — по умолчанию те, у которых на сайте что-то есть.

Ключи `consent.*` — обычные настройки, MCP: `settings_get` / `settings_set`. Непустая настройка
важнее конфига. Без `module-settings` — `config/webx-widgets.php` (`consent.enabled`, `version`,
`policy`, `categories`, `texts`, `lifetime`; `vendor:publish --tag=webx-widgets-config`).

## 10. Видео

```blade
<x-webx-video src="https://www.youtube.com/watch?v=…" :poster="$image" title="…" />
<x-webx-video :file="$media" :poster="$image" ratio="4/3" />
```

- **YouTube, Vimeo** — «фасад»: сервер печатает ссылку на страницу ролика с постером и кругом
  `play` (без JS это и есть ссылка на ролик), скрипт делает из неё кнопку «Play: <title>»; по клику
  — `iframe` (YouTube — `youtube-nocookie.com`, Vimeo — `dnt=1`), фокус в плеер. Только с согласием
  на `media` (§9.4). «Всегда загружать видео» играет нажатый ролик, остальные становятся фасадом и
  ждут своего клика: пять плееров разом — пять тяжёлых загрузок, о которых никто не просил.
- **Площадки — реестр `Video\VideoProviders`**: `VideoProvider` отвечает на «чей адрес» (`find()`),
  «плеер», «страница ролика» и «превью»; в пакете `YouTube` (watch, youtu.be, shorts, embed, live)
  и `Vimeo` (в том числе скрытые с хешем). Секунда старта из адреса сохраняется. Третью площадку сайт
  регистрирует своим провайдером. Адрес чужой площадки в `src` — исключение.
- **Постер всегда с сайта.** Заданный — как есть. Не заданный — превью ролика, которое сайт
  забирает к себе **один раз** (`Video\Posters`) в библиотеку медиа, папку «Video posters», картинкой
  `<площадка>-<id>`, через `RemoteFetcher` и конвейер библиотеки (WebP). Загрузка идёт после ответа
  (`terminating`): страница, первой показавшая ролик, печатает его без постера; неудача помнится
  сутки. Владелец может удалить постер — следующая страница заберёт снова. Без `module-media`
  постера нет вовсе, а не адрес `ytimg`: за ним посетитель тоже не ходит к площадке.
- **Свой файл** — `<video controls preload="none" playsinline>` с постером, без согласия и без
  скрипта: это первая сторона.
- Пропорция — `ratio` (`16/9`, `4:3`, `9 / 16`, число; по умолчанию 16/9) в `--webx-video-ratio`;
  постер, плеер и заглушка стоят внутри рамки, поэтому их смена ничего ниже не двигает.
- Без JS — ссылка на ролик с постером.

**Фон** — `<x-webx-video :file="$media" :poster="$image" variant="background">…текст…</x-webx-video>`
для первого экрана: тот же компонент и тот же `dist/video.js`. Только свой файл (`src` —
исключение): фон с YouTube означал бы сторонний запрос на каждом показе первого экрана.

- Без звука, по кругу, без элементов управления, `playsinline`; `autoplay` в разметке нет — без JS
  ничего не движется, остаётся постер.
- Играет, только пока рамка на экране, вкладка впереди и посетитель не против; никогда сам при
  `prefers-reduced-motion` и `navigator.connection.saveData` — тогда файл не запрашивается вовсе.
- Кнопка паузы есть всегда, пусть и неброская (WCAG 2.2.2). Пауза запоминается в `localStorage` для
  следующих страниц, «играть» — только на эту: тот, кто остановил движение, не должен
  останавливать его на каждой странице.
- Постер показывается до первого кадра (`playing`), поэтому первый экран не пустеет.
- Видео — декор: `aria-hidden`, текст поверх него — в разметке страницы (то, что тег оборачивает),
  а не в ролике. Корень — сетка в одну клетку: процент высоты от `aspect-ratio` не считается, а
  растянутый элемент сетки высоту знает.

Каталог показывает видео галереи товара этим компонентом (`module-catalog` требует
`webx-ui/widgets`): YouTube ждёт согласия и там. Реестр видео каталога остаётся — он про хранение;
`PlayedByWidgets` отдаёт его площадки реестру виджетов (`WEBX_UI_CATALOG_VIDEO.md` §3, §6).

## 11. Карта

**Leaflet** (BSD-2) с тайлами **OpenStreetMap** по умолчанию — без ключа и регистрации. Другие
провайдеры тайлов — записями конфига `webx-widgets.map.providers` (адрес с `{z}/{x}/{y}` и `{key}`,
`attribution`, `max_zoom`, `key`), выбор — `webx-widgets.map.provider`; в пакете `openstreetmap` и
`maptiler`. Неописанный провайдер или `{key}` без ключа — исключение: ошибка конфига сайта, а не
карта, которая молча просит тайлы без ключа. Привязки к стране нет: провайдер выбирает сайт.

```blade
<x-webx-map :lat="…" :lng="…" :zoom="15" marker="…" height="24rem" />
<x-webx-map from="settings" />
```

- `from="settings"` — главный адрес вкладки «Контакты» (§12.1): текст на языке страницы,
  координаты, введённая ссылка на карту. Адрес без координат — только место (`webx-map--place`:
  адрес и ссылка, без рамки, скрипта и согласия); нет адреса — ничего.
- Сервер печатает рамку высотой `--webx-map-height` с адресом, «Open in maps» (`webx-widgets.map.open`
  — шаблон ссылки, по умолчанию openstreetmap.org) и до согласия на `media` — строку и кнопки
  «Загрузить» / «Всегда загружать карты» (§9.4): тайлы — запросы к третьей стороне с IP
  посетителя. «Всегда» ставит все карты страницы — карта ничего не проигрывает и не шумит.
- **Карты без согласия — решение владельца.** Переключатель «Карты без согласия» вкладки «Cookie»
  (`consent.maps-at-once`) или `webx-widgets.map.consent = false` (`Consent::mapsWait()`): хватает
  любого из двух, переключатель только снимает ожидание — вкладка, сохранённая с ним выключенным,
  не отменяет конфиг. Тогда сервер не печатает строку и кнопки, на рамке нет `is-blocked` и
  `data-webx-consent="media"` (баннер не предлагает `media` ради карты; сохранение переключателя
  сбрасывает запомненный список категорий, конфигу — `cache:clear`), скрипту сказано
  `consent: false` — карта ставится сразу. Баннер и остальные категории не меняются; аудит
  `widgets.before_consent` такую карту ошибкой не считает, а одной заметкой (`notice`) перечисляет
  страницы с ней. `:consent="false"` / `true` у компонента решает за одну карту.
- С согласием карта ждёт, пока рамка подойдёт к экрану (`IntersectionObserver`): карта внизу
  длинной страницы не просит тайлов, до которых не долистали.
- **До клика или фокуса карта спит:** колесо прокручивает страницу (и на секунду показывает
  подсказку), на сенсорном экране палец листает страницу; клик или фокус будят (`is-active`),
  нажатие вне карты — снова сон. Кнопки +/− и клавиши — всегда.
- Атрибуция провайдера печатается **сервером, всегда**: до карты, поверх неё и без JS — контрол
  Leaflet есть только со скриптом.
- Стили Leaflet как есть, без его PNG (вырезаны при сборке — в `map.css` ни одного `url(`); булавка
  — своя SVG в `currentColor`. Холст — свой контекст наложения: кнопки Leaflet не встают поверх
  липкой шапки сайта.
- Без JS — адрес и ссылка на карту.

Google Maps не сделан (§19): это свой JavaScript API со своими правилами согласия, и условия Google
запрещают брать его тайлы в Leaflet. Ссылку «Open in maps» на Google сайт ставит конфигом.

## 12. Контакты

### 12.1 Данные: вкладка «Контакты» в настройках

Контакты — данные сайта, а не виджета: их читают виджеты, карта (`from="settings"`, §11),
`module-seo` (`Organization`/`LocalBusiness`) и шаблоны темы. Поэтому вкладка **«Контакты»** живёт в
самом `module-settings`, а не патчем виджетов. Видна она, когда контакты кто-то печатает: заявляют
тема (`settings` в манифесте), пакет (`extra.webx.settings`) или проект (`webx-settings.uses`) —
спека и гайд настроек.

| Ключ                        | Что                                                                                                           |
| --------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `contacts.phones`           | список: номер, подпись (`localized`), главный, мессенджеры на этом номере (WhatsApp, Telegram, Viber, Signal) |
| `contacts.emails`           | список: адрес, подпись                                                                                        |
| `contacts.addresses`        | список: адрес (`localized`), широта, долгота, ссылка на карту, главный                                        |
| `contacts.hours`            | строки «дни + открытие + закрытие» (как в Google Business); перерыв — две строки на день                      |
| `contacts.hours-exceptions` | даты: подпись, выходной или свои часы                                                                         |
| `contacts.timezone`         | часовой пояс часов и таймера (§14)                                                                            |
| `contacts.messengers`       | каналы, не привязанные к номеру: Telegram-бот, WhatsApp Business-ссылка                                       |
| `contacts.socials`          | список: сеть (из словаря иконок) и ссылка                                                                     |

- Номер хранится **как его ввели**; E.164 и `tel:` (RFC 3966, с `;ext=`) считаются при чтении
  (`PhoneNumber` на `libphonenumber-for-php-lite`): вторая копия — вещь, которую надо держать в ногу
  с первой. Проверка — «возможный», а не «действительный» номер: диапазоны стран меняются быстрее
  данных библиотеки.
- **Страна не угадывается:** язык — не страна, а неверная догадка — звонок чужому. Номер без кода
  — отказ при сохранении (`ContactsCheck`, в панели и в `settings_set`) с 422 под путём поля строки
  и словами, что добавить.
- Хелпер `contacts()` (`WebxUi\Settings\Contacts\Contacts`): `phones()`, `primaryPhone()`,
  `emails()`, `addresses()`, `primaryAddress()`, `hours()`, `messengers()`, `chats()`, `socials()`.
  Подписи — на текущем языке; что контактом не читается (номер без кода, ссылка `javascript:`),
  пропускается.
- `module-seo` берёт отсюда `telephone`, `email`, `address`, `sameAs`; с координатами или часами
  блок — `LocalBusiness` с `geo` и `openingHoursSpecification` (исключения ближайших 60 дней —
  `validFrom`/`validThrough`).
- Сайт, у которого уже были свои ключи `contacts.*` патчем экрана, переносит значения командой
  `webx:settings:contacts --from=<ключ>`; старые ключи читаются до переноса.
- MCP: `settings_get` / `settings_set` по тем же ключам; агент, которого попросили «поменяй телефон
  на сайте», меняет его в одном месте, а не в пяти шаблонах.

Виджеты контактов — свой файл `dist/contacts.js|css`; ничего не печатают, пока данных нет
(`shouldRender`), а без `module-settings` печатают только то, что им дали пропсами
(`Contacts\ContactsSource`).

### 12.2 Телефоны

```blade
<x-webx-phones />                                  {{-- главный, остальные в выпадашке --}}
<x-webx-phones callback="callback" />              {{-- и «Заказать звонок» под номером --}}
<x-webx-phones layout="list" />                    {{-- все номера списком: подвал, контакты --}}
```

- Главный номер — ссылкой `tel:` в E.164, показан как введён; если номеров больше одного — стрелка
  (отдельная кнопка: ссылке внутри `<summary>` жить нельзя) и выпадашка (§6.3) с остальными, у
  каждого его подпись.
- `callback` — slug формы: под номером ссылка на `#webx-form-<slug>` (§6.4).
- `compact` — иконка трубки, открывающая все номера; `placement` — выпадашки.
- У номера с мессенджерами — их иконки рядом, ведут в чат с этим номером (`wa.me`, `t.me/+…`,
  `viber://chat?number=…`, `signal.me`).

Классы: `webx-phones`, `__primary`, `__number`, `__label`, `__list`, `__callback`, `__messengers`.

### 12.3 Часы работы

```blade
<x-webx-hours />                 {{-- «Открыто до 19:00», расписание в выпадашке --}}
<x-webx-hours layout="table" />  {{-- неделя таблицей: страница контактов --}}
```

- Статус по часовому поясу сайта, а не посетителя: «Открыто до 19:00», «Закрыто, откроется завтра в
  9:00», «Сегодня выходной». Исключения по датам учитываются; закрытие раньше открытия — после
  полуночи; 00:00–00:00 — весь день (24/7 — без «до»).
- Минута дня — **по настенным часам** (`setTime`, а не `addMinutes` от полуночи), «завтра» — по
  дате: в ночь перевода часов в сутках 23 или 25 часов (`docs/pitfalls/laravel-and-php.md`).
- Время и дни пишет сервер на языке страницы (`isoFormat('LT')`: «7:00 PM» в `en`, «19:00» в `de`)
  — как `useDates()` в панели, без `toLocaleString` по браузеру. `data-webx-hours` несёт часы, пояс
  и **все** слова: скрипт пересчитывает статус по `Intl.DateTimeFormat` с `timeZone` сайта сразу и
  на каждой новой минуте (страница может лежать в кеше часами), подставляет готовое и ничего не
  форматирует сам.
- Подряд идущие одинаковые дни сворачиваются: «Пн–Пт 9:00–19:00».
- Где падеж дня недели не встаёт в предложение, язык пишет «откроется: понедельник, 9:00».

Классы: `webx-hours`, `__status`, `is-open`, `is-closed`, `__table`, `__day`, `is-today`.

### 12.4 Мессенджеры и быстрая связь

Два виджета на одних данных (`contacts.phones[].messengers`, `contacts.messengers`):

- **`<x-webx-contact-button corner form :items>`** — плавающая кнопка в углу, раскрывается в
  список (выпадашка §6.3): мессенджеры, звонок, форма в окне (§6.4). Не перекрывает баннер согласия
  (§9): пока баннер на экране, кнопка над ним (`--webx-contact-lift`).
- **`<x-webx-contact-bar form :breakpoint>`** — нижняя полоса на телефоне: «Позвонить», «Написать»,
  «Заявка». Без скрипта: корень в потоке в конце страницы — контейнер, в нём распорка высотой полосы
  (подвал не закрыт) и сама полоса `fixed`; `@container (min-width: breakpoint)` прячет обе.
  Учитывает `safe-area-inset-bottom`.

Обычно на сайте стоит одно из двух; оба на одной странице — замечание аудита `widgets.contact_both`
(§15.2). `theme-default` ставит кнопку; сайт без неё выключает её ключом
`webx-widgets.contact_button => false` — кнопки нет в HTML, где бы она ни стояла, и скрипт контактов
ради неё не подключается.

Классы: `webx-contact-button`, `__toggle`, `__list`, `__item`, `--<канал>`; `webx-contact-bar`,
`__item`.

### 12.5 Соцсети

`<x-webx-socials />` — ряд иконок из `contacts.socials`. Иконки сетей и мессенджеров — вьюхи пакета
(Simple Icons, CC0) и свои `phone`, `chat`, `mail`, `clock`, `link`, `form`, `close`, `globe`,
`zoom`, `search`; `<x-webx-icon name>` печатает любую, тема заменяет любую своей (§5). Ссылки —
`rel="noopener"`, с подписью для скринридера.

## 13. Переключатель языка

`<x-webx-language-switcher layout codes placement label fallback-label />` — для мультиязычного
сайта; на одноязычном, без `routing`/`localization` и при стратегии не `prefix` не печатает ничего.

- Ссылки ведут на **ту же страницу** на другом языке (`LanguageLinks`) — адреса из реестра
  `routing`, того же источника, что `hreflang`, но без SEO: закрытая от индекса страница
  переключается — читатель не поисковик. Нет перевода у страницы, тип которой показывает её без
  перевода (ROUTING §8.7), — ведёт на **ту же страницу** под префиксом языка
  (`Untranslated::path()`: интерфейс на выбранном языке, содержимое на языке по умолчанию,
  `noindex`), без `is-fallback`. Нет перевода у остальных, сущность скрыта в языке, 404 — ведёт на
  главную того языка и помечает это (`is-fallback` и `title` на **языке ссылки**). Адрес вне реестра
  (свой маршрут модуля) — тот же путь под префиксом каждого языка.
- Вид: `dropdown` (§6.3, глобус и текущий язык) или `list` в ряд; подпись — название языка на нём
  самом из `locales.native_name` («Deutsch», «Polski»), `codes` добавляет код. Флагов нет: флаг —
  страна, а не язык. `x-default` нет — это слово `hreflang` для поисковика.
- `hreflang` и `lang` у каждой ссылки; текущий язык — `aria-current`.
- Своего скрипта нет — выпадашка runtime'а; свой файл — только `dist/language-switcher.css`.
- В мобильном меню `theme-default` он внизу — это копия `actions` шапки (§6.2); тема, которой нужен
  верх, кладёт `layout="list"` в `top` своего меню. `LanguageLinks::current()` — те же ссылки для
  своей разметки.

Классы: `webx-language-switcher`, `__current`, `__list`, `__link`, `is-current`, `is-fallback`.

Плюс те, что нужны почти каждому сайту и каждый раз делаются заново:

| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `<x-webx-toc>`        | оглавление длинной страницы: собирает `h2`/`h3` из указанного контейнера, ставит им `id`, подсвечивает текущий раздел; на широком контейнере — липкое сбоку (под `--webx-header-height`), на узком — сворачивается в полосу с панелью над текстом. Политика, услуга, статья |
| `<x-webx-load-more>`  | «Показать ещё» поверх обычной пагинации Laravel: догружает следующую страницу, дописывает элементы в список, обновляет адрес (`?page=3`) и ссылку «вперёд». Без JS и для поисковиков — обычная пагинация; фокус после догрузки — на первом новом элементе                   |
| `<x-webx-pagination>` | ссылки страниц списка: «назад», номера вокруг текущей с первой и последней, «вперёд»; без скрипта. Ими печатает свои ссылки «показать ещё»                                                                                                                                  |

| инерционная прокрутка | `data-webx-smooth-scroll` на `<html>`/`<body>` лейаута — инерционная прокрутка колесом (Lenis в своём файле), подробности ниже                                                                                                                                              |

Правила, которые держатся у всех:

- **Таблицы в прозе и оглавление делает сервер в `Widgets::finish()`, а не каждый модуль и не
  скрипт.** Прозу и заголовки печатает кто угодно (блоки, FAQ, рецепты, шаблон темы) и часто после
  оглавления; только готовая страница знает их все. Ссылки оглавления тогда работают без JS.
  Обёртку получает **таблица без класса** — санитайзер панели снимает с `<table>` все атрибуты,
  значит таблица редактора всегда без класса, а таблица шаблона (`webx-hours__table`) — с классом.
  `<caption>` выносится над рамкой и называет таблицу через `aria-labelledby`. Колонки держатся не
  уже `--webx-table-column-min` (7rem), иначе в узкой колонке ряды становятся втрое выше.
  `id` заголовка — из слов (`Str::slug` по языку страницы), уникальный на странице; данный
  редактором остаётся. Следствие: страница без `@webxTheme` и предпросмотр блока в панели (JSON)
  остаются без обёртки и без списка.
- **Анимация не прячет видимое:** появление прячет и счётчик считает **только то, что ниже экрана**
  в момент монтирования — видимое мигнуло бы итогом и упало в ноль. Скрытое состояние — без
  перехода, показанное — с ним (`docs/pitfalls/layout-and-browser.md`). `beforeprint` показывает
  всё.
- **«Наверх»** встаёт над баннером согласия, нижней полосой и кнопкой быстрой связи своего угла
  (меряет, докуда они достают, в том числе после `transitionend`); по нажатию фокус — на `<body>`,
  следующий Tab — «К содержимому». «Наверх» и «поделиться» в лейауте `theme-default` не стоят:
  каждый грузит свой файл, ставит тот, кому нужен.
- **«Поделиться»** — адреса «поделиться» самих сетей в новой вкладке (Facebook, X, LinkedIn,
  Telegram, WhatsApp, почта и «Copy link» по умолчанию; Viber, Reddit, Pinterest, Threads, Bluesky,
  VK по списку), `url` — абсолютный. На телефоне (`navigator.share` и `pointer: coarse`) ряд
  прячется за одной кнопкой системного меню.
- **Счётчик** печатает итог по языку страницы (`NumberFormatter`), в конце счёта — ровно текст
  сервера; пока считает — цифры `aria-hidden`, рядом итог для скринридера, ширина закреплена.
- **Таймер** — по поясу сайта (`contacts.timezone`, иначе `app.timezone`); `to` — стенное время в
  нём или момент со смещением. Тикает от часов, а не счётчиком: страница из кеша сразу верна.
  Конец — текст `ended` или уход вместе с ближайшим `[data-webx-countdown-scope]`; закончился до
  ответа и сказать нечего — ничего. **Без JS видна дата** («Ends on 31 December 2026 18:00»): цифры
  на момент ответа из кеша неправда.
- **«До и после»** — граница — `<input type="range">` (клавиатура и скринридер без строчки
  скрипта; скрипт добавляет шаги, мышь и палец — палец двигает, только когда пошёл вбок, вертикаль
  остаётся странице). Рамка — форма первой картинки с размерами, сетка в одну клетку; «после»
  обрезано `clip-path`. Слева направо на любом языке. **Без JS — `@media (scripting: none)`**, а не
  `html:not(.webx-js)`: класс ставится после разбора, и рамка на мгновение была бы двумя картинками
  рядом — скачок на каждой странице.
- **Оглавление** — со слотом: от 48rem текст и список сбоку (`side`), список липкий; уже — список
  над текстом и сворачивается в полосу под шапкой. Выпадашка — своя, а не `<x-webx-dropdown>`: в
  широком контейнере тот же список стоит открытым, рисовать его дважды — дубли ссылок; сворачивает
  CSS контейнера. Без JS — открытый список над текстом, не липкий. `fold="never"` — открыт всегда.
- **«Показать ещё» берёт HTML следующей страницы, а не JSON:** элемент списка рисует модуль своей
  вьюхой, и тема её перекрывает; JSON потребовал бы у каждого модуля конечную точку и второй шаблон
  карточки. Скрипт запрашивает обычную следующую страницу, находит корень с тем же
  `data-webx-load-more` и переносит детей списка (новые монтирует `webx.mount`). Адрес —
  `replaceState`, а не `pushState`: «Назад» уводит со списка, перезагрузка открывает последнюю
  загруженную страницу. `pages="covered"` — кнопка закрывает ссылки, `shown` — ссылки под кнопкой.
  Кнопку показывает и ссылки закрывает скрипт: сломанный скрипт не оставит список без ссылок.
- **Пагинация** — первая страница — адрес списка, а не `?page=1` (иначе краулер встречает каждый
  список дважды); в узком контейнере (до 30rem) — компактный ряд: первая, текущая, последняя и
  стрелки. Сервер печатает оба ряда одним списком, ряд выбирает CSS.
- **Полоса объявления** — содержимое — первый баннер места `notice` из `module-banners` (место слов
  без картинки — исключение из решения 8 спеки баннеров), иначе слот. Закрытие помнит версию (хеш
  слов) в `localStorage`; **без мигания** — строчка в `<head>`, которую пишет `finish()`, прячет
  закрытые версии до отрисовки тела. Не cookie: она ехала бы на сервер и делала страницу разной
  для разных посетителей. Согласия не спрашивает — посетитель попросил сам. `theme-default` ставит
  полосу после «К содержимому» и перед шапкой, в потоке.

- **Инерционная прокрутка** (`data-webx-smooth-scroll` на `<html>` или `<body>` лейаута темы, по
  умолчанию выключена). Щелчок колеса — один растянутый проезд с затуханием (Lenis; `duration` 1.1 с,
  `1-(1-t)^4`, `wheelMultiplier` 0.9 — как в макетах), якорь — 1.4 с, in-out. Включение — атрибутом,
  а не настройкой панели: это решение дизайна темы, как и её CSS; сервер видит атрибут в
  `claimAttributes()` и подключает файл виджета — без атрибута Lenis не грузится. Параметры —
  атрибуты `-duration`, `-easing`, `-wheel`, `-anchor-duration` или токены
  `--webx-smooth-scroll-*`. Не включается при `prefers-reduced-motion` и без
  `(hover: hover) and (pointer: fine)` (палец — своя инерция системы); без JS и в этих случаях —
  нативная прокрутка и `scroll-behavior: smooth` темы для якорей (класс `webx-smooth-scroll` на
  `<html>` снимает его, пока работает Lenis; селектор по атрибуту виджету нельзя — правило DistTest
  «одна плоская `.webx-*`»). Пауза — пока на `<html>` `webx-scroll-locked` (диалог,
  мобильное меню); своё правило `.lenis-stopped { overflow: clip }` не берём — `clip` теряет
  `scrollbar-gutter`, и страница прыгала бы на ширину полосы. Колесо внутри прокручиваемого
  (`allowNestedScroll`), `dialog`, лайтбокса, карты, панелей и `[data-webx-scroll-native]` —
  нативное. Якоря на текущей странице — свой обработчик, а не `anchors` Lenis: адрес получает
  `#id` (`pushState`, «Назад» возвращает), клик с клавиатуры (`detail === 0`) — прыжок браузера
  с переносом фокуса; отступ — `scroll-padding-top` шапки и `scroll-margin-top` цели. Перед
  проездом `reset()`: прыжок, о котором `scroll` ещё не сообщил, сместил бы цель.

**Зум картинки** (`<x-webx-zoom :image src large mode scale group alt label :eager>`):

- **Картинка — ссылка на оригинал, которая открывает лайтбокс** (§8): это путь клавиатуры и
  скринридера, без JS ссылка открывает файл. Отдельной кнопки «Увеличить» нет — значок лупы в углу
  только подсказка.
- **Десктоп:** `mode="inner"` — картинка увеличивается в своей рамке, точка под курсором остаётся
  под ним; `mode="side"` — «лупа» и панель рядом (в `<body>`, `fixed` — `overflow` слайдера её не
  режет). Место решает ближайший контейнер (кроме своих `webx-*`), а не окно: не помещается ≥ 60%
  ширины картинки — `inner`. Панель всегда справа (§19). Кратность — `scale` (2,5).
- **Окно по контейнеру:** `frame="container"` (`data-zoom-frame="container"`) —
  окно `inner` не коробка фото, а весь `.webx-zoom` со своим скруглением: для фото в кадре другой
  пропорции (портрет в 4:3 галереи). Копия — коробка фото × `scale`, точка под курсором под ним,
  пока пускают края: длиннее окна по оси — упор в край, окно всегда покрыто; короче — по центру на
  `--webx-zoom-bg`. Пальцы и `side` — как были. По умолчанию `picture`, атрибута нет. Каталог —
  `images.zoom_frame`.
- **Телефон:** два пальца — зум и перемещение; один палец, пока картинка не увеличена, листает
  страницу и слайдер; двойное касание — 2× и обратно; одиночный тап открывает лайтбокс через 300 мс.
- Оригинал грузится при первом наведении или касании; `reduced-motion` — без плавности.
- `data-webx-zoom` на элементе с картинкой и ссылкой — то же без компонента (слайдер `gallery`,
  галерея товара каталога). Меньшая копия для показа есть у каталога (`thumbUrl()`); у картинок
  библиотеки показывается оригинал.

## 15. Блоки и аудит

### 15.1 Предложенные блоки

`resources/blocks/*.json` — документы `webx:blocks:export`, предлагаются `BlockOffers` под именем
`widgets`, если есть `module-blocks` и `module-media` (все стоят на полях библиотеки). Ставит их
`webx:blocks:offered --install --module=widgets` (`webx:setup` только печатает её); дальше тип принадлежит сайту, тип
с тем же slug в цепочке темы важнее (§10.3 спеки тем). Слова типов — английские, группа `media`.
Стили блоков — на `em`, `currentColor` и прозрачности, без `--site-*`: блок предлагается и сайту без
темы. Значения `default` читаются, как панель рисует, — блок, сохранённый до появления поля, ведёт
себя как новый. Чего показать нечем (удалённая картинка, пустая ссылка, адрес неизвестной площадки),
блок не печатает, а не роняет страницу.

| Блок        | Поля                                                                                                        | Внутри                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `gallery`   | заголовок, картинки (подпись — `title` картинки), вид (сетка / слайдер), колонки, увеличение, зум слайдера  | сетка или слайдер `gallery` + лайтбокс, зум |
| `logos`     | заголовок, повторитель: имя, логотип, ссылка                                                                | слайдер `logos`                             |
| `video`     | заголовок, источник (переключатель ссылка / файл), ссылка, файл, постер, подпись, форма (16:9 4:3 1:1 9:16) | `<x-webx-video>`                            |
| `map`       | заголовок, источник (контакты / координаты), широта, долгота, адрес, масштаб, высота (три ступени)          | `<x-webx-map>`                              |
| `counters`  | заголовок, повторитель: число (как пишет редактор), до, после, подпись                                      | `<x-webx-counter>`                          |
| `countdown` | заголовок, текст, дата, время (стенное время сайта), в конце — текст или спрятать                           | `<x-webx-countdown>`                        |
| `compare`   | заголовок, до, после, их подписи, где граница, подпись                                                      | `<x-webx-compare>`                          |
| `toc`       | заголовок, источник (вся страница / свой текст), текст, сторона, глубина                                    | `<x-webx-toc>`                              |

Решения, которые держатся:

- **Переключатель вместо двух соперничающих полей** (`video`, `map`, `toc`): с двумя заполненными
  непонятно, что главнее; переключатель показывает одно поле и говорит шаблону, какое читать.
- `logos` — повторитель, а не `wx-gallery`: ссылка у каждого логотипа своя.
- Дата и время `countdown` — два поля, а не `wx-date-time-picker`: тот хранит момент со смещением
  **редактора**, а распродаже нужно стенное время сайта.
- Зум (`magnify`) — только у слайдера и только с включённым лайтбоксом: ячейка сетки мала, а без
  ссылки у клавиатуры не было бы пути.
- Блок `toc` соседей не обёртывает: «рядом с текстом» — только со своим текстом; липкое сбоку для
  страницы целиком — дело шаблона темы.
- Описание типа — не длиннее 255 символов: иначе `webx:blocks:offered` отказывает в установке.

### 15.2 Аудит

Проверки для `module-audit` по снимку страницы. Аудит не хранит HTML, поэтому у `module-audit` шов
`Contracts\AuditPageReader` и реестр `Crawl\PageReaders`: `WidgetsPageReader` пакета кладёт факты
страницы под `widgets`, проверки читают их на разборе. Регистрируются, только если `module-audit`
стоит. Слова — `lang/<10>/checks.php`, `audit.php`, `fixes.php`.

| Проверка                 | Вес            | Что                                                                                         |
| ------------------------ | -------------- | ------------------------------------------------------------------------------------------- |
| `widgets.before_consent` | ошибка         | известный плеер, карта, счётчик, пиксель или кнопки сервисов «поделиться» грузятся сразу    |
| `widgets.banner_off`     | предупреждение | баннер выключен, а стороннее на сайте есть; одна на сайт                                    |
| `widgets.lightbox_size`  | предупреждение | ссылка лайтбокса без размеров                                                               |
| `widgets.slider_pause`   | предупреждение | движущийся слайдер без кнопки паузы (вьюха перекрыта и кнопку потеряла)                     |
| `widgets.video_pause`    | предупреждение | видео-фон без кнопки паузы                                                                  |
| `widgets.compare_range`  | предупреждение | «до и после» без `input[type=range]`                                                        |
| `widgets.toc_target`     | предупреждение | ссылка оглавления на `#id`, которого на странице нет                                        |
| `widgets.load_more_link` | предупреждение | «показать ещё» без ссылки на следующую страницу                                             |
| `widgets.zoom_link`      | предупреждение | `[data-webx-zoom]` без ссылки                                                               |
| `widgets.form_script`    | предупреждение | `<x-webx-form>` на странице без `form.js` (нет `@webxTheme`/`@webxWidgets` или не выложено) |
| `widgets.counter_number` | замечание      | в разметке счётчика нет его числа                                                           |
| `widgets.contact_both`   | замечание      | кнопка быстрой связи и нижняя полоса на одной странице                                      |

Проверки сверх первых четырёх — того же рода: обещания §10, §14 и §17, которые перекрытие вьюхи
может молча потерять.

- **Известные третьи стороны — `Audit\ThirdParty`:** хост (с поддоменами) или хост с путём →
  категория (YouTube, Vimeo, Google Maps, OSM — `media`; Tag Manager, Analytics, Метрика, Hotjar,
  Clarity — `statistics`; пиксели, DoubleClick, Ads, LinkedIn, TikTok, ShareThis/AddToAny —
  `marketing`). Свои — `webx-widgets.audit.third-party`.
- **`widgets.before_consent` молчит, пока баннер выключен** — тогда ничего не ждёт по выбору сайта,
  и это одна находка `banner_off`, а не по одной на страницу. `banner_off` — предупреждение, а не
  ошибка: §2.4 разрешает выключить сайту, которому согласие не нужно, — он скрывает находку с
  причиной.
- **Исправление `widgets.wait-for-consent`** переписывает код там, где он хранится (поле контента
  любого `AuditContentSource` — текст блока, тело страницы, поле модуля), в ждущий вид §9.3. Для
  того, что печатает шаблон, не предлагается — текст находки говорит обернуть в `<x-webx-consent>`
  или взять блок `video`/`map` (наши блоки `iframe` до согласия не печатают никогда).
- **Исправление `widgets.banner-on`** включает переключатель вкладки «Cookie» (он главнее конфига);
  без `module-settings` не предлагается.
- Предупреждение об обоих виджетах быстрой связи — проверка аудита, а не `webx:theme:check`: «оба на
  одной странице» — свойство страницы, которое видит снимок обхода.
- Краулер не собирает диалоги «поделиться» сетей (`PageParser::SHARE`), а `mailto:?subject=…` не
  считается «`mailto:` без адреса» — иначе каждая страница с рядом «поделиться» давала бы битые
  ссылки.

## 16. Тесты

- PHP: компоненты рисуются с нужными классами и `data-*`; `Widgets::need` печатает только заявленное;
  заглушка вместо видео и карты без согласия и `iframe` с согласием (сервер читает cookie);
  `Consent` — версия политики, GPC.
- PHP: нормализация телефонов в E.164 и отказ без кода страны; статус часов работы на границах
  интервалов, в выходной, в исключение, в другом часовом поясе и в ночь перевода часов; переключатель
  языка ведёт на ту же страницу (без перевода — ту же страницу под префиксом, ROUTING §8.7) и
  помечает `is-fallback` только там, где ведёт на главную; форма в окне печатается один раз на slug.
- `DistTest`: `dist/` собран из исходников, список файлов, бюджеты (§4), правило токенов и одного
  класса (§5), паритет словарей.
- vitest (`php/packages/*/resources/js/**/*.test.js`): поведения — клавиатура, фокус, ARIA;
  выпадающая панель — переворот у края, одна открытая; согласие — включение `text/plain`-скриптов
  и `data-src`, Consent Mode, событие; размонтирование освобождает Swiper/PhotoSwipe/Leaflet.
- Браузер (не jsdom), `pnpm test:starter` — Playwright по стартовому сайту (`tests/starter/`,
  локально, не в CI): мобильное меню на 375px — тело прокручивается, страница под ним нет, низ виден
  целиком, фокус не уходит за панель; шапка с `collapse="auto"` прячет меню ровно тогда, когда пункты
  не помещаются, а переход по якорю под липкой шапкой оставляет заголовок видимым; слайдер в узкой
  колонке и на всю ширину — число видимых слайдов по ширине контейнера; без JS — лента
  прокручивается; лайтбокс на телефоне; баннер на 360px не закрывает больше трети экрана, кнопки
  одного размера, контраст в каждом пресете; до согласия — ни одного запроса не к сайту (всё чужое
  подменено `context.route`, прогон от сети не зависит).

### 16.1 Где проверяем

На стартовом сайте и его витрине — спека тем, §18.1–§18.5: каждый виджет получает страницу витрины
«Kitchen sink › …» со всеми вариантами и крайними случаями, браузерные замеры выше входят в
локальный прогон Playwright (`pnpm test:starter`), жесты и iOS — на копии стартового сайта на
хомлабе. Этап виджетов без страницы витрины и без своих замеров в прогоне не закрыт. Чего
настоящий блок показать не может (узкая колонка 20rem, ссылки руками), витрина держит на демо-типах
`theme-default/demo/blocks/showcase-*.json`; картинки и ролик витрины — в `demo/media/` темы, сеются
демо медиа и называются в страницах `demo:<имя>`.

## 17. Формы: поля и оболочка — здесь, заявки — в `module-inbox`

Форм на сайте несколько: заявка, вход и личный кабинет (с пользователями сайта), оформление заказа
(с магазином), отклик на вакансию, подписка. Каждая форма — это поля, их вид, ошибки, проверка и
отправка. Если это общее не вынести, каждый модуль сверстает свои поля и свою отправку, и тема будет
перекрашивать три системы. Это та же болезнь, от которой лечит §6 спеки тем: «у каждого стиля одно
место». Гайд — `apps/docs/guide/forms.md` (с примерами формы входа, шага заказа, формы inbox и
поиска каталога).

### 17.1 Граница

Единая — система полей и оболочка формы, а не конструктор «любая форма из схемы». Заявка, вход и
заказ похожи снаружи и разные внутри:

| Чьё                                | Что                                                                                                                           |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **widgets** — поля                 | разметка поля (подпись, подсказка, ошибка, обязательность), вид на токенах, доступность, `old()` и `$errors` по имени поля    |
| **widgets** — оболочка             | CSRF и подмена метода, отправка без перезагрузки, ошибки 422 по полям, двойная отправка, ответ по соглашению (§17.4), события |
| **widgets** — проверка             | в браузере теми же правилами, что на сервере, и теми же словами (§17.5); маска телефона; загрузка файлов                      |
| **владелец формы** (inbox, модули) | куда отправляется, правила на сервере (`FormRequest` или массив), что делать с данными                                        |
| **inbox**                          | конструктор форм в панели, приём, хранение заявок, антиспам и капча, письма; рисует свои формы полями и оболочкой виджетов    |
| **модули входа, кабинета, заказа** | свои формы в Blade из тех же полей; лимит попыток и сессия — у входа; шаги, корзина, оплата — у заказа                        |

Конструктор «любая форма из схемы» для заказа — ловушка: шаги, пересчёт суммы и оплата в схему не
ложатся. Схема остаётся у inbox (форма, которую владелец собирает в панели) и строится на тех же
полях.

### 17.2 Поля

```blade
<x-webx-field type="email" name="email" :label="__('auth.email')" autocomplete="email" required />
<x-webx-field type="password" name="password" :label="__('auth.password')" autocomplete="current-password" required />
<x-webx-field type="select" name="delivery" :label="…" :choices="$methods" />
```

- **Типы** (`Field::TYPES`): `text`, `email`, `tel`, `url`, `password` (с кнопкой «показать»),
  `number`, `textarea`, `select`, `radio` (группа), `checkbox` (группа с `:choices` или одна
  галочка без них), `consent`, `date`, `file`, `hidden` — одиннадцать типов inbox и сверху.
  `:choices` — `value => label` или список `['value', 'label', 'disabled']`; `select` и `radio` без
  вариантов, неизвестный тип и пустое имя — исключение.
- **Одна разметка — рамка и вьюха типа:** `components/field.blade.php` (подпись, подсказка, ошибка)
  и `components/field/<type>.blade.php` (сам элемент). Всё, что элементу ставит поле (`required`,
  ARIA, подсказки клавиатуре, правила), — одна строка `{{ $control($attributes) }}`: тема
  перекрывает один тип и не теряет ни ARIA, ни `autocomplete`. `class` уходит на поле, любой другой
  атрибут — на элемент (у группы — на `<fieldset>`).
- **Классы:** `webx-field`, `--<type>`, `__label`, `__required`, `__optional`, `__control`,
  `__hint`, `__error`, `__choices`, `__choice`, …; состояния `is-invalid`, `is-required`,
  `is-disabled` — на корне, у элемента свои (`aria-invalid`, `:disabled`). Корень несёт
  `data-webx-field="<ключ валидатора>"` — по нему 422 находит поле.
- **Ошибка есть всегда** — пустая и `hidden`, пока сказать нечего, и элемент описан ею всегда
  (`aria-describedby`): скрипт формы пишет в готовое место. С ошибкой — `aria-invalid="true"` у
  элемента (у группы — у каждого; на `<fieldset>` он не читается); группа — `<fieldset>` с
  `<legend>`. Обязательность — `required` и `*` с `aria-hidden`; у группы галочек `required` нет —
  браузер потребовал бы каждую.
- **Laravel сам по себе:** значение — `old($key)`, ошибка — `$errors->getBag($bag)->first($key)`;
  имя с точкой (`fields.email`, `items.0.qty`) пишется скобками (`fields[email]`), ключ ищется по
  точкам (`Field::keyOf()`, `Field::nameOf()`). **Вернувшаяся форма отвечает целиком:** снятая
  посетителем галочка не встаёт обратно из умолчания страницы; пароль и файл не возвращаются никогда.
  Поле внутри `<x-webx-form>` берёт старый ввод и ошибки, только если вернулась **его** форма
  (`_webx_form`): заявка, отказанная в теле страницы, не красит подписку в подвале.
- **`autocomplete`, `inputmode`** — пропсами, с умолчанием по типу (`email` → `email`/`email`,
  `password` → `current-password`, `number` → `numeric`/`decimal` по шагу); `false` — ничего. У
  `enterkeyhint` умолчания нет: поле не знает, последнее ли оно в форме. Для входа и заказа это не
  мелочь: менеджер паролей и автозаполнение адреса работают только по ним.
- **«Необязательно»** — по пропу `optional`, а не само: слово у каждого необязательного зашумило бы
  форму, где их большинство.
- **Вид** — каркас на `--site-*` и `--webx-field-*` (§5): поле, вариант и кнопки не ниже 44px,
  видимый `:focus-visible`, ошибка цветом `--site-color-danger` и словом, а не только цветом; своя
  стрелка списка на `currentColor`. Варианты `inline` в ряд — только если поле ≥ 30rem
  (`@container`). Тема перекрашивает по классам или перекрывает вьюху `field.<тип>`.
- **Файл.** Кнопка браузера говорит на языке браузера, поэтому со скриптом элемент лежит невидимым
  поверх своей кнопки и строки на языке страницы; без скрипта — элемент браузера.
- **Слова поля** («показать пароль», «необязательно», «выбрать файл») — `widgets.field.*` на
  десяти языках, любое перекрывается пропсом. `dist/field.js` грузится с любым полем (≈0,5 КБ): заявка
  по типу внутри поля была бы второй дверью, которую тема при перекрытии вьюхи могла бы потерять.

### 17.3 Оболочка формы

```blade
<x-webx-form :action="route('login')" method="post" class="auth-form">
    …поля…
    <x-webx-form.submit>{{ __('auth.sign_in') }}</x-webx-form.submit>
</x-webx-form>
```

- **CSRF и метод.** `@csrf` и `@method` печатаются сами, и скрытое `_webx_form` — какая из форм
  страницы отправлена (без него вернувшаяся страница печатала бы ответ и ошибки во всех). Страницы
  сайта кэшируются вместе с токеном (решение 8 спеки inbox), поэтому скрипт шлёт `X-XSRF-TOKEN` из
  cookie, а `_token` из тела убирает; на 419 берёт свежий токен (`GET {webx-widgets.path}/csrf` —
  маршрут пакета, 204, `no-store`) и повторяет запрос **один** раз. `:csrf="false"` — для двери,
  которая защищена иначе, как приём inbox (Origin, honeypot, лимит). `method="get"` — обычная форма
  поиска или фильтра: ни токена, ни отправки на месте. Поле файла делает форму multipart.
- **Без JavaScript работает.** Обычный POST, ответ — redirect с flash `webx-form`, ошибки — через
  сессию; ошибки, которых не показало ни одно поле, — в общем месте отправленной формы. Отправка на
  месте — улучшение поверх, а не требование (§2.7).
- **С JavaScript:** submit перехватывается, `fetch` с `Accept: application/json`; на время
  отправки у формы `is-sending` и `aria-busy`, кнопки — `aria-disabled` (не `disabled`: тот роняет
  фокус нажавшего на `<body>`), повторный submit гасится; файлы уходят `XMLHttpRequest` с
  прогрессом.
- **Ошибки 422** (формат Laravel как есть, `{ message, errors }`) раскладываются по полям (ключ,
  потом без последнего сегмента), общая — в область формы (`role="alert"`), фокус — на первое
  неверное поле **в порядке формы**. Ошибка поля, которого в форме нет, — в общую, а не в никуда.
  Исправленное поле теряет ошибку на вводе. 429, 5xx и сеть — одно слово «failed» (у Laravel
  `message` английский); второй 419 — «expired».
- **Сообщение и «спасибо»** — в живой области (`aria-live`), под полями, форма очищается; пустые
  области без своей коробки — форма не прыгает.
- **События** на элементе формы: `webx:form:submit` (отменяемое; `detail.data` — `FormData`,
  `detail.wait(promise)` держит форму занятой до ответа — так капча и пересчёт работают до
  отправки), `webx:form:success`, `webx:form:error`. На них модуль вешает своё — пересчёт суммы
  заказа, счётчик аналитики (с согласием, §9.3), — и не пишет свою отправку.
- **В окне.** `<x-webx-dialog>` с любой `<x-webx-form>` внутри: сообщение встаёт **вместо полей**,
  «Закрыть» открыт и в фокусе, закрытое окно — свежая форма; окно с вернувшейся формой печатается
  `open` и открывается модально (§6.4).

Классы: `webx-form`, `__body`, `__progress`, `__message`, `__answer`, `__heading`, `__text`,
`__error`, `__refusals`, `__refusal`, `__done`, `is-sending`, `is-sent`.

### 17.4 Ответ сервера

Одно соглашение для всех форм; ответ inbox (§6 спеки inbox) стал общим:

```json
{ "ok": true, "heading": "Спасибо", "message": "<p>…</p>", "redirect": null, "html": null }
```

| Поле       | Что делает форма                                            |
| ---------- | ----------------------------------------------------------- |
| `redirect` | переходит по адресу — вход, заказ, переход к оплате         |
| `message`  | показывает на месте, с `heading` над ним — заявка           |
| `html`     | заменяет содержимое формы — следующий шаг оформления заказа |
| ничего     | только событие `webx:form:success`: модуль решает сам       |

Серверная половина — `WebxUi\Widgets\Forms\FormResponse` (`Responsable`): `::message($heading,
$html)`, `::redirect($url)`, `::html($view)`, `::ok()` (строка «ничего»). На запрос, который ждёт
JSON, отвечает JSON; на обычный — redirect с flash (`message` и `html` — на ту же страницу, где
форма их покажет). Контроллер входа или заказа пишет одну строку и получает оба режима; ответивший
обычным `redirect()` тоже работает — браузер прошёл по нему сам.

### 17.5 Проверка в браузере

- **Один источник правил — сервер.** Правила пишутся один раз, в Laravel.
  `FormRules::for($rules, $attributes, $messages)` (те же массивы, что у `FormRequest`) в `:rules`
  формы или `:rules` у одного поля переводит ту часть, которую понимает браузер: `required`,
  `accepted`, `email`, `url`, `numeric`/`integer`, `min`/`max`/`between`/`size` (длина строки,
  число, размер файла — по типу поля), `regex`/`not_regex` (если выражение читается и в JavaScript),
  `in`, `mimes`/`extensions`/`mimetypes`/`image` (`accept`), `confirmed`, `same`/`different`,
  `date`, `after`/`before`/`after_or_equal`/`before_or_equal` с буквальной датой; `bail` и
  `nullable` — без слов. Остальное (`unique`, `exists`, `required_if`, замыкания, объекты правил)
  проверяет только сервер, и это нормально. Поле находит правила формы через данные компонента Blade
  — перекрытая вьюха их не теряет; правила лежат в `data-webx-rules` на корне поля.
- **Те же слова.** Текст ошибки для каждого переведённого правила сервер кладёт рядом — строкой
  самого валидатора (`RuleWords` — наследник `Validator`, у которого спрашивают только строку) с
  `messages`, `attributes` и `validation.custom.*` формы, на языке страницы. Браузер говорит ровно
  то, что сказал бы сервер; второго словаря нет. Тест сверяет каждое правило с `Validator::make()`
  слово в слово.
- **Порядок валидатора:** пустое поле без `nullable` получает все правила, как на сервере; после
  проваленного `required` — ничего, под `bail` — после первого провала. Значение обрезается, длина —
  в кодовых точках. `email`, `url`, `date` в браузере никогда не строже сервера.
- **Когда:** поле, в котором что-то меняли, — когда его покидают; при отправке — все, и ничего не
  уходит, пока одно неверно; неверное поле перепроверяется на вводе. Встроенные пузыри браузера
  выключены — `novalidate` ставит **скрипт**, а не сервер: без JavaScript встроенные проверки
  остаются, других до круга на сервер нет. Кнопка с `formnovalidate` идёт прямо к серверу. Сервер
  проверяет всё всегда; браузер — только удобство.
- **Проверяет браузер только то, что пришло из `FormRules`:** поле с `required` пропом и без правил
  браузер не проверяет — его слово было бы не словом сервера. `maxlength` из `max` не печатается:
  он молча обрезал бы вставку.
- **Маска телефона** — по пропу `mask` (`<x-webx-field type="tel" mask>`), а не у каждого телефона:
  у поля сайта могут быть свои правила на цифры. `+`, код страны, группы цифр, без сторонней
  библиотеки; ни одна клавиша не отказывается — вставка и автозаполнение приходят как есть,
  порядок наводится после. У inbox маски нет: посетитель набирает и местный номер.
- **Файлы:** перетаскивание, список выбранных с размером и превью картинок, «Убрать» до отправки,
  проверка типа и размера сразу, прогресс при отправке. Выбор заново в поле нескольких добавляет.

### 17.6 Вес и тесты

- `dist/form.js` грузится только там, где есть `<x-webx-form>` (§4): оболочка и проверка ≤ 8 КБ
  gzip; маска (`mask.js`) и файлы (`files.js`) — свои входы сборки, заявляет их поле, а не куски
  `import()`: динамический кусок был бы `[name]-<hash>.js`, которого `webx:theme:sync` не знает.
- PHP: каждое поле с `old()` и `$errors` по имени с точками, настоящий POST без JavaScript;
  `FormRules` на каждое правило списка и молчание на остальные; `FormResponse` в обоих режимах;
  `@csrf` и `:csrf="false"`.
- vitest: 422 по полям и в общую, фокус, двойная отправка, 419 → свежий токен → один повтор,
  события, отмена `webx:form:submit`; правила, маска, файлы.
- Браузер на стартовом сайте: витрина «Kitchen sink › Forms» (Fields, Sending, Validation, Inbox,
  Suggestions) — все типы во всех состояниях, длинные подписи на немецком и польском, 360px; форма
  без JavaScript и с ним приходит к одним и тем же ошибкам, ошибка в браузере и с сервера — одно
  слово; поле и кнопка не ниже 44px, фокус виден, контраст ошибки в `night`. Двери витрины —
  маршруты пакета `webx/widgets/showcase*` (у темы нет PHP): отвечают, только пока есть журнал демо,
  `webx:demo --remove` его удаляет — двери отвечают 404.

### 17.7 Документация для агентов

Цель — агент, которому сказали «сделай форму входа» или «добавь поле в оформление заказа», строит
её из полей и оболочки, не читая исходников и не написав ни своей разметки поля, ни своего
`fetch`:

- **`AGENTS.md` виджетов** — о формах: компоненты и их пропсы, классы, соглашение ответа,
  `FormResponse`, `FormRules`, события; в «Do not» — своя отправка, своя разметка поля, `<form>` без
  `@csrf` на маршрут приложения, проверка только в браузере, второй набор правил в JavaScript. Файл
  держится в 150 строках (`AgentDocsCoverageTest`), подробности — в гайде.
- **Гайд `apps/docs/guide/forms.md`** — для людей и агентов: поля, оболочка, ответ, проверка,
  подсказки и примеры целиком; ссылка из гайдов «Site widgets» и «Where the styles live».
- **`AGENTS.md` inbox** — что форма заявки нарисована полями виджетов, как перекрасить её классами
  `webx-field-*` и что из формы принадлежит inbox (антиспам, капча, приём).
- **Корневой `AGENTS.md` сайта** (`webx:panel --sync`) — абзац в «The first rule»: любая форма сайта
  — `<x-webx-form>` и `<x-webx-field>`, ответ — `FormResponse` (`AgentGuideTest`).
- **Каждый будущий модуль с формами** (вход, кабинет, заказ) называет в своём `AGENTS.md` свои
  формы, их поля и события.
- **Покрытие проверяет тест** `FormsDocsCoverageTest`: списки берутся из кода — каждый тип поля,
  каждый метод `FormResponse`, каждое правило `FormRules`, каждое событие `form.js` и `suggest.js` и
  метки ответа подсказок — и каждое должно быть в `AGENTS.md` виджетов или в гайде.

**Подсказки при вводе — `<x-webx-suggest>`**, а не тип поля: поиск — своя GET-форма, чей ответ —
страница, а тип поля добавил бы рамке тип без подсказки, ошибки и `FormRules`.

- Два режима: **с `action`** — `<form method="get" role="search">` на страницу результатов (без
  JavaScript — обычный поиск); **без `action`** — поле без своей формы (формы не вкладываются),
  ставится внутрь любой формы, в том числе `<x-webx-form>`: выбор кладёт значение в поле и шлёт
  `change`, ничего не отправляя.
- Combobox по APG: роли ставит скрипт (без него обещать нечего); фокус всегда в поле, выбранный —
  `aria-activedescendant`; Home/End двигают каретку, пока вариант не выбран; Escape закрывает.
- Запросы — после `min` символов и паузы `delay`; устаревший обрывается (`AbortController`), поздний
  ответ отбрасывается, ответы помнятся. Чужой источник (другой origin) — скрипт не поднимается.
- **Содержимое панели — у сайта:** адрес отвечает HTML своей вьюхи, оболочке нужны только
  `data-webx-option` у пунктов и `data-webx-section` с заголовком у групп; пустой ответ или 204 —
  «ничего не найдено». Недавние запросы — `:recent`, `localStorage`, только в пустом поле, строятся
  `textContent`.
- События `webx:suggest:select` (отменяемое) и `webx:suggest:results`. Первый потребитель — поиск
  каталога (`GET /{prefix}/suggest`, вьюха `webx-catalog::suggest`, тот же движок, что у страницы
  поиска).

### 17.8 Не сейчас

Многошаговые формы как механизм, условная видимость полей и вычисляемые поля (они же в §18 спеки
inbox), телефон с выбором страны, адрес как составное поле, повторитель строк, hCaptcha третьим
драйвером рядом с reCAPTCHA и Turnstile — когда попросит первый модуль, которому нужно. Пока каждое
решается полями, событиями и `html` в ответе.

## 19. Отложено и открытые вопросы

- **Блок `site-header`** — шапка, собранная в панели (зона `header`), с поведением виджета §6.2:
  поля «логотип», «какое меню», «кнопки». Когда кто-то правда захочет собирать шапку в панели.
- **Журнал согласий на сервере** — доказательство «посетитель согласился тогда-то на то-то». Нужен
  ли — зависит от того, что потребует первый сайт с рекламой; таблица и отпечаток без персональных
  данных.
- **Сканер cookie** — какие cookie сайт на самом деле ставит, чтобы список в диалоге не врал. Хороший
  кандидат в `module-audit`: снимок страницы уже есть.
- **Google Maps** — второй драйвер карты рядом с `MapTiles` со своим скриптом и тем же контрактом
  заглушки; когда попросит сайт.
- **Справа налево:** панель зума всегда справа, «до и после» — слева направо; сайту на арабском —
  отдельной правкой.
- **Иконки — в спрайт цепочки**, когда он появится у тем; пока вьюхи (дверь замены та же).
- **Рамка `webx-field` у поля подсказок без формы** (подсказка, ошибка под полем, `FormRules`) — когда
  попросит первая форма, где это важно; пока ошибка сервера о нём — в общий alert формы.
- **Значок календаря у даты на тёмном пресете** остаётся браузерным: `color-scheme` — не токен
  словаря.
- **Переход форм inbox с `wx-form*`** — когда владелец переведёт свои сайты, удалить вьюхи до
  движка, `inbox-legacy.js`, `LegacyAssets`, ветку прежнего flash и `formDialog` одним коммитом,
  проверку `inbox.legacy_views` оставить ещё на выпуск (§20, W6.4).
- **Вторая очередь** — делать, когда попросит второй сайт:
  - **фильтр сетки** — портфолио и кейсы с фильтром по категориям на странице, с анимацией
    перестройки;
  - **промо-окно** — по таймеру, при уходе со страницы, по прокрутке; «не чаще раза в N дней»;
    содержимое — место `popup` в `module-banners`, виджет — только показ и частота;
  - **прогресс чтения** — полоска над статьёй;
  - **«скопировать»** — у почты, промокода, реквизитов.
- **Что ещё повторяется** — сверх §14 и второй очереди добавлять, когда два сайта попросят одно и
  то же, а не заранее.
- **Хлебные крошки — отдельной задачей, не виджетом.** Сейчас у модулей свои вьюхи
  (`webx-catalog::breadcrumbs`, страницы блога, бренды). Это не интерактив, а разметка плюс
  `BreadcrumbList` в микроразметке — место ей в `routing` или `module-seo`: одна вьюха, которую
  модули зовут со своим списком, тема перекрывает, SEO печатает разметку.
- **Не делаем:**
  - **панель доступности** (крупный шрифт, контраст поверх сайта) — такие оверлеи критикуют сами
    специалисты по доступности; путь — доступная вёрстка (правила 29–31 спеки тем) и аудит;
  - **встраиваемые отзывы Google и подобные** — сторонний скрипт, cookie и чужая вёрстка; отзывы — это
    `module-reviews`;
  - **онлайн-чаты** (Jivo, Tawk и т. п.) — не виджет: сторонний скрипт оборачивается в
    `<x-webx-consent category="…">` (§9.3), этого достаточно;
  - **запись на приём** — модуль, не виджет.
- **Поиск по сайту, корзина, сравнение** — им нужны свои модули; этап магазина.

Решения реализации, которые держатся (сверх §1–§17):

- **Окна форм — в `ResponsePrepared`, стили и скрипты — в `RequestHandled`.** Первое — потому что
  flash формы без JavaScript иначе уже выброшен; второе — потому что шапка и подвал заявляют виджеты
  после головы.
- **Слова — скриптом Node на десять языков**, паритет словарей (`widgets.php`, `panel.php`,
  `checks.php`, `audit.php`, `fixes.php`) держит `DistTest`. Счёт — в конце строки («Files chosen:
  :count», «Suggestions: :count»), подписи плиток таймера — заголовки, а не счёт: плюрализации в
  словаре нет.
- **`Widgets::sequence()`** — номер компонента на странице (id полей, форм, оглавлений), сбрасывается
  с запросом.
- **Публичный статический метод компонента с именем его публичного свойства** перекрывает свойство во
  вьюхе («htmlspecialchars(): … Closure given») — `docs/pitfalls/laravel-and-php.md`.
- **Ключ `items` в значениях демо-блока** — вложенные блоки; поля витрины называть иначе
  (`docs/pitfalls/packages-and-demo-sites.md`). Описание демо-типа и предложенного типа — ≤ 255
  символов, `ThemeDefaultTest` меряет каждое.
- **Форма inbox на движке — с переходным периодом, а не чистой заменой.** У формы сменилась разметка
  (группа — `<fieldset>`, ошибка внутри поля), и старые классы на новой разметке легли бы
  наполовину; а сайт, опубликовавший старую вьюху, без старых переменных падал бы 500 и терял
  невидимую капчу. Поэтому вьюха без `<x-webx-form>` считается написанной до движка: ей передаются
  прежние переменные и частичные вьюхи, `$assets->script()` отдаёт `inbox-legacy.js`, приём кладёт
  и прежний flash; проверка аудита `inbox.legacy_views` называет путь такой вьюхи; таблица «было →
  стало» — в гайде «Inbox». `inbox.js` теперь только капча, на событиях оболочки, слушатель на
  `document`. В JSON приёма больше нет `form` (слаг — на `<form data-webx-form>`). Кнопка во время
  отправки слов не меняет («Sending…» ушло).
- **Ловушки замеров**, найденные по ходу, — в `docs/pitfalls/layout-and-browser.md`: неявная строка
  `auto` сетки растёт мимо `max-height`; скрытая панель останавливает `ResizeObserver`; проза темы
  даёт `li + li` отступ ячейкам сетки; два пальца, поднятые вместе, приходят двумя `touchend`; Tab
  по ленте с петлёй Swiper в полном прогоне — по нажатию на кадр.
