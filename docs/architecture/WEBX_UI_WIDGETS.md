Пакет — новая библиотека `webx-ui/widgets` (§3);

Из сайта в сайт повторяются одни и те же интерактивные куски: слайдер, увеличение картинки, видео с
YouTube, карта на странице контактов, баннер согласия на cookie, вкладки, аккордеон, мобильное меню.
Сегодня каждый сайт ставит их заново — свой слайдер, свой скрипт меню, своя обёртка над YouTube — и
почти никогда не ставит баннер согласия, без которого сайт с аналитикой или видео в ЕС работать не
должен.

Ответ — **один пакет виджетов**: поставил — и в шаблонах есть `<x-webx-slider>`, `<x-webx-video>`,
`<x-webx-map>`, баннер согласия на каждой странице, вкладки по атрибуту. Логика, доступность,
загрузка по требованию и согласие — готовы; вид — каркас на токенах сайта, который тема
перекрашивает и перерисовывает теми же дверями, что вид модулей.

## 1. Границы

**Внутри:**

- пакет, его место в цепочке темы, загрузка по требованию (§3, §4);
- контракт виджета: компонент, классы, CSS на токенах, скрипт, слова (§5);
- лёгкие поведения: выпадашки, диалог, вкладки, аккордеон (§6); мобильное меню (§6.1); шапка (§6.2);
  выпадающая панель (§6.3); форма в окне (§6.4);
- слайдер (§7), лайтбокс (§8), видео (§10), карта (§11);
- согласие на cookie и блокировка стороннего до согласия (§9);
- контакты как данные сайта и виджеты на них: телефоны, часы работы, мессенджеры, соцсети (§12);
- переключатель языка (§13); контентные виджеты второй волны (§14);
- предложенные блоки (§15.1); проверки аудита (§15.2).

**Снаружи (и почему):**

- **Формы.** Они — `module-inbox`, и уже умеют серверную валидацию, honeypot, лимит частоты,
  проверку Origin, reCAPTCHA и Turnstile, отправку на месте и поле согласия. Второй пакет форм —
  две системы, которые разъедутся. Чего не хватает (§17), доращивается в inbox.
- **Аналитика как таковая** — какие счётчики стоят и где их ключи. Здесь только то, что они не
  запускаются до согласия (§9.3).
- **Хлебные крошки** — разметка, а не поведение; отдельная задача (§19).
- **Вид.** Пакет даёт каркас, а не дизайн; красивым виджет делает тема.

## 2. Принятые решения (не переоткрывать)

1. **Один пакет, не пакет на виджет.** Каждый пакет в монорепе стоит цикла: четыре места в `php/`,
   первая публикация руками, документация, `AGENTS.md`. Виджеты маленькие, связаны общим (загрузка,
   согласие, токены) и почти всегда нужны вместе. Грузится при этом только то, что стоит на
   странице (§4) — один пакет не значит один большой файл.
2. **Логика готова, вид — каркас.** Виджет несёт поведение, доступность и базовый CSS на токенах
   `--site-*`; классы `webx-<виджет>-*` — публичный контракт (§5). Тема меняет вид токенами, CSS на
   классах или перекрытием вьюхи компонента — те же двери, что у модулей (§10.5 спеки тем).
3. **Поведения живут здесь, а не в движке тем.** Движок тем остаётся без JavaScript: цепочка,
   токены, проверки. Меню, диалог, вкладки, аккордеон — лёгкие виджеты этого пакета (§6);
   `theme-default` зависит от `widgets`, как зависит от модулей.
4. **Ничего стороннего до согласия.** Видео, карта, счётчики — до согласия на их категорию на
   странице нет ни одного запроса к третьей стороне: вместо них заглушка с понятной кнопкой (§9.4).
   Это не настройка, а поведение по умолчанию; выключить можно только явно и только для сайта вне
   ЕС, и аудит это заметит.
5. **Скрипт — только там, где виджет есть.** Компонент сам заявляет свои файлы, `@webxTheme`
   печатает только заявленные (§4). Слайдер на главной не грузит Swiper на остальные сто страниц.
6. **Без сборки на сайте.** Пакет приезжает с готовым `dist/`, как тема (§2.9 спеки тем). Сторонние
   библиотеки (Swiper, PhotoSwipe, Leaflet) вшиты в `dist/` и обновляются версией пакета, а не
   сайтом.
7. **Работает и без JavaScript.** Слайдер — прокручиваемая лента, лайтбокс — ссылка на картинку,
   вкладки — заголовки над блоками, видео — ссылка на ролик, карта — адрес и ссылка на карту.
8. **Сторонние библиотеки — с лицензией MIT или равной ей**, без ключей и регистрации там, где можно
   (карта по умолчанию — OpenStreetMap без ключа, §11).

## 3. Пакет

**`webx-ui/widgets`** — библиотека без префикса `module-`: виджеты работают на любом сайте, панель
им не нужна (настройки согласия — вкладка в `module-settings`, §9.5). Namespace `WebxUi\Widgets`,
таблиц нет. Требует `webx-ui/themes` (словарь токенов, цепочка, выкладка ассетов).

```
widgets/
├── src/                      ← PHP: компоненты, провайдер, Consent, команды
├── resources/
│   ├── views/components/     ← <x-webx-slider>, <x-webx-video>, … (перекрываются темой)
│   ├── blocks/*.json         ← предложенные блоки (§15.1)
│   ├── icons/*.svg           ← стрелки, play, закрыть, развернуть
│   └── js/, css/             ← исходники по виджету
├── dist/                     ← собранное: по файлу JS и CSS на виджет + общий runtime
├── lang/<locale>/widgets.php ← подписи, ARIA, тексты баннера по умолчанию на 10 языках
└── tests/
```

В цепочке темы пакет — **нижний слой**, как модуль (§7.1 спеки тем): его вьюхи компонентов
перекрываются в `views/vendor/webx-widgets/`, его CSS идёт первым в каскаде, его иконки — в общий
спрайт, его блоки — через `BlockOffers`.

## 4. Загрузка по требованию

Компонент при рендере заявляет свой виджет: `Widgets::need('slider')`. `@webxTheme` раскрывается
лениво (как `@webxBlocks`, §20 спеки блоков) и печатает в `<head>` `<link>` на CSS заявленных
виджетов, а перед `</body>` — `<script type="module">` на их JS. Страница без виджетов не получает
ничего, кроме баннера согласия (он заявлен на каждой странице, §9).

Атрибутный путь (`data-webx-tabs` в шаблоне блока без компонента) тоже должен заявить виджет — иначе
скрипта не будет. Поэтому лёгкие поведения (§6) лежат в общем runtime, который грузится всегда (его
вес — единицы килобайт), а тяжёлые (слайдер, лайтбокс, карта) — только через компонент.

Все скрипты монтируются через рантайм блоков (`webx.mount(root)`, §10 спеки блоков): виджет
поднимается и на живой странице, и в блоке, который панель подменила в предпросмотре, и в куске
страницы, догруженном позже. Монтирование идемпотентно, размонтирование освобождает экземпляр
сторонней библиотеки.

Бюджет веса проверяет тест сборки: runtime с поведениями, мобильным меню и шапкой ≤ 16 КБ gzip; слайдер ≤ 45; лайтбокс ≤ 25;
видео ≤ 4; карта ≤ 50 (без тайлов); баннер согласия ≤ 6.

## 5. Контракт виджета

Каждый виджет устроен одинаково, и `AGENTS.md` пакета описывает его по одной форме:

| Что              | Как                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Компонент        | `<x-webx-<имя>>` с пропсами; вьюха `webx-widgets::components.<имя>` перекрывается темой                                               |
| Классы           | `webx-<имя>`, `webx-<имя>__<элемент>`, состояния `is-*` — публичный контракт, переименование ломающее                                 |
| CSS              | каркас на `--site-*`, `@container`, без буквальных значений (проверка §8 спеки тем)                                                   |
| Локальные токены | `--webx-<имя>-*` для того, что тема чаще всего крутит (`--webx-slider-gap`, `--webx-slider-arrow-size`); по умолчанию — из `--site-*` |
| Скрипт           | через `webx.mount`, настройки из `data-*` компонента                                                                                  |
| Слова            | `webx-widgets::widgets.<имя>.*` на 10 языках; любое перекрывается пропсом                                                             |
| Иконки           | из спрайта цепочки — тема заменяет стрелку своей, не трогая виджет                                                                    |
| Без JS           | описано, что видит посетитель, и это проверено тестом                                                                                 |

## 6. Лёгкие поведения

Без зависимостей, в общем runtime, включаются атрибутом или компонентом:

| Поведение    | Атрибут / компонент                    | Что делает                                                                                     |
| ------------ | -------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `disclosure` | `data-webx-disclosure`                 | меню шапки, выпадашки; закрытие по Esc и клику мимо; ARIA `expanded`                           |
| `dialog`     | `data-webx-dialog` / `<x-webx-dialog>` | `<dialog>` с ловушкой фокуса и возвратом фокуса; мобильное меню и фильтры каталога на телефоне |
| `tabs`       | `data-webx-tabs` / `<x-webx-tabs>`     | вкладки с клавиатурой (стрелки, Home, End) и ARIA                                              |
| `accordion`  | `data-webx-accordion`                  | на `<details>`; «одна открыта» по желанию                                                      |

### 6.1 Мобильное меню

Есть на каждом сайте и каждый раз пишется заново — с теми же ошибками: страница прокручивается под
открытым меню, низ меню уезжает под панель браузера на iPhone, фокус уходит за меню, длинное меню не
прокручивается. Поэтому это не поведение по атрибуту, а **компонент с готовой разметкой, слотами и
каркасом стилей**; что внутри — решает сайт.

```blade
<x-webx-mobile-menu side="right" label="{{ __('theme::menu.open') }}">
    <x-slot:top>
        <a href="/" class="site-logo">…</a>
    </x-slot:top>

    <x-webx-mobile-menu.nav :items="menu('header')" mode="drill" />

    <x-slot:bottom>
        <a href="tel:{{ settings('contacts.phone') }}">{{ settings('contacts.phone') }}</a>
        <x-webx-consent-link />
    </x-slot:bottom>
</x-webx-mobile-menu>
```

**Устройство** — три зоны в одной панели:

| Зона | Слот         | Что                                                                                 |
| ---- | ------------ | ----------------------------------------------------------------------------------- |
| верх | `top`        | закреплён: логотип, кнопка закрытия (есть всегда, даже если слот пуст), язык, поиск |
| тело | по умолчанию | **прокручивается само**, страница под ним — нет: навигация, любые блоки сайта       |
| низ  | `bottom`     | закреплён: телефон, кнопка заявки, соцсети, «Настройки cookie»                      |

Плюс слот `trigger` — своя кнопка вместо стандартного «бургера» (иконка `menu` из спрайта цепочки).

**Пропсы:** `side` — `left` | `right` | `top` | `bottom` (снизу — «шторка» на всю ширину) | `full`;
`breakpoint` — до какой ширины **шапки** виден триггер (по умолчанию 960px, через `@container` на
корне шапки — §2 спеки тем: решает контейнер, а не окно); `close-on-navigate` (по умолчанию да).

**Навигация** — `<x-webx-mobile-menu.nav>` рисует дерево `menu()` в двух режимах:

- `accordion` — подпункты раскрываются на месте (`<details>`);
- `drill` — подпункт открывает следующий уровень поверх, с кнопкой «Назад» и названием раздела
  наверху; для глубоких меню каталога и услуг.

Текущий пункт помечен `aria-current="page"`, его ветка раскрыта. Сайт может не использовать этот
компонент и положить в тело свою разметку — оболочка меню от этого не меняется.

**Что сделано за сайт:**

- `<dialog>` с ловушкой фокуса, Esc, кликом мимо, возвратом фокуса на триггер (§6 `dialog`);
- блокировка прокрутки страницы без скачка вёрстки (`scrollbar-gutter`, без `position: fixed` на
  `body`, который сбрасывает прокрутку на iOS);
- высота `100dvh`, отступы `env(safe-area-inset-*)` — низ не уходит под панель браузера и «чёлку»;
- `overscroll-behavior: contain` в теле — прокрутка меню не протекает на страницу;
- закрытие при переходе по ссылке, в том числе по якорю на той же странице;
- «Назад» в браузере закрывает меню, а не уводит со страницы (запись в истории при открытии,
  выключается пропсом);
- свайп в сторону `side` закрывает;
- анимация открытия — на `--site-duration`/`--site-easing`, без неё при `prefers-reduced-motion`;
- без JavaScript — триггер — ссылка на `#webx-mobile-menu`, панель открывается через `:target`
  и закрывается ссылкой «Закрыть»; прокрутка тела работает.

**Классы и токены:** `webx-mobile-menu`, `__trigger`, `__panel`, `__top`, `__body`, `__bottom`,
`__close`, `--<side>`, `is-open`; навигация — `webx-mobile-nav`, `__item`, `__link`, `__back`,
`__level`, `is-current`. Локальные токены: `--webx-mobile-menu-width` (по умолчанию `min(88vw,
400px)`), `--webx-mobile-menu-backdrop`, `--webx-mobile-menu-padding`. Каркас — фон
`--site-color-surface`, разделители `--site-color-border`, пункты не ниже 44px по высоте.

Скрипт — в общем runtime (≤ 4 КБ из бюджета §4): меню есть на каждой странице, грузить его отдельным
файлом незачем.

### 6.2 Шапка

Второй кусок, который есть на каждом сайте. Виджет отвечает за **поведение и каркас**, а не за вид:
как шапка выглядит и в каком порядке стоят её части, решает тема. Иначе шапка — самая «дизайнерская»
часть сайта — превращается в компонент с пропсами на каждый случай.

```blade
<x-webx-header sticky="hide-on-scroll" collapse="auto">
    <x-slot:topbar>…телефон, часы работы, язык…</x-slot:topbar>
    <x-slot:brand><a href="/" class="site-logo">…</a></x-slot:brand>

    <x-webx-header.nav :items="menu('header')" />

    <x-slot:actions>…телефон, кнопка заявки, поиск…</x-slot:actions>
    <x-slot:mobile-bottom>…что добавить в низ мобильного меню…</x-slot:mobile-bottom>
</x-webx-header>
```

| Слот            | Что                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------ |
| `topbar`        | необязательная полоса над шапкой; при `sticky` уезжает, шапка остаётся                     |
| `brand`         | логотип; уезжает в верх мобильного меню                                                    |
| по умолчанию    | навигация; обычно `<x-webx-header.nav>`, но может быть любая разметка                      |
| `actions`       | кнопки справа: телефон, заявка, язык, поиск (позже корзина); уезжают в низ мобильного меню |
| `mobile-bottom` | добавляется в низ мобильного меню после `actions`                                          |
| `mobile`        | своё мобильное меню целиком — тогда шапка не собирает его сама                             |
| `trigger`       | своя кнопка вместо «бургера»                                                               |

**Шапка и мобильное меню — два виджета, а не один.** По умолчанию шапка сама вставляет
`<x-webx-mobile-menu>` (§6.1) и собирает его из того, что у неё уже есть: `brand` — наверх,
навигация — в тело, `actions` и `mobile-bottom` — вниз. Меню пишется один раз, а не дважды. Связь
не жёсткая:

| Ситуация                                 | Как                                                   |
| ---------------------------------------- | ----------------------------------------------------- |
| обычный сайт                             | `<x-webx-header>` — мобильное меню соберётся само     |
| мобильное меню отличается от десктопного | слот `mobile` со своим `<x-webx-mobile-menu>`         |
| своя шапка, не виджетом                  | `<x-webx-mobile-menu>` прямо в ней (§6.1)             |
| короткое меню, «бургер» не нужен         | `collapse="never"` — мобильное меню не рисуется вовсе |

Почему раздельно: мобильное меню нужно и теме со своей шапкой; открывают его не только из шапки
(нижняя панель навигации на телефоне, кнопка в hero); и меняются они по разным причинам — шапка из-за
десктопа (выпадашки, липкость, раскладка), меню из-за телефона (жесты, высота экрана, iOS).

**Пропсы:**

- `collapse` — когда навигация прячется в мобильное меню:
  - `auto` (по умолчанию) — **когда не помещается**: шапка меряет свою ширину и ширину навигации
    (`ResizeObserver` на корне) и ставит `is-collapsed`, только если пункты в строку уже не входят.
    Не угаданная ширина окна, при которой меню на 1100px либо уже не влезает, либо ещё влезло бы;
  - число (`960`) — по ширине шапки через `@container`;
  - `never` — никогда.

  Без JavaScript `auto` работает как число из `--webx-header-collapse` (по умолчанию 960px).

- `sticky` — `none` | `sticky` | `hide-on-scroll` (прячется при прокрутке вниз, появляется при
  прокрутке вверх).
- `overlay` — шапка прозрачная поверх первого экрана (hero) и становится сплошной после прокрутки на
  свою высоту (`is-scrolled`). Цвет текста в прозрачном состоянии — локальный токен
  `--webx-header-overlay-color`: поверх тёмной картинки нужен светлый.

**Что сделано за сайт:**

- **Высота шапки — в `--webx-header-height`** на `:root`, обновляется при изменении размера, и
  `scroll-margin-top` у целей якорей её учитывает: переход по якорю не прячет заголовок под липкой
  шапкой. Этот же токен берут другие липкие вещи (боковая колонка, фильтры каталога) для `top`.
- **Ссылка «К содержимому»** первой в документе, видна при фокусе с клавиатуры; ведёт на `<main>`.
- **Выпадающие меню навигации** (`<x-webx-header.nav>` рисует дерево `menu()`):
  - мышью — открытие по наведению с задержкой и «коридором»: меню не закрывается, когда курсор идёт
    наискосок к подпункту;
  - на тач-экране — по касанию, второе касание идёт по ссылке;
  - с клавиатуры — Enter и пробел открывают, стрелки ходят по пунктам, Esc закрывает и возвращает
    фокус;
  - выпадашка не вылезает за край окна: прижимается к правому краю, если справа не хватает места;
  - текущий пункт и его ветка — `aria-current="page"` и `is-current`.
- **Режим `mega`** у пункта — вместо списка подпунктов широкая панель во всю ширину шапки со своей
  вьюхой: `<x-webx-header.nav :items="…" :mega="['services' => 'components.mega.services']">`.
  Режим задаёт вёрстка, а не пункт меню в панели: как выглядит панель — решение темы.
- `hide-on-scroll` не прячет шапку, пока открыта выпадашка, мобильное меню или фокус внутри шапки.
- Анимации — на `--site-duration`/`--site-easing`, без них при `prefers-reduced-motion`.

**Раскладка — дело темы.** Корень — CSS-сетка с именованными областями:

```css
.webx-header__bar {
  display: grid;
  grid-template-areas: 'brand nav actions';
  grid-template-columns: auto 1fr auto;
}
```

Логотип по центру, меню справа, две строки — тема переопределяет `grid-template-areas` одной правкой
на этих классах, не перекрывая вьюху (вторая дверь, §10.5 спеки тем). Модификаторы `--sticky`,
`--overlay`, `is-scrolled`, `is-hidden`, `is-collapsed` — для её стилей.

**Классы и токены:** `webx-header`, `__topbar`, `__bar`, `__brand`, `__nav`, `__actions`,
`__trigger`, `__skip`; навигация — `webx-header-nav`, `__item`, `__link`, `__dropdown`, `__mega`,
`is-open`, `is-current`. Локальные токены: `--webx-header-height` (считается), `--webx-header-bg`,
`--webx-header-overlay-color`, `--webx-header-collapse`, `--webx-header-gap`.

**Зона `header`.** Шапка сайта — зона лейаута (`WEBX_UI_LAYOUT_REGIONS.md`): пока зона пуста,
печатается Blade-компонент шапки из цепочки темы, и у `theme-default` он собран на этом виджете.
Заполненная в панели зона заменяет шапку целиком, как сейчас. Блок `site-header`, который дал бы
шапке, собранной в панели, то же поведение, — отложен (§19).

Подвал — не виджет: поведения у него нет, это разметка темы.

Скрипт — в общем runtime (≤ 5 КБ из бюджета §4), вместе с мобильным меню.

### 6.3 Выпадающая панель

`<x-webx-dropdown>` — панель, привязанная к кнопке. Основа для выпадашки телефонов (§12.2),
расписания (§12.3), переключателя языка (§13), «поделиться» (§14) и выпадашек шапки (§6.2).

```blade
<x-webx-dropdown open-on="hover" placement="bottom-start">
    <x-slot:trigger>0800-303-332</x-slot:trigger>
    …что угодно…
</x-webx-dropdown>
```

- **Позиционирование:** `placement` — `bottom-start` | `bottom-end` | `bottom` | `top-*`; у края окна
  панель переворачивается или прижимается, чтобы не вылезти за экран. CSS anchor positioning там, где
  браузер его умеет, расчёт в скрипте — там, где нет.
- **Открытие:** `click` (по умолчанию) или `hover` — с задержкой открытия и закрытия и «коридором»
  для курсора; на тач-экране `hover` всегда становится `click`.
- **Клавиатура и ARIA:** Enter/пробел открывают, Esc закрывает и возвращает фокус, Tab из панели —
  закрывает; `aria-expanded`, `aria-controls`; панель — `popover` там, где браузер умеет, чтобы не
  бороться с `overflow: hidden` и `z-index` предков.
- Одна открытая панель на странице: открытие другой закрывает первую.
- Без JavaScript — `<details>`: панель раскрывается по клику под кнопкой.

Классы: `webx-dropdown`, `__trigger`, `__panel`, `--<placement>`, `is-open`. Токены:
`--webx-dropdown-offset`, `--webx-dropdown-min-width`; поверхность — `--site-color-surface`, тень —
`--site-shadow-md`, радиус — `--site-radius-md`.

### 6.4 Форма в окне

«Заказать звонок», «Получить консультацию», «Записаться» — самое частое окно на корпоративном сайте.
Диалог (§6) с формой `module-inbox` внутри; открыть его может любая кнопка:

```blade
<a href="#callback" data-webx-form="callback">{{ __('theme::contacts.callback') }}</a>
```

- `data-webx-form="<slug>"` открывает диалог с формой по её slug. Формы, которые открываются на
  странице, рисуются в конец `<body>` **один раз** на slug — сколько бы кнопок на них ни вело.
  Компонент заявляет форму при рендере (`Widgets::form('callback')`), как виджет заявляет себя (§4).
- Форма печатается тем же `<x-webx-inbox::form slug="…" placement="modal" />`, что везде: заявка
  помнит место `modal` (`placement`, §11 спеки зон), панель показывает «Место: modal».
- Заголовок окна — название формы; после отправки окно показывает «спасибо» формы и закрывается по
  кнопке, а не само: человек должен успеть прочитать.
- Кнопка может передать в форму скрытое значение: `data-webx-form-value-service="{{ $service->id }}"`
  — «записаться» со страницы услуги приходит в панель уже с услугой.
- Без JavaScript `href="#callback"` ведёт на ту же форму, которая без скрипта — обычный блок в конце
  страницы (`:target` показывает его поверх).

Классы: `webx-form-dialog`, `__title`, `__close`; форма внутри — свои `wx-form wx-form--modal`.

## 7. Слайдер

**Swiper** (MIT), собранный модулями: в `dist/slider.js` только навигация, пагинация, клавиатура,
a11y, autoplay, эффект fade и миниатюры.

```blade
<x-webx-slider variant="cards" :per-view="['sm' => 1.2, 'md' => 2, 'lg' => 3]">
    @foreach ($services as $service)
        <x-webx-slide>…</x-webx-slide>
    @endforeach
</x-webx-slider>
```

| Вариант   | Для чего                                                    |
| --------- | ----------------------------------------------------------- |
| `cards`   | лента карточек: услуги, товары, отзывы, команда             |
| `hero`    | первый экран: по слайду на ширину, затухание, автопрокрутка |
| `gallery` | большая картинка и миниатюры: товар, объект, портфолио      |
| `logos`   | бегущая лента логотипов без стрелок                         |

Вариант — набор настроек Swiper и модификатор класса `webx-slider--<вариант>`; любую настройку можно
переопределить пропсом. `per-view` — по ширине **контейнера** (у Swiper брейкпоинты по окну, поэтому
компонент пересчитывает их через `ResizeObserver` на своём корне): слайдер в узкой колонке ведёт себя
как слайдер в узкой колонке, а не как на широком экране.

- Без JS — лента со `scroll-snap`, которую листают пальцем или прокруткой.
- Автопрокрутка останавливается при наведении, фокусе и `prefers-reduced-motion`; у неё всегда есть
  кнопка паузы (WCAG 2.2.2).
- Картинки слайдов, кроме первых видимых, — `loading="lazy"`.
- `gallery` вместе с лайтбоксом (§8) — галерея товара в каталоге (§10.6 спеки тем).

<a href="{{ $image->url() }}" data-webx-lightbox="product-{{ $product->id }}"

## 9. Согласие на cookie

### 9.1 Что показывает

Баннер на каждой странице, пока нет ответа: короткий текст, ссылка на политику, три кнопки —
**«Принять всё»**, **«Отклонить всё»**, **«Настроить»**. «Отклонить» — того же веса и размера, что
«Принять»: в ЕС согласие, вырванное неравными кнопками, согласием не считается. «Настроить» открывает
диалог (§6) с категориями и переключателями.

| Категория     | Что в ней                                     | По умолчанию         |
| ------------- | --------------------------------------------- | -------------------- |
| `necessary`   | сессия, CSRF, сам ответ о согласии            | всегда, не выключить |
| `preferences` | язык, тема, свёрнутые блоки                   | выкл                 |
| `statistics`  | счётчики, аналитика                           | выкл                 |
| `marketing`   | рекламные пиксели, ремаркетинг                | выкл                 |
| `media`       | видео (§10), карты (§11) и прочие встраивания | выкл                 |

Категорию, которой на сайте ничего не нужно, баннер не показывает: `statistics` без единого
счётчика — пустой переключатель, который только путает.

Ссылка «Настройки cookie» в подвале (`<x-webx-consent-link>`) снова открывает диалог — отозвать
согласие должно быть так же просто, как дать.

### 9.2 Где хранится

Cookie `webx_consent` (первая сторона, `SameSite=Lax`, год): категории, дата, **версия политики**.
Версия меняется в панели, когда меняется политика или список того, что ставится, — и баннер
спрашивает заново. Ответ читается и на сервере (`Consent::has('media')`), поэтому заглушку вместо
видео сервер рисует сразу, без мигания.

Журнал согласий на сервере — не в первой редакции (§19): ответ живёт в браузере посетителя.

### 9.3 Блокировка до согласия

Всё стороннее, что ставит cookie или передаёт данные посетителя, на странице лежит **выключенным** и
включается скриптом согласия:

```html
<script type="text/plain" data-webx-consent="statistics" src="https://…/counter.js"></script>
<iframe data-webx-consent="media" data-src="https://www.youtube-nocookie.com/embed/…"></iframe>
```

- `script type="text/plain"` браузер не выполняет; после согласия скрипт пересоздаётся с настоящим
  типом. `iframe` получает `src` из `data-src`.
- Отказ после согласия — перезагрузка страницы: выполненный скрипт не выгрузить.
- Компонент `<x-webx-consent category="statistics">…</x-webx-consent>` оборачивает любой
  произвольный код (вставку из настроек сайта) — его же использует `module-seo` или настройки,
  когда там появятся коды счётчиков.
- **Google Consent Mode v2**: если на странице есть `gtag`, скрипт шлёт `consent default` с отказом
  до ответа и `consent update` после — так счётчики Google работают в режиме без cookie, а не
  молчат совсем.
- Сигнал `Sec-GPC` браузера (Global Privacy Control) — `marketing` выключен и не предлагается
  включить по умолчанию.
- API для скриптов сайта: `webx.consent.has('media')`, событие `webx:consent` с новым ответом.

### 9.4 Заглушка

Видео и карта до согласия на `media` — заглушка на месте: превью (постер ролика — своя картинка,
не с серверов YouTube; карта — статичная картинка или просто адрес), строка «Видео загрузится с
YouTube, который может ставить cookie» и две кнопки: «Загрузить» (только это встраивание) и «Всегда
загружать видео» (согласие на `media`). Тексты — в словаре, на 10 языках.

### 9.5 В панели

Вкладка **«Cookie»** в `settings.index` — патчем экрана от `webx-ui/widgets`, если стоит
`module-settings`:

- баннер вкл/выкл (выкл — только для сайта, которому он не нужен; аудит это заметит, §15.2);
- тексты баннера и категорий — `localized`, по умолчанию из словаря пакета;
- ссылка на страницу политики — выбор страницы сайта;
- версия политики и кнопка «Спросить всех заново»;
- какие категории показывать — по умолчанию те, у которых на сайте что-то есть.

Без `module-settings` — конфиг `webx-widgets.consent`. MCP: `settings_get` / `settings_set`.

## 10. Видео

```blade
<x-webx-video src="https://www.youtube.com/watch?v=…" :poster="$image" title="…" />
<x-webx-video :file="$media" :poster="$image" />
```

- **YouTube, Vimeo** — «фасад»: постер и кнопка; `iframe` (YouTube — `youtube-nocookie.com`)
  только по клику и только с согласием на `media` (§9.4). Постер — из библиотеки медиа; если не
  задан, сервер один раз забирает превью ролика к себе (загрузкой по ссылке в библиотеку медиа), чтобы посетитель не ходил за ним на сторонний сервер.
- **Свой файл** — `<video>` с `preload="none"` и постером, без согласия: это первая сторона.
- Пропорция — `aspect-ratio` из пропса или 16/9, без скачка вёрстки при загрузке.
- Без JS — ссылка на ролик с постером.

**Фон** — `<x-webx-video :file="$media" :poster="$image" variant="background" />` для первого экрана: свой
файл, без звука, по кругу, без элементов управления, `playsinline`. Только свой файл — фон с YouTube
означал бы сторонний запрос на каждом показе первого экрана.

- На паузе при `prefers-reduced-motion`, вне экрана (`IntersectionObserver`) и на экономном
  соединении (`navigator.connection.saveData`): тогда только постер.
- Кнопка паузы есть всегда, пусть и неброская (WCAG 2.2.2 — движение дольше пяти секунд).
- Постер показывается до первого кадра, поэтому первый экран не пустеет, пока видео грузится.
- Видео — декор: `aria-hidden`, текст поверх него — в разметке страницы, а не в ролике.

Каталог уже умеет видео в галерее товара (`data-webx-embed`, спека видео каталога); в этапе W3 его
вьюха переходит на этот компонент, чтобы согласие и фасад были в одном месте.

## 11. Карта

**Leaflet** (BSD-2) с тайлами **OpenStreetMap** по умолчанию — без ключа и регистрации. Другие
провайдеры — драйверами по конфигу (`webx-widgets.map.provider`): тайлы по URL с ключом (MapTiler и
подобные) или полноценный Google Maps по ключу. Привязки к стране нет: провайдер выбирает сайт.

```blade
<x-webx-map :lat="…" :lng="…" :zoom="15" :marker="settings('contacts.address')" />
<x-webx-map from="settings" />
```

- `from="settings"` — координаты и адрес из общих настроек (контакты), чтобы карта на странице
  контактов не дублировала адрес вручную.
- До согласия на `media` — заглушка с адресом и ссылкой «Открыть в картах» (§9.4); тайлы — это
  запросы к третьей стороне с IP посетителя.
- Прокрутка колесом не масштабирует карту, пока по ней не кликнули: страница не застревает на карте.
- Без JS — адрес и ссылка на карту.
- Атрибуция OSM — обязательна по лицензии данных и печатается всегда.

## 12. Контакты

### 12.1 Данные: вкладка «Контакты» в настройках

Сегодня у сайта нет контактов как данных: в общих настройках только логотип, а телефон и почта
появляются, если проект сам допишет поле патчем экрана, — у каждого сайта свои ключи. Виджету
«телефоны» негде их взять, карте (`from="settings"`, §11) — адрес, `module-seo` — телефон и часы для
`Organization`/`LocalBusiness`.

Поэтому **`module-settings` получает стандартную вкладку «Контакты»** — это данные сайта, а не
виджета, и читают их виджеты, карта, SEO и шаблоны темы:

| Ключ                  | Что                                                                                                                           |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `contacts.phones`     | список: номер, подпись (`localized`: «Отдел продаж»), главный, мессенджеры на этом номере (WhatsApp, Telegram, Viber, Signal) |
| `contacts.emails`     | список: адрес, подпись                                                                                                        |
| `contacts.addresses`  | список: адрес (`localized`), координаты, главный, ссылка на карту                                                             |
| `contacts.hours`      | неделя — по дню интервалы или «выходной»; исключения по датам (праздники); часовой пояс сайта                                 |
| `contacts.messengers` | ссылки на каналы, не привязанные к номеру: Telegram-бот, WhatsApp Business-ссылка                                             |
| `contacts.socials`    | список: сеть (из словаря иконок) и ссылка                                                                                     |

- Номер хранится **как его ввели** и рядом нормализованным в E.164 (`+380443930810`): показывается
  первое, в `tel:` и в микроразметку идёт второе. Нормализация — `libphonenumber` по стране из номера
  или из языка сайта, если номер без кода; не распознан — сохранение просит код страны, а не молчит.
- Хелперы: `contacts()->phones()`, `->primaryPhone()`, `->hours()->openNow()`, `->addresses()`.
  Переводимые подписи — на текущем языке.
- `module-seo` берёт отсюда `telephone`, `email`, `address`, `geo` и `openingHoursSpecification`; свои
  поля «телефон» и «адрес» организации ему больше не нужны.
- Сайт, у которого уже есть свои ключи `contacts.*` патчем экрана, переносит значения командой
  `webx:settings:contacts --from=<ключ>`; старые ключи читаются до переноса.
- MCP: `settings_get` / `settings_set` по тем же ключам; агент, которого попросили «поменяй телефон
  на сайте», меняет его в одном месте, а не в пяти шаблонах.

### 12.2 Телефоны

```blade
<x-webx-phones />                                  {{-- главный, остальные в выпадашке --}}
<x-webx-phones :callback="'callback'" />           {{-- и «Заказать звонок» под номером --}}
<x-webx-phones layout="list" />                    {{-- все номера списком: подвал, контакты --}}
```

- Главный номер — ссылкой `tel:`; если номеров больше одного — стрелка и выпадашка (§6.3) с
  остальными, у каждого его подпись.
- `callback` — slug формы: под номером ссылка, которая открывает форму в окне (§6.4).
- На телефоне номер в шапке может свернуться в иконку трубки (`compact`), которая открывает ту же
  выпадашку.
- У номера с мессенджерами — их иконки рядом, ведут в чат с этим номером (`wa.me`, `t.me`, `viber://`).

Классы: `webx-phones`, `__primary`, `__number`, `__label`, `__list`, `__callback`, `__messengers`.

### 12.3 Часы работы

```blade
<x-webx-hours />                 {{-- «Открыто до 19:00», расписание в выпадашке --}}
<x-webx-hours layout="table" />  {{-- неделя таблицей: страница контактов --}}
```

- Статус по часовому поясу сайта, а не посетителя: «Открыто до 19:00», «Закрыто, откроется завтра в
  9:00», «Сегодня выходной». Исключения по датам учитываются.
- Сервер рисует статус на момент ответа; скрипт пересчитывает его в браузере, потому что страница
  может лежать в кеше часами.
- Подряд идущие одинаковые дни сворачиваются: «Пн–Пт 9:00–19:00».
- Формат времени — по языку страницы (24 или 12 часов), на сервере, как `useDates()` в панели, без
  `toLocaleString` по браузеру.

Классы: `webx-hours`, `__status`, `is-open`, `is-closed`, `__table`, `__day`, `is-today`.

### 12.4 Мессенджеры и быстрая связь

Два виджета на одних данных (`contacts.phones[].messengers`, `contacts.messengers`):

- **`<x-webx-contact-button>`** — плавающая кнопка в углу, раскрывается в список: мессенджеры,
  звонок, форма в окне (§6.4). Угол, отступ и что в списке — пропсами. Не перекрывает баннер согласия
  (§9) и поднимается над ним, пока баннер на экране.
- **`<x-webx-contact-bar>`** — нижняя полоса на телефоне: «Позвонить», «Написать», «Заявка».
  Показывается до заданной ширины контейнера, учитывает `safe-area-inset-bottom`, добавляет странице
  нижний отступ на свою высоту, чтобы не закрывать подвал.

Обычно на сайте стоит одно из двух; оба сразу `webx:theme:check` не запрещает, но предупреждает.

Классы: `webx-contact-button`, `__toggle`, `__list`, `__item`, `--<канал>`; `webx-contact-bar`,
`__item`.

### 12.5 Соцсети

тема может заменить любую своей. Ссылки — `rel="noopener"`, с подписью для скринридера.

## 13. Переключатель языка

`<x-webx-language-switcher />` — для мультиязычного сайта; на одноязычном не печатает ничего.

- Ссылки ведут на **ту же страницу** на другом языке — адреса берутся из реестра `routing` (тот же
  источник, что `hreflang`), а не на главную. Нет перевода — ведёт на главную того языка и помечает
  это (`is-fallback`), чтобы тема могла показать иначе.
- Вид: `dropdown` (§6.3) или `list` в ряд; подпись — название языка на нём самом («Deutsch»,
  «Polski»), код — опционально. Флагов по умолчанию нет: флаг — страна, а не язык.
- `hreflang` и `lang` у каждой ссылки; текущий язык — `aria-current`.
- В мобильном меню (§6.1) — в `top` или `bottom` по выбору темы.

Классы: `webx-language-switcher`, `__current`, `__list`, `__link`, `is-current`, `is-fallback`.

## 16. Тесты

- PHP: компоненты рисуются с нужными классами и `data-*`; `Widgets::need` печатает только заявленное;
  заглушка вместо видео и карты без согласия и `iframe` с согласием (сервер читает cookie);
  `Consent` — версия политики, GPC.
- PHP: нормализация телефонов в E.164 и отказ без кода страны; статус часов работы на границах
  интервалов, в выходной, в исключение и в другом часовом поясе; переключатель языка ведёт на ту же
  страницу и помечает `is-fallback`; форма в окне печатается один раз на slug.
- vitest: поведения — клавиатура, фокус, ARIA; выпадающая панель — переворот у края, одна открытая; согласие — включение `text/plain`-скриптов и
  `data-src`, Consent Mode, событие; размонтирование освобождает Swiper/PhotoSwipe/Leaflet.
- Сборка: бюджет веса (§4).
- Браузер (не jsdom): мобильное меню на 375px — тело прокручивается, страница под ним нет, низ виден целиком (замер `getBoundingClientRect` низа против `innerHeight`), фокус не уходит за панель; шапка с `collapse="auto"` прячет меню ровно тогда, когда пункты не помещаются (ширина навигации против ширины шапки), а переход по якорю под липкой шапкой оставляет заголовок видимым (`getBoundingClientRect().top` цели не меньше `--webx-header-height`); слайдер в узкой колонке и на всю ширину — число видимых слайдов по ширине
  контейнера; без JS — лента прокручивается; лайтбокс на телефоне; баннер на 360px не закрывает
  больше трети экрана; в тёмном пресете контраст кнопок баннера.

### 16.1 Где проверяем

На стартовом сайте и его витрине — спека тем, §18.1–§18.5: каждый виджет получает страницу витрины
со всеми вариантами и крайними случаями, браузерные замеры выше входят в локальный прогон Playwright
(`pnpm test:starter`), жесты и iOS — на копии стартового сайта на хомлабе. Этап виджетов без страницы
витрины и без своих замеров в прогоне не закрыт.

## 17. Формы — в `module-inbox`, не здесь

Чего формам не хватает, чтобы закрыть «из проекта в проект», — отдельной правкой inbox, а не
виджетом:

- проверка в браузере до отправки **теми же правилами**, что на сервере: правила полей уже описаны,
  их отдаёт манифест формы, `inbox.js` проверяет на `blur` и при отправке;
- маски ввода (телефон в международном формате, дата);
- загрузка файлов: перетаскивание, прогресс, превью, отмена — на сегодняшнем приёме файлов;
- hCaptcha третьим драйвером рядом с reCAPTCHA и Turnstile; капча — с учётом согласия (Turnstile и
  hCaptcha — `necessary`, reCAPTCHA — по решению сайта).

Вид формы — классы `wx-form`, `wx-form--<placement>` и базовый CSS модуля, как у любого модуля (§10 спеки тем).

## 19. Отложено и открытые вопросы

- **Блок `site-header`** — шапка, собранная в панели (зона `header`), с поведением виджета §6.2:
  поля «логотип», «какое меню», «кнопки». Когда кто-то правда захочет собирать шапку в панели.

- **Журнал согласий на сервере** — доказательство «посетитель согласился тогда-то на то-то». Нужен
  ли — зависит от того, что потребует первый сайт с рекламой; таблица и отпечаток без персональных
  данных.
- **Сканер cookie** — какие cookie сайт на самом деле ставит, чтобы список в диалоге не врал. Хороший
  кандидат в `module-audit`: снимок страницы уже есть.
- **Вторая очередь** — делать, когда попросит второй сайт:
  - **фильтр сетки** — портфолио и кейсы с фильтром по категориям на странице, с анимацией
    перестройки;
  - **промо-окно** — по таймеру, при уходе со страницы, по прокрутке; «не чаще раза в N дней»;
    содержимое — место `popup` в `module-banners`, виджет — только показ и частота;
  - **прогресс чтения** — полоска над статьёй;
  - **«скопировать»** — у почты, промокода, реквизитов.
- **Что ещё повторяется** — сверх §14 и второй очереди добавлять, когда два сайта попросят одно и
  то же, а не заранее.
- **Хлебные крошки — отдельной задачей, не виджетом.** Сейчас у модулей свои вьюхи
  (`webx-catalog::breadcrumbs`, страницы блога, бренды). Это не интерактив, а разметка плюс
  `BreadcrumbList` в микроразметке — место ей в `routing` или `module-seo`: одна вьюха, которую
  модули зовут со своим списком, тема перекрывает, SEO печатает разметку.
- **Не делаем:**
  - **панель доступности** (крупный шрифт, контраст поверх сайта) — такие оверлеи критикуют сами
    специалисты по доступности; путь — доступная вёрстка (правила 29–31 спеки тем) и аудит;
  - **встраиваемые отзывы Google и подобные** — сторонний скрипт, cookie и чужая вёрстка; отзывы — это
    `module-reviews`;
  - **онлайн-чаты** (Jivo, Tawk и т. п.) — не виджет: сторонний скрипт оборачивается в
    `<x-webx-consent category="…">` (§9.3), этого достаточно;
  - **запись на приём** — модуль, не виджет.
- **Поиск по сайту, корзина, сравнение** — им нужны свои модули; этап магазина.

## 20. Как легло в код

### W1.1 — пакет, загрузка по требованию, общий runtime, лёгкие поведения

Пакет `php/packages/widgets` (`WebxUi\Widgets`), без таблиц, требует `webx-ui/themes`.

- **Нижний слой цепочки — через движок тем, а не мимо него.** В `webx-ui/themes` два шва:
  `Contracts\HeadPart` (тег `webx-themes.head`) — что пакет ниже тем печатает в `@webxTheme` после
  токенов и **до** CSS слоёв, то есть первым в каскаде; `BottomLayers` — пакеты ниже тем со своим
  `dist/`, которые `webx:theme:sync` выкладывает рядом со слоями темы тем же хешированным каталогом
  (`public/themes/webx-ui/widgets/<hash>/`). Движок по-прежнему не знает ни одного имени, и тот же шов
  возьмёт базовый вид модулей (§10.2 спеки тем, TH3). Вьюхи компонентов перекрываются в
  `<слой>/views/vendor/webx-widgets/` сами — провайдер тем перестраивает любое пространство имён.
- **`Widgets`** (scoped) — `need($name)`, `claimed()`, `finish($html)`; фасад
  `WebxUi\Widgets\Facades\Widgets`. Имя, которого нет ни в runtime, ни в `dist/`, — исключение:
  опечатка в шаблоне иначе была бы виджетом, который молча не стартует.
- **`@webxTheme` раскрывается лениво — маркером.** С компонентами голова печатается после
  содержимого, но **до** шапки и подвала, а шапка — первый, кто заявит виджет (W1.2). Поэтому
  `head()` печатает `<!--webx-widgets-->`, а слушатель `RequestHandled` — когда вся страница
  отрисована — меняет его на `<link>` и ставит `<script type="module">` перед последним `</body>`.
  Только HTML с маркером: JSON со страницей внутри строки (предпросмотр) остаётся JSON. Страница,
  отрисованная вне запроса, держит маркер — HTML-комментарий. Второй `@webxTheme` не печатает ничего
  дважды. Заявки сбрасываются после каждого ответа (долгоживущий воркер).
- **Runtime — на каждой странице сайта с темой**, а не «ничего для страницы без виджетов»: §4 сам
  говорит, что атрибутный путь заявить нечем, поэтому поведения — в общем runtime, который грузится
  всегда. Собственные файлы виджета (`dist/<name>.js|css`) — только у заявленных. Сайт без темы
  (`--no-theme`) не получает ничего: `@webxTheme` без темы молчит, как и раньше.
- **`window.webx` общий с рантаймом блоков.** Каждый оборачивает `mount`, который нашёл, поэтому
  `webx.mount(root)` поднимает и блоки, и виджеты — в любом порядке загрузки. Рантайм блоков для этого
  поправлен: раньше он **заменял** `window.webx` целиком, теперь дополняет. `webx.unmount(root)`
  вызывает очистку каждого виджета; `webx.widget(name, selector, setup)` — регистрация, `setup(el)`
  возвращает очистку. Монтирование идемпотентно (по элементу и имени).
- **Поведения §6** — `data-webx-disclosure` (Esc и клик мимо закрывают, фокус — на кнопку; без JS
  панель видна — прячет её runtime), `data-webx-dialog` (`showModal()`: страница за окном инертна —
  это и есть ловушка фокуса; Esc, клик по подложке, `[data-webx-dialog-close]`; фокус — опенеру;
  `html.webx-scroll-locked` с `scrollbar-gutter: stable`; адрес с `#<id>` открывает окно при
  загрузке), `data-webx-tabs` (заголовки панелей → `role="tablist"`, стрелки по кругу, Home/End,
  roving `tabindex`; открывается панель, в которую ведёт якорь адреса, или
  `data-webx-tab-selected`), `data-webx-accordion="single"` (на `<details>`, одна открыта).
  Компоненты — `<x-webx-dialog id title close>`, `<x-webx-tabs label>` и `<x-webx-tabs.panel title
selected level>`; заявляют себя при рендере.
- **Без JS** — `html.webx-js` ставит runtime; до него окно показывается через `:target`
  (`html:not(.webx-js) .webx-dialog:target`), вкладки — заголовки над панелями, раскрывашка видна.
- **CSS — один плоский класс на правило, а не `:where()`** (находка в браузере). Проза `theme-default`
  написана в `:where()` ровно затем, чтобы компонент со своим классом побеждал её без усилий, как
  блок `.b-<slug> h2`; каркас виджета в `:where()` проигрывал ей — заголовок окна внутри `<main>`
  получал отступ 48px и размер `h2` прозы. Поэтому правило виджета — `.webx-<имя>__<элемент>`, с
  состоянием не больше (0,1,0–0,2,0): прозу бьёт, а тема перекрывает тем же классом — она позже в
  каскаде. Только токены словаря и свои токены словаря и свои `--webx-<имя>-*`, объявленные
  на `:where(:root)` из `--site-*` (тема перекрывает на `:root` или на классе), без буквальных
  цветов, запасных значений в `var()` и `@media` по ширине. Подложка окна —
  `color-mix(in srgb, var(--site-color-text) 55%, transparent)`.
- **Сборка** — `vite.config.js` как у `theme-default`: вход `resources/js/runtime.js` (CSS
  импортируется им) → `dist/runtime.js` + `dist/runtime.css`, `dist/sources.json` — хеши
  `resources/js` и `resources/css` без `*.test.*`. `dist/` закоммичен (`!php/packages/widgets/dist/`).
  Вес runtime сейчас ≈2,9 КБ gzip из 16.
- **Слова** — `webx-widgets::widgets.dialog.close` на 10 языках; любое перекрывается пропсом.
- **`webx:setup`** ставит виджеты по умолчанию: §11 спеки тем говорит «`theme-default` зависит от
  `widgets`», и это зависимость в её `composer.json`, а не шаг установки.
- **Тесты** — PHP: `LoadingTest` (runtime на странице, поздняя заявка всё равно в `<head>`, заявки
  не переживают запрос, не выложено — только подсказка в debug, JSON нетронут, опечатка — исключение,
  второй маркер), `ComponentsTest`, `ViewOverrideTest` (четвёртая дверь), `NoThemeTest`, `DistTest`
  (`dist/` собран из исходников, бюджет 16 КБ, правило токенов и плоских классов, паритет словарей);
  `themes`: `HeadPart` между токенами и слоями, sync нижнего слоя. vitest
  (`php/packages/*/resources/js/**/*.test.js` добавлен в `vitest.config.ts`): общий `webx` с
  блоками, идемпотентность и размонтирование, клавиатура и ARIA вкладок, якорь, раскрывашка, окно и
  возврат фокуса, аккордеон. `php-smoke.sh` и `starter-site.sh` проверяют `runtime.js` на главной.

- **Проверено в браузере** на пересобранном стартовом сайте (`starter-site.sh` зелёный, главная
  несёт `runtime.css` в `<head>` и `runtime.js` перед `</body>`): на 360px вкладки — список 44px,
  прокручивается внутри себя (584 против 328), страница без горизонтальной прокрутки; окно 328px с
  полями по 16px, крестик 44px, в цветах `night` фон и текст окна из токенов; Esc/крестик/`close()`
  снимают блокировку и возвращают фокус; стрелки ведут по вкладкам. Две находки исправлены здесь же —
  плоские классы (выше) и блокировка прокрутки, которая держалась на событии `close`: его не получает
  скрытая вкладка, поэтому окно следит за атрибутом `open` (`docs/pitfalls/layout-and-browser.md`).

Отступления от спеки:

- **Страницы витрины у W1.1 нет.** Блоки демо — только `hero`/`text`/`columns`, тело `text` —
  простой текст, а своего блока у виджетов этого этапа нет (§15.1 — галерея, видео, карта, логотипы).
  Первая страница витрины — шапка и мобильное меню W1.2, через саму тему. Поведения проверены в
  браузере на стартовом сайте вставкой разметки и `webx.mount()`.
- **Playwright (`pnpm test:starter`)** — с W1.2: у W1.1 нечего мерить на страницах витрины.
- Иконка закрытия окна — символ `×`, а не спрайт: спрайта цепочки ещё нет (TH2).

### W1.2 — мобильное меню и шапка

- **`<x-webx-mobile-menu>`** — корень `display: contents` с настройками в `data-*`, триггер (ссылка
  на `#<id>`, по умолчанию `webx-mobile-menu`) и `<dialog>` трёх зон. Открывает его поведение
  `dialog` W1.1 — модальность, ловушка фокуса, блокировка прокрутки, возврат фокуса, — а скрипт
  меню добавляет телефонное: ссылка внутри закрывает меню (якорь на той же странице тоже),
  «Назад» закрывает через запись в истории, свайп в сторону `side` закрывает, панель идёт за
  пальцем. Открыто ли меню, читается по атрибуту `open`, как в W1.1. Ссылку при открытой записи
  истории меню перехватывает и ведёт по ней **после** того, как запись снята (`history.back()` →
  `popstate`): иначе новая страница легла бы поверх записи меню, и «Назад» с неё вёл бы сначала
  на меню. Без записи (`:history="false"`) ссылка просто закрывает меню и идёт дальше.
- **`breakpoint` и `collapse` пишутся в `<style>` рядом с компонентом**, а не токеном
  `--webx-header-collapse`: условие контейнерного запроса не читает custom property. У меню —
  `@container (min-width: N)` прячет триггер; у шапки — `@container webx-header (width < N)`
  под `html:not(.webx-js)`, то есть только без JavaScript: со скриптом решает замер.
- **`<x-webx-mobile-menu.nav>`** — оба режима на `<details>`, поэтому без JavaScript ветка
  открывается на месте в обоих. В `drill` открытая ветка ложится поверх родителя (абсолютный
  уровень, у списка родителя `is-drilled` — `visibility: hidden`, чтобы его пункты не ловили
  фокус), сверху «Назад» и имя раздела ссылкой на его страницу; в `accordion` страница раздела —
  первый пункт ветки. Ветка текущей страницы открыта (`open` на сервере), в `drill` меню
  открывается сразу на ней.
- **`<x-webx-header>`** — сетка `brand nav actions trigger` (`auto minmax(0, 1fr) auto auto`) на
  `.webx-header__bar`. `collapse="auto"` меряет, а не угадывает: снять `is-collapsed`, проверить,
  что каждый пункт навигации лежит внутри `nav` в одну строку, а `brand` и `actions` — внутри
  полосы, вернуть, если нет, — в одном кадре, без мерцания, при любой сетке темы. Наблюдатель
  размеров только назначает пересчёт на следующий кадр: свёртывание меняет размер того, за кем он
  следит. `is-collapsed` ставится на корень, навигацию, действия и триггер — состояние, которое
  меняет вложенное, едет на сам элемент, а не цепочкой (правило плоских классов W1.1).
- **Высота** — `--webx-header-height` (что остаётся на экране, когда шапка липнет: шапка без
  topbar) и `--webx-header-topbar-height` на `:root`. Липкая шапка стоит с
  `top: calc(-1 * topbar)` — topbar уезжает, полоса остаётся. Якоря — `scroll-padding-top` на
  `html.webx-header-sticky`, а не `scroll-margin-top` у каждой цели: правило виджета — один класс,
  а целью якоря бывает что угодно. `overlay` — отрицательный нижний отступ на полную высоту:
  работает и с липкой шапкой.
- **`hide-on-scroll`** не прячет шапку, пока внутри есть `.is-open`, открытый `<dialog>` или фокус
  с клавиатуры (`:focus-visible`, а не `:focus-within`: после щелчка мышью по триггеру фокус
  остаётся на нём, и шапка не пряталась бы никогда). Фокус, вошедший в спрятанную шапку,
  показывает её.
- **Меню из частей шапки.** `<x-webx-header.nav>` отдаёт своё дерево шапке через scoped
  `HeaderNavigation`: Blade рисует слоты раньше вьюхи компонента, поэтому к вьюхе шапки дерево
  уже есть, и тело меню — `<x-webx-mobile-menu.nav>` по тому же дереву, а не копия десктопной
  разметки с выпадашками. Навигация своей разметкой копируется в тело как есть. `brand` — наверх,
  `actions` и `mobile-bottom` — вниз.
- **Пункты** — `WebxUi\Widgets\Menu\Item`: читает и `MenuLink` из `module-menu` (по тому, что
  он несёт, а не по классу — библиотека не требует модуль), и массивы
  `['label', 'url' | 'attrs', 'children', 'current', 'variant']`; у массива без `current` текущим
  считается адрес текущей страницы.
- **Выпадашки** — ссылка пункта ведёт куда ведёт, рядом кнопка-переключатель (у пункта без адреса
  переключатель — сам пункт). Мышь: открытие через 120 мс, закрытие через 300 мс после ухода;
  при открытой выпадашке соседний пункт не перехватывает, пока курсор в треугольнике от точки,
  где он был, до верхних углов панели. Тач: первое касание открывает, второе идёт по ссылке.
  Клавиатура: Enter/пробел на переключателе, ↓ ↑ внутри, ← → по верхнему уровню, Esc закрывает и
  возвращает фокус, Tab наружу закрывает. Выпадашка, которая вылезла бы за правый край окна, —
  `is-flipped`. `mega` — по ключу (адрес пункта без слэшей или его имя) вьюха темы с `$item`,
  панель на ширину полосы. Без JavaScript выпадашка открывается на `:hover` и `:focus-within` —
  через локальный токен `--webx-header-nav-panel`, который наследуется вниз.
- **Правило плоских классов расширено на одно состояние или модификатор того же элемента**
  (`.webx-header.is-hidden`, `.webx-header--overlay.is-scrolled`) — то, что §20 W1.1 и называл
  0,2,0; `DistTest` это и проверяет. Цепочек по-прежнему нет.
- **Вес runtime** — 7,9 КБ gzip из 16 (было 2,9): меню и шапка ≈5 КБ, в бюджете §6.1/§6.2.
- **Слова** — `mobile_menu.open|close|title|back`, `header.skip|nav|submenu` на 10 языках.
- **`theme-default`** — фолбэк зоны `header` теперь `<x-webx-header class="site-header"
sticky="sticky" mode="drill" :skip="false">`: ссылка «к содержимому» остаётся в лейауте — она
  нужна и тогда, когда зону заполнили в панели. `menu('header')` — вложенным деревом; пункт вида
  `button` — призыв к действию в `actions` (`site-header__cta`), а не пункт навигации; без меню —
  опубликованные страницы под главной, как было. Из `shell.css` ушли правила шапки — остались
  `site-header__title` и `site-header__cta`.
- **Демо.** Находка на стартовом сайте: демо `module-blocks` заполняло зоны `header` и `footer`
  своими блоками на любом сайте, и шапки темы на сайте с темой не было видно вовсе. Теперь при
  активной теме (`ThemeDemo::themed()`) демо оставляет зоны пустыми — у темы шапка и подвал уже
  есть (это то, что §15.1 спеки тем называет «зоны сеются из слоя»; свои `regions/*.json` у
  темы — позже). Смоук ждёт на главной шапку темы. Демо меню вкладывает созданные страницы под
  их родителей в шапке (подвал — по-прежнему только верх): выпадашкам и веткам меню есть что
  показать.
- **Витрина** — «Kitchen sink › Header and menu» (что пробовать) с «Second level › Third level» —
  три уровня для `drill`, и «Services» с восемью страницами — длинная выпадашка и ветка меню,
  которая прокручивается в своём теле.
- **`pnpm test:starter`** — Playwright по стартовому сайту, `tests/starter/`, локально, не в CI;
  браузер — Edge, который есть на Windows (ничего не качает; `PW_CHANNEL=chromium` — свой).
  Страницы — все, на которые ссылается шапка. Замеры: нет горизонтальной прокрутки на 360px; меню
  на 375×520 — тело прокручивается колесом, `scrollY` страницы не меняется, низ панели и зоны
  `bottom` не ниже `innerHeight`, 25 нажатий Tab не выводят фокус на страницу, Esc возвращает
  его на триггер и снимает блокировку, «Назад» закрывает меню без ухода со страницы, ссылка
  закрывает, `drill` открыт на ветке страницы и «Назад» поднимает; шапка от 1600 до 360px с шагом
  40 — `is-collapsed` ровно тогда, когда brand + навигация + actions + три зазора больше полосы
  (замер ширины при 1600); якорь под липкой шапкой на 375 и 1280 — верх цели не выше
  `--webx-header-height` и низа шапки; выпадашка по наведению и с клавиатуры. Отчёт со снимком
  каждой страницы на 375 и 1280 в каждом пресете — `tests/starter/report/`.
- **Тесты** — PHP `MenusTest` (разметка меню и навигации, `drill`, шапка со всеми слотами, без
  меню, со своим меню, `collapse` числом, отказы, текущий пункт массива); `module-blocks`
  `DemoTest` — тема оставляет зоны; `module-menu` `DemoTest` — вложенность в шапке. vitest
  `menus.test.js` — история и «Назад», ссылка внутри, свайп, `drill`, клавиатура и тач выпадашек,
  задержки и коридор, переворот у края, свёртывание числом и замером, высоты на `:root`,
  `hide-on-scroll`.

### W1.3 — согласие на cookie

- **Баннер печатает сам пакет, а не компонент в лейауте.** §4 говорит «заявлен на каждой
  странице» — значит, его не нужно ставить и нельзя забыть: `Widgets::finish()` при опубликованном
  `dist/consent.js` заявляет `consent` и кладёт перед `</body>` вьюху `webx-widgets::consent`
  (баннер и диалог `#webx-consent`) — перекрывается в `<слой>/views/vendor/webx-widgets/consent.blade.php`.
  Свой файл `dist/consent.js|css` — второй вход Vite, ничего не импортирует из runtime (иначе общий
  чанк — лишний запрос на каждой странице; `DistTest` проверяет список файлов `dist/`). Вес ≈2,9 КБ
  gzip из 6. Не опубликовано — ни баннера, ни скрипта, как и стилей.
- **Баннер напечатан с `hidden`, показывает его скрипт**, когда в cookie нет ответа на текущую
  версию: ответивший не видит мигания, а страница без JavaScript — кнопок, которые не работают
  (без JavaScript и стороннее не включается — спрашивать не о чем). Ссылка в подвале без
  JavaScript спрятана тем же правилом `html:not(.webx-js)`.
- **Ответ** — cookie `webx_consent` (`Path=/`, `SameSite=Lax`, `Max-Age` — `lifetime` дней,
  `Secure` на https): `{"v": <версия>, "d": "<дата>", "c": [<категории>]}`, пишет скрипт.
  Сервер читает его в `WebxUi\Widgets\Consent` (scoped, фасад `Facades\Consent`): `has()`,
  `answered()`, `answer()`, `gpc()`; ответ на другую версию — не ответ. Laravel шифрует cookie —
  `webx_consent` внесён в `EncryptCookies::except`, иначе сервер не прочёл бы ответ скрипта (и
  наоборот). Ответ сбрасывается после каждого запроса, как заявки виджетов.
- **«Принять всё» и «Отклонить всё» — один элемент с одним классом** `webx-consent__button`;
  «Настроить» — `data-webx-dialog="webx-consent"`, то есть открывает его поведение `dialog` из
  runtime (ловушка фокуса, Esc, возврат фокуса), своего окна у согласия нет. В диалоге —
  переключатели (`input type="checkbox" role="switch"`), «Отклонить всё», «Сохранить выбор»,
  «Принять всё». Баннер — у низа окна, `max-height: 100dvh / 3`: текст прокручивается внутри,
  кнопки остаются.
- **Какие категории предлагать.** Выбранные в настройках; если не выбраны — те, о которых что-то на
  сайте просит: сервер ищет `data-webx-consent="<категория>"` в отрисованной странице и помнит
  найденное в кэше (`webx-widgets.consent.seen`) — счётчик на одной странице включает строку
  «Статистика» в диалоге на всех; скрипт показывает и ту, о которой просит текущая страница, и уже
  разрешённую (разрешённое должно быть видно, чтобы его забрать).
- **Что ждёт согласия:** `script type="text/plain"` пересоздаётся (у перенесённого парсером
  скрипта флаг «уже запущен» — выполняется только новый; настоящий тип — в `data-webx-type`,
  внешние — с `async = false`, порядок как в разметке), `iframe` получает `src` из `data-src`,
  `<template data-webx-consent>` — то, что печатает `<x-webx-consent category>` без согласия, —
  распаковывается со скриптами. С согласием сервер печатает содержимое `<x-webx-consent>` как есть.
  Всё это — виджет `consent-blocked` через `webx.widget`, поэтому работает и в куске страницы,
  догруженном позже (`webx.mount`). Отзыв (из разрешённого что-то пропало) пишет cookie и
  перезагружает страницу. Баннер выключен — разрешено всё, скрипт всё равно грузится: он и
  включает ждущее.
- **Google Consent Mode v2** — `consent default` печатается в `<head>` до слоёв (сервер знает
  ответ из cookie: разрешённое — `granted`, остальное — `denied`, `security_storage` — всегда),
  через `dataLayer.push(arguments)`, как это делает `gtag()`: он раньше любого тега Google и
  безвреден, где Google нет. `consent update` после ответа — через `gtag`, а если его ещё нет — в
  тот же `dataLayer`. Соответствие: `statistics` → `analytics_storage`, `marketing` →
  `ad_storage`, `ad_user_data`, `ad_personalization`, `preferences` → `functionality_storage`,
  `personalization_storage`.
- **GPC** — заголовок `Sec-GPC: 1` (сервер, `data-gpc` на корне) или
  `navigator.globalPrivacyControl`: «Принять всё» не включает `marketing`, в диалоге строка «ваш
  браузер просит не отслеживать»; включить руками можно.
- **API** — `webx.consent.has(category)`, `.categories`, `.set([...])`, `.open()`; событие
  `webx:consent` на `document` с `{ categories }`.
- **Настройки.** Без `module-settings` — `config/webx-widgets.php` (`consent.enabled`, `version`,
  `policy` — адрес, `categories`, `texts` по языкам, `lifetime`). С ним — вкладка «Cookie» в
  `settings.index` патчем экрана `resources/screens/settings.consent.json` из провайдера пакета (как
  вкладка SEO; патч на незарегистрированный экран не применяется, поэтому без модуля ничего не
  ломается): баннер вкл/выкл, страница политики (`wx-link` — выбор страницы сайта), версия,
  «Спросить всех заново», категории (`wx-checkbox-group`), тексты баннера и каждой категории —
  `localized`, плейсхолдер — слово словаря. Ключи `consent.*` — обычные настройки, поэтому
  `settings_get` / `settings_set` по MCP их видят без единой строчки. Непустая настройка важнее
  конфига. Слова панели — `lang/<10>/panel.php`, `DistTest` проверяет паритет и их.
- **Слова** — `widgets.consent.*` (кнопки, «Настройки cookie», категории, тексты по умолчанию) на 10
  языках.
- **`theme-default`** — в подвале всегда есть `<nav class="site-footer__nav">` с
  `<x-webx-consent-link class="site-footer__link">` последним пунктом (баннер выключен — ссылки
  нет).
- **Витрина** — «Kitchen sink › Cookie consent»: что пробовать (отклонить, настроить, ссылка в
  подвале, отзыв с перезагрузкой, удалить cookie, чтобы начать заново), GPC, разметка для сайта.
- **Тесты** — PHP `ConsentTest` (баннер с `hidden` на каждой странице, одинаковые кнопки,
  `necessary` включён и выключить нельзя, категории со страницы и запомненные, выбранные в
  настройках, ответ только на текущую версию, cookie не шифруется, выключенный баннер, GPC, Consent
  Mode по ответу, `<x-webx-consent>` до и после, опечатка в категории, ссылка, слова и политика),
  `ConsentSettingsTest` (вкладка на экране, значения по умолчанию, настройки по MCP, «Спросить всех
  заново»), `LoadingTest` — `consent.js` на каждой странице, `DistTest` — бюджет 6 КБ и отсутствие
  общего чанка. vitest `consent.test.js` — показ до ответа и после смены версии, «Принять всё» и
  событие, сохранение из диалога, предлагаемые категории, GPC из заголовка и из `navigator`,

- **`pnpm test:starter`** — на странице витрины: баннер на 360×640 и 360×740 не выше трети экрана,

### W1.4 — выпадающая панель и форма в окне

- **`<x-webx-dropdown placement open-on label open>`** со слотом `trigger` — `<details>` с
  `<summary class="webx-dropdown__trigger">` (атрибуты слота едут на него) и
  `.webx-dropdown__panel`. Без JavaScript это и есть §6.3: щелчок открывает панель под кнопкой,
  место задают локальные токены модификатора `--<placement>`
  (`--webx-dropdown-top|bottom|left|right|shift`): правило — один класс, и модификатор корня не
  дотянется до панели цепочкой. Со скриптом состояние по-прежнему `details.open` — раскрытие
  скринридер читает с `<summary>` сам, `aria-expanded` и `aria-controls` скрипт ставит поверх.
  Опечатка в `placement` или `open-on` — исключение.
- **Панель — `popover="manual"` там, где браузер умеет**, показывается вместе с `details.open`:
  верхний слой, `overflow: hidden` и `z-index` предков (липкая шапка, карточка) не мешают. Место
  считает скрипт — `fixed` от прямоугольника кнопки: снизу нет места, а сверху есть — вверх;
  `start` вылезает за правый край — по правому краю кнопки, `end` за левый — по левому
  (`is-flipped`); шире обеих сторон — прижата внутрь окна. Пересчёт на прокрутке и изменении
  размера — только пока открыта. Без `popover` — то же самое `absolute` внутри `<details>`.
- **`hover`** — открытие через 120 мс, закрытие через 300 мс после ухода; щелчок той же мыши
  сразу после открытия наведением не закрывает. Коридор курсора теперь общий с выпадашками шапки
  (`behaviours/corridor.js`). Тач и перо — всегда `click` (по `pointerType`).
- **Одна открытая на странице**; Esc закрывает и возвращает фокус на кнопку, если фокус был
  внутри; Tab наружу (`focusout` с `relatedTarget` снаружи) и щелчок мимо закрывают.
  Напечатанная с `open` открывается скриптом сразу — с местом и счётом.
- **Форма в окне — `FormDialogs`.** Открывающий — `<a>` или `<button>` с
  `data-webx-form="<slug>"` **или ссылка на `#webx-form-<slug>`**: второе вписывается в пункт
  меню или кнопку блока в панели, без шаблона. Сервер находит открывающих в отрисованной странице
  (как согласие — категории), `Widgets::form('<slug>')` — для открывающего, которого сервер не
  печатает. `<form data-webx-form>` самого inbox — тот же атрибут на другом конце, открывающим не
  считается. Каждый slug — один `<dialog id="webx-form-<slug>" class="webx-dialog
webx-form-dialog">` перед `</body>`: заголовок — название формы, внутри
  `<x-webx-inbox::form :form placement="modal">` (вьюха `webx-widgets::form-dialog`,
  перекрывается). Нет `module-inbox`, нет формы с таким slug или она выключена — окна нет,
  ссылка остаётся ссылкой.
- **Окна вставляются в `ResponsePrepared`, а не в `RequestHandled`.** К `RequestHandled`
  `StartSession` уже сохранил сессию и выбросил flash: форма, отправленная без JavaScript,
  вернулась бы без «спасибо» и без ошибок. Роутер шлёт `ResponsePrepared` дважды — внутри
  middleware и снаружи; окна идут на первом (`Widgets::withDialogs()`, раз за ответ), `finish()`
  вставляет их сам, если ответ прошёл мимо роутера. Страница, вернувшаяся с ответом этой формы
  (flash `webx-inbox` с её slug или старый ввод с `webx_placement=modal`), печатает окно с `open`
  — со скриптом оно снова открывается модально, без него стоит поверх страницы.
- **Скрипт окна** — в runtime: открывающий зовёт `openDialog()` поведения `dialog` (модальность,
  ловушка фокуса, блокировка прокрутки, возврат фокуса). `data-webx-form-value-<поле>` пишет в
  `fields[<поле>]` формы, следующий открывающий без него получает поле как напечатано. «Спасибо»
  показывает `inbox.js` (снимает `hidden` с `[data-webx-message]`) — окно следит за этим
  атрибутом, прячет остальное содержимое формы и показывает «Закрыть»
  (`webx-form-dialog__done`, фокус на ней), `is-sent`; закрытое окно — снова свежая форма.
  Скрипт inbox не тронут (§17). Заголовок окна липкий — длинная форма прокручивается под ним.
- **Вес runtime** — 9,8 КБ gzip из 16 (было 7,9). Своих файлов в `dist/` у обоих нет: это лёгкие
  поведения §6, атрибутный путь заявить нечем. Новых слов нет — «Закрыть» окна — `dialog.close`.
- **Витрина** — «Kitchen sink › Dropdown and form in a dialog»: два hero с кнопкой на

  выпадающая панель.
- **Тесты** — PHP `FormDialogTest` (одно окно на slug при трёх открывающих, форма `modal` внутри,

  переворот у правого края и вверх, прижатие в узком окне, наведение с задержками и тач,

- **`pnpm test:starter`** (21 из 21) — на странице витрины: ряд выпадашек во всю ширину окна

  раздела лендинга. Пример §6.4 `href="#callback"` пишется `href="#webx-form-callback"`, и такой
  ссылке `data-webx-form` уже не нужен.
- **Открывающих сервер находит сам**, а не только по заявке компонента: кнопку на форму пишут
  руками в шаблоне и в панели, и забытая заявка была бы кнопкой, которая молча ведёт в никуда.
- **CSS anchor positioning не используется** — место считает скрипт во всех браузерах: запасные
  позиции `position-try` не говорят, какую сторону выбрали (`is-flipped` нечем поставить), а один
  путь проще проверить.
- **Выпадашку на витрине руками не потрогать**: блоки демо — только `hero`/`text`/`columns`. На
  витрине она описана и мерится прогоном; живой она появится с телефонами (W1.5) и языками (W1.6)
  в шапке темы.
- **Форма inbox на сайте без стилей** (каркас модулей — TH3): в окне она такая же, как на
  странице.

- **Вкладка «Контакты» — в самом `module-settings`** (`resources/screens/index.json`, между
  «Брендингом» и «Шорткодами»), а не патчем виджетов: это данные сайта, их читают виджеты, SEO и
  шаблоны. Четыре карточки: телефоны и почта, адреса, часы, чаты и соцсети. Ключи —
  `contacts.phones` (`number`, `label` по языкам, `messengers` из WhatsApp/Telegram/Viber/Signal,
  `primary`), `contacts.emails`, `contacts.addresses` (`address` по языкам, `latitude`,
  `longitude`, `map`, `primary`), `contacts.hours` (строки `days` + `opens` + `closes`),
  `contacts.hours-exceptions` (`date`, `label`, `closed`, `opens`, `closes`), `contacts.timezone`,
  `contacts.messengers` (`channel`, `url`, `label`), `contacts.socials` (`network`, `url`,
  `label` для «другой»). Слова панели — `webx-settings::screen.*` на 10 языках.
- **`contacts()`** — `WebxUi\Settings\Contacts\Contacts` (scoped, сбрасывается на `SettingsSaved`):
  `phones()`, `primaryPhone()` (отмеченный или первый), `emails()`, `addresses()`,
  `primaryAddress()` (`mapUrl()` — введённая ссылка или OpenStreetMap по координатам),

  Подписи — на текущем языке. Что контактом не читается (номер без кода, сохранённый до проверки;
  ссылка `javascript:`), пропускается: шаблон не напечатает ссылку в никуда.
- **Номер** — `PhoneNumber` на `giggsey/libphonenumber-for-php-lite` (Apache-2.0, зависимость
  `module-settings`): показывается как введён, `e164` — `+442079460958`, `href` — RFC 3966
  (`tel:+44-20-7946-0958`, с `;ext=12`, которого в E.164 нет). `00` в начале — `+`. Проверка —
  «возможный», а не «действительный»: диапазоны стран меняются быстрее данных библиотеки, и
  отказать настоящему новому номеру хуже, чем пропустить опечатку в длине. Проверка при
  сохранении — `ContactsCheck` рядом с `DataShortcodes::check` в контроллере и в `settings_set`:
  номер без кода, почта, ссылки, неполные строки часов, неизвестный пояс — 422 под путём поля
  строки (`contacts.phones.1.number`: «020 7946 0321 has no country code. Start it with + and the
  code…»), так что панель подсвечивает и раскрывает эту строку, а агент читает строку из ключа.
- **Часы** — `Hours`: интервалы в минутах от начала дня, закрытие раньше открытия — после полуночи
  (22:00–02:00 = `[1320, 1560]`), 00:00–00:00 — весь день; дата из исключений заменяет свой день
  недели. `status()` → `HoursStatus` с `kind()`: `open`, `always` (24/7 — «до» нет: «до полуночи»,
  упирающееся в открытие следующего дня в 00:00, продлевается), `today`, `tomorrow`, `later`,
  `closed`, и с `off-` впереди, когда сегодня выходной. Минута дня — **по настенным часам**
  (`setTime`, а не `addMinutes` от полуночи), и «завтра» — по дате, а не по `diffInDays`: в ночь
  перевода часов в сутках 23 или 25 часов (`docs/pitfalls/laravel-and-php.md`). Вперёд смотрит
  на 14 дней. `rows()` сворачивает подряд идущие одинаковые дни, `upcoming()` — исключения

  предупреждает §12.4. Полоса на витрине мерится вставленной разметкой.

### W1.6 — переключатель языка

- **`<x-webx-language-switcher layout codes placement label fallback-label>`** — `dropdown` (по
  умолчанию: на кнопке выпадашки §6.3 глобус и текущий язык, в панели — все) или `list` в ряд.
  Подпись — название языка на нём самом из `locales.native_name` (`webx-ui/localization` уже
  его хранит, справочник — `LocaleCatalogue`), `codes` добавляет «EN». У каждой ссылки
  `hreflang` и `lang` (`pt-BR`, как в `<head>`), у текущей — `is-current` и
  `aria-current="page"`. Навигация — `<nav aria-label>` словом на языке страницы; подпись
  кнопки — видимый текст, своего `aria-label` у неё нет.
- **Адреса — `LanguageLinks`**, из того же места, что `hreflang` (`Alternates` в `module-seo`),
  но без SEO: страница, которую нашёл реестр (`Resolution::of($request)->entity`), — её
  каноническая строка `routes` в каждом языке, где она показана (`Visible::isVisible($code)`);
  адрес вне реестра (свой маршрут модуля) — тот же путь под префиксом каждого языка. Нет строки,
  скрыта в языке, 404 (маршрут `fallback` без найденной сущности) — главная того языка,
  `is-fallback` и `title` на **языке ссылки** («Jeszcze nie przetłumaczono…»): у `<a lang="pl">`
  и подсказка польская. В отличие от `hreflang`, закрытая от индекса страница переключается —
  читатель не поисковик. Ничего — при одном языке, без `routing`/`localization` (пакет их не
  требует, они в `suggest`) и при `strategy` не `prefix`: у всех языков один адрес, ссылке
  нечего выбрать. `LanguageLinks::current()` — те же ссылки для своей разметки.
- **Своего скрипта нет** — выпадашка runtime'а; свой файл — только `dist/language-switcher.css`
  (вход Vite — сам CSS, JS-обёртки Vite для него не пишет), ≈0,5 КБ gzip из 2 (бюджет в
  `DistTest`, и что `.js` нет). Правило `.webx-icon` переехало из `contacts.css` в runtime:
  глобус переключателя стоит и без контактов. Раскладка корня доходит до списка свойством
  `--webx-language-switcher-direction`, не цепочкой. Иконка `globe` — своя, вьюхой, как
  остальные.
- **Слова** — `widgets.language.label`, `.fallback` на 10 языках; оба — пропсы.
- **`theme-default`** — переключатель последним в `actions` шапки, а значит и внизу мобильного
  меню (§6.1: «bottom» — выбор темы); слот ставится, только когда языков больше одного, ссылки
  считаются один раз и отдаются компоненту `:languages`.
- **Витрина** — «Kitchen sink › Language switcher»: hero с кнопкой на польскую главную, что
  пробовать, откуда адреса, разметка для сайта.
- **Тесты** — PHP `LanguageSwitcherTest`: та же страница на другом языке по строкам реестра
  (псевдоним — не перевод), `is-fallback` с подсказкой на языке ссылки, скрытый в языке перевод
  — не перевод, путь вне реестра под каждым префиксом, 404 — только главные, кнопка выпадашки и
  `codes`, ничего при одном языке и при `header`, опечатка в `layout`; `DistTest` — файл и
  бюджет. Код `module-seo` и `routing` не тронут — их тесты те же.
- **`pnpm test:starter`** — 31 из 31 (27 прежних и 4 новых, на пересобранном стартовом сайте с
  en/ru/pl): на главной три ссылки `English`/`Русский`/`Polski` на `/`, `/ru`, `/pl`, ни одной
  `is-fallback`, у каждой `hreflang` = `lang`, каждая отвечает 200 с `<html lang>` своего языка,
  `aria-current` — только у текущей; с польской главной английская ведёт на `/`. На странице

Отступления от спеки:

- **Своего JS нет** (§13 его и не требовал): выпадашка — runtime'а, переключателю нечего делать

- **В мобильном меню — только внизу**: это копия `actions` шапки (§6.2), и `theme-default`

- **Демо-страницы стартового сайта — на одном языке** (`PagesDemo` пишет язык по умолчанию):
  «та же страница» на витрине проверяется на главной, которая есть на всех трёх, а `is-fallback`
  — на странице витрины. Переводить демо — не задача виджета.
- **`x-default` нет** — это слово `hreflang` для поисковика, не язык для читателя.

### W2.1 — слайдер

- **`<x-webx-slider variant per-view arrows pagination loop autoplay continuous effect thumbs speed
options label id>`** с `<x-webx-slide thumb>` внутри. Вариант — набор настроек в
  `Slider::VARIANTS` (`cards` — 1.2/2/3 на вид, стрелки и точки; `hero` — затухание,
  автопрокрутка 6 с, петля; `gallery` — миниатюры; `logos` — непрерывная лента: петля, задержка 0,

  `options` — всё прочее, что берёт Swiper, как есть. Сервер решает всё и отдаёт скрипту в
  `data-webx-slider` вместе со словами. Опечатка в варианте, эффекте, брейкпоинте, числе на вид,
  `autoplay` или `id` — исключение.
- **«На вид» — по ширине контейнера, одним источником.** `per-view` — число или карта
  брейкпоинтов: `sm` от 0, `md` от 640, `lg` от 960, `xl` от 1280 или ширина в пикселях; самый
  узкий из данных действует с нуля. Компонент пишет `<style>` рядом: `#<id>-track {
--webx-slider-per-view: N }` и `@container webx-slider (min-width: …)` на каждый брейкпоинт
  (условие контейнерного запроса не читает custom property, как у меню W1.2). Это свойство
  задаёт ширину слайда ленте без JavaScript, а скрипт читает его обратно (`getComputedStyle`) при
  старте и в `ResizeObserver` на корне — у Swiper брейкпоинты по окну. Зазор — так же:
  `row-gap` дорожки, который однострочная лента не использует. Тема меняет число на вид тем же
  свойством на своём классе.
- **Swiper без своих классов и стилей.** Swiper 14.2 (MIT, `devDependencies` корня), в
  `dist/slider.js` — `Navigation`, `Pagination`, `A11y`, `Autoplay`, `EffectFade`, `Thumbs`:
  ≈31 КБ gzip из 45 (`DistTest`, и что в `slider.css` нет `.swiper`). Все имена классов Swiper
  переназначены на свои (`webx-slider__track`, `__slide`, `__bullet`, `is-active`, `is-visible`,
  `is-locked`, `webx-slider__viewport--horizontal`, живая область `webx-slider__notice`), его
  стили не грузятся — что ему нужно, написано в `slider.css` по правилу одного плоского класса.
  Затухающему слайду скрипт ставит `webx-slider__slide--fade` (цепочка `.swiper-fade
.swiper-slide` правилу не годится).
- **Без JavaScript** — `.webx-slider__track` с `overflow-x: auto` и `scroll-snap-type: x
mandatory`, слайды по `--webx-slider-per-view`; стрелки, точки и пауза напечатаны `hidden`,
  миниатюры делает скрипт. `is-ready` на корне и дорожке — Swiper взял ленту.
- **Клавиатура — своя, не модуль `Keyboard`:** тот слушает документ и двигает **все** слайдеры
  в окне; здесь стрелки, Home и End двигают тот, в котором фокус. Ссылка в слайде за краем при
  фокусе выводит свой слайд (`A11y`). Слайды — `role="group"`, `aria-roledescription` словом
  языка, имя «2 / 8»; корень — `<section aria-roledescription="carousel" aria-label>`.
- **Автопрокрутка (WCAG 2.2.2)** — кнопка паузы у всего, что движется само (`hero`, `logos`, любой
  `autoplay`), 44px; пауза на время наведения и фокуса внутри; остановленная кнопкой не
  возобновляется уходом курсора. При `prefers-reduced-motion` не стартует, скорость 0, кнопка
  предлагает «Play».
- **Петля непрерывной ленты** — Swiper без копий петлю не крутит, когда слайдов мало: скрипт
  дописывает копии с `aria-hidden` и `inert`, размонтирование их убирает.
- **Ленивые картинки** — `Sliders` (scoped) держит стек открытых слайдеров: Blade зовёт
  `render()` компонента до слота, а вьюху — после, поэтому слайд берёт свой номер из верхнего
  кадра. Слайды за пределами первого экрана (`ceil` самого широкого «на вид») получают
  `loading="lazy"` у `<img>`, которые не выбрали сами. Тот же сервис даёт id без `id`: хеш слайдов
  и номер повтора.
- **Миниатюры `gallery`** — кнопки со своим `aria-label` и `aria-current="true"` у текущей,
  картинка — `thumb` слайда или его первая `<img>`; второй экземпляр Swiper, `slidesPerView:
'auto'`, размер — `--webx-slider-thumb-size`.
- **Слова** — `widgets.slider.*` (carousel, slide, prev, next, first, last, go_to, position, pause,
  play, thumbs, thumb) на 10 языках; иконки `chevron-left|right`, `pause`, `play` — вьюхами, как у
  контактов.
- **Витрина** — «Kitchen sink › Slider»: карточки на всю ширину и в колонке 20rem, hero,
  галерея на всю ширину и в колонке, логотипы, один слайд, что пробовать, разметка для сайта.
  Блоков, в которых виджет стоял бы на странице, у демо не было (`hero`/`text`/`columns`),
  поэтому `theme-default` несёт демо-тип `demo/blocks/showcase-slider.json`, а `BlocksDemo` теперь
  сеет `demo/blocks/` темы (§15.1 спеки тем: копия темы важнее, свои типы — после трёх). Настоящие
  блоки `gallery` и `logos` — W2.3.
- **Находка в `module-blocks`.** Публикация демо-типа падала «Undefined array key 0»: рендерер
  исполнял шаблон мимо `View::render()`, и вьюха внутреннего компонента сбрасывала стек внешнего.
  Починено в `Renderer::evaluate()` (`docs/pitfalls/laravel-and-php.md`) — любой тип блока с
  компонентом внутри компонента.
- **Тесты** — PHP `SliderTest` (разметка без JS, контейнерные запросы на брейкпоинты, именами и

  слайде, ленивые картинки, `thumb`, два id у одинаковых слайдеров, слова по языку, файлы на

  наведением, фокусом и кнопкой, reduced motion, миниатюры, копии ленты, размонтирование и
  повторный монтаж.
- **`pnpm test:starter`** — 36 из 36 (31 прежний и 5 новых): на 1400, 900, 375 и снова 1280 в
  одном окне — карточки 3/2/1.2 на вид, в колонке 20rem всегда 1.2, ширина слайда = (ширина −

  без JavaScript каждая лента прокручивается и прилипает, слайд по той же формуле, контролы

### W2.2 — лайтбокс

- **Ядро PhotoSwipe, без его модуля `lightbox`.** PhotoSwipe 5.4.4 (MIT, `devDependencies` корня,
  последняя версия, май 2024) — в `dist/lightbox.js|css`: ≈19.6 КБ gzip из 25 (`DistTest`).
  `photoswipe/lightbox` грузит ядро вторым файлом через `import()` — лишний запрос и лишний
  чанк в `dist/`; поэтому скрипт пакета сам ловит клик, собирает группу и создаёт `new
PhotoSwipe({ dataSource, index })`.
- **Стили PhotoSwipe — как есть, перекраска — через его же свойства.** Swiper даёт переназначить
  каждое имя класса опцией, и W2.1 обошёлся без его CSS; PhotoSwipe рисует свой DOM (`.pswp`,
  `__bg`, `__item`, `__button`, `__counter`…) с зашитыми именами — переписать его каркас под
  `.webx-*` нельзя, не переписав саму библиотеку. Поэтому его стилевой файл идёт в
  `lightbox.css` первым, без правок, а вид задаётся его custom properties (`--pswp-bg`,
  `--pswp-icon-color`, `--pswp-root-z-index`…) на `.webx-lightbox` — класс, который скрипт даёт
  корню (`mainClass`), — из локальных токенов `--webx-lightbox-backdrop|color|outline|
placeholder|icon-size|z`, а те — из `--site-*`. Свои правила пакета (ссылка, иконки) — по
  правилу одного плоского класса, как везде. `DistTest` проверяет, что в `dist/lightbox.css` нет
  ничего, кроме `.pswp*` и `.webx-lightbox*` (и кадров его спиннера). Подложка непрозрачная
  (`bgOpacity: 1`) и цвета фона сайта: в `night` — тёмная, в светлом — светлая; просвечивающая
  страница мешала читать счётчик на телефоне (видно на снимке).
- **«Компонент картинки» — `<x-webx-lightbox>`.** Отдельного компонента картинки у
  `module-media` нет: шаблон блока получает значение поля медиа (`url`, `thumb`, `alt`, `width`,
  `height` — размеры записаны при загрузке, `MediaValues::details()`), модуль каталога — фото с
  `url()` и `width`/`height`. Компонент берёт любое из них (`:image`), пропы `src width height
thumb alt` — то же руками или поверх, слот — вместо миниатюры; печатает `<a
class="webx-lightbox-link" href data-webx-lightbox="<group>" data-width data-height>` и зовёт
  `Widgets::need('lightbox')`. Без `url` — исключение (опечатка в шаблоне).
- **Заявка по атрибуту — как у формы в окне.** `Widgets::finish()` ищет в готовой странице
  `<a … data-webx-lightbox>` (`Lightbox::wanted()`, только на ссылке и только этот атрибут) — тем
  же путём, каким `FormDialogs::openers()` находит кнопки форм: ссылка из блока, из вьюхи модуля,
  из партиала темы заявляет лайтбокс без компонента. Там же перед `</body>` один раз печатается
  `<script type="application/json" id="webx-lightbox">`: слова на языке страницы и иконки цепочки
  (`chevron-left|right`, `close` и новая `zoom`) — стрелку темы лайтбокс берёт так же, как
  слайдер.
- **Группы.** Одно значение `data-webx-lightbox` — одна группа, пустое — картинка сама по себе.
  Порядок — порядок страницы, но слайды зацикленного слайдера — по своему номеру
  (`data-swiper-slide-index`): петля Swiper переставляет их в DOM. Копии непрерывной ленты
  (`data-webx-copy`, ставит `slider.js`) в группу не входят.
- **`gallery` слайдера с лайтбоксом.** Ссылка в слайде — обычная `<x-webx-lightbox>`. Перетаскивание
  не открывает лайтбокс: Swiper гасит клик после свайпа своим слушателем в фазе захвата
  (`preventClicks`), и до ссылки он не доходит; скрипт ещё и пропускает клик с
  `defaultPrevented`, с модификатором и не левой кнопкой (новая вкладка — дело браузера). При
  закрытии на другой картинке слайдер встаёт на её слайд — картинка уходит в свою миниатюру.
- **Фокус** возвращается на ссылку **последней показанной** картинки, а не всегда на ту, что
  открыла: пролистал до пятой — Tab идёт от пятой (`returnFocus: false` и свой фокус в
  `destroy`). Ловушка фокуса, Esc, стрелки, щипок и свайп вниз — PhotoSwipe. Корень —
  `role="dialog"` с `aria-modal` и `aria-label` словом языка; его английские `carousel`/`slide`
  заменены словами `widgets.slider.*`. Ссылке скрипт ставит `aria-haspopup="dialog"`.
- **Без размеров** картинка до открытия загружается и меряется (`naturalWidth`), соседние —
  когда до них долистали (`refreshSlideContent`). Работает, но это лишняя загрузка: аудит
  «лайтбокс без размеров» — W4.
- **Размонтирование** снимает слушатели и закрывает открытый PhotoSwipe, если открыт из
  размонтированного; повторный `webx.mount` поднимает снова (vitest).
- **Слова** — `widgets.lightbox.*` (dialog, close, zoom, prev, next, error) на 10 языках
  скриптом Node, как у слайдера.
- **Витрина** — «Kitchen sink › Lightbox» на демо-типе `theme-default/demo/blocks/showcase-lightbox.json`
  (сетка из шести картинок одной группой через `<x-webx-lightbox :image>` со значением, как у поля
  медиа; `gallery` слайдера со ссылками в слайдах; две ссылки руками — высокая 1200×2000 и
  без размеров; что пробовать; разметка для сайта). Картинки — нарисованные SVG в
  `theme-default/assets/showcase/`, публикуются `webx:theme:sync`: страница ничего не просит у
  третьих сторон, а ссылка без JavaScript открывает настоящий файл (на `data:`-адрес с SVG
  страница браузер не переводит).
- **Тесты** — PHP `LightboxTest` (значение медиа и объект с `url()`, пропы поверх, слот, без
  размеров, ссылка в никуда, ссылка руками и компонент заявляют файлы и слова, слова по языку и
  иконки цепочки, атрибут только на ссылке); `DistTest` — список `dist/`, бюджет 25 КБ, чужих
  правил в `lightbox.css` нет. vitest `lightbox.test.js` — группы и пустая группа, порядок
  петли и копии, открытие с ARIA и словами, модификаторы и погашенный клик, Esc и фокус на
  последней, размонтирование и повторный монтаж, замер без размеров (78 из 78).
- **`pnpm test:starter`** — 40 из 40 (36 прежних и 4 новых): на 375×667 картинка 3:2 во всю
  ширину и целиком на экране, высокая — по высоте; свайп мышью и стрелка листают группу
  («2 / 6», «3 / 6»), Esc закрывает и фокус на ссылке третьей; боковой прокрутки нет ни с
  открытым, ни после; открытие с клавиатуры, стрелка назад по кругу («6 / 6»); ссылка без
  размеров открывается в 3:2 на всю высоту; за всё время — ни одного запроса не к сайту; в
  `gallery` перетаскивание двигает слайдер и ничего не открывает, клик открывает «2 / 6»,

- **Проверено в браузере** на пересобранном стартовом сайте (`starter-site.sh` зелёный):

- **«Компонент картинки» из §8 — `<x-webx-lightbox>` этого пакета**, а не компонент

### W2.3 — блоки `gallery` и `logos`

- **Где лежат.** `widgets/resources/blocks/gallery.json` и `logos.json` — документы
  `webx:blocks:export`, как у FAQ и команды. Провайдер предлагает их `BlockOffers` под именем
  `widgets` (`WidgetsServiceProvider::OFFERS`), если есть `module-blocks` и `module-media`: обе
  стоят на полях библиотеки, а тип с полем, которого никто не зарегистрировал, не пережил бы
  сохранения в панели. `webx:setup` раньше ставил предложенное только для выбранных модулей —
  теперь и `--module=widgets`, когда пакет установлен (виджеты приходят с темой, модулем их не
  выбирают). Поставленный тип — сайта: следующая версия пакета его не трогает.
- **`gallery`** — поля: `heading` (`localized`), `pictures` (`wx-gallery`, подписи включены по
  умолчанию), `view` (`wx-segmented`: `grid` | `slider`, `default` — сетка), `columns`
  (`wx-input-number` 1–6, видно только у сетки, `default` 3), `zoom` (`wx-switch`, `default`
  включено). Значения `default` блок читает так же, как панель рисует (`Rendering\Values`), поэтому
  блок, добавленный до появления поля, ведёт себя как новый. Сетка — `<ul>` с
  `repeat(auto-fill, minmax(min(100%, max(9em, …/N)), 1fr))` по ширине **контейнера**: N колонок
  максимум, меньше, где ячейка уже 9em (на 1280 — 3, на 375 — 2). Ячейка — квадратное превью
  библиотеки (`thumb` 320×320 `cover`) с `srcset` на оригинал по его ширине, `loading="lazy"`
  со второго ряда. Слайдер — вариант `gallery` с миниатюрами из того же `thumb`
  (`<x-webx-slide :thumb>`), слайд — оригинал с `width`/`height`. `title` картинки —
  `<figcaption>` под ней, `alt` — её `alt`. Увеличение — `<x-webx-lightbox :image="$picture">`
  со своим `<img>` в слоте, группа `gallery-<ключ блока>` (`$block->key`): две галереи на
  странице листаются каждая своя. Картинка, удалённая из библиотеки (`url` пустой), выпадает;
  блок без картинок не печатает ничего.
- **`logos`** — `heading` и `logos`: `wx-repeater` из `name`, `logo` (`wx-media`, только
  картинки) и `link` (`wx-link`, «никуда» разрешено). Повторитель, а не `wx-gallery`: ссылка у

### W3.1 — видео

- **`<x-webx-video src file poster title ratio>`** (`View\Components\Video`). `src` — адрес YouTube
  или Vimeo, `file` — видео сайта; оба или ни одного, адрес чужой площадки в `src` — исключение
  (опечатка в шаблоне). `poster` и `file` берут то же, что `<x-webx-lightbox :image>`: значение поля
  медиа (`url`, `width`, `height`, `mime`), объект с `url()` или адрес. `ratio` — `16/9`, `4:3`,
  `9 / 16` или число, без него 16/9; печатается в `style="--webx-video-ratio: W / H"` корня, рамка
  держит высоту до любой загрузки, постер, плеер и заглушка стоят внутри неё (`position:
absolute`), поэтому их смена ничего ниже не двигает. Заявляет `Widgets::need('video')`.
- **Площадки — реестр `Video\VideoProviders`** (singleton): `VideoProvider` отвечает на «чей
  адрес» (`find()` → `ProvidedVideo`: id, хеш, секунда старта), «плеер» (`embed()`), «страница
  ролика» (`page()`, ссылка без JS) и «превью» (`preview()`). В пакете `YouTube` (`watch`,
  `youtu.be`, `shorts`, `embed`, `live`, `m.`, `music.`, `youtube-nocookie.com`; плеер —
  `youtube-nocookie.com/embed/<id>?autoplay=1&playsinline=1&rel=0[&start]`) и `Vimeo` (в том числе
  скрытые `vimeo.com/<id>/<хеш>` и `player.vimeo.com/video/<id>?h=`, каналы, группы, витрины;
  плеер с `dnt=1`). Старт из `?t=1m30s` / `#t=45s` сохраняется. Третью площадку сайт регистрирует
  своим провайдером — W3.2 так подключит реестр каталога, если тот будет нужен.
- **Фасад.** Сервер печатает `<a class="webx-video__facade" href="<страница ролика>">` с постером
  и кругом `play` — без JS это и есть «ссылка на ролик с постером» (§10). Скрипт меняет ссылку на
  `<button type="button">` с теми же детьми и `aria-label` «Play: <title>»; по клику кнопка
  заменяется на `<iframe class="webx-video__frame">` (`allow` с `autoplay` и `fullscreen`,
  `title`, `referrerpolicy`), фокус — в плеер, на корне `is-playing`.
- **Заглушка §9.4 рисуется сервером по cookie.** `Consent::has('media')` ложно — корень с
  `is-blocked`, поверх постера `webx-video__consent`: строка «The video loads from YouTube, which
  may set cookies.» и две кнопки — «Load» (только этот ролик, согласия не даёт) и «Always load
  videos» (`webx.consent.set([...categories, 'media'])`: баннер получает ответ, событие
  `webx:consent` снимает заглушки со всех роликов страницы без перезагрузки, нажатый — играет,
  остальные становятся фасадом и ждут своего клика). За заглушкой кнопка фасада `inert`. Корень
  несёт `data-webx-consent="media"` — по нему баннер и сервер (`Consent::categories()`) предлагают
  «Медиа». Баннер выключен — согласие не нужно, заглушки нет. Кусок страницы, смонтированный
  позже ответа, читает `webx.consent.has('media')` сам.
- **Постер всегда с сайта.** Заданный — как есть. Не заданный — превью ролика, которое сайт
  забирает к себе **один раз** (`Video\Posters`, scoped). **Где лежит:** в библиотеке медиа, папка
  «Video posters» в корне (создаётся при первой загрузке), картинка с именем `<площадка>-<id>`
  (`youtube-aqz-KE-bpKQ`) — через `RemoteFetcher` библиотеки (только публичные адреса, её лимит) и
  `FileStore` (конвейер делает WebP). Владелец видит постеры, может удалить — следующая страница
  заберёт снова. Какой файл чей, помнит кэш (`webx-widgets.video.poster.<имя>` → ключ файла), так
  что переименованный в панели или совпавший по байтам с другим файлом постер находится; без кэша
  находится по имени в папке. YouTube — `i.ytimg.com/vi/<id>/maxresdefault.jpg`, при отказе
  `hqdefault.jpg`; Vimeo — `thumbnail_url` из его oEmbed (`width=1280`). Берётся только картинка
  (тип по байтам). **Посетитель не ждёт:** страница, первой показавшая ролик, печатает его без
  постера, а загрузка идёт в `terminating` — после ответа; неудача помнится сутки
  (`webx-widgets.video.poster-failed.*`), одновременные запросы держит замок в кэше. Без
  `module-media` хранить негде — постера нет, рамка на своём фоне, никто никуда не ходит.
- **Свой файл** — `<video class="webx-video__player" controls preload="none" playsinline
poster>` с `<source type>` (тип из `mime` значения или из расширения) и ссылкой на файл внутри;

### W3.2 — блок `video`, видео каталога через компонент

- **Где лежит.** `widgets/resources/blocks/video.json` — документ `webx:blocks:export`, рядом с
  `gallery` и `logos`, предлагается тем же `BlockOffers` под `widgets` (с `module-blocks` и
  `module-media`). Группа `media`, слова — английские строки, как у остальных предложенных.
- **Поля.** `heading` (`localized`); `source` — `wx-segmented` `link` | `file`, `default` —
  `link`; `link` — `wx-input` с подсказкой, видно при `link`; `file` — `wx-media accept=video`,
  видно при `file`; `poster` — `wx-media accept=image`; `caption` (`localized`); `ratio` —
  `wx-segmented` `16/9` | `4/3` | `1/1` | `9/16`, `default` `16/9`. **Почему переключатель, а не
  два поля рядом:** с двумя заполненными непонятно, что играет, а «файл главнее» — правило,
  которое редактор не видит; переключатель показывает одно поле и говорит шаблону, какое читать.
  Заполненная ссылка при переключателе на `file` молчит — и тест это держит. Блок, сохранённый до
  поля, — ссылка (`default` читается, как панель рисует, `Rendering\Values`).
- **Шаблон** печатает `<x-webx-video>` внутри `<figure class="b-video__figure">`, подпись —
  `<figcaption>` под рамкой, заголовок — `title` ролика («Play: <заголовок>»). Чего печатать
  нечем — ничего: пустая ссылка, адрес, которого не знает ни одна площадка реестра (шаблон
  спрашивает `VideoProviders::find()` до компонента — иначе компонент бросил бы исключение и
  уронил страницу), файл, удалённый из библиотеки (`url` пустой). Постер, удалённый из
  библиотеки, — как не заданный: превью ролика.
- **Стили** — на `em` и прозрачности, без `--site-*` (блок предлагается и сайту без темы);
  `figure` и подпись сбрасывают поля — проза темы их раздвигает. Квадрат и вертикальный ролик
  во всю колонку были бы выше любого экрана: `b-video--1-1` держит рамку в `36em`, `b-video--9-16`
  — в `22em`, по центру колонки.
- **Каталог.** `product.blade.php`: картинка с роликом — `<figure class="webx-catalog-product__video">`
  с `<x-webx-video>`: постер — эта картинка, пропорция — её `width/height`, имя — `title`, иначе
  `alt`, иначе название товара. Ролик площадки — `src` = `videoData()['url']` (страница ролика),
  файл — `file`. Встроенный скрипт, `data-webx-embed` / `data-webx-video` и кнопка
  `webx-catalog-product__play` ушли; **YouTube теперь ждёт согласия на `media`** — изменение
  поведения, названо в changeset. `ProductMarkup` (`VideoObject`) не тронут.
- **Два реестра и мост.** `module-catalog` теперь **требует `webx-ui/widgets`**: запасная старая

### W3.3 — карта и блок `map`

- **`<x-webx-map lat lng zoom marker address height title link>`** и **`<x-webx-map from="settings">`**
  (`View\Components\Map`). `from="settings"` — главный адрес вкладки «Контакты» (`contacts()->
primaryAddress()`, §12.1, W1.5): текст на языке страницы, `latitude`/`longitude`, введённая
  ссылка на карту. **Координаты на вкладке уже были** (W1.5 завёл их для `LocalBusiness`), и
  демо `module-settings` сеет лондонский адрес с ними — дописывать в настройки ничего не
  пришлось. Адрес без координат — только место (`webx-map--place`: адрес и ссылка, без рамки,
  без скрипта и без согласия); нет адреса или нет `module-settings` — ничего (`shouldRender`).
  `marker` — подпись булавки (по умолчанию адрес), `false` — без булавки; `height` — длина CSS
  или число пикселей, по умолчанию `24rem`; `zoom` — целое 1–22, не глубже, чем рисует провайдер;
  `title` — имя области для скринридера («Map: <адрес>»); `link` — своё «Open in maps».
  Опечатки — `lat` без `lng`, вне Земли, `from="contacts"`, дробный масштаб, «высокая» высота —
  исключение с тем, чего не хватает. Заявляет `Widgets::need('map')`.
- **Что печатает сервер.** Рамка высотой `--webx-map-height` с ролью `region`, внутри — место:
  адрес, «Open in maps» (`target="_blank"`, `rel="noopener"`) и до согласия на `media` строка
  «The map loads from OpenStreetMap, which receives your IP address.» с кнопками «Load» и
  «Always load maps». В углу — атрибуция провайдера, **всегда**: до карты, поверх неё и без JS.
  Корень несёт `data-webx-consent="media"` — по нему баннер предлагает «Медиа». Без JS кнопки и
  строка спрятаны правилом `html:not(.webx-js)`: остаются адрес и ссылка на карту (§2.7).
- **Скрипт** — `dist/map.js|css`, Leaflet 1.9.4 (BSD-2) вшит, ≈45 КБ gzip из 50 (`DistTest`).
  ESM-сборка Leaflet почти не трясётся (`Map.include`, хуки — побочные эффекты модуля), поэтому
  вес — почти весь Leaflet. Стили Leaflet — как есть, `.leaflet-*` (как PhotoSwipe, W2.2), без
  PNG булавки и переключателя слоёв и без правила VML: плагин в `vite.config.js` вырезает их до
  сборки, иначе Vite вписал бы их base64 в `map.css` (`DistTest`: ни одного `url(`). Булавка —
  своя SVG в `currentColor` (`DivIcon`, `--webx-map-marker`), атрибуция Leaflet выключена —
  печатает сервер. «Load» ставит эту карту сразу, согласия не даёт; «Always» —
  `webx.consent.set([...categories, 'media'])`, событие `webx:consent` ставит все карты без
  перезагрузки. С согласием карта ждёт, пока рамка подойдёт к экрану на 200px
  (`IntersectionObserver`): карта внизу длинной страницы не просит тайлов, до которых не
  долистали. `ResizeObserver` зовёт `invalidateSize` — колонка меняется и без окна.
- **Колесо и палец.** До клика или фокуса карта спит: `scrollWheelZoom` выключен, на сенсорном
  экране (`pointer: coarse`) — ещё перетаскивание и щипок, и `touch-action` Leaflet снимает
  вместе с ними, так что страница едет под пальцем. Клик (Leaflet `click` — и касание) или фокус
  (Tab) будят: колесо масштабирует, палец двигает, `is-active` на корне. Нажатие вне карты или
  уход мыши — снова сон. Колесо над спящей картой на 1,5 с показывает подсказку «Click the map to
  zoom with the wheel» (`webx-map__hint`, `aria-hidden`). Кнопки +/−, клавиши — всегда.
- **Свой контекст наложения.** Холст (`webx-map__canvas`) — `position: absolute; z-index: 0`:
  панели и кнопки Leaflet (z-index до 1000) остаются внутри рамки и не встают поверх липкой
  шапки сайта.
- **Провайдеры — конфиг** (`webx-widgets.map`): `provider` — имя записи `providers`, запись — адрес
  тайла с `{z}/{x}/{y}`, `label`, `attribution`, `max_zoom`, `key` (подставляется в `{key}`).
  В пакете `openstreetmap` (по умолчанию, без ключа) и `maptiler`. `open` — шаблон «Open in maps»
  с `{lat}`, `{lng}`, `{zoom}` (по умолчанию openstreetmap.org). Неописанный провайдер или
  `{key}` без ключа — исключение (`MapTiles::configured()`): ошибка конфига сайта, а не карта,
  которая молча просит тайлы без ключа.
- **Слова** — `widgets.map.untitled|label|notice|load|always|open|hint` на 10 языках скриптом Node.
- **Блок `map`** — `widgets/resources/blocks/map.json`, рядом с `video`, тем же `BlockOffers`.
  Поля: `heading` (`localized`); `source` — `wx-segmented` `settings` | `coordinates`, `default`
  `settings`; `latitude`, `longitude` — `wx-input-number` с теми же `min`/`max`/`step`/`precision`,
  что на вкладке «Контакты»; `address` (`localized`) — видны при `coordinates`; `zoom` —
  `wx-input-number` 1–19, `default` 15; `height` — `wx-segmented` `small` | `medium` | `large`
  (16em, 24em, 32em), `default` `medium`. Шаблон не отдаёт компоненту того, что тот отвергнет:
  координаты вне Земли и не числа — как пустые, масштаб зажат в 1–19; в контактах нет адреса,
  нет координат у своих — блок не печатает ничего. Переключатель главнее заполненных полей.
- **Витрина** — «Kitchen sink › Map» на настоящем блоке: «From the contacts» (лондонский адрес
  демо), «Coordinates of its own» (Pariser Platz, Berlin, 16, высокая), «Low, the whole city»

- **Тесты.** PHP `MapTest` — место и строка до согласия, ни одного `<img>`, атрибуция,
  `data-webx-map`; с согласием — только место; ответ без `media` и выключенная вкладка «Cookie»;
  файлы `map.*` и строка «Медиа» на странице; `from="settings"` — главный, а не первый адрес,
  язык страницы, введённая ссылка, `marker=false`; адрес без координат и пустая вкладка; MapTiler
  с ключом (`rawurlencode`), масштаб не глубже провайдера, свой `open`; провайдер без ключа и
  неописанный; восемь опечаток; слова по-немецки. `BlocksTest` (+3): контакты по умолчанию и
  переключатель главнее координат, свои координаты с адресом и без, пять случаев «ничего».
  `DistTest` — список `dist/`, бюджет 50 КБ, каждое правило `map.css` — Leaflet или пакета, ни
  одного `url(`. vitest `map.test.js` (10): до согласия ни Leaflet, ни `<img>`; «Load» — тайлы

  cookie, событие, обе карты; ожидание `IntersectionObserver`; поздний монтаж после ответа;

- **`pnpm test:starter`** — 54 из 54 (50 прежних и 4 новых). До ответа на 375 и 1280 — четыре

Отступления от спеки:

- **Google Maps не сделан** (§11 называл его «полноценным по ключу»). Это не тайлы по адресу, а
  свой JavaScript API: второй драйвер со своим скриптом, своими правилами согласия и своей
  булавкой — и условия Google запрещают брать его тайлы в Leaflet. Отложено до сайта, который
  попросит (§19); путь — драйвер рядом с `MapTiles`, тот же контракт заглушки. Ссылку «Open in
  maps» на Google сайт ставит уже сейчас (`webx-widgets.map.open`).
- **Поле `address` у блока** — §15.1 его не называет; без него у карты по координатам заглушке
  нечего показать, кроме кнопок, а булавке — подписи.
- **Поле `source` (переключатель)** — §15.1 говорит «из настроек или координаты»: одно поле
  смысла, как у `video` (W3.2).
- **Высота блока — три ступени, а не число:** пиксели в панели — не то, о чём думает редактор, и
  число не проверить на телефоне; компонент берёт любую длину CSS.
- **Атрибуция — разметка сервера, а не контрол Leaflet:** §11 требует печатать её «всегда», а
  контрол Leaflet есть только со скриптом и после согласия.
- **«Always load maps» грузит все карты страницы**, а не только нажатую (видео в W3.1 делает
  наоборот): карта ничего не проигрывает и не шумит, а тайлы ждут, пока рамка подойдёт к экрану.

### W4 — проверки аудита, `AGENTS.md`, гайд, выпуск

- **Аудит не хранит HTML страницы (§12 спеки аудита), поэтому виджетам нужен шов в `module-audit`.**
  `Contracts\AuditPageReader` (`id()`, `read(HTMLDocument, $url)`) и реестр `Crawl\PageReaders`
  (singleton): парсер обхода зовёт каждого читателя, пока страница у него в руках, и кладёт
  непустой ответ в факты страницы под `id()` — проверки модуля читают `$page->fact('widgets')` на
  разборе, как свои. Читатель, который бросил исключение, — `report()` и дальше: баг модуля не
  останавливает обход. **Находка замером:** `PageParser::text()` вырезает из документа `script`,

### W5.1 — таблицы в прозе, появление при прокрутке, «наверх», «поделиться»

- **Таблицы в прозе оборачивает `Widgets::finish()`, а не каждый модуль.** Прозу печатают блоки
  (`wx-rich-text` через `Rendering\Values`), FAQ, рецепты, описания рубрик и категорий — каждый
  своей вьюхой, и ни один не знает про виджеты. Ответ, который уже проходит через `finish()`
  (подстановка стилей и скриптов, W1.1), — единственное место, где видна вся проза сайта сразу.
  `Prose\Tables::wrap($html, $label)` берёт **таблицу без класса**: санитайзер `module-admin`
  (`Screens\Types\Html`) снимает с `<table>` все атрибуты, значит таблица редактора — всегда без
  класса, а таблица шаблона (`webx-hours__table`, характеристики товара) — с классом, и её
  раскладку никто не трогает. Только внешние таблицы; внутри `<script>`, `<style>`, `<template>`,
  `<textarea>` и комментариев — текст, не таблица. Второй проход ничего не меняет: у обёрнутой
  уже есть класс `webx-table__table`. Обёрнута хоть одна — заявлен `table`.
- **Разметка** — `.webx-table` (`data-webx-table`, `style="--webx-table-columns: N"`) >
  `__caption` + `__frame` > `__scroller` (`tabindex="0"`, `role="region"`) > `__table`.
  **`<caption>` выносится из таблицы над рамкой:** внутри прокрутки он ехал бы вместе с таблицей
  (у подписи ширина таблицы, `sticky` ей двигаться некуда). Имя таблице и рамке он отдаёт через
  `aria-labelledby`; без подписи рамка называется «Table» (`widgets.table.label`).
- **Колонки не сжимаются до слова в строке** (находка на снимке 375px). Таблица с `display:
table` и шириной `auto` в узкой колонке ужимает каждую колонку до `min-content`: «A manager of
  your own» — по слову в строке, ряды втрое выше. Сервер считает колонки первой строки (с
  `colspan`), CSS держит таблицу не уже `N × --webx-table-column-min` (7rem): девять колонок на
  1280 помещаются, на телефоне и в колонке 20rem — прокручиваются. Каскад темы (`display: block;
overflow-x: auto` у таблиц прозы `theme-default`) перебит одним классом `webx-table__table`.
- **`dist/table.js|css`** (≈1 КБ gzip) рисует только края: `is-more-left` / `is-more-right` на
  `__frame` (тени — `::before`/`::after` с `color-mix` от `--site-color-text`), и снимает
  `tabindex` у таблицы, которой нечего прокручивать. Стороны физические, а не `start`/`end`:
  правило одного класса не пускает `:dir(rtl)`, поэтому справа налево скрипт сам решает, где
  скрыто (`scrollLeft` от 0 до минуса). Без JS — рамка прокручивается, теней нет, `tabindex` есть.
- **`data-webx-reveal`** — в runtime (`behaviours/reveal.js`, `reveal.css`): `up` (по умолчанию),
  `fade`, `scale`; `stagger` на контейнере с `data-webx-reveal-effect` для детей. Прячется
  **только то, что ниже экрана** в момент монтирования: видимое и пролистанное мигнуло бы.
  Классы `webx-reveal webx-reveal--<эффект> is-pending` ставит скрипт; показ — `IntersectionObserver`
  (поле −8% снизу), один раз; дети `stagger`, пришедшие одной пачкой, получают задержку по своему
  месту в контейнере (`--webx-reveal-delay: calc(i * var(--webx-reveal-stagger))`). Показанный
  элемент теряет классы и задержку после `transitionend` (или через 3 с) — его собственные переходы
  (наведение у карточки) снова его. `beforeprint` показывает всё. С `reduced-motion`, без
  `IntersectionObserver` и без JS не прячется ничего.
- **Скрытие без перехода** (находка замера: `opacity` 0.26 под сгибом). Изменение берёт
  `transition` того состояния, в которое приходит: у `.webx-reveal.is-pending` — `none`, у
  показанного — переход. Записано в `docs/pitfalls/layout-and-browser.md`.
- **`<x-webx-back-to-top corner :after label>`** (`dist/back-to-top.js|css`, ≈1,5 КБ) — ссылка на
  `#top`; скрипт делает её круглой кнопкой в углу (`is-shown` после `after` экранов, по умолчанию
  два), по нажатию — `scrollTo` плавно или сразу при `reduced-motion`, фокус — на `<body>`
  (`tabindex="-1"` до ухода фокуса): следующий Tab — ссылка «к содержимому». **Встаёт над** баннером
  согласия, нижней полосой контактов и кнопкой быстрой связи своего угла: скрипт меряет, докуда
  они достают от низа окна (`--webx-back-to-top-lift`), на прокрутке, по `ResizeObserver`,
  `MutationObserver` и **`transitionend`** — кнопка быстрой связи поднимается над баннером и
  опускается обратно переходом, и конечное место известно только после него (находка замера).
  Без JS — обычная ссылка в потоке, где её поставил шаблон.
- **`<x-webx-share url title :networks label>`** (`dist/share.js|css`, ≈1,2 КБ) — адреса «поделиться»
  самих сетей обычными ссылками в новой вкладке: Facebook, X, LinkedIn, Telegram, WhatsApp, почта
  и «Copy link» по умолчанию; Viber, Reddit, Pinterest, Threads, Bluesky, VK — по списку. Почта —
  `mailto:?subject=…&body=…` без `target`. `url` — адрес страницы без запроса; относительный —
  исключение (сеть его не откроет), как и сеть не из списка. Скрипт: «Copy link» —
  `navigator.clipboard`, а где его нет (не https) — выделение и `execCommand('copy')`; строка
  «Link copied» видна рядом и читается как `role="status"`. На телефоне (`navigator.share` и
  `pointer: coarse`) ряд прячется, одна кнопка «Share» открывает системное меню; на десктопе с
  `navigator.share` ряд остаётся — его меню беднее. Без JS «Copy link» спрятан.
- **Бюджеты** — по 2 КБ gzip на `table`, `back-to-top`, `share` (`DistTest`); §4 их не называет.
  Runtime с появлением — ≈10,3 КБ из 16.
- **Слова** — `widgets.table.label`, `back_to_top.label`, `share.label|on|email|copy|copied|failed`
  на 10 языках скриптом Node. Иконки пакета — `arrow-up`, `share`.

  странице с рядом «поделиться». Краулер их не собирает (`PageParser::SHARE`).

  помещающейся ни того ни другого, девять колонок прокручиваются на телефоне и в 20rem и
  помещаются на 1280; регионы названы подписью и «Table»; стрелка с клавиатуры прокручивает, тень
  встаёт слева, подпись не двигается; без боковой прокрутки страницы. На 1280×900 — 24 карточки
  ждут ниже сгиба с `opacity` 0, ряд `stagger` приходит целиком, задержки `calc(1 * …)` и дальше,
  после прокрутки до конца ни одного `webx-reveal` и все `opacity` 1; с `reduced-motion` и без JS —
  все сразу. «Наверх» на 375×812 до ответа баннеру: на двух экранах ещё нет, чуть ниже — есть,
  ≥ 44px, над баннером и над кнопкой быстрой связи; после «Reject all» — в 16px над кнопкой
  быстрой связи; Enter — наверх, фокус на `<body>`, следующий Tab — «Skip to content». «Поделиться»:
  два ряда, шесть ссылок с адресом страницы, каждая ≥ 44px и в своём блоке, «Link copied», ни одного
  запроса наружу; на телефоне (`isMobile`, `hasTouch`) ряд спрятан, «Share» отдаёт системе адрес и
  заголовок. Без JS — таблицы прокручиваются, «Copy link» спрятан, «наверх» — ссылка в потоке.
- **Проверено в браузере** на пересобранном стартовом сайте (`starter-site.sh` зелёный): снимки
  Playwright (msedge) таблиц, карточек, рядов «поделиться» и угла на 375 и 1280 в обычном и `night`.
  `php artisan webx:audit:run` — у «Page tools» те же находки, что у соседних страниц витрины
  (`h1.missing`, длина заголовка, favicon), из `widgets.*` по всему сайту — только нарочная
  ссылка без размеров на «Kitchen sink › Lightbox».

Отступления от спеки:

- **Обёртку ставит ответ, а не «рендер прозы»** каждого модуля (выше — почему). Следствие:
  предпросмотр блока в панели приходит JSON-ом и обёртки не получает — там таблица прокручивается
  старым правилом прозы темы (`display: block; overflow-x: auto`), без теней и с подписью внутри.
- **Подпись выносится из `<table>`** в `div` над рамкой и называет таблицу через
  `aria-labelledby` — §14 требует только «не уезжает»; иначе это недостижимо.
- **«Наверх» и «поделиться» не стоят в лейауте `theme-default`** — каждый грузит свой файл, а §14
  говорит «только на странице, где стоит»; ставит тот, кому нужен. Свои бюджеты — по 2 КБ, §4 их не
  называет.
- **«Copy link» в «поделиться»** — §14 называет только ссылки сетей и `navigator.share`; копирование
  ссылки — то, ради чего «поделиться» открывают чаще всего, и стороннего в нём ничего.

### W5.2 — видео-фон, счётчик, таймер и их блоки

- **Видео-фон — вариант `<x-webx-video variant="background" :file :poster ratio>`**, а не свой
  компонент: тот же `Video`, та же вьюха (ветка `@if ($background)`), тот же `dist/video.js|css`.
  **Где живёт скрипт — в `video.js`:** фон — ≈60 строк, а первый экран, заявивший два файла,
  платил бы лишним запросом; `video.js|css` теперь ≈2,5 КБ gzip из 4 (`DistTest`). Регистрация —
  второй `webx.widget('video-background', '[data-webx-video-background]')` в том же файле. Только
  `file`: `src` (или ничего) — исключение с объяснением (§10: фон с YouTube — сторонний запрос на
  каждом показе). `variant` не из списка — исключение.
- **Разметка.** Корень `.webx-video.webx-video--background` с `data-webx-video-background`; внутри
  `__backdrop` (`aria-hidden="true"`: постер `<img>` без `loading="lazy"` — первый экран не ждёт —
  и `<video class="webx-video__background" muted loop playsinline preload="none"
disablepictureinpicture tabindex="-1">`), `__over` — то, что тег оборачивает (текст поверх — разметка
  страницы, §10), и `__pause` **вне** `aria-hidden` с `data-pause`/`data-play` — словами, которые
  скрипт ставит в `aria-label`. **`autoplay` в разметке нет:** без JS ничего не движется, а значит
  и кнопке нечего останавливать — остаётся постер (кнопка спрятана `html:not(.webx-js)`).
- **Скрипт.** Играет, только пока рамка на экране (`IntersectionObserver`), вкладка впереди
  (`visibilitychange`) и посетитель не против; никогда сам при `prefers-reduced-motion` (слушает
  смену) и `navigator.connection.saveData` — и тогда файл не запрашивается вовсе (`preload="none"`
  и ни одного `play()`). Постер стоит, пока не пришло `playing`: видео с `opacity: 0` до класса
  `is-playing` на `<video>` — первый экран не пустеет. Кнопка: пауза — запоминается в
  `localStorage` (`webx-video-background` = `paused`) для следующих страниц; «играть» — только на эту
  страницу (в том числе поверх reduced-motion: посетитель сам попросил). Браузер, отказавший даже
  немому `play()` (энергосбережение телефона), — состояние «на паузе», кнопка говорит «играть».
- **Рамка.** Пропорция — минимум: `aspect-ratio` растёт под содержимое, пока корень не обрезает
  его, поэтому у фона `overflow: visible`, а углы и обрезку держит `__backdrop` (`overflow: hidden;
border-radius: inherit`, `z-index: -1` под `isolation: isolate`). **Корень — сетка в одну
  клетку** (находка снимка): `__over` с `min-height: 100%` в коробке, чья высота — из
  `aspect-ratio`, не растягивался — процент не от чего считать, и тень демо закрывала только верх
  рамки. Растянутый элемент сетки высоту знает. Записано в `docs/pitfalls/layout-and-browser.md`.
  Токены `--webx-video-pause-size|inset|bg|color|border`, иконки по `--webx-video-pause-shown` /
  `-play-shown`, как у паузы слайдера.
- **`<x-webx-counter :value prefix suffix decimals duration>`** (`dist/counter.js|css`, ≈1 КБ).
  Сервер печатает итог по языку страницы (`NumberFormatter`, без `intl` — английский
  `number_format`): `3,000`, по-немецки `12.500,5`. Знаков после точки — сколько написано
  (`4.9` → 1), `decimals` 0–6 перекрывает; `duration` 0–10000 мс. Скрипт считает **только
  счётчик ниже экрана** в момент монтирования — как появление W5.1: видимый мигнул бы итогом и
  упал в ноль. Пока считает — цифры `aria-hidden`, рядом невидимый `__final` с итогом для
  скринридера, ширина цифр закреплена на итоговой (`min-inline-size`), шрифт `tabular-nums`; в
  конце — **ровно текст сервера**, а не `Intl` браузера. `beforeprint` и размонтирование ставят
  итог сразу. Слов у счётчика нет.
- **`<x-webx-countdown to ended>`** (`dist/countdown.js|css`, ≈1,2 КБ). **Часовой пояс сайта** — тот
  же, что у часов работы (W1.5): `contacts()->hours()->timezone()` (`contacts.timezone`, иначе
  `app.timezone`), без `module-settings` — `app.timezone`. `to` — стенное время в нём
  (`2026-12-31 18:00`), строка со смещением или `DateTimeInterface` — тот момент; не дата —
  исключение. `Countdown::moment()` и `siteZone()` публичные — их зовёт шаблон блока. Сервер
  печатает остаток на момент ответа (дни без нуля впереди, остальное двумя цифрами), скрипт —
  каждую секунду **от часов** (`end` — метка времени в `data-webx-countdown`), с подстройкой к
  границе секунды; страница из кеша сразу верна. Конец: текст `ended` (напечатан заранее с `hidden`),
  без него таймер уходит вместе с ближайшим `[data-webx-countdown-scope]` — блок, ради которого он
  стоял. Закончился до ответа и сказать нечего — `shouldRender()` ложно, ничего. **Без JS цифры
  соврали бы**, поэтому видна строка «Ends on 31 December 2026 18:00 (UTC+01:00)» (`<time
datetime>`), плитки спрятаны; с JS эта строка визуально скрыта и её слышит скринридер, а
  тикающие плитки — `aria-hidden`. Плитки — `flex-wrap`, в контейнере уже 20rem — два на два;
  `--webx-countdown-justify` для центровки блоком.
- **Слова** — `widgets.video.pause|resume`, `widgets.countdown.ends|days|hours|minutes|seconds` на
  10 языках скриптом Node. Подписи плиток — заголовки («Days», «Дней»), не счёт: с `:count` в
  строке они сломались бы на единице.
- **Блок `counters`** — `widgets/resources/blocks/counters.json`, тем же `BlockOffers`. Поля:
  `heading` (`localized`); `numbers` — `wx-repeater` до 12 (не `items`: так у блоков-контейнеров зовутся вложенные блоки, и тест витрины темы обходит их как блоки): `value` (`wx-input`, а не
  `wx-input-number`: «4.9» и «3 000» — как пишет редактор), `prefix`, `suffix` (`localized`),
  `label` (`localized`). Шаблон читает число как его написали: пробелы (и неразрывные) прочь,
  `3,000` — тысячи, `4,9` — запятая десятичная; не число — строки нет; ни одной строки — блока нет.
  Сетка `auto-fit, minmax(min(100%, 10em), 1fr)`, в узком — по два.
- **Блок `countdown`** — `countdown.json`. Поля: `heading`, `text` (`localized`), `date`
  (`wx-date-picker`), `time` (`wx-time-picker`, `default` `00:00`), `end` — `wx-segmented`
  `text` | `hide`, `ended` (`localized`, видно при `text`). **Почему дата и время, а не
  `wx-date-time-picker`:** тот хранит момент со смещением **редактора** — редактор в другом поясе
  поставил бы распродаже чужие шесть часов; дата и время без пояса — стенное время сайта, как
  §14. Несуществующий день (`2027-02-31`) Carbon перенёс бы в март — шаблон проверяет `checkdate`.
  Секция несёт `data-webx-countdown-scope`; закончился и «спрятать» (или текста нет) — ничего.
- **Аудит.** Два обещания, которые перекрытая вьюха может потерять, — по образцу `slider_pause`:
  `widgets.video_pause` (**предупреждение**: фон без `.webx-video__pause`, WCAG 2.2.2) и
  `widgets.counter_number` (**замечание**: в разметке счётчика нет его числа — сверка цифр
  `__number` с `value`/`decimals` из `data-webx-counter`, так что `3,000`, `3 000` и `3.000` —
  одно и то же). Факты `video_unpaused`, `counter_empty` в `WidgetsPageReader`, слова в
  `checks.php` и `audit.php` на 10 языках. У таймера проверять нечего: закончившийся сервер не
  печатает.
- **Витрина** — две страницы. «Kitchen sink › Background video» на демо-типе
  `showcase-background` (фона нет ни у одного блока темы): первый экран с заголовком, строкой и
  кнопкой поверх ролика 21:9, то же в колонке 20rem (текст делает рамку выше пропорции), ролик
  без постера и без текста; что пробовать; разметка. Ролик — `demo/media/showcase-clip.mp4` (W3.1).
  «Kitchen sink › Counters and countdown» — на настоящих блоках: таймер до 2030 года, закончившийся
  с текстом, закончившийся «спрятать» (его нет на странице — сказано в тексте), счётчики ниже
  сгиба; демо-тип `showcase-numbers` — то, чего блок не покажет: таймер, кончающийся через 75 секунд
  после рендера, таймер и счётчики в колонке 20rem.
- **Тесты.** PHP `MotionTest` (9): фон — разметка, `aria-hidden` у декора, не у кнопки, ни
  `controls`, ни `autoplay`, ни согласия, слова по-немецки, `webm`; счётчик — итог по-английски
  и по-немецки, знаки по написанному, `decimals`; таймер — стенное время Берлина в UTC, остаток,
  текст скрыт до конца, момент со смещением, конец с текстом и без, слова по-русски, файлы на
  странице, пояс без контактов; восемь опечаток. `BlocksTest` (+3): счётчики — четыре строки из
  шести, `3,000`, `4,9`, `12 500` с `$`; таймер — пояс Токио из вкладки «Контакты», полночь без
  времени, «спрятать» без текста; закончившийся — текст или ничего в пяти случаях. `AuditTest` —
  фон без кнопки и счётчик с `0` вместо 3000 найдены на своей странице, `3 000` и `4,9` — нет.
  `DistTest` — список `dist/`, бюджеты 2 КБ счётчика и таймера. vitest `motion.test.js` (11):
  фон играет на экране, отдыхает вне, постер до `playing`, reduced-motion и saveData, пауза
  запомнена и снята, отказ браузера, размонтирование; счётчик ниже сгиба, видимый, пролистанный и
  reduced-motion, плавный ход, десятые, печать и размонтирование; таймер пересчитывает от часов,

- **Фон — вариант того же компонента и того же файла**, без своего `dist/`: §4 говорит «скрипт там,
  где виджет есть», и у фона это `video.js` — его бюджет 4 КБ держит оба.
- **Пауза фона запоминается между страницами**, «играть» — нет: §10 требует кнопку, но не
  говорит, сколько живёт выбор; тот, кто остановил движение, не должен останавливать его на каждой
  странице.
- **Счётчик в первом экране не считает** — как появление W5.1 не прячет видимое: §14 говорит
  «при появлении на экране», а мигание итогом и падение в ноль хуже, чем итог сразу.
- **Таймер без JS показывает дату, а не цифры** — §14 об этом молчит; цифры на момент ответа из
  кеша неправда.
- **Поля блока `countdown` — дата и время, не `wx-date-time-picker`** (выше — почему); `text` —
  поле, которого §14 не называет: «до конца распродажи» обычно стоит над таймером.
- **Блоки `counters` и `countdown` предлагаются, как остальные, только с `module-media`** — одна
  папка `resources/blocks` одним `offer()`; сайт без библиотеки медиа их пока не получит.
- **Две новые проверки аудита** (`video_pause`, `counter_number`) — §15.2 их не называет; это
  обещания §10 и §14, которые перекрытие вьюхи может молча потерять, как `slider_pause`.

### W5.3 — «до и после», оглавление и их блоки

- **`<x-webx-compare :before :after start ratio before-label after-label label>`**
  (`dist/compare.js|css`, ≈2 КБ gzip). `before` и `after` — то же, что `<x-webx-lightbox :image>`:
  значение поля медиа, объект с `url()` или адрес; без любого из двух — исключение. Рамка берёт
  форму **первой картинки, у которой есть размеры** (библиотека хранит их с загрузки), `ratio` —
  руками, ни того ни другого — 4/3; печатается в `--webx-compare-ratio`, позиция — в
  `--webx-compare-position` (`start` 0–100, по умолчанию 50). Рамка — **сетка в одну клетку**
  (ловушка W5.2): обе стороны в ней, «после» обрезано `clip-path: inset(0 0 0 позиция)`, и ничего
  ниже не сдвигается, пока грузятся картинки. Подписи — пропсы, по умолчанию «Before»/«After» по
  языку страницы; `figcaption` — из слота.
- **Граница — `<input type="range">`** (`aria-label` «Divider between Before and After»,
  `aria-valuetext` — процент по языку: `25 %` по-немецки, `%25` по-турецки): скринридер слышит
  ползунок, клавиатура получает стрелки без строчки скрипта. Скрипт ставит свои шаги — стрелки по
  5%, с Shift по 1%, Page Up/Down по 25%, Home/End — края — и связывает поле с рамкой: мышь —
  там, где нажала, и пока тянет; **палец — только когда пошёл вбок** (6px): страницу листают и по
  картинкам, и касание, которое прыгало бы границей, двигало бы её под пальцем, хотевшим только
  прокрутить; касание без движения ставит границу туда. `touch-action: pan-y` — вертикаль
  остаётся странице. Фокус — на поле (и после мыши: стрелки продолжают с того места), кольцо на
  ручке — только при `:focus-visible` (`is-focused`). Само поле спрятано: ручка — линия и круг
  2.75rem со стрелкой, вырезанной `clip-path`, без иконки. У линии тонкий край цвета стрелки
  (`color-mix`, находка снимка): в `night` линия цвета фона терялась на тёмной картинке.
- **Слева направо на любом языке** (`dir="ltr"` у рамки): «до» слева — так снимают и показывают,
  а граница, бегущая в другую сторону, была бы вторым соглашением.
- **Без JS — `@media (scripting: none)`, а не `html:not(.webx-js)`**, как в остальном пакете:
  класс ставит runtime-модуль после разбора страницы, и рамка на мгновение была бы двумя картинками
  рядом, а потом одной — скачок. С медиа-запросом страница с JS сразу рисует рамку с границей на
  месте, ещё до скрипта. Без JS — две картинки рядом, каждая в своей пропорции и со своей подписью,
  в контейнере уже 28rem — одна под другой; ни ручки, ни поля.
- **`<x-webx-toc for depth title side fold>`** (`dist/toc.js|css`, ≈2 КБ). **Список и `id` делает
  сервер — в `Widgets::finish()`, как обёртку таблиц W5.1**, а не скрипт. Почему: заголовки
  печатает кто угодно (блок, модуль, шаблон темы) и часто **после** оглавления — оно стоит над
  текстом или рядом; только готовая страница знает их все. Ссылки тогда работают без JS, ссылкой
  на раздел можно поделиться, поисковик видит оглавление. Компонент печатает маркер
  (`<!--webx-toc:…-->`, base64 JSON), `Prose\Contents::fill()` находит элемент — свой слот, элемент
  по `for` (id без `#`) или `<main>`, а без него `<body>` — берёт его `h2` (и `h3` при `depth` 3,
  по умолчанию), пропускает текст `script`/`style`/`template`/`textarea`/комментариев и
  `data-webx-toc-skip`, даёт заголовку без `id` id из слов (`Str::slug` по языку страницы:
  «Политика конфиденциальности» → `politika-konfidentsialnosti`; пусто — `section`), уникальный на
  всей странице (`-2`, `-3`, считая `id` чужих элементов), а данный редактором или шаблоном
  оставляет. `h3` до первого `h2` — в верхний уровень. Нечего перечислить — ни маркера, ни `<nav>`.
  Список — вьюха `webx-widgets::toc` (перекрывается темой); номер компонента на странице — новый
  `Widgets::sequence()`, сбрасывается с запросом.
- **Раскладка — по контейнеру `webx-toc`.** Со слотом корень — сетка: от 48rem — текст и список
  `--webx-toc-width` (15rem) сбоку (`side`: `end` по умолчанию или `start`), список **липкий** под
  `--webx-header-height` + `--webx-toc-offset` и прокручивается сам, если длиннее экрана; уже
  48rem — список над текстом. Без слота (`__layout--alone`) — список там, где тег. **Выпадашка —
  своя, а не `<x-webx-dropdown>`:** в широком контейнере тот же список стоит открытым, а
  `<details>`/popover выпадашки закрыт, пока его не открыли; рисовать список дважды — дубли
  ссылок. Поэтому скрипт ставит `is-ready` на то, что меняется, а сворачивает **CSS контейнера**:
  в узком `__title` прячется, появляется `__toggle` (≥ 44px: заголовок списка и раздел, который
  читают), а `__panel` — выпадающая панель с поверхностью, тенью и радиусом §6.3; Esc (фокус — на
  кнопку), клик мимо и ссылка закрывают. Свёрнутый `__nav` липнет полосой под шапкой, поэтому
  скрипт даёт заголовкам списка `scroll-margin-top` = высота полосы + 8px: переход по ссылке не
  прячет заголовок ни под шапкой (её `scroll-padding-top`, W1.2), ни под полосой. Без JS свёртки
  нет: открытый список над текстом, не липкий — липкий список длиной в страницу закрыл бы её.
  `fold="never"` — список открыт всегда (колонка темы, которая уже телефона, но не телефон).
- **Текущий раздел** — последний заголовок выше линии «шапка + четверть экрана», а у самого низа
  страницы — последний видимый; `is-current` и `aria-current="true"` на ссылке, его слова — в
  `__current` полосы. Прокрутка — через `requestAnimationFrame`, размер — `ResizeObserver` на
  корне (свёрнут ли сейчас — по `display` кнопки, то есть решение CSS).
- **Блок `compare`** — `widgets/resources/blocks/compare.json`, тем же `BlockOffers`. Поля:
  `heading`, `before`, `after` (`wx-media`, только картинки), `before_label`, `after_label`
  (`localized`, пусто — слова страницы), `start` (`wx-input-number` 0–100, `default` 50),
  `caption`. Картинка, удалённая из библиотеки, — как не выбранная; одной сравнивать нечего — блока
  нет.
- **Блок `toc`** — `toc.json`. Поля: `heading` (заголовок списка, пусто — «On this page»),
  `source` — `wx-segmented` `page` | `text` (переключатель вместо двух соперничающих полей, урок
  W3.2), `body` (`wx-rich-text`, видно при `text`), `side` (при `text`), `depth` (`2` | `3`).
  «Вся страница» — список `<main>` там, где стоит блок; «свой текст» — список рядом с текстом
  блока, липкий. **Блок не обёртывает соседей:** блоку-контейнеру нужен список разрешённых типов
  (`allow`), а предложенный тип не знает, какие типы есть на сайте; поэтому «рядом» — только со
  своим текстом (политика и есть один длинный текст), а для страницы — список над ней. В
  предпросмотре панели (JSON, без `finish()`) маркер не заполняется и списка нет — как нет там и
  обёртки таблиц. Описание типа — не длиннее 255 символов (`webx:blocks:offered` иначе отказывает
  в установке, а тест видит только «код возврата 1»).
- **Слова** — `widgets.compare.before|after|label`, `widgets.toc.title` на 10 языках скриптом Node.
- **Бюджеты** — по 3 КБ gzip на `compare` и `toc` (`DistTest`): у них своя раскладка, а не
  несколько строк, как у инструментов W5.1–W5.2 (по 2 КБ); сейчас ≈2 КБ каждый.
- **Аудит.** Обещания, которые перекрытие вьюхи может молча потерять, — по образцу W5.2:

  `[data-webx-toc]` на `#id`, которого на странице нет, — список, написанный руками или
  перекрытый; `id` сравнивается раскодированным). Факты `compare_rangeless`, `toc_dangling` в
  `WidgetsPageReader`, слова в `checks.php` и `audit.php` на 10 языках.

Отступления от спеки:

- **`id` заголовкам ставит сервер, а не скрипт** — §14 говорит «сам ставит им `id`», не уточняя
  кто; сервер (выше — почему) делает ссылки рабочими без JS. Следствие то же, что у таблиц W5.1:
  страница без `@webxTheme` (`finish()` не идёт) и предпросмотр блока в панели остаются без
  списка.
- **Выпадашка оглавления — своя кнопка и панель с видом §6.3, а не `<x-webx-dropdown>`** (выше).
- **«Рядом с текстом» у блока `toc` — только со своим текстом**; список всей страницы стоит там,
  где блок (блок не обёртывает соседей). Липкое сбоку для страницы целиком — дело шаблона темы
  (`<x-webx-toc>` со слотом или `for`).
- **«До и после» без JS — по `@media (scripting: none)`**, не по классу `html.webx-js`, как
  остальной пакет: иначе скачок раскладки на каждой странице с JS.
- **Свой бюджет 3 КБ** у `compare` и `toc` — §4 их не называет.
- **Две новые проверки аудита** (`compare_range`, `toc_target`) — §15.2 их не называет; это
  обещания §14, которые перекрытие вьюхи может молча потерять.
