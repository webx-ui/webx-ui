# `webx-ui/module-banners` — спецификация

Статус: выпущено, вместе со слоями (раздел «Слои»). Пакеты — `webx-ui/module-banners` (composer)
и `@webx-ui/module-banners` (npm).

Баннеры — картинка (и отдельная под телефон), по желанию видео, заголовок, текст и до трёх
кнопок. Стоят они в **именованных местах**, как пункты меню: шаблон сайта просит
`banners('hero')`, редактор кладёт в место баннеры и двигает их руками. Своей страницы нет ни у
баннера, ни у модуля, блоком на страницу баннеры не ставятся: на сайт они попадают **хелпером** —
данными, а разметку пишет шаблон сайта; у места со слоями разметку отдаёт пакет
(`<x-webx-banners>`, «Слои»).

Ядро не меняется. Модуль стоит на выпущенном: `RecordQuery` (`module-team`), `Link`/`wx-link`
(`module-menu`), `wx-media` с `props.accept` (`module-media`), переводимые поля и ошибки строк
внутри `wx-repeater` (`module-press`).

## 1. Границы

**Внутри:** места (объявленные конфигом и свои), баннеры с медиа, словами, кнопками,
выключателем и ручным порядком внутри места, корзина; хелперы `banners()` и `banners_layout()`;
конфиг видов и их параметров; слои и компоненты `<x-webx-banners>`/`<x-webx-banner>`; экраны
панели, API, MCP, демо.

**Снаружи:** источник `wx-collection` и тип блока (решение 7, §7); расписание показа (решение
5); связи с записями (решение 6); своя страница и schema.org; черновики и версии (решение 13);
статистика кликов и A/B; ссылка на весь баннер, отдельное видео под телефон (§7).

## 2. Принятые решения (не переоткрывать)

1. **Места именованные, как меню** (`WEBX_UI_MODULE_MENU.md` §2, решение 10). Конфиг объявляет
   места, строка в `banner_places` создаётся при первом сохранении баннера в место — ни записи
   на загрузке, ни команды синхронизации. Администратор заводит и удаляет свои места; удалить
   можно только пустое. Объявленное место не удаляется и не переименовывается: шаблон просит его
   по ключу.
2. **Из чего состоит баннер:** картинка и картинка под телефон; видео (картинка при нём — постер и
   замена); заголовок и текст; кнопки — повторитель, максимум 3, у каждой переводимый текст,
   `wx-link` и вариант оформления из конфига; «Включён» и ручной порядок внутри места; слои —
   у места, которое их объявило.
3. **Медиа не переводятся**, слова переводятся. `alt` и `title` внутри значения `wx-media` — по
   языкам (`MediaValues::resolve()`).
4. **Виды: `single`, `random`, `slider`, параметры — в конфиге:** интервал, автопрокрутка, цикл,
   стрелки, точки, пауза при наведении, пропорции, порог телефона, видео на телефоне. Объявленное
   место переопределяет вид и параметры (§5.3); пакет отдаёт слитые значения
   (`banners_layout()`).
5. **Расписания нет.** Баннер показывается, пока включён.
6. **Связей нет** — ни `HasRelations`, ни цели для других модулей.
7. **Интеграции с блоками нет — хелпер `banners('PLACE')`.** Пакет отдаёт карточки (`banners()`)
   и параметры вида (`banners_layout()`); место целиком печатают компоненты пакета
   `<x-webx-banners>`/`<x-webx-banner>` (§4) — с разметкой, CSS и скриптом, слои тоже (решение
   Л10). Своя разметка сайта по хелперам возможна, но место со слоями — только через компонент. Ни
   источника для `wx-collection`, ни типа блока.
8. **Картинка обязательна** — единственное обязательное поле: на ней держатся все три вида
   (пропорции, постер видео, замена без JS). Видео без картинки — отказ под `image`.
   Исключение — объявленное место с `'image' => false`, место слов: там баннер без картинки
   доходит до шаблона (`image` — `null`), видео без постера — всё так же отказ. Так объявлено
   `notice` — его печатает полоса объявления виджетов (`<x-webx-notice-bar>`, спека виджетов §14).
9. **Место — колонка записи, а не поле экрана.** Список мест живой, а опции селекта в описанном
   экране кладутся патчем при `boot()` — живой список туда не ложится. Поэтому место выбирается
   `WxSelect` вне экрана и едет рядом с `values`: `PUT { values, place }` (§5.6).
10. **`random` выбирают в браузере, а не на сервере:** печатаются все баннеры места, кроме
    первого — с `hidden`, случайный открывает скрипт; без JS виден первый. Выбор случаен на
    каждый показ даже при кеше HTML, скрытые картинки с `loading="lazy"` не грузятся. Шага
    «случайный» у `BannerQuery` нет.
11. **Вариант кнопки, убранный из конфига, не запирает баннер:** сохранённый вариант проходит
    назад, выбрать его для новой кнопки нельзя — 422. В карточке такая кнопка получает первый
    вариант конфига, а не выпадает: кнопка важнее оформления.
12. **Видимость по языку.** Слова баннера — заголовок и текст. Баннер без слов виден везде, со
    словами — только на языках, где написан заголовок или текст. Кнопка без подписи на языке
    выпадает, но видимость баннера не решает. Запасного языка нет: чужой язык на картинке хуже,
    чем её отсутствие.
13. **Корзина есть, черновиков и версий нет.** «Включён» — единственное «не на сайте». Новый
    баннер выключен: иначе первое же сохранение недоделанного баннера — это баннер на главной.
14. **Экраны панели.** `/banners` — `WxListDetail`, как у меню: слева места, справа баннеры места
    с перетаскиванием. Баннер — отдельный экран `banners.form` (описанный, проект добавляет поля в
    `extra`). Смена места в форме ставит баннер в конец нового места.
15. **Несколько мест в одном запросе можно** (`banners(['hero', 'promo'])`): местами в названном
    порядке, внутри места — по `position`.

## 3. Схема

```
banner_places
  id
  key          string(64) unique   -- то, чем место просят: hero, promo
  title        json nullable       -- переводимое название своего места; у объявленного не читается
  timestamps

banners
  id
  place_id     FK → banner_places, cascadeOnDelete
  image        json nullable       -- значение wx-media (path, alt, title); обязательна на записи
  image_mobile json nullable       -- то же, под телефон
  video        json nullable       -- значение wx-media с accept: video
  title        json nullable       -- переводимое
  text         json nullable       -- переводимое, простой текст (textarea)
  buttons      json nullable       -- [{ "label": {"en": "…"}, "link": {Link}, "variant": "primary" }]
  layers       json nullable       -- слои (§Л3); null — слоёв не видел, [] — слои убрали
  enabled      bool default false  -- решение 13
  position     int default 0       -- порядок внутри места
  extra        json nullable
  softDeletes, timestamps

index (place_id, position)
```

- **Дефолтов у строковых колонок нет** — нарочно: `enabled` и `position` числовые. Понадобится
  дефолт у строки — считать символы против длины (`docs/pitfalls/laravel-and-php.md`, MariaDB).
- `image` в базе `nullable`, хотя обязательна: обязательность — правило формы (решение 8).
  Картинку, удалённую из библиотеки, база не держит внешним ключом (`wx-media` хранит путь), и
  карточка без картинки на сайт не выходит (§5.2).
- Модели — `Place` и `Banner`; колонка `enabled`, а не `visible`/`hidden`: у модели Eloquent это
  свойства, а не атрибуты.
- Каскад на `place_id` — страховка, а не механизм: API удаляет только пустое место (§5.6).

## 4. На сайт — хелпер

Место печатает `<x-webx-banners place="hero" />`. Шаблон, который рисует место сам, берёт
`banners('hero')->get()` и `banners_layout('hero')` и ведёт себя так же — каркас в гайде
`apps/docs/guide/banners.md` («A template»):
`<picture>` с `<source>` под `image_mobile` по `breakpoint`, первый баннер `eager`, остальные
`lazy`; видео, которому адрес ставит скрипт (не на телефоне без `video_on_mobile` и не при
`prefers-reduced-motion`); кнопки — `<a>` с классом варианта и `rel` как есть
(`Link::relAttribute()` уже добавил `noopener noreferrer` новой вкладке); виды — `single`,
`random` (решение 10), `slider` со `scroll-snap` и параметрами из `data-banners`.

Пустое место — пустой список, страница отвечает 200. Место, которого нет ни в конфиге, ни в
таблице, — тоже пустой список, а не исключение: шапка без баннера лучше белого экрана.

## 5. Модуль

### 5.1. Модели и зависимости

- `Place` — `HasTranslations` (`title`), `hasMany(Banner)`. Ключ — `[a-z0-9-]{1,64}`, с буквы.
  `Places` (сервис) — объединение конфига и таблицы: объявленное место без строки существует,
  строка создаётся `Places::row($key)` в транзакции первого баннера. Объявленное место, убранное
  из конфига при живой строке, становится своим.
- `Banner` — `HasExtra`, `HasTranslations` (`title`, `text`), `SoftDeletes`, `belongsTo(Place)`.
  `scopeVisible()` — включён и не в корзине. Новый и перенесённый баннер встаёт в конец места
  (`max(position) + 1`).
- `require`: `module-admin`, `module-media`, `localization`, `mcp`. Ни `module-blocks`, ни
  `routing`: адреса кнопок считает `wx-link` (`LinkType::resolve()`).

### 5.2. Карточка

`Rendering\Cards` — баннер так, как его читает шаблон:

```php
[
    'id' => 5,
    'anchor' => 'banner-5',
    'place' => 'hero',                // ключ места
    'title' => 'Spring sale',         // на языке страницы, иначе ''
    'text' => "…",                    // то же; шаблон печатает nl2br(e())
    'image' => [                      // MediaValues::resolve() на языке страницы
        'url' => …, 'thumb' => …, 'width' => 1920, 'height' => 720,
        'alt' => '…', 'title' => '…', 'mime' => 'image/jpeg',
    ],
    'image_mobile' => [ … ] | null,   // null — шаблон берёт image
    'video' => [ 'url' => …, 'mime' => 'video/mp4' ] | null,
    'buttons' => [                    // в порядке редактора; без подписи на языке — выпадает
        [
            'label' => 'Book now',
            'url' => '/booking',      // LinkType::resolve(): префикс языка, адрес сущности
            'new_tab' => false,
            'rel' => 'nofollow' | null,  // с новой вкладкой — плюс noopener noreferrer
            'variant' => 'primary',   // вне конфига — первый вариант конфига (решение 11)
        ],
    ],
    'fields' => [ 'badge' => 'New' ], // поля проекта по имени
    // слои, ratio, ratio_mobile — §Л4.1
]
```

- **Кнопка выпадает** без подписи на языке (решение 12) и со ссылкой, у которой
  `available = false` (сущность в черновике или в корзине): кнопка на 404 хуже, чем её нет.
- **Баннер выпадает**, если его картинки нет в библиотеке (`url === null`), — до лимита
  (`BannerQuery::models()`), так что `take(3)` — три напечатанных. Видео, которого нет, — `null`,
  остаётся постер.
- Список любой длины — несколько запросов (библиотека и ссылки пачкой), не по запросу на баннер.

### 5.3. Хелперы и конфиг

`Rendering\BannerQuery extends RecordQuery`:

| Шаг                | Что делает                                                             |
| ------------------ | ---------------------------------------------------------------------- |
| `in('hero')`       | Только из этих мест — ключ, id, модель или список; неизвестное — пусто |
| `only([5, 2])`     | Только эти, в этом порядке                                             |
| `except($banner)`  | Кроме этих                                                             |
| `take(3)`          | Не больше трёх; null или ноль — все                                    |
| `locale('uk')`     | Язык карточек; по умолчанию тот, на котором рисуется страница          |
| `get()`, `first()` | Список карточек или один; сам запрос можно перебирать и считать        |

- `banners(string|int|iterable|null $places = null): BannerQuery` — `banners('hero')` это
  `banners()->in('hero')`. Без места — все включённые баннеры сайта.
- **Место — не категория `RecordQuery`:** у баннера место — колонка, а не пивот. Поэтому `in()` —
  свой шаг (`withStep`) по **ключу**, фильтр — в `narrow()`, порядок — места в порядке `in()`
  (решение 15, `case place_id` в SQL), затем `position`, `id`. `withCategories()` не вызывается.
- `banners_layout(string|int|null $place = null, ?string $layout = null): array` — параметры в
  порядке «пакет ← `options` конфига ← место ← `$layout`» плюс ключ `layout`; вид не из
  `single|random|slider` — вид места. Каждый ключ читается с дефолтом пакета, а не из слияния
  (`mergeConfigFrom` сливает на один уровень). Неизвестное место — параметры по умолчанию.
  Незнакомые ключи `options` отдаются шаблону как есть — сайт может завести свои.
- **Вид места по умолчанию — `default_layout`, а не `layout`:** верхний `layout` в
  `config/webx-<модуль>.php` — лейаут публичных страниц для `webx:doctor` и `webx:panel --sync`.
- Оба хелпера — за `function_exists`, строки в `Doctor\Checks\Helpers`.

Конфиг — `config/webx-banners.php`: `places` (объявленные `hero` — `slider` со слоями, `promo` —
`single` 3/1, `notice` — `single` без картинки), `default_layout`, `options` (`interval`,
`autoplay`, `loop`, `arrows`, `dots`, `pause_on_hover`, `ratio`, `ratio_mobile`, `breakpoint`,
`video_on_mobile`), `variants` (ключ → название; первый — запасной, решение 11), `layers`
(§Л4.4). Каждый ключ объяснён комментарием в самом файле.

- Названия мест и вариантов — простые строки или ключи перевода через `__()`.
- Варианты кнопок попадают в экран `banners.form` патчем `Screens::extend()` при `boot()` (`set`
  доходит внутрь `wx-repeater`). Опции — `trans::…`, чтобы экран говорил на языке открывшего.

### 5.4. Панель

- Пункт меню «Баннеры» верхнего уровня, иконка `image`, `order() = 660` — после команды; права
  `banners.view`, `banners.manage`.
- **`/banners` — `WxListDetail`**, как меню (`WEBX_UI_MODULE_MENU.md` §9). Слева места: название,
  ключ, число баннеров, замок у объявленного, подсказка `banners('<key>')`. «Новое место» —
  диалог с ключом и названием; своё место переименовывается и удаляется из `WxRowMenu`
  (непустое — пункт выключен с подсказкой). Открытое место — `?place=<key>`.
- **Справа баннеры места** — `WxSortableList` с ручкой; `WxRowMenu` — открыть,
  включить/выключить (через форму: `GET` + `PUT` с `enabled`), в корзину; корзина —
  `view=trashed`. На телефоне правая колонка уезжает в ящик.
- **Баннер — отдельный маршрут** `/banners/{id}` и `/banners/new?place=<key>` (`POST` на первом
  сохранении, потом замена адреса); Ctrl+S, вопрос при уходе с несохранённым.
- **Экран `banners.form`** (описанный, одна колонка карточек): «Медиа» — `image`, `image_mobile`
  (`wx-media`, `accept: image`), `video` (`accept: video`); «Слова» — `title`, `text`
  (`localized`); «Кнопки» — `wx-repeater` (`max: 3`, `sortable`): `label`, `link`, `variant`;
  «Слои» — только у места со слоями (§Л5.1); «Настройки» — `enabled`; `project-fields`.
  Место — `WxSelect` над экраном, вне `values` (решение 9).

### 5.5. Права

`banners.view` — раздел и списки; `banners.manage` — всё, что пишет: баннеры, порядок, свои места.

### 5.6. API панели

```
GET    /api/cms/banners/places                 → { data: [{ id|null, key, title, declared, layout, count, titles?, layers? }] }
POST   /api/cms/banners/places                 { key, title } → 201 { data: place }
PUT    /api/cms/banners/places/{key}           { title }            только своё
DELETE /api/cms/banners/places/{key}           только своё и пустое; иначе 422 с числом
GET    /api/cms/banners/places/{key}/banners   ?trashed=1 → { data: [{ id, title, thumb, video, enabled, position, updated_at, deleted_at }] }
POST   /api/cms/banners/places/{key}/banners   { values } → 201 { data: { banner, values } }
POST   /api/cms/banners/places/{key}/reorder   { ids }
GET|PUT|DELETE /api/cms/banners/{id}           { data: { banner, values } }
POST   /api/cms/banners/{id}/restore
GET    /api/cms/banners/theme                  §Л6
```

- **Место в списке:** `id` — `null` у объявленного без строки; `title` — на языке панели;
  `declared` — есть ли ключ в конфиге; `layout` — вид после слияния; `count` — баннеры вне
  корзины; `titles` — все языки своего места (для диалога переименования); `layers` — у места со
  слоями (§Л6). Порядок: объявленные в порядке конфига, затем свои по названию.
- `POST places` — ключ `[a-z0-9-]`, до 64, с буквы, не занят ни строкой, ни конфигом; 422 под
  `key`. `title` — карта языков или строка (язык по умолчанию), обязателен на языке по
  умолчанию, до 120 символов — 422 под `title.<язык>`. `PUT` сливает языки поверх сохранённых.
- `PUT`/`DELETE` объявленного места — 403 (рисует только контроллер). `DELETE` непустого — 422
  под `place` с числом (корзина считается: каскад снёс бы и её) и полем `count`; вечного удаления
  баннера нет — сначала восстановить и перенести. Удачный `DELETE` — 204.
- **Баннеры места:** неизвестный ключ — 404; объявленное место без строки — `{ data: [] }`.
- `POST places/{key}/banners` — место без строки получает её в той же транзакции; баннер встаёт в
  конец. `reorder` — `{ ids }`, 204; не-список или чужие id — 422 под `ids`.
- **Форма:** `banner` — `{ id, place, title, enabled, deleted_at }`; `values` — медиа, `title` и
  `text` картами языков, `buttons`, `layers`, `enabled`, поля проекта. `PUT` — `{ values, place? }`,
  неизвестное место — 422 под `place`. `POST` и `PUT` — одна `Panel\BannerForm::save()` в
  транзакции: отказ не оставляет ни баннера, ни ленивого места. Места — `Panel\PlaceEditor`;
  обеими дверьми ходят и контроллеры, и MCP.
- **Проверки в два шага:** сначала свои (`place`, строки кнопок, картинка, слои), потом экран.
  Нет картинки — `image` (и «видео без картинки»); не тот вид файла — поле медиа текстом
  `MediaValues`; кнопок больше трёх — `buttons`; строка — `buttons.<n>.link` /
  `buttons.<n>.variant`, `n` — номер строки, как её видит редактор. Пустая строка кнопки
  выбрасывается; подпись без ссылки — 422; ссылка без подписи и пустой вариант проходят.
  Убранный из конфига вариант узнаётся по вариантам, которые уже есть у баннера.

### 5.7. MCP

`banners_create`, `banners_update`, `banners_delete`, `banners_reorder` — через те же `Panel\*`.
Место называется ключом, баннер — id. Медиа — ключ файла библиотеки, неизвестный или не того вида

`link` — как у `menu_add_link`; вариант не из конфига — отказ со списком ключей. Ресурс
`banners://catalog`: варианты и виды; места с `declared`, `layout`, `layers` и баннерами по
порядку (`enabled`, `written_in`, `has_video`, число слоёв). Описание говорит, что на сайт

## Слои

Слой — текст, картинка или кнопка, которые редактор ставит на картинку баннера руками, с
положением, размером и видом: на каждом слайде своя композиция (крупный заголовок слева, круглая
картинка с надписью справа, процент у края). Баннер со слоями — картинка-фон плюс список слоёв;
разметку и математику положения отдаёт пакет, чтобы панель и сайт рисовали одно и то же.
Главное требование — **координаты относительно картинки**, а не окна и не рамки: баннер на 1920
и на 1024 — одна композиция, уменьшенная целиком. Гайд — раздел «Layers»
`apps/docs/guide/banners.md`.

Код ссылается на «§N of the layers spec» и «decision N of the layers spec» — это §ЛN и решение ЛN
ниже.

### Л1. Границы

**Внутри:** колонка `layers`; четыре вида слоя — `text`, `image`, `button`, `buttons` (кнопки
баннера); подстановки полей баннера (`{title}`, `{text}`); геометрия в долях ширины картинки;
раскладка под телефон; анимация появления; выход за край; компоненты `<x-webx-banners>` и
`<x-webx-banner>` и `layers.css`; редактор в форме баннера; проверки, MCP, демо.

**Снаружи:** фигуры, линии, маски, градиенты; группы слоёв; произвольный HTML и стили сайта в
слое; ключевые кадры и таймлайн; видео как слой; копирование слоёв между баннерами; тип блока
`banners`.

### Л2. Решения

1. **Единица всего — процент ширины картинки.** `x`, `y`, ширина, кегль, отступ, скругление —
   «процентов ширины картинки»; `y` — тоже от ширины, а не от высоты: одна единица на всё, и
   положение не зависит от обрезки рамкой. На сайте это `cqw` сцены (§Л4.2) — баннер
   масштабируется целиком без скрипта. Исключение — межбуквенный интервал: в `em`, он следует за
   шрифтом.
2. **Сцена — это картинка, а не рамка.** Рамка места имеет пропорции `ratio`, картинка в ней —
   `cover`. Слои стоят на **сцене** — коробке с пропорциями самой картинки, которая покрывает
   рамку так же, как `cover` — картинкой. Слой приклеен к пикселям картинки при любой обрезке;
   что за рамкой — обрезается вместе с картинкой.
3. **Две раскладки: компьютер и телефон.** Геометрия (положение, ширина, кегль, отступы,
   скругление, интервал, поворот, «скрыт») хранится отдельно под `desktop` и `mobile`; вид
   (цвет, шрифт, насыщенность, выравнивание, регистр) — общий. `mobile: null` — как `desktop`.
   Переключение — **по окну**, той же границей `breakpoint`, что `<source media>` у
   `<picture>`: иначе картинка уже телефонная, а слои компьютерные. Осознанное исключение из
   правила «контейнерные запросы вместо медиа» — его диктует `<picture>`.
4. **Положение общее для всех языков.** Слой ширины `w` переносит строки сам, длинный язык
   встаёт в ту же коробку. Не влезает — правят ширину или текст; переопределения по языку нет.
5. **Поля баннера попадают на картинку подстановками.** `title`, `text`, `buttons` остаются в
   форме источником слов; текст слоя может содержать `{title}` или `{text}`, кнопки ставит слой
   `buttons`. Баннеру места со слоями, у которого `layers` — `null`, редактор кладёт **три слоя
   по умолчанию** — `{title}` (`h2`), `{text}` (`p`), `buttons` колонкой слева
   (`LayerRules::defaults()` и `defaultLayers()` панели — одни числа). `[]` — слои убрали, и это
   сохраняется как есть. Удалили слой `{title}` — поле остаётся именем баннера и решает
   видимость. Так `banners_update` меняет заголовок слайда, не трогая JSON слоёв, а подстановка
   внутри текста даёт смешанное («{title} — до −50 %»). Отвергнуты «слои вместо полей» (заголовок
   дважды) и «слои вдобавок к раскладке шаблона» (две системы раскладки).
6. **Текст слоя — по языкам, с запасным языком.** Карта языков всегда; нет на языке страницы —
   язык сайта по умолчанию, нет и его — первый заполненный. Слой выпадает, только если текста нет
   нигде. Мягче решения 12: слой — часть композиции, дыра хуже чужого языка. Видимость баннера
   по-прежнему решают только `title` и `text`; подстановки запасного языка не берут.
7. **Порядок в списке — стопка, порядок чтения — положение.** Верхний в списке — ближе к
   зрителю (`z-index`); в HTML слои идут сверху вниз, слева направо по раскладке `desktop`.
8. **Слои — настоящий текст** (`<h2>`/`<p>`): его читают поиск, диктор и перевод браузера. Тег —
   из конфига (`p`, `h2`, `h3`, `span`); `h1` — только если место его добавило (§Л4.4): в
   слайдере пять `h1`.
9. **Без блока — Blade-компоненты, которые ставятся куда угодно.** Компоненты не знают, где
   стоят: ширину даёт родитель, высоту — `ratio` места. `<x-webx-banners place>` — место целиком,
   `<x-webx-banner :banner>` — один баннер; ставятся в шаблон, лейаут, вьюху типа блока темы.
10. **Разметка слоёв — в пакете.** Математика сцены одна, и панель обязана рисовать ровно то же,
    что сайт, иначе редактор врёт. Тема перекрывает вьюхи обычным `vendor/webx-banners`.
11. **Шрифты и цвета — из темы.** Шрифт — `heading` или `body` (`var(--site-font-<имя>)`), `null`
    — как у сайта; цвет — `token:<имя>` (`var(--site-color-<имя>)` без запасного значения: токена
    нет — цвет наследуется) или `#rrggbb[aa]`. Панель вид сайта не правит, но **показывать** его
    на холсте обязана (§Л6). Сайт без темы — системный шрифт и свободный цвет.
12. **Анимация — появление и одна петля.** Появление (`fade`, `rise`, `slide-start`,
    `slide-end`, `zoom`) с задержкой и длительностью — когда слайд становится активным; петля
    (`spin`, `float`) — для декоративного. Выключено при `prefers-reduced-motion`; без JS слои
    стоят на месте. Своих ключевых кадров нет.
13. **Выход за край — по выбору места** (`'overflow' => true`). Рамка не режет слои (картинка
    режется своим `<img>`); по горизонтали — `overflow-x: clip` на обёртке, а не `hidden` (тот по
    одной оси делает прокручиваемой и другую, и низ снова срезан). Слайдер такого места листается
    только затуханием: неактивные слайды прозрачны, ленте можно снять `overflow: hidden`, соседи не
    покажутся. Обёртка — `z-index: 1` над следующим блоком; декоративная картинка (пустой `alt`) —
    `pointer-events: none`. Высоту пакет не меняет — место под вылезшим оставляет сайт. Без JS
    лента со `scroll-snap` режет и по вертикали — приемлемо, за краем живёт декоративное.
14. **Лимиты.** До 20 слоёв (`webx-banners.layers.max`); текст — до 500 символов на язык; числа —
    в диапазонах `LayerRules`. Слой целиком за обрезкой рамки — предупреждение в редакторе, не
    отказ.

### Л3. Данные

**Л3.1. Колонка.** `banners.layers` — `json nullable` (миграция
`2026_10_13_000000_add_layers_to_banners_table`). Переводимые тексты — картами языков внутри JSON,
как подписи кнопок; `HasTranslations` на `layers` не вешается — переводы читает `Rendering\Layers`.

#### Л3.2. Слой

```jsonc
{
  "id": "k3f9",                     // [a-z0-9]{4,12}, уникален в баннере: выделение, undo, ошибки
  "type": "text",                   // text | image | button | buttons
  "name": "Headline",               // имя в списке слоёв, не печатается
  "text": { "uk": "{title} — до −50 %" }, // text и button: карта языков (Л2.6), подстановки §Л3.3
  "tag": "h2",                      // text: из тегов места
  "image": { "path": "…", "alt": { … } }, // image: значение wx-media, accept: image
  "link": { /* Link */ }, "variant": "primary", // button: как кнопка баннера
  // buttons — своих полей нет: всё из buttons баннера
  "style": {                        // общее для обеих раскладок
    "font": "heading",              // heading | body | null
    "weight": 700, "italic": false, "uppercase": false,
    "align": "start",               // start | center | end
    "line_height": 1.1,             // 0.8…3
    "color": "token:text-inverse",  // token:<имя> | #rrggbb[aa] | null
    "background": null, "opacity": 1, "shadow": false
  },
  "frames": {                       // числа — % ширины картинки (Л2.1)
    "desktop": {
      "x": 5.22, "y": 5.22,         // −50…150 (за краем — Л2.13)
      "origin": "tl",               // точка коробки в x,y: tl t tr l c r bl b br
      "w": 40,                      // 1…150; высота — по содержимому / пропорциям картинки
      "size": 1.71,                 // кегль, 0.3…20
      "pad": 0, "radius": 0,        // 0…10, 0…50
      "tracking": 0,                // em, −0.2…1
      "rotate": 0, "gap": 1,        // −180…180; gap у buttons, 0…10
      "hidden": false
    },
    "mobile": null                  // null — как desktop
  },
  "motion": { "in": "rise", "delay": 200, "duration": 600, "loop": null }
}
```

- **`origin`** — для текста, который растёт не вправо: процент у правого края ставится
  `origin: "tr"`, и длинный язык растёт влево, а не за край.
- Текст, одинаковый на всех языках, пишется один раз — на языке по умолчанию (Л2.6); инспектор
  подсказывает в пустых языках, что будет напечатано.
- **`buttons`** — одна группа на баннер: кнопки в строку с переносом, `align` — к какому краю
  коробки, `size` — кегль всех. Отдельная кнопка со своей ссылкой — слой `button`.
- Высота картинки-слоя — из её пропорций (`width`/`height` библиотеки).
- Диапазоны и значения по умолчанию — константы `Panel\LayerRules`: числа округляются до сотых,
  недостающее встаёт по умолчанию, лишние ключи выбрасываются — сайт никогда не гадает.

#### Л3.3. Подстановки

- Имён два: `{title}` и `{text}`, точно так. Подставляется значение поля на языке страницы,
  `{text}` — с переносами `<br>`. Экранирование — после подстановки, всего текста: HTML из поля
  не проходит.
- Прочие фигурные скобки — просто текст («{2026}» законно). Редактор показывает известные
  подстановки плашкой, а незнакомые `{…}` — предупреждением, чтобы `{titel}` не уехал молча.
- Порядок: сначала выбирается текст слоя (Л2.6), потом в него подставляются поля **на языке
  страницы** — слой `{title}`, записанный только на `uk`, на английской странице печатает
  английский заголовок.
- Слой, у которого после подстановки остались только пробелы и знаки, выпадает.
- Холст показывает текст подставленным на языке холста; слой с текстом ровно `{title}` в списке
  зовётся «Заголовок баннера» (`{text}` — «Текст баннера»), если своего имени нет.

**Л3.4. Проверки и отказы.** `Panel\LayerRules` в `BannerForm::save()` среди своих проверок. 422 —
под `layers.<n>.<поле>`, `n` — номер слоя, как его видит редактор:

- не тот `type`, `id` не по маске или повторился, больше 20 слоёв, второй `buttons` — `layers`;
- число вне диапазона — `layers.<n>.frames.desktop.x` и т. п.;
- `tag` не из тегов места, `font` не из списка, цвет не `token:`/`#hex` — под полем;
- картинка не картинка или нет в библиотеке — `layers.<n>.image` текстом `MediaValues`;
- кнопка: подпись без ссылки — `layers.<n>.link`; вариант — как у кнопок баннера (решение 11).

Выбрасываются, а не отбиваются: текстовый слой, пустой на всех языках, и кнопка без слов и без
ссылки — как пустая строка кнопки баннера.

### Л4. На сайте

**Л4.1. Карточка.** `Rendering\Cards` добавляет к карточке (§5.2) `layers` — в порядке чтения
(Л2.7), `[]` — слоёв нет или место их не печатает, — и `ratio`/`ratio_mobile` картинок для сцены.
Слой в карточке: `id`, `type`, `tag`, `text` (на языке страницы, подстановки раскрыты), `image`,
`button`, `buttons`, `z` (место в стопке), `style` (custom properties обеих раскладок) и `class`.

- Выпадают: текст и кнопка без текста или пустые после подстановки; `buttons` без кнопок на
  языке; кнопка на недоступную сущность; картинка, которой нет в библиотеке; слой, скрытый в
  обеих раскладках.
- Слои стоят в той же пачке запросов, что баннеры (`Layers::wants()`), своих запросов нет.
- `style` собирает `Rendering\Layers` — одна функция для карточки и MCP. В CSS попадают только
  числа и проверенные цвета, пользовательский текст — никогда.

#### Л4.2. Сцена

- Рамка `.webx-banner` — `aspect-ratio: var(--ratio)` и `container-type: size`; сцена
  `__stage` — по центру, `width: max(100cqw, 100cqh * var(--img))` с пропорциями картинки
  (`--img`) и `container-type: inline-size`, то есть покрывает рамку, как `cover`. `cqw` слоя
  считается от сцены — от ширины картинки на экране: `left: calc(var(--x) * 1cqw)` и т. д. Это и
  есть решение Л2.1.
- Раскладка `mobile` — тот же набор с префиксом `--m-*`. `resources/css/layers.css` — **один
  файл**: сайт печатает его раз на страницу, а блок между маркерами `mobile:start`/`mobile:end` —
  ещё раз внутри `@media (max-width: breakpoint − 1)` на каждую границу; панель импортирует тот
  же файл и включает этот блок классом `is-mobile`. Тест держит, что в `dist` npm он байт в байт.
- `object-position` картинки и сцена — по центру; меняется одно — меняется и другое.

#### Л4.3. Компоненты

```blade
<x-webx-banners place="hero" />                                   {{-- the whole first screen --}}
<x-webx-banners place="hero" class="b-hero__media" />            {{-- a column of the theme's hero --}}
<x-webx-banner :banner="banners('promo')->first()" />            {{-- one banner the template chose --}}
```

- **`<x-webx-banners place layout?>`** — место целиком в его виде. `slider` — слайдер виджетов
  (`<x-webx-slider variant="hero">`) с параметрами места; без виджетов — своя лента со `scroll-snap`,
  автопрокруткой, паузой, стрелками и точками (`Rendering\Stylesheet::scripts()`, печатается раз
  и ждёт `DOMContentLoaded`: мест на странице бывает два). `single` — первый баннер, `random` —
  решение 10. Пустое место — ничего, даже обёртки: шаблону не нужен `@if`.
- **`<x-webx-banner :banner layout? eager?>`** — рамка, `<picture>`, видео, сцена и слои; у
  баннера без слоёв — слова и кнопки, как в образце гайда. В слайдере — `role="group"`,
  `aria-roledescription="slide"`, `aria-label` из `title`.
- **Размер даёт родитель** (Л2.9): в колонке в половину ширины баннер вдвое меньше, композиция та
  же; раскладка `mobile` при этом — по окну (Л2.3).
- Атрибуты (`class`, `id`, `data-*`) ложатся на внешнюю обёртку. Вьюхи
  `vendor/webx-banners/components/banners.blade.php` и `banner.blade.php` перекрываются темой.
- Анимация появления — класс `is-in-<вид>`, стартует, когда у ближайшего `.swiper-slide` есть
  `.swiper-slide-active`, вне слайдера — сразу. Только CSS.

#### Л4.4. Конфиг

- `webx-banners.layers.tags` — теги текстового слоя (тег → название), `h1` нарочно нет;
  `webx-banners.layers.max` — 20.
- У места: `'layers' => true` включает редактор слоёв (у `hero` включён), `'overflow' => true` —
  выход за край (Л2.13), `'tags'` — расширяет теги (место — единственный `h1` страницы).
- **Слои включает место, а не баннер:** у `notice` и `promo` их нет, форма их не показывает.
  Включается только конфигом — у своего места администратора слоёв нет.
- Баннер, перенесённый в место без слоёв, их не теряет: колонка остаётся, карточка их не отдаёт.

### Л5. Редактор

**Л5.1. Где живёт.** Узел `wx-banner-layers` (`kind: 'field'`, `name: "layers"`) — свой тип модуля в
`module.ts` (серверный — `Screens\LayersType`). Карточка «Слои» видна, только если у места есть
`layers`; смена места в селекте показывает и прячет её без перезагрузки. Ядро не меняется:
перетаскивание — pointer events с `setPointerCapture`, как в `WxImageEditor`.

**Л5.2. Раскладка экрана.** Холст и под ним список слоёв, справа инспектор; на узком экране
инспектор уезжает под холст.

- **Холст** — тот же `layers.css` и та же сцена: что видно здесь, то и на сайте. Картинка
  показана целиком, обрезка рамки места — затемнением поверх; у места с `overflow` под картинкой —
  штрихованная полоса. Ширина холста меняет только масштаб.
- **Компьютер / Телефон** — раскладка и картинка. На «Телефоне» первое изменение слоя без своей
  раскладки копирует `desktop`; «Как на компьютере» сбрасывает `mobile` в `null`.
- Поля `title`, `text`, `buttons` формы видны всегда: это источник слов, а не слои.
- **Язык холста** связан с языками поля текста в инспекторе.
- **Список слоёв** — `WxSortableList`, сверху передний план (Л2.7); глаз — `hidden` текущей
  раскладки, замок — не выделяется на холсте; тип и имя (иначе начало текста).
- Баннер, созданный агентом без `layers`, печатается без слоёв, пока его не откроют в панели.

**Л5.3. Жесты.** Клик выделяет, Tab ходит по слоям; перетаскивание — сдвиг, боковые ручки — ширина,
угол — ширина с кеглем. Стрелки — 0,05 (с Shift — 0,5), `Delete`, `Ctrl+D` — дублировать слой,
`Ctrl+Z` / `Ctrl+Shift+Z` — свой стек на 100 шагов (перетаскивание — один шаг), `Esc`. Прилипание к
краям и центру картинки, обрезки и других слоёв — в 6 px экрана, `Alt` — без него. Двойной клик —
фокус в поле текста инспектора; правки прямо на холсте нет.

**Л5.4. Инспектор.** Поля слоя §Л3.2 по группам: слова, геометрия (`origin` — сетка 3×3, числа с
подписью единицы), вид (цвет и фон — `WxColorPicker` с палитрой темы первыми образцами), движение.
Кнопки баннера правятся в поле «Кнопки» формы, у слоя `buttons` — только вид и зазор. Геометрия
подписана раскладкой («Телефон: свой» / «как на компьютере»), чтобы было видно, что правится.

### Л6. API и MCP

```
GET /api/cms/banners/theme   → { data: { tokens_css, fonts_css, palette: [{ key, value }] } }
```

- `tokens_css` — `:root` токенов темы, `fonts_css` — `@font-face` с абсолютными адресами,
  `palette` — `--site-color-*`. Темы нет — пустые строки и `[]`.
- Место в `GET places` несёт `layers`: `ratio`, `ratio_mobile`, `breakpoint`, `overflow`, `tags`,
  `variants` — по ним холст рисует рамку. `GET|PUT /banners/{id}` — `values.layers` формы §Л3.2.
- **MCP:** `banners_create` (`layers`) и `banners_update` (`values.layers`) — той же формы;
  картинка-слой — ключ библиотеки, слова строкой — язык по умолчанию. Отказ — текстом 422 с путём
  `layers.<n>.<поле>`. Ресурс `banners://layers` — справка: единица, сцена, раскладки, `origin`,
  подстановки, лимиты; описание говорит, что композицию проверяет человек на холсте.

### Л7. Мелочи

Сменили картинку на другую по пропорциям — слои остаются, `y` может уйти под низ, редактор
предупреждает. У видео слои лежат над ним, сцена — по пропорциям постера. В поиске по сайту слоёв
нет: баннер не страница.

### Л8. Тесты, которые обязательны

Геометрия, запасной язык и подстановки (`{2026}`/`{titel}` как есть, HTML экранирован), каждый
отказ §Л3.4, `layers.css` в `dist` байт в байт, `style` только из чисел, разметки
`<x-webx-banners>` по видам. Вёрстку — в браузере (Playwright, не jsdom): на 1440, 1024 и 375
кромка слоя — `x`·ширина картинки / 100 до пикселя при любой обрезке; холст и сайт на одной
ширине дают те же прямоугольники; выход за край — поверх соседа, без боковой прокрутки.

### Л9. Выпуск слоёв

Выпущено (L1 — сервер, L2 — редактор, L3 — гайд, демо и замеры в браузере). **Открыто:**

- своё место администратора слоёв не получает — нет выключателя «Слои» в диалоге места;
- дублирования баннера целиком (со слоями, с новыми `id`) в панели нет — только `Ctrl+D` слоя;
- прилипание по вертикали — только к краям картинки, обрезки и верху других слоёв;
- телефон (жесты пальцем, инспектор под холстом) — за владельцем.
