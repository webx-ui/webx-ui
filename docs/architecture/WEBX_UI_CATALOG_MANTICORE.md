# Движок Manticore — `module-catalog-manticore`

Спутник ядра каталога: реализация `CatalogEngine` на Manticore Search для каталогов, которые
`SqlEngine` уже не тянет (больше пары тысяч товаров). Архитектура семейства —
[`WEBX_UI_CATALOG.md`](WEBX_UI_CATALOG.md) (§4.2, §4.3, §5), ядро, контракт движка и очередь
индексации — [`WEBX_UI_MODULE_CATALOG.md`](WEBX_UI_MODULE_CATALOG.md); здесь они не повторяются.
Статус: спека согласована 01.10.2026; M1 (php-ядро пакета), M2 (поиск), M3 (панель и MCP) и M4
(приёмка на выгрузке reference-shop) сделаны — §7, итоги замеров — §4. Порядок работ — §5.

## 1. Решения (не переоткрывать)

Приняты в обсуждении 01.10.2026.

1. **Пакет — `module-catalog-manticore`, а не библиотека.** Без ядра каталога ему нечего
   индексировать — тот же довод, что собрал SEO одним `module-seo`. Своего пункта меню нет, место
   в панели (состояние индекса, очередь) — на правах раздела без меню.
2. **Manticore ставим не мы.** Пакет подключается к готовому серверу по HTTP JSON API:
   `MANTICORE_HOST`, `MANTICORE_PORT` (9308). Сервер общий для нескольких проектов — нормальный
   случай, а не исключение (так живёт хомлаб).
3. **`MANTICORE_TABLE_PREFIX` обязателен и без умолчания.** Из `APP_NAME` его не вывести: два
   демо — один сайт с одним `APP_NAME` и одной Manticore, и они молча перетёрли бы индексы друг
   друга. Без префикса движок не стартует, `webx:doctor` говорит почему. Префикс — `[a-z0-9_]`,
   таблицы — `{prefix}_catalog_products_{locale}`, суффикса `_idx` нет. Пакет трогает только
   таблицы своего префикса; doctor предупреждает, если префикс — начало чужих имён.
4. **Обычная жизнь — по товару, через очередь ядра** (§5.3 архитектуры): сохранение помечает,
   воркер пишет пачкой, упавший Manticore не роняет сохранение. Полная перестройка нужна, только
   когда Manticore подключили к каталогу с товарами, поменялась схема индекса (язык, морфология,
   новая версия пакета) или сервер потерял данные.
5. **Таблица на язык, и в каждой — все языки сайта.** Свой язык — в основных полях с бо́льшим
   весом, остальные — в поле «на других языках» с меньшим; артикул, штрихкод и бренд — в каждой.
   Нет перевода — в основные поля идёт текст основного языка, как на витрине. Так товар находится
   словом на любом языке сайта со страницы любого языка, и это гарантия, а не «обычно в названии
   есть латиница».
6. **Морфология таблицы — процессоры всех языков сайта, свой первым.** У языков на одном
   алфавите выигрывает первый процессор, поэтому немецкая таблица разбирает слова по-немецки,
   английская — по-английски; ради этого таблицы и разделены. Соответствие «язык → процессоры» —
   конфиг пакета с умолчаниями; язык без настройки — без морфологии.
7. **Поиск по началу слова включён всегда** (`min_prefix_len`) — подстраховка для языков, где
   морфология слабая или её нет.
8. **Перестройка — подменой, без окна с неполным каталогом.** `--rebuild` собирает
   `{table}_next` рядом, витрина работает на старой, затем `ALTER TABLE … RENAME`. Это делается
   в v1: добавление языка на живом магазине — реальный сценарий.
9. **Устаревшую схему видит doctor, перестройку запускает человек.** `prepare()` сравнивает
   требуемую схему с живой; на 93 тысячах товаров перестройка — минуты нагрузки, и время для неё
   выбирает человек.

10. **Карточка товара от Manticore не зависит** — она из базы по адресу. Без движка ломаются
    только списки: категория, фильтры, поиск.
11. **Каталог до `sql_engine_limit` откатывается на `SqlEngine` сам**: покупатель не замечает,
    в логе предупреждение, doctor показывает.
12. **Каталог больше лимита отвечает 503 с `Retry-After`** — «каталог временно недоступен», шапка,
    меню и подвал на месте. Не 500 и не пустой список: 503 поисковик переждёт, пустую категорию с
    200 — запомнит. `SqlEngine` с фасетами на 93 тысячах положил бы базу.
13. **Панель откатывается на `SqlEngine` всегда**, с плашкой над списком: человек один, нагрузка
    небольшая, работа не встаёт.
14. **Недоступность запоминается на полминуты** после первой ошибки — дальше запасной путь сразу,
    без ожидания; таймаут соединения 1–2 секунды, а не 30 по умолчанию.

15. **Встроенного нечёткого поиска нет.** `fuzzy=1` с морфологией не находит ничего, без неё —
    часть опечаток (§2).
16. **Пустой результат — второй заход:** другая раскладка среди языков сайта, затем `CALL QSUGGEST`
    на каждое слово и поиск исправленным запросом. Сверху — «Показаны результаты для …, искать
    …» (две строки, переводимые, шаблон переопределяемый).
17. **В панели — те же два захода**, подсказок при вводе нет.
18. **Без Manticore — только `LIKE`** `SqlEngine`, без исправлений: для запасного режима
    достаточно.

19. **Коды товара — в двух видах:** артикул, штрихкод и внешний ID как есть (разбиты по
    разделителям) и нормализованные — нижний регистр, только буквы и цифры, поиск по подстроке
    (`infix_fields`). Запрос нормализуется так же; спецсимволы ввода экранируются всегда — `/`,
    `-` и кавычки ошибкой не становятся.
20. **Точное совпадение кода — первым**, выше любых совпадений по названию.
21. **Витрина: запрос ровно равен артикулу или штрихкоду одного опубликованного товара — сразу
    его карточка** (302). В панели — одна строка в списке.
22. **Подстрока — только для кодов.** Для названий хватает морфологии и начала слова, а индекс
    от подстрок заметно растёт.

23. **Смысл фасетов — ядра** (§8.1 спеки ядра): выбранный сужает всё, кроме себя; дерево — с
    потомками; число — min/max. Manticore отвечает ровно как `SqlEngine`, только быстрее.
24. **Поля индекса — из `Facet::field()`**; множественные значения (категории с предками,
    значения свойств) — MVA. Значения всех справочных свойств — один атрибут `property_values`,
    один `FACET` на все, `BatchCountedFacet` раскладывает; числовые свойства — своими атрибутами.
25. **Счётчики — пакетом:** запрос с `FACET` по невыбранным плюс по запросу на каждый выбранный
    без его фильтра, одним сетевым вызовом.
26. **Общий набор тестов на оба движка** — одни сценарии (выборки, счётчики, дерево, числа,
    состояния панели) на `SqlEngine` и Manticore с одинаковым ответом. В CI — сервис-контейнер
    `manticoresearch/manticore` 29, отдельной джобой; локально — Manticore хомлаба с префиксом
    `wxtest_`, тесты убирают за собой и пропускаются, если сервер недоступен.
27. **В панели — «Система → Поисковый индекс»**, только при движке `manticore`: подключение (хост,
    версия, префикс, доступность), по каждой языковой таблице — товаров в индексе против товаров в
    базе, очередь (сколько ждут и с какого времени самый старый), «схема устарела» с кнопкой
    «Перестроить» — задачей в очереди с прогрессом, а не долгим HTTP-запросом.
28. **MCP — `catalog_index_status`**, только чтение: чтобы агент ответил, почему товара нет в
    поиске.

### 1.1. Добавить язык на сайт с товарами

Добавили язык в настройки сайта → doctor: «индекс устарел, запустите
`webx:catalog:index --rebuild`» → перестройка создаёт таблицу нового языка (в ней пока текст
основного языка) и подменой обновляет остальные (их морфология и поле «на других языках»
меняются) → дальше каждый переведённый товар уходит в очередь при сохранении. Витрина всё это
время работает.

## 2. Проверено на Manticore 29.0.2 (хомлаб, 01.10.2026)

Временные таблицы `wxtmp_*`, созданы и удалены.

- Товар с русским названием без латиницы и английским «Protective case for phone»: в `_ru`
  (`lemmatize_ru_all, stem_en`) находится по case, cases, чехлы, чехлов. В `_en` с одним
  `stem_en` «чехлы» не находит, с `stem_en, lemmatize_ru_all` — находит: морфология нужна всех
  языков, а не только своего.
- `libstemmer_de, stem_en`: находятся Schutzhüllen, cases, phones.
- Веса полей: «кабель» в `_ru` — 10643 (своё поле), «cable» — 3643 (поле других языков).
- Украинский: `lemmatize_uk_all` есть, но неполный — «чохли» находит «чохол», «чохлів» нет;
  `libstemmer_uk` отсутствует. Это словарь Manticore, а не схема; лечится синонимами или
  словоформами — волна B.
- `ALTER TABLE … morphology=` и `ALTER TABLE … RENAME` работают.
- Опечатки: `fuzzy=1, distance=2` с `lemmatize_ru_all, stem_en` — ни одной из шести; с `none` —
  «наушнеки» и «headphnes» да, «кабль» и «чехлол» нет. `CALL QSUGGEST` с морфологией исправил все
  пять (чехлол, кабль, наушнеки, headphnes, телефрн). Раскладка «xt[jk» → «чехол» и
  `CALL AUTOCOMPLETE` («чех» → чехол) работают.
- Артикулы `AT-1234/56`, `NGK.BKR6E-11`: стандартная разбивка находит «AT-1234», «1234», «BKR6E»,
  но не «at1234» и «bkr6e11», а «AT-1234/56» целиком — синтаксическая ошибка (`/` — оператор).
  `blend_chars` хуже: «AT-1234» перестаёт находиться. Нормализованное поле с подстрокой находит
  at123456, at1234, bkr6e11, 123456 и «34/5».

## 4. Приёмка

Пакет готов, когда на выгрузке reference-shop (93 525 товаров) в Manticore хомлаба с префиксом
`webx_cms_local`:

- полная перестройка проходит, её время записано;
- категория с фильтрами и счётчиками — **< 100 мс** на сервере;
- поиск с исправлением опечатки — **< 150 мс**;
- сохранённый товар на витрине — ~~< 5 с при работающем воркере~~ **≤ 60 с** (пересмотрен
  01.10.2026, M4: очередь индекса разбирает планировщик раз в минуту, сам проход — 51 мс;

## 6. Открыто

- **Колонка сменила тип — до перестройки её как будто нет.** Живая схема (§7, M3) оставляет только
  колонки того же типа: атрибут, ставший из строки JSON, не спрашивается и не пишется, фасет по
  нему пуст до `--rebuild`. Сейчас таких смен нет; появится — решать вместе с ней.
- **Сохранённый товар доходит до витрины за минуту.** Очередь разбирает только планировщик
  (`webx:catalog:index` раз в минуту); порог §4 пересмотрен на ≤ 60 с. Если понадобится быстрее —
  ядро после сохранения ставит в очередь Laravel одну задачу «разобрать очередь индекса» с
  замком, планировщик остаётся страховкой (при работающем воркере ~1 с).
- **Страница категории целиком — ~320 мс на рабочей машине**, из них движок ~45, пустая страница
  сайта — ~130. Остальное — карточки и подписи фасетов из базы (SQLite, OSPanel); это ядро
  витрины, а не движок. Профилировать на хомлабе, где база и PHP боевые.
- **Консольная перестройка и кнопка панели друг о друге не знают.** 409 отвечает только на задачу
  панели; кнопка, нажатая во время `--rebuild` из консоли, пересоздаст `_next`, и консольный
  прогон упадёт на записи. Страница эту перестройку видит (§7, M4), но кнопку не прячет: таблица
  `_next`, оставленная убитой перестройкой, держала бы её вечно.
- **Перестройку обрывает флаг недоступности.** Один отказ соединения помечает сервер упавшим на
  `down_for` секунд — для всех процессов, и следующая запись перестройки падает «failed less than
  30 seconds ago». Старые таблицы на месте, перестройку запускают снова. Видно было только под
  стендом, исчерпавшим порты (ловушка в `docs/pitfalls/laravel-and-php.md`, «Manticore»).

## 7. Как легло в код

Где код разошёлся с §1–§5 и почему. Решения §1 не менялись.

### M1: php-ядро пакета

- **Пакет.** `php/packages/module-catalog-manticore`, namespace `WebxUi\Catalog\Manticore`,
  зависит от `module-catalog` (плюс `illuminate/http` и Guzzle — HTTP-клиент). Движок —
  `ManticoreEngine`, зарегистрирован в `CatalogEngines` под ключом `manticore`; конфиг
  `webx-catalog-manticore.php`: `host`, `port`, `table_prefix` (env `MANTICORE_*`),
  `connect_timeout` 1,5 с, `timeout` 5 с, `down_for` 30 с, карта морфологии, `min_prefix_len` 3,
  веса, `facet_values`, `relevance_sample`.
- **Сервер — `Manticore`.** SQL в raw-режиме через `/sql?mode=raw`, документы — `/bulk`
  (`replace`/`delete`). Несуществующая таблица в `/bulk` — ошибка, а не автосоздание (`INSERT`
  через SQL таблицу бы создал — им не пишем). Отказ сервера (соединение, ответ без JSON)
  запоминается в кеше на `down_for` секунд и пишется в лог; ответ с ошибкой — не отказ, а
  `ManticoreError`.
- **Отступление от решения 25: не «один вызов», а один заход.** У HTTP API нет нескольких
  операторов в запросе (`;` — синтаксическая ошибка), поэтому страница, итог (`FACET 1`) и
  счётчики всех невыбранных фасетов — один оператор, а рядом, параллельно (`Http::pool`), —
  по оператору на выбранный фасет без его выбора, один на концы всех диапазонов и, если источник
  выбирает уместные фасеты, выборка id для него. Время — одного запроса, а не суммы.
- **Решение 24, поле — из `Facet::field()`; раскладка — у `BatchCountedFacet`.** В ядре
  интерфейс получил `indexValues()` (выбор в значениях поля: «да» свойства — это id свойства в
  `pb`) и `splitIndexCounts()` (один `FACET pv` раскладывается по свойствам одним запросом —
  `owners()` у справочников и интервалов). Атрибут называется `pv`, как его уже назвал пакет
  свойств, а не `property_values`.
- **Числа свойств — JSON-картой, а не атрибутом на свойство.** В ядре появился
  `IndexField::JSON`; `pn` теперь JSON (раньше — строка с JSON), и `RangeFacet` читает
  `pn.12` как `DOUBLE(pn['12'])`. Новое свойство не меняет схему таблицы — иначе каждое новое
  числовое свойство требовало бы перестройки, а это противоречит §6 спеки свойств.
- **Пустых значений в Manticore нет.** Число, которого может не быть (цена), несёт флаг рядом
  (`price__set`): диапазон и его концы берут только товары с флагом, сортировка ставит товары без
  цены в конец в обе стороны. Несколько строк, дробей или флагов — JSON-массив (MVA бывают только
  целые). Float в Manticore 32-битный: концы диапазона отдаются как `%.7g` — 99.99, а не 99.989998.
- **Таблица.** `{prefix}_catalog_products_{locale}`; локализованный текст — одна колонка своего
  языка (без перевода — основной язык), остальные языки — `other_languages`; `name` — ещё и
  строковый атрибут для сортировки по названию. Морфология — процессоры всех языков сайта, свой
  первым; `min_prefix_len` 3 и `expand_keywords=1` в запросе — без него начало слова не
  находится (`protec` → «protective»). Поиск в M1 — `MATCH` по всем текстовым колонкам с весами
  10/3; коды и два захода — M2.
- **Сравнение схемы (решение 9)** — `DESCRIBE` и `SHOW TABLE … SETTINGS` против
  `TableSchema`: колонки, их типы и свойства, `morphology`, `min_prefix_len`
  (`index_exact_words` Manticore ставит сам — не сравнивается). `prepare()` создаёт недостающие
  таблицы и не трогает устаревшие; `status()` — состояние каждой таблицы для doctor и будущей
  страницы M3.
- **Подмена (решение 8)** — новый интерфейс ядра `RebuildsAside`: `prepare(rebuild: true)`
  создаёт `{table}_next`, `index()` пишет туда, `Indexer::rebuild()` в конце зовёт
  `completeRebuild()` (`DROP` старой, `ALTER TABLE … RENAME`) и заново ставит в очередь товары,
  изменённые с начала перестройки. Воркер, запущенный во время перестройки, пишет в обе таблицы.
- **Уместные фасеты.** Выбор «какие фасеты показывать» (источник с `RelevantFacets`) вынесен из
  `SqlEngine` в общий `FacetPlacement`, оба движка решают одинаково. Manticore даёт источнику
  выборку до `relevance_sample` (1000) id найденного: доли по выборке, а не по всем 93 тысячам.
- **Откат (10–14).** Панель (`context: panel`, `withUnpublished`, `onlyTrashed`) и каталог до
  `sql_engine_limit` — на `SqlEngine` (`fellBack()` — для плашки M3); больше лимита —
  `CatalogUnavailable`, `HttpException` 503 с `Retry-After`. Страница 503 с шапкой и подвалом —
  в M2.
- **Doctor** — `ManticoreCheck`, только при `engine = manticore`: нет префикса — fail; сервер не
  отвечает — fail; префикс — начало чужих таблиц — warn; таблица языка отсутствует или устарела —
  warn с командой перестройки.
- **Тесты (решение 26).** Сценарии вынесены в `module-catalog/tests/EngineScenarios.php`:
  `EngineTest` (база) и `ManticoreEngineTest` (Manticore) — один класс, одинаковые ответы. Плюс
  свои: таблица на язык с морфологией, устаревшая схема и подмена, удаление; без сервера —
  откат, 503, запоминание, префикс. Сервер — `MANTICORE_TEST_HOST`/`MANTICORE_TEST_PORT`, префикс
  `wxtest_<случайный>`, таблицы удаляются в `tearDown`, без сервера тесты пропускаются. CI —
  джоба `PHP on Manticore` в `ci.yml` (сервис `manticoresearch/manticore:29.0.2` с `EXTRA=1`,
  `--fail-on-skipped`), в агрегаторе. Тега `29` у образа нет — только полные версии.

### M2: поиск

- **Отступление от решения 22: infix — у всей таблицы, а «подстрока только для кодов» держит
  запрос.** `CALL QSUGGEST` без infix отвечает «suggests work only for keywords dictionary with
  infix enabled», а `infix_fields` на одно поле real-time-таблица молча игнорирует (в
  `SHOW TABLE … SETTINGS` его нет, и `@name ехол` находит «чехол»). Поэтому у таблицы
  `min_infix_len` (конфиг, 3), а `expand_keywords` из запроса убран — с infix он искал бы
  `*слово*` и в названиях. Звёздочки запрос пишет сам: каждое слово от `min_prefix_len` букв —
  `(слово | слово*)`, кодам — `@codes_flat *at1234*`. Решение 7 (начало слова) держится.
- **Коды (19–20).** В ядре `IndexField` получил флаг `code`; `CoreDocument` помечает им `sku`,
  `barcode` и новый в документе `external_id`, `Documents::schema()` флаг сохраняет. В таблице
  три колонки на все коды: `codes` — как написаны (стандартная разбивка: «AT-1234/56» — at, 1234,
  56), `codes_flat` — нижний регистр, только буквы и цифры (`TableSchema::flat()`), `code_keys` —
  те же целиком, JSON-список. Поиск — `MATCH` по словам плюс `| (@codes_flat *плоский запрос*)`,
  если плоский запрос не короче `min_infix_len`. Ввод экранируется всегда; запрос без единой
  буквы и цифры — пустой ответ, а не синтаксическая ошибка.
- **Точное совпадение (20–21)** — `IN(code_keys, '<плоский запрос>') AS is_exact` в списке
  `SELECT` и первым ключом сортировки (Manticore сортирует не больше чем по пяти ключам — у
  сортировки остаётся три плюс `id`); рядом в том же заходе — `… AND is_exact = 1 LIMIT 2`. Ответ
  движка получил `CatalogResult::$exact` — до двух id, чтобы отличить «один» от «нескольких».
  Manticore сравнивает плоско: «at123456» — это «AT-1234/56». `SqlEngine` сравнивает как есть
  (`Product::scopeCoded`, коллация базы), ставит совпавшие первыми через `ORDER BY CASE`; `LIKE`
  теперь смотрит и `external_id`.
- **Переход на карточку (21)** — в `Storefront::listing()` для поиска: ровно один `exact`, ничего
  не выбрано, без `?page=` → 302 на `url()` товара. Работает на обоих движках (на `SqlEngine` —
  код как есть). В панели `ProductController` отдаёт одну строку (`total` 1); счётчики фасетов
  остаются от всего найденного — пересчитывать не стали.
- **Два захода (16–17)** — `ManticoreEngine::answer()`: пусто, запрос есть, не `asTyped` →
  раскладки (`KeyboardLayouts`: 47 клавиш US-клавиатуры и столько же с Shift на язык, конфиг
  `layouts` — en, ru, uk, be, de; пробуются только языки сайта, сначала язык страницы; символ,
  которого нет в исходной раскладке, снимает её с проверки) — все варианты параллельно,
  `LIMIT 1`, первый непустой; затем `CALL QSUGGEST(слово, таблица, 1 AS limit)` на каждое
  буквенное слово параллельно (коды и числа не исправляются) и поиск исправленным. Не нашлось и
  после — пустой ответ без исправления. Худший случай — четыре захода за один запрос страницы.
- **«Показаны результаты для …, искать …»** — `CatalogResult::$corrected`; `CatalogQuery::$asTyped`
  (`?typed=1`, его несут ссылки сортировки и редиректы) и `withSearch()` для повторного вопроса.
  Витрина — вид `webx-catalog::search-corrected` (переопределяемый) и строки
  `storefront.search-corrected`, `storefront.search-instead`; панель — `corrected` в ответе
  списка, строка над таблицей с кнопкой, `typed=1` в запросе (`panel.search-corrected`,
  `panel.search-instead`).
- **503 (12)** — `CatalogUnavailable::render()`: HTML — вид `webx-catalog-manticore::unavailable` в
  макете каталога (`webx-catalog.layout` — макет сайта с шапкой, меню и подвалом), `noindex`, 503 и
  `Retry-After`; JSON — `{message}` с теми же заголовками. Строки —
  `webx-catalog-manticore::storefront.unavailable-*`, вид публикуется тегом
  `webx-catalog-manticore-views`.
- **Изменение схемы — это «устарела» у doctor.** Новые колонки (`codes`, `codes_flat`, `code_keys`,
  `external_id`) и `min_infix_len` делают таблицы M1 устаревшими: `webx:doctor` предупреждает,
  `webx:catalog:index --rebuild` пересоздаёт их подменой. Пакет ещё не выпускался — живых таблиц
  M1 нет; общий случай — в «Открыто».
- **Тесты.** В общий набор — код первым и в ответе (артикул, штрихкод, внешний ID; в панели — и
  неопубликованный), спецсимволы ввода; в тесты пакета — подстрока кода и плоский код целиком,
  исправление опечатки и раскладки, `asTyped`, витрина (строка исправления, 302 по плоскому коду),
  панель (одна строка, `corrected`, `typed=1`), 503 на странице сайта; раскладки и колонки кодов —
  без сервера.

### M3: панель и MCP

- **Раздел — `SearchIndexModule`, id `search-index`,** группа `system`, порядок 720 (после SEO),
  права `search-index.view` и `search-index.manage`. Регистрируется, только когда
  `webx-catalog.engine = manticore` (`available()`, как у `ConnectModule`); маршруты
  `GET /api/cms/search-index` и `POST …/rebuild` есть всегда, но без движка отвечают 404.
  Отчёт собирает `IndexStatus::report()`: подключение (адрес, префикс, версия из `SHOW VERSION`,
  доступность и текст ошибки), товары в базе вместе с корзиной — корзина тоже индексируется, по
  таблице — `status()` движка (состояние, причина, документы и `rebuilding`, если рядом есть
  `_next`), очередь — `Catalog::queue()`. Каждая часть спрашивается отдельно: без сервера страница
  всё равно показывает очередь и базу.
- **Перестройка — задача `RebuildIndex`** (`tries` 1, `timeout` из `rebuild.timeout`, 3600;
  очередь — `rebuild.queue`). Одна задача на всю перестройку, а не по пачке: подмена — в конце,
  обрыв оставляет старые таблицы. Прогресс — `RebuildProgress` в кеше (общий у веба и воркера):
  `queued → running (done/total) → done | failed`; `Indexer::rebuild()` получил колбэк
  `progress(done, total)` после каждой пачки. Вторая перестройка, пока первая ждёт или идёт, — 409. Без вестей 15 минут — `stalled`: воркер умер или его нет, кнопка снова доступна.
- **Плашка (решение 13) — по ответу, а не по движку.** `CatalogResult` получил `fellBack`, откат
  `ManticoreEngine` его ставит, список товаров отдаёт `fell_back`, `ProductsPage` рисует над
  таблицей предупреждение (`panel.fell-back` ядра). `fellBack()` у движка остался.
- **MCP — `catalog_index_status`** через `SatelliteTools` (имя, scope и права каталога), только на
  движке `manticore`. Отчёт страницы и, с `product`, ответ «почему товара нет в поиске»: удалён,
  снят или скрыт в базе, ждёт в очереди с какого времени, и что о нём в каждой таблице
  (`ManticoreEngine::document()`).
- **«Устаревшая таблица ломает запросы» (§6) — решено живой схемой.** `ManticoreEngine::reading()`
  берёт колонки и настройки живой таблицы (`DESCRIBE` + `SHOW TABLE … SETTINGS`, кеш на
  `schema_for` секунд, 60; сбрасывается после `prepare()` и подмены), и если таблица устарела —
  спрашивает и пишет по `TableSchema::within()`: требуемая схема, суженная до колонок того же
  типа; коды — только если есть все три колонки, число — только с флагом, `min_prefix_len` и
  `min_infix_len` — таблицы. Фасет без атрибута отвечает пусто (так движок и раньше отвечал на
  неизвестный фасет), без infix нет `QSUGGEST`. Без этого ломалась не только витрина, но и воркер:
  `/bulk` отвечал «unknown column: 'codes'», и очередь вставала. Таблица следующей перестройки
  (`_next`) пишется по полной схеме.
- **npm — `@webx-ui/module-catalog-manticore`:** `catalogManticore()` — один раздел
  (`/search-index`), страница `SearchIndexPage` (сервер, очередь, таблицы — карточками на узкой
  ширине, полоса перестройки с опросом раз в 2 с), словарь `webx-catalog-manticore::panel`. Мок
  плейграунда — `apps/playground/server/panel/catalog-manticore.ts`: русская таблица устарела,
  перестройка идёт по часам, `POST /api/cms/search-index/_outage` выключает сервер — так видна
  плашка над товарами.
- **Регистрации:** `Setup\Catalogue` (`catalog-manticore`), `extra.webx.npm`/`panel` в
  composer.json пакета, `apps/playground/src/panel/main.ts`; в `webx-cms.local` —
  `scripts/packages.mjs`. Гайд — раздел «The search index on Manticore» в
  `apps/docs/guide/catalog.md`.
- **Тесты.** Без сервера (`SearchIndexPageTest`): плашка в списке, страница без сервера (очередь и
  база есть), права, задача и 409, «stalled», упавшая перестройка, раздел и инструмент на движке;
  `SearchIndexOnTheDatabaseTest` — на `sql` ни раздела, ни инструмента, страница 404. С сервером
  (`ManticoreEngineTest`): таблица старой схемы без кодов и цены — пишется, ищет, фасет пуст, код
  не находится, а после `RebuildIndex` — находится; отчёт против базы и `product()`. В npm —
  страница (отчёт, перестройка с опросом, права, сервер недоступен), модуль, паритет словаря,
  плашка в `ProductsPage`.

### M4: приёмка на reference-shop

- **Стенд.** `webx-cms.local` слинкован с веткой (`packages.mjs local`), выгрузка reference-shop залита
  `scripts/shop-import.php` сайта (93 525 строк, 993 с, ошибок ноль), движок `manticore`,
  сервер хомлаба, префикс `webx_cms_local`. Замеры и пороги — §4; страница «Система → Поисковый
  индекс» проверена на этих данных в браузере, в светлой и тёмной теме и на 390 px.
- **Фасеты спутников (§6).** Бренды и метки уже писали в документ только видимые значения (а
  скрытие бренда или метки помечает их товары). Наличие писало id скрытого статуса как есть —
  Manticore считал его там, где база его не видит. `StockDocument` пишет статус, только если он в
  фильтре; товар без строки, как и в базе, — под статусом по умолчанию. Общий набор спутников —
  `SatelliteFacetScenarios` в тестах пакета (на базе и на Manticore, одинаковый ответ): скрытый
  бренд, скрытая метка, статус по умолчанию и скрытый статус.
- **Перестройка — одна задача.** 41–44 с на 93 677 товаров в трёх таблицах, ~2 100 товаров в
  секунду; до `rebuild.timeout` (3600) запас в восемьдесят раз — задачи на пачки не нужны.
- **Перестройку из консоли видно со счётом.** `status()` у таблицы с `_next` рядом отдаёт `filled` —
  сколько документов уже там; страница пишет «Перестройка заполняет таблицу рядом: N из M» и,
  пока такая таблица есть, опрашивает сервер раз в 2 с. Кнопку это не прячет (§6).
- **Подмена не атомарна — и это видно.** На копии таблицы ru (93 тысячи) под восемью читателями
  окно между `DROP` и `RENAME` — 18–34 мс, в нём 13–33 упавших чтения из ~1 600 («unknown local
  table»). Два `RENAME` (живую в сторону, новую на место, старую удалить потом) дают то же окно.
  Поэтому движок, получив «unknown local table» на вопросе, ждёт `swap_wait` (150 мс) и
  спрашивает ещё раз (`throughSwap()`): 1 413 вопросов витрины сквозь перестройку с подменой — ни
  одного отказа. Ошибки в обход повтора — запись воркера в этот миг; пачка остаётся в очереди и
  уходит следующим проходом.
- **Infix на всю таблицу (§6, M2) почти ничего не стоит.** Та же выгрузка: 40,5 МБ на диске без
  infix, 44,4 МБ с `min_infix_len` 3 и столько же с 4 — при `dict=keywords` подстроки в словарь
  не пишутся, а разворачиваются при запросе. `min_infix_len` остаётся 3.
- **Порог «< 5 с» пересмотрен** (§4): задержку задаёт минутный планировщик, а не движок.
- **Тесты.** Спутники на обоих движках; счёт `_next` в ходе перестройки (`ManticoreEngineTest`);
  повтор вопроса через окно подмены — без сервера (`OutageTest`); в npm — счёт консольной
  перестройки и опрос.
