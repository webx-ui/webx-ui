# Движок Manticore — `module-catalog-manticore`

Спутник ядра каталога: реализация `CatalogEngine` на Manticore Search для каталогов, которые
`SqlEngine` уже не тянет (больше пары тысяч товаров). Архитектура семейства —
[`WEBX_UI_CATALOG.md`](WEBX_UI_CATALOG.md) (§4.2, §4.3, §5), ядро, контракт движка и очередь
индексации — [`WEBX_UI_MODULE_CATALOG.md`](WEBX_UI_MODULE_CATALOG.md); здесь они не повторяются.
Статус: черновик, обсуждение идёт 01.10.2026.

## 1. Решения (не переоткрывать)

Приняты в обсуждении 01.10.2026.

1. **Пакет — `module-catalog-manticore`, а не библиотека.** Без ядра каталога ему нечего
   индексировать — тот же довод, что собрал SEO одним `module-seo`. Своего пункта меню нет, место
   в панели (состояние индекса, очередь) — на правах раздела без меню.
2. **Manticore ставим не мы.** Пакет подключается к готовому серверу по HTTP JSON API:
   `MANTICORE_HOST`, `MANTICORE_PORT` (9308). Сервер общий для нескольких проектов — нормальный
   случай, а не исключение (так живёт хомлаб).
3. **`MANTICORE_TABLE_PREFIX` обязателен и без умолчания.** Из `APP_NAME` его не вывести: два
   демо — один сайт с одним `APP_NAME` и одной Manticore, и они молча перетёрли бы индексы друг
   друга. Без префикса движок не стартует, `webx:doctor` говорит почему. Префикс — `[a-z0-9_]`,
   таблицы — `{prefix}_catalog_products_{locale}`, суффикса `_idx` нет. Пакет трогает только
   таблицы своего префикса; doctor предупреждает, если префикс — начало чужих имён.
4. **Обычная жизнь — по товару, через очередь ядра** (§5.3 архитектуры): сохранение помечает,
   воркер пишет пачкой, упавший Manticore не роняет сохранение. Полная перестройка нужна, только
   когда Manticore подключили к каталогу с товарами, поменялась схема индекса (язык, морфология,
   новая версия пакета) или сервер потерял данные.
5. **Таблица на язык, и в каждой — все языки сайта.** Свой язык — в основных полях с бо́льшим
   весом, остальные — в поле «на других языках» с меньшим; артикул, штрихкод и бренд — в каждой.
   Нет перевода — в основные поля идёт текст основного языка, как на витрине. Так товар находится
   словом на любом языке сайта со страницы любого языка, и это гарантия, а не «обычно в названии
   есть латиница».
6. **Морфология таблицы — процессоры всех языков сайта, свой первым.** У языков на одном
   алфавите выигрывает первый процессор, поэтому немецкая таблица разбирает слова по-немецки,
   английская — по-английски; ради этого таблицы и разделены. Соответствие «язык → процессоры» —
   конфиг пакета с умолчаниями; язык без настройки — без морфологии.
7. **Поиск по началу слова включён всегда** (`min_prefix_len`) — подстраховка для языков, где
   морфология слабая или её нет.
8. **Перестройка — подменой, без окна с неполным каталогом.** `--rebuild` собирает
   `{table}_next` рядом, витрина работает на старой, затем `ALTER TABLE … RENAME`. Это делается
   в v1: добавление языка на живом магазине — реальный сценарий.
9. **Устаревшую схему видит doctor, перестройку запускает человек.** `prepare()` сравнивает
   требуемую схему с живой; на 93 тысячах товаров перестройка — минуты нагрузки, и время для неё
   выбирает человек.

10. **Карточка товара от Manticore не зависит** — она из базы по адресу. Без движка ломаются
    только списки: категория, фильтры, поиск.
11. **Каталог до `sql_engine_limit` откатывается на `SqlEngine` сам**: покупатель не замечает,
    в логе предупреждение, doctor показывает.
12. **Каталог больше лимита отвечает 503 с `Retry-After`** — «каталог временно недоступен», шапка,
    меню и подвал на месте. Не 500 и не пустой список: 503 поисковик переждёт, пустую категорию с
    200 — запомнит. `SqlEngine` с фасетами на 93 тысячах положил бы базу.
13. **Панель откатывается на `SqlEngine` всегда**, с плашкой над списком: человек один, нагрузка
    небольшая, работа не встаёт.
14. **Недоступность запоминается на полминуты** после первой ошибки — дальше запасной путь сразу,
    без ожидания; таймаут соединения 1–2 секунды, а не 30 по умолчанию.

15. **Встроенного нечёткого поиска нет.** `fuzzy=1` с морфологией не находит ничего, без неё —
    часть опечаток (§2).
16. **Пустой результат — второй заход:** другая раскладка среди языков сайта, затем `CALL QSUGGEST`
    на каждое слово и поиск исправленным запросом. Сверху — «Показаны результаты для …, искать
    …» (две строки, переводимые, шаблон переопределяемый).
17. **В панели — те же два захода**, подсказок при вводе нет.
18. **Без Manticore — только `LIKE`** `SqlEngine`, без исправлений: для запасного режима
    достаточно.

19. **Коды товара — в двух видах:** артикул, штрихкод и внешний ID как есть (разбиты по
    разделителям) и нормализованные — нижний регистр, только буквы и цифры, поиск по подстроке
    (`infix_fields`). Запрос нормализуется так же; спецсимволы ввода экранируются всегда — `/`,
    `-` и кавычки ошибкой не становятся.
20. **Точное совпадение кода — первым**, выше любых совпадений по названию.
21. **Витрина: запрос ровно равен артикулу или штрихкоду одного опубликованного товара — сразу
    его карточка** (302). В панели — одна строка в списке.
22. **Подстрока — только для кодов.** Для названий хватает морфологии и начала слова, а индекс
    от подстрок заметно растёт.

23. **Смысл фасетов — ядра** (§8.1 спеки ядра): выбранный сужает всё, кроме себя; дерево — с
    потомками; число — min/max. Manticore отвечает ровно как `SqlEngine`, только быстрее.
24. **Поля индекса — из `Facet::field()`**; множественные значения (категории с предками,
    значения свойств) — MVA. Значения всех справочных свойств — один атрибут `property_values`,
    один `FACET` на все, `BatchCountedFacet` раскладывает; числовые свойства — своими атрибутами.
25. **Счётчики — пакетом:** запрос с `FACET` по невыбранным плюс по запросу на каждый выбранный
    без его фильтра, одним сетевым вызовом.
26. **Общий набор тестов на оба движка** — одни сценарии (выборки, счётчики, дерево, числа,
    состояния панели) на `SqlEngine` и Manticore с одинаковым ответом. В CI — сервис-контейнер
    `manticoresearch/manticore` 29, отдельной джобой; локально — Manticore хомлаба с префиксом
    `wxtest_`, тесты убирают за собой и пропускаются, если сервер недоступен.

### 1.1. Добавить язык на сайт с товарами

Добавили язык в настройки сайта → doctor: «индекс устарел, запустите
`webx:catalog:index --rebuild`» → перестройка создаёт таблицу нового языка (в ней пока текст
основного языка) и подменой обновляет остальные (их морфология и поле «на других языках»
меняются) → дальше каждый переведённый товар уходит в очередь при сохранении. Витрина всё это
время работает.

## 2. Проверено на Manticore 29.0.2 (хомлаб, 01.10.2026)

Временные таблицы `wxtmp_*`, созданы и удалены.

- Товар с русским названием без латиницы и английским «Protective case for phone»: в `_ru`
  (`lemmatize_ru_all, stem_en`) находится по case, cases, чехлы, чехлов. В `_en` с одним
  `stem_en` «чехлы» не находит, с `stem_en, lemmatize_ru_all` — находит: морфология нужна всех
  языков, а не только своего.
- `libstemmer_de, stem_en`: находятся Schutzhüllen, cases, phones.
- Веса полей: «кабель» в `_ru` — 10643 (своё поле), «cable» — 3643 (поле других языков).
- Украинский: `lemmatize_uk_all` есть, но неполный — «чохли» находит «чохол», «чохлів» нет;
  `libstemmer_uk` отсутствует. Это словарь Manticore, а не схема; лечится синонимами или
  словоформами — волна B.
- `ALTER TABLE … morphology=` и `ALTER TABLE … RENAME` работают.
- Опечатки: `fuzzy=1, distance=2` с `lemmatize_ru_all, stem_en` — ни одной из шести; с `none` —
  «наушнеки» и «headphnes» да, «кабль» и «чехлол» нет. `CALL QSUGGEST` с морфологией исправил все
  пять (чехлол, кабль, наушнеки, headphnes, телефрн). Раскладка «xt[jk» → «чехол» и
  `CALL AUTOCOMPLETE` («чех» → чехол) работают.
- Артикулы `AT-1234/56`, `NGK.BKR6E-11`: стандартная разбивка находит «AT-1234», «1234», «BKR6E»,
  но не «at1234» и «bkr6e11», а «AT-1234/56» целиком — синтаксическая ошибка (`/` — оператор).
  `blend_chars` хуже: «AT-1234» перестаёт находиться. Нормализованное поле с подстрокой находит
  at123456, at1234, bkr6e11, 123456 и «34/5».

## 3. Отложено

- **Подсказки при вводе** — выпадашка в строке поиска: слова из `CALL AUTOCOMPLETE` и товары с
  картинкой и ценой, JSON-эндпоинт и Blade-компонент. Manticore их умеет (§2), решено отложить.

## 4. Открыто

- Локальная разработка: `webx-cms.local` смотрит в Manticore хомлаба со своим префиксом.
