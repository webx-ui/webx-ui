# Подборки товаров — `module-catalog-collections`

Спутник ядра каталога: именованный блок товаров, который менеджер собирает один раз, а сайт выводит
везде, куда его вставили: блоком, в тексте, тегом в шаблоне темы. Архитектура семейства —
[`WEBX_UI_CATALOG.md`](WEBX_UI_CATALOG.md) (§11 «Анатомия спутника»), ядро —
[`WEBX_UI_MODULE_CATALOG.md`](WEBX_UI_MODULE_CATALOG.md), образец спутника —
[`WEBX_UI_CATALOG_LANDINGS.md`](WEBX_UI_CATALOG_LANDINGS.md); здесь они не повторяются.

Статус: сделано (webx-ui#124), демо на lab-сайте; релиз — вместе с первой версией npm-пакета.

## 1. Назначение и границы

На сайтах с каталогом нужны блоки товаров в разных местах: «Популярные товары» и «Новинки» на главной,
«Со скидкой» в разделе, подборка камер в статье «Какую камеру выбрать». Сейчас такое делается руками в
теме. Подборка заводится в панели или агентом, выводится по ключу и обновляется сама.

### 1.2. Объём первой версии

**Входит:** подборки ручные и по фильтру, пресеты «Новинки», «Со скидкой», «По метке», условия по
категории и бренду (§3.3), три способа вставки, вид «сетка» и «карусель», панель, «где используется»
для блоков и регионов (§6.4), MCP, демо.

**Отложено, место оставлено (§2.4):** смешанный режим (закреплённые плюс добор фильтром);
контекстные подборки на карточке товара («Похожие», «С этим покупают», «Аксессуары»); хиты по
фактическим продажам.

**Отложено, модели не касается:** «где используется» для шорткодов в тексте и тегов в файлах темы.
Причины — §6.4.

**Не здесь:**

- **Своего адреса у подборки нет.** Подборка — кусок страницы. Страница с адресом, SEO и фильтром —
  посадочная. Поэтому нет `RouteType`, карты сайта и записи `SiteBar::entity()`.
- **Рекомендуемые товары посадочной** остаются у посадочной: это полоса одной страницы, а не сущность.
- **`products()` и блок с `wx-collection` (источник `products`) остаются.** Это инструмент разработчика,
  он выбирает товары в коде шаблона. Подборка — запись, которой управляет менеджер, и читает она
  через тот же `ProductQuery` (§5.1).

### 1.3. Имена

По правилу спутников: пакет `module-catalog-collections` (`webx-ui/module-catalog-collections`,
namespace `WebxUi\CatalogCollections`), npm `@webx-ui/module-catalog-collections`, id модуля
`catalog-collections`, таблицы `catalog_collection*`, группа «Каталог», MCP `catalog_collections_*`
через `SatelliteTools`, ресурс `catalog://collections`. В панели — Product collections, «Подборки
товаров».

Слово `collection` в коде уже занято, и путать нельзя:

| Что уже есть                                                 | Что это                                                 |
| ------------------------------------------------------------ | ------------------------------------------------------- |
| `wx-collection`, `WebxUi\Admin\Collections\*`                | поле блока «какие записи модуля показать», любой модуль |
| `WebxUi\Catalog\Collections\ProductsSource`                  | источник `products` этого поля                          |
| `webx-catalog-landings::storefront.collections` («Подборки») | подпись ссылок на посадочные у категории                |
| `Illuminate\…\Collection`                                    | коллекция Laravel                                       |

Поэтому модель — `ProductCollection`, а не `Collection`; поле формы блока — `wx-catalog-collection`;
блок и шорткод — `product-collection`. Подпись ссылок на посадочные на витрине
остаётся как есть: посетитель двух смыслов не видит (решение 8).

## 2. Модель

Миграции — день `2026_01_06`: связь ссылается на `catalog_products`, посадочные занимают `2026_01_05`.

### 2.1. `catalog_collections` — модель `ProductCollection`

| Колонка            | Тип                             | Что                                                              |
| ------------------ | ------------------------------- | ---------------------------------------------------------------- |
| `id`               | bigint                          |                                                                  |
| `key`              | string(64), unique              | `[a-z0-9-]`, стабильный, для вставки в код (§2.2)                |
| `title`            | json, translatable              | заголовок на языках сайта                                        |
| `source`           | string(16), default `manual`    | `manual`, `filter`; место под будущие (§2.4)                     |
| `category_id`      | bigint, nullable, index, без FK | основа фильтра: ветка категории; пусто — весь каталог (§3.3)     |
| `filters`          | json, nullable                  | набор фасетов, форма `catalog_landings.filters` (§3.2)           |
| `on_sale`          | boolean, default false          | только со старой ценой (§3.4)                                    |
| `sort`             | string(32), nullable            | ключ реестра `Sorts`; у `manual` не читается                     |
| `only_purchasable` | boolean, default true           | только товары, которые можно купить (§5.2)                       |
| `limit`            | smallint, default 8             | своё поле каждой подборки, 1…`max_limit`                         |
| `view`             | string(16), default `grid`      | `grid`, `carousel`                                               |
| `link`             | json, nullable                  | значение `wx-link`: категория, посадочная или произвольный адрес |
| `link_text`        | json, nullable, translatable    | подпись ссылки; пусто — «Все товары» из словаря модуля           |
| `is_enabled`       | boolean, default true           | выключенная не выводится нигде                                   |
| `attention`        | string(32), nullable, index     | «требует внимания», как у посадочной (§3.5)                      |
| `deleted_at`       | timestamp, nullable             | корзина; ключ остаётся занятым                                   |
| timestamps         |                                 |                                                                  |

Без внешнего ключа на `category_id` намеренно: `nullOnDelete` молча превратил бы подборку одной
категории в подборку всего каталога. Несуществующая категория даёт пустой отбор: `ProductQuery`
подставляет `[0]`, и подборка ничего не выводит.

**Лимит (решение 11).** `max_limit` — конфиг `webx-catalog-collections.max_limit`, 48: верхняя граница для
всех подборок. Кроме него у каждой подборки своё поле `limit`, потому что в разных местах нужен разный
лимит. Больше `max_limit` оно не сохраняется. Параметр `limit` вставки может только уменьшить лимит
подборки (§4.1).

### 2.2. Ключ

Делается из заголовка при создании, можно задать свой. После создания не меняется: форма показывает
его только для чтения, `_update` отказывает. Ключ живёт в шаблонах и текстах, менять его там некому.
Занят он и записью в корзине, поэтому восстановление не встречает конфликта.

### 2.3. `catalog_collection_products` — ручной список

Как `catalog_landing_products`: `collection_id` и `product_id` с `cascadeOnDelete`, `position`,
первичный ключ по паре, индекс на `product_id`. Товар в корзине строку не теряет: в форме он с
пометкой, на сайте не виден, после восстановления вернётся на место. Строк — не больше `max_limit`.

### 2.4. Место под будущие режимы

Режим — значение `source`, а отбор за ним — класс реестра:

```php
interface CollectionResolver
{
    public function source(): string;                 // 'manual', 'filter'

    /** @return list<int> id товаров в порядке показа, не больше $limit */
    public function ids(ProductCollection $collection, int $limit, string $locale): array;
}
```

- **Смешанный режим** — третий резолвер `mixed`: строки ручного списка, затем добор по `filters`.
  Обе части в таблицах уже есть, миграция не нужна.
- **Контекстные подборки** — резолвер с товаром страницы. Компонент получит проп `:product`, а в ключ
  кеша войдёт его id. Новый метод контракта появится с этой работой, не раньше.
- **Хиты по продажам** — сигнал реестра `PopularitySignals` ядра или новая сортировка реестра `Sorts`.
  Подборке правка не нужна: сортировка выбирается по ключу.

### 2.5. Что ещё регистрирует модель

- `SnapshotTables::content('catalog_collections', 'catalog_collection_products')`: подборка — контент.
- `HistoryTypes` под типом `catalog.collection`, права — каталога; вкладка журнала в форме.

## 3. Наполнение

### 3.1. Вручную

`source = manual`. Поиск по товарам и список с перетаскиванием — как поле рекомендуемых у посадочной
(`LandingProductsField.vue`: `wx-autocomplete` и `wx-sortable-list`). Порядок — `position`. Поля
фильтра в форме скрыты. Лимит действует и здесь: в списке может лежать 20 товаров, выводятся первые
`limit` из тех, что прошли отсев (§5.2), поэтому снятый с продажи товар заменяется следующим.

### 3.2. По фильтру: что переиспользуется

Новой модели фильтра нет. Берётся то, что работает у посадочных и в списке товаров панели.

| Что нужно               | Что берём                                                                                     | Что меняем                                          |
| ----------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| Условие по фасету       | реестр `Facets`, `Facet::applySql()`, `FacetValue`, `FilterState`                             | ничего, это ядро                                    |
| Хранимый набор          | `WebxUi\CatalogLandings\Catalog\LandingSet`: нормализация, `state()`, `retarget()`, `known()` | переезд в ядро как `WebxUi\Catalog\Filter\FacetSet` |
| Какие фасеты предложить | `CatalogLandings\Catalog\BaseFacets`                                                          | переезд в ядро рядом с `FacetSet`                   |
| Поле в форме            | `LandingSetField.vue`                                                                         | общая часть — в `@webx-ui/module-catalog` (§6.3)    |
| Сортировка              | реестр `Sorts`, `ProductQuery::sort()`                                                        | ничего                                              |
| Выборка                 | `ProductQuery::narrowedBy()`                                                                  | лимит в SQL (§5.1)                                  |
| Значение слили, удалили | `FacetValueRetargeted`, образец — `LandingRepairs`                                            | свой слушатель (§3.5)                               |

Переезд нужен потому, что спутник знает только ядро: зависимость подборок от посадочных заставила бы
ставить посадочные и `module-seo` ради блока на главной. Поведение посадочных не меняется.

Набор применяется так:

```php
$state = FacetSet::from($collection->filters)->state($facets);

$query->narrowedBy('set', static function (Builder $products) use ($state, $facets): void {
    foreach ($state->all() as $key => $value) {
        $facets->find($key)?->applySql($products, $value);
    }
});
```

**Запрос к базе, а не к движку** — то же решение, что `WEBX_UI_CATALOG_FEEDS.md` §5.1: у `applySql()`
те же условия, что у витрины, индекс Manticore подборке не нужен, а результат всё равно кешируется.

**Спутник не установлен — его фасета нет**, и условия в форме тоже. Значение в наборе остаётся, в
`state()` выпадает. Это поведение `LandingSet` как есть.

**Форма фильтра фидов.** В `WEBX_UI_CATALOG_FEEDS.md` §5.1 записан свой JSON (`categories`, `brands`,
`labels`), но кода фидов нет. Подборка берёт форму посадочных, потому что она работает. Фиды на своём
этапе решат, брать ли `FacetSet`; здесь их спека не правится. У фидов переиспользуется подход
(`applySql()` вместо движка), а не код.

### 3.3. Категория и бренд — да, сразу

Оба условия почти бесплатны:

- **Бренд** — обычный фасет `brand`, входит в набор без единой строки кода (решение 1 посадочных).
- **Категория** — основа, как у посадочной: `category_id`, `ProductQuery::category()` берёт всю ветку.
  Основа заодно сужает список предложенных фасетов (`BaseFacets::of()`). Одна категория, как у
  посадочной. Несколько веток — фасет `category` в наборе, но `state()` его отбрасывает намеренно; не
  в первой версии.

Этим же путём работают цена, наличие и свойства: их не отключаем, форма показывает весь реестр.

### 3.4. Пресеты и сортировка

Пресет — кнопка формы и слово `preset` в MCP, а не колонка: он заполняет обычные поля, и менеджер
может их поправить.

| Пресет       | Заполняет                                   | Условие                                         |
| ------------ | ------------------------------------------- | ----------------------------------------------- |
| «Новинки»    | `sort = new`, остальное пусто               | по дате добавления (`created_at desc`)          |
| «Со скидкой» | `on_sale = true`, `sort` по умолчанию       | `old_price` больше `price`                      |
| «По метке»   | `filters.label.values`, `sort` по умолчанию | фасет `label`; метка выбирается, например «Хит» |

Реестр `CollectionPresets` в пакете; форма показывает выбранный пресет, пока поля ему соответствуют,
иначе — «Свой отбор».

- **«Со скидкой» — единственное новое условие.** Фасета для него нет, а заводить фасет ради этого
  значит добавить его на витрину и в индекс. Это шаг `narrowedBy('on-sale', …)` внутри пакета:
  `whereColumn('old_price', '>', 'price')`. Правило то же, что у `sale_price` фидов (§4.3 их спеки). Индекс
  проверяется `EXPLAIN` на этапе 6.
- **«Популярные товары» с главной** собираются без четвёртого пресета: либо «По метке» с меткой
  «Хит», либо любой отбор с сортировкой `popular` реестра `Sorts` (популярность по просмотрам). Хиты
  по продажам отложены.
- Сортировка — любой ключ реестра `Sorts`, спутниковые тоже. Неизвестный ключ `Sorts::resolve()`
  заменяет порядком по умолчанию.

### 3.5. Значение набора слили или удалили

Как решение 10 посадочных, слушатель `FacetValueRetargeted`:

- **слили** — подборка молча переходит на новое значение (`FacetSet::retarget()`);
- **удалили** — значение выпадает, `attention = value-deleted`;
- **набор опустел из-за удаления** — ещё и `is_enabled = false`. Иначе подборка «По метке» после удаления
  метки стала бы подборкой всего каталога. Пустой набор, заданный руками («Новинки»), законен.

Сохранение формы снимает пометку. Удаление метки с товарами и так запрещено её справочником, так что
случай редкий, но слушатель обязателен.

## 4. Вставка

Все три пути заканчиваются одним компонентом. Блок и шорткод — тонкие обёртки, вёрстка живёт в одной
вьюхе. Образец — `<x-webx-configurator key="…" />` и его блок `configurator`.

### 4.1. Blade-компонент

```blade
<x-webx-catalog-collections::collection key="popular" />
<x-webx-catalog-collections::collection key="new" view="carousel" :limit="4" title="-" />
```

- Регистрация: `Blade::componentNamespace('WebxUi\\CatalogCollections\\View\\Components',
'webx-catalog-collections')`, как `webx-seo`. Класс `View\Components\Collection`.
- `key` — обязателен. `view` — `grid` или `carousel`, неизвестное значение отбрасывается. `limit` — только
  уменьшает: выводится меньшее из `limit` вставки и лимита подборки, увеличить лимит подборки вставка не
  может. `title` — как у конфигуратора: пусто — заголовок подборки, `-` — без заголовка.
- Работает в файле темы, в вьюхе модуля, в шаблоне блока из базы (`Blade::compileString()` разбирает
  `<x-…>` так же, решение 1 §24.2 блоков) и в композиции темы как обычный тег.

### 4.2. Блок контента и регионы

Предложенный блок `product-collection`: `resources/blocks/product-collection.json`, регистрация через
`BlockOffers::offer()` под проверкой `$this->app->bound(BlockOffers::class)`, установка —
`webx:blocks:offered --install`. Шаблон тонкий:

```blade
@if ($collection)
<div class="b-product-collection" data-wx-block="product-collection">
    <x-webx-catalog-collections::collection :key="$collection" :view="$view" :limit="$limit" :title="$title" />
</div>
@endif
```

Поля: `collection` (`wx-catalog-collection`), `title` (localized, пусто — заголовок подборки, `-` —
без него), `view` и `limit` (пусто — как в подборке; `limit` только уменьшает, §4.1).

- **`wx-catalog-collection`** — копия `ConfiguratorFieldType`: хранит ключ, через `ChecksNewValues`
  отказывает неизвестному ключу только при записи, с перечнем существующих. Подборка, ушедшая в
  корзину после сохранения страницы, сохранение не ломает. Выбор — через `RelationTargets`
  (`CollectionTarget`), как `ConfiguratorTarget`.
- **Регионы** работают без отдельной работы: регион держит те же блоки (`blocks_region_*`), тема
  ставит блок в регион как любой другой.

### 4.3. В тексте страницы и статьи

Механизм есть: **шорткод**. Отдельной вставки сущностей в `wx-rich-text` нет, а текст страницы и статьи —
это rich text внутри конструктора (`wx-blocks` в `pages` и `article-form`): `Values` прогоняет его через
`Shortcodes::htmlIn()`. Тексты вне блоков (описание категории, бренда, товара) идут через
`PageText::html()` и тот же `htmlIn()`.

```text
[product-collection key=cameras]
[product-collection key=cameras view=carousel limit=4]
```

Шорткод регистрируется в коде: `Shortcodes::register('product-collection', fn (array $args) => …,
plain: '')`. `plain: ''` убирает его из выдержек, мета-описаний, ленты и поискового индекса. `limit` здесь тоже только
уменьшает лимит подборки (§4.1).

Нужны три правки `module-admin` — без них работать будет плохо:

1. **Абзац.** Редактор кладёт строку в `<p>`, и `<section>` с сеткой окажется внутри него: браузер закроет
   абзац раньше времени, вёрстка рассыплется. Нужен признак `Shortcode::$block`. Если блочный
   шорткод — единственное содержимое абзаца, `htmlIn()` снимает `<p>`.
2. **Только там, где можно.** `html()` и `resolve()` работают и для строк (`wx-input`, `wx-textarea`), а
   сетка в строке недопустима. Блочный шорткод вне `htmlIn()` печатает пусто.
3. **Выбор в меню.** Меню `[` вставляет имя из `GET <api>/shortcodes` и аргументов не спрашивает, то есть
   менеджеру пришлось бы помнить ключ. Нужен второй источник строк меню: готовая вставка
   `[product-collection key=cameras]` с заголовком подборки, по строке на подборку. `list()` к тому же
   считает `html()` каждого шорткода, поэтому без `key` он обязан вернуть пустую строку, а не отчёт об ошибке.

Опечатку в ключе шорткод не отличает от выключенной подборки и печатает пусто. Поэтому ключ вставляет меню
(правка 3), а не память менеджера; имя шорткода проверяет существующий аудит `UnknownShortcodesCheck`.
Проверки ключа в тексте в первой версии нет: шорткоды в «где используется» не входят (§6.4).

### 4.4. Подборка выключена, удалена, ключа нет

Везде одно: **не печатается ничего**, страница живёт. Посетителю незачем читать «не найдено», а узнаёт об
этом менеджер в панели — так же решён `<x-webx-configurator>`.

| Случай                | Сайт  | Панель                                                     |
| --------------------- | ----- | ---------------------------------------------------------- |
| `is_enabled = false`  | пусто | список: «Выключена»; блок и текст остаются на месте        |
| в корзине             | пусто | поле блока рисует «нет такой»; восстановление вернёт вывод |
| ключа нет             | пусто | при записи блока — отказ с перечнем ключей                 |
| в предпросмотре блока | пусто | плашка `Renderer::problem()`, как у блоков                 |

**Удаление — в корзину с восстановлением (решение 9).** Используемую подборку удалить можно: без блокировки и
без подтверждения со списком мест, в панели и в MCP одинаково. Удаление обратимо: восстановление вернёт вывод
на всех местах, потому что ключ остаётся занятым (§2.2). А список мест неполный (§6.4), так что запрет и
подтверждение обещали бы больше, чем знают.

## 5. Вывод на сайте

### 5.1. Как читаются товары

```text
ключ ──► живая запись подборки (кеш группы catalog-collections)
     ──► CollectionProducts::ids()  ← резолвер, кеш групп catalog + catalog-collections
     ──► products()->only($ids)->models()   ← видимость проверяется ещё раз
     ──► StorefrontParts::extend(), Purchasability::forMany()
     ──► webx-catalog::card на каждый товар
```

**Выборка — `ProductQuery`, модели, а не карточки-массивы.** `get()` отдаёт массивы (`Cards`), а вьюха
`webx-catalog::card` принимает `Product` и `$verdict`, поэтому нужен `models()`. Полоса рекомендуемых
посадочной (`LandingViews::recommended()`) делает то же, она и есть образец.

**В ядре надо чинить две вещи (этап 1):**

- **Лимит считается в PHP.** `RecordQuery::models()` делает `$query->get()` и режет `array_slice()`, потому
  что «написано ли на языке» проверяет `shownIn()`. Для `ProductQuery` это значит: подборка «Новинки» на
  каталоге в 40 тысяч товаров грузит 40 тысяч моделей с `categories` и `images` ради восьми. Сегодня так
  же работает `products()->sort('popular')->take(8)`. У товара условие выразимо в SQL:
  `hasUrlIn()` — это наличие `slug` на языке. `ProductQuery` переносит его в запрос, а `RecordQuery`
  получает защищённый признак «лимит можно ставить в SQL». Остальные модули не меняются.
- **`StorefrontParts` — синглтон**, и `prepare()` сбрасывает данные прошлого запроса. На странице без
  листинга `prepare()` не зовётся, а `extend()` дописывает к чужому состоянию: долгоживущий воркер
  напечатает бейджи прошлого запроса и пропустит товары из `preparedIds`. Состояние надо сбрасывать на
  каждый запрос (`scoped`).

### 5.2. Правила отсева

- **Скрытые и снятые с публикации** — `Product::visible()` внутри `ProductQuery`: опубликован, не в
  корзине, в видимой категории. Отключить нельзя, это не шаг.
- **Нет адреса на языке страницы** — `hasUrlIn()`.
- **Только то, что можно купить (решение 10)** — настройка подборки `only_purchasable`: по умолчанию включена,
  лежит на вкладке `main` формы (§6.2), действует на оба способа наполнения. Отбор — готовый шаг `inStock()`
  спутника наличия. Несмотря на имя, он читает не склад, а флаг статуса «Может быть куплен»
  (`is_purchasable`), а товар без строки судит по статусу по умолчанию. Поэтому «Под заказ» с включённым
  флагом попадает в подборку, а «Нет в наличии» с выключенным — нет.
- **Настройка выключена** — товары с любым статусом остаются, в карточке вместо кнопки название статуса (§5.3).
  Это случай редакционной подборки в статье.
- **Без `module-catalog-stock`** макроса нет (`ProductQuery::hasMacro('inStock')`): шаг пропускается, поле формы
  скрыто, значение в записи хранится и заработает, когда спутник поставят.
- **Отказы вне статуса не отсеиваются.** Настройка читает только флаг. Товар без цены остаётся, и карточка
  покажет «Узнать цену».
- **Лимит считается после отсева**, в обоих режимах.

SQL шага — `Stock::whereIn()`, он входит в тот же запрос отбора. Здесь 1 и 3 — статусы с включённым флагом:

```sql
select catalog_products.id from catalog_products
where …
  and (catalog_products.id in (select product_id from catalog_product_stock where status_id in (1, 3))
       or not exists (select * from catalog_product_stock
                      where catalog_product_stock.product_id = catalog_products.id))
order by … limit 8
```

Ветка `or not exists` есть, только если статус по умолчанию можно купить. Если покупаемых статусов нет, условие
становится `status_id in (0)`, и подборка пуста. Индексы есть: `product_id` — первичный ключ связи, `status_id`
проиндексирован. Перед отбором идут два коротких запроса к статусам: список покупаемых и проверка статуса по
умолчанию. Число запросов от числа товаров не зависит (§5.6). Правило `StockRule` читает тот же флаг, поэтому
отбор и кнопка в карточке не расходятся.

### 5.3. Разметка

```blade
<section class="webx-catalog-collection webx-catalog-collection--grid" data-collection="popular">
    <header class="webx-catalog-collection__head">
        <h2 class="webx-catalog-collection__title">Popular products</h2>
        <a class="webx-catalog-collection__all" href="…">All products</a>
    </header>
    <ul class="webx-catalog-grid">
        <li>@include('webx-catalog::card', ['product' => $product, 'verdict' => $verdict])</li>
    </ul>
</section>
```

- **Карточка — `webx-catalog::card`**, как есть: картинка, название, цена, старая цена; метки — точка
  `catalog.card.badges`; наличие и бренд — `catalog.card.meta`. Тема, переопределившая карточку, меняет её
  и здесь. Копии вёрстки нет.
- **«Купить» — во всех карточках, всегда (решение 7).** Сегодня кнопка есть только в `product.blade.php`. Её ветки
  выносятся в общий partial `webx-catalog::buy`, который включают страница товара и `card.blade.php`. Так кнопка
  появляется везде, где стоит карточка: `grid.blade.php`, полоса посадочной `parts/listing-top.blade.php`,
  подборка. Настройки отключения нет. Ветки те же, что на странице товара, решает `$verdict` из `Purchasability`:

  | `$verdict`                                      | Что выводится                                      |
  | ----------------------------------------------- | -------------------------------------------------- |
  | можно купить, есть корзина (`CartButton`)       | `webx-cart::add`                                   |
  | можно купить, корзины нет                       | `<button data-product>` «Купить», подключает сайт  |
  | `price-on-request`                              | «Узнать цену»                                      |
  | отказ, например `stock` (флаг статуса выключен) | `$verdict->label` — название статуса вместо кнопки |

- **Название статуса в карточке — один раз.** Строка `webx-catalog-stock::status` в точке `catalog.card.meta`
  напечатала бы то же название рядом с отказом. Поэтому на карточке она молчит, когда статус нельзя купить
  (`purchasable` у `StockLine` уже есть). Страница товара не меняется.
- **«В один клик» в partial не входит**: точка `catalog.product.quick` остаётся на странице товара.
- **Выбирать перед покупкой сейчас нечего.** Конфигуратор — ссылка в `catalog.product.aside`, правила в цепочке у
  него нет. Когда появятся варианты (webx-ui#66), их отказ придёт через ту же цепочку, и карточку править не
  придётся.
- **Пустая подборка не печатает ничего**: ни `<section>`, ни заголовка. Компонент возвращает `''`.
- **Ссылка «Все товары»** — только если `link` задан и доступен (`available` значения `wx-link`).

### 5.4. Сетка и карусель

- **Сетка** — `ul.webx-catalog-grid`, как в листинге.
- **Карусель** — `<x-webx-slider variant="cards">` и `<x-webx-slide>` виджетов. `webx-ui/widgets` уже в
  `require` ядра каталога, запасной ветки не нужно. Скрипт слайдера подгружается по требованию самим
  компонентом.
- **Базовый вид** — `resources/theme/catalog-collections.css` на токенах темы, `webx:theme:sync` склеит его
  с остальными. Правила `.webx-catalog-grid` сейчас есть только в `partials/base` — документе пакета для
  сайта без своего лейаута. На странице темы сетка без них превратится в столбец, поэтому файл
  подборки несёт сетку под своим классом. Проверка — в браузере, этап 7.

### 5.5. Кеш

Правила — [`WEBX_UI_CACHE.md`](WEBX_UI_CACHE.md), [`WEBX_UI_PERFORMANCE.md`](WEBX_UI_PERFORMANCE.md).
Полностраничного кеша нет, блоки рисуются на каждый запрос, поэтому кеш подборки — свой.

| Что                     | Запись                                   | Группы                           |
| ----------------------- | ---------------------------------------- | -------------------------------- |
| Живые подборки по ключу | `LiveCollections`, одна запись на сайт   | `catalog-collections`            |
| Состав                  | `id`, язык → список id на лимит подборки | `catalog`, `catalog-collections` |

- **Группа `catalog-collections` — своя**, `bumpOn(ProductCollection::class)`. Подборка в
  `StorefrontCache::watch()` не идёт: её сохранение не должно сбрасывать счётчики фильтра всего каталога.
- **Товары двигают группу `catalog`**, она уже покрывает сохранение товара, цены, метки, бренда, наличия и
  все пути без событий (`Catalog::touch()`, `touchQuery()`). Флаг `is_purchasable` входит в `touchingFields()`
  статуса, поэтому его смена тоже двигает группу. Своих слушателей товаров нет.
- **`limit` вставки в ключ не входит.** Состав кешируется на лимит подборки, а меньший `limit` режет готовый
  список: порядок тот же, отсев уже пройден. Запись одна на подборку и язык, сколько бы вставок ни было.
- **Ручной список без события модели.** Реордер и замена строк идут в транзакции сохранения подборки,
  которая и двигает группу. Запись строк мимо модели обязана звать `bump()`.
- **Кешируются id, а не модели и не HTML.** HTML зависит от темы и цен, а модели тяжело сериализовать.
  Цена этого — несколько запросов на подборку каждый раз, зато их число постоянно.
- Выключатель — `StorefrontCache::enabled()`. Выключен кеш — считается каждый раз.

### 5.6. Бюджет запросов

Постоянное число на подборку, от числа товаров не зависит:

- **тёплая подборка:** товары, их `categories`, их `images`, плюс по запросу на часть карточки
  (`prepare()` меток, бренда, наличия, свойств), проверка покупки и один запрос строк корзины на всю страницу
  (`CartHandle` их запоминает). Адреса — из `RouteCache`;
- **холодная:** плюс запрос отбора и, при `only_purchasable`, два запроса к статусам (§5.2).

Точное число фиксирует `PerformanceTest` пакета на этапе 7: `assertNoRepeatedQueries` на тёплой подборке,
бюджет для одной подборки и для двух на странице. Отдельный тест свежести — на каждую группу кеша.
Индексы под новые условия (`old_price`, `created_at` у `new`) — `EXPLAIN` на MariaDB, миграция откатывается.

## 6. Панель

Раздел «Каталог» → «Подборки», ниже «Посадочных». Права и готовые куски — как у посадочных.

### 6.1. Список

`CollectionsPage.vue` по образцу `LandingsPage.vue`: заголовок, ключ, способ наполнения, вид, «Выключена»,
«Требует внимания», счётчик мест («Мест: 3», §6.4), «Удалённые». Поиск по заголовку и ключу. Ключ
копируется кнопкой вместе с тегом — то, что вставит разработчик.

### 6.2. Форма

Экран `catalog.collection-form` (`resources/screens/collection-form.json`, обязателен для чтения
`WEBX_UI_SCREENS.md`), вкладки:

- **`main`:** `title`, `key`, `source` (ручная, по фильтру), `limit`, `view`, `link`, `link_text`,
  `is_enabled`, `only_purchasable`.
- **`products-tab`:** при `manual` — ручной список; при `filter` — пресет, `category_id`, набор, `on_sale`,
  `sort`. Рядом — предпросмотр.
- **`history-tab`:** журнал.

Два поля `main` подробнее:

- **«Лимит» (`limit`)** — у каждой подборки своё, от 1 до `max_limit`. Сохранить больше нельзя, ошибка называет
  предел. Подсказка под полем: вставка может только уменьшить это число (§4.1).
- **«Только товары, которые можно купить» (`only_purchasable`)** — включено по умолчанию. Без спутника наличия
  поля нет (§5.2).

Сайт дополняет форму патчем `Screens::extend('catalog.collection-form', […])`.

### 6.3. Предпросмотр и общее поле набора

**Предпросмотр** — колонка рядом с условиями: первые товары в порядке вывода (картинка, название, цена,
старая цена), число подошедших, предупреждение на пустой результат. Считается на несохранённых
значениях через `POST catalog/collections/preview`, с задержкой после правки, как живое число
посадочной. Там же, отдельным списком, — товары ручного списка, которые на сайт не попадут, с причиной
(снят с публикации, скрыт, статус нельзя купить — с его названием, нет на языке). Иначе менеджер не поймёт, почему добавил пять
товаров, а показано три.

**Поле набора.** `LandingSetField.vue` привязан к `useLandingEditor` и `createLandingsApi`. Общая часть
(«добавить фасет», значения, диапазоны) уходит в `@webx-ui/module-catalog` как `WxCatalogFacetSet`:
фасеты и число приходят пропсами, наружу идут события. Посадочная оставляет обёртку с предупреждением о
дубликате, подборка заводит свою.

### 6.4. Где используется

**В первой версии — блоки и регионы (решение 9).** Это дёшево, потому что готовый механизм есть:
`Blocks\Panel\Usage` (§13 блоков) обходит сущности и регионы, черновик и живую версию, а `Usage::fragments()`
уже ищет места по значению поля. Блок `product-collection` хранит ключ в поле `collection`, поэтому в
`module-blocks` нужен один открытый метод `Usage::valued($slug, $field)`: тот же обход, та же строка (`live`,
`draft`, `url`, `region`), ответ — места по значению. Существующего `values()` мало: в его строках нет ни адреса,
ни дерева.

- **Сервис `CollectionUsage`:** один обход на все подборки, кеш на группе `block-usage` (`Usage::GROUP`). Её двигает
  сохранение любой сущности с блоками и региона.
- **Поповер** за словами «Мест: 3», как `wx-popover` в редакторе блока. Компонент свой, небольшой:
  `@webx-ui/module-blocks` в зависимости спутника не идёт.
- **Подпись под списком:** «Считаются блоки и регионы. Вставки в текст и теги в шаблонах здесь не видны».
- **Без `module-blocks`** блока нет, поэтому нет ни счётчика, ни поповера.

**Отложено.** Каждый из этих источников — новый обход, а не вызов готового:

| Откуда                       | Почему не сейчас                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| Шорткод в блоках             | `Usage` ищет по типу и полю блока. Шорткод надо искать в значениях всех блоков, а `trees()` закрыт    |
| Шорткод в текстах вне блоков | нужен список моделей и полей и полный проход по описаниям категорий, брендов и товаров: самый дорогой |
| Тег в файлах темы            | отдельное чтение файлов по образцу `Rendering\ViewCalls`, а `:key="$x"` всё равно не виден            |

Значит, «Мест: 0» не означает «нигде не стоит». Удаление это переживает, потому что корзина обратима (§4.4).
Вернуться к отложенному можно без миграции: источники добавляются в `CollectionUsage`.

## 7. MCP

`CollectionTools` через `SatelliteTools` ядра: имена, скоупы и права — каталога, собирается при запросе
агента, не при загрузке. Все меняющие принимают `dry_run` и отвечают, что сделали бы. Ошибки —
`ToolFailure` словами панели: неизвестный ключ с перечнем существующих, неизвестный фасет или значение
со ссылкой на `catalog_collections_facets`, смена `key` с объяснением, почему нельзя, `limit` больше `max_limit`
с его значением.

| Инструмент                     | Что                                                                          | Скоуп           | Право            |
| ------------------------------ | ---------------------------------------------------------------------------- | --------------- | ---------------- |
| `catalog_collections_list`     | подборки: ключ, заголовок, способ, состояние, число мест в блоках и регионах | `catalog:read`  | `catalog.view`   |
| `catalog_collections_get`      | подборка целиком: все языки, набор кодами и id, ручной список                | `catalog:read`  | `catalog.view`   |
| `catalog_collections_facets`   | фасеты и значения для основы, пресеты, сортировки                            | `catalog:read`  | `catalog.view`   |
| `catalog_collections_preview`  | `{collection?, values?, locale?}`: состав и отсеянные с причиной             | `catalog:read`  | `catalog.view`   |
| `catalog_collections_usage`    | блоки и регионы; в ответе сказано, что текст и теги не считаются (§6.4)      | `catalog:read`  | `catalog.view`   |

- `_preview` данных не меняет, поэтому `dry_run` у него нет, как у `catalog_feeds_preview`.
- `_products` у подборки по фильтру — отказ: ручной список там не читается, и агент решил бы, что
  записал состав. Неизвестный или удалённый товар — отказ с его id.
- Набор принимается кодами и слагами (как `set` у `catalog_landings_create`), хранится id.
- **Ресурс** `catalog://collections` — правила дома: чем подборка отличается от посадочной и от
  `wx-collection`, три способа вставки с образцами, пресеты, «сначала `_facets`, потом `_create`, потом
  `_preview`». Блок и текст агент правит инструментами `blocks_*` и `pages_*`.

## 8. Безопасность и права

Модель — [`WEBX_UI_PERMISSIONS.md`](WEBX_UI_PERMISSIONS.md).

- **Своих прав нет**, как у всех спутников: смотреть — `catalog.view`, править и удалять —
  `catalog.manage`. Раздел виден держателю любого (`visibleWith()`). Маршруты — `cms.can`, узлы экрана —
  `can`, инструменты — `permission:`. `AccessCoverageTest` пакета зелёный, права описаны в `### Permissions`
  его `AGENTS.md`.
- **Аргументы шорткода и тега — ввод редактора.** `key` — по `[a-z0-9-]`, иначе пусто. `view` — белый список.
  `limit` приводится к числу и зажимается в `1…limit подборки`. В ключ кеша он не входит и записей не плодит (§5.5).
  Значения в разметку идут только через `{{ }}`. Шорткод возвращает доверенный HTML только из своей вьюхи.
- **Никакого шаблона из панели.** Подборка хранит данные, Blade менеджер не пишет. Фасеты и сортировки
  ограничены реестрами, в SQL попадают только через `applySql()` и `Sort::applySql()`.
- **Ссылка** — значение `wx-link`: тот же разбор, что у блоков. На этапе 5 тест отказа на `javascript:`.
- **Закрытые данные наружу не идут.** Карточка показывает только то, что видно в каталоге. Предпросмотр
  сверх этого раскрывает причину отсева и только администратору. Цены скрыты вместе с
  `webx-catalog.price.enabled`.
- **Кеш общий для всех посетителей**, поэтому в ключе нет пользователя, а в значении только id. Цена, скидка и
  кнопка считаются при выводе. Когда появятся цены по группам, значение от этого не изменится.
- **Нагрузка.** `preview` ограничен `max_limit` и лимитом в SQL, `POST` без записи. Подборка без условий
  законна и не тяжелее других: `limit` стоит в запросе (§5.1).
