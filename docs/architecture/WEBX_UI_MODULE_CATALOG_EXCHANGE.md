# Обмен каталога — импорт и экспорт CSV и XLSX

Конвейер обмена в ядре `module-catalog`: контракт колонок, импорт и экспорт таблиц, профили,
журнал прогонов с ошибками по строкам, раздел «Обмен» в панели и инструменты агента. Архитектура
семейства — [`WEBX_UI_CATALOG.md`](WEBX_UI_CATALOG.md) (§4.5, решения 10 и 15), ядро —
[`WEBX_UI_MODULE_CATALOG.md`](WEBX_UI_MODULE_CATALOG.md) (§7.6 — колонки ядра), формат колонок
свойств — решение 12 [`WEBX_UI_CATALOG_PROPERTIES.md`](WEBX_UI_CATALOG_PROPERTIES.md), справочников —
[`WEBX_UI_CATALOG_DICTIONARIES.md`](WEBX_UI_CATALOG_DICTIONARIES.md) §3. Статус: спека написана
30.09.2026; E1–E4 в коде (01.10.2026): php ядра, колонки спутников, экраны панели, агент, демо и
прогон alfatech — §15. Порядок работ — §14.

Решения §1 приняты по рекомендации без долгого обсуждения: опыта таких модулей у владельца нет, и
договорились поправить то, что выберет первый живой прогон (выгрузка alfatech на 85 тысяч, E4).
Поэтому здесь «не переоткрывать» значит «не переоткрывать без прогона, который показал проблему».

## 1. Решения

1. **Конвейер, CSV и XLSX — в ядре, а не отдельным пакетом.** Магазин без загрузки таблицы — не
   магазин, а пакет ради двух форматов — лишняя строка в `webx:setup`. Ядро держит реестр
   форматов `ExchangeFormats`; YML, CommerceML, Google Merchant приходят отдельными пакетами
   через него (волна B). Строка §3 архитектуры поправлена этим же PR.
2. **Чтение и запись — `openspout/openspout`.** Потоковая, одна зависимость на CSV и XLSX, 85
   тысяч строк не держит в памяти. Старый двоичный `.xls` не поддерживаем: кому нужен —
   пересохранит.
3. **Строка файла пишется тем же путём, что форма.** `ProductForm::save()` — «каждая дверь, один
   путь»: проверка экрана, части спутников, журнал. Колонка обмена — это не запись в базу, а
   кодек «ячейка ↔ значение поля формы» (`name`, `price`, `stock.status`, `properties.cvet`).
   Спутнику не нужно второй раз учить, как писать свои данные.
4. **Ключ строки — `sku` по умолчанию**; в профиле — `external_id`, `barcode` (если включён) или
   `id`. Удалённый товар находится по ключу тоже (артикул уникален с удалёнными, §3 ядра) — строка
   даёт ошибку «товар в удалённых», а не дубль.
5. **Режим профиля:** «создавать и обновлять» (по умолчанию), «только обновлять», «только
   создавать». Строка вне режима — пропуск со счётчиком, а не ошибка.
6. **Пустая ячейка не трогает поле.** Стереть — флаг профиля `empty_clears`. Колонки, которой нет в
   файле или которая не сопоставлена, импорт не касается вовсе.
7. **Товары, которых нет в файле:** `keep` по умолчанию или `unpublish`. Снимаются только в
   охвате прогона: по умолчанию — категории, встретившиеся в файле (прайс поставщика не снимает
   чужой ассортимент), опцией — весь каталог. Удаления нет ни в каком режиме. Шаг идёт после всех
   строк и только если прогон дошёл до конца без остановки.
8. **Незнакомое значение справочника или категории** — создаётся или даёт ошибку строки;
   переключатель профиля `create_missing`, один на категории, бренды, метки и значения свойств.
   Наличие (`stock`) не создаётся никогда: статус несёт флаг «можно купить», его выбирает человек.
9. **Плохая строка не роняет пачку.** Пачка — транзакция, каждая строка — точка сохранения
   (вложенная транзакция Laravel). Ошибка строки откатывает только её и пишется в журнал:
   номер строки, колонка, значение, причина.
10. **Проверка без записи.** Тот же прогон целиком с `dry_run`: все строки проходят кодеки и
    проверку формы, журнал ошибок полный, в базу не пишется ничего (транзакция пачки
    откатывается). Панель предлагает проверку перед первым запуском профиля; агент получает
    `dry_run` как у любого инструмента.
11. **Источник файла — загрузка или адрес.** Загрузка — кусками через `/api/cms/uploads` из V1
    ([`WEBX_UI_CATALOG_VIDEO.md`](WEBX_UI_CATALOG_VIDEO.md) §4), назначение `catalog-exchange`;
    адрес качает очередь. Расписание («прайс поставщика каждую ночь») — отложено (§11).
12. **Журнал изменений:** прогон — один run журнала `module-admin` с источником
    `HistoryContext::IMPORT`; строки товаров пишет `ProductForm::save()` внутри run, как у
    массовых действий. Товар в своей истории показывает «импорт №N».
13. **Индексация — одним запросом на пачку.** `Catalog::deferTouch()` собирает id, пока идёт пачка,
    и помечает их после коммита (§4.5 архитектуры).
14. **Экспорт** — отбор списка (фильтр или выделение) и набор колонок профиля или выбранных
    вручную, в очереди. Файл живёт `exchange.keep_hours` (24 по умолчанию) и забирается ссылкой
    из прогона.
15. **Языки в колонках:** `name` — язык по умолчанию, `name@de` — перевод. Так же у свойств
    (решение 12 свойств) и у всего переводимого.
16. **Картинки по адресам** качает очередь галереи (`Gallery::fetch()`), по хешу адреса повторно не
    качает. Профиль: `images: replace` или `append` (по умолчанию `append`).

## 3. Контракт колонок

```php
interface ExchangeColumn
{
    /** The header code: `[a-z0-9_]`, what a file carries in its first row. */
    public function key(): string;

    /** Words for the mapping screen. */
    public function label(): string;

    /** The form field it fills: `name`, `price`, `stock.status`, `properties.cvet`. */
    public function field(): string;

    /** Whether `key@<locale>` columns exist for it. */
    public function localized(): bool;

    /**
     * Cells for a page of products, for the export — product id → text.
     * Locale is null for the default language.
     *
     * @param  Collection<int, Product>  $products
     * @return array<int, string>
     */
    public function export(Collection $products, ?string $locale): array;

    /**
     * The cell as the form wants it. Throws RowError on a value it cannot read; with
     * `$context->createMissing` it may create a reference-book value and return its id.
     */
    public function parse(string $cell, ImportContext $context): mixed;
}
```

- **Колонка = поле формы.** `Importer` собирает из строки тот же массив, что шлёт редактор, и
  зовёт `ProductForm::save()`. Поле, которое форма не знает (часть спутника выключена), — ошибка
  регистрации колонки, а не молчание.
- **`export()` пачкой**, как `ProductPart::read()`: на страницу из 500 товаров — запросы на
  колонку, а не на товар. Большинство колонок спутников — обёртка над `read()` их части.
- **Динамические колонки** даёт `ExchangeColumnProvider::columns(): iterable<ExchangeColumn>` —
  свойства отдают колонку на каждое неудалённое свойство, код — код свойства на языке по
  умолчанию.
- **Коды уникальны.** Занятый код — исключение при регистрации, как у фасетов. Код свойства,
  совпавший с колонкой ядра, получает приставку `p_` и предупреждение в doctor.
- **Колонки выключенного признака не объявляются** (цена, штрихкод) — как в форме.

## 4. Импорт

### 4.1. Шаги

1. **Файл.** Загрузка (назначение `catalog-exchange`, форматы — расширения зарегистрированных) или
   адрес (`fetch` в очереди, лимит `exchange.max_bytes`, 200 МБ по умолчанию).
2. **Заголовок.** Первая строка — коды или подписи колонок. Сопоставление по коду, потом по
   подписи без регистра; что не нашлось — «не импортировать». CSV: кодировка по BOM, иначе
   проверка UTF-8, иначе `exchange.csv_fallback_encoding` (`Windows-1252`); разделитель — по
   первой строке из `,` `;` `\t`; всё переопределяется профилем.
3. **Сопоставление** — сохраняется в профиль или живёт только в прогоне.
4. **Проверка** (`dry_run`) — по желанию; панель предлагает её, если профиль ещё не запускался.
5. **Прогон** — пачки по `exchange.chunk` строк (200) в очереди; малый файл (≤
   `exchange.sync_limit`, 50 строк) — сразу, как массовые действия.
6. **Шаг «нет в файле»** (§1 п. 7) — одним запросом по охвату, после последней пачки.
7. **Итог:** создано, обновлено, пропущено, ошибок; журнал ошибок скачивается CSV-файлом.

### 4.2. Пачка

```
transaction(batch):
  deferTouch:
    for row in rows:
      savepoint:
        product = find by key (with trashed)       → RowError if trashed
        mode check                                 → skip
        input = columns.parse(cells)               → RowError(column, value, reason)
        form.save(product, input, can)             → ValidationException → RowError per field
      on error: rollback savepoint, log error, continue
  if dry_run: rollback batch
```

Пачка хранит смещение в файле (`rows_done`), поэтому задача, упавшая посреди, повторяется с
начала своей пачки и не пишет строки дважды: транзакция пачки не закоммичена. Остановка:
ошибок больше `exchange.max_errors` (1000) — прогон `stopped`, записанные пачки остаются, шаг «нет
в файле» не выполняется.

### 4.3. Права

Импорт требует `catalog.products.create` и/или `.update` по режиму, плюс права спутника на его
колонки — то же `can`, что у формы. Колонку, на которую прав нет, сопоставление не предлагает.
Создание значений справочника (`create_missing`) — только с правом записи в справочник, иначе
ошибка строки.

### 4.4. Производительность

`ProductForm::save()` на строку дороже прямой вставки, зато один путь. Цель — 85 тысяч строк alfatech
за время, в которое очередь успевает за ночь (ориентир — 20 мс на строку, полчаса); E4 меряет. Если
не укладывается — сначала кеш справочников на прогон (`ImportContext` держит словари «слаг → id»),
потом уже прямые пути; решение принимает прогон, не догадка.

## 5. Экспорт

- **Отбор** — тот же `BulkSelection`, что у массовых действий (фильтр списка или id), включая
  «Удалённые» по флагу.
- **Колонки** — профиль экспорта (упорядоченный список кодов, языки) или выбор на месте.
- Пачки по `exchange.chunk` товаров, `export()` каждой колонки пачкой, запись потоком в файл на
  диске `exchange.disk` (`local`). Готовый файл — ссылка в прогоне с подписанным адресом; через
  `keep_hours` его убирает `webx:catalog:exchange-prune` (в расписании каталога).
- Экспорт, загруженный обратно тем же профилем без правок, ничего не меняет — это тест (§13).

### `catalog_exchange_errors`

`id`, `run_id` (cascade), `row` (unsigned int), `column` (string, null — ошибка строки целиком),
`value` (text, null, обрезанное до 500 символов), `message` (string). Индекс `(run_id, row)`.
Храним не больше `max_errors` на прогон.

Прогоны старше `exchange.keep_runs_days` (90) убирает тот же prune.

## 7. Колонки

### 7.1. Ядро

| Код             | Поле           | Формат ячейки                                                                        |
| --------------- | -------------- | ------------------------------------------------------------------------------------ |
| `id`            | —              | только ключ; при создании игнорируется                                               |
| `sku`           | `sku`          | строка                                                                               |
| `barcode`\*     | `barcode`      | строка                                                                               |
| `external_id`   | `external_id`  | строка                                                                               |
| `name`\@        | `name`         | строка                                                                               |
| `slug`\@        | `slug`         | строка; пусто при создании — из названия, как в форме                                |
| `summary`\@     | `summary`      | строка                                                                               |
| `description`\@ | `description`  | HTML как есть                                                                        |
| `category`      | `category_id`  | путь по названиям через `/` (`Электроника/Телефоны`) или `#id`                       |
| `categories`    | `category_ids` | несколько путей через `;`                                                            |
| `price`\*       | `price`        | число, точка или запятая, без валюты                                                 |
| `old_price`\*   | `old_price`    | то же                                                                                |
| `unit`          | `unit`         | код из `webx-catalog.units`                                                          |
| `priority`      | `priority`     | целое                                                                                |
| `is_published`  | `is_published` | `1/0`, `yes/no`, `true/false`; публикация без категории — ошибка строки, как в форме |
| `images`        | галерея        | адреса через `;`; экспорт — публичные адреса картинок                                |

\* — не объявляется, если признак выключен. \@ — есть `code@<locale>`.

Путь категории разбирается по названиям на языке по умолчанию, от корня; неоднозначный путь (два
брата с одним названием) — ошибка строки с id обоих, подсказка — `#id`.

### 7.2. Спутники

| Модуль                      | Код                | Поле               | Формат                                                                                                                   |
| --------------------------- | ------------------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `module-catalog-labels`     | `labels`           | `labels.ids`       | коды меток через `;`                                                                                                     |
| `module-catalog-stock`      | `stock`            | `stock.status`     | код статуса; не создаётся (§1 п. 8)                                                                                      |
| `module-catalog-brands`     | `brand`            | `brand.id`         | слаг, иначе название без регистра                                                                                        |
| `module-catalog-properties` | `<код свойства>`\@ | `properties.<код>` | решение 12 свойств: `;` — несколько, `/` — путь дерева, число без единицы, `bool` — как `is_published`, текст — как есть |

Справочники дописывают в `DictionariesServiceProvider` по колонке; свойства — провайдер. Экспорт
справочника отдаёт то, что импорт примет обратно: коды меток, слаг бренда, путь значения.

## 8. Панель

### 8.1. Меню и экраны

Пункт «Обмен» в разделе каталога после «Удалённых». Экраны (все — узлы `@webx-ui/schema`, как
остальной каталог):

- **`catalog.exchange`** — список прогонов (дата, кто, направление, профиль, статус с прогрессом,
  итоги) и две кнопки: «Импорт», «Экспорт». Строка прогона раскрывается: итоги, ошибки таблицей
  (первые 100 и «скачать все CSV»), ссылка на файл экспорта, ссылка на run журнала.
- **Мастер импорта** (`catalog.exchange-import`, шаги `WxSteps`): файл (загрузка кусками или
  адрес) → сопоставление (таблица «колонка файла → колонка каталога», пять строк примера под
  каждой) → настройки (§1: ключ, режим, пустые, нет в файле, создавать недостающее, картинки) →
  «Проверить» / «Запустить». «Сохранить как профиль» — на шаге настроек.
- **Экспорт** — диалог: профиль или колонки с языками, формат; из списка товаров — «Экспорт» в
  массовых действиях с текущим отбором.
- **Профили** — список и форма (название, направление, формат, настройки, сопоставление).

Прогресс — опросом прогона раз в 2 секунды, пока `queued|running`, как у массовых действий.

### 8.2. API

Под `/api/cms/catalog/exchange`:

| Метод и путь                | Что                                                                                                   |
| --------------------------- | ----------------------------------------------------------------------------------------------------- |
| `GET columns`               | колонки с подписями, полями, языками — с учётом прав                                                  |
| `POST inspect`              | `{upload_id \| url}` → формат, кодировка, разделитель, заголовок, 5 строк, предложенное сопоставление |
| `POST import`               | `{upload_id \| url, profile_id \| mapping+options, dry_run}` → прогон                                 |
| `POST export`               | `{selection, profile_id \| columns+format}` → прогон                                                  |
| `GET runs`, `GET runs/{id}` | список и прогон                                                                                       |
| `GET runs/{id}/errors`      | страница ошибок; `?format=csv` — файлом                                                               |
| `GET runs/{id}/file`        | готовый экспорт                                                                                       |
| `apiResource profiles`      | профили                                                                                               |

## 9. MCP

Инструменты в наборе `catalog`:

- `catalog_exchange_columns` — какие колонки есть, их формат;
- `catalog_import` — `{url, profile_id? | mapping+options, dry_run}`; файл только по адресу,
  отдаёт прогон;
- `catalog_export` — `{filter | ids, columns | profile_id, format}` → прогон, ссылка появится в
  `catalog_exchange_run`;
- `catalog_exchange_run` — прогон с итогами и первыми 50 ошибками;
- `catalog_exchange_profiles` — список профилей.

Ресурс `catalog://exchange` — правила формата §7 одной страницей: агенту проще собрать CSV
правильно, чем разбирать ошибки.

## 13. Тесты, которые обязательны

- экспорт → импорт тем же профилем без правок: ноль изменений, ноль строк журнала;
- ключ: `sku`, `external_id`, `id`; удалённый товар по ключу — ошибка строки, не дубль;
- режимы: «только обновлять» пропускает новые, «только создавать» — найденные;
- пустая ячейка не трогает поле, с `empty_clears` — стирает; несопоставленная колонка не
  трогает;
- ошибка одной строки откатывает её одну; остальные в пачке записаны; журнал — строка, колонка,
  значение, причина;
- `dry_run` не пишет ничего (ни товаров, ни значений справочников, ни журнала изменений), но
  журнал ошибок полный;
- `create_missing`: категория путём, бренд, метка, значение свойства (и дерево по пути)
  создаются; без флага — ошибка строки; `stock` не создаётся никогда;
- «нет в файле» с `unpublish`: только в охвате категорий файла; прогон со остановкой шаг не
  делает;
- языки: `name@de` пишет перевод, `name` — язык по умолчанию;
- индексация: пачка помечает товары одним запросом (счёт запросов);
- права: колонки без права не предлагаются; `create_missing` без права записи в справочник —
  ошибка;
- CSV: BOM, `;`-разделитель, Windows-1252; XLSX читается и пишется;
- пачка, упавшая посреди (исключение в задаче), повторяется без дублей.

## 15. Как легло в код

### E1 — php ядра

Всё в `module-catalog`, `WebxUi\Catalog\Exchange\` — раскладка §2 как есть, плюс мелочь вокруг:
`WritesProduct` (колонка, которая пишет мимо формы), `RenamedColumn` (колонка провайдера под
`p_<код>`), `ChunkResult` (итоги пачки), `ExchangeFiles` (загрузка, адрес, диск),
`FetchExchangeImages` (задача картинок), `Columns\CategoryPaths` (дерево категорий по путям).
Колонки ядра §7.1 — `Columns\ValueColumn` (текст, цена, целое, да/нет, единица), `IdColumn`,
`ExternalIdColumn`, `CategoryColumn` (`category` и `categories`), `ImagesColumn`. Форматы —
`Formats\CsvFormat` и `Formats\XlsxFormat` на общем трейте `SpreadsheetCells`. Схема — миграция
`2026_01_02_000008_create_catalog_exchange_tables`, API — `ExchangeController` и
`ExchangeProfileController`, prune — `webx:catalog:exchange-prune` раз в час. Тесты —
`tests/ExchangeTest.php`: всё из §13, что касается колонок ядра, круг «экспорт → импорт» для CSV и
для XLSX.

Отклонения от спеки и почему:

- **`ExchangeFormat` — не `reader`/`writer`, а `options()`, `read()`, `write()`.** `options()`
  отдаёт, как файл читается (кодировка и разделитель CSV — то, что показывает `inspect` и
  запоминает прогон); `read()` — генератор «номер строки → ячейки текстом», пустые строки
  пропущены, но посчитаны: «строка 12» в ошибке — та, что откроет редактор; `write()` пишет
  каждую ячейку строкой (артикул `0012` остаётся `0012`, описание с `=` — не формула).
- **Назначение загрузки — `catalog.exchange`, а не `catalog-exchange`**: так же, как
  `catalog.video` у галереи. Тип файла не проверяется — формат решает расширение, а читатель
  отказывает сам; лимит — `exchange.max_bytes`.
- **Права — три права ядра, а не `catalog.products.create/.update` (§4.3).** Таких прав у
  каталога нет. Импорт и профили — `catalog.manage`; колонки, прогоны, ошибки, файлы и экспорт —
  любое из трёх. Колонка, чьё поле на экране стоит за `can`, которого нет, не предлагается и в
  сопоставлении даёт 422.
- **Права в очереди — снимком.** Воркеру некого спросить, поэтому прогон при старте
  запоминает в `options.granted`, какие из известных прав у запустившего есть (права модулей
  реестра плюс `can` узлов формы товара), а `ImportContext::can()` читает снимок. Из ответа API
  снимок вырезан.
- **`external_id` и картинки — не поля формы.** Для них интерфейс `WritesProduct`: колонка пишет
  сама после `ProductForm::save()`, внутри той же точки сохранения, и реестр не ищет её поле на
  экране. `external_id` пишется `saveQuietly()` (журнал его всё равно пропускает); занятый чужим
  товаром — ошибка строки с id владельца.
- **Картинки качает своя задача на товар, а не очередь галереи напрямую.** `ImagesColumn`
  ставит `FetchExchangeImages` после коммита (`afterCommit`: строка, откатанная к точке
  сохранения, уносит и задачу); та зовёт `Gallery::add()` на каждый новый адрес и пишет в
  картинку `source_hash` (новая колонка `catalog_product_images`). «Уже есть» — это адрес своей
  картинки (экспорт, присланный обратно) или хеш адреса, с которого картинку уже качали. Отказ
  галереи — строка ошибок прогона под номером строки, а не упавшая задача. `replace` снимает
  картинки, которых ячейка не называет, в той же задаче. Экспорт пишет адреса с хостом: диск,
  отдающий `/storage/…`, получает `url()`.
- **Четвёртая таблица — `catalog_exchange_run_items` (`run_id`, `product_id`).** Экспорт
  фиксирует в ней отбор на момент старта, как массовые действия; импорт с `absent: unpublish`
  кладёт туда встреченные товары — шагу «нет в файле» нужно знать их все, а не только последнюю
  пачку. Без `unpublish` импорт туда не пишет.
- **`last_run_id` у профиля — без внешнего ключа**: таблицы указывали бы друг на друга, а
  prune, убравший прогон, профиль не трогает.
- **Файл читается раз на задачу, а не раз на пачку.** Задача делает пачки, пока не пройдёт
  `exchange.job_seconds` (новый ключ конфига, 60), и ставит следующую; иначе XLSX на 85 тысяч
  строк распаковывался бы 425 раз. Пачка по-прежнему — одна транзакция, смещение `rows_done`
  меняется в ней же под `lockForUpdate`, так что повтор упавшей задачи не пишет строк дважды
  (тест с «убитой» второй пачкой).
- **Экспорт — одна задача на весь файл**: электронную таблицу следующая задача не продолжит.
  Чтение — страницами по `exchange.chunk`, `export()` каждой колонки — страницей.
- **`deferTouch` пишет пометки в конце пачки, внутри её транзакции**, а не после коммита: они
  коммитятся и откатываются вместе со строками, и проверка без записи не оставляет пометок.
  Вложенный `deferTouch` — часть внешнего.
- **Готовый экспорт — два адреса:** `runs/{id}/file` под сессией панели и подписанная ссылка
  `…/exchange/download/{run}` (живёт `keep_hours`) в `file_url` прогона — её отдаст агент (E4).
- **`inspect` загрузку не забирает**, а читает её `.part` на месте: иначе `import` не смог бы
  её забрать. Адрес `inspect` скачивает во временный файл и удаляет.
- **Категории путём:** сравнение без регистра; созданная импортом категория опубликована —
  скрытая молча сняла бы с сайта товары, которые в неё положили. Экспорт пишет `#id` вместо
  пути, когда путь не прочитался бы обратно тем же: имя с `/`, `;` или `#`, брат с тем же именем,
  предок в корзине.
- **Ключ обязан быть среди сопоставленных колонок** — иначе 422 до запуска. Неизвестный `id`
  при создании — новый товар со своим id (§7.1: «при создании игнорируется»).
- **`updated` считает найденные и сохранённые строки**, даже если ничего не поменялось: что
  поменялось на самом деле, говорит журнал (у круга «экспорт → импорт» в нём ноль строк).
- **Пустые ячейки с `empty_clears`** стирают и то, что пишет колонка сама: пустые `images` с
  `replace` снимают галерею.
- **openspout — `^4.32`, а не 5.x**: пятая требует PHP 8.4, пакет обещает `^8.3`.
- **Не сделано в E1:** предупреждение doctor о переименованной в `p_` колонке — сделано в E2.

### E2 — колонки спутников

Колонки лежат в своих пакетах, рядом с частью формы, которую заполняют: `LabelsExchangeColumn`
(`module-catalog-labels`), `StockExchangeColumn` (`module-catalog-stock`), `BrandExchangeColumn` и
`BrandNames` (`module-catalog-brands`), в `module-catalog-properties` — пространство
`WebxUi\CatalogProperties\Exchange\`: провайдер `PropertyExchangeColumns`, колонка
`PropertyExchangeColumn`, дерево значений по путям `ValuePaths` и `ExportPage` — общая страница
значений на все колонки свойств одного экспорта. В ядре прибавились `EntryColumn`, `Lookup` и
проверка doctor `Doctor\ExchangeCheck`. Тесты — `module-catalog-properties/tests/ExchangeTest.php`:
всё из §13, что касается спутников, и круг «экспорт → импорт» для CSV и XLSX на товаре с метками,
наличием, брендом и свойствами всех четырёх типов (многозначный справочник, дерево, число, два
«да/нет», текст на двух языках, значение вне набора), с `create_missing` и `empty_clears`.

Отклонения от спеки и почему:

- **`DictionariesServiceProvider` нет** — справочники давно три пакета, и колонку регистрирует
  провайдер каждого (`LabelsServiceProvider`, `StockServiceProvider`, `BrandsServiceProvider`)
  рядом со своей колонкой списка.
- **Поле свойства — не `properties.<код>`, а одна запись объекта `properties.values`.** Форма
  принимает свойства одним полем `{ "<id свойства>": значение }`, и колонки свойств, писавшие
  каждая в своё «поле», затирали бы друг друга. Для этого в ядре интерфейс `EntryColumn`
  (`entry()` — ключ внутри объекта): `Importer` собирает из таких колонок один объект, переводимая
  кладёт `{ "<id>": { "<язык>": текст } }`, а отказ формы под `properties.values.12` подписывается
  колонкой свойства 12, а не первой попавшейся. `RenamedColumn` отдаёт исходную колонку
  (`column()`), чтобы `p_<код>` не терял запись.
- **Заголовок колонки свойства — код с `_` вместо `-`.** Код свойства — `[a-z0-9-]`, заголовок —
  `[a-z0-9_]`; `_` в коде свойства запрещён, так что замена однозначна (`net-weight` → `net_weight`).
  Свойство без кода на языке по умолчанию — колонка `p<id>`, как его называет `codeIn()`.
- **`p_<код>` бывает реже, чем кажется.** Код свойства уже уникален среди фасетов ядра (§4.1
  свойств), так что `price` или `brand` свойство не получит вовсе; столкнуться можно только с
  колонкой, которая не фасет: `sku`, `name`, `summary`, `images`… Doctor (`ExchangeCheck`)
  предупреждает о каждой переименованной и о той, которой не досталось и `p_<код>`
  (`ExchangeColumns::renamed()`).
- **Значение справочника свойства — по названию, а не по слагу.** Файл пишет человек, и пишет
  «Чёрный», а не `chernyy`. Импорт берёт название на языке по умолчанию без регистра (у дерева —
  путь названий через `/`), потом слаг на любом языке, потом `#id`; экспорт пишет путь названий и
  `#id` там, где путь не прочитался бы обратно тем же значением: разделитель в названии (`/` у
  дерева, `;` у многозначного), сестра с тем же названием. Созданное импортом значение — через
  `ValueBook::create()`, как в панели: слаг сделает модель.
- **Наличие экспортируется, только если его выбрали.** Товар без строки в
  `catalog_product_stock` стоит в статусе по умолчанию, и экспорт пишет ему пустую ячейку, а не
  код этого статуса: иначе файл, присланный обратно, приколол бы все товары к сегодняшнему
  умолчанию (§2.2 справочников — «явное сильнее неявного»), и смена умолчания их бы больше не
  двигала. Пустая ячейка — «не трогать», с `empty_clears` — «умолчание».
- **«Да/нет» свойства в наборе экспорт пишет `1` или `0`, вне набора — пусто.** Значения вне
  набора (решение 6 свойств) в файл не попадают вовсе: форма отказала бы им на обратном пути.
- **Пустая ячейка свойства вне набора с `empty_clears` — не ошибка.** Нашлось кругом «экспорт →
  импорт»: выгрузка каталога со смешанными категориями несёт колонку каждого свойства у каждого
  товара, и `null` для свойства не из набора `PropertiesPart::write()` отказывал строке целиком.
  Теперь `null` вне набора — пустая операция (стирать в форме нечего, а хранимое вне набора
  остаётся, решение 6); непустое значение вне набора по-прежнему ошибка колонки.
- **Бренд:** слаг на любом языке, потом название без регистра на языке по умолчанию, потом
  `#id`; два живых бренда с одним названием — ошибка строки с обоими id, бренд из корзины —
  ошибка «восстановите». Экспорт пишет слаг языка по умолчанию, у бренда без слага — название,
  если оно читается обратно однозначно, иначе `#id`. Созданный импортом бренд видим и получает
  адрес из названия через общий `CategoryForm::create()`; отказ реестра адресов — ошибка строки,
  а не 422 под чужой колонкой `slug`.
- **Метка создаётся с кодом из ячейки и с ним же как названием** — переименовать её в панели
  дело человека. Ячейка, которая не годится в код (`[a-z0-9-]`, до 32), — ошибка строки, а не
  метка с выдуманным кодом. Метка из корзины находится по коду: она всё ещё стоит на товарах.
- **Кеш «код → id» — `Lookup` в ядре**, общий для меток и наличия: читается первой строкой,
  пополняется созданным, забывается вместе с мешком, если строка, создавшая что-то, откатилась.
  Бренды и значения свойств держат свои индексы (`BrandNames`, `ValuePaths`) тем же
  `ImportContext::remember` / `made()`.
- **Право на создание — `catalog.manage`** у всех четырёх справочников: своих прав у них нет
  (решение 8 справочников). Импорт сам требует `catalog.manage`, поэтому отказ «нет права
  создать» достижим только снимком прав без него — тест зовёт колонку с таким `ImportContext`
  напрямую.
- **`ValueColumn::decimal()` и `::boolean()` стали публичными** — число свойства читается как
  цена, «да/нет» — как `is_published`, одним кодом.
- **`module-catalog-properties` получил в `require-dev` метки, наличие и бренды**: круг на товаре
  со всеми частями живёт в его тестах.

### E3 — экраны панели

Всё в `@webx-ui/module-catalog`: `exchange.ts` (типы ответов §8.2, `createExchangeApi`,

Отклонения от спеки и почему:

- **Пункт «Обмен» — не в навигации, а в `···` товаров после «Удалённых».** Навигация — одна запись
  на модуль, и «Удалённые» тоже живут в шапке товаров, а не отдельным модулем. Своё место в меню
  потребовало бы php-модуль без прав и без инструментов, как `catalog-categories`, ради редкого
  экрана. Если на хомлабе окажется, что его не находят, — модуль добавляется одним классом.
- **Узлы схемы — две формы, а не все экраны.** Настройки импорта (`catalog.exchange-import`) и шапка
  профиля (`catalog.exchange-profile`: название, формат, кодировка и разделитель для CSV-импорта) —
  описанные экраны: сервер их регистрирует, проект патчит, мастер и форма профиля рисуют одни и те
  же. Список прогонов, сопоставление и колонки экспорта — Vue, как списки остального каталога:
  ни одно из них не форма записи, а таблица «заголовок → колонка» с примерами под каждым
  заголовком на узлах не собирается. Поэтому E3 трогает и php: два JSON, две строки регистрации,
  слова в `exchange.settings` и `panel.exchange-*`.
- **«Сохранить как профиль» — поле с названием и кнопкой на шаге настроек**, а не диалог:
  спросить строку из кода ядру нечем (`confirm` есть, `prompt` нет), а поле видно сразу.
- **Профиль с `last_run_id === null` меняет кнопки местами:** «Проверить без записи» — основная,
  «Запустить» — обычная, и сверху совет проверить. Не запрет: сервер прогон без проверки не
  отвергает, и панель тоже.
- **Ссылка на run журнала — диалог со строками run**, а не переход: отдельной страницы run в
  панели нет (run открывается из истории записи, внутри `WxHistory`). Диалог зовёт тот же
  `GET history/runs/{id}`.
- **Экспорт из списка товаров — пункт «Экспорт» первым в «Действиях»**, рядом с массовыми, и
  виден только тем, кому видна панель выделения (`catalog.manage` или `catalog.delete`). Право
  только на просмотр экспортирует из «Обмена» весь каталог; выделять у него нечего.
- **Строка прогона на телефоне — таблица, а не карточки** (`cards-below="0"`): карточки `WxTable`
  не рисуют слот `expanded`, и раскрыть прогон было бы нечем. Колонки «Итог» и «Начат» уходят по
  `hideBelow`, остаются прогон и статус; итоги — в раскрытой строке.
- **Мок честен в главном и условен в остальном.** `inspect` разбирает настоящий CSV (BOM, UTF-8
  или Windows-1252, разделитель по первой строке, кавычки) и угадывает сопоставление как
  `Importer::suggest()`; строка пишется тем же `writeProduct`, что форма, и отказы — формы.
  Условно: прогон идёт по таймеру (3 строки раз в 0,9 с); XLSX отвергается; адрес «скачивается»
  только демонстрационный `https://shop.webx-demo.test/price/catalog-import.csv` (18 строк, три
  ошибки нарочно: цена словом, неизвестная категория, публикация без категории); колонки — только
  ядра §7.1, колонки спутников проверяются на `webx-cms.local` в E4; экспорт всегда пишет CSV.
  В моке есть профиль «Demo import» на этот файл.

### E4 — агент, демо, живой прогон

Инструменты §9 и ресурс — `WebxUi\Catalog\Mcp\ExchangeTools`, рядом с `CatalogTools`;
`CatalogModule` отдаёт их в наборе `catalog` (двадцать шесть инструментов, семь ресурсов).
Импорт и экспорт идут теми же `Importer::start()` и `Exporter::start()`, что API §8.2, поэтому
прогон агента — обычная строка «Обмена» с ошибками и файлом. Как читается ячейка, колонка говорит
сама: новый необязательный интерфейс `DescribesCell` (`cellFormat()`), его реализуют все колонки
ядра и все четыре спутника; колонка без него идёт в ресурсе как «текст как есть». Тесты —
`tests/ExchangeMcpTest.php`: права, импорт по адресу с предложенным сопоставлением, `dry_run`,
профиль, экспорт подписанной ссылкой, круг «экспорт → импорт» агентом по `file_url`, ресурс.

Демо (§12) — в `webx-cms.local`: `database/demo/catalog-import.csv` (30 строк, все колонки ядра,
перевод `@en`, метки, наличие, бренд, свойства `cvet`, `material` деревом и `ves`; ошибка одна —
цена словом в строке 18) и `CatalogExchangeSeeder` в `docker/entrypoint.sh`: профиль «Demo import»
(сопоставление «код → код») и копия файла на публичный диск, `/storage/demo/catalog-import.csv`, —
у агента нет загрузки, ему нужен адрес. Хомлаб получает то же сидером; до релиза с обменом сидер
молчит.

Живая проверка на `webx-cms.local`, слинкованном с веткой:

- **Мастер:** профиль «Demo import», файл по адресу, сопоставление пришло всё (24 колонки, свойства
  кодами `cvet`, `material`, `ves`), «Проверить без записи» → 27 строк прошли, ошибок три вместо одной: статуса
  `preorder` на сайте нет (он в корзине) — поправлен демо-файл, а не код. Запуск: создано 29,
  ошибка одна, 46 значений свойств, run журнала.
- **Агент** через `mcp:start` (настоящий транспорт): `catalog_exchange_columns`, ресурс,
  `catalog_export` фильтром — 25 колонок со спутниками; круг «экспорт → импорт» по `file_url` в CSV и
  в XLSX — обновлено 29, ошибок ноль, в журнале только пустой run без строк.
- **alfatech:** 93 525 товаров `shop.alfatech.local` (скрипт `scripts/alfatech-export.php` в
  сайте, 64 МБ CSV: `external_id`, артикул, название и описание на двух языках, категория путём,
  цены, публикация, бренд, наличие), импорт `scripts/alfatech-import.php` — задача за задачей, как
  очередь, с `create_missing`. SQLite на рабочей машине, OSPanel PHP 8.4:

  | Прогон                                              | Строк  | Время | На строку | Запросов на строку | Задач | Память |
  | --------------------------------------------------- | ------ | ----- | --------- | ------------------ | ----- | ------ |
  | создание (238 категорий и 6 брендов заводит импорт) | 93 525 | 824 с | 8,8 мс    | 38                 | 14    | 30 МБ  |
  | тот же файл ещё раз                                 | 93 525 | 373 с | 4,0 мс    | 16                 | 7     | 28 МБ  |

  Цель §4.4 (20 мс) выполнена с запасом вдвое без кеша справочников: `Lookup`, `BrandNames` и
  дерево категорий уже держат словари на прогон (E1–E2), а пачка в одной транзакции снимает с
  SQLite главный тормоз. Повторный прогон — 93 525 «обновлено» и одна запись журнала (пустой run):
  круг «без изменений» держится и на 93 тысячах. Память не растёт — файл читается потоком, задача
  держит одну пачку. Первый прогон остановился на 27 400 строке по `max_errors` — та ошибка
  слага, что ниже; правило остановки сработало как задумано, записанные пачки остались.

Отклонения от спеки и почему:

- **Подписанная ссылка экспорта кончается именем файла** (`…/download/{run}/catalog-export-12.xlsx`).
  Нашлось кругом агентом: импорт по `…/download/12` не знал формата («csv, txt, xlsx») — формат
  берётся из имени в адресе. Для адреса поставщика без расширения у `catalog_import` есть
  `options.format`.
- **Категория, созданная импортом, на занятом слаге получает номер** (`gaskets-2`), а не ошибку.
  Нашлось прогоном alfatech: слаги категорий плоские, а названия в дереве повторяются
  («Прокладки та ущільнення» в нескольких ветках), и каждая строка второй ветки падала на `slug`.
  До двадцати номеров; отказ не про слаг — по-прежнему ошибка строки.
- **`catalog_import` без профиля и без сопоставления** берёт то, что предложила бы панель
  (`Importer::suggest()`): файл читается дважды — заголовок здесь, строки в очереди. Агенту так
  проще: файл, собранный по `catalog://exchange`, сопоставляется сам.
- **`catalog_export` — читающий инструмент** (область `catalog:read`, любое из трёх прав, без
  `dry_run`): каталог он не меняет, а право на просмотр и в панели экспортирует.
- **Ответ инструмента — `{ run, errors_total, errors }`**, первые 50 ошибок, как обещано; у импорта и
  экспорта ответ тот же, что у `catalog_exchange_run`.

Открыто:

- **Экспорт без выбранных колонок пишет только язык по умолчанию.** Переводы (`name@en`) уходят
  в файл, только если их назвали; круг от этого ничего не теряет, но «выгрузить всё» на
  многоязычном сайте — не всё. Решать, когда попросит живой магазин.
- **Замер — на SQLite рабочей машины.** На хомлабе (MySQL в Docker) прогон alfatech не повторяли:
  его база — демо, и 93 тысячи чужих товаров там ни к чему. Если панель магазина на MySQL покажет
  больше 20 мс на строку — первым смотреть индексы `routes` и журнала, потом уже кеш (§4.4).
- **Задача в 60 секунд даёт ~7 000 строк** — очередь с `retry_after` меньше `job_seconds`
  (по умолчанию 90 у `database`) уложится, но сайт с коротким `retry_after` получит повтор
  задачи посреди пачки. Повтор безопасен (E1), но лишний; сказать об этом в гайде, если всплывёт.
