# Документация для агентов — `AGENTS.md` в пакетах и на сайте

Сайт на скелете WebX UI должен быть понятен агенту с первой минуты: человек без опыта открывает
сайт в Claude Code, Codex или Cursor и правит его, не изучая систему. Код модулей живёт в
`vendor/`, и агент, который его не знает, первым делом полезет туда — форкнет модуль или поправит
файл, который сотрёт следующий `composer update`. Эта спека описывает, как каждый пакет объясняет
себя агенту и как сайт собирает эти объяснения в один вход.

Две аудитории, два канала:

- **Агент по коду** (правит файлы сайта) — читает `AGENTS.md`. Это предмет этой спеки.
- **Агент по контенту** (работает через MCP) — читает правила дома из базы ресурсом MCP. Это
  этап AG3, §5.

## 1. Решения (не переоткрывать)

1. **`AGENTS.md` в каждом composer-пакете** `php/packages/*`, в корне пакета, рядом с
   `README.md`. Он едет в dist: `.gitattributes` пакетов исключают только `/tests` и сам
   `.gitattributes`, и тест покрытия следит, чтобы `AGENTS.md export-ignore` не появился.
2. **Корневой `AGENTS.md` сайта генерируется**: его пишет `webx:panel` (а значит и `webx:setup`,
   который зовёт `webx:panel --sync`) и обновляет каждый `webx:panel --sync`. Генератор владеет
   **одним блоком между маркерами** `<!-- webx:agents -->` … `<!-- /webx:agents -->` и
   переписывает его целиком; всё вне маркеров — **блок проекта**, его генератор не читает и не
   трогает. Так же устроен `resources/js/admin.ts` с его регионами.
3. **`CLAUDE.md` сайта — одна строка `@AGENTS.md`.** Пишется, только если файла нет. Свой
   `CLAUDE.md` без этой строки не трогаем — команда говорит, какую строку добавить.
4. **Ссылки — в `vendor/webx-ui/<пакет>/AGENTS.md`**, а не на GitHub: агент читает текст той
   версии, что установлена, а не той, что сегодня в `main`.
5. **Первое правило корня — не форкать модуль и не править `vendor/`.** Расширять конфигом,
   публикацией видов, патчем экрана, своей регистрацией или заменой сервиса — в этом порядке.
   Не хватает шва — сказать об этом и предложить его в репозиторий, а не обходить.
6. **Тексты `AGENTS.md` — английские**, как README пакетов и все тексты кода. Спека — русская.
7. **Охват проверяет тест**, а не память: пакет без `AGENTS.md` или с файлом не по формату —
   красный CI (с AG2).

## 2. Формат пакетного `AGENTS.md`

Не пересказ README, а то, что нужно агенту, чтобы **изменить сайт, не трогая пакет**. README
отвечает «что умеет пакет и его PHP-API», `AGENTS.md` — «что пакет держит и где разрешено
менять».

```
# webx-ui/<пакет>                     ← первая строка, ровно имя пакета

<абзац: что это, из чего собрано, к каким соседям идти с вопросами о них>

## What it owns                        ← таблицы, тип адреса, виды, экраны и id их узлов,
                                         API, права, MCP-инструменты и scopes, что регистрирует
## Change it without forking           ← таблица «хочешь → делай»: ключи конфига и env,
                                         теги vendor:publish, патч экрана, реестры, сервисы
## Do not                              ← запреты с причиной: что ломается и что вместо
## Check your work                     ← команды и признаки, что получилось (doctor, MCP dry_run)
## Read more                           ← README.md рядом; гайд и спека — полными URL
```

Правила:

- **Пять разделов `##`, ровно эти и в этом порядке.** Подразделы `###` — по нужде.
- **Не длиннее 150 строк.** Длинное — в README или гайд, ссылкой из «Read more».
- **Без относительных ссылок наружу** (`](../…)`): в `vendor/` соседей по монорепе нет. Файл
  рядом (`README.md`) — можно, остальное — полным URL.
- **Только проверенное.** Каждое имя — ключ конфига, тег, `id` узла, инструмент — должно
  существовать в коде пакета. Сомнительное лучше не писать, чем написать неправду.
- **Запрет — с альтернативой**: не «не трогай X», а «не X, потому что Y; вместо этого Z».

Пилот — `php/packages/module-pages/AGENTS.md`.

## 3. Корневой `AGENTS.md` сайта

```
<!-- webx:agents -->
<!-- Written by `php artisan webx:panel --sync`; … replaced on the next run. -->
# This site                  ← что за сайт, где панель (config('webx-admin.path'))
## The first rule            ← не форкать, не править vendor; порядок способов расширения
## Installed packages        ← - [webx-ui/x](vendor/webx-ui/x/AGENTS.md) — description из composer
                               «Without a guide yet …» — установленные webx-ui/* без AGENTS.md
## After changing packages   ← composer update "webx-ui/*" -W, webx:panel --sync, npm build, migrate, doctor
<!-- /webx:agents -->

## This project              ← блок проекта: заготовка-комментарий, дальше — только руками
```

Поведение генератора:

| Что лежит в корне сайта            | Что делает `webx:panel`                                        |
| ---------------------------------- | -------------------------------------------------------------- |
| `AGENTS.md` нет                    | пишет блок и заготовку блока проекта                           |
| есть, с маркерами                  | заменяет текст между маркерами, остальное байт в байт как было |
| есть, без маркеров (писали руками) | ставит блок **сверху**, весь текст файла остаётся под ним      |
| блок уже такой же                  | ничего не пишет, «already lists what is installed»             |
| `CLAUDE.md` нет                    | пишет `@AGENTS.md`                                             |
| `CLAUDE.md` есть без `@AGENTS.md`  | не трогает, предупреждает строкой                              |

Список пакетов — из `vendor/composer/installed.json` (как и реестр панели): все `webx-ui/*`,
по алфавиту; «документирован» — значит в установленной копии есть файл `AGENTS.md`. Повторный
прогон без изменений в `vendor` не меняет ни байта.

## 4. Покрытие

Тест `AgentDocsCoverageTest` в `module-admin` (только в монорепе — в зеркале пакета соседей нет,
там он пропускается):

1. **Обязательные пакеты имеют `AGENTS.md`.** Обязателен каждый пакет, кроме списка
   `PENDING`; в AG1 там все, кроме `module-pages`, и тест печатает, у кого файла ещё нет. AG2
   опустошает `PENDING` — и обязательны все. Новый пакет в `php/packages` обязателен сразу.
2. **Каждый существующий `AGENTS.md` — по формату §2**: первая строка `# webx-ui/<пакет>`, пять
   разделов по порядку, ≤ 150 строк, без `](../`.
3. **Ни один `.gitattributes` не исключает `AGENTS.md`** из dist.

## 5. Правила контента сайта и граница с AG4

Агент по контенту пишет статьи, карточки и блоки через MCP и `AGENTS.md` не видит. Что ему
нужно знать о сайте — на каких языках писать, каким голосом, чего нельзя, — сайт отдаёт ему
сам, из базы.

1. **Что входит в правила.**
   - **Языки и основной язык** — не хранятся в правилах, а берутся из `webx-ui/localization`
     (`Locales::all()`, `Locales::default()`): список языков сайта уже есть, второй копии,
     которая разойдётся с первой, не заводим.
   - **Тон** (`content.tone`) — каким голосом пишет сайт: кому, на «ты» или на «вы», как
     длинно, чего держаться.
   - **Чего нельзя** (`content.donts`) — по запрету на строку: слова и обещания, которых сайт
     не говорит, темы, которых не касается.
   - **Заметки для агента** (`content.notes`) — всё остальное свободным текстом: термины,
     написание названий, как подписывать картинки.

   Правила одни на все языки (поля не `localized`): агент пишет на каждом языке по тем же
   правилам, а переводить запреты редактору незачем.

2. **Где живут.** В той же таблице `cms_settings`, ключами `content.*`: это вкладка `content`
   экрана `settings.index` в `module-settings` — узлы `content`, `content-card`, `tone`,
   `donts`, `notes`. Своей таблицы нет: значения, кэш, проверка, событие `SettingsSaved`,
   `settings_get` / `settings_set` и патч экрана достаются даром. Сайт добавляет своё правило
   патчем узла `content-card` с ключом `content.<имя>` — оно попадает в ресурс само (п. 4).
3. **Кто правит.** Человек — в панели, «Настройки» → вкладка «Контент», с правами раздела:
   `settings.view` видит, `settings.manage` сохраняет. Агент — `settings_set` со scope
   `settings:write`, как любую настройку. Нового права нет.
4. **Как доходят до агента.** Ресурс MCP **`settings://content-rules`** (имя — по правилу
   `<модуль>://<что>`, как `blocks://guidelines`, `audit://checks`), JSON:
   `languages` (`code`, `name`, `native_name`, `primary`), `primary` — код основного языка,
   `tone`, `donts` (список строк), `notes`, `more` — остальные ключи `content.*` из патчей
   (`key`, `label`, `value`), `empty` — правда, если ни одно правило не заполнено. Ресурсы MCP
   не закрыты scope'ами, как и у остальных модулей: правила не секрет, секретам в настройках не
   место (`AGENTS.md` модуля это запрещает).
5. **`instructions` сервера.** `WebxServer` дописывает строку «перед тем как писать контент,
   прочитай `settings://content-rules`», **когда ресурс есть в реестре**, то есть когда
   установлен `module-settings`, — и тогда всегда, даже если правила пусты: языки в ресурсе
   есть всегда, а `instructions` читаются один раз при подключении и о базе знать не должны.
   Без `module-settings` строки нет — она указывала бы в пустоту.
6. **Не в корневом `AGENTS.md`.** Агент по коду правила контента не применяет; ресурс и ключи
   называет `AGENTS.md` модулей `module-settings` и `mcp`.

Путь человека без опыта — Docker с нуля и «где живут стили и что безопасно менять» — AG4;
корневой блок тогда получит ссылку на этот гайд.

| AG1  | эта спека, пилот `module-pages`, генератор корня в `webx:panel`, тест покрытия |

## 7. Как легло в код

### AG1 (04.10.2026)

- `WebxUi\Admin\Agents\AgentDocs` читает `installed.json` (путь — `PackageRegistry::locate()`,
  теперь публичный) и отдаёт список `AgentDoc` (`name`, `description`, `documented`, `link()`).
  Наличие файла проверяется по `install-path`, а ссылка всегда `vendor/<имя>/AGENTS.md` — так
  она одинакова для path-репозитория и Packagist.
- `WebxUi\Admin\Agents\RootFile` — чистая работа с текстом: `block()` собирает блок,
  `with()` вставляет его в файл по правилам §3, `PROJECT` — заготовка блока проекта.
- `PanelCommand::syncAgentGuide()` — последний шаг `webx:panel` (с `--sync` и без); `webx:setup`
  получает его через свой вызов `webx:panel --sync`, отдельного кода в setup нет.
- Тесты: `AgentGuideTest` (фикстура `tests/Fixtures/agents` — свой маленький `vendor`),
  `AgentDocsCoverageTest`. `PanelCommandTest` и `PanelSyncTest` убирают за собой `AGENTS.md` и
  `CLAUDE.md` из корня Testbench.
- Пилот `php/packages/module-pages/AGENTS.md`, гайд — раздел «Agent guide» в
  `apps/docs/guide/new-site.md`.

### AG2 (04.10.2026)

- `AGENTS.md` во всех 32 composer-пакетах `php/packages`; `PENDING` в `AgentDocsCoverageTest`
  пуст — пакет без гайда или не по формату §2 теперь красный CI, новый пакет обязателен сразу.
- Гайд `module-admin` шире остальных: оболочка панели, реестр модулей, экраны и патчи,
  черновики/версии/журнал, команды `webx:setup` / `webx:panel` / `webx:doctor` и блок корневого
  `AGENTS.md`. Пакеты без своих экранов (`localization`, `routing`, `nested-set`, `mcp`) узлы
  не перечисляют.
- Имена MCP-инструментов в гайдах — как их видит агент (`<модуль>_<инструмент>`), хотя в коде
  пакета инструмент зарегистрирован без префикса; scopes — по правилу `BoundTool`
  (`<id модуля>:read|write`). Общие инструменты категорий (`*_categories_*`, `catalog_brands_*`,
  `tariff_groups_*`) приходят из `module-admin`, гайд пакета их называет.
- Сверка имён — скриптом по всем `` `...` `` гайда против кода пакета; в репозиторий он не лёг,
  формат и охват держит тест.

### AG3 (04.10.2026)

- Вкладка `content` экрана `settings.index` (`resources/screens/index.json` в `module-settings`):
  три `wx-textarea` по 4000 знаков, не `localized`. Строки — во всех десяти языках модуля, демо
  (`resources/demo/settings.json`) заполняет все три правила.
- `WebxUi\Settings\ContentRules` собирает ресурс: языки — `Locales::all()` / `defaultCode()`,
  `donts` — поле, разрезанное по строкам без пустых, `more` — остальные `content.*` из патчей с
  их подписью. `SettingsModule::mcpResources()` отдаёт `ContentRules::resource()`; обработчик
  берёт сервис из контейнера при чтении, а не при сборке модуля: модуль создаётся на загрузке
  сайта, и синглтон `Settings`, взятый тогда, держал бы настоящий диспетчер событий мимо
  `Event::fake` (на этом упал тест `SettingsSaved`).
- Адрес — `WebxServer::CONTENT_RULES` в `mcp`; `ContentRules::URI` ссылается на него, так что
  строка в `instructions` и ресурс не разойдутся. `WebxServer::boot()` дописывает строку, если
  ресурс с этим адресом есть в реестре, и не дважды при повторном `start()`.
- Тесты: `ContentRulesTest` в `module-settings` (пустые правила с языками, запись через
  `settings_set`, патч в `more`, 403 без `settings.manage`, строка в `instructions`),
  `WebxServerTest` в `mcp` (без ресурса строки нет, с ним — одна).
- Гайды: раздел «Content rules» в `apps/docs/guide/settings.md`, «The site's house rules» в
  `apps/docs/guide/agents.md`; `AGENTS.md` у `module-settings` и `mcp`.
