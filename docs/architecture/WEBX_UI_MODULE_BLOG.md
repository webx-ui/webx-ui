# `webx-ui/module-blog` — спецификация и план реализации

Статус: спроектирован 18.09.2026, не начинался. Пакеты — `webx-ui/module-blog` (composer) и
`@webx-ui/module-blog` (npm).

Блог: статьи, рубрики, теги. Содержимое статьи — блоки конструктора (`webx-ui/module-blocks`),
адреса — реестр (`webx-ui/routing`), SEO — `webx-ui/module-seo`, обложки — `webx-ui/module-media`,
черновик и история — `webx-ui/module-admin`, языки — `webx-ui/localization`.

Своего у модуля мало, как и у `module-pages`, и по той же причине: почти всё уже написано.
Отличий от страниц три, и они определяют всю спеку — у статьи есть **дата** (в том числе будущая),
у неё **несколько рубрик**, и у неё есть **теги**, которых заводят сотнями и потом разгребают.

Прототипы экранов (семь артбордов, цвета из `tokens.css`):
<https://claude.ai/artifact/8jjNnJJfdriTYdFddvmsCp>.

## 1. Границы

**Внутри:** статьи, рубрики, теги; адреса всех трёх; лента, страницы рубрики и тега с пагинацией;
черновик, публикация (в том числе отложенная), история; обложка, анонс, автор, закрепление;
похожие статьи; RSS; экраны панели; API; MCP.

**Снаружи:** комментарии, лайки, счётчик просмотров, подписка и рассылка, серии статей,
соавторы, авторы-не-администраторы, карта сайта (принадлежит `module-seo`), права
(отдельная задача, как у `module-pages`).

## 2. Принятые решения (не переоткрывать)

1. **Один пакет.** Рубрики и теги — не библиотека таксономии: без панели им нечего показывать, а
   каталог получит свой `category` со своим смыслом (фильтры, хвост адреса), и общего кода там
   меньше, чем стыков.
2. **Адрес статьи — `{prefix}/{slug}`**, приставка из конфига (`webx-blog.prefix`, по умолчанию
   `blog`). Пустая приставка означает корень сайта. Рубрика — `{prefix}/{rubric-slug}` в том же
   плоском пространстве, тег — `{prefix}/tag/{tag-slug}`.
3. **Политика столкновений — `Fail`** у всех трёх типов. Адрес статьи выбирают осознанно; молча
   переехать на `-2` он не должен. Столкновение со страницей — ошибка валидации в форме с именем
   того, кто занял адрес.
4. **Рубрики плоские, у статьи их может быть несколько.** Дерево рубрик заполняется на один
   уровень из трёх, а кросс-темы и так закрывают теги.
5. **Рубрика в адрес статьи не входит** — это прямое следствие пункта 4: «какая из трёх» не имеет
   ответа, а любой ответ был бы скрытой главной рубрикой, меняющей адрес при смене порядка
   галочек.
6. **Главная рубрика — первая в списке**, порядок задаётся перетаскиванием (`position` в pivot).
   Она идёт в крошки, в ссылку «ещё в рубрике» и в `<category>` RSS. Отдельного переключателя нет:
   один контрол вместо двух.
7. **Дата публикации и состояние публикации — один столбец** (`published_at` из `HasDraft`).
   Дата в будущем = запланирована, дата в прошлом двигает статью в ленте. Шедулер не нужен:
   публикация проверяется на чтении (§7).
8. **Теги заводятся из формы статьи**, но имеют свой экран: переименование, слияние, удаление,
   `noindex`. Без слияния через полгода в базе «ремни», «ремень» и «приводные ремни».
9. **Страницы тегов по умолчанию `noindex`**, переключается на теге. Совсем без адресов их
   оставлять неправильно — по тегам ходят люди; но в индекс такую выдачу пускать не надо.
10. **Правило SEO на адрес тега открывает его индексу.** Если в `module-seo` для адреса тега
    заведено активное правило (`seo_urls`), страница индексируется и печатает всё, что в правиле
    написано, — сам факт правила и есть решение «эта страница нужна». Флаг тега при этом не
    трогается: открыть тег можно двумя способами, и оба видны в панели.
11. **Лента — маршрут модуля**, а не сущность: `{prefix}` с пагинацией `?page=2`. Реестр закроет
    этот адрес для страниц сам, потому что `Reserved` опрашивает роутер. При пустой приставке
    маршрут ленты не регистрируется вовсе — список выводит сайт на своей странице.
12. **Пагинация в query, не в пути.** Иначе страница списка — это двести строк в реестре вместо
    одной, и `?page=` всё равно нужен резолверу, который query отбрасывает.
13. **Похожие статьи считаются**, вручную прибивается несколько штук. Полностью ручной список
    после сотой статьи никто не заполняет.
14. **Автор — администратор** (`module-auth`), не своя сущность. Гостевые авторы — это справочник
    людей, и он не про блог.
15. **Тело статьи — блоки.** Прозу держит блок «Текст» на типе поля `wx-rich-text`, который
    приезжает в `module-admin` до этого модуля (§17, этап 1). Двух механизмов содержимого в одной
    панели не будет.
16. **Экран формы описанный** (`blog.article-form`), списки — компоненты пакета: узла-таблицы в
    схеме экранов нет, и придумывать его здесь не место.
17. **Правки защищены ревизией**, как у страниц: панель шлёт то, какой она прочитала статью,
    сервер отбивает устаревший `PUT` кодом 409.

## 3. Схема

Своих колонок мало — остальное привозят макросы соседей.

### `articles`

```
id            bigint
title         json nullable      -- переводимый
slug          json nullable      -- переводимый
lead          json nullable      -- анонс, текст без разметки, переводимый
cover_id      bigint nullable    -- FK media files, nullOnDelete
author_id     bigint nullable    -- FK admins, nullOnDelete
pinned        bool default false
blocks()                         -- module-blocks
draft()                          -- module-admin: json draft + timestamp published_at
softDeletes
timestamps

index (published_at)
index (pinned)
```

Уникального индекса на слаг тут нет: уникальность адреса живёт в `routes (locale, path)` и знает
про страницы тоже. Вторая копия правила — копия, которая разъедется.

### `rubrics`

```
id            bigint
title         json nullable      -- переводимый
slug          json nullable      -- переводимый
lead          json nullable      -- вступление над списком, переводимый
cover_id      bigint nullable
is_visible    bool default true
position      int default 0
softDeletes
timestamps
```

Черновика и версий у рубрики нет — есть `is_visible`. Скрытая рубрика пропадает из меню и отвечает
404, её статьи остаются доступными по своим адресам: они не её собственность.

### `tags`

```
id            bigint
title         json nullable      -- переводимый
slug          json nullable      -- переводимый
noindex       bool default true  -- дефолт из конфига webx-blog.tags.noindex
timestamps
```

### Связи

```
article_rubric   article_id · rubric_id · position     unique(article_id,rubric_id), index(rubric_id)
article_tag      article_id · tag_id                   unique(article_id,tag_id),    index(tag_id)
article_related  article_id · related_id · position    unique(article_id,related_id)
```

Внешние ключи каскадные по `article_id`: мягкое удаление строки pivot не трогает, а окончательное
уносит. `article_related.related_id` — тоже каскад: прибитая статья, удалённая совсем, исчезает из
списков, а не остаётся висеть.

## 4. Адреса

Три типа в реестре, все с `OnConflict::Fail`:

| Тип       | Форматтер                              | Пример            |
| --------- | -------------------------------------- | ----------------- |
| `article` | `Prefixed($prefix, Slug::class)`       | `blog/kak-vybrat` |
| `rubric`  | `Prefixed($prefix, Slug::class)`       | `blog/remont`     |
| `tag`     | `Prefixed("$prefix/tag", Slug::class)` | `blog/tag/remni`  |

Приставка читается из `webx-blog.prefix` в момент регистрации типов. Пустая — форматтер статьи и
рубрики вырождается в `Slug`, тега — в `Prefixed('tag', Slug)`.

Статья и рубрика делят одно плоское пространство, поэтому рубрика «Ремонт» и статья со слагом
`remont` — ошибка валидации при сохранении второго из них. Это правильно: два разных экрана по
одному адресу — не то, что редактор имел в виду.

**Смена приставки** — это `webx:routes:rebuild --type=article --type=rubric --type=tag`: пути
пересчитываются, старые остаются алиасами с 301. Технически одна команда; по выдаче — массовый
переезд, так что решение принимается один раз.

Обработчики (`RouteHandler`) — свои на каждый тип, по образцу `PageHandler`: имя вьюхи из конфига,
фолбэк на вьюху пакета, публикацию проверяет обработчик, а не реестр.

## 5. Лента, рубрика, тег

Три списка с одинаковым устройством: заголовок, вступление (у рубрики), карточки статей,
пагинация `?page=`.

- **Лента** — маршрут `{prefix}`, статьи по `published_at desc`, закреплённые впереди.
- **Рубрика** — статьи, у которых она в pivot; порядок тот же.
- **Тег** — то же; `noindex,follow`, пока у тега стоит флаг и на его адрес нет правила SEO (§12).
- **RSS** — `{prefix}/rss`, двадцать последних, `<category>` из главной рубрики.

Размер страницы — `webx-blog.per_page`, по умолчанию 12.

## 6. Рубрики и теги

**Удаление рубрики со статьями отказывается** (422 с числом статей и предложением перенести):
мягко удалённая рубрика с живыми статьями — это дыра в навигации, которую никто не заметит.
Пустая удаляется мягко.

**Порядок рубрик** (`position`) — это порядок в меню сайта и в фильтрах панели.

**Слияние тегов** — операция экрана тегов: выбранные теги переезжают в один, pivot дедуплицируется
(`unique(article_id,tag_id)` тут и есть гарантия), слитые удаляются. Галочка «поставить редиректы»
пишет строки в `seo_redirects`: алиасы `routing` умирают вместе с сущностью каскадом, так что
пережить удаление может только правило SEO. Операция необратима, и диалог говорит об этом прямо.

## 7. Дата, публикация, черновик

`HasDraft` уже привозит `published_at` и считает «опубликовано» как «не null». Статья
переопределяет это:

```php
public function isPublished(): bool
{
    $at = $this->published_at;

    return $at !== null && $at->lessThanOrEqualTo(now());
}

public function scopePublished(Builder $q): Builder
{
    return $q->whereNotNull('published_at')->where('published_at', '<=', now());
}
```

Отложенная публикация этим и исчерпывается: ни очереди, ни шедулера — проверка происходит там, где
статью читают. Обратная дата работает тем же полем.

**Ловушка, которую надо помнить:** для `module-admin` запланированная статья уже опубликована —
`published_at` не пуст. Любой общий счётчик или выборка «живых» посчитает её. Внутри модуля везде
ходить через `published()`; в тестах брать дату в будущем нарочно, иначе тест зелёный на любом коде.

`HasDraft::publish()` ставит `Carbon::now()` и пропускает `published_at` в `applyDraft()` — то
есть дату, выбранную редактором, через черновик не протащить. Поэтому в `module-admin` у
`publish()` появляется необязательный аргумент `?CarbonInterface $at = null` (этап 1 плана): это
одна строка и обратная совместимость, а альтернатива — второе сохранение сразу после публикации,
которое оставит в истории версию с чужой датой.

Версии — `HasVersions`, как у страниц: автосейв в кольцо, публикация пишет версию и чистит
автосейвы.

## 8. Похожие статьи

Ручной список (`article_related`, порядок перетаскиванием) плюс автоподбор: сначала статьи с
наибольшим числом общих тегов, потом по главной рубрике, всё — только опубликованные, минус сама
статья и минус уже прибитые. Число — `webx-blog.related`, по умолчанию 3.

## 9. Языки

`title`, `slug`, `lead` статьи; `title`, `slug`, `lead` рубрики; `title`, `slug` тега —
переводимые (`webx-ui/localization`). Адрес свой на каждый язык: в `routes` для этого есть
`locale`, а `EntitySlug::read` уже умеет читать переводимый слаг. Статья без слага в языке просто
не имеет в нём адреса.

Слова интерфейса — английские в коде, переводы в `lang/*` на те же десять языков, что у соседей.
Компоненты ядра переводит тот, кто их открывает (диалоги `WxImageEditor`, `WxFileCard`).

## 10. Экраны панели

Группа меню «Blog»: **Articles · Rubrics · Tags**. Теги отдельным пунктом, а не вкладкой рубрик:
рубрики правят раз в квартал, теги разгребают после каждого всплеска писанины.

### Список статей

Таблица `layout="fixed"` с шириной на каждой колонке, кроме заголовка: обложка (44×32), заголовок
со слагом подписью, рубрики чипами, автор, дата (`WxDate`), статус, `WxRowMenu`. На телефоне —
карточки (`cards-below`), 96 px на карточку.

Статусы: черновик · запланирована (с датой) · живая · живая с правками · снята. Фильтры: рубрика,
тег, автор, статус, поиск по заголовку. Закреплённые — со значком, всегда сверху.

### Редактор статьи

Вкладки, как у страницы и у блока: **Контент · Настройки · SEO · История**.

- **Контент** — конструктор блоков `module-blocks`, автосейв в черновик, предпросмотр по токену.
- **Настройки** — заголовок и адрес (с приставкой приставленной слева и подсказкой про редирект);
  рубрики списком с перетаскиванием, первая помечена «главная»; теги комбобоксом с числом статей у
  каждого и пунктом «создать»; анонс со счётчиком; дата и время публикации с подсказкой про
  будущее; автор; обложка; переключатель «закрепить»; похожие.
- **SEO** — карточка `wx-seo` из `module-seo`, приезжает патчем оттуда же, как у страниц.
- **История** — версии `HasVersions`.

Панель действий снизу: состояние («опубликована 12 сентября · есть неопубликованные правки»),
«Отменить правки», «Сохранить черновик», «Опубликовать».

### Рубрики

`WxListDetail`: слева список с перетаскиванием (название, адрес, число статей, значок скрытой),
справа форма — название, адрес, вступление, обложка, «показывать на сайте», ссылка на SEO,
удаление с объяснением, почему оно сейчас недоступно.

### Теги

Таблица с выделением: название (инлайн-переименование по Enter/Esc), адрес, число статей,
индексация (три состояния, §12), `···`. Фильтры «Без статей» и «Не индексируются» — второй
считает по тому же правилу, то есть тег с правилом SEO в него не попадает. Панель выделения снизу:
«Слить в один», «Индексировать», «Удалить». Диалог слияния — что с чем сливается, какой тег
остаётся, галочка редиректов, предупреждение о необратимости.

## 12. SEO

`HasSeo` на статье и на рубрике, тип поля `wx-seo` на вкладке — всё из `module-seo`, как у
страниц. Карточка SEO приезжает патчем от `module-seo`, а не от проекта.

Карта сайта — за `module-seo`, когда она там появится: блог только отдаёт свои канонические
адреса через контракт.

### Тег и правило SEO

Правило `seo_urls` на адрес тега открывает его индексу целиком (решение 10): печатается всё, что в
правиле написано, а `noindex` не добавляется, даже если флаг у тега стоит.

Сделать это мержем источников нельзя, и это главное здесь. `UrlRuleSource` имеет приоритет 100 и
перебивает всё, но `SeoData::mergeOver()` работает по полям: правило, в котором заполнены
`title` и `description`, а `robots` пуст, оставит `robots` нижнего источника — то есть наш
`noindex`. Редактор при этом видит заполненное правило и ждёт, что страница в индексе. Поэтому
решает **факт совпадения правила**, а не его содержимое:

- блог регистрирует свой `TagSource` с приоритетом ниже `EntitySource` (40);
- источник возвращает `robots: 'noindex,follow'` только когда у тега стоит флаг **и**
  `module-seo` отвечает, что активного правила на этот адрес нет;
- для этого вопроса в `module-seo` появляется контракт — `hasRuleFor(string $url): bool` у
  `Panel\UrlRuleSource` поверх того же скомпилированного кеша, которым пользуется
  `Panel\UrlMatcher`. Своего матчинга блог не пишет: две реализации масок разъедутся первой же
  звёздочкой (`*` против `**`), и разойдутся они молча.

Тот же ответ отдаётся в панель, поэтому колонка «Индексация» на экране тегов различает три
состояния: `индексируется`, `индексируется — правило SEO`, `noindex`. Иначе редактор, написавший
правило, будет смотреть на строку с `noindex` и не понимать, кто прав.

## 13. MCP

Через те же двери, что и панель (валидация, ревизия, события):

- `articles_list`, `articles_get`, `articles_create`, `articles_update`, `articles_publish`,
  `articles_unpublish`, `articles_delete`;
- `rubrics_list`, `tags_list`, `tags_merge`;
- ресурс `blog://feed` — последние статьи с адресами;
- промпт `write_article` — черновик по теме с рубрикой и тегами.

Содержимое блоками правит `blocks_edit_content` (§18.1 `WEBX_UI_MODULE_BLOCKS.md`), своего
инструмента для тела статьи не заводим.

## 14. Права

Как у `module-pages`: объявляются модулем, отдельной задачей не занимаемся. Заготовка —
`blog.articles.view`, `blog.articles.manage`, `blog.taxonomy.manage`.

## 15. Тесты

Что действительно ловит ошибки:

- адрес пишется и переписывается, старый остаётся алиасом с 301; столкновение со страницей —
  422 на слаге;
- **запланированная статья**: 404 на своём адресе, нет в ленте, появляется после сдвига времени;
  дата в прошлом двигает порядок ленты;
- слияние тегов: pivot без дублей, статьи не потеряны, редиректы созданы, слитые удалены;
- **тег с правилом SEO**: страница печатает `title` и `description` правила и **не** печатает
  `noindex`, хотя флаг у тега стоит; правило без `robots` — тот же результат (это и есть та
  ошибка, которую мерж полей не ловит); правило выключили — `noindex` вернулся;
- удаление рубрики со статьями — 422; пустой — мягкое удаление;
- порядок рубрик у статьи: первая — главная, в крошках и RSS она же;
- переводимый слаг: свой адрес в каждом языке, отсутствие слага = отсутствие адреса;
- ревизия: устаревший `PUT` — 409;
- лента и пагинация, RSS валиден;
- экранные тесты панели — на `mousedown` по вкладкам, не на `click`;
- `scripts/php-smoke.sh` против настоящей СУБД: миграции, дефолты в колонках, панель после
  `config:cache`.

## 16. Демо

После выпуска — оба сайта: `webx-cms.local` (пакеты из чекаута) и `webx-cms.alexx.group`
(реестр, пуш в Gitea). Наполнить десятком настоящих статей с обложками, тремя-четырьмя рубриками и
десятком тегов, включая пару дублей — иначе слияние проверить не на чем.

## 18. Отложено

- Комментарии — отдельный модуль размером с `module-inbox` (модерация, спам, уведомления).
- Подписка и рассылка — нужен работающий шедулер и отправка, которых у нас нет.
- Счётчик просмотров — запись на каждый GET, и разговор про кеш.
- Серии статей, соавторы, авторы-не-администраторы.
- Дерево рубрик — если когда-нибудь окажется нужным, `nested-set` и `TreePath` уже лежат.
- Перевод адреса тега в `slug-id`, если редакторы начнут воевать за слаги:
  `webx:routes:rebuild --type=article` переводит блог за минуту.
