# `webx-ui/module-audit` — аудит сайта

Раздел панели «Аудит»: обход собственного сайта и набор проверок, который сеошник, верстальщик и
админ делают руками на каждом новом проекте. Зеркала, индексные файлы, слэши, 404, robots, карта
сайта, title и H1, битые ссылки, заголовки безопасности, конфиг продакшена. Пара к нему —
`@webx-ui/module-audit`. Реестр пакетов — [`WEBX_UI_COMPOSER_PACKAGES.md`](WEBX_UI_COMPOSER_PACKAGES.md).

Статус: спецификация написана 01.10.2026; A1–A5 сделаны 02.10.2026 (§14). Порядок — CLAUDE.md §6.

## 1. Границы

- **Свои проверки, без внешних сервисов.** Всё, что можно узнать запросом к своему сайту, из его
  базы или конфига. Внешние сервисы — потом и спутниками (§13), первый — DataForSEO.
- **Максимум информации, а не только ошибки.** Обход сохраняет снимок каждой страницы (§4) — по
  нему в панели строится любая выборка, как в Screaming Frog. Находки — вид поверх снимка.
- **Отдельный модуль, а не часть `module-seo`.** По правилу имён (CLAUDE.md §1) это раздел панели,
  а большинству проверок SEO-модуль не нужен: зеркала, слэши, битые ссылки, H1 — это факты
  HTTP-ответа и HTML. SEO, каталог и другие модули приносят свои проверки и исправления через
  контракт (§6, §7) — так же, как спутники каталога.
- **Не делаем:** Core Web Vitals и Lighthouse (нужен headless Chrome на сервере), рендер JS,
  позиции в выдаче, внешние ссылки на сайт. Это работа внешних сервисов.

## 2. Решения (не переоткрывать)

1. **Свой краулер** на HTTP-клиенте Laravel (пул Guzzle) и `DOMDocument` + `DOMXPath`. Без
   `spatie/crawler`: у нас уже есть карта и реестр адресов, а лишняя зависимость в каждом сайте
   не нужна.
2. **Префикс таблиц — `audit_*`**, идентификатор модуля — `audit`, права — `audit.view`,
   `audit.run`, `audit.manage`, MCP-скоупы `audit:read` / `audit:write`.
3. **Проверка — класс за контрактом `AuditCheck`**, реестр `AuditChecks` — синглтон; модули
   регистрируют свои проверки из провайдеров. Исправление — отдельный контракт `AuditFix` (§6).
4. **Находка не чинит сама.** Исправление — только явной кнопкой (или MCP с `dry_run`), и делает
   его модуль, которому принадлежит то, что меняется: нормализацию адресов — `module-seo`,
   алиасы — `routing`.
5. **Прогон — задача в очереди, порциями.** Одна задача обходит пачку адресов и ставит в очередь
   следующую — ни один хостинг не любит задачу на 20 минут. Прогресс — в `audit_runs`, панель его
   опрашивает. С драйвером `sync` прогон из панели не запускается — предупреждение и команда
   `php artisan webx:audit:run` для крона.
6. **Сайт стучится сам к себе, но по публичному имени.** Запрос идёт на `APP_URL` с настоящим
   `Host` и SNI, а соединение — на адрес из настройки «подключаться к» (`CURLOPT_RESOLVE`, по
   умолчанию — как резолвит DNS). Так аудит работает в Docker и за NAT без hairpin, а проверяет
   ровно то, что видит посетитель.
7. **Вежливость по умолчанию:** 2 параллельных запроса, лимит 1000 страниц, свой `User-Agent`
   (`WebxAudit/1.0`). robots.txt по умолчанию **не** соблюдается — это свой сайт, — но всё, что
   им закрыто, помечается на странице.
8. **История — через отпечаток.** У находки `fingerprint` = проверка + адрес + ключ деталей;
   сравнение с прошлым прогоном даёт «новая / висит / исправлена» без хранения состояний.
   Снимки страниц держим за последние N прогонов (настройка, по умолчанию 5), находки — дольше.
9. **Скрыть можно, удалить — нет.** Осознанное (`noindex` на странице поиска, длинный title у
   лендинга) скрывается правилом `audit_ignores`: проверка + маска адреса + причина + кто скрыл.
10. **Пороги — настройками**, с дефолтами из §5. Длина title и description — в символах, с
    подсказкой про пиксели в объяснении проверки.
11. **Все слова — ключами словаря** модуля, как у остальных разделов; у каждой проверки — три
    текста: что найдено, почему это важно, как исправить.
12. **Каждый абсолютный адрес классифицируется по хосту** — не только ссылки, а всё, что ведёт
    наружу: `href`, `src`, `srcset`, `url()` в инлайн-стилях, `action` форм, `og:image`,
    canonical, hreflang, JSON-LD, `<loc>` карты. Классы: свой, свой через другое зеркало,
    **стенд разработки**, внешний (§5.6). Повод — живой случай 01.10.2026: клиент наполнил сайт
    на dev-стенде абсолютными адресами, после выкладки ссылки и картинки вели на dev, заметили
    случайно.
13. **Контент проверяется и в базе, а не только обходом.** Обход видит опубликованное, а ссылки на
    стенд лежат и в черновиках, скрытых записях, полях, которые шаблон не выводит. Модули отдают
    свои текстовые поля контрактом `AuditContentSource` (§6), поиск адресов в них — общий.

## 3. Прогон

Охват выбирается при запуске: **полный**, **только быстрые** (пробы + конфиг + база, секунды),
**по списку адресов** (после правки — перепроверить пять страниц).

Этапы полного прогона:

1. **Конфиг** — читает `config()` и окружение, без запросов.
2. **Пробы** — несколько десятков запросов к хосту: зеркала, схема, индексные файлы, слэши,
   регистр, случайный адрес, robots.txt, sitemap.xml, TLS.
3. **Затравка** — главная, все адреса из `sitemap.xml` (с индексом), канонические строки реестра
   `routing`. Источник у страницы запоминается: так находятся сироты и адреса мимо карты.
4. **Обход** — в ширину от затравки, только свой хост, глубина считается от главной. Редиректы
   не следуют автоматически: каждый шаг цепочки — своя запись.
5. **Внешние ресурсы** — внешние ссылки и картинки проверяются `HEAD` (откат на `GET`), с кешем на
   прогон и отдельным лимитом.
6. **База** — проверки модулей, которым не нужен обход, и поиск адресов в контенте всех записей,
   включая черновики (§2 п. 13). Этот этап входит и в «только быстрые».
7. **Разбор** — проверки по снимку: дубли, сироты, глубина, взаимность hreflang. Отпечатки,
   сравнение с прошлым прогоном, счётчики.

## 4. Схема

### `audit_runs`

`status` (`queued | running | done | failed | cancelled`), `scope`, `base_url`, `resolve_to`,
`pages_limit`, `pages_crawled`, `progress` (этап и счётчики), `counts` json (по важности и
группам), `started_by` (администратор, `schedule`, `mcp`), `started_at`, `finished_at`, `error`.

### `audit_pages` — снимок страницы

| Группа   | Поля                                                                                                                   |
| -------- | ---------------------------------------------------------------------------------------------------------------------- |
| Адрес    | `url`, `url_hash`, `final_status`, `redirect_to`, `depth`, `source` (`home`, `sitemap`, `registry`, `link`, `probe`)   |
| Ответ    | `status`, `content_type`, `bytes`, `ttfb_ms`, `total_ms`, `compression`, `headers` json (выборка), `blocked_by_robots` |
| Разметка | `title`, `description`, `h1` json, `headings` json (счёт по уровням), `canonical`, `robots_meta`, `x_robots_tag`       |
| Языки    | `lang`, `hreflang` json                                                                                                |
| Соцсети  | `og` json, `twitter` json                                                                                              |
| Данные   | `json_ld` json (типы и ошибки разбора)                                                                                 |
| Текст    | `word_count`, `text_hash`                                                                                              |
| Связи    | `links_in`, `links_out_internal`, `links_out_external`, `images`, `images_without_alt`, `in_sitemap`, `in_registry`    |

### `audit_links`

`run_id`, `from_page_id`, `to_url`, `to_page_id` (null для внешних), `kind` (`a`, `img`,
`srcset`, `script`, `link`, `iframe`, `form`, `style`, `meta`, `json_ld`), `anchor`, `rel`,
`target`, `host`, `host_class` (`own | own_mirror | dev | external`), `status` (для внешних —
после проверки).

### `audit_content_urls` — адреса, найденные в базе

`run_id`, `source` (модуль и тип записи), `record_id`, `record_label`, `field`, `locale`,
`url`, `host`, `host_class`, `published` (видна ли запись на сайте), `edit_url` (куда вести из
панели).

### `audit_issues`

`run_id`, `check`, `severity` (`error | warning | notice`), `page_id` (null для проверок хоста
и базы), `url`, `details` json, `fingerprint`, `state` (`new | persisting`), `ignored_by` (id
правила скрытия). Исправленные — вычисляются из прошлого прогона, отдельно не хранятся.

**`details` — данные для раскрытия, а не текст.** Строка-сводка (`summary`: «ещё 1 страница с
таким title», «5% текста при пороге 10% · 662 слова») и, если нужно, таблица (`table`:
`columns` + `rows`, у ячейки — тип `url | status | bool | text | missing`). Панель рисует
раскрытие по этой форме одним компонентом, своя вёрстка у проверки не нужна. Примеры:

- `hreflang.*` — матрица: язык, адрес, ответ, «ссылается назад», индексируется; недостающая
  строка (`x-default`) — ячейками `missing`, красным;
- `*.duplicate` — список «ещё N страниц» со ссылками на их карточки;
- `redirects.chain` — шаги цепочки с кодами;
- `hosts.dev_content` — запись, поле, язык, «Открыть в редакторе».

### `audit_ignores`

`check`, `pattern` (точный адрес или маска как в правилах SEO), `reason`, `created_by`.

## 5. Проверки

Важность: **E** — ошибка, **W** — предупреждение, **N** — к сведению. Пороги в скобках — дефолты
настроек.

### 5.1. Конфиг (`config.*`)

| Проверка              | Что                                                                       | Важность |
| --------------------- | ------------------------------------------------------------------------- | -------- |
| `config.debug`        | `APP_DEBUG=true` на рабочем домене                                        | E        |
| `config.env`          | `APP_ENV` не `production`                                                 | W        |
| `config.app_url`      | `APP_URL` не совпадает с хостом и схемой, с которых сайт реально отвечает | E        |

### 5.6. Исходящие адреса и чужие хосты (`hosts.*`)

**Стенд разработки** — хост из настройки «Другие адреса этого сайта» (dev, stage, старый домен)
плюс то, что стендом быть обязано: `localhost`, `127.0.0.0/8`, `::1`, частные сети
(`10/8`, `172.16/12`, `192.168/16`), зоны `.local`, `.localhost`, `.test`, `.example`,
`.invalid`, `.internal`, хосты с первым словом `dev`, `stage`, `staging`, `test`, `preview`,
`demo`. Хост из `APP_URL` стендом не считается никогда — иначе локальный прогон на
`shop.local` объявит ошибкой весь сайт.

| Проверка                  | Что                                                                                                | Важность |
| ------------------------- | -------------------------------------------------------------------------------------------------- | -------- |
| `hosts.dev_page`          | на странице ссылка или ресурс (картинка, скрипт, стиль, `og:image`, canonical…) на стенд           | E        |
| `hosts.dev_content`       | адрес стенда в базе — в том числе в черновике или скрытой записи (покажет, где и в каком поле)     | E        |
| `hosts.similar`           | хост похож на свой: то же первое слово в другой зоне (`shop.local` при `shop.com`) — глазами       | W        |
| `hosts.wrong_mirror`      | ссылка на свой сайт через `http` или другое зеркало — каждый клик через 301                        | W        |
| `hosts.absolute_own`      | абсолютная ссылка на свой хост — работает, но сломается при следующем переезде                     | N        |
| `hosts.new_domain`        | внешний домен, которого не было в прошлом прогоне — так видно и опечатки, и взлом со спам-ссылками | N        |
| `hosts.external_many`     | больше 100 внешних ссылок на странице                                                              | N        |
| `hosts.external_redirect` | внешняя ссылка отвечает редиректом — лучше сразу на конечный адрес                                 | N        |
| `hosts.blank_opener`      | `target=_blank` без `rel=noopener` на внешнюю ссылку                                               | N        |

Исправление `audit.replace-host`: заменить хост стенда на рабочий (или сделать ссылку
относительной) во всех найденных полях. Сначала предпросмотр — список записей, полей и число
замен, — потом замена **через модели модулей**, не SQL: журнал изменений `module-admin` пишет
каждую правку, и её можно откатить.

## 6. Контракты

```php
interface AuditCheck
{
    public function id(): string;            // 'title.duplicate'
    public function group(): string;         // 'page'
    public function needs(): array;          // ['config'] | ['probes'] | ['database'] | ['crawl']
    public function run(AuditContext $context): iterable; // of Finding
}

interface AuditFix
{
    public function id(): string;            // 'seo.normalise-host'
    public function fixes(): array;          // ids of checks it closes
    public function available(Finding $finding): bool;
    public function preview(Finding $finding): FixPreview; // what will change, for dry_run
    public function apply(Finding $finding): void;
}

interface AuditContentSource
{
    public function id(): string;            // 'pages', 'blog.posts', 'blocks'
    /** Every record, drafts and hidden ones included, chunked. */
    public function records(): iterable;     // of ContentRecord: id, label, published, edit_url
    /** Text-bearing fields: plain text, HTML, block JSON, URL fields; per locale. */
    public function fields(ContentRecord $record): iterable; // of ContentField
    /** Writes a field back through the model, so the history journal sees it. */
    public function replace(ContentRecord $record, ContentField $field, string $value): void;
}
```

`AuditContext` отдаёт снимок прогона (страницы, ссылки, пробы), HTTP-клиент с теми же
настройками и пороги. Проверки по `crawl` выполняются на этапе разбора по уже собранному
снимку — ни одна из них сама сайт не обходит.

Где исправить кнопкой нельзя (зеркало и схема на уровне веб-сервера — запрос на «чужой» хост до
Laravel не доходит), находка несёт готовый сниппет для nginx и Apache.

## 7. Что приносят другие модули

Регистрируют проверки и исправления, только если `module-audit` установлен (`suggest` в
composer.json, регистрация под `class_exists`).

- **`module-seo`:**
  - проверки по базе: сущности без `seo_meta` или с пустыми полями, дубли title между
    сущностями, правила SEO на адреса, которые отвечают 404, редиректы на отсутствующие адреса,
    цепочки в `seo_redirects` — до обхода, по таблице;
  - **middleware нормализации адреса** с настройками: главное зеркало, https, схлопывание
    слэшей, срез индексных файлов, политика конечного слэша, нижний регистр — всё одним 301 без
    цепочки. Исправления `seo.normalise-*` закрывают `host.*` из §5.2;
  - исправление `seo.collapse-chain` для `redirects.chain` (пункт «Схлопывание цепочек»
    `WEBX_UI_MODULE_SEO.md` §16);
  - исправление `seo.robots-sitemap` — дописать `Sitemap:` в `seo.robots-txt`.
- **`routing`:** алиасы, ведущие в никуда; канонические строки без живой сущности.
- **`module-media`:** картинки библиотеки без `alt`, файлы в базе без файла на диске, тяжёлые
  оригиналы, которые отдаются без превью.
- **`module-catalog`:** категории без описания, товары без картинки, опубликованные товары без
  цены.
- **`module-menu`:** пункты меню на 404 и на редиректы.
- **Каждый контентный модуль** (`module-pages`, `module-blocks`, `module-blog`,
  `module-services`, `module-catalog`, `module-menu`, `module-banners`, `module-settings`,
  `module-seo` — `canonical` и `og_image` правил, …) — `AuditContentSource` для своих полей. Без
  него поля модуля в базе не проверяются, и раздел «Источники» в обзоре это показывает: какие
  модули стоят, а источника не отдали.
- **`module-admin`, следом:** предупреждение прямо при сохранении — поле со ссылкой на стенд или
  абсолютной ссылкой на свой хост подсвечивается до того, как попадёт на сайт. Тот же
  классификатор хостов, вынесенный в общий код. Не часть аудита, но та же беда, пойманная раньше.

**Команда для выкладки:** `php artisan webx:audit:run --quick --fail-on=error` — быстрый прогон
(конфиг, пробы, база) с ненулевым кодом выхода при ошибках. Шаг деплоя после миграций: сайт со
ссылками на dev-стенд или с `APP_DEBUG=true` не выедет молча.

## 8. Панель

Раздел «Аудит» в группе «Система».

- **Обзор** — последний прогон: здоровье в процентах, счётчики по важности и группам, «новые /
  исправлены» относительно прошлого, прогресс текущего прогона, кнопка запуска с выбором охвата.
- **Находки** — таблица проверок, раскрытие — адреса. Фильтры: важность, группа, состояние
  (новая, висит, скрыта). У проверки — три текста из §2 п. 11, кнопка исправления с
  предпросмотром, «Скрыть» с причиной.
- **Страницы** — все обойдённые адреса со всеми полями снимка, выбор колонок, фильтры по любому
  полю, экспорт CSV.
- **Карточка страницы** — выезжает справа. Шапка: код ответа, адрес, title, «Перепроверить»
  (охват «по списку адресов» на одну страницу), «Экспорт» (снимок и находки страницы).
  Вкладки со счётчиками:
  - **Обзор** — ответ, заголовки, время, вес, разметка `<head>`, источник и глубина;
  - **Проблемы** — находки страницы, раскрытие по `details` (§4), метка NEW, «?» с тремя
    текстами;
  - **Входящие** и **Исходящие** — ссылки с анкором, `rel`, ответом и классом хоста;
  - **Картинки**, **CSS**, **JS** — ресурсы страницы из `audit_links`: размер, ответ, кэш,
    сжатие, `alt` у картинок;
  - **Микроразметка** — найденные блоки JSON-LD с ошибками и предупреждениями.

  Скриншота и замера скорости тут нет — нужен браузер, это спутники (§13).

- **Исходящие** — все хосты, на которые ссылается сайт, по классам (§5.6): число ссылок и
  страниц, ответы, `rel`, когда впервые замечен. Раскрытие хоста — страницы с анкорами и записи
  в базе с полями и ссылкой «Открыть в редакторе». Стенды разработки — наверху, красным.
- **Прогоны** — история, сравнение двух прогонов.
- **Настройки** — базовый адрес, «подключаться к», **другие адреса этого сайта** (стенды и
  старые домены), лимиты, параллельность, пороги, исключённые пути, ночной прогон по расписанию
  (выключен по умолчанию), сколько прогонов хранить.

## 12. Открытые вопросы

- Здоровье в процентах — как считать, чтобы одна сотня `images.alt` не топила сайт с рабочим
  `noindex` на главной. Предложение: вес по важности, проверка считается один раз, а не на адрес.
- Обходить каждую языковую версию целиком или главную и дальше по hreflang. Как есть после A3:
  отдельной затравки по языкам нет — версии приходят ссылками, картой, реестром `routing` (он
  отдаёт адреса всех языков с префиксом) и самими hreflang, которые краулер ставит в очередь.
  Предложение — так и оставить: на сайте с картой и реестром каждая версия и так в затравке, а
  отдельный обход «по языку» удвоит лимит страниц ради того же снимка. Решает владелец.
- Хранить ли HTML страницы (для «показать, где именно») — место против удобства. Предложение: не
  хранить, держать в деталях находки выдержку вокруг проблемного места.

## 13. Потом: `module-audit-dataforseo`

- **Отдельный спутник**, как спутники каталога: платная интеграция не попадает в базовую
  установку, а рядом так же встанут другие поставщики: PageSpeed Insights API — Core Web Vitals и
  кнопка замера скорости в карточке страницы; скриншот страницы — тоже спутником (headless Chrome
  или внешний сервис).
- Поставщик за тем же контрактом: OnPage API DataForSEO пишет находки в те же `audit_issues` с
  `source = dataforseo` — одна таблица, один экран, одни кнопки.
- Логин и пароль API — в настройках спутника; без них раздел работает на своих проверках, и это
  нормальное состояние, а не ошибка.
- Перед прогоном — оценка стоимости (страниц × цена) и подтверждение; потолок расходов в месяц —
  настройкой.
- Не раньше, чем выпущен свой аудит (A1–A5).

## 14. Как легло в код

### A1 (02.10.2026)

- **Пакеты.** `php/packages/module-audit` (namespace `WebxUi\Audit`) и `packages/module-audit`
  (`audit()` — экраны «Обзор» и «Находки»). Раздел — в `Setup\Catalogue` (с 04.10.2026 `default: true`;
  до первой публикации npm-пакета был `false`), в плейграунде — с фикстурами
  `apps/playground/server/panel/audit.ts`. В `scripts/packages.mjs` сайта `webx-cms.local` —
  после первой публикации: в режиме `registry` неопубликованный пакет ломает установку.
- **Таблицы A1:** `audit_runs`, `audit_issues`, `audit_content_urls`. `audit_pages` и
  `audit_links` приходят с краулером (A2), `audit_ignores` — со скрытиями (A5); колонка
  `ignored_by` уже есть и уже учитывается в счётчиках. У `audit_runs` есть `probes` (json) — что
  увидели пробы, без тел ответов: §4 его не называл, а обзору и A3 он нужен.
- **Контракт проверки шире §6 на один метод:** `severity()` — худшая важность проверки. Находка
  может быть мягче (зеркало, которое не резолвится, — notice у проверки-ошибки), а здоровье и
  каталог весят проверку по нему.
- **Этапы и порции.** `Runs\Runner::step()` делает следующий кусок и говорит, есть ли ещё;
  задача `RunAuditStage` зовёт его раз и ставит следующую, `webx:audit:run` — в цикле.
  Этапы: `probes` (конфиг читается в том же куске), `database` (порции по
  `webx-audit.job_seconds`, курсор в `progress`), `crawl` (только полный охват, в A1 пуст),
  `analyse`. Проверка выполняется один раз — на последнем из этапов, которые ей нужны.
  Повтор куска очередью не удваивает находок: перед проверками этапа их прошлые строки в этом
  прогоне удаляются.
- **Пробы держат тела в памяти**, поэтому проверки по `probes` идут в том же куске, что их
  снял. Слэши, регистр и конечный слэш проверяются на первой внутренней ссылке главной; нет
  ссылки — нет и этих проб, а не догадка. Сертификат читает `Probes\CertificateReader` (в тестах
  подменяется), с тем же SNI и `resolve_to`.
- **Отпечаток** — проверка + адрес + ключ. У проверок случайного адреса (`host.soft_404`,
  `host.404_page`) адрес находки — главная, а случайный адрес лежит в параметрах сводки: иначе
  каждая находка была бы «новой».
- **Здоровье** — предложение §12: проверка весит по `severity()` один раз (10 / 3 / 1), не по
  числу адресов; `100 × (сумма весов − потерянное) / сумма весов`.
- **«Новая / висит / исправлена»** — против прошлого законченного прогона **того же охвата**;
  исправленными считаются только находки проверок, которые выполнились и в этот раз.
- **`details`** — `summary` ключом словаря с параметрами и `table`; API переводит их на язык
  читателя (`IssueResource`). К типам ячеек §4 добавлен `edit` — путь редактора в панели
  (`/pages/12`, `/regions/header`), из `ContentRecord::$editUrl`.
- **Производственные проверки конфига** (`config.debug`, `env`, `mail`, `queue`, `schedule`)
  молчат, когда базовый хост похож на стенд (`HostClassifier::looksLikeStand()` без исключения
  для своего хоста). `config.schedule` держится на собственном «пульсе» модуля в
  планировщике (`webx-audit:schedule-heartbeat` в кеше) и молчит на кеше `array`.
- **Настройки A1** — вкладка «Аудит» в настройках сайта (патч `settings.index`, ключи
  `audit.base-url`, `audit.resolve-to`, `audit.other-hosts`); кнопка «Настройки» раздела ведёт
  туда. Лимиты, пороги и расписание — экраном раздела в A5; пороги до тех пор — в
  `config/webx-audit.php`.
- **Источники контента** — `PageContentSource` в `module-pages` (колонка `blocks` и черновик,
  корзина не читается) и `RegionContentSource` в `module-blocks` (дерево и черновик). Оба
  регистрируются под `class_exists(AuditContentSources::class)`, `module-audit` у них в
  `suggest` и `require-dev`. `replace()` пишет через модель (черновик — `saveDraft`); кнопка
  `audit.replace-host` — в A4 вместе с остальными исправлениями.
- **Обзор показывает «Источники»:** искали и — какие контентные разделы стоят без источника
  (список id в `Runner::CONTENT_MODULES`).

### A2 (02.10.2026)

- **Этап `crawl` — три фазы в `progress.crawl`:** `seed` (одним куском), `fetch` (очередь
  порциями по `job_seconds`), `checks` (снимок доводится, потом проверки обхода — по одной, сколько
  влезет в кусок, но не меньше одной). `pages_limit` пишется в прогон при старте
  (`webx-audit.pages_limit`, 1000), параллельность — `webx-audit.concurrency` (2).
- **Затравка** (`Crawl\Seeder`): главная; `robots.txt` — его строки `Sitemap:` и `/sitemap.xml`,
  индекс карт разворачивается (до 50 файлов, `.gz` тоже), в снимок идут только свои адреса;
  канонические строки реестра `routing` — с префиксом языка через `SiteUrl`, под `class_exists`
  (`routing` у модуля в `suggest`). Флаги `in_sitemap` / `in_registry` ставятся и уже известным
  адресам.
- **Очередь — сами строки `audit_pages`** без `fetched_at` (`Crawl\Frontier`): умерший воркер
  теряет кусок, а не прогон. Порядок — по глубине, адреса без глубины (их знает только карта или
  реестр) — последними, поэтому первое найденное расстояние от главной и есть кратчайшее. Адреса
  добавляются пачкой на страницу, не запросом на ссылку.
- **Обход** (`Crawl\Crawler`): `SiteClient::many()` — пул HTTP-клиента Laravel с теми же `Host`,
  SNI и `resolve_to`; файлы по расширению спрашиваются `HEAD`. Редирект не следуется: адрес, куда
  он ведёт, встаёт в очередь с той же глубиной. В очередь идут свои `<a>`, canonical и hreflang
  (последние два — без глубины: это не клик). После обхода — `links_in` (страницы-источники,
  только `<a>`), `final_status` (цепочка внутри снимка, петля или выход за него — `null`) и
  `indexable`: 200, HTML, без `noindex`, canonical пуст или на себя.
- **Разбор** (`Crawl\PageParser`) — `Dom\HTMLDocument`, HTML5-парсер PHP 8.4 (то же дерево, что
  строит браузер; решение 1 о «без лишних зависимостей» держится). Ссылки — по одной на вид,
  адрес и `rel`, не больше 2000 на страницу. `robots.txt` читает `Crawl\RobotsRules`: группа `*`,
  самое длинное совпадение, `Allow` выигрывает ничью — для `blocked_by_robots`; проверки самого
  файла — A3.
- **Сверх §4 в снимке:** у `audit_pages` — `fetched_at` (очередь), `error`, `indexable` и `facts`
  json (число `<title>` и canonical'ов, canonical из заголовка `Link`, viewport, иконка, пропуск
  уровня заголовков, пустые ссылки, картинки без размеров, кнопки без имени, поля без подписи,
  фреймы без `title`, доля текста); у `audit_links` — `absolute` (написан с хостом).
- **50 проверок по снимку**, группы `indexing`, `page`, `content`, `links`, `images`, `a11y`,
  `structure`, `hosts`. Базовые классы: `Page\PageCheck` (страница за страницей),
  `Page\LinkCheck` (одна находка на страницу, её адреса в таблице), `Page\DuplicateCheck` (своя
  находка у каждой из одинаковых страниц, остальные — в таблице, до 20), `Hosts\HostCheck`
  (находка на хост, ключ — хост).
  - `hosts.absolute_own` не считает адреса, которые стоят больше чем на половине страниц: это
    решение шаблона (меню через `url()`), а проверка — про ссылки, вставленные в контент.
  - `hosts.new_domain` сравнивает с прошлым полным прогоном, у которого снимок ещё есть; без него
    молчит, а не объявляет новым всё.
  - `html.lang` — только отсутствие `lang`; расхождение с hreflang — A3, вместе с hreflang.
    `html.favicon` — только «иконки нет»; «не открывается», `og.image_broken`, `images.broken` /
    `heavy` / `format`, `links.external_broken`, `links.to_redirect`,
    `hosts.external_redirect` — A3, вместе с проверкой ресурсов.
- **Снимки хранятся за `webx-audit.keep_snapshots` (5) последних полных прогонов** — чистит
  `analyse`; находки остаются.
- **Экран «Страницы»** — последний законченный полный прогон (`runs/latest` отдаёт его как
  `crawled`). Колонки — любое поле `Pages\PageColumns`, выбор помнится в браузере; фильтры — класс
  ответа, индексируемость, «с находкой проверки…» и любое поле: `f[поле]=операция:значение`
  (`contains`, `eq`, `empty`, `filled`, `gt`, `lt`, `yes`, `no`); сортировка по любому полю, кроме
  `h1`. CSV — те же фильтры и колонки экрана, с BOM и защитой от формул. Карточка — `WxDrawer`
  со вкладками «Обзор», «Проблемы», «Входящие», «Исходящие». Не сделано в A2: «Перепроверить»
  (охват по списку адресов) и экспорт одной страницы, вкладки «Картинки», «CSS», «JS»,
  «Микроразметка» — с ресурсами и JSON-LD в A3.
- **Плейграунд:** второй прогон фикстур — полный, двенадцать страниц со ссылками; CSV там не
  отдаётся.

### A3 (02.10.2026)

- **robots.txt и карта читаются на этапе проб**, то есть и в быстром прогоне: пробы просят
  `/robots.txt`, `Crawl\SitemapReader` — файлы из его строк `Sitemap:` (и `/sitemap.xml`, который
  при названных в robots необязателен), индекс разворачивается (до 50 файлов, `.gz` тоже,
  разбор — `XMLReader` потоком, файл читается до 50 МБ). В `audit_runs.probes` ложатся файлы со
  счётами (`sitemaps`), адресов там нет: затравка обхода читает карту второй раз тем же
  читателем — список в пятьдесят тысяч адресов между этапами не носим.
- **`robots.syntax`** — неизвестная директива, правило до первого `User-agent`, строка не «поле:
  значение» (`RobotsRules::problems()`; известные — с `host` и `clean-param` Яндекса).
  **`robots.disallow_all`** молчит на стенде, как производственные проверки конфига.
  **`robots.blocks_assets`** смотрит CSS и JS главной из проб.
- **Карта по снимку:** `sitemap.bad_url` — находка на каждый адрес карты, который редирект,
  ошибка, `noindex` или canonical на другой; `sitemap.missing_page` — индексируемая страница вне
  карты, и молчит, если карты нет вовсе (это `sitemap.missing`, одной находкой). Флаг
  `in_sitemap` ставится и после лимита страниц — уже известным адресам.
- **Редиректы** (`Checks\Redirects`, группа `redirects`) — цепочки идут по `redirect_to` внутри
  снимка, сайт второй раз не спрашивается. Голова цепочки — редирект, на который не ведёт другой
  редирект: `chain` и `to_error` говорятся у головы, `loop` — у каждого шага петли (у петли
  головы нет), `temporary` — у каждого 302/307. `links.to_redirect` — `LinkCheck` на `<a>` к
  странице с `redirect_to`.
- **hreflang** (`Checks\Hreflang`): альтернатива ищется в снимке; не обойдённую (лимит) не
  судим, в матрице у неё пустые «ссылается назад» и «индексируется» — для этого ячейка `bool`
  с `null` рисуется пустой. Неверный код — регэксп BCP 47 без расширений плюс известные ошибки
  (`jp`, регион `UK`). Расхождение `html.lang` — с hreflang-строкой страницы на саму себя, по
  языку без региона.
- **JSON-LD:** разбор по правилам `Crawl\JsonLdRules` — обязательные поля только те, что требуют
  сами поисковики (у `Product` — имя и одно из цены, отзыва, рейтинга; у `FAQPage` — вопрос и
  текст ответа у каждого; у `BreadcrumbList` — позиция и имя у каждого шага), рекомендуемые —
  короткий список. В `audit_pages.json_ld` у блока теперь `items` (тип, чего нет) и `source` —
  блок, обрезанный до 4000 символов, для вкладки «Микроразметка».
- **Этап 5 — ресурсы** — фаза `resources` обхода между `fetch` и `checks`, таблица
  `audit_resources` (у `audit_links` — `resource_id`). `Crawl\Resources::collect()` кладёт каждый
  адрес один раз на прогон: картинки (`<img>`, `srcset`, `url()` картинок), OG и twitter-картинку,
  иконку, CSS, JS (и `preload`), внешние `<a>`; чужое по порядку важности до
  `webx-audit.resources_limit` (2000), внешние страницы — последними. Стенд не спрашивается.
  Спрашивается `HEAD` (на 405/501 — `GET`), OG-картинка — `GET`: её размер в пикселях читает
  `getimagesizefromstring`. **Чужой хост спрашивается напрямую** (`SiteClient::direct()`):
  `resolve_to` — адрес своего сайта, и внешняя картинка, спрошенная там, спрошена не у того
  сервера. Ответы переносятся на `audit_links.status`.
- **Проверки ресурсов** (`Checks\Resources`): `images.broken` / `heavy` / `format`,
  `og.image_broken` (не открывается или меньше 1200×630), `html.favicon` теперь и «не
  открывается», `links.external_broken` (429 не считается — это просьба притормозить), `hosts.external_redirect`.
  Пороги — `image_kb`, `image_format_kb`, `og_width`, `og_height` в `thresholds`.
- **`images.format` понят так:** своя JPEG/PNG тяжелее 100 КБ, отданная браузеру, который
  сказал, что берёт WebP и AVIF (`Accept`), и без современного `<source>` рядом в `<picture>`
  (такой `<img>` — запасной для старых браузеров, у ссылки `rel=modern`). Есть ли «вариант» у
  файла вообще, по одному адресу не узнать, а соглашения об именах у модулей нет.
- **Ячейка `word`** в `details.table`: значение — ключ `webx-audit::details`, `IssueResource`
  переводит его на язык читателя и отдаёт как `text` (причины в `robots.syntax` и
  `hreflang.broken`).
- **Панель:** в карточке страницы вкладки «Картинки», «CSS», «JS» (`GET runs/{run}/pages/{page}/resources?tab=`:
  ссылка страницы + ответ ресурса — код, размер, кеш, сжатие, `alt`, «не проверялось» за лимитом и
  у стенда) и «Микроразметка» (блоки, чего не хватает, исходник). Счётчики вкладок — в `counts`
  карточки. Обзор во время этапа 5 пишет «проверено N из M» (`progress.resources`).
- **Не сделано в A3:** «Перепроверить» (охват по списку адресов) и экспорт одной страницы —
  вместе с историей в A5; открытый вопрос про языковые версии — §12, решает владелец.

### A4 (02.10.2026)

- **Исправление — контракт с предпросмотром.** `Fixes\AuditFixes` (синглтон, как проверки),
  `Fixes\FixRunner` — общий для кнопки и MCP: `offers()` (исправления находки, у каждого —
  `FixPreview`), `run($issue, $fix, $dryRun)`. Пустой предпросмотр — исправление не предлагается:
  менять нечего. Нажатое исправление находку не закрывает, а помечает (`audit_issues.fixed_with`,
  `fixed_at`) — «исправлено, ждёт следующего прогона»; закрывает только прогон. У
  `FixPreview` строка — поле записи с числом замен или настройка «было → станет»
  (`before`/`after`), плюс `note` для того, что строкой не сказать. Тексты исправления —
  `<namespace>::fixes.<id>.title|description` (`FixTexts`, `textNamespace()` как у проверки).
- **`audit_issues.key`** — ключ находки хранится (миграция `…000007`): исправлению по нему
  возвращаться к записи, а не разбирать `details`. `Finding::$runId` заполняет
  `AuditIssue::finding()` — исправлению нужен снимок прогона.
- **API:** `GET runs/{run}/issues/{issue}/fixes` (видят все с `audit.view`) и
  `POST runs/{run}/issues/{issue}/fixes/{fix}` с `dry_run` (только `audit.manage`); у строки
  проверки в `runs/{run}/checks` — `fixes` (ids), по нему экран рисует кнопку.
- **`audit.replace-host`** (в самом `module-audit`): ключ находки `hosts.dev_content` —
  `источник|запись|поле|язык`; хосты стенда — из `audit_content_urls` этого прогона, поле читается
  заново при предпросмотре и при нажатии (`AuditContentSource::find()` — **в контракт добавлен
  метод**: записать нужно одну запись, а не перебирать все). Замена — на origin прогона, со схемой
  и без, с портом и без, только там, где хост кончается (`dev.shop.com.evil.net` не трогается).
- **`module-seo`:**
  - **Middleware `NormaliseAddress`** — глобальный, перед таблицей редиректов (таблица сверяется с
    нормализованным адресом); главное зеркало, https, двойные слэши, индексные файлы, конечный
    слэш, нижний регистр — одним 301. Каждая часть — настройка карточки «Один адрес у страницы»
    на вкладке SEO (`seo.normalise-*`, класс `Normalisation`), по умолчанию всё выключено.
    Файлы (адрес с расширением) не трогаются ни регистром, ни слэшем; адреса панели — тоже.
  - **Исправления:** шесть `seo.normalise-*` (одним классом `NormaliseFix`: проверка `host.*` →
    настройка и её значение; зеркало — то, что открывал прогон, слэш — как у ссылок самого сайта;
    не предлагается, если настройка уже стоит — значит, адрес отвечает веб-сервер),
    `seo.collapse-chain` (`RedirectChains` — таблица редиректов, пройденная как её прошёл бы
    middleware; переписываются только `exact`-строки, маска — шаблон на тысячу адресов),
    `seo.robots-sitemap` (строка `Sitemap:` в `seo.robots-txt`; закрывает и `robots.missing`, если
    настройка пуста; предупреждает про `public/robots.txt`).
  - **Проверки** (`SeoChecks`, группа `seo`): `seo.redirect_chain` и `seo.title_duplicate` — по
    таблицам, до обхода; `seo.redirect_broken` и `seo.rule_dead` — `exact`-строка против снимка
    обхода. «Сущности без `seo_meta`» не сделаны: на сайте без SEO-карточек это сотни находок
    без пользы — по ним говорят `title.missing` и `description.missing` обхода.
- **`routing`:** логика `webx:routes:check` вынесена в `RegistryHealth`, команда печатает её
  же. Проверки `routing.orphan`, `alias_broken`, `shadowed`, `no_address`, `unknown_type` —
  одним классом, реестр читается раз на прогон. У пакета появился словарь (`webx-routing`).
- **`module-media`:** `media.missing_file` (файла нет на диске) и `media.heavy` (картинки тяжелее

  у библиотеки нет: `alt` живёт в поле, которое картинку использует, а не в файле, — его ловит

- **`module-catalog`:** `catalog.category_description`, `catalog.product_image`,

- **`module-menu`:** `menu.broken` (пункт ведёт на 4xx/5xx — или на запись без адреса: такой

  пункта — `LinkUrls::href()`.
- **База для модулей:** `Checks\ModuleCheck` — константы как у своих проверок плюс `NAMESPACE`
  словаря; сводка — `<namespace>::audit.<ключ>`. Модуль регистрирует проверки под

- **MCP** (`Mcp\AuditTools`, скоупы `audit:read` / `audit:write`): `audit_run` (на `sync`-очереди
  — отказ с командой), `audit_status`, `audit_issues` (без `check` — сводка по проверкам с тремя
  текстами, с `check` — находки), `audit_pages`, `audit_page_get` (по id или адресу),
  `audit_hosts` (хосты по классам из обхода и из базы, стенды первыми; с `host` — места),

- **Панель:** в раскрытии проверки, у которой есть исправления, — кнопка «Fix» на каждом адресе

### A5 (02.10.2026)

- **Скрытия** — таблица `audit_ignores` (миграция `…000008`), `Runs\AuditIgnore`, `Runs\Ignores`.
  Маска — как в правилах SEO (`*` без слэша, `**` со слэшами, `Runs\Mask`): шаблон со схемой
  сравнивается со всем адресом, без схемы — с путём (и запросом, если в маске есть `?`), пустой —
  вся проверка, находки без адреса тоже. Правило применяется ко всем хранимым прогонам сразу и
  пересчитывает их `counts` (`Runner::recount()`), новый прогон скрывает на разборе — до
  счётчиков. Скрытое не «исправлено»: отпечаток остался. API — `GET/POST ignores` (`dry_run` —
  сколько находок последнего прогона скроет, без причины), `DELETE ignores/{id}`; в «Находках» —
  кнопка «Hide» с диалогом и состояние фильтра `hidden` (`IssueController::HIDDEN`) с причиной и
  «Show again»; `created_by` — имя администратора, `mcp` у агента. MCP `audit_ignore`.
- **Охват `urls` (перепроверка)** — `AuditRun::URLS`, адреса в `progress.urls` (до 50, только
  свой хост — `RunController::ownUrls()`). Прогон начинается сразу с `crawl`: robots.txt читается,
  карта и реестр — нет, ссылки не идут в очередь (`Frontier` берёт только адреса списка), источник
  страницы — `list`. Проверки — только те, что судят страницу саму по себе: `PageCheck` и
  `LinkCheck`, кроме hreflang и списка `Runner::WHOLE_SITE` (сироты, глубина, canonical на

  the runs» (`runs?to=<id>`); «Export» — `GET runs/{run}/pages/{page}/export`, JSON: снимок,

- **«Прогоны»** — история (`GET runs`) и сравнение (`Runs\Comparison`, `GET runs/compare` и

  проверок, которые выполнил более поздний прогон; без `from` — против прогона, с которым его

- **«Исходящие»** — `HostController` (его же зовёт MCP `audit_hosts`): хосты из ссылок последнего
  полного прогона и из `audit_content_urls` последнего прогона по сайту, стенды первыми; сверх

  страницы с анкорами и записи с «Open in the editor».
