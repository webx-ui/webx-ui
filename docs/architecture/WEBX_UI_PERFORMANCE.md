# Производительность модулей — правила

Статус: действует. Задача webx-ui#16 сделала серверную половину быстрой «из коробки» (замеры
«было/стало» — [`WEBX_UI_PERFORMANCE_AUDIT.md`](WEBX_UI_PERFORMANCE_AUDIT.md), §9 и §10); этот
документ — правила, по которым новые модули и правки старых не откатывают её назад. Кеш подробно —
[`WEBX_UI_CACHE.md`](WEBX_UI_CACHE.md); фронт тем (картинки, шрифты, CSS/JS) — правила 36–41
[`WEBX_UI_THEMES.md`](WEBX_UI_THEMES.md) §16.1 и `php/packages/themes/RULES.md`. Гайд для людей —
`apps/docs/guide/performance.md`.

## 1. Зачем и для кого

Сайт на WebX стоит на любом хостинге: MariaDB на соседнем сервере, кеш и сессии в той же базе
(`CACHE_STORE=database` в скелете). Каждый запрос к базе стоит там 0,3–1 мс сети, и страница из
130 запросов (холодный `sitemap.xml` до задачи) — это то, что посетитель ждёт. Поэтому мерило —
**число запросов на страницу и его рост с числом записей**, а не время на машине разработчика:
sqlite in-memory в тестах не покажет ни сети, ни отсутствующего индекса.

Правила — для любого пакета `php/packages/module-*` и для модулей сайта (`webx:make-module`).

## 2. N+1 и загрузка связей

1. **Всё, что шаблон списка трогает у строки, грузится запросом на список**, а не на строку:
   `with('routes', 'cover', 'categories')` в том месте, где собирается список. Адрес записи —
   связь `routes` (`HasUrl::url()` отвечает из загруженной связи, без неё — из реестра по
   запросу на вызов). Карточки, крошки, связанные записи, `ItemList` разметки — тоже списки.
2. **Предки дерева — одним запросом** (`ancestors()` nested-set с `with('routes')`), не обходом
   `parent` по одному.
3. **Нужны id — бери id.** `HasRelations::shownRelatedIds()`, `HasCategories::categoryKeys()`,
   `Relations::loadIds()`, `RelationTarget::names()` отвечают без загрузки моделей целей; пикер на
   тысячу услуг ради подписи фильтра — ошибка.
4. **Тяжёлые колонки — только там, где читаются.** Списки версий — `EntityVersion::scopeWithoutPayload()`;
   JSON-тело записи в списке панели не нужно.
5. **Значения блоков страницы — одним запросом на тип.** Тип поля, который ходит в базу за каждым
   значением (картинка, файл, ссылка на запись), реализует `Screens\PreloadsValues`: `Renderer`
   до рендера обходит всё дерево (вложенные `wx-blocks`, элементы повторителей) и отдаёт типу все
   значения разом (`MediaFiles::load()` копит ключи до первого `find()`).
6. **Sitemap — скоупом модели.** `scopeForSitemap()` грузит на чанк адреса, обложку и `lastmod`;
   `Sitemap` зовёт его через прототип модели. Чанк — `lazyById()`/`chunkById()`, не `get()` всей
   таблицы.
7. **Раз на запрос — мемо, а не синглтон навсегда.** Справочник, поддерево, видимость, которые
   страница спрашивает много раз, держит объект с привязкой к запросу и сбросом на
   `RequestHandled`/`JobProcessing` (пример — `RequestMemo` каталога, `OutletLoader` прессы).
   Статическое свойство без сброса под Octane и в очереди отдаёт данные прошлого запроса.
8. **Lazy loading не запрещаем глобально** (`Model::preventLazyLoading()` сломал бы сайты с
   собственным кодом поверх модулей); держат бюджеты (§5) и `assertNoRepeatedQueries`.

## 3. Кеш

Механизм — версионные группы `webx-ui/cache` ([`WEBX_UI_CACHE.md`](WEBX_UI_CACHE.md) §2–3).
Правила модуля:

1. **Данные, которые читает каждая страница** (настройки, меню, регионы, правила), — через
   `CacheGroups::remember(name, depends, fn)` с группами, из которых они собраны. Свой
   `Cache::remember` на своём ключе — нет: его не сбросит ни правка, ни кнопка.
2. **Запись, нужная каждой странице, объявляется** `prefetch()` из провайдера: на `database` это
   один `many()` вместо запроса на запись.
3. **Своя группа — у владельца данных**, одна-две на модуль: `declare` + `bumpOn(group, ...models)`
   из `boot()`, провайдер `webx-ui/cache` регистрируется в `register()`. Читать чужую группу
   можно, объявлять заголовок чужой — нет.
4. **Путь без Eloquent-события — явный `bump()` в том же коммите**: массовый `update()`,
   `insert`/`upsert`, сырой SQL, импорт, реордер одним запросом, команда. Внутри транзакции сброс
   сам ждёт коммита; писать в кеш руками внутри транзакции нельзя.
5. **Тяжёлая сборка — своя группа**, чтобы двигалась реже (`sitemap`, `block-usage`).
6. **Ничего о пользователе в общей записи**, кроме языка (он в ключе сам). Права, бейджи, «мои»
   — считаются на запрос (урок `admin.manifest`: `meta` модулей вне кеша).
7. **В ключе — всё, от чего зависит ответ, кроме версий групп**: хост запроса, если в значении
   абсолютный адрес; конфиг, если он меняет вывод.
8. **Не кешировать то, что обновляется асинхронно** после сброса группы (счётчики фасетов на
   Manticore: индекс догоняет очередью, кеш сохранил бы старые числа под новой версией).
9. **Кнопка сброса — признак бага.** «Система → Кеш», `webx:cache:reset`, MCP `cache_reset` —
   аварийный выход. Если её пришлось нажать, где-то пропущен `bump`: строка журнала (`history`
   типа `cache`) говорит, когда и какую группу; найти путь записи, добавить `bump`, закрыть тестом
   свежести (§5.2).

## 4. Индексы и запросы

1. **Индекс — под настоящий запрос**, который показал `EXPLAIN` на MariaDB: составной в порядке
   `WHERE =` → диапазон/сортировка (`blog_articles (deleted_at, pinned, published_at)` под ленту).
   Индекс «на всякий случай» не ставим: каждый стоит записи.
2. **Новый индекс — новой миграцией** с комментарием, какой запрос он обслуживает, и с `down()`.
   Длинная строка на MySQL/MariaDB — префикс (`media_files path(255)`); sqlite префикса не знает —
   ветка по драйверу. Миграцию проверить на MariaDB: накатить, откатить, накатить.
3. **Что индексом не лечится — так и записать**: `LIKE '%x%'` по JSON переводов, сортировка по
   `coalesce(...)`. Поиск по `LIKE` приемлем примерно до 5 000 записей; дальше — Manticore
   (`module-catalog-manticore`) или генерируемая колонка с индексом.
4. **Пагинация — у каждого списка, который растёт**: публичные ленты и списки панели
   (`->paginate()` отдаётся таблице как есть). Исключение — списки с ручным порядком (услуги,
   рецепты, вакансии, FAQ): реордер пишет весь видимый порядок, и потолок спрятал бы строки. Такой
   список обязан быть плоским по цене — бюджет не растёт с числом строк (тест).
5. **`count()`/`exists()` вместо `get()->count()`**, `value()`/`pluck()` вместо модели ради одного
   поля, `whereIn` пачкой вместо цикла `find()`.

## 5. Тесты

Хелпер — `WebxUi\Admin\Testing\CountsQueries` (аудит §7): `assertQueriesWithin(N, fn)`,
`assertNoRepeatedQueries(fn)`, `recordQueries(fn)`. При провале печатает все запросы и повторы.

### 5.1. Бюджет

- **`tests/PerformanceTest.php` в каждом модуле с публичными страницами или списками панели**:
  каждый тип публичной страницы (список, категория, запись, sitemap, RSS) холодным и тёплым
  запросом; список, форма и MCP-список панели тёплым.
- **Данных больше, чем показывает страница** (30+ записей с категориями, обложками, связями) — иначе
  N+1 не виден по росту.
- **На тёплых списках — `assertNoRepeatedQueries`**: N+1 ловится при любом счёте.
- **Бюджет — потолок, под которым страница помещается сегодня, а не цель.** Поднять — только с
  объяснением в тесте, почему нужно больше.
- Кеш в тесте включён, как на сайте (`cache.default=array`, кеши пакетов `enabled`); между
  «запросами» — `CacheGroups::forgetMemo()`, иначе тест читает мемо, а не хранилище.

### 5.2. Свежесть

На каждую группу модуля — тест «сохранил через панель — сайт показывает новое»: правка через API
панели (или MCP), затем страница или `version(group)` до и после. Для пути без события модели
(массовый апдейт, импорт, реордер) — тот же тест после него. Пример —
`module-blog/tests/PerformanceTest.php`, `module-admin/tests/ManifestCacheTest.php`.

### 5.3. Заготовка

`webx:make-module <Name>` пишет рядом с классом модуля `tests/Feature/Cms/<Name>ModulePerformanceTest.php`
с двумя незаполненными тестами (бюджет и свежесть, `markTestIncomplete`): пустая заготовка видна в
выводе PHPUnit, пока её не заполнят.

## 6. Обязательный набор модуля

То, без чего модуль не сдаётся (дублирует чек-лист `CLAUDE.md` §6 и реестр пакетов):

- [ ] списки и карточки грузят связи запросом на список; `assertNoRepeatedQueries` зелёный;
- [ ] данные каждой страницы — в `remember` с группами; своя группа объявлена с моделями;
      пути без событий делают `bump`;
- [ ] индексы под запросы списков и фильтров, проверены `EXPLAIN` на MariaDB;
- [ ] растущие списки — с пагинацией (или плоские по цене, если порядок ручной);
- [ ] `PerformanceTest`: бюджет на каждый тип страницы и список панели, тест свежести на группу;
- [ ] в `AGENTS.md` — «Check your work» называет бюджет-тест и проверку свежести.

## 7. Чего не делаем

- **Полностраничный кеш для анонимных** — не делаем (аудит §6): сессия гостю, CSRF в формах,
  согласие, язык по заголовку и превью панели делают его источником старых и чужих страниц.
  Вернуться, если бюджеты упрутся.
- **Теги Laravel** (`Cache::tags()`) — нет: не работают на `file`/`database`.
- **`cache:clear` для «обновить сайт»** — нет: сносит сессии, блокировки и лимиты.
