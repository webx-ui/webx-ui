# `webx-ui/module-faq` и контракт «вставить блоком» — спецификация

Статус: выпущено (§6). Пакеты — `webx-ui/module-faq` (composer) и `@webx-ui/module-faq` (npm);
контракт — в `module-admin` и `module-blocks` на обеих половинах.

FAQ — вопросы и ответы с плоскими категориями. Своей страницы у вопроса нет, у модуля нет ни
одного публичного маршрута: вопросы попадают на сайт **блоком**, поставленным на любую страницу, —
«FAQ по оплате» на странице услуги или «все вопросы с фильтром» на обычной странице `/faq`.

Этот способ попадать на сайт — общий: команда, отзывы, тарифы и прочие разделы устроены так же.
Поэтому спека описывает две вещи: контракт «вставить блоком» (§3) и `module-faq` — его первого
потребителя (§4).

## 1. Границы

**Контракт:** `CollectionSource` и реестр источников в `module-admin`; тип поля `wx-collection` на
обеих половинах (выбор категорий источника, лимит, фильтр, разметка); значение раскрывается на
чтении сайта в список записей; модуль предлагает свои типы блоков, а сайт ставит их один раз
(`BlockOffers` в `module-blocks`); одна разметка schema.org на страницу из нескольких блоков
(`Seo::put()` в `module-seo`); плейграунд рисует такой блок.

**`module-faq`:** вопросы и категории, порядок, переводы, якоря, источник `faq`, тип блока «FAQ» с
аккордеоном и фильтром, `FAQPage`, экраны панели, API, MCP, демо.

**Снаружи:** выбор отдельных записей руками («эти три вопроса»), а не категорий; вставка записей
без блоков (директива в Blade сайта); экран «предложенные типы» в панели «Блоки»; поиск по
вопросам на сайте; голосование «помог ли ответ» (§7).

## 2. Принятые решения (не переоткрывать)

1. **Категории плоские, «многие ко многим», код общий, таблица своя** — `faq_categories` и
   `faq_category_question` на ядре категорий из `module-admin` (спека услуг).
2. **У категории FAQ нет адреса, SEO и блоков:** `slug` пустой, `CategoryLinkSource` не
   регистрируется. Экран категории — название, видимость и поля проекта.
3. **У вопроса нет своей страницы и нет главной категории:** поле `wx-categories` с `main: false`.
4. **Два порядка, как у услуг:** общий (`position`) и внутри категории (`item_position` в связи);
   перетаскивают в том списке, который видят.
5. **Поля проекта — патч экрана плюс `extra`**, через `ScreenRecord`, как у услуг.
6. **Общей страницы у модуля нет.** «Общая страница FAQ» — обычная страница `module-pages` с
   блоком FAQ в режиме «все категории, с фильтром». Адрес, SEO, меню, карта сайта и перевод слага
   приходят от страницы; у модуля нет маршрутов, которым можно столкнуться с чужими адресами; «не
   нужна общая страница» — значит блок не поставили.
7. **Контракт общий, а не под FAQ:** его форма должна выдерживать команду и отзывы (§5).
8. **Разметка `FAQPage` — флаг на блоке.** По умолчанию она включена только в режиме «все
   категории» и выключена у блока с выбранными категориями: Google просит не размечать один
   вопрос на нескольких страницах, а «FAQ по оплате» стоит на каждой услуге. Редактор может
   включить разметку и там — его страница, его решение.
9. **Вопрос без перевода на язык страницы не показывается.** Вопрос виден на языке, если на нём
   есть и вопрос, и ответ; подстановки языка по умолчанию нет. FAQ, где половина ответов на
   другом языке, хуже короткого.
10. **Якорь генерируется сам.** При создании — из вопроса на языке по умолчанию, уникальный в
    таблице; потом он не меняется, даже если вопрос переписали: иначе ссылки
    `…/faq#oplata-kartoy` ломаются молча. В форме якорь показывается только для чтения, с
    копированием ссылки.
11. **Ответ — rich-text, а не блоки.** Ответ — это абзац, список, ссылка, иногда картинка, и
    `FAQPage` нужен его текст. `wx-rich-text` хранит ключ картинки, а не адрес.
12. **Черновиков и версий у вопроса нет** — только `published`. Вопрос правится за минуту;
    `HasDraft` для него — церемония. Корзина есть, как у всех.

## 3. Контракт «вставить блоком»

### 3.1. Как это выглядит у автора блока

В схеме блока — поле типа `wx-collection`:

```json
{ "type": "wx-collection", "id": "questions", "label": "Questions", "props": { "source": "faq" } }
```

Редактор страницы видит в этом поле выбор категорий источника (пусто — «все»), лимит, флаг
«показывать фильтр по категориям» и флаг «разметка для поисковиков», если источник её умеет.
В базе лежит только выбор:

```json
{ "categories": [3, 5], "limit": null, "filter": false, "markup": null }
```

`markup: null` — «по умолчанию» (решение 8); `true` и `false` — явный выбор редактора. Источник в
значении не хранится: он записан в `props` поля схемы, и блок, собранный под FAQ, не превращается
в блок отзывов правкой содержимого.

Шаблон блока получает значение уже раскрытым (`FieldType::resolve()`, спека блоков):

```php
$questions['items']   // list: ['id', 'anchor', 'categories' => [id…], ...поля записи от источника]
$questions['groups']  // list: ['id', 'title', 'items' => [id…]] — для фильтра; пусто без filter
$questions['filter']  // bool
```

Что лежит в элементе, решает источник: у FAQ это `question` и `answer` (HTML), у команды — фото,
имя, должность. Общие у всех только `id`, `anchor` и `categories`.

**Порядок:** выбрана одна категория — её порядок (`item_position`); ни одной или несколько —
общий (`position`), без повторов. **Группы фильтра** считает `CollectionType`, а не источник:
видимая категория, в которой есть хоть одна показанная запись, — и среди выбранных тоже (кнопка,
которая опустошает список, не нужна никому); без выбора — все такие категории источника.

### 3.2. `CollectionSource` в `module-admin`

```php
namespace WebxUi\Admin\Collections;

interface CollectionSource
{
    public function key(): string;              // 'faq' — то, что пишут в props.source
    public function title(): string;            // переведённое, для подписи поля
    public function categories(): ?string;      // путь API категорий (как props.source у wx-categories), null — без категорий
    public function supportsMarkup(): bool;
    public function permission(): ?string;      // кто может ставить (для /api/cms/collections), null — все

    public function items(Selection $selection, string $locale): array; // list элементов §3.1, уже по порядку
}
```

- Реестр `CollectionSources` — синглтон по образцу `LinkSources` и `CategorySources`; модуль
  регистрирует источник из своего провайдера (не из файла маршрутов — `route:cache`).
- `items()` отдаёт `list<array>`, а не `Collection`: шаблон `TValue` у `Collection` инвариантен, и
  PHPStan не сводит литералы с ним.
- `Selection` — разобранное значение поля (`categories`, `limit`, `filter`, `markup` с уже
  применённым умолчанием). `Selection::apply(Builder)` — общий фильтр по категориям (подзапросом,
  без повторов), порядок и лимит для источников на `HasCategories`.
- Видимость решает источник, до `apply()`: неопубликованное, удалённое и не переведённое на
  `$locale` в `items()` не попадает (решение 9 — правило FAQ, а не контракта).
- Разметку источник пишет сам, если `$selection->markup`: контракт не знает про `module-seo` и
  знать не должен.

### 3.3. Тип поля `wx-collection`

php — `Screens\Types\CollectionType`:

- `rules()` — `categories` существуют у источника, `limit` — целое 1…100 или `null`, флаги —
  булевы; неизвестный источник в `props.source` — отказ с понятным сообщением. Работают там, где
  поле стоит на описанном экране.
- `store()` — нормализует и сортирует id категорий, выкидывает то, чего источник не умеет
  (`markup` и `categories` у источника без них). **На содержимом блоков правила не запускаются ни
  на одной двери**, поэтому `store()` — единственное, что стоит между запросом и строкой. Id
  несуществующей категории он не проверяет: на чтении она просто ничего не находит.
- `resolve()` — на чтении сайта раскрывает значение в `items`/`groups`/`filter`, язык —
  `Locales::current()`. **Только на чтении сайта:** панель читает значение сырым, как
  `MediaValues`. Источника нет (модуль удалён) — пустой список, а не исключение: блок рисуется
  пустым, страница живёт.
- Маркер `Screens\ResolvesMissing`: блок хранит только то, что редактор задал, и нетронутое поле
  `wx-collection` резолвится как «все записи». Прочие отсутствующие поля в шаблоне — по-прежнему
  `null`.

npm — компонент поля в `@webx-ui/module-admin`: выбор категорий берёт список по `categories()`
источника (тот же запрос, что у `wx-categories`), лимит, два переключателя; слова — ключи
`webx-admin::collections.*`. Описание источников панель берёт из `GET /api/cms/collections`
(`{ data: [{ key, title, categories, markup }] }`) — только тех, чьи права есть у администратора.

Правило «значения идут через тип поля» держится **на обеих дверях**: панель (`PageForm::save`) и
агент (`BlockTools::writeContent`).

### 3.4. Типы блоков, которые приносит модуль

Типы блоков заводятся в панели, из кода их не регистрируют (спека блоков). Но блок FAQ без
готового типа — это инструкция «соберите аккордеон сами», поэтому модуль **предлагает** тип, а
сайт **ставит** его один раз:

- `BlockOffers` в `module-blocks` — реестр «модуль → документы типов» (формат
  `webx:blocks:export`, лежит в `resources/blocks/*.json` модуля). Ключ — id модуля панели, тот же,
  что в `Setup\Catalogue`; регистрация — из `boot()` провайдера.
- `webx:blocks:offered` показывает предложенное и что из этого уже стоит; `--install` ставит
  недостающее и публикует. Документ проверяется правилами `BlockInput`, как импорт; тип, который
  не рисуется на своём `sample`, остаётся черновиком, а команда выходит с кодом 1. **Тип с таким
  `slug` не трогает никогда** — сайт мог его переделать.
- `webx:setup` зовёт `webx:blocks:offered --install --module=<id>` после `migrate` для выбранных
  модулей; на сайте, где модуль ставят в существующую панель, это одна команда из README модуля
  (`webx:panel --sync` сюда не расширяем — он не трогает существующее).

### 3.5. Одна разметка на страницу

На странице могут стоять два блока FAQ с общим вопросом. `Seo::push()` складывает блоки подряд —
получилось бы два `FAQPage` с повтором. Поэтому есть `Seo::put(string $key, array $block)`: блок
под ключом, последний выигрывает, пустой блок снимает ключ; `head()` печатает их после `push()`.
Источник FAQ копит вопросы запроса у себя (по id, без повторов) и каждый раз кладёт весь
`FAQPage` под ключом `faq`.

Работает, потому что содержимое страницы рисуется раньше layout'а, в котором стоит `@webxSeo`.
Сайт, чей layout печатает `<head>` раньше блоков, разметки не получит — это записано в гайде, а не
лечится.

### 3.6. Плейграунд

Предпросмотр страницы в плейграунде рисует блоки своим `renderTemplate()`, поэтому раскрытие
`wx-collection` из фикстур лежит там же, через что идут и страница, и конструктор.

## 4. `module-faq`

### 4.1. Схема

```
faq_questions
  id
  question     json nullable      -- переводимый
  answer       json nullable      -- переводимый, wx-rich-text
  anchor       string(96) unique  -- решение 10
  published    bool default false
  position     int default 0
  extra        json nullable
  softDeletes, timestamps

faq_categories        -- $table->category(); slug остаётся пустым
faq_category_question -- $table->categoryLinks('faq_questions', 'faq_categories')
```

Миграции — `2026_01_01_*`; на чужие таблицы модуль не ссылается.

### 4.2. Модели

- `Question` — `HasCategories`, `HasExtra`, `HasTranslations` (`question`, `answer`),
  `SoftDeletes`. `visibleIn(string $locale)` — опубликован и оба поля есть на языке. Якорь — при
  создании: слаг вопроса на языке по умолчанию, при столкновении — `-2`, `-3` (корзина в счёт:
  восстановленный вопрос сохраняет якорь); пустой вопрос — `q-<id>` после вставки.
- `FaqCategory` — `IsCategory`; вид категории без адреса (`prefix: null`) и без SEO (решение 2):
  модель обнуляет `slug` при сохранении, общий список, экран и `CategoryTools` адреса не
  показывают. Право — `faq.categories.manage`.
- Новый вопрос встаёт в конец общего порядка (`position = max + 1`), в категорию — по общему
  порядку.

### 4.3. Источник `faq`

`FaqSource implements CollectionSource`: элемент — `id`, `anchor`, `categories`, `question`
(строка), `answer` (HTML, ключи картинок раскрыты в адреса тем же кодом, что у `wx-rich-text` на
чтении). Лимит считается в php после видимости. Разметка — `FAQPage` с `mainEntity` из
`Question`/`acceptedAnswer`, текст ответа без тегов, через `Seo::put('faq', …)` (§3.5).

`require` — `module-admin`, `module-blocks`, `localization`, `mcp`; `module-seo` — только
`suggest`: без него разметки нет. Конфиг `webx-faq.markup` выключает разметку у всех блоков разом
— для сайта, чей layout печатает её сам.

### 4.4. Тип блока «FAQ»

`resources/blocks/faq.json`, предлагается через `BlockOffers`:

- Схема: заголовок (переводимый, необязательный), `questions` — `wx-collection` с
  `source: faq`.
- Шаблон: `<details>`/`<summary>` на каждый вопрос, `id` — якорь; фильтр — кнопки по `groups`,
  печатается только при `filter`. Без JS аккордеон работает, фильтр — нет, и это допустимо.
- Скрипт: фильтр по группам и открытие вопроса по `#якорю` при загрузке и при `hashchange`.
  Фильтрует по DOM (`data-faq-group`, `data-faq-categories`), а не по `data-wx-values`: там только
  выбор редактора, а не раскрытые записи.
- Стили — не на `--wx-*`: это вёрстка сайта, токенов панели на сайте нет. Нейтральные, на
  `currentColor` и `em`, чтобы встать в чужой сайт без спора.

### 4.5. Панель

- Раздел «FAQ» — группа меню со своей иконкой, пункты «Вопросы» и «Категории».
- **Вопросы — `WxListDetail`** на одном маршруте `/faq`, вопрос — `?question=<id|new>`: слева
  список с перетаскиванием и фильтром по категории (`useItemOrder`, как у услуг), справа форма
  описанного экрана `faq.form`: вопрос, ответ (`wx-rich-text`), категории (`wx-categories`,
  `main: false`), «Опубликован», якорь только для чтения (узел `wx-faq-anchor`, копирует
  `#якорь`), карточка `project-fields`. На телефоне форма уходит в ящик и сама рисует «назад».
  Создание — строка «Новый вопрос» в списке и форма, а не диалог: строку создаёт первое
  сохранение (`POST { values }`).
- **Категории — общие страницы** (`categoryRoutes`), экран `faq.category-form`: название,
  видимость, `project-fields`.
- Права: `faq.view`, `faq.manage`, `faq.categories.manage`.
- Сохранение — кнопкой и Ctrl+S; «уйти без сохранения?» — при смене вопроса. Ревизий и 409 нет —
  нет черновика.

### 4.6. API панели

```
GET    /api/cms/faq/questions            ?category=&trashed=1&search=
POST   /api/cms/faq/questions            { values }
GET    /api/cms/faq/questions/{id}       → { question, values }
PUT    /api/cms/faq/questions/{id}       { values }            422 под именем поля
DELETE /api/cms/faq/questions/{id}
POST   /api/cms/faq/questions/{id}/restore
POST   /api/cms/faq/questions/reorder    { ids, category? }     CategoryRoutes::items()
       /api/cms/faq/categories/*         общие маршруты категорий
```

Список — без пагинации: вопросов десятки, а не тысячи, и список — то место, где их упорядочивают.

### 4.7. MCP

`faq_list`, `faq_get`, `faq_create`, `faq_update`, `faq_delete`, `faq_reorder` — через те же
`Panel\*`, что и панель; `faq_categories_*` — общий `CategoryTools`. Вопрос называют id или
якорем, категорию — id или названием; несуществующая категория — отказ до записи; строка без
языка — язык по умолчанию. Создание в транзакции: отказ не оставляет голый вопрос. Ресурс
`faq://catalog`: категории с вопросами в их порядке, вопросы без категории в конце,
неопубликованные с пометкой, у каждого — `visible_in`, на каких языках он виден.

### 4.8. Демо

`FaqDemo`: три категории, десять вопросов на двух языках демо, один вопрос в двух категориях,
один неопубликованный, один без перевода. Ставит предложенный тип блока, если его нет. Если стоит
`module-pages` — страница `/faq` с блоком «все категории, с фильтром»; если стоит
`module-services` — блок «FAQ по оплате» в содержимом одной демо-услуги (проверка решения 8:
разметка на `/faq` есть, на услуге — нет).

### 4.9. Регистрации

Стандартные для composer-пакета и раздела панели (CLAUDE.md §4) плюс строка в реестре
`WEBX_UI_COMPOSER_PACKAGES.md`.

### 4.10. Что держат тесты

- Вопрос без перевода не попадает в `items()` на этом языке, с переводом — попадает.
- Порядок: одна категория — её порядок; две — общий, без повторов.
- Якорь: уникальность, стабильность после правки вопроса.
- `FAQPage`: два блока с общим вопросом — одна разметка, вопрос в ней один раз; `markup: null`
  с категориями — разметки нет, без категорий — есть.
- `wx-collection` через **настоящий путь записи** обеих дверей (панель и `blocks_edit_content`),
  а не только на чистой функции.
- `webx:blocks:offered --install` не трогает тип с тем же `slug`.
- Удалённый модуль: блок с `wx-collection` рисуется пустым, страница отвечает 200.

## 5. Как на контракте сидят другие разделы

Проверка формы контракта: источник `team` отдаёт фото (раскрытый `wx-media`), имя, должность,
текст, соцсети; `reviews` — автора, текст, оценку, дату. Разметка — `supportsMarkup()` у отзывов,
у команды — нет. Ни одному не нужно в контракте ничего сверх §3.2. Понадобится выбор отдельных
записей — это новое поле `Selection` (`ids`), а не новый тип.

## 6. Выпуск

Контракт и `module-faq` вышли одним выпуском и стоят на обоих демо (страница `/faq`).

- Контракт: `CollectionSource`, `wx-collection`, `/api/cms/collections`, `BlockOffers` с
  `webx:blocks:offered`, `Seo::put()`, раскрытие в плейграунде.
- `module-faq`: схема, источник, тип блока, панель, API, MCP, демо, гайд.
- Попутно: `CategoryTools::create` отвечает после `refresh()` (раньше видимая категория
  приходила с `is_visible: false`).

**Открыто:** проверка на телефоне — за пользователем. Rich Results Test FAQ не показывает
(сниппеты только для авторитетных сайтов) — `FAQPage` проверять на validator.schema.org.
Отложенное — §7.

## 7. Отложено

- Выбор отдельных записей в `wx-collection` (`Selection::ids`) — когда попросят «эти три отзыва».
- Экран «предложенные типы блоков» в разделе «Блоки» — пока хватает команды и `webx:setup`.
- Вставка коллекции без блока (`@collection('faq', …)` в Blade сайта).
- Поиск по вопросам на сайте, «помог ли ответ».
- Разметка `FAQPage` на странице, чей layout печатает `<head>` раньше содержимого (§3.5).
