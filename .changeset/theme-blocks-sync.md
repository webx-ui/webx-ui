Block types travel with the theme (THEMES §9.2, TH2.2). A layer carries them as `blocks/<slug>.json`, the files `webx:blocks:export` writes; an upper layer replaces a lower one's type with the same slug whole. `webx-ui/themes`: **`Blocks\LayerBlocks::of($chain)`** gives the resulting set; **`webx:theme:check`** now also reads every layer's block types — a file that is not a block document, styles that break §8, and an override whose schema drops or retypes a field of the type below. **`webx:theme:sync`** runs, after the assets, the steps packages tag `webx-themes.sync` (`Contracts\SyncStep`) and exits non-zero on a refused line. `webx-ui/module-blocks`: its step puts the set on the site — creates and publishes what is missing, publishes a new version where the site has not touched the type since the last sync, keeps a type edited in the panel (`--force` overwrites it), refuses a slug the site uses for a type of its own, a type whose CSS breaks §8 and one that does not publish, and never deletes a type a layer stopped carrying. New columns `blocks.theme_source` and `blocks.theme_hash` (run `php artisan migrate`); the versions it writes say «theme» in the history, in ten languages. `webx-ui/module-admin`: `webx:setup` syncs the theme after `migrate` and before the modules' offers, and adds `webx:theme:sync` to the site's `post-update-cmd`.
