`module-seo`: interlinking, and addresses bound to entities. Two features off by default — `webx-seo.links.enabled` (`WEBX_SEO_LINKS`) and `webx-seo.faq.enabled` (`WEBX_SEO_FAQ`); the manifest gives `meta: { links, faq }`, and a feature that is off has no routes, no MCP tools and a silent component, while its tables migrate anyway. Exact rules now remember the entity behind their address (`entity_type`/`entity_id` on `seo_urls`), so a renamed page keeps its rule: an old address binds to the entity it belonged to, an address behind a redirect is replaced by its target and reported (`redirected_from`), another site's host is refused, and the compiled rules use the entity's current address (`current_pattern` in the API). Interlinking: `seo_link_blocks` / `seo_link_items`, `<x-webx-seo::links />` with the overridable `webx-seo::links` view (a `<nav aria-labelledby>`, broken links left out, the `seo.links-heading` setting when a block has no heading), CSV/XLSX import with a preview and per-row errors (replace or append), export in the same flat file, a bulk heading by address prefix, the panel API under `/seo/links` and the MCP tools `seo_links_list/get/set/delete/import/heading`. `module-seo` now requires `openspout/openspout`.
