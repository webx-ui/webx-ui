Themes TH6. `webx-ui/themes`: **`Testing\ThemeContract`** — the test every theme runs (`use ThemeContract;` + `themePath()`): the chain builds with the theme on top, every token has a value, `webx:theme:check` finds nothing, text reads in every preset (WCAG AA), the layout keeps `@webxTheme`, `@webxSeo`, `@webxBlocks` and the `header`/`footer` regions, the theme's views compile, a packaged `dist/` is built from its `src/` (`Testing\ThemeProbe` gives the same as lists). **`php artisan webx:theme:make vendor/name`** scaffolds a packaged theme (over `webx-ui/theme-default` by default, in `packages/<name>`): the manifest in `composer.json`, an already built empty `dist/`, the Vite build, a Testbench test on the contract and a CI — green from the first run. **`webx:theme:extract vendor/name`** turns the site's `theme/` into such a package and stands the site on it (path repository, `WEBX_THEME`); **`webx:theme:eject [vendor/name]`** folds a packaged theme into the site's local theme, the site's files, tokens and words winning (never `theme-default`). Both compare the look before and after (`ThemeLook`) and print the Composer and npm commands instead of running them. A packaged theme's `dist/theme.js` is linked by `@webxTheme`. The 35 rules of a theme are in `RULES.md`; the engine's `AGENTS.md` is rewritten around the commands, `theme-default`'s names every token, and `ModuleThemeContract` checks that every `@webxPart` point of a module is in its `AGENTS.md`. The local theme's test stub now runs the contract. `webx-ui/module-admin`: the site's root `AGENTS.md` (`webx:panel --sync`) names the site's theme chain, the doors of its local theme, `webx:theme:show`/`check` and `RULES.md`.
