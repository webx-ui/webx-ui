`module-blocks`: every value a block holds is checked by its field type's rules on every door — `blocks_set_content`, `blocks_edit_content`, the panel's save, a region's save and a publication — and every block against where it stands (a container's `allow` and `max`, a type's `allowed_in` and `max_per_entity`); a refusal names the block's key and the field. Links outside `http(s)`, `mailto`, `tel`, paths and anchors are refused and never printed; a library key nobody has is refused as a new value. Switching a field's `localized` converts the stored values when the type is published (asking before other languages are dropped), and reading takes either shape. A type's slug is renamed everywhere it is named. Thumbnails are drawn in the site's language and cached until any type changes. New MCP tools `blocks_delete`, `blocks_versions`, `blocks_version_restore`, `blocks_usage`, `blocks_region_discard`, `blocks_region_versions`, `blocks_region_restore`, `blocks_region_adopt`, `pages_versions`, `pages_version_restore`, `services_versions`, `services_version_restore`; `duplicate` in `blocks_edit_content`, `rename_to` and a short answer in `blocks_update`, `drop_translations` in `blocks_publish`, the panel's lints on MCP saves. The `script` field's description says that `values` is what the template prints in `data-wx-values`.
