`webx:make-module --local <name>` writes a module of the site into `modules/<name>`, built like a packaged module: `site/module-<name>` (version `0.1.0`, `Site\<Name>\`) with its provider, one translatable record with its migration, the section with `<id>.view` / `<id>.manage` and the ready-made roles, the routes of the panel behind `cms.can`, the described form, MCP tools for the list, one record, create, update, delete and the order (the changing ones with `dry_run`) and the resource `<id>://catalog`, help for every field, words in English and the languages of the site's panel, a demo of three rows, `AGENTS.md`, and the tests a module carries (access, help, translations, MCP dry runs, query budgets, the panel); the front end `@site/module-<name>` in `js/` with the list, the form and a test of its English keys. The site is wired once and idempotently — the path repository `modules/*`, the autoload of the module's tests, the `Modules` suite of `phpunit.xml`, the npm tools and the scripts `typecheck:modules` and `test:modules` — with the Vue plugin and the `Dockerfile` named rather than edited, and the module is installed by a child `webx:module:add`, then `migrate`. An id of a module of the catalogue or of an installed module is refused; `--force` writes over the files of the scaffold and nothing else; `--no-install` stops after the wiring.
