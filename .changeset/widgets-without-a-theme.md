The form engine's scripts on a site without a theme. `@webxTheme` prints nothing there, so every `<x-webx-form>` — an inbox form among them — fell back to a plain POST with a reload. `webx-ui/widgets`: a layout writes **`@webxWidgets`** before `</body>`, and the page is finished as under a theme with the runtime and the claimed widgets' scripts (`form.js`, `field.js`, `files.js`, `mask.js`…), without stylesheets (made of a theme's tokens) and without the consent banner; under a theme the directive adds nothing. New audit check **`widgets.form_script`** (warning, ten languages): a form that sends in place on a page loading no `form.js`. `webx-ui/themes`: `webx:theme:sync` without a theme publishes the packages below the themes (the widgets) and nothing else. `webx-ui/module-admin`: `webx:setup` and the boot plan run the sync without a theme when `webx-ui/widgets` is installed (and add it to `post-update-cmd`), and the layout of `webx:setup --no-theme` carries `@webxWidgets`. A site set up before: add the line to its layout and run `php artisan webx:theme:sync` once — and drop any import of `vendor/webx-ui/widgets/dist/*.js` from its own bundle.
