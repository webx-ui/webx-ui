`module-catalog-properties` to an agent (P5, the last stage of the properties series). The tools are the catalogue's own, with its `catalog:read` / `catalog:write` scopes and `catalog.view` / `catalog.manage` permissions: `catalog_properties_list`, `_get`, `_create`, `_update` (the editor's fields and a number's intervals as a whole table), `_delete`, `_restore`, `_reorder`; `catalog_property_values_list` (a level of the book, or a search at any depth with the path of each value), `_create`, `_update`, `_move`, `_merge` (with `dry_run`, the number of products that would move) and `_delete` (refused with the number of products and a pointer to merging); `catalog_property_groups_*`, the shared category tools; `catalog_categories_properties` and `catalog_categories_properties_set` for a category's set. `catalog://properties` lists every property with its codes in each language and, per type, the flags and fields it keeps — an agent does not offer a filter on a text. In `catalog_products_update` a value of a reference book is its id or its slug in any language; an unknown slug is refused with a pointer to `catalog_property_values_create`. The core gets `SatelliteTools`, for a satellite whose tools belong to the catalogue by name, and `Tool::prefixed()` in `webx-ui/mcp`. `webx:setup` offers the properties, and `webx:panel --sync` adds `@webx-ui/module-catalog-properties` to the panel.
